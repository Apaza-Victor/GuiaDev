¿Qué es Jenkins y cuándo usarlo?

Jenkins es el servidor de automatización open source más veterano y extendido del mundo empresarial (Java, 2011). No es un hosting: lo instalas y administras tú. Su superpoder es el ecosistema de +1800 plugins que conecta con absolutamente todo.

Úsalo cuando:

  • Necesitas control total on-premises (bancos, gobierno, salud).
  • Tienes pipelines complejos o heterogéneos que las plataformas SaaS no cubren.
  • Herencias infraestructura existente basada en Jenkins.

Evítalo si buscas cero mantenimiento: un SaaS como GitHub Actions te ahorra actualizar servidor, plugins y backups.

Instalación con Docker

# Jenkins LTS con persistencia
docker run -d --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  jenkins/jenkins:lts

# Obtener la contraseña inicial del log
docker logs jenkins | grep -A 5 "initialAdminPassword"
# o desde dentro:
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
  1. Abre http://localhost:8080.
  2. Pega la contraseña inicial.
  3. Elige "Install suggested plugins".
  4. Crea tu usuario admin — listo para usar.

Jenkinsfile: pipeline declarativo

El pipeline se define en un archivo Jenkinsfile versionado junto al código:

// Jenkinsfile
pipeline {
    agent any

    environment {
        NODE_VERSION = '20'
    }

    stages {
        stage('Checkout') {
            steps { checkout scm }
        }
        stage('Install') {
            steps { sh 'npm ci' }
        }
        stage('Test') {
            steps { sh 'npm test' }
            post {
                always {
                    junit 'test-results/**/*.xml'
                }
            }
        }
        stage('Deploy') {
            when { branch 'main' }
            steps { sh './deploy.sh' }
        }
    }

    post {
        failure { echo 'Notificar al equipo...' }
        success { echo 'Pipeline OK ✓' }
    }
}

Cada push dispara el pipeline; los resultados se ven como etapas coloreadas en la UI.

Agentes distribuidos

El controlador (master) orquesta pero conviene no ejecutar builds en él. Los agentes hacen el trabajo pesado:

  • Permanent agents: VMs/físicas dedicadas registradas vía SSH.
  • Docker agents: cada build corre en un contenedor efímero.
  • Kubernetes plugin: agentes autoescalables en clúster K8s.
pipeline {
    agent { docker { image 'node:20' } }   // build en contenedor Node
    ...
}

Etiqueta agentes (linux, gpu, windows) y asígnalas por job: agent { label 'linux && docker' }. Con esto escala horizontalmente sin límite práctico.
