Instalación y configuración inicial

GitHub Desktop es el cliente oficial gratuito de GitHub para Windows y macOS. Descárgalo desde desktop.github.com, instálalo e inicia sesión con tu cuenta GitHub.

En File → Options configura:

  • Name y Email: identidad de tus commits (usa el email de noreply si quieres privacidad).
  • Default branch: normalmente main.
  • Línea de comandos: instala el atajo para abrir repos desde terminal.
# Desde la terminal puedes abrir cualquier repo:
github path/al/repo

Interfaz y flujo básico

La ventana tiene tres zonas: lista de cambios (izquierda), diff del archivo seleccionado (derecha) y barra superior con el repositorio activo, rama actual y botones Fetch/Pull/Push.

El ciclo completo de trabajo:

  1. Add repository / Clone: File → Clone repository (de tus repos GitHub, URL o disco local).
  2. Edita archivos en tu editor favorito; Desktop los detecta al instante.
  3. Stage: marca los archivos a incluir (o líneas sueltas con clic derecho → Discard/Stage hunk).
  4. Commit: escribe summary + descripción y confirma.
  5. Publish/Push: sube los cambios; Fetch trae lo nuevo del remoto.
Equivalencia con terminal:
Marcar archivos   → git add
Botón Commit      → git commit -m "..."
Botón Push        → git push
Botón Pull        → git pull

Ramas y sincronización

  • Nueva rama: Branch → New branch (desde la rama actual). El selector superior cambia entre ramas con un clic.
  • Cambiar de rama: guarda automáticamente tus cambios sin commit (los lleva contigo o hace stash silencioso).
  • Merge visual: Branch → Merge into current branch; eliges origen desde una lista.
  • Update from main: sincroniza tu feature con main en un clic.
  • Preview Pull Request: botón dedicado que crea el PR en GitHub y abre la página web.
Branch → Create PR: abre github.com con el PR prellenado,
comparando tu rama contra main ✓

Resolver conflictos visualmente

Al hacer merge/pull con conflicto, Desktop avisa y ofrece "Open in your editor". Abre el archivo con marcadores clásicos:

<<<<<<< HEAD
tu versión
=======
versión entrante
>>>>>>> feature/x

Editas, guardas, y al volver a Desktop los archivos resueltos aparecen listos para el commit final del merge. VS Code además resalta los bloques de conflicto con botones Accept Current / Incoming.
