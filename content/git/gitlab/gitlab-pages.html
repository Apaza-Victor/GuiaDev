¿Qué es GitLab Pages?

GitLab Pages permite publicar sitios estáticos (HTML/CSS/JS, documentación, blogs generados) directamente desde un repositorio, gratis y con HTTPS incluido. El sitio se publica como parte de un pipeline: cada push puede regenerar y publicar la versión nueva.

Casos típicos: portafolios, documentación técnica con MkDocs/VitePress/Docusaurus, demos de proyectos y páginas de producto.

Configuración del job pages

Pages funciona mediante un job especial llamado pages que debe producir un artefacto con nombre exacto public/:

pages:
  stage: deploy
  image: node:20
  script:
    - npm ci
    - npm run build          # genera dist/ o build/
    - mkdir -p public
    - cp -r dist/* public/   # Pages exige una carpeta llamada public
  artifacts:
    paths:
      - public
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

Dos reglas de oro: el artefacto debe llamarse public y el job debe llamarse pages.

Publicar un sitio estático

Ejemplo completo sin herramientas externas, solo HTML plano:

pages:
  stage: deploy
  image: alpine:latest
  script:
    - mkdir -p public
    - cp -r sitio/* public/
  artifacts:
    paths:
      - public
  only:
    - main

Al terminar el pipeline, tu sitio queda disponible en la URL que muestra Deploy → Pages, normalmente:

https://tu-usuario.gitlab.io/mi-proyecto/

# Si el proyecto vive en un grupo:
https://grupo.gitlab.io/mi-proyecto/

Dominios y HTTPS

En Deploy → Pages puedes añadir un dominio propio (por ejemplo docs.tuempresa.com). GitLab genera certificados TLS automáticamente con Let's Encrypt si usas DNS administrado, o te pide verificar la propiedad con un registro TXT.

  • Crea un registro CNAME apuntando al dominio Pages de tu proyecto.
  • Habilita "Force HTTPS" para redirigir siempre tráfico seguro.
  • Los sitios privados requieren plan Premium (acceso restringido a miembros).
