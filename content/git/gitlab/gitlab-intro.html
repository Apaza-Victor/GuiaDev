¿Qué es GitLab?

GitLab es una plataforma DevOps completa que va mucho más allá del hospedaje de repositorios Git: incluye integración continua, despliegue, registro de contenedores, gestión de paquetes, wikis y seguimiento de trabajo en una única aplicación.

Su gran diferencia frente a GitHub es que el CI/CD viene integrado de fábrica: no dependes de servicios externos para compilar, probar y desplegar tu aplicación.

Repositorio + CI/CD + Registro + Issues + Wiki + Despliegue
        \      |      /
         UNA SOLA PLATAFORMA: GitLab

Existe en dos modalidades:

  • GitLab.com (SaaS): servicio administrado, gratis con límites de minutos de CI.
  • Self-hosted (CE/EE): instalas GitLab en tu propio servidor; la Community Edition es open source.

"Una sola aplicación" no es marketing: el MR sabe qué pipeline lo valida, el pipeline publica la imagen al registro integrado, el despliegue registra el entorno y los issues se cierran con el merge. En GitHub eso son 4 productos que integrar; aquí es un grafo coherente.

GitLab vs GitHub

Ambos son excelentes; la elección depende del contexto del equipo:

CriterioGitHubGitLab
CI/CDGitHub Actions (pago por minutos)Incluido nativamente
Self-hosted gratuitoNo (solo Enterprise)Sí (Community Edition)
Comunidad open sourceMucho más grandeMenor pero creciente
DevOps integralRequiere herramientas extraTodo en uno

En resumen: para proyectos open source orientados a comunidad, GitHub suele ser la opción natural; para equipos de empresa que quieren un flujo DevOps completo y controlado, GitLab destaca.

Pregunta decisiva para tu contexto: ¿necesitas self-hosted GRATIS? Si sí, la conversación termina: GitLab CE es la única opción completa sin costo de licencia. GitHub Enterprise Server requiere suscripciones caras.

SaaS y self-hosted

Los niveles principales de GitLab.com son Free, Premium y Ultimate. El plan Free ya incluye pipelines con 400 minutos mensuales de CI en runners compartidos, suficiente para aprender y proyectos pequeños.

Si tu empresa necesita datos en su propia infraestructura, la Community Edition se instala en un servidor Linux con Docker o paquetes Omnibus:

# Instalación rápida con Docker (pruebas locales)
docker run --detach \
  --hostname gitlab.ejemplo.com \
  --publish 443:443 --publish 80:80 --publish 22:22 \
  --name gitlab \
  --restart always \
  --volume $GITLAB_HOME/config:/etc/gitlab \
  --volume $GITLAB_HOME/logs:/var/log/gitlab \
  --volume $GITLAB_HOME/data:/var/opt/gitlab \
  gitlab/gitlab-ce:latest

GitLab self-hosted NO es ligero: recomienda mínimo 4 GB de RAM + swap (8 GB cómodos) y arranca consumiendo varios GB. En un VPS pequeño será inutilizable; en tu laptop para pruebas, cierra todo lo demás o usa la versión mínima con ajustes de puma/sidekiq.

Crear cuenta y primer proyecto

  1. Entra a gitlab.com/users/sign_up y regístrate con correo o SSO.
  2. Haz clic en New project → Create blank project.
  3. Elige nombre, visibilidad (Private/Internal/Public) y marca "Initialize repository with a README".
  4. Clona el proyecto igual que en GitHub:
git clone https://gitlab.com/tu-usuario/mi-proyecto.git
cd mi-proyecto

# Flujo diario idéntico a cualquier remoto Git
echo "# Mi primer proyecto" >> README.md
git add README.md
git commit -m "feat: primer commit"
git push origin main

Todos los comandos Git que ya conoces funcionan sin cambios: solo cambia la URL del remoto.

Tour por la interfaz

Dentro de un proyecto encontrarás estas zonas clave en el menú lateral:

  • Code: archivos, ramas, tags, commits y gráficos del repositorio.
  • Plan: issues, tableros Kanban, milestones y epics (gestión de trabajo).
  • Build: Pipelines, jobs, editor de CI/CD y schedules programados.
  • Deploy: entornos, releases, feature flags y páginas estáticas.
  • Secure: escaneo de dependencias y vulnerabilidades.
  • Settings: membresías, webhooks, variables CI/CD y ramas protegidas.

El menú cambia según tu ROL en el proyecto: un Guest no ve Build ni Deploy. Si "te falta" una sección, antes de buscar bugs revisa tus permisos: GitLab oculta por completo lo que no puedes usar.

Ejercicios prácticos

  1. Onboarding completo: crea cuenta GitLab.com, primer proyecto con README y clónalo por HTTPS usando PAT — documenta cada paso y tropiezo.
  2. SSH configurado: genera clave, regístrala en GitLab, clona por SSH y verifica push sin pedir credenciales.
  3. Tour guiado propio: visita las 6 zonas del menú lateral de tu proyecto y anota qué harías desde cada una en un flujo real.
  4. Laboratorio CE (opcional): levanta gitlab-ce en Docker si tienes 8 GB RAM; cronometra arranque inicial y consumo final de memoria.
  5. Migrante GitHub→GitLab: importa un repo tuyo de GitHub con el asistente; verifica issues/ramas/historial y compara experiencia de MR vs PR.
