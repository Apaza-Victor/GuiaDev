¿Qué son los Bitbucket Pipelines?

Bitbucket Pipelines es el servicio CI/CD integrado de Bitbucket: cada push puede disparar builds y despliegues definidos en un solo archivo YAML dentro del repositorio. No necesitas conectar herramientas externas como Jenkins o CircleCI para automatizar.

Se factura por minutos de build: el plan gratuito incluye 50 minutos mensuales, suficiente para aprender y proyectos pequeños.

El archivo bitbucket-pipelines.yml

Todo se define en bitbucket-pipelines.yml en la raíz del repo. La estructura básica:

image: node:20          # contenedor donde corren los steps

pipelines:
  default:              # corre en cualquier rama sin branch específico
    - step:
        name: Instalar y testear
        script:
          - npm ci
          - npm test
  branches:
    main:               # pipeline exclusivo de main
      - step:
          name: Build
          script:
            - npm ci && npm run build

Cada step corre en su propio contenedor con la imagen indicada; los artefactos entre steps se pasan explícitamente.

Steps, caches y artifacts

Para acelerar builds y pasar datos entre pasos usa caches y artifacts:

pipelines:
  default:
    - step:
        name: Build
        caches:
          - node           # cachea node_modules
        script:
          - npm ci
          - npm run build
        artifacts:
          - dist/**        # pasa dist/ al siguiente step
    - step:
        name: Test sobre el build
        script:
          - npm ci
          - npm test
  • caches: reutiliza dependencias entre builds (node, pip, maven, custom).
  • artifacts: archivos que sobreviven entre steps del mismo pipeline.
  • max-time: límite de minutos por step para evitar bucles infinitos.

Despliegues a producción

Las secciones branches y las deployment environments permiten desplegar automáticamente según la rama, con control de permisos y variables por entorno:

pipelines:
  branches:
    develop:
      - step:
          name: Deploy staging
          deployment: staging     # entorno declarado en Bitbucket
          script:
            - ./deploy.sh $STAGING_HOST
    main:
      - step:
          name: Deploy produccion
          deployment: production
          trigger: manual         # requiere clic humano
          script:
            - ./deploy.sh $PROD_HOST

Las variables $STAGING_HOST y secretos se configuran en Repository settings → Repository/Pipeline/Deployment variables, protegidas y ocultas en los logs.
