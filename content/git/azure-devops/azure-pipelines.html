Conceptos: pipelines, agentes y etapas

La jerarquía conceptual de Azure Pipelines:

Pipeline
└── Stages (etapas: Build → Test → Deploy)
    └── Jobs (unidades de trabajo en un agente)
        └── Steps (tareas individuales: scripts o tasks)
  • Agente: la máquina que ejecuta jobs. Puede ser Microsoft-hosted (mantenido por Azure) o self-hosted (tu propia VM).
  • Task: paso empaquetado y reutilizable (npmInstall, Docker@2, AzureWebApp...).

El archivo azure-pipelines.yml

El pipeline clásico se define en azure-pipelines.yml:

trigger:
  branches:
    include:
      - main

pool:
  vmImage: ubuntu-latest       # agente hospedado por Microsoft

stages:
  - stage: Build
    jobs:
      - job: compilar
        steps:
          - task: NodeTool@0
            inputs:
              versionSpec: '20.x'
          - script: npm ci && npm run build
          - publish: dist/
            artifact: webapp

  - stage: Deploy
    dependsOn: Build
    condition: succeeded()
    jobs:
      - job: publicar
        steps:
          - download: current
            artifact: webapp
          - script: echo "Desplegando..."

Triggers, tareas y plantillas

  • trigger: ramas que disparan CI. pr: validación automática en pull requests.
  • schedules: ejecuciones programadas tipo cron.
  • templates: reutiliza YAML entre pipelines para no duplicar configuración.
# templates/build-node.yml
steps:
  - task: NodeTool@0
    inputs: { versionSpec: '${{ parameters.node }}' }
  - script: npm ci && npm test

# azure-pipelines.yml lo consume
jobs:
  - template: templates/build-node.yml
    parameters:
      node: '20.x'

Despliegue a Azure App Service

Con una conexión de servicio (service connection) hacia tu suscripción Azure, el despliegue queda en dos pasos:

steps:
  - task: AzureWebApp@1
    inputs:
      azureSubscription: 'conexion-mi-suscripcion'
      appType: 'webAppLinux'
      appName: 'mi-tienda-prod'
      package: '$(Pipeline.Workspace)/webapp/**'

La service connection guarda credenciales de forma segura; nunca pones secretos en el YAML.
