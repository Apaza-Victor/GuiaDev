Work items y tipos de trabajo

Azure Boards gestiona todo el trabajo del equipo mediante work items. Según el proceso elegido al crear el proyecto (Agile, Scrum o Basic/CMMI) los tipos varían ligeramente:

  • Epic: iniciativa grande que abarca meses.
  • Feature: funcionalidad entregable dentro de un epic.
  • User Story / Product Backlog Item: requerimiento desde la perspectiva del usuario.
  • Task: unidad técnica de trabajo (horas/días).
  • Bug: defecto con flujo propio.
Epic: Plataforma de ventas
└── Feature: Carrito de compras
    └── User Story: Persistir carrito entre sesiones
        ├── Task: Modelo de datos
        ├── Task: API endpoints
        └── Task: Frontend

Tableros Kanban y sprints

  • Boards (Kanban): columnas personalizables (Nuevo, Activo, Resuelto...) donde arrastras work items; soporta WIP limits y swimlanes.
  • Sprints: iteraciones de duración fija (configurable en Project settings); cada sprint tiene su backlog y capacity plan por integrante.
  • Backlogs: priorización jerárquica Epics → Features → Stories.

Consultas y gráficos

Las queries filtran work items por campos combinables (tipo, estado, asignación, área, iteración):

Query: Bugs activos del sprint actual
  Type = Bug AND State IN (New, Committed)
  AND Iteration = @CurrentIteration
  ORDER BY Priority DESC

Sobre cualquier query puedes generar gráficos circulares/de barras y fijarlos en dashboards compartidos. Los informes analíticos nativos incluyen velocity, burn-down y lead time.

Vincular commits y PRs a work items

La trazabilidad es la gran fortaleza: cada cambio de código puede quedar ligado a su motivo de negocio.

# Menciona el #ID en el mensaje de commit
git commit -m "#1234 implementar persistencia del carrito"

# O usa AB#ID (formato oficial desde repos externos)
git commit -m "AB#1234 fix: restaurar carrito al iniciar sesión"
  • El work item muestra sus commits, PRs y builds asociados automáticamente.
  • Puedes exigir por política de rama que cada PR tenga al menos un work item vinculado.
  • Estados como "Resolved"/"Done" pueden moverse solos al fusionar el PR.
