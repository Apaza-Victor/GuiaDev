Crear un PR desde tu rama

Con tu feature pusheada, un comando crea el pull request completo:

git push -u origin feat/login
gh pr create --title "feat: login con OAuth" \
  --body "Implementa Google y GitHub OAuth. Closes #42"

Atajos prácticos:

  • Sin argumentos: gh abre un editor interactivo para título/cuerpo.
  • --fill: rellena título y cuerpo con el primer commit de la rama.
  • --base develop: apunta el PR a otra rama destino.
  • --draft: lo crea como borrador.
  • --reviewer @usuario: asigna revisores al vuelo.
# El flujo completo en una línea:
git checkout -b feat/x && git commit -am "feat: x" \
  && git push -u origin feat/x && gh pr create --fill

Ver y revisar PRs

# Listar PRs abiertos del repo actual
gh pr list
#  #58  feat: pagos con Stripe   [feat/pagos]
#  #57  fix: fuga de memoria     [fix/memoria]

# Ver detalles, checks y comentarios
gh pr view 58

# Ver SOLO los diffs
gh pr diff 58

# Revisar desde la terminal
gh pr review 58 --approve -m "LGTM 🚀"
gh pr review 58 --request-changes -m "Falta test del caso límite"
gh pr review 58 --comment -m "Duda en la línea 20"

# Bajarte el PR de otro a tu máquina para probarlo localmente
gh pr checkout 58

gh pr checkout es oro puro: te posiciona en la rama del PR sin buscar URLs ni fetch manuales.

Fusionar PRs: merge, squash y rebase

gh pr merge 58 --merge    # merge commit clásico
gh pr merge 58 --squash   # comprime todos los commits en uno
gh pr merge 58 --rebase   # aplica commits sobre main sin merge commit

# Fusionar Y borrar la rama remota en un paso:
gh pr merge 58 --squash --delete-branch
EstrategiaCuándo usarla
mergeQuieres preservar todo el historial de la rama + merge visible
squashRama con commits "wip" desordenados → historial limpio
rebaseHistorial lineal estricto (sin nodos de merge)

Si el repo exige checks verdes o aprobaciones, gh respeta esas reglas igual que la web.

Gestionar issues y labels

# Crear issue interactivamente o directo:
gh issue create --title "Bug: login falla con email largo" \
  --body "Pasos: ..." --label bug --assignee @me

# Filtrar
gh issue list --label "bug" --state open --limit 10
gh issue list --assignee "@me"

# Cerrar / reabrir / comentar
gh issue close 42 --comment "Resuelto por PR #58"
gh issue comment 42 -m "Reproducido en v2.1.0"

# Crear labels personalizadas
gh label create "prioridad-alta" --color d93f0b

Monitorear Actions con gh run

# Últimas ejecuciones de workflows
gh run list
#  ✓ deploy.yml   Deploy to prod   main   hace 5 min
#  ✗ tests.yml    CI               #58    hace 2 min

# Seguir en vivo una ejecución (se actualiza sola)
gh run watch

# Inspeccionar logs de un run fallido
gh run view 1234567890 --log-failed

# Reintentar
gh run rerun 1234567890

Ciclo típico: haces push → gh run watch → si falla, gh run view --log-failed → corriges — todo sin salir de la terminal.
