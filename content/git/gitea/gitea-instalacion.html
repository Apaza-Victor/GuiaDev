Instalación binaria simple

Gitea se distribuye como un único binario estático: descárgalo desde dl.gitea.com/gitea, dale permisos y ejecútalo.

# Linux x64 — descargar el binario
wget https://dl.gitea.com/gitea/1.22/gitea-1.22-linux-amd64
chmod +x gitea-1.22-linux-amd64

# Probarlo (usa SQLite por defecto)
./gitea-1.22-linux-amd64 web
# Servidor disponible en http://localhost:3000

Para producción conviene crear un usuario dedicado (git) y un servicio systemd que lo mantenga vivo.

Instalación con Docker Compose

La forma recomendada: Gitea + PostgreSQL con persistencia en volúmenes.

# docker-compose.yml
services:
  gitea:
    image: gitea/gitea:1.22
    container_name: gitea
    environment:
      - USER_UID=1000
      - USER_GID=1000
      - GITEA__database__DB_TYPE=postgres
      - GITEA__database__HOST=db:5432
      - GITEA__database__NAME=gitea
      - GITEA__database__USER=gitea
      - GITEA__database__PASSWD=gitea_pass_segura
    restart: always
    volumes:
      - ./gitea-data:/data
      - /etc/timezone:/etc/timezone:ro
    ports:
      - "3000:3000"   # interfaz web
      - "2222:22"     # SSH de Git
    depends_on:
      - db

  db:
    image: postgres:16
    restart: always
    environment:
      - POSTGRES_USER=gitea
      - POSTGRES_PASSWORD=gitea_pass_segura
      - POSTGRES_DB=gitea
    volumes:
      - ./pg-data:/var/lib/postgresql/data
docker compose up -d
docker compose logs -f gitea   # esperar a que esté listo

Configuración inicial (wizard)

Al abrir http://tu-servidor:3000 por primera vez aparece el instalador:

  1. Database: ya viene precargada por las variables de entorno.
  2. General: título del sitio y URL base (importante para clones correctos).
  3. Cuenta admin: crea el usuario administrador aquí mismo (si no, el primer registrado será admin).
  4. Opcional: desactivar autorregistro público si solo entrarán usuarios invitados.

Toda la configuración queda en /data/gitea/conf/app.ini; puedes editarla y reiniciar el contenedor.

HTTPS con proxy inverso

Gitea sirve HTTP plano; para HTTPS ponle delante Nginx, Caddy o Traefik. Ejemplo mínimo con Caddy (certificados automáticos):

# Caddyfile
git.tudominio.com {
    reverse_proxy localhost:3000
}

Con Nginx necesitas certbot para Let's Encrypt y pasar los headers correctos. Recuerda también configurar en app.ini:

[server]
ROOT_URL = https://git.tudominio.com/
PROTOCOL = http
HTTP_ADDR = 0.0.0.0

Copias de seguridad

Gitea incluye respaldo integrado que exporta repos, base de datos y configuración:

# Crear backup dentro del contenedor
docker exec -u git gitea \
  gitea dump -c /data/gitea/conf/app.ini

# Genera: gitea-dump-20260821.zip en /data (o donde corriste el comando)

# Restaurar: extraer el zip sobre /data y recuperar custom/, data/ y la BD

Automatiza el dump con cron y copia el zip a almacenamiento externo. Como los repos son archivos planos, incluso un rsync del volumen /data con Gitea detenido es una estrategia válida.
