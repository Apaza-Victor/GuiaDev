El problema de los archivos grandes en Git

Git guarda cada versión completa de los archivos binarios en su historial. Un PSD de 50 MB modificado 100 veces = ~5 GB de historial que cada clon debe descargar. Los repos crecen sin control y las operaciones se vuelven lentísimas.

Repositorio con binarios versionados:
commit 1: modelo.psd   (50 MB)  ─┐
commit 2: modelo.psd   (51 MB)   ├─ TODO queda en .git/ para siempre
commit 3: modelo.psd   (53 MB)  ─┘
→ clone de 154 MB por un archivo de 53 MB

Los diffs tampoco funcionan bien en binarios: no puedes ver "qué cambió" dentro de una imagen o video.

¿Cómo funciona Git LFS?

Git LFS (Large File Storage) reemplaza los archivos grandes en tu repo por pequeños punteros de texto; el contenido real se guarda en un servidor aparte especializado.

En el repositorio Git (liviano):
version https://git-lfs.github.com/spec/v1
oid sha256:4d7a214614ab2935c943f9e0ff69d22eadbb8f32...
size 52428800

El contenido real → servidor LFS (se descarga bajo demanda)
  • git status, log, checkout siguen funcionando igual.
  • Al hacer checkout, LFS descarga automáticamente los binarios reales.
  • El clon solo trae la versión actual de cada binario, no todo el historial.

Instalación y configuración

# Windows
winget install GitHub.GitLFS

# macOS
brew install git-lfs

# Linux (Debian/Ubuntu)
sudo apt install git-lfs

# ACTIVAR LFS en tu usuario Git (una sola vez por máquina)
git lfs install
# Updated Git hooks. Git LFS initialized.

Verifica con git lfs version. Si usas Windows, Git for Windows ya lo trae incluido — solo falta ejecutar git lfs install.

Rastrear patrones con .gitattributes

Dices a LFS qué archivos manejar con git lfs track. Esto escribe reglas en .gitattributes, que debe committearse:

# Rastrear por tipo
git lfs track "*.psd"
git lfs track "*.mp4"
git lfs track "assets/models/*.glb"

# Ver qué está siendo manejado
git lfs track --list
# *.psd filter=lfs diff=lfs merge=lfs -text

# IMPORTANTE: commitear .gitattributes ANTES de añadir los archivos
git add .gitattributes
git commit -m "chore: rastrear PSDs y videos con Git LFS"

Advertencia clave: LFS convierte a puntero los archivos añadidos después de la regla. Si un binario grande ya está en el historial, necesitas migrar el repo (lección siguiente).

# Confirmar que un archivo quedó como LFS
git lfs ls-files
# 52428800 modelo.psd  (-)
