Tipos numéricos

Elegir el tipo correcto define tamaño en disco, velocidad de índices y exactitud de cálculos. MySQL separa enteros (exactos) de decimales de coma flotante (aproximados) — y añade DECIMAL para exactitud decimal absoluta.

Decimales: la decisión crítica del dinero

TipoNaturalezaUso correcto
DECIMAL(M,D)EXACTO decimal fijo💰 Precios, saldos, impuestos — SIEMPRE
FLOATAproximado 4 bytesCientífico con tolerancia
DOUBLEAproximado 8 bytesEstadística, coordenadas GPS
 
CREATE TABLE productos (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nombre      VARCHAR(120) NOT NULL,
    precio      DECIMAL(10,2) NOT NULL,     -- hasta 99,999,999.99 EXACTO
    peso_kg     DECIMAL(6,3),               -- 999.999 gramos finos
    stock       INT UNSIGNED DEFAULT 0,
    es_activo   TINYINT(1) DEFAULT 1        -- booleano por convención
);

-- Demostración del error clásico:
SELECT CAST(0.1 AS DOUBLE) + CAST(0.2 AS DOUBLE);
-- 0.30000000000000004  ← FLOAT/DOUBLE aproximan
SELECT 0.1 + 0.2;   -- DECIMAL literal: 0.3 exacto ✅

Jamás guardes dinero en FLOAT/DOUBLE: los redondeos acumulados desequilibran contabilidad real. DECIMAL(12,2) para precios normales; BIGINT en centavos si el rendimiento extremo importa y controlas la conversión en app.

Charsets y collations

CREATE TABLE clientes (
    nombre VARCHAR(100)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- utf8mb4 = UTF-8 REAL (emojis incluidos). El "utf8" de MySQL es un
-- alias histórico de utf8mb3 que NO soporta emojis ni algunos símbolos.

El charset por defecto antiguo latin1 corrompe nombres con tildes al migrar. En MySQL 8 el default ya es utf8mb4, pero verifica bases heredadas con SHOW CREATE TABLE. Migrar charset después es doloroso: hazlo bien desde el día uno.

Fecha y hora

TipoFormatoRangoNotas
DATE'YYYY-MM-DD'1000-01-01 a 9999-12-31Solo fecha
DATETIME'YYYY-MM-DD HH:MM:SS'Igual que DATE8 bytes, sin zona horaria
TIMESTAMP'YYYY-MM-DD HH:MM:SS'1970 a 2038 ⚠️Guarda UTC, convierte según time_zone sesión
TIME'HH:MM:SS'-838 a 838 horasDuraciones posibles

CREATE TABLE pedidos (
    id           BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    creado_en    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    actualizado_en DATETIME NULL ON UPDATE CURRENT_TIMESTAMP,  -- auto-touch
    fecha_entrega DATE NULL
);

-- Funciones frecuentes:
SELECT NOW(), CURDATE();
SELECT DATE_ADD(creado_en, INTERVAL 30 DAY) FROM pedidos;
SELECT DATEDIFF(NOW(), creado_en) AS dias_transcurridos FROM pedidos;
SELECT DATE_FORMAT(creado_en, '%d/%m/%Y %H:%i') FROM pedidos;

-- TIMESTAMP con zona horaria automática:
SET time_zone = 'America/Mexico_City';
SELECT created_at FROM sesiones;   -- se muestra en TU zona aunque guarde UTC

Regla práctica moderna: DATETIME para todo por defecto (rango amplio, comportamiento predecible); TIMESTAMP solo cuando necesites conversión automática de zona horaria multi-región — y consciente del límite 2038.

Ejemplo integral: tabla bien tipada

CREATE TABLE empleados (
    id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    legajo          CHAR(8) NOT NULL UNIQUE,           -- código fijo
    nombre          VARCHAR(80) NOT NULL,
    email           VARCHAR(254) NOT NULL UNIQUE,
    salario         DECIMAL(11,2) NOT NULL,            -- 💰 exacto
    comision_pct    DECIMAL(4,2) NULL,                 -- 0.00–99.99
    fecha_nac       DATE NOT NULL,
    contratado_el   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    activo          TINYINT(1) NOT NULL DEFAULT 1,
    notas           TEXT NULL,
    perfil_json     JSON NULL,
    CONSTRAINT chk_salario CHECK (salario >= 0),
    INDEX idx_nombre (nombre),
    INDEX idx_contratado (contratado_el)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
Decisión de diseñoJustificación
INT UNSIGNED para PKNo existen IDs negativos; duplica techo gratis
DECIMAL para salario/comisiónDinero exacto, sin sorpresas FLOAT
VARCHAR dimensionado razonable80/254 cubren casos reales sin despilfarrar índice
TINYINT(1) para booleanoMySQL no tiene bool nativo; convención universal
DATETIME + DEFAULT CURRENT_TIMESTAMPAuditoría automática sin lógica app
utf8mb4 explícitoNombres internacionales + emojis seguros

VARCHAR(255) por inercia NO es diseño: piensa el largo real (¿nombre de 255 caracteres?). Índices sobre VARCHAR gigantes desperdician memoria y velocidad. Dimensiona con criterio del dominio.

Ejercicios prácticos

  1. Tabla inventario perfecta: diseña tabla productos con todos los tipos vistos correctamente elegidos; justifica cada tipo en comentario SQL.
  2. Demostración de precisión: inserta 0.1+0.2 en columna DOUBLE y en DECIMAL(10,2); SELECT ambas y documenta la diferencia observada.
  3. Emojis test: crea tabla con utf8mb4 e intenta insertar "🎉"; luego crea otra en latin1 y observa el fallo/corrupción.
  4. Zona horaria viva: tabla TIMESTAMP; SET time_zone distinto dos veces y consulta mismo registro mostrando cómo cambia la presentación.
  5. JSON flexible: tabla eventos con columna JSON de atributos variables; inserta tres eventos con estructuras distintas y consulta con ->>'$...' extrayendo campos.
