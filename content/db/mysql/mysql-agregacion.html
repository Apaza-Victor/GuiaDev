Funciones de agregación

Las funciones de agregación colapsan muchas filas en UN solo valor resumen. Son la base de todo reporting: totales, medias, conteos, extremos:

SELECT
    COUNT(*)                    AS total_pedidos,      -- cuenta FILAS
    COUNT(enviado_el)           AS pedidos_enviados,   -- ignora NULLs ⚠️
    SUM(total)                  AS facturado,
    AVG(total)                  AS ticket_medio,
    MIN(total)                  AS pedido_min,
    MAX(total)                  AS pedido_max,
    ROUND(AVG(total), 2)        AS ticket_redondeado
FROM pedidos
WHERE fecha >= '2026-01-01';
FunciónCon NULLs…Sobre conjunto vacío…
COUNT(*)Cuenta todas las filas0
COUNT(col)Salta los NULL0
SUM/AVGLos saltaNULL (no 0)
MIN/MAXLos saltaNULL

La distinción COUNT(*) vs COUNT(columna) es una pregunta de entrevista clásica y un bug real: "pedidos sin enviar" se calcula con COUNT(*) - COUNT(enviado_el), no con COUNT sobre columnas que crees que están vacías.

Agregaciones condicionales: SUM(CASE)

-- Varios KPIs en UN solo escaneo:
SELECT
    COUNT(*)                                        AS total,
    SUM(estado = 'pagado')                          AS pagados,       -- truco booleano MySQL
    SUM(estado = 'pendiente')                       AS pendientes,
    SUM(total)                                      AS ingresos_totales,
    SUM(IF(estado = 'pagado', total, 0))            AS ingresos_cobrados,
    ROUND(AVG(IF(estado='pagado', total, NULL)),2)  AS ticket_pagado  -- NULL excluye del AVG
FROM pedidos;

GROUP BY: agrupar por dimensiones

-- Ventas por categoría:
SELECT c.nombre AS categoria,
       COUNT(*) AS num_ventas,
       SUM(d.cantidad * d.precio_unit) AS ingreso
FROM detalle d
JOIN productos p ON p.id = d.producto_id
JOIN categorias c ON c.id = p.categoria_id
GROUP BY c.id, c.nombre          -- agrupar por PK + nombre (seguro)
ORDER BY ingreso DESC;

-- Múltiples dimensiones (año × mes):
SELECT YEAR(fecha) AS anio, MONTH(fecha) AS mes,
       COUNT(*) AS pedidos, SUM(total) AS facturado
FROM pedidos
GROUP BY anio, mes               -- MySQL permite alias en GROUP BY
ORDER BY anio, mes;

-- Agrupar por expresión:
SELECT LENGTH(email) AS largo_email, COUNT(*) AS cuantos
FROM clientes
GROUP BY largo_email;

ONLY_FULL_GROUP_BY: la regla que salva datos

Toda columna en SELECT debe estar en GROUP BY o dentro de un agregado. El modo ONLY_FULL_GROUP_BY (default en 5.7+) lo impone; desactivarlo para "que funcione" produce filas con valores ARBITRARIOS de grupos — bugs de reportes imposibles de rastrear. Si necesitas otra columna del grupo, usa ANY_VALUE() explícito o mejor diseño.

-- Ambos juntos: filtrar filas temprano (barato) y grupos tarde:
SELECT ciudad, COUNT(*) AS clientes, AVG(edad) AS edad_media
FROM clientes
WHERE activo = 1                        -- filtra FILAS primero
GROUP BY ciudad
HAVING COUNT(*) >= 10                   -- filtra GRUPOS después
   AND AVG(edad) BETWEEN 25 AND 60
ORDER BY clientes DESC;

-- ❌ error clásico: WHERE COUNT(*) > 1 → sintaxis inválida
-- ✅ siempre HAVING para condiciones agregadas

Window functions vs GROUP BY (MySQL 8+)

-- GROUP BY colapsa; OVER() mantiene el detalle fila a fila:
SELECT nombre, departamento, salario,
       AVG(salario) OVER (PARTITION BY departamento) AS media_depto,
       RANK() OVER (PARTITION BY departamento ORDER BY salario DESC) AS puesto
FROM empleados;
-- Cada empleado conserva su fila + contexto de su grupo ✨

Regla práctica: reporte resumido → GROUP BY. Ranking o comparación contra su grupo conservando detalle → window functions. Las ventanas NO reemplazan GROUP BY: resuelven otro problema.

GROUP_CONCAT y WITH ROLLUP

-- Concatenar valores del grupo en una lista:
SELECT c.nombre,
       GROUP_CONCAT(p.nombre ORDER BY p.nombre SEPARATOR ', ') AS productos_comprados
FROM clientes c
JOIN pedidos pd ON pd.cliente_id = c.id
JOIN detalle d ON d.pedido_id = pd.pedido_id
JOIN productos p ON p.id = d.producto_id
GROUP BY c.id, c.nombre;
-- Ana | Teclado, Monitor, Ratón

-- Subtotales jerárquicos automáticos:
SELECT YEAR(fecha) AS anio, estado, COUNT(*) AS pedidos, SUM(total) AS monto
FROM pedidos
GROUP BY anio, estado WITH ROLLUP;
-- filas por (año,estado)... + subtotal por año (estado=NULL) + TOTAL GENERAL
HerramientaRiesgo/límiteMitigación
GROUP_CONCATTrunca por defecto (1024 bytes)SET SESSION group_concat_max_len = 1000000
WITH ROLLUPNo combina con ORDER BY ni window functionsOrdenar en app o envolver en subconsulta

Las filas de subtotal de ROLLUP muestran NULL en las dimensiones colapsadas — confundibles con NULLs reales de datos. En app, detecta GROUPING()/NULL de dimensión y etiqueta como "TOTAL" antes de mostrar.

Ejercicios prácticos

  1. Dashboard mensual: ventas por año×mes con total, ticket medio y % crecimiento vs mes anterior (window LAG).
  2. Ranking de vendedores: RANK() OVER por departamento y global simultáneamente en una sola query.
  3. KPIs condicionales: una query con pagados/pendientes/cancelados, ingresos cobrados vs proyectados, todo vía SUM(CASE).
  4. Carritos legibles: GROUP_CONCAT de productos por pedido con cantidades formateadas ("Teclado x2, Monitor x1").
  5. Reporte con subtotales: GROUP BY país→ciudad WITH ROLLUP interpretando NULLs como subtotales/totales etiquetados.
