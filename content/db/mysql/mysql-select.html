SELECT básico, alias y proyección

SELECT es el verbo que usarás el 90% del tiempo: proyecta columnas de una tabla aplicando filtros, orden y formato. Dominar su orden de evaluación interna evita la mitad de los errores de sintaxis:

Orden lógico de ejecución

SELECT    [5. columnas/distinct]     ← lo último conceptualmente
FROM      [1. tabla(s)]
WHERE     [2. filtra FILAS]
GROUP BY  [3. agrupa]
HAVING    [4. filtra GRUPOS]
ORDER BY  [6. ordena]
LIMIT     [7. recorta]

Por eso un alias definido en SELECT no puede usarse en WHERE (aún no se evaluó), pero sí en ORDER BY (ya se evaluó). MySQL permite algunos atajos, pero el estándar y otros motores no: escribe pensando en este orden.

-- Proyección con alias:
SELECT
    nombre AS empleado,
    salario AS sueldo_mensual,
    salario * 12 AS sueldo_anual,
    CONCAT(nombre, ' <', email, '>') AS contacto
FROM empleados;

-- Columnas calculadas + funciones:
SELECT nombre,
       UPPER(email),
       YEAR(contratado_el) AS anio_ingreso,
       TIMESTAMPDIFF(YEAR, fecha_nac, CURDATE()) AS edad
FROM clientes;

WHERE: operadores y nulos

-- Operadores completos:
SELECT * FROM productos WHERE precio >= 50;
SELECT * FROM productos WHERE precio BETWEEN 20 AND 100;   -- inclusive ambos
SELECT * FROM clientes WHERE ciudad IN ('Madrid', 'Lima', 'Bogotá');
SELECT * FROM productos WHERE nombre LIKE '%pro%';         -- % cualquier cosa, _ un char
SELECT * FROM pedidos WHERE total NOT BETWEEN 10 AND 500;

-- Combinación booleana:
SELECT * FROM pedidos
WHERE (estado = 'pendiente' OR estado = 'procesando')
  AND total > 100;

-- NULL: JAMÁS con = (NULL = NULL devuelve NULL, ni true ni false):
SELECT * FROM clientes WHERE telefono = NULL;        -- ❌ siempre vacío
SELECT * FROM clientes WHERE telefono IS NULL;       -- ✅
SELECT * FROM clientes WHERE telefono IS NOT NULL;

-- Regex nativa:
SELECT * FROM productos WHERE sku REGEXP '^ABC-[0-9]{4}$';
Operador LIKECoincide con…Ejemplo match
'A%'Empieza por AAna, Adidas
'%ez'Termina en ezPérez, Martínez
'_a%'Segunda letra aMarta, Salas
'%ana%'Contiene anaHernández, Anaya

LIKE '%texto%' NO puede usar índices B-tree normales (búsqueda al inicio libre): sobre tablas grandes se convierte en full scan. Búsqueda textual seria → FULLTEXT index o motor de búsqueda dedicado.

ORDER BY y paginación LIMIT/OFFSET

-- Orden simple y múltiple:
SELECT nombre, precio FROM productos ORDER BY precio ASC;          -- default ASC
SELECT ciudad, apellido, nombre FROM clientes
ORDER BY ciudad ASC, apellido ASC, nombre ASC;

-- Expresiones y posiciones:
SELECT nombre, salario*12 AS anual FROM empleados ORDER BY anual DESC;
SELECT nombre, salario FROM empleados ORDER BY 2 DESC;             -- por columna 2 (frágil)

-- Paginación clásica (página 3, 20 por página):
SELECT * FROM productos
ORDER BY id
LIMIT 20 OFFSET 40;              -- o abreviado LIMIT 40, 20

-- El patrón "top N":
SELECT nombre, total FROM pedidos ORDER BY total DESC LIMIT 10;

Paginación profunda: OFFSET mata rendimiento

TécnicaPágina 1Página 10.000Nota
LIMIT 20 OFFSET NRápida ⚡Lentísima 🐌 (lee y descarta N filas)Sencilla; OK hasta ~10k filas
Keyset/cursor (seek)Rápida ⚡Igual de rápida ⚡Necesita columna ordenable única
 
-- Keyset: "siguiente página desde la última vista":
SELECT * FROM productos
WHERE (precio, id) < (29.99, 84512)   -- última fila de página anterior
ORDER BY precio DESC, id DESC
LIMIT 20;

Infinite scroll y "cargar más" modernos usan keyset pagination: guardan el último id/valor visto y consultan "desde ahí". OFFSET solo para paginadores numerados pequeños.

DISTINCT y combinación de resultados

-- Valores únicos de una columna:
SELECT DISTINCT ciudad FROM clientes ORDER BY ciudad;

-- Único por COMBINACIÓN completa:
SELECT DISTINCT ciudad, pais FROM clientes;

-- DISTINCT con agregación cuenta combinaciones únicas:
SELECT COUNT(DISTINCT pais) AS paises_con_clientes FROM clientes;

-- UNION: apila resultados eliminando duplicados (caro):
SELECT nombre AS dato, 'cliente' AS tipo FROM clientes WHERE pais='ES'
UNION
SELECT nombre, 'proveedor' FROM proveedores WHERE pais='ES';

-- UNION ALL: conserva duplicados, mucho más rápido:
SELECT producto_id FROM pedidos_2023
UNION ALL
SELECT producto_id FROM pedidos_2024;
OperadorDuplicadosCosteUso
UNIONElimina (sort/hash interno)AltoListados únicos cruzados
UNION ALLConservaMínimoApilar particiones/años/reportes

Si sabes que las ramas jamás comparten filas (particiones por año), UNION ALL siempre: UNION paga un dedupe innecesario. Y las columnas de todas las ramas deben coincidir en número y tipos compatibles — los nombres finales salen de la PRIMERA rama.

Ejercicios prácticos

  1. Catálogo filtrable: escribe 6 queries progresivas sobre productos: por rango de precio, por patrón de nombre, múltiples ciudades IN, combinadas AND/OR con paréntesis.
  2. Buscador de nulos: encuentra registros con teléfono NULL vs vacío '' y documenta por qué son distintos y cómo tratarlos.
  3. Paginador completo: implementa páginas 1-3 con LIMIT/OFFSET y luego versión keyset equivalente; EXPLAIN ambas comparando rows examined.
  4. Directorio unificado: UNION de clientes y proveedores con columna tipo, ordenado alfabético global; luego UNION ALL versionado por año.
  5. Cazador del LIMIT sin order: corre LIMIT 5 tres veces sobre tabla sin índice claro; observa variaciones si hay; añade ORDER BY y estabiliza.
