SELECT y alias

-- Proyección con alias (AS opcional pero recomendado):
SELECT
    nombre          AS empleado,
    salario         AS sueldo,
    salario * 12    AS sueldo_anual,
    FORMAT(salario, 'N2') AS formateado
FROM dbo.Empleados;

-- Alias con corchetes para espacios/caracteres raros:
SELECT nombre AS [Nombre Completo], salario AS [€/mes]
FROM dbo.Empleados;

-- Concatenación T-SQL (+) y CONCAT (NULL-safe):
SELECT nombre + ' ' + apellido AS nombre_completo,   -- NULL si algo es NULL ⚠️
       CONCAT(nombre, ' ', apellido) AS seguro,      -- trata NULL como ''
       CONCAT_WS(' ', nombre, apellido2, apellido) AS con_separador  -- 2017+
FROM dbo.Empleados;

El orden lógico de evaluación es idéntico a MySQL: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. Por eso un alias de SELECT no existe aún en WHERE, pero sí en ORDER BY.

TOP: el LIMIT de SQL Server

SELECT TOP 10 nombre, total FROM Pedidos ORDER BY total DESC;

-- Con porcentaje:
SELECT TOP 25 PERCENT nombre FROM Empleados ORDER BY salario DESC;

-- WITH TIES: empates incluidos (puede devolver MÁS de N filas):
SELECT TOP 5 WITH TIES nombre, salario
FROM Empleados ORDER BY salario DESC;

-- TOP sin ORDER BY = filas ARBITRARIAS (bug clásico):
SELECT TOP 10 * FROM Clientes;              -- ❌ ¿cuáles? nadie sabe
SELECT TOP 10 * FROM Clientes ORDER BY id;  -- ✅ determinista

-- Variables en TOP (no posible con OFFSET):
DECLARE @n INT = 20;
SELECT TOP (@n) * FROM Productos ORDER BY precio DESC;

TOP vs OFFSET-FETCH

CasoHerramientaEjemplo
N primeros/últimosTOP ✅ más directoSELECT TOP 5 ...
Paginación realOFFSET-FETCH ✅ único estándar aquíORDER BY ... OFFSET 40 ROWS FETCH NEXT 20
N dinámico por variableTOP(@var)SELECT TOP (@n)...

TOP requiere ORDER BY para tener sentido de negocio. "Los 10 mejores" sin orden definido son simplemente 10 filas al azar según el plan del motor — un bug silencioso que aparece cuando el plan cambia.

WHERE: operadores T-SQL

SELECT * FROM Productos WHERE precio >= 50;
SELECT * FROM Productos WHERE precio BETWEEN 20 AND 100;
SELECT * FROM Clientes WHERE pais IN ('ES','MX','AR');
SELECT * FROM Productos WHERE sku LIKE 'ABC-%';
SELECT * FROM Pedidos WHERE NOT (estado = 'cancelado');

-- Desigualdad estilo T-SQL (ambas válidas):
WHERE activo != 1
WHERE activo <> 1;

-- NULL: IS NULL / IS NOT NULL (nunca =):
WHERE telefono IS NULL;
WHERE telefono IS NOT NULL;

-- Fechas SARGable:
WHERE fecha_pedido >= '2026-01-01' AND fecha_pedido < '2026-02-01';

-- CASE dentro de WHERE (filtros condicionales):
WHERE CASE WHEN @solo_vip = 1 THEN vip ELSE 1 END = 1;

T-SQL tiene atajos propios potentes: IIF(cond, si, no), CHOOSE(n, v1, v2...) y el operador & bit a bit para flags. Úsalos donde simplifiquen, sin sacrificar portabilidad si tu código migrará algún día.

Paginación: OFFSET-FETCH

-- Página 3, 20 filas por página (estándar ANSI desde 2012):
SELECT id, nombre, precio
FROM dbo.Productos
ORDER BY precio DESC, id ASC          -- ORDER BY OBLIGATORIO para OFFSET
OFFSET 40 ROWS                        -- saltar 2 páginas completas
FETCH NEXT 20 ROWS ONLY;

-- Sin FETCH = solo saltar filas:
ORDER BY id OFFSET 100 ROWS;          -- todo menos los 100 primeros
TécnicaSintaxisRendimiento profundo
OFFSET-FETCHLimpia, ANSISe degrada con páginas altas (igual que LIMIT/OFFSET)
Keyset (seek method)WHERE clave > última vista + TOPConstante ⚡ recomendada en tablas grandes
ROW_NUMBER() en CTEFiltrando por número de filaClásica pre-2012; hoy OFFSET la reemplaza

OFFSET sin FETCH NEXT es legal y significa "salta N". Pero para paginar SIEMPRE acompaña FETCH NEXT n ROWS ONLY — y ORDER BY determinista con desempate por PK para páginas estables entre ejecuciones.

DISTINCT y combinación UNION

SELECT DISTINCT ciudad FROM Clientes ORDER BY ciudad;
SELECT DISTINCT ciudad, pais FROM Clientes;
SELECT COUNT(DISTINCT pais) AS paises_atendidos FROM Clientes;

-- UNION deduplica (sort interno caro):
SELECT nombre, 'cliente' AS origen FROM Clientes WHERE pais='ES'
UNION
SELECT razon_social, 'proveedor' FROM Proveedores WHERE pais='ES';

-- UNION ALL conserva duplicados y vuela:
SELECT producto_id FROM Ventas_2025
UNION ALL
SELECT producto_id FROM Ventas_2026;

-- EXCEPT e INTERSECT: exclusivos de T-SQL bien aprovechados:
SELECT email FROM Marketing_Lista
EXCEPT                                   -- en marketing pero NO clientes
SELECT email FROM Clientes;

SELECT sku FROM Catalogo_Web
INTERSECT                                -- disponibles en ambos canales
SELECT sku FROM Almacen_Central;
OperadorDuplicadosUso estrella
UNION / UNION ALLElimina / conservaApilar resultados homogéneos
EXCEPTElimina duplicados del resultadoDiferencias entre conjuntos ("quiénes NO")
INTERSECTDevuelve solo comunes únicosCruces de listas sin JOIN

EXCEPT e INTERSECT comparan TODAS las columnas del SELECT de cada lado y requieren mismo número/tipos. Para "filas de A sin match en B" suelen ser más claros y rápidos que LEFT JOIN + IS NULL.

Ejercicios prácticos

  1. Top-N variados: top 5 productos caros, top 10% empleados mejor pagados, top 3 WITH TIES por salario — verifica empates incluidos.
  2. Paginador completo: implementa página 1-4 con OFFSET/FETCH sobre productos ordenados por precio+id; valida estabilidad insertando una fila nueva entre páginas.
  3. Cazador de NULLs: compara concatenación + vs CONCAT vs CONCAT_WS con apellidos NULL; documenta cada resultado.
  4. Analista de conjuntos: resuelve tres preguntas con EXCEPT (clientes no compradores), INTERSECT (productos vendidos online y tienda), UNION ALL (ventas por año).
  5. Migrante MySQL→T-SQL: traduce 5 queries con LIMIT/DISTINCT tuyas a TOP/OFFSET-FETCH equivalentes verificando mismos resultados.
