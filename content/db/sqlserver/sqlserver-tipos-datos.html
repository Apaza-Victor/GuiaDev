Numéricos exactos: DECIMAL es el rey del dinero

La regla de oro que separa juniors de seniors: dinero NUNCA en FLOAT/REAL. Son binarios de aproximación: 0.1+0.2 ≠ 0.3. Todo lo que se suma, factura o audita usa tipos exactos:

TipoRango / precisiónBytesUso correcto
TINYINT0 a 2551Flags numéricos, edades, cantidades pequeñas
SMALLINT-32.768 a 32.7672Años, códigos cortos
INT±2.100 millones4IDs estándar, contadores ✅ default razonable
BIGINT±9×10¹⁸8IDs globales, logs masivos, tokens
DECIMAL(10,2)Exacto: p dígitos, s decimales5-17Dinero, tasas, medidas críticas 💰
FLOAT/REALAproximado IEEE7544-8Científicos, ML, coordenadas — NO dinero ⚠️
 
DECLARE @precio DECIMAL(10,2) = 12345678.91;   -- total: 10 dígitos, 2 decimales
DECLARE @f     FLOAT = 0.1 + 0.2;
SELECT @f, IIF(@f = 0.3, 'igual', '¡DIFERENTE!');   -- ¡DIFERENTE!

-- Overflow silencioso clásico:
SELECT 2147483647 + 1;          -- Arithmetic overflow error
SELECT CAST(2147483647 AS BIGINT) + 1;   -- ✅ 2147483648

Para porcentajes/tasas: DECIMAL(5,4) guarda 0.0000–9.9999 perfecto para "21%". Para división entera sorpresa: 5/2 = 2 en SQL Server; CAST uno de los operandos a DECIMAL si esperas 2.5.

Cadenas: CHAR vs VARCHAR vs NVARCHAR

TipoAlmacenamientoEjemplo 'Ana'Cuándo
CHAR(n)Fijo SIEMPRE n bytes (rellena espacios)'Ana' + 2 espaciosCódigos fijos: CP '28001', ISO 'ES', DNI
VARCHAR(n)Variable, 1 byte/char (ASCII/collation)3 bytesSolo si GARANTIZAS sin Unicode
NVARCHAR(n)Variable, 2 bytes/char UTF-166 bytesNombres, direcciones, TODO texto usuario ✅
VARCHAR(MAX)/NVARCHAR(MAX)Hasta 2 GB—Textos largos, JSON crudo — con coste rendimiento
 
CREATE TABLE Clientes (
    nombre      NVARCHAR(80)  NOT NULL,
    pais_iso    CHAR(2)       NOT NULL,          -- 'ES', 'MX'
    biografia   NVARCHAR(MAX) NULL,
    email       VARCHAR(120)  NOT NULL           -- emails son ASCII seguros
);

-- Truncamientos silenciosos según configuración:
SET ANSI_WARNINGS OFF;   -- ❌ 'Muy largo...' entra TRUNCADO sin avisar
SET ANSI_WARNINGS ON;    -- ✅ error "String or binary data would be truncated"

-- Longitud en BYTES vs CARACTERES:
SELECT LEN(N'ñandú') AS chars, DATALENGTH(N'ñandú') AS bytes;  -- 5, 10

Error histórico #1 de apps SQL Server: VARCHAR para nombres → "José" se guarda bien pero "李明" o emojis se rompen. NVARCHAR cuesta el doble de espacio y salva integridad de datos reales. Default NVARCHAR salvo evidencia contraria.

Fecha y hora: DATETIME2 y DATE son los ganadores

TipoPrecisiónRangoVeredicto
DATEDía exacto0001-9999Cumpleaños, fechas puras ✅ 3 bytes
TIME(p)Hasta 100nsHora del díaHorarios de atención
DATETIME2(p)Hasta 100ns0001-9999Timestamps modernos ✅ sucesor oficial
DATETIMEOFFSET+ zona horaria—Apps multi-zona serias
DATETIME3.33 ms (redondo)1753-9999Legacy: solo compatibilidad ⚠️
SMALLDATETIMEMinutos1900-2079Legacy compacto
 
DECLARE @ahora DATETIME2(3) = SYSDATETIME();
SELECT
    GETDATE()          AS legacy_ahora,
    SYSDATETIME()      AS moderno_ahora,
    SYSUTCDATETIME()   AS utc_recomendado_para_servidores,
    DATEADD(day, -7, @ahora)                    AS hace_una_semana,
    DATEDIFF(day, '2026-01-01', @ahora)         AS dias_del_anio,
    FORMAT(@ahora, 'yyyy-MM-dd HH:mm')          AS formateado;

-- Comparaciones seguras por rango (SARGable):
WHERE creado_el >= '2026-01-01' AND creado_el < '2026-02-01';
-- ❌ WHERE YEAR(creado_el) = 2026  → mata índices (función sobre columna)

Guarda timestamps de servidor en UTC (SYSUTCDATETIME()) y convierte a zona local SOLO al presentar. Mezclar horas locales de usuarios con DST es un infierno de datos imposible de auditar después.

Otros tipos útiles

CREATE TABLE Ejemplos (
    id            UNIQUEIDENTIFIER DEFAULT NEWID(),   -- GUID aleatorio
    activo        BIT             NOT NULL DEFAULT 1, -- true/false compacto (8 por byte)
    etiquetas     XML             NULL,               -- documentos XML validables
    config        NVARCHAR(MAX)   NULL,               -- JSON via ISJSON()/JSON_VALUE()
    foto          VARBINARY(MAX)  NULL,               -- blobs pequeños
    saldo_inicial MONEY           NOT NULL,           -- moneda (4 decimales fijos)
    direccion     GEOGRAPHY       NULL                -- espacial: lat/lng consultable
);

-- JSON moderno (2016+) sobre NVARCHAR:
INSERT INTO Ejemplos (config) VALUES ('{"tema":"oscuro","idioma":"es"}');
SELECT JSON_VALUE(config, '$.idioma') FROM Ejemplos WHERE ISJSON(config) = 1;

-- SEQUENCE: números compartidos entre tablas:
CREATE SEQUENCE seq_factura START WITH 1000 INCREMENT BY 1;
SELECT NEXT VALUE FOR seq_factura;

UNIQUEIDENTIFIERNEWID() aleatorio fragmenta índices clusteredNEWSEQUENTIALID() como default en tablas grandes
BITNo acepta otros valores que 0/1/NULLPerfecto para flags; no lo uses como TINYINT pequeño
MONEYDivisión/computo con redondeos peculiaresDECIMAL(19,4) suele preferirse hoy

Ejercicios prácticos

  1. Banco anti-FLOAT: tabla Cuentas con saldo FLOAT; acumula 100 depósitos de 0.10; compara contra DECIMAL(12,2). Documenta la divergencia.
  2. Laboratorio Unicode: inserta 'Ñoño 李明 😀' en VARCHAR y NVARCHAR; observa corrupción; explica DATALENGTH.
  3. Rango vs función: crea tabla 1M fechas; EXPLAIN ambas formas de filtrar año 2026 (YEAR() vs rango); compara lecturas lógicas.
  4. Calculadora temporal: con variables DATETIME2 calcula edad exacta, próximo cumpleaños, días hasta fin de trimestre — sin funciones de formato innecesarias.
  5. Diseñador de tipos: define la tabla Facturas completa eligiendo tipo justificado para cada columna (totales, IVA, número legal, fecha emisión, estado) y defiende cada elección.
