Clustered vs Nonclustered

La tabla solo puede tener UN índice clustered (define el orden físico de las filas; normalmente la PRIMARY KEY). Los nonclustered son estructuras aparte tipo "índice de libro".

CREATE NONCLUSTERED INDEX IX_Productos_Categoria
ON dbo.Productos (CategoriaId);

CREATE UNIQUE INDEX IX_Clientes_Email
ON dbo.Clientes (Email);

Índices con INCLUDE y filtrados

-- Covering index: la consulta se resuelve sin tocar la tabla
CREATE NONCLUSTERED INDEX IX_Ventas_Fecha
ON dbo.Ventas (Fecha) INCLUDE (Total);

-- Índice filtrado: solo filas relevantes
CREATE NONCLUSTERED INDEX IX_Pedidos_Pendientes
ON dbo.Pedidos (Fecha)
WHERE Estado = N'Pendiente';

Regla práctica: indexa las columnas del WHERE, JOIN y ORDER BY más frecuentes. Cada índice adicional ralentiza INSERT/UPDATE/DELETE.

Medir antes de optimizar

SET STATISTICS IO ON;    -- lecturas lógicas/físicas
SET STATISTICS TIME ON;  -- tiempo CPU

SELECT * FROM dbo.Productos WHERE CategoriaId = 2;

-- Ver los índices existentes
SELECT name, type_desc FROM sys.indexes
WHERE object_id = OBJECT_ID('dbo.Productos');

En SSMS activa Incluir plan de ejecución real (Ctrl+M): busca Table Scan en tablas grandes (malo) versus Index Seek (bueno).

Mantenimiento

UPDATE STATISTICS dbo.Productos;              -- refresca estadísticas
ALTER INDEX ALL ON dbo.Productos REORGANIZE;  -- desfragmentación ligera
ALTER INDEX ALL ON dbo.Productos REBUILD;     -- reconstrucción completa
