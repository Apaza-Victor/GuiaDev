Login vs Usuario

Un login da acceso al SERVIDOR; un usuario mapea ese login dentro de UNA base de datos. Son dos niveles.

-- Nivel servidor
CREATE LOGIN vendedor WITH PASSWORD = 'S3gura!2026', CHECK_POLICY = ON;

-- Nivel base de datos
USE Tienda;
CREATE USER vendedor FOR LOGIN vendedor;

Roles fijos de base de datos

ALTER ROLE db_datareader ADD MEMBER vendedor;   -- solo lectura
ALTER ROLE db_datawriter ADD MEMBER vendedor;   -- lectura/escritura
ALTER ROLE db_ddladmin  ADD MEMBER desarrollador; -- puede crear objetos

Roles clave: db_datareader, db_datawriter, db_ddladmin, db_owner (control total de la BD).

GRANT, DENY y REVOKE

GRANT SELECT, EXECUTE ON SCHEMA::ventas TO vendedor;
DENY DELETE ON dbo.Facturas TO vendedor;   -- gana sobre cualquier GRANT
REVOKE DENY ON dbo.Facturas FROM vendedor; -- revierte el DENY

Buenas prácticas

  • Usa Windows Authentication cuando sea posible (integrada con AD).
  • Principio de mínimo privilegio: nada de trabajar con sa.
  • Contraseñas con política (CHECK_POLICY = ON).
  • Audita con sys.server_principals, sys.database_permissions y SQL Server Audit.
-- ¿Quién tiene acceso y con qué permisos?
SELECT name, type_desc FROM sys.server_principals WHERE type IN ('S','U');
SELECT * FROM fn_my_permissions(NULL, 'DATABASE');
