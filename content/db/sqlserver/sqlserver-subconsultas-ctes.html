Subconsultas escalares y con IN

Una subconsulta es un SELECT dentro de otro. La escalar devuelve un único valor usable donde iría una columna; la de lista alimenta IN/ANY:

-- Escalar en SELECT (contexto por fila):
SELECT nombre,
       salario,
       (SELECT AVG(salario) FROM Empleados) AS media_empresa,
       salario - (SELECT AVG(salario) FROM Empleados) AS diferencia
FROM Empleados;

-- Escalar en WHERE:
SELECT * FROM Pedidos
WHERE total = (SELECT MAX(total) FROM Pedidos);

-- Lista con IN:
SELECT nombre FROM Clientes
WHERE cliente_id IN (
    SELECT cliente_id FROM Pedidos WHERE total > 1000
);

-- NOT IN + NULL = TRAMPA CLÁSICA:
SELECT * FROM Clientes
WHERE cliente_id NOT IN (SELECT cliente_id FROM Pedidos);
-- si la subconsulta devuelve UN NULL: resultado VACÍO siempre ⚠️

NOT IN con subconsulta que contenga un solo NULL devuelve cero filas silenciosamente (three-valued logic). Alternativas seguras: NOT EXISTS, o LEFT JOIN ... IS NULL. Es el bug #1 al migrar lógica entre motores.

EXISTS y correlacionadas

Una subconsulta correlacionada referencia columnas del query externo y se re-evalúa por fila. Con EXISTS solo importa SI existe match, no qué valores:

-- El patrón seguro anti-huérfanos:
SELECT c.nombre FROM Clientes c
WHERE EXISTS (
    SELECT 1 FROM Pedidos p          -- 1 = no leo datos, solo pruebo existencia
    WHERE p.cliente_id = c.cliente_id
      AND p.total > 1000
);

-- Y su negación segura:
SELECT c.nombre FROM Clientes c
WHERE NOT EXISTS (
    SELECT 1 FROM Pedidos p WHERE p.cliente_id = c.cliente_id
);   -- ✅ inmune a NULLs, optimizador lo adora

-- Correlacionada como columna calculada:
SELECT p.pedido_id, p.total,
       (SELECT SUM(total) FROM Pedidos x
        WHERE x.cliente_id = p.cliente_id) AS acumulado_cliente
FROM Pedidos p;
FormaCuándo ganaPeligro
IN (subquery)Listas pequeñas, sin NULLs posiblesNOT IN + NULL = vacío trampa
EXISTSSolo importa existencia; semántica NULL-safeNinguno relevante ✅ default profesional
Correlacionada escalarFilas pocas, índice cubre lookupRe-ejecución por fila en tablas enormes

El optimizador moderno reescribe IN↔EXISTS frecuentemente, pero la SEMÁNTICA difiere ante NULLs. Escribe EXISTS por defecto para "existe/no-existe" y deja IN para listas literales ('ES','MX','AR').

CTEs (Common Table Expressions)

Una CTE define conjuntos temporales CON NOMBRE que viven durante UNA sola sentencia — legibilidad estructurada sin persistir nada:

WITH VentasPorCliente AS (
    SELECT cliente_id, SUM(total) AS gastado
    FROM Pedidos
    GROUP BY cliente_id
),
ClientesVIP AS (
    SELECT cliente_id, gastado
    FROM VentasPorCliente           -- CTEs pueden encadenarse
    WHERE gastado > 5000
)
SELECT c.nombre, v.gastado
FROM ClientesVIP v
JOIN Clientes c ON c.cliente_id = v.cliente_id
ORDER BY v.gastado DESC;

-- CTE con parámetros de contexto (TOP/DELETE/UPDATE legibles):
WITH PeoresStock AS (
    SELECT TOP 10 producto_id
    FROM Productos ORDER BY stock ASC
)
DELETE FROM Productos
WHERE producto_id IN (SELECT producto_id FROM PeoresStock);

Mito frecuente: "la CTE materializa y se calcula una vez". Falso: SQL Server puede expandirla inline y re-evaluarla en cada referencia. Si tu CTE pesada se usa dos veces y notas doble coste → #tabla temporal con índice.

CTE recursiva: jerarquías completas

El superpoder exclusivo real de las CTEs: recorrerse a sí mismas. Ancla + recursión hasta agotar filas nuevas:

WITH Organigrama AS (
    -- ANCLA: la raíz:
    SELECT id, nombre, jefe_id, 0 AS nivel,
           CAST(nombre AS NVARCHAR(400)) AS ruta
    FROM Empleados WHERE jefe_id IS NULL

    UNION ALL

    -- RECURSIÓN: hijos del nivel anterior:
    SELECT e.id, e.nombre, e.jefe_id, o.nivel + 1,
           CAST(o.ruta + ' > ' + e.nombre AS NVARCHAR(400))
    FROM Empleados e
    JOIN Organigrama o ON e.jefe_id = o.id
)
SELECT REPLICATE(N'    ', nivel) + nombre AS organigrama, nivel, ruta
FROM Organigrama
ORDER BY ruta;

-- Descendientes de UN nodo concreto:
WITH Subordinados AS (
    SELECT id FROM Empleados WHERE jefe_id = @jefe
    UNION ALL
    SELECT e.id FROM Empleados e JOIN Subordinados s ON e.jefe_id = s.id
)
SELECT COUNT(*) AS reportes_totales FROM Subordinados;
PiezaRol
AnclaFilas iniciales (raíz o nodo de arranque)
UNION ALLUne ancla+recursión (ALL obligatorio aquí)
Miembro recursivoReferencia la propia CTE: genera siguiente nivel
OPTION (MAXRECURSION n)Tope iteraciones (default 100; 0 = ilimitado)

Datos ciclicos (A→B→C→A) disparan recursión infinita: error 530 al llegar a MAXRECURSION. Protege con rutas visitadas en la recursión o OPTION (MAXRECURSION 50) consciente mientras depuras.

Ejercicios prácticos

  1. Cazador de NOT IN: construye caso con NULL en sublista demostrando vaciado; reescribe con NOT EXISTS y compara planes.
  2. Pipeline legible: refactoriza una query de 4 niveles anidados en pipeline de 3 CTEs encadenadas con nombres de negocio.
  3. Organigrama completo: implementa la CTE recursiva con niveles y rutas; añade OPTION(MAXRECURSION) y cuenta iteraciones.
  4. BOM explosión: jerarquía de componentes de producto (pieza→subpiezas) recursiva sumando costes acumulados por rama.
  5. CTE vs #temp: CTE pesada referida 2 veces; mide lecturas vs versión #tabla temporal indexada; documenta cuándo cambia la balanza.
