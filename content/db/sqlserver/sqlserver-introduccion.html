Qué es SQL Server

Microsoft SQL Server es un sistema gestor de bases de datos relacionales (RDBMS) que habla el dialecto T-SQL (Transact-SQL), una extensión del SQL estándar con control de flujo, procedimientos y manejo de errores propios. Domina entornos corporativos Windows, ERP como Dynamics/SAP, y todo el ecosistema .NET.

ComponenteRol
Database EngineEl motor: almacena datos, ejecuta queries, gestiona transacciones y bloqueos
T-SQLLenguaje: SQL estándar + variables, IF/WHILE, TRY/CATCH, procedimientos
SQLOSCapa que administra memoria, hilos, planificadores y E/O del sistema operativo
Buffer PoolCaché en RAM de páginas de datos: la razón por la que las segundas lecturas vuelan

Aprender SQL Server después de MySQL es mayormente aprender diferencias: TOP en vez de LIMIT, corchetes [nombre] en vez de backticks, GETDATE() en vez de NOW(). El 80% del SQL que ya sabes funciona idéntico.

Instancias y bases de datos

SQL Server organiza su mundo jerárquicamente. Entender esta pirámide evita confusión cuando llegan los primeros errores de conexión:

Ver código PlantUML 
@startuml
skinparam backgroundColor #FDFDF8
skinparam defaultFontSize 11

title Organización lógica de SQL Server

package "Instancia\n(NOMBRE_SERVIDOR\\SQLEXPRESS)" {
  package "Bases del sistema" {
    [master] as m
    [model]
    [tempdb]
    [msdb]
  }
  database "MiTienda\n(base usuario)" as bd {
    folder "esquema dbo" {
      [Clientes]
      [Pedidos]
      [Productos]
    }
  }
}
@enduml
  • Instancia: el servidor en sí (motor + sus bases). Una máquina puede tener varias (default: sin nombre; nombrada: SERVIDOR\SQLEXPRESS).
  • Bases de sistema: master (catálogo y configuración), model (plantilla para nuevas bases), tempdb (espacio temporal compartido, se recrea en cada arranque), msdb (jobs y backups del Agent).
  • Bases de usuario: tus proyectos. Cada una contiene esquemas (dbo por defecto, otros para seguridad/organización) y dentro, tablas, vistas, procedures...
-- Referencias completas estilo T-SQL:
SELECT * FROM MiTienda.dbo.Clientes;
--           base . esquema . objeto

-- Cambiar contexto de base (el USE de toda la sesión):
USE MiTienda;
GO   -- GO NO es T-SQL: separador de lotes que entienden SSMS/sqlcmd

GO no es una sentencia T-SQL sino un separador de lotes del cliente. Fallará en drivers/applications que envían batches programáticamente. En scripts de app usa conexiones/batches separados reales, nunca GO.

Ejercicios prácticos

  1. Tour del entorno: abre SSMS, conecta, explora Object Explorer identificando las 4 bases del sistema y qué guarda cada una (sp_helpfile en cada una).
  2. Primera referencia triple: crea base PruebaDB, tabla dentro, y consúltala con nombre completo server-less: PruebaDB.dbo.Tabla.
  3. Cazador del GO: script con dos lotes separados por GO donde el segundo usa variable declarada en el primero; observa el error y explica por qué los lotes son independientes.
  4. tempdb volátil: crea tabla en tempdb, inserta filas, reinicia servicio SQL Server desde services.msc, verifica vaciado.
  5. Inventario de ediciones: SELECT @@VERSION y SERVERPROPERTY('Edition') — documenta qué tienes instalado y sus límites.
