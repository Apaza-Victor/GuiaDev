¿Qué es PlantUML?

PlantUML es una herramienta open source que genera diagramas a partir de texto plano. Escribes una descripción declarativa, y el motor la renderiza como imagen. Su filosofía es la misma que Markdown hizo popular para documentos: los diagramas como código.

@startuml
class Usuario {
  -email : String
  +login()
}

class Sesion {
  -token : String
}

Usuario "1" --> "*" Sesion : abre
@enduml

Ese bloque de texto produce un diagrama de clases completo y determinista: el mismo código genera siempre la misma imagen. Soporta casi todos los diagramas UML (clases, secuencia, casos de uso, estados, componentes, despliegue...) más extras como Gantt, JSON y YAML visualizados.

Puedes probarlo sin instalar nada en plantuml.com/plantuml (editor online) o con las extensiones oficiales para VS Code e IntelliJ.

Sintaxis esencial

Todo diagrama vive entre @startuml y @enduml. Los bloques fundamentales:

DiagramaInstrucciones clave
Secuenciaactor, participant, ->, -->, alt/else/end, loop ... end
Clasesclass Nombre { }, visibilidad + - # ~, flechas -->, --|>, *--
Casos de usoactor, usecase, (Texto), -- para asociaciones
Estadosstate, [*] --> EstadoInicial, Estado1 --> Estado2 : evento
Componentescomponent, interface, package, ..>

Decoradores útiles que elevan la calidad al instante:

  • skinparam: colores, fuentes, estilo de líneas (skinparam linetype ortho para ángulos rectos).
  • title y caption: título del diagrama y numeración de figuras.
  • note left/right/top of X: anotaciones sobre cualquier elemento.
  • !theme: temas predefinidos (por ejemplo !theme cerulean-outline).

PlantUML en tu flujo de trabajo

Aquí es donde brilla frente a los editores gráficos: los archivos .puml son texto, y el texto se lleva bien con todo lo que ya usas:

  • Git: diffs línea a línea, pull requests que muestran exactamente qué cambió en el diseño, sin binarios.
  • Documentación viva: incrusta el mismo archivo fuente en README, wikis o docs generadas (MkDocs, Docusaurus) vía extensiones o CI.
  • CI/CD: regenera las imágenes en cada build y falla el pipeline si un .puml tiene error de sintaxis — tus diagramas nunca quedan obsoletos en silencio.
  • IDEs: VS Code (extensión PlantUML) e IntelliJ ofrecen preview en vivo mientras escribes.
# Renderizar localmente (requiere Java + Graphviz)
java -jar plantuml.jar diagramas/*.puml

# O con Docker, sin instalar dependencias
docker run --rm -v $(pwd):/data plantuml/plantuml /data/*.puml

Conviención recomendada: guarda los .puml junto al código que documentan (docs/diagrams/) y referencia las imágenes generadas desde el README. El diseño viaja con la implementación, nunca se separan.

Ventajas y limitaciones

VentajasLimitaciones
Versionable en Git con diffs realesControl fino del layout limitado: el motor decide posiciones
Rápido: editar texto es mucho más veloz que arrastrar cajasCurva inicial de sintaxis por tipo de diagrama
Determinista y consistente entre autoresDiagramas muy grandes requieren partición manual
Automatizable en pipelines y docsNecesita Java/Graphviz (o servidor remoto) para renderizar
Gratis, open source, comunidad enormeAlgunos diagramas exóticos de UML (tiempos avanzados) son básicos

Regla de decisión: si tu prioridad es mantener documentación arquitectónica viva y versionada, PlantUML es imbatible. Si necesitas maquetar un diagrama "de marketing" con estética milimétrica, un editor visual te costará menos pelea.
