5.1. ¿Qué son los fragmentos combinados?

Los fragmentos combinados (combined fragments) son marcos rectangulares con una esquina etiquetada (pentágono) que indican el operador de control de flujo: alt, opt, loop, par, etc. Cubren un segmento de las líneas de vida y permiten modelar condicionales, bucles y concurrencia sin salir del diagrama.

┌─ alt ────────────────────────────────┐
│ [condición A]                        │
│ A → B : mensaje1()                   │
├──────────────────────────────────────┤
│ [condición B]                        │
│ A → B : mensaje2()                   │
└──────────────────────────────────────┘

La condición entre corchetes se llama guarda. Un alt divide el marco en regiones separadas por línea discontinua; se ejecuta solo la primera cuya guarda sea verdadera.

5.2. alt: alternativas condicionales

Equivalente a un if / else if / else. Ejemplo: procesamiento de pago:

@startuml
actor Cliente
participant "Checkout" as CO
participant "PasarelaPago" as PP

Cliente -> CO : confirmarPedido()
CO -> PP : cobrar(total)
alt pago aprobado
  PP --> CO : autorizacion(nro)
  CO --> Cliente : pedidoConfirmado()
else tarjeta rechazada
  PP --> CO : error(fondoInsuficiente)
  CO --> Cliente : solicitarOtroMedio()
else pasarela caída
  PP --> CO : timeout
  CO --> Cliente : reintentarMasTarde()
end
@enduml

Regla: la última región puede quedar sin guarda para actuar como "else". Si todas las guardas son excluyentes, el diagrama documenta decisiones de negocio verificables.

5.3. opt: opción única

opt es un alt de una sola región: si la guarda es verdadera se ejecuta, si no, se omite. Ideal para comportamiento opcional como cupones o logs:

@startuml
participant Carrito
participant Tienda

Tienda -> Carrito : aplicarCupon(codigo)
opt codigo valido
  Carrito -> Tienda : descuento(porcentaje)
end
@enduml

5.4. loop: iteraciones

El operador loop acepta una especificación de repetición en la guarda: [min, max], [i = 1..n] o condiciones libres.

@startuml
participant App
participant API

App -> API : GET /productos?pagina=1
loop mientras hayaPaginaSiguiente [pag <= total]
  App -> API : GET /productos?pagina=sig
  API --> App : lote(productos)
end
@enduml

Sugerencia: escribe la condición en lenguaje natural cuando el detalle numérico no aporta claridad ("mientras queden ítems por validar").

5.5. par: concurrencia paralela

par divide el flujo en regiones que ocurren simultáneamente, en cualquier orden o intercaladas. Es la forma correcta de modelar operaciones independientes:

@startuml
participant ServicioPedido
participant Inventario
participant Facturacion
participant Notificaciones

ServicioPedido -> Inventario : reservarStock(pedido)
ServicioPedido -> Facturacion : emitirFactura(pedido)
par notificaciones paralelas
  ServicioPedido -> Notificaciones : email(cliente)
else
  ServicioPedido -> Notificaciones : push(app)
end
@enduml

Útil también para documentar dónde el código real usa Promise.all, goroutines o hilos.

5.6. break, critical y neg

  • break: si su guarda se cumple, la secuencia del fragmento contenedor se abandona (equivalente al break/excepción temprana).
  • critical: región que debe ejecutarse atómicamente, sin interleaving de otros flujos (secciones críticas, transacciones).
  • neg: escenario inválido que el sistema debe prevenir; sirve para documentar restricciones y casos de abuso.
  • ref: referencia a otra interacción definida en otro diagrama, evitando duplicación.
@startuml
participant Gateway
participant Cuenta

Gateway -> Cuenta : retirar(monto)
break saldo insuficiente
  Cuenta --> Gateway : rechazo("fondos insuficientes")
end
critical transaccion atomica
  Cuenta -> Cuenta : debitar(monto)
  Cuenta -> Cuenta : registrarMovimiento()
end
@enduml

5.7. Ejemplo completo combinando fragmentos

Proceso de compra que combina los cinco operadores principales:

@startuml
actor Usuario
participant "App" as App
participant "API" as API

Usuario -> App : finalizarCompra()
opt hay cupon
  App -> API : validarCupon()
end
API -> API : calcularTotal()

alt stock disponible
  loop cada producto del carrito
    API -> API : reservarUnidad()
  end
  par envio de confirmaciones
    API -> App : email()
  else
    API -> App : push()
  end
  App --> Usuario : compra exitosa
else sin stock
  break producto agotado
    App --> Usuario : aviso de agotamiento
  end
end
@enduml

Buena práctica final: no anides más de dos niveles de fragmentos; si necesitas más profundidad, extrae una interacción aparte con ref.
