Diagrama de Secuencia

Muestra el orden temporal de los mensajes entre objetos. Las figuras clave son: rectángulos (objetos), líneas de vida verticales y flechas de mensaje.

Ver código PlantUML 
@startuml
title Diagrama de Secuencia: Compra online
actor Cliente
participant "Web" as Web
participant "Servicio" as Serv
participant "BD" as BD
Cliente -> Web : hacerPedido()
Web -> Serv : crearPedido()
Serv -> BD : insertar(pedido)
BD --> Serv : ok
Serv --> Web : pedidoId
Web --> Cliente : confirmación
@enduml

Figuras presentes

FiguraPapel en este diagrama
RectánguloCada participante (Cliente, Web, Servicio, BD).
Línea de vidaLínea vertical punteada que muestra el tiempo de vida de cada objeto.
Flecha llenaMensaje síncrono: quien llama espera respuesta.
Flecha punteadaMensaje de retorno: la respuesta al que llamó.
En la línea de vida, un rectángulo delgado (focus/activation) indica el período en que el objeto está procesando. El tiempo fluye de arriba hacia abajo.

Diagrama de Componentes

Muestra los módulos de software (componentes) y sus dependencias. Figuras clave: componente (rectángulo con pestañas), paquete y cilindro de base de datos.

Ver código PlantUML 
@startuml
title Diagrama de Componentes
package "Frontend" {
  [Vue App] as FA
  [UI Components] as UC
}
package "Backend" {
  [API REST] as API
  [Servicio de Pago] as Pago
}
package "Datos" {
  database "PostgreSQL" as DB
}
FA --> UC
UC --> API : HTTP
API --> Pago
API --> DB : JDBC
@enduml

Figuras presentes

FiguraPapel en este diagrama
ComponenteCada módulo ejecutable: la app Vue, la API REST, el servicio de pago.
PaqueteAgrupa los componentes por capa (Frontend, Backend, Datos).
CilindroLa base de datos PostgreSQL.
Flecha de dependenciaLa relación de uso entre componentes (UC → API).
El diagrama de componentes responde a "¿de qué módulos se compone el sistema y cómo se comunican?". Ideal para explicar una arquitectura por capas.

Diagrama de Despliegue

Modela la infraestructura física: servidores, nodos y dónde se ejecuta cada artefacto. Figuras clave: nodo y artefacto.

Ver código PlantUML 
@startuml
title Diagrama de Despliegue
node "Servidor Web" {
  artifact "app.war"
  [Nginx] as nginx
}
node "Servidor App" {
  [Tomcat] as tomcat
}
node "Servidor BD" {
  database "MySQL" as mysql
}
nginx --> tomcat
tomcat --> mysql
@enduml

Figuras presentes

FiguraPapel en este diagrama
NodoCada servidor/máquina (Servidor Web, App, BD).
ArtefactoEl archivo desplegable (app.war).
Componente internoEl software que corre dentro del nodo (Nginx, Tomcat).
CilindroLa base de datos MySQL alojada en su nodo.
Es el diagrama favorito para hablar de arquitectura en la nube: muestra dónde vive cada parte del sistema y la comunicación entre servidores.

Diagrama de Estados

Muestra los estados por los que pasa un objeto y las transiciones que lo mueven de uno a otro. Figuras clave: estado (rectángulo redondeado) y el óvalo inicial/final.

Ver código PlantUML 
@startuml
title Diagrama de Estados: Pedido
[*] --> Nuevo
Nuevo --> Enviado : confirmar()
Enviado --> Entregado
Enviado --> Cancelado : cancelar()
Entregado --> [*]
Cancelado --> [*]
@enduml

Figuras presentes

FiguraPapel en este diagrama
Estado (rectángulo redondeado)Cada situación del objeto: Nuevo, Enviado, Entregado.
Óvalo rellenoEstado inicial [*].
Óvalo con anilloEstado final [*] al que se llega al terminar.
Flechas con etiquetaTransiciones disparadas por eventos (confirmar(), cancelar()).
Ideal para modelar máquinas de estado: pedidos, sesiones, tickets o flujos de aprobación.

Diagrama Entidad-Relación

Modela las entidades de datos y sus relaciones, la base para diseñar bases de datos. Figuras clave: entidad (rectángulo), relación (rombo) y multiplicidad.

Ver código PlantUML 
@startuml
title Diagrama Entidad-Relación
entity Cliente {
  * id
  --
  nombre
  email
}
entity Pedido {
  * id
  --
  fecha
  total
}
entity Producto {
  * id
  --
  nombre
  precio
}
Cliente ||--o{ Pedido : realiza
Pedido }o--o{ Producto : contiene
@enduml

Figuras presentes

FiguraPapel en este diagrama
Entidad (rectángulo)Cada tabla/concepto con sus atributos (Cliente, Pedido, Producto).
Atributo clave (* id)La clave primaria de cada entidad.
Multiplicidad (||, o{)La cardinalidad: uno (||) a muchos (o{).
Relación (etiqueta)El verbo que describe el vínculo: realiza, contiene.
Notación de cardinalidad de crow's foot: || = uno, o{ / |{ = muchos, o = cero o uno. Aquí un Cliente (1) tiene muchos Pedidos (*) y un Pedido tiene muchos Productos (*).
