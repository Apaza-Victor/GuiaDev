Figuras de estructura y comportamiento

Estas son las figuras que representan entidades, acciones, decisiones y estados. Son el corazón de casi todos los diagramas UML.

Figuras principales

FormaQué representaDetalles de la notaciónDiagramas donde aparece
RectánguloClase / EntidadDividido en 3 compartimentos: nombre, atributos, métodos. Opcionalmente 2 (sin métodos) o 1 (solo nombre).Clases, ER
AcciónActividadUna sola tarea que se ejecuta de forma atómica.Actividades
DecisiónDecisiónPunto de bifurcación con etiquetas sí/no (o true/false) en cada salida.Actividades, Secuencia
InicioNodo inicial del flujo (círculo relleno).Actividades, Estados
FinNodo final (círculo con anillo exterior). Puede haber varios finales.Actividades, Estados
ActorFigura de palo: persona u organismo externo que interactúa.Casos de uso
Caso de usoCaso de usoFuncionalidad que el sistema ofrece a un actor.Casos de uso
 Línea de vidaObjeto + línea de vidaRectángulo con el nombre del objeto y una línea vertical punteada que muestra su existencia en el tiempo.Secuencia
Atención a la confusión clásica: el rombo en actividades = decisión (flujo), pero en clases / ER el rombo significa relación/composición. Siempre interpreta el rombo según el tipo de diagrama.

Figuras de agrupación y anotación

Estas figuras no representan datos ni acciones, sino que agrupan o comentan el diagrama para hacerlo más legible.

Agrupación y comentarios

FormaQué representaCómo se dibujaEjemplo de uso
PaquetePaquete / móduloRectángulo con una pestaña en la esquina superiorAgrupa clases de un mismo dominio: "modelo", "controlador"
ComponenteComponenteRectángulo con dos pestañas a la izquierdaUn módulo ejecutable: "API REST", "Servicio de pago"
NodoNodo / nodo de despliegueRectángulo o cubo (3D) según el estiloUn servidor físico o máquina: "Servidor web"
NotaNota / comentarioRectángulo con la esquina superior derecha dobladaAclarar un paso o una regla de negocio sin añadir clases
«interface»Estereotipo«nombre» entre comillas dobles angulares sobre el elemento«interface», «enum», «controller»
Buena práctica: los paquetes ayudan a limitar la complejidad (regla de ~15 elementos por diagrama) y las notas permiten documentar decisiones sin ensuciar el modelo con clases falsas.

En notación estricta, el nodo de despliegue se dibuja como un cubo 3D; en muchas herramientas (draw.io, PlantUML) se simplifica a un rectángulo con nombre. Ambos son válidos mientras seas consistente.

Catálogo visual con PlantUML

Este diagrama reúne todas las figuras del catálogo en un solo lugar para que las veas todas de un vistazo.

Ver código PlantUML 
@startuml
title Catálogo de Figuras UML
rectangle "Rectángulo\n(clase)"
rectangle "Acción" as act
actor "Actor"
usecase "Caso de uso"
package "Paquete" {
  component "Componente"
  node "Nodo"
  database "Base de datos"
  note right of act : Nota\n(comentario)
  state "Estado"
}
@enduml
Resumen de todo el catálogo:
· Rectángulo = clase/entidad · Rectángulo redondeado = acción · Rombo = decisión · Óvalo = inicio/fin · Persona = actor · Elipse = caso de uso · Paquete = módulo · Componente = pieza de software · Nodo = máquina · Nota = comentario · Cilindro = base de datos.
