Formas básicas y su significado

Cada forma UML (rectángulo, rombo, óvalo...) tiene un significado concreto y normalizado. Usar bien estas formas es lo que hace que cualquier persona del equipo lea el diagrama sin ambigüedad.

Recetario de formas

FormaNombre técnicoQué representaDónde se usa
RectánguloClass / EntidadUna clase, entidad o componente con estado y comportamientoDiagramas de clases, componentes, ER
AcciónActividadUn paso, acción o tarea que se ejecutaDiagramas de actividades
DecisiónCondiciónUn punto en el que el flujo se bifurca según una condiciónDiagramas de actividades, secuencia
Nodo inicial / finalEl comienzo o el final del flujoDiagramas de actividades y estados
ActorUna persona, sistema o entidad externa que interactúaDiagramas de casos de uso
Caso de usoUse caseUna funcionalidad o servicio que ofrece el sistemaDiagramas de casos de uso
Ideas clave: el rectángulo representa cosas con identidad propia (clases, entidades); el rombo siempre implica tomar una decisión sí / no; el óvalo marca el inicio y el fin de un flujo.

Líneas y flechas de relación

Las conexiones entre formas comunican tipos de relación. No todas las líneas significan lo mismo: la forma y el extremo de la flecha cambian el significado.

Vocabulario de líneas

LíneaNombreSignificado
AsociaciónConexión simple o "usa/está conectado con"
Dependencia / flujo"Usa", "depende de", o dirección del flujo
Herencia / generalización"Es un tipo de": una clase hereda de otra
Composición"Está compuesto por": parte inseparable del todo
Agregación"Contiene": una colección de elementos
Mensaje asíncrono / dependenciaEn secuencia: mensaje; en clases: dependencia débil
Truco para recordarlo: punta hueca (▷) = herencia ("es un"); rombo relleno (◆) = composición ("vive dentro de"); rombo vacío (◇) = agregación ("contiene una colección de").

Formas por tipo de diagrama

Cada diagrama usa un subconjunto de formas. Esta referencia te dice qué símbolos esperar en cada tipo.

Mapa de formas por diagrama

DiagramaFormas principalesRelaciones
ClasesRectángulos (clases) con atributos y métodosAsociación, herencia, composición, agregación
ActividadesRectángulos redondeados (acciones), rombos (decisiones), óvalos (inicio/fin)Flechas de flujo (sí/no)
Casos de usoFiguras humanas (actores), elipses (funciones)Flechas de asociación actor→caso
SecuenciaRectángulos (objetos) + líneas de vida (líneas punteadas verticales)Flechas de mensajes (síncronas/asíncronas)
Componentes / DespliegueRectángulos con dos pestañas (componentes), cajas (nodos)Dependencias e interfaces
Entidad-RelaciónRectángulos (entidades), rombos (relaciones)Líneas con cardinalidad (1..*, 1..1)

Nota sobre cardinalidades

En entidad-relación y clases, los extremos de las líneas llevan números de multiplicidad: 1 (exactamente uno), 0..* (cero o muchos), 1..* (uno o muchos). Esta notación dice cuántos elementos del otro lado participan en la relación.

Ejemplos visuales combinados

Estos ejemplos muestran las formas en acción dentro de diagramas reales.

Rombo y flujo con decisión

Ver código PlantUML 
@startuml
if (¿saldo suficiente?) then (sí)
  :Procesar pago;
else (no)
  :Mostrar error;
endif
:Enviar confirmación;
@enduml

Aquí el rombo es la decisión central: el flujo se divide en dos ramas según la condición "¿saldo suficiente?". Los rectángulos redondeados son las acciones que se ejecutan en cada rama.

Óvalo de inicio y fin

Ver código PlantUML 
@startuml
start
:Ingresar datos;
:Validar formulario;
stop
@enduml

El óvalo relleno (inicio) y el óvalo con círculo concéntrico (fin) delimitan el flujo: todo proceso tiene exactamente un inicio y puede tener uno o más finales (éxito, error, cancelación).

Rectángulos: clases y relaciones

Ver código PlantUML 
@startuml
class Usuario {
  -id : int
  -nombre : string
  +autenticar() : bool
  +cambiarPassword() : void
}
class Pedido {
  -numero : int
  +crear() : void
  +confirmar() : void
}
Usuario "1" -- "0..*" Pedido : realiza
@enduml

Cada rectángulo es una clase dividida en tres compartimentos (nombre, atributos, métodos). La línea con multiplicidad "1" a "0..*" indica que un usuario realiza cero o muchos pedidos.

Actores y casos de uso

Ver código PlantUML 
@startuml
left to right direction
actor "Cliente" as C
actor "Sistema de Pago" as P
rectangle Sistema {
  usecase "Registrarse" as U1
  usecase "Hacer pedido" as U2
  usecase "Pagar" as U3
}
C --> U1
C --> U2
U2 --> U3
U3 --> P
@enduml

Las figuras de persona son actores (externos) y las elipses son casos de uso (funciones). El rectángulo delimita el sistema y muestra qué interacciones pasan del actor al sistema.

Resumen: rectángulo = cosa/concepto · rectángulo redondeado = acción · rombo = decisión · óvalo = inicio/fin · persona = actor · elipse = función. Domina estas seis formas y podrás leer la mayoría de diagramas UML.
