¿Qué es un diagrama de objetos?

El diagrama de objetos es una fotografía del sistema en un instante concreto de su ejecución: muestra las instancias reales existentes en memoria, con sus valores concretos y los enlaces activos entre ellas.

Mientras el diagrama de clases describe el plano ("toda Persona tiene nombre y edad"), el de objetos captura el edificio construido ("ahora mismo existen Ana(34) y Luis(28), y Ana es amiga de Luis").

  • Nivel tipo: Clases → describe todos los posibles sistemas.
  • Nivel instancia: Objetos → describe UNA configuración concreta.

Es el diagrama estructural menos usado de forma independiente, pero muy valioso como complemento explicativo.

┌──────────────────┐
│  ana : Persona   │   ← nombre : Clase, todo subrayado
├──────────────────┤
│ edad = 34        │   ← valores concretos
│ ciudad = "Lima"  │
└──────────────────┘

Relación con el diagrama de clases

Cada objeto debe ser instancia de una clase existente, y cada enlace debe ser instancia de una asociación declarada. El diagrama de objetos es entonces una prueba de consistencia:

@startuml
class Departamento {
  nombre : String
}
class Empleado {
  nombre : String
}
Departamento "1" -- "0..*" Empleado : emplea

object "RRHH" as d1 {
  nombre = "Recursos Humanos"
}
object "ana : Empleado" as e1 {
  nombre = "Ana Torres"
}
object "luis : Empleado" as e2 {
  nombre = "Luis Rojas"
}
d1 --> e1
d1 --> e2
@enduml

Lectura: RRHH es un Departamento real; Ana y Luis son Empleados reales; ambos enlaces materializan la asociación 1 a muchos "emplea". Si dibujas un enlace que no existe como asociación, hay error de diseño.

Cuándo usarlo

  • Explicar estructuras recursivas o complejas: árboles, grafos y listas enlazadas se entienden mejor con instancias concretas que con la clase abstracta Nodo<T>.
  • Documentar casos de prueba: "con estos tres pedidos y este cliente, el sistema debe..." — el diagrama de objetos ES ese escenario de datos.
  • Diseñar fixtures de test: lo que dibujas en el diagrama es literalmente el arrange de tu unit test.
  • Enseñar OO: para estudiantes, ver la diferencia clase/instancia dibujada elimina años de confusión.
  • Comunicar snapshots de negocio: "estado actual del inventario", "carrito de María ahora".

Regla práctica: úsalo cuando el valor está en los valores concretos y las relaciones entre instancias específicas; si te interesa solo la estructura general, quédate con el de clases.
