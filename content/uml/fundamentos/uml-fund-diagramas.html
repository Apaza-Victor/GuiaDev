Los 7 diagramas estructurales

DiagramaQué muestraPregunta que responde
ClasesTipos, atributos, operaciones y relaciones estáticas¿Cómo está organizado el código?
ObjetosInstancias concretas con valores en un instante dado¿Cómo se ve el sistema en ejecución?
ComponentesBloques de software intercambiables e interfaces¿Cómo se conectan los módulos?
DespliegueNodos físicos y artefactos sobre ellos¿Dónde corre cada cosa?
PaquetesAgrupaciones lógicas y dependencias entre ellas¿Cómo se estructura a gran escala?
Estructura compuestaPartes internas de una clase o componente¿Cómo funciona por dentro esta pieza?
PerfilExtensiones del propio lenguaje (meta-modelado)¿Cómo adapto UML a mi dominio?

En proyectos web típicos se usan intensivamente: Clases, Componentes, Despliegue y Paquetes.

Los 7 diagramas de comportamiento

DiagramaQué muestraPregunta que responde
Casos de UsoFuncionalidad visible para actores externos¿Qué hace el sistema para sus usuarios?
ActividadesFlujos de trabajo con decisiones y paralelismo¿Cuál es el proceso paso a paso?
Estados (State Machine)Ciclo de vida de un objeto según eventos¿Qué estados tiene y cómo transita?
SecuenciaIntercambio de mensajes ordenado en el tiempo¿Quién llama a quién y cuándo?
ComunicaciónMensajes numerados sobre una red de objetos¿Quién está conectado con quién?
Tiempos (Timing)Restricciones temporales y cambios de estado vs reloj¿Cuánto tarda cada fase? (embebidos)
Visión general de interacciónResumen de varias interacciones como actividades¿Cómo se encadenan escenarios grandes?

Consejo práctico: domina primero Clases + Secuencia + Casos de Uso. Con esos tres cubres el 90% de las conversaciones técnicas. El resto se aprende según lo necesite tu dominio.

Cómo se relacionan entre sí

  • Casos de Uso → Secuencia: cada caso de uso importante merece uno o más diagramas de secuencia detallando su realización.
  • Clases ↔ Objetos: el diagrama de objetos es una instantánea válida solo si es consistente con el diagrama de clases (mismo tipo, mismas asociaciones).
  • Componentes → Despliegue: los componentes definen qué; el despliegue define dónde corren.
  • Estados ↔ Clases: las clases con ciclo de vida rico (Pedido, Cuenta) suelen llevar su propia máquina de estados adjunta.
  • Actividades ↔ Secuencia: ambos muestran comportamiento; actividades priorizan el flujo lógico, secuencia los mensajes entre objetos.
REQUISITOS ──► Casos de Uso
                    │
ANÁLISIS ──────► Clases · Actividades · Estados
                    │
DISEÑO ────────► Secuencia · Comunicación · Componentes
                    │
IMPLANTACIÓN ──► Despliegue · Paquetes

Esta progresión refleja el ciclo clásico: de requisitos a análisis, de análisis a diseño, de diseño a implantación. En ágil se recorre rápido y parcialmente, pero el mapa mental sirve igual.
