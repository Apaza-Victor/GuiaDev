5.1. Escenario: aplicación SaaS multiusuario

Modelaremos el despliegue de "FacturaFlow", un SaaS de facturación con estos requisitos operativos:

  • Usuarios en todo el mundo → necesita CDN y baja latencia.
  • Carga variable → autoescalado horizontal.
  • Datos sensibles → red privada, cifrado y backups.
  • Alta disponibilidad → sin punto único de fallo.

Infraestructura elegida (nube pública genérica):

  • CDN + balanceador HTTP(S) en el borde.
  • Kubernetes con 3 réplicas del backend en contenedores Docker.
  • PostgreSQL administrado con réplica de lectura.
  • Bucket de objetos para PDFs de facturas.

5.2. Diseño del diagrama paso a paso

  1. Nodos de hardware/dispositivo: el navegador del usuario (:Navegador) como nodo externo; la nube como nodo raíz.
  2. Subdividir por zonas: región cloud con subred pública (borde) y subred privada (datos). Cada una es un nodo de ejecución.
  3. Colocar artefactos: dentro de cada dispositivo van los ejecutables — «artifact» frontend.bundle, backend.jar, migraciones.sql.
  4. Etiquetar protocolos y estereotipos: «docker container», «managed service»; conexiones anotadas con HTTPS, SQL, TLS.
  5. Marcar réplicas: multiplicidad 3 en las instancias del backend comunica el escalado.

Error típico evitado: no dibujamos "microservicios" aquí. Los servicios son lógica (diagrama de componentes); los contenedores que los hospedan son despliegue. Un backend puede empaquetarse en un solo artefacto aunque tenga cinco módulos internos.
