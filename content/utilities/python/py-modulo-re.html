¿Para qué sirve y cuándo usarla? Concepto

`re` implementa las expresiones regulares (regex) en Python: patrones de texto que sirven para buscar, validar, extraer o reemplazar cadenas según reglas flexibles, desde validar un email hasta limpiar miles de líneas de un log.

¿Para qué se usa?

  • Buscar coincidencias con `search` y `match`, o todas ellas con `findall` y `finditer`.
  • Extraer partes concretas del texto con grupos `(...)` y `group()`.
  • Reemplazar patrones con `sub` y dividir cadenas con `split`.
  • Escapar texto literal con `re.escape` y compilar patrones reutilizables con `compile`.

¿En qué casos conviene usarla?

  • Validar formatos de entrada: emails, teléfonos, códigos postales o fechas.
  • Buscar y extraer datos de logs, CSVs o configuraciones de texto plano.
  • Normalizar textos o migrar formatos con reemplazos masivos.

Para HTML y XML no uses regex: un parser como `BeautifulSoup` o `html.parser` entiende la jerarquía real. Y cuidado con patrones anidados que causan "catastrophic backtracking"; simplifica la expresión.

Buscar con search y match Paso 1

import re

texto = "El pedido #1234 fue enviado ayer."

# search: encuentra en CUALQUIER parte del texto
m = re.search(r"\d+", texto)
m.group()            # '1234'
m.span()             # (12, 16) posición inicial-final

# match: exige que coincida DESDE el principio
re.match(r"El", texto)      # match (<objeto match>)
re.match(r"pedido", texto)  # None

# ¿contiene un email? (patrón simple)
correo = "contacto@guia.dev"
if re.search(r"[\w.]+@[\w]+\.[a-z]{2,}", correo):
    print("Email válido")

`match` solo mira al inicio del string; `search` barre todo el texto. Usa patrones crudos (`r"..."`) para que la barra invertida `\d` no se interprete como escape del string.

Encontrar Todas las Coincidencias Paso 2

import re

log = "ERROR login; OK request /api/v1; ERROR timeout; OK 200"

# findall: devuelve lista de coincidencias
re.findall(r"ERROR", log)          # ['ERROR', 'ERROR']
re.findall(r"\d{3}", log)          # ['200']

# finditer: devuelve objetos match (con posiciones)
for m in re.finditer(r"[A-Z]{2,}", log):
    print(m.group(), m.span())

# Con grupos, findall devuelve tuplas
fechas = "12/08/2026 y 01/01/2027"
re.findall(r"(\d{2})/(\d{2})/(\d{4})", fechas)
# [('12', '08', '2026'), ('01', '01', '2027')]

`findall` es ideal para "saca todos los emails/ids/IPs". Si tu patrón tiene paréntesis, cada coincidencia devuelve una tupla con los grupos capturados.

Reemplazar y Dividir Paso 3

import re

# sub: reemplaza las coincidencias
texto = "Celular: +51 999-888-777"
limpio = re.sub(r"[^\d+]", "", texto)    # '+51999888777' (quita no-dígitos)
re.sub(r"-", "", "2026-08-29")           # '20260829'

# sub con función de reemplazo: transforma cada match
def mayus(m):
    return m.group(0).upper()
re.sub(r"\bpython\b", mayus, "amo python en python")   # 'amo PYTHON en PYTHON'

# split: divide usando el patrón
re.split(r"[\s,;]+", "hola, mundo; hoy")   # ['hola', 'mundo', 'hoy']

`re.sub` es muy potente: quita caracteres, normalize espacios múltiples o anonimiza datos (por eso va bien con funciones de callback). Ojo con `\b` (límite de palabra) para no reemplazar "pythonista" al buscar "python".

Grupos y Flags Paso 4

import re

# Grupos con nombre
m = re.search(r"(?P<dia>\d{2})/(?P<mes>\d{2})/(?P<anio>\d{4})", "29/08/2026")
m.group("dia")     # '29'
m.group("mes")     # '08'
m.group("anio")    # '2026'
m.group(0, 1, 2, 3)

# Flags que cambian el comportamiento
re.findall(r"hola", "Hola HOLa", re.IGNORECASE)      # ['Hola', 'HOLa']
re.findall(r".+", "una\nlínea\nmás", re.DOTALL)      # multilinea completa

# Alternancia y opcionalidad
re.search(r"(madrid|lima|tokyo)", "vivo en Lima, Perú")  # lima
re.search(r"colou?r", "color")      # 'color' (?) hace opcional la u

# Compilar para reusar patrón
patron = re.compile(r"\d{4}-\d{2}-\d{2}")
patron.fullmatch("2026-08-29")      # asegura que TODO el texto coincide

Los grupos nombrados hacen el código legible (en vez de `match.group(1)` sabes qué es cada captura). `fullmatch` valida que el texto completo encaja: la forma correcta de validar formatos estrictos.
