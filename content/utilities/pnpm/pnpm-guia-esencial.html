¿Para qué sirve y cuándo usarla? Concepto

PNPM (Performant NPM) es un gestor de paquetes alternativo a NPM que destaca por velocidad y eficiencia de disco: guarda cada versión una sola vez en un almacén global y los proyectos enlazan a él con hard links en lugar de copiar dependencias.

¿Para qué se usa?

  • Instalar dependencias de un proyecto de forma mucho más rápida que NPM.
  • Ahorrar espacio en disco compartiendo las dependencias entre proyectos.
  • Mantener un `node_modules` estricto que impide usar dependencias no declaradas.
  • Gestionar monorepos de forma nativa con workspaces.

¿En qué casos conviene usarla?

  • En equipos con muchos proyectos que reutilizan las mismas versiones de paquetes.
  • En CI/CD donde cada instalación debe ser lo más rápida posible.
  • Cuando el espacio en disco o la velocidad de instalación son un problema.

Algunas herramientas antiguas asumen el layout plano de NPM y fallan con el `node_modules` simbólico de PNPM; puede requerir ajustar `node-linker` o `hoist`. Para proyectos pequeños, la ventaja frente a NPM puede no compensar la migración.

1. ¿Qué es PNPM?

Concepto

PNPM (Performant NPM) es un gestor de paquetes alternativo a NPM que destaca por su velocidad y eficiencia en el uso de espacio en disco.

Características principales

CaracterísticaDescripción
Almacén globalLos paquetes se guardan una sola vez en disco
Hard linksLos proyectos enlazan al almacén en vez de copiar
VelocidadHasta 2x más rápido que NPM
Ahorro de espacioReduce significativamente el uso de disco
EstrictoPreviene acceso a dependencias no declaradas

¿Por qué elegir PNPM sobre NPM?

  • Espacio en disco: Si tienes 10 proyectos con React, solo se descarga una vez
  • Velocidad: Instalaciones más rápidas gracias al caché eficiente
  • Seguridad: Solo puedes importar dependencias declaradas explícitamente
  • Monorepos: Soporte nativo para workspaces

2. Instalación

Métodos de instalación

# Usando NPM (más común)
npm install -g pnpm

# Usando Corepack (Node.js 16.13+)
corepack enable
corepack prepare pnpm@latest --activate

# Windows (PowerShell)
iwr https://get.pnpm.io/install.ps1 -useb | iex

# macOS/Linux (curl)
curl -fsSL https://get.pnpm.io/install.sh | sh -

Verificar instalación

# Verificar versión
pnpm --version
# 8.15.0

# Ver ayuda
pnpm --help

Actualizar PNPM

# Actualizar a la última versión
pnpm add -g pnpm

# O usando npm
npm install -g pnpm@latest

3. Inicializar un Proyecto

Crear proyecto nuevo

# Crear package.json interactivo
pnpm init

# Crear con valores por defecto
pnpm init -y

Migrar desde NPM

# Si ya tienes un proyecto con NPM
# Simplemente elimina node_modules y el lock file

rm -rf node_modules
rm package-lock.json

# Instalar con PNPM
pnpm install

# Esto crea pnpm-lock.yaml
PNPM es compatible con `package.json`. Solo cambia el lock file: de `package-lock.json` a `pnpm-lock.yaml`.

pnpm install

# Atajo
pnpm i

# Instalación limpia (como npm ci)
pnpm install --frozen-lockfile

# Solo producción
pnpm install --prod

5. Desinstalar y Actualizar

Desinstalar paquetes

# Desinstalar un paquete
pnpm remove express

# Atajo
pnpm rm express

# Desinstalar múltiples
pnpm remove express mongoose

# Desinstalar global
pnpm remove -g typescript

Actualizar paquetes

# Ver paquetes desactualizados
pnpm outdated

# Actualizar un paquete
pnpm update express

# Actualizar todos los paquetes
pnpm update

# Actualizar a última versión (interactivo)
pnpm update --interactive

# Actualizar a latest (puede romper)
pnpm update --latest
`pnpm update -i` muestra una interfaz interactiva para seleccionar qué paquetes actualizar. ¡Muy útil!

Ejecutar scripts del package.json

# Ejecutar script
pnpm run dev
pnpm run build
pnpm run test

# Scripts especiales (sin 'run')
pnpm start

# Ver todos los scripts disponibles

# Ejecutar con argumentos

Crear proyectos con frameworks

Usa pnpm create o pnpm dlx para iniciar proyectos con frameworks populares:

pnpm create vite mi-app-react --template react
pnpm create vite mi-app-react-ts --template react-ts

# Vue
pnpm create vue@latest mi-app-vue

# Next.js

# Astro

pnpm create svelte@latest mi-app-svelte

`pnpm create nombre` es equivalente a `pnpm dlx create-nombre`. Ambos descargan y ejecutan el paquete sin instalarlo permanentemente.

# Atajo con pnpx (similar a npx)

pnpm dlx degit user/repo mi-proyecto

7. El Almacén Global (Store)

¿Cómo funciona?

PNPM guarda todos los paquetes en un almacén global y crea hard links a los proyectos. Esto significa:

  • Un paquete se descarga una sola vez
  • Todos los proyectos comparten el mismo archivo
  • Ahorro masivo de espacio en disco
# Ver ubicación del store
pnpm store path
# ~/.local/share/pnpm/store/v3 (Linux/macOS)
# %LOCALAPPDATA%/pnpm/store/v3 (Windows)

# Ver estado del store
pnpm store status

# Limpiar paquetes no usados del store
pnpm store prune

Ejemplo de ahorro

Sin PNPM (NPM):
├── proyecto-1/node_modules/react (5MB)
├── proyecto-2/node_modules/react (5MB)
├── proyecto-3/node_modules/react (5MB)
Total: 15MB

Con PNPM:
├── ~/.pnpm-store/react (5MB) ← único archivo real
├── proyecto-1/node_modules/react → link
├── proyecto-2/node_modules/react → link
├── proyecto-3/node_modules/react → link
Total: 5MB

8. Estructura de node_modules

Estructura estricta

PNPM usa una estructura no plana que previene el acceso a dependencias no declaradas.

node_modules/
├── .pnpm/                    # Paquetes reales (hard links)
│   ├── express@4.18.2/
│   │   └── node_modules/
│   │       └── express/
│   └── lodash@4.17.21/
│       └── node_modules/
│           └── lodash/
├── express -> .pnpm/express@4.18.2/node_modules/express
└── lodash -> .pnpm/lodash@4.17.21/node_modules/lodash

Beneficios de la estructura estricta

BeneficioDescripción
SeguridadNo puedes importar paquetes no declarados
ClaridadSabes exactamente qué dependencias usas
Menos bugsEvita errores por dependencias fantasma
Algunos paquetes antiguos pueden fallar con la estructura estricta. Usa `pnpm install --shamefully-hoist` como último recurso.

9. Workspaces (Monorepos)

¿Qué son los workspaces?

Permiten gestionar múltiples paquetes en un solo repositorio (monorepo).

Configurar workspaces

# pnpm-workspace.yaml (en la raíz)
packages:
  - 'packages/*'
  - 'apps/*'
  - '!**/test/**'

Estructura de monorepo

mi-monorepo/
├── package.json
├── pnpm-workspace.yaml
├── pnpm-lock.yaml
├── packages/
│   ├── ui/
│   │   └── package.json
│   └── utils/
│       └── package.json
└── apps/
    ├── web/
    │   └── package.json
    └── api/
        └── package.json

Comandos para workspaces

# Instalar dependencias en todos los workspaces
pnpm install

# Ejecutar script en todos los workspaces
pnpm -r run build
pnpm --recursive run test

# Ejecutar solo en un workspace específico
pnpm --filter web run dev
pnpm --filter @mi-org/ui run build

# Añadir dependencia a un workspace
pnpm add lodash --filter web

# Añadir dependencia local (otro workspace)
pnpm add @mi-org/utils --filter web --workspace

10. Mantenimiento y Limpieza

Limpiar caché y store

# Limpiar paquetes no usados del store
pnpm store prune

# Ver tamaño del store
pnpm store path
du -sh $(pnpm store path)

# Verificar integridad
pnpm store status

Solucionar problemas

# Reinstalar todo desde cero
rm -rf node_modules
pnpm install

# Instalación estricta (como npm ci)
pnpm install --frozen-lockfile

# Si hay problemas de compatibilidad
pnpm install --shamefully-hoist

# Verificar vulnerabilidades
pnpm audit

# Corregir vulnerabilidades
pnpm audit --fix
