¿Para qué sirve y cuándo usarla? Concepto

El desarrollo en C++ depende en gran medida de la herramienta de compilación, el depurador y el sistema de build: CMake, un compilador moderno y un IDE con buen soporte definen la experiencia. Esta página revisa las opciones de IDEs, compiladores y herramientas de build para C++.

¿Para qué se usa?

  • Compilar con estándares modernos (C++20/23) usando GCC, Clang o MSVC.
  • Organizar proyectos y dependencias con CMake o el sistema de build del equipo.
  • Depurar con gdb, lldb o las herramientas integradas del IDE.
  • Analizar y perfilar el código con sanitizers y perfiles de rendimiento.

¿En qué casos conviene usarla?

  • Para proyectos C++ serios donde el build y el debugging son parte central del flujo.
  • Cuando necesitas soporte multiplataforma y reproducción de builds.
  • Para equipos que exigen convenciones comunes de configuración y estilo.

No te limites a un IDE sin entender el toolchain subyacente: en C++ el sistema de build y el compilador importan más que el editor. Elige herramientas que se integren bien con CMake y el depurador que vayas a usar.

---

Compiladores y sistemas de build Herramienta

# GCC 13+/Clang 17+: C++20/23 listo
g++ -std=c++20 -Wall -Wextra prog.cpp -o prog
clang++ -std=c++20 -Wall -Wextra prog.cpp -o prog

# CMake: el estándar de build multiplataforma
cmake_minimum_required(VERSION 3.24)
project(mi_proyecto CXX)
set(CMAKE_CXX_STANDARD 20)
add_executable(main main.cpp)

# Con vcpkg (gestor de dependencias en Windows/Linux/Mac)
vcpkg install fmt spdlog nlohmann-json gtest
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=$VCPKG/scripts/buildsystems/vcpkg.cmake
cmake --build build

# Conan (otro gestor, docker-first)
conan install . --output-folder=build

Usa CMake + un gestor de paquetes (vcpkg o Conan) para dependencias externas. Nunca copies librerías a mano dentro del repo.

IDEs y editores C++ IDE

# CLion (JetBrains, de pago): CMake + depurador + refactorización potentes
# Qt Creator: ideal si usas Qt (gratis, con diseño visual)
# Visual Studio (Windows): el referente en MSVC y profiler integrado

# VS Code gratuito (recomendado light)
code --install-extension ms-vscode.cpptools
code --install-extension llvm-vs-code-extensions.vscode-clangd

# Vim/Neovim + clangd + generic-lsp, Emacs + LSP-mode

Elige IDE según ecosistema: Qt Creator para Qt, CLion para CMake puro, VS Code/Neovim como liviano multiplataforma con clangd.

Depuración y perfilado Debug

# Compilar con símbolos y sanitizers
g++ -g -fsanitize=address,undefined prog.cpp -o prog

# gdb (igual que C, pero con conocimiento de tipos STL)
gdb ./prog
(gdb) break main
(gdb) run
(gdb) print vector                # con pretty-printers de STL
(gdb) bt                          # backtrace en crash
(gdb) up / down                   # navegar entre frames

# Perfiles de demanda: perf o AMD uProf en Linux, xperf en Windows
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
perf record ./build/prog
perf report                       # ver embudos de CPU (hot spots)

Pedir `RelWithDebInfo` con símbolos nos permite más fácilmente analizar con perf. gcc -g también funciona para gdb.

Análisis estático y formato Calidad

# clang-tidy: linting y análisis avanzado
clang-tidy prog.cpp -checks='*,-cppcoreguidelines-*' -- -std=c++20

# clang-format: formato automático
clang-format -i *.cpp *.hpp

# cppcheck: detecta bugs clásicos
cppcheck --enable=warning,performance,portability .

# include-what-you-use
iwyu prog.cpp

# Cobertura
#   gcov + lcov + genhtml tras ejecutar tests
lcov --capture --directory build --output-file cov.info
genhtml cov.info -o coverage

# Integración CI: GitHub Actions + build + tests + clang-tidy

En CI deja que clang-tidy y cppcheck fallen el build si hay críticas; clang-format que resuelva formato. Así el estilo queda blindado.

Ejercicios prácticos Reto

  1. Crea un proyecto CMake con dos archivos fuentes y configúralo con `-std=c++20`.
  2. Añade fmt y gtest mediante vcpkg y compila un test de ejemplo.
  3. Coloca un breakpoint, inspecciona un `std::vector` completo y navega 2 frames del stack.
  4. Ejecuta clang-tidy sobre un archivo y corrige 3 advertencias de rendimiento.
  5. Genera un reporte de cobertura con lcov para un módulo con 5 tests.
