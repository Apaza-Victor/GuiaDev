¿Para qué sirve y cuándo usarla? Concepto

Escribir SQL es solo la mitad del trabajo: el resto son clientes (DBeaver, DataGrip, psql), análisis de planes con EXPLAIN, bases de datos locales con Docker y rutinas de backups y monitoreo. Esta página reúne las herramientas que acompañan al lenguaje en el día a día.

¿Para qué se usa?

  • Explorar bases de datos y editar datos con clientes gráficos multi-motor (DBeaver).
  • Analizar y optimizar consultas con EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON).
  • Levantar bases de datos de desarrollo aisladas y reproducibles con docker-compose.
  • Respaldar con pg_dump/mysqldump y monitorear con pg_stat_activity o Grafana.

¿En qué casos conviene usarla?

  • Desarrollo local sin instalar motores en tu máquina: Docker acerca el entorno real.
  • Cazar consultas lentas antes de producción con EXPLAIN y estadísticas de uso.
  • Restaurar backups en pruebas o incidentes con tiempos controlados.

El cliente gráfico no debe ser tu única herramienta: las CLIs (psql, mysql) son imprescindibles en scripts y CI. Y un índice por cada columna no acelera nada: valida cada uno con EXPLAIN y elimina los que no se usen.

Clientes y editores SQL IDE

# Gráficos multiplataforma
# DBeaver: excelente, gratuito, soporta casi todas las BD y diagrama ER
winget install DBeaver.DBeaver
# DataGrip (JetBrains): el más potente de pago (refactorización, visual)
# Beekeeper Studio: ligero moderno; TablePlus (Mac); HeidiSQL (Windows/MySQL)

# CLIs nativos
psql -h host -U ana -d app
mysql -u ana -p
sqlite3 mi.db "SELECT * FROM usuarios"

# IDE junto a código (VS Code)
code --install-extension mtxr.sqltools
code --install-extension ms-mssql.mssql   # para SQL Server

DBeaver cubre el 90% (multibase, ER, import/export). Si ya usas JetBrains, DataGrip se integra con el resto. Los CLIs siguen siendo insustituibles en scripts.

EXPLAIN y herramientas de tuning Rendimiento

-- PostgreSQL: explica el plan de ejecución con costo y "loops"
EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)
SELECT * FROM ordenes o JOIN clientes c ON c.id = o.cliente_id;

-- PG también expone estadísticas de uso
SELECT schemaname, relname, seq_scan, idx_scan
FROM pg_stat_user_tables ORDER BY seq_scan DESC;
-- MySQL
EXPLAIN ANALYZE SELECT ...
SHOW PROFILE; SET profiling = 1;
-- SQL Server
SET STATISTICS IO ON; SET STATISTICS TIME ON; SELECT ...;
-- SQLite
EXPLAIN QUERY PLAN SELECT ...;

Si un `EXPLAIN` muestra "Seq Scan" enorme en la unión pero esperabas un índice, revisa condiciones, juntos de tipo o falta de índice en la FK.

BD local de desarrollo vía Docker Dev

# docker-compose.yml: PostgreSQL + Adminer para desarrollo
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: ana
      POSTGRES_PASSWORD: local
      POSTGRES_DB: miapp
    ports: ["5432:5432"]
    volumes: [db_data:/var/lib/postgresql/data]
  adminer:
    image: adminer
    ports: ["8080:8080"]
volumes:
  db_data:

docker compose up -d
# O una instancia aislada para tests: testcontainers en tus languages
# (Java/Go/Python/.NET) para levantar la BD solo cuando hay tests

Correr la BD en Docker estandariza el entorno local; Testcontainers crea BD efímeras en cada suite de tests para pruebas aisladas.

Backups, observabilidad y seguridad Ops

# Backups
pg_dump -Fc miapp > miapp.dump      # formato comprimido
createdb copia && pg_restore -d copia miapp.dump
# Automatizar con cron + retención (ej: 7 días)
# MySQL: mysqldump; SQL Server: BACKUP DATABASE ... TO DISK

# Monitoreo
#   pg_stat_activity    (PostgreSQL): consultas concurrentes bloqueadas
#   Percona PMM / pgAdmin dashboard / Grafana + exporters
# Seguridad:
#   - Parámetros preparados contra SQL injection
#   - Usuarios con mínimo privilegio (GRANT/SELECT/...)
#   - encriptar en reposo: PostgreSQL: pgcrypto / parámetros TLS

Optimiza: `pg_stat_activity` muestra bloqueos entre transacciones largas; reporteros de bloqueos e índices sobran al detectar los hotspots antes de que llegue a producción.

Ejercicios prácticos Reto

  1. Con DBeaver conecta una BD local y genera el diagrama ER de 3 tablas.
  2. Provoca una consulta lenta y analízala con `EXPLAIN (ANALYZE, BUFFERS)`.
  3. Levanta PostgreSQL con docker-compose y conéctate vía psql y Adminer.
  4. Crea un nightly que haga pg_dump y lo restaure sobre una BD `copia`.
  5. Revisa `pg_stat_activity` y detecta una sesión bloqueada (inténtalo con dos transacciones conflictivas).
