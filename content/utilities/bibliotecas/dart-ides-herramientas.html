¿Para qué sirve y cuándo usarla? Concepto

El desarrollo en Dart y Flutter se apoya en editores modernos y la toolchain oficial: VS Code y Android Studio destacan, junto al SDK con el analizador, el formateador y las herramientas de test. Esta página compara estas opciones y cuándo usar cada una.

¿Para qué se usa?

  • Desarrollar y depurar Flutter en VS Code o Android Studio.
  • Formatear y analizar código con dart format y dart analyze.
  • Ejecutar y depurar apps en dispositivos o emuladores.
  • Probar y gestionar dependencias con la CLI de Dart y pub.

¿En qué casos conviene usarla?

  • Para el desarrollo diario de apps Flutter, VS Code es ligero y eficaz.
  • Cuando necesitas el depurador y emuladores completos de Android Studio.
  • Para automatizar análisis, formato y tests en CI/CD.

No elijas el editor más pesado por defecto: para Flutter, VS Code con la extensión oficial suele ser suficiente y rápido. Reserva Android Studio para necesidades específicas de Android que el editor ligero no cubre.

IDEs de Dart y Flutter IDE

# VS Code es la opción gratuita estándar
code --install-extension Dart-Code.dart-code
code --install-extension Dart-Code.flutter
# Incluye: hot reload, widget inspector, debug, snippets

# Android Studio / IntelliJ (con plugin Flutter): flujo completo móvil
#   - emulador, devices manager, plugin dart de JetBrains
# Android Studio: importantísimo para Android SDK (adb, emulador)
# Neovim: dart LSP + iOS/macOS clave solo en editores tradicionales

# hot reload:  Estándar para iterar UI en segundos
flutter run --profile   # modo profiling
flutter run --release  # binario de liberación

VS Code + Flutter es suficiente para la mayoría; Android Studio es necesario por el Android SDK/emulador aunque escribas el código en VS Code/IDEA.

CLI: dart format, analyze, doc CLI

# Formato
dart format lib test
dart fix --apply              # aplica fixes automáticos de analysis_options

# Análisis estático
dart analyze                  # verifica analysis_options.yaml
# analysis_options.yaml
include: package:lints/recommended.yaml
linter:
  rules:
    - prefer_final_locals
    - avoid_print                 # usa debugPrint/logger en Flutter

# Docs
dart doc                       # genera documentación API local
# Tests
dart test --coverage=coverage
dart run coverage:format_coverage --in=coverage --out=coverage/lcov.info

mantén `dart analyze` sin errores y `dart format` en la CI. Los `lints` recomendados de `package:lints` son el punto de partida estándar.

Diagnóstico: DevTools y profile Debug

# DevTools (viene con Flutter)
flutter run
# presiona "o" o: flutter run --devtools para abrir suite:
#  - Widget tree / Layout inspector
#  - CPU profiler, Memory, Network, Timeline
#  - Performance Overlay (widgets que piden render)

# Depuración
debugPrint('...')        # no se pierde en consola (vs print)
# assert() para invariantes en modo debug
# breakpoints en VS Code/Android Studio con soporte Dart

# Logcat Android: flutter logs ; flutter run -v detalla
# llama a flutter analyze --fatal-infos si quieres exigir cero info

`print` en release se conserva; usa `debugPrint` o logger (package:logger) y evita logs sensibles. DevTools es tu mejor aliado para UI y rendimiento.

Build y despliegue multilenguaje Ops

# Android APK/AAB
flutter build apk --release
flutter build appbundle --release   # para Google Play
# iOS
flutter build ipa
# Web/escritorio
flutter build web
flutter build windows / macos / linux

# CI recomendada (GitHub Actions): melos (workspaces monorepo)
#   orta/codemagic/buildkite para flutter
# Tamaño: --split-debug-info, --obfuscate para reducir
# Entorno: --dart-define=API_URL=... para variables por entorno

Flutter compila a nativo con un solo flujo: `flutter build `. Codemagic/Codemagic y las acciones de la comunidad publican a Play/App Store automáticamente.

Ejercicios prácticos Reto

  1. Instala VS Code + plugins Dart/Flutter y ejecuta la app contador.
  2. Usa `dart format` y `dart analyze` hasta tener cero warnings.
  3. Abra DevTools y navega el widget tree de tu app.
  4. Genera un APK release y compruébalo en un emulador.
  5. Crea una GitHub Action que corra `dart analyze` y `flutter test`.
