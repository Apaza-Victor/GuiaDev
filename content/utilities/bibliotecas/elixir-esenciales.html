¿Para qué sirve y cuándo usarla? Concepto

La librería estándar de Elixir es enormemente completa: Enum, String, Map, List y Kernel cubren colecciones, concurrencia y manipulación de datos. Esta página reúne las utilidades esenciales de la stdlib que conviene dominar antes de recurrir a paquetes externos.

¿Para qué se usa?

  • Procesar colecciones con Enum y Stream de forma expresiva y funcional.
  • Manipular cadenas, maps, tuplas y listas con funciones dedicadas.
  • Gestionar procesos y concurrencia con los módulos base del lenguaje.
  • Consultar y transformar datos con el pipeline y las convenciones idiomáticas.

¿En qué casos conviene usarla?

  • Para la mayoría del código Elixir: la stdlib resuelve colecciones, texto y flujos.
  • En APIs y servicios donde la inmutabilidad y la concurrencia son clave.
  • Como base sólida antes de incorporar frameworks como Phoenix o Ecto.

No asumas que necesitas paquetes externos para lógica básica: la stdlib de Elixir es amplia y funcional. Añade dependencias solo cuando el dominio (web, base de datos, jobs) lo requiera y no dupliques lo que ya implementa.

Elixir stdlib: Enum, String, Map Base

# La stdlib de Elixir es enorme: Enum, String, Map, List, Kernel

list = [3, 1, 4, 1, 5]
Enum.filter(list, &(rem(&1, 2) == 0))
|> Enum.map(&(&1 * 10))
|> Enum.sort()
|> Enum.sum()          # 140 si fuera solo pares * 10... mejor: Enum.frequencies

frec = Enum.frequencies(["hola", "mundo", "hola"])   # %{"hola" => 2}

mapa = %{nombre: "Ana", edad: 30}
Map.put(mapa, :ciudad, "Madrid")

String.upcase("hola") |> String.split() |> Enum.join("-")

# pipes: |> encadena funciones limpiamente
# pattern matching y inmutabilidad

Enum+String+Map+List de la stdlib resuelven el 90% sin librerías: `|>` pipes, `Enum` para todo, pattern matching. Todo se ejecuta sobre la BEAM (Erlang VM).

Hex y Mix: gestión de paquetes Deps

# mix: build/task runner (a la vez bundler + rake)
mix new mi_app && cd mi_app
# Hex: package manager (hex.pm)
mix hex.info json
mix hex.install hex

# En mix.exs:
defp deps do
  [
    {:jason, "~> 1.4"},
    {:req, "~> 0.5"}
  ]
end

mix deps.get          # descarga
mix deps.update jason # actualiza
mix deps.clean

# mix.exs
defmodule MiApp.MixProject do
  use Mix.Project

  def project do
    [app: :mi_app, version: "0.1.0", elixir: "~> 1.16"]
  end

  def application, do: [extra_applications: [:logger]]

  defp deps do
    [{:jason, "~> 1.4"}, {:req, "~> 0.5"}]
  end
end

mix genera/escala el proyecto y gestiona deps vía Hex; `mix deps.get` + `mix test` son el ciclo normal. Hex trae docs y versionado semántico desde el primer día.

Librerías esenciales: jason, req, timex Utilidad

# Jason: JSON rápido
Jason.encode!(%{nombre: "Ana", edad: 30})
Jason.decode!("{\"x\": 1}")

# Req: cliente HTTP ergonómico
Req.get!("https://api.github.com/users/octocat").body

# Timex: fechas y zonas horarias (sobre DateTime)
Timex.now()
Timex.shift(Timex.now(), days: 3)

# StreamData: generación de datos para test
# ExUnit: testing nativo (ver frameworks en su sección)

jason (JSON), req (HTTP) y timex (fechas) son las tres más descargadas; jason y req son de la escena actual, timex para datetime. Extra: `floki` (HTML) y `ecto_sql` (BD).

Instalación de Elixir Inicio

# Comparar: asdf / mise (multiversión)
asdf install erlang 27   # BEAM primero
asdf install elixir 1.16
asdf global elixir 1.16.2
# O Windows: choco install elixir o scoop (flutter? no)
# macOS/linux también con brew (brewmintake? no: brew install elixir)

# Verificar
elixir --version
mix --version
echo 'IO.puts("Hola desde Elixir")' > hola.exs
elixir hola.exs

# iex: shell interactivo con tab-complete

asdf/mise gestiona Erlang+Elixir como rbenv; brew en macOS; choco/scoop en Windows. `iex` es un REPL potente con inspect, rem y autocompletado.
