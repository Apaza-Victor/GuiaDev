¿Para qué sirve y cuándo usarla? Concepto

El ecosistema de frameworks web de Go incluye a Gin, Echo y Fiber, que añaden routing, middleware y helpers ergonómicos sobre net/http. Esta página presenta los frameworks de Go y cuándo conviene usarlos frente a la librería estándar.

¿Para qué se usa?

  • Routing y agrupación de rutas con middleware en Gin, Echo o Fiber.
  • Validación, binding y respuestas JSON de forma más concisa.
  • Desarrollo rápido de APIs REST con convenciones comunes.
  • Rendimiento con Fiber aprovechando una implementación muy optimizada.

¿En qué casos conviene usarla?

  • Cuando necesitas routing complejo y middleware sin implementarlo a mano.
  • Para APIs con estructura clara y muchas rutas donde el framework reduce código.
  • Cuando el equipo ya conoce un framework concreto y su forma de trabajo.

La regla de oro: muchas apps no necesitan framework. Para servicios simples, net/http + chi es suficiente y con menos dependencias. Elige Gin, Echo o Fiber solo cuando necesites la ergonomía y el routing; no por inercia.

Empieza con net/http + chi y crece cuando lo necesites. Gin es la opción más común si quieres un marco web completo.

Gin: validación, JSON y middleware Framework

package main

import (
	"net/http"
	"github.com/gin-gonic/gin"
)

type Usuario struct {
	Nombre string `json:"nombre" binding:"required,min=3"`
	Email  string `json:"email" binding:"required,email"`
}

func main() {
	r := gin.Default()                     // logging + recovery integrados
	r.Use(gin.Logger(), gin.Recovery())

	r.GET("/usuarios", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"usuarios": []string{}})
	})

	r.POST("/usuarios", func(c *gin.Context) {
		var u Usuario
		if err := c.ShouldBindJSON(&u); err != nil {
			c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
			return
		}
		c.JSON(http.StatusCreated, u)
	})

	r.Run(":8080")                          // http.ListenAndServe
}

Gin agrupa routing, validación de structs (binding), middleware y JSON con mínima ceremonia. Los códigos de error se asignan con helper de estado claro.

Fiber y Echo Alternativas

// Fiber: sintaxis "Express-like"
import "github.com/gofiber/fiber/v2"

app := fiber.New()
app.Get("/hola/:nombre", func(c *fiber.Ctx) error {
	return c.JSON(fiber.Map{"saludo": "Hola " + c.Params("nombre")})
})
app.Listen(":3000")

// Echo: middlewares ricos y context sensitivo a errores
import "github.com/labstack/echo/v4"
e := echo.New()
e.GET("/ping", func(c echo.Context) error {
	return c.JSON(200, map[string]string{"pong": "ok"})
})
e.Logger.Fatal(e.Start(":1323"))

Fiber (similar a Express) y Echo (middlewares + routing paramétrico) son alternativas con excelente rendimiento; elijan el estilo que tu equipo lea mejor.

Datos: GORM, sqlx y migraciones Datos

import "gorm.io/gorm"
import "gorm.io/driver/postgres"

// Modelo + migración automática
type Usuario struct {
	ID    uint   `gorm:"primaryKey"`
	Nombre string
	Email  string `gorm:"unique"`
}

db, _ := gorm.Open(postgres.Open("host=localhost user=app password=x dbname=app"), &gorm.Config{})
db.AutoMigrate(&Usuario{})

// CRUD
db.Create(&Usuario{Nombre: "Ana"})
var u Usuario
db.First(&u, 1)
db.Where("email = ?", "ana@x").Find(&usuarios)

// sqlx: para SQL explícito con mapeo a struct
rows, _ := dbx.Queryx("SELECT * FROM usuarios WHERE id=$1", 1)
for rows.Next() { rows.StructScan(&u) }
// migraciones: golang-migrate / atlas

GORM es el ORM más cómodo; sqlx cuando quieres SQL crudo con mapeo a structs. Usa golang-migrate para versionar el esquema como SQL/Go.

Testing: testing estándar y testify Calidad

// testing estándar
package calc

import "testing"

func TestSuma(t *testing.T) {
	got := suma(2, 3)
	if got != 5 {
		t.Errorf("suma() = %d; want 5", got)
	}
}

// tabla + subtests
func TestDivide(t *testing.T) {
	casos := []struct{ a, b, want int }{{6, 2, 3}, {10, 2, 5}}
	for _, c := range casos {
		t.Run(fmt.Sprintf("%d/%d", c.a, c.b), func(t *testing.T) {
			if got := divide(c.a, c.b); got != c.want {
				t.Errorf(...)
			}
		})
	}
}
// Correr: go test ./... ; Cobertura: go test -cover ./...
// Sobre HTTP: httptest + httptest.NewRequest

El paquete `testing` nativo + tablas de casos cubre la mayoría. `testify` añade asserts/aserciones y mocks cuando lo necesites.
