¿Para qué sirve y cuándo usarla? Concepto

El desarrollo en Scala se apoya en Metals (LSP) para VS Code o Neovim, o en el plugin Scala de IntelliJ, más herramientas de formato (scalafmt), linting (scalafix), scripting (scala-cli) y empaquetado (sbt-assembly). Esta página repasa ese flujo completo hasta producción.

¿Para qué se usa?

  • Navegación, autocompletado, depuración y refactors con Metals o IntelliJ.
  • Formato consistente y verificable con scalafmt, con --check en CI.
  • Lint y auto-fix de migraciones de código con scalafix.
  • Empaquetar fat jars con sbt-assembly para desplegar sobre la JVM.

¿En qué casos conviene usarla?

  • CI con scalafmt --check, scalafix y sbt test en cada push.
  • Prototipos y ejercicios rápidos con scala-cli sin proyecto completo.
  • Debug de flujos complejos con breakpoints vía el protocolo DAP de Metals.

Scala corre en la JVM, así que depuración y perfilado usan exactamente las herramientas de Java: JFR, async-profiler y JMH. No reinventes el pipeline: reutiliza las prácticas JVM probadas.

IDEs y Metals IDE

# Metals: LSP para Scala (recomendado, gratis, en VS Code)
code --install-extension scalameta.metals
# metal: autocompletado, go-to-definition, metales, renames, type info
# Visual Studio Code es lo más común; también Neovim (Metals + LSP)

# IntelliJ IDEA: plugin Scala (maduro, refactorizaciones)
#   instalar scala plugin en IntelliJ; no para proyectos exclusivos

# scalafmt y Metals integrados de serie en el LSP

Metals (LSP, mantenga por scalameta) otorga heavy tooling sin IDE comercial: debug, refactors y `scalafmt`. IntelliJ+Scala para heavy IDE con GUI.

---

scalafmt, scalafix y CLI CLI

# scalafmt (estilo obligatorio de la comunidad)
scalafmt                   # formatea
scalafmt --check           # verifica (CI)
# scalafix (lints/auto-fix migraciones)
scalafixAll                # aplica reglas
sbt "scalafix RemoveUnused"
# scala-cli (scripts/pruebas rápidas)
scala-cli run src/main.scala --scala 3.3.4
scala-cli test --test-framework munit
# código educational para tips: taplook
# interactive: sbt shell con Tab de comandos

scalafmt es el estándar de formato: se usa en CI con `--check`. scala-cli es perfecto para scripts y ejercicios rápidos sin proyecto completo.

Depuración y perfilado Debug

# Debug via a DAP (Debug Adapter Protocol) en Metals:
#   breakpoints, call stack, variables en VS Code/IntelliJ
# Estrategias = println!, logger
#   slf4j + logback (clásico en JVM)
#   scribe (Scala moderno, funcional y rápido)
#   cats-effect tiempo de prueba: munit/cats

# Perfilado en JVM
#   async-profiler  (hot spots JIT)
#   VisualVM / JFR (image heap y CPU)
#   JFR en JDK moderno: -XX:StartFlightRecording
# CI perf guard: JMH (microbenchmarks JVM) via jmh-sbt

Scala corre en JVM, así que Debug (breakpoints) por Metals/DAP y perfilado con JFR/async-profiler/JMH son exactamente las mismas herramientas que en Java.

Compilación y despliegue Ops

# Fat jar con sbt-assembly (un solo ejecutable con deps)
sbt assembly
java -jar target/scala-3.3.4/mi-app-assembly-0.1.0.jar

# Docker (multistage) - imagen JVM pequeña

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY target/scala-3.3.4/mi-app-assembly-0.1.0.jar app.jar
EXPOSE 8080
CMD ["java", "-jar", "app.jar"]

# JVM tuning: -Xmx, G1GC, -XX flags según carga
# Orchestación: cualquiera (K8s, Nomad) ya que es estándar HTTP
# CI/CD: github actions + opcionalmente sbt-dynver para versión

sbt-assembly empaqueta todo en un jar; Docker con `temurin` JRE es lo mínimo. Scala produce binarios de ~100MB+ y JVM warmup, aunque perfecto para servicios HTTP.

Ejercicios prácticos Reto

  1. Instala Metals en VS Code y explora goto-definition en tu código.
  2. Configura scalafmt en CI con `--check`.
  3. Haz un script con scala-cli que lea stdin y cuente líneas.
  4. Depura un breakpoint en Metals y mira variables del stack.
  5. Build con sbt-assembly y corre el jar en una imagen temurin.
