ASP.NET Core: web y APIs Framework

// API mínima (minimal APIs)
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();
if (app.Environment.IsDevelopment()) app.UseSwagger();

var usuarios = new List<Usuario> { new(1, "Ana") };

app.MapGet("/usuarios", () => usuarios);
app.MapGet("/usuarios/{id}", (int id) => usuarios.FirstOrDefault(u => u.Id == id));
app.MapPost("/usuarios", (Usuario u) => { usuarios.Add(u); return Results.Created($"/usuarios/{u.Id}", u); });

app.Run();
record Usuario(int Id, string Nombre);

// MVC clásico para apps más complejas:
// app.MapControllers(); + [ApiController] [Route("api/[controller]")]

Minimal APIs (C# 9+) son compactas para REST; MVC para proyectos grandes. Swagger/OpenAPI se añade con un paquete y da documentación interactiva.

EF Core: ORM principal Datos

// EF Core: mapeo objeto-relacional
using System.ComponentModel.DataAnnotations;

public class Usuario {
  public int Id { get; set; }
  [Required, MaxLength(100)]
  public string Nombre { get; set; } = "";
  public List<Orden> Ordenes { get; set; } = new();
}

public class AppDbContext : DbContext {
  public DbSet<Usuario> Usuarios => Set<Usuario>();
  public AppDbContext(DbContextOptions<AppDbContext> o) : base(o) { }
}

// Migraciones (CLI)
//   dotnet add package Microsoft.EntityFrameworkCore.SqlServer
//   dotnet ef migrations add Inicial
//   dotnet ef database update

// Uso
var user = new Usuario { Nombre = "Ana" };
await ctx.Usuarios.AddAsync(user);
await ctx.SaveChangesAsync();

EF Core soporta SQL Server, PostgreSQL, MySQL, SQLite e InMemory. Migraciones versionan el esquema; `AsNoTracking()` y `Include()` son los dos ajustes que más rinden.

Blazor: UI interactiva en C# UI

@page "/contador"

<h3>Contador</h3>
<p>Valor: @valor</p>
<button class="btn btn-primary" @onclick="Incrementar">+1</button>

@code {
    private int valor = 0;
    private void Incrementar() => valor++;
}

# Crear proyecto
dotnet new blazorwasm -o AppBlazor     # WebAssembly (en el navegador)
dotnet new blazorserver -o AppServer   # Server (SignalR)

Blazor WebAssembly ejecuta C# en el navegador (WASM); Blazor Server lo hace desde el servidor con SignalR. Mismo lenguaje y componentes para toda la stack.

xUnit y Testing en .NET Calidad

// xUnit: framework de testing preferido
using Xunit;

public class CalculadoraTests {
  [Fact]
  public void Suma_DevuelveCorrecta() {
    Assert.Equal(5, Calculadora.Suma(2, 3));
  }

  [Theory]
  [InlineData(1, 2, 3)]
  [InlineData(0, 0, 0)]
  [InlineData(-1, 1, 0)]
  public void Suma_ConTeoria(int a, int b, int expected) {
    Assert.Equal(expected, Calculadora.Suma(a, b));
  }
}

// Mocking con Moq / NSubstitute
var repo = new Mock<IRepositorio>();
repo.Setup(r => r.Find(1)).Returns(new Usuario(1, "Ana"));

// Correr: dotnet test
// Cobertura: dotnet coverlet o visual studio

xUnit + Moq son la pareja más extendida en .NET. Usa `[Theory]`+`[InlineData]` para parametrizar casos y disminuir duplicación de tests.
