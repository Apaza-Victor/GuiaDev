¿Para qué sirve y cuándo usarla? Concepto

Las herramientas complementan al CSS en el día a día: linters como stylelint, formateadores como Prettier, preprocesadores y build tools ayudan a mantener calidad y consistencia. Esta página revisa las herramientas y entornos recomendados para trabajar con CSS.

¿Para qué se usa?

  • Detectar errores y mantener reglas de estilo con stylelint.
  • Formatear CSS automáticamente con Prettier o los formateadores integrados.
  • Preprocesar y optimizar hojas con Sass y herramientas de build.
  • Inspeccionar y depurar estilos en el navegador o el editor.

¿En qué casos conviene usarla?

  • En proyectos con muchos estilos donde la consistencia y calidad importan.
  • Cuando trabajas en equipo y necesitas reglas uniformes de lint y formato.
  • Para integrar CSS en un pipeline de build y optimización de producción.

No sobrecargues un proyecto pequeño con múltiples herramientas: un linter y un formateador suelen bastar. Introduce preprocesadores y builds completos solo cuando el tamaño y la complejidad del CSS lo justifiquen.

stylelint: lint y reglas de calidad Calidad

# stylelint: el linter de CSS estándar
npm i -D stylelint stylelint-config-standard
# .stylelintrc.json
# { "extends": ["stylelint-config-standard"] }
npx stylelint "src/**/*.css"
# --fix corrige automático lo seguro
npx stylelint "src/**/*.css" --fix

# Reglas destacadas: selector-class-pattern (nombrado),
#   declaration-block-no-shorthand-property-overrides,
#   order/properties-alphabetical-order, a11y/media-feature-range
# Extensión: stylelint-config-prettier para evitar conflicto con prettier

stylelint + config-standard asegura consistencia y errores tipográficos de CSS. Con `--fix` y su asociación a pre-commit te olvidas de revisarlo a mano.

Prettier y formato CSS Formato

# Prettier: formatter universal (html/css/js/md)
npm i -D prettier
npx prettier --write "src/**/*.{css,scss}"
npx prettier --check "src/**/*.css"   # en CI

# Config .prettierrc:
# {
#   "semi": false,
#   "singleQuote": true,
#   "printWidth": 100
# }

# Formateo automático al guardar en VS Code:
#   ext: esbenp.prettier-vscode; editor.formatOnSave
# Si usas stylelint: instala stylelint-config-prettier y apaga reglas de formato

Prettier unifica el estilo (espacios, comillas, saltos). Su conflicto con stylelint se resuelve con `stylelint-config-prettier` apagando las reglas de formato.

DevTools y autoprefixer: depurar y desplegar Debug

# Chrome DevTools (F12) para CSS:
#   - Elements → styles: editar en vivo, ver css variables
#   - Computed: qué regla gana (especificidad)
#   - El botón "force state" (:hover/:focus)
#   - Rendering → mostrar FPS/layout shifts; Performance rec
# Autoprefixer: prefijos -webkit-/moz- según caniuse
npm i -D postcss autoprefixer cssnano
# en build (vite/postcss) automático
# Vaciar caché/el deploy: hashes en filenames (vite lo hace)

DevTools = taller en vivo; `autoprefixer` evita diseñar por navegador; Vite añade hashes al build. Un flujo sano: editar→lint→build (prefijos+min)→deploy.

Pipeline CSS: CI, cobertura y presupuestos Ops

# .github/workflows/css.yml
name: CSS quality
on: [push]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npx prettier --check "src/**/*.css"
      - run: npx stylelint "src/**/*.css"
      - run: npm run build

# Presupuestos de performance (paquete size) con Lighthouse CI:
npm i -D @lhci/cli
npx lhci autorun    # mide performance/LCP/CLS
# CSS tamaño meta: nuevo cssbudget: cssnano ya minifica
# Rules de a11y: stylelint-config-recommended / axe en el HTML check

El pipeline ideal: prettier + stylelint + build + lighthouse en CI. No publicas regresiones de CSS ni de performance. `lhci` define presupuestos para parar el deploy.
