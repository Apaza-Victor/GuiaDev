¿Para qué sirve y cuándo usarla? Concepto

Ruby brilla en desarrollo web, sobre todo con Rails, un framework de "convención sobre configuración" que integra todo lo necesario. Esta página compara Rails con las alternativas ligeras (Sinatra, Roda), repasa el testing con RSpec y los extras como jobs, WebSockets y autenticación.

¿Para qué se usa?

  • Construir apps web completas (MVC, ORM, vistas, migraciones) con Rails.
  • Crear APIs REST ligeras y servicios simples con Sinatra o Roda.
  • Probar con RSpec junto a FactoryBot, Capybara y otros aliados de Rails.
  • Procesar trabajo en segundo plano con Active Job (Sidekiq o Solid Queue).

¿En qué casos conviene usarla?

  • MVPs o productos web donde la productividad del día uno importa.
  • CRUD más autenticación, jobs y WebSockets en un solo framework coherente.
  • APIs pequeñas donde Rails sobra: Sinatra o Roda con Sequel.

Rails viene con mucho acoplado: para microservicios de streaming intenso o máxima concurrencia evalúa Sinatra/Roda u otro lenguaje. Y para una API pura, considera Rails en modo API con un frontend separado.

Elegir framework Ruby Guía

# Rails: el framework por defecto (productividad + convenciones)
gem install rails
rails new mi_app -d postgresql
# Sinatra: micro-framework para APIs y apps sencillas
gem install sinatra
# Roda: muy rápido, encadenando rutas, más "bajo nivel"
gem install roda

# Comparativa
#  Rails:   todo incluido (MVC, ORM, views, jobs, action cable)
#  Sinatra: unas rutas y middleware; déjate el resto tú
#  Roda:    ruteador veloz, idea de "tree routing"

Rails domina el ecosistema; Sinatra/Roda son ideales para APIs ligeras o widgets. Si vienes de Hotwire/Laravel, Rails te resultará familiar por convenciones.

---

Rails: rutas, Active Record y vistas Framework

# Config/routes.rb
Rails.application.routes.draw do
  resources :usuarios
  root "usuarios#index"
end

# Model: Active Record
class Usuario < ApplicationRecord
  validates :email, presence: true, uniqueness: true
  has_many :ordenes
end

# Controller
class UsuariosController < ApplicationController
  def index
    @usuarios = Usuario.order(:nombre).page(params[:page])
  end
end

# Vistas: erb / slim + Turbolinks/Hotwire para UX rica
bin/rails server

Rails intenta que escribas menos: convenciones de nombres (`_controller`, plural para tablas), migraciones y generadores (`bin/rails generate scaffold`).

Sinatra: micro-API en 10 líneas API

require "sinatra"
require "json"

set :port, 3000

get "/saludo/:nombre" do
  { saludo: "Hola #{params[:nombre]}" }.to_json
end

post "/usuarios" do
  datos = JSON.parse(request.body.read)
  { recibido: datos }.merge(guardado: true).to_json
end

# Roda (alternativa veloz)
class MiApp < Roda
  route do |r|
    r.get "saludo" do
      "Hola"
    end
  end
end

Sinatra/Roda se bastan para REST sin capas extras. Cuando el proyecto crezca, subeme a Rails o usa Sequel + Roda (stack "slim").

RSpec: testing en Ruby Calidad

# spec/calculadora_spec.rb
require "calculadora"

RSpec.describe Calculadora do
  describe ".suma" do
    it "suma dos números" do
      expect(Calculadora.suma(2, 3)).to eq(5)
    end

    it "funciona con negativos" do
      expect(Calculadora.suma(-1, 1)).to eq(0)
    end
  end
end

# Ejecutar: bundle exec rspec
# Rails: system tests con Capybara, factories con FactoryBot,
#        respuestas JSON con json_matchers, fixtures de BD con use_transactional_fixtures

RSpec es el estándar BDD. En Rails: FactoryBot para datos, Capybara para prueba E2E, y `rspec-rails` para controladores/modelos.

Extras del ecosistema: jobs y websockets Extras

# Active Job (Rails): colas de trabajo en segundo plano
class ProcesarPedidoJob < ApplicationJob
  queue_as :default
  def perform(pedido)
    # trabajo pesado...
  end
end
# ProcesarPedidoJob.perform_later(pedido)
# Backends: Solid Queue (BD), Sidekiq (Redis), GoodJob

# Action Cable: WebSockets
# Hotwire+Stimulus: experiencia SPA sin escribir JS
# Otras gemas: pundit (autorización), devise (auth), brakeman (seguridad)

Active Job + Sidekiq/Solid Queue y Hotwire son lo que hacen que Rails sea "completo": autenticación, jobs, websockets y seguridad en un mismo framework.
