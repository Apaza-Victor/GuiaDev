¿Para qué sirve y cuándo usarla? Concepto

Go brilla con su librería estándar: http, json, io, contexto y testing cubren la mayoría de necesidades de servicios y herramientas sin dependencias externas. Esta página reúne las utilidades esenciales de la stdlib de Go y qué conviene conocer de ella.

¿Para qué se usa?

  • Servidores y clientes HTTP con net/http y sus helpers.
  • Serialización JSON y formatos de datos con encoding/json.
  • Manejo de contexto, concurrencia y cancelaciones con context y goroutines.
  • Testing, benchmarks y utilidades de archivos con la stdlib integrada.

¿En qué casos conviene usarla?

  • Para la mayoría de servicios y CLI de Go: la stdlib cubre el grueso.
  • Cuando valoras builds nativos, rapidez y sin infraestructura pesada.
  • Para herramientas de operaciones y microservicios ligeros.

No añadas frameworks http si la stdlib basta: muchos servicios funcionan con net/http y chi. Antes de instalar dependencias, comprueba si la stdlib de Go ya resuelve el caso con simplicidad y rendimiento.

La librería estándar de Go Base

// Go brilla con su stdlib: http, json, io, contexto, testing
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"os"
	"time"
)

func main() {
	// HTTP server con net/http
	http.HandleFunc("/saludo", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		json.NewEncoder(w).Encode(map[string]string{"saludo": "Hola"})
	})
	go http.ListenAndServe(":8080", nil)

	// Cliente HTTP
	resp, err := http.Get("https://api.github.com/users/octocat")
	if err != nil { fmt.Fprintln(os.Stderr, err); return }
	defer resp.Body.Close()

	// Tipado de JSON a struct
	var u struct{ Name string `json:"name"` }
	json.NewDecoder(resp.Body).Decode(&u)
	fmt.Println("usuario:", u.Name)

	// time con formatos limpios
	fmt.Println(time.Now().Format(time.RFC3339))
}

net/http (server más sencillo de producción), encoding/json, context, io y testing vienen en el SDK. En Go casi no necesitas frameworks "web" para servicios.

go mod, go get y dependencias Deps

go mod init mi_app          # crear módulo (go.mod)
go get github.com/gorilla/mux
go get -u ./...             # actualizar
go mod tidy                 # añade/quita lo necesario según el código
go vet ./...                # análisis estático

# go.mod (compatible/versionado con sum)
module mi_app
go 1.22
require github.com/gorilla/mux v1.8.1

Corre `go mod tidy` antes de commitear para que go.mod/go.sum reflejen exactamente lo que importa el código.

librerías populares: chi, cobra, viper Utilidad

// chi: router para net/http delgado y componible
import "github.com/go-chi/chi/v5"

r := chi.NewRouter()
r.Get("/usuarios/{id}", func(w http.ResponseWriter, r *http.Request) {
	id := chi.URLParam(r, "id")
	w.Write([]byte("usuario " + id))
})

// cobra: CLI apps (kubectl, gh, docker usan cobra)
// viper: configuración (JSON, YAML, env...)
import "github.com/spf13/viper"
viper.SetConfigFile("config.yaml")
viper.AutomaticEnv()

// Otros favoritos
//  - sqlx: filas a structs sobre database/sql
//  - gorm: ORM (en la guía SQL)
//  - uber-go/zap o slog (estándar): logging
//  - google/uuid

chi es el router favorito para net/http. Cobra + Viper son la pareja estándar de herramientas CLI y config. `slog` es el logging oficial desde Go 1.21.

Instalación de Go Inicio

# Descargar binario oficial o:
winget install GoLang.Go         # Windows
brew install go                  # macOS
sudo apt install golang-go       # Debian/Ubuntu (versión puede atrasar)
golang.org/dl/ → instalador

# Verificar y hola mundo
go version
mkdir hola && cd hola
go mod init hola
# main.go
package main
import "fmt"
func main() { fmt.Println("Hola desde Go") }
go run .

Prefiere el instalador oficial o las últimas majors. Define `GOPATH`/`GOBIN` o usa el default `~/go`; el editor (VS Code) necesita el extension de Go.
