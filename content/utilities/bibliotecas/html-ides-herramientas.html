¿Para qué sirve y cuándo usarla? Concepto

Escribir HTML es solo el principio; esta página cubre las herramientas que lo rodean: validadores y linters, motores de plantillas para generarlo y herramientas de build para minificar y optimizar el resultado final de producción.

¿Para qué se usa?

  • Detectar errores de marcado con validadores W3C y linters como html-validate.
  • Generar páginas repetitivas con motores de plantillas (Nunjucks, Blade, Liquid).
  • Minificar y optimizar el HTML final en el build de producción.

¿En qué casos conviene usarla?

  • Para revisar el HTML generado dinámicamente antes de publicarlo.
  • Para mantener layouts y componentes compartidos en sitios con muchas páginas.
  • Para reducir el peso final y mejorar los tiempos de carga.

Un validador solo garantiza sintaxis correcta, no buena semántica ni accesibilidad. Complementa la validación con revisión manual y con auditorías como Lighthouse antes de dar la página por terminada.

Validadores y lint de HTML Calidad

# 1. W3C Markup Validator (https://validator.w3.org): el estándar
#    subes archivo/URL y reporta errores de estructura
# 2. html-validate (Node): lint en CI/pre-commit
npm i -D html-validate
npx html-validate src/index.html
# 3. VSCode: extensión "HTML End Tag Labels" / "Mithril Emmet"

# Otros:
#   - a11y: axe-core (DevTools → axe) / Lighthouse accessibility
#   - SEO: Lighthouse SEO / meta defaults

# integración en CI:
npx prettier --check "src/**/*.html"
npx html-validate "src/**/*.html"

W3C valida la especificación; html-validate (con eslint de html) se integra en Git hooks; axe-core audita accesibilidad. Así cerramos el piso de calidad HTML.

Emmet, Snippets y documentación DX

# Emmet: scribes HTML ultrarrápido (built-in en VS Code)
#   `ul>li*3>a[href="#"]` + Tab → lista de 3 enlaces
#   `!` + Tab → doctype completo
#   `section.card>.titulo+p` → estructura anidada
#   `.clase` y `#id` para divs
# Snippets: puedes crear los tuyos en VS Code (File > Preferencias > Snippets)
# Documentación de referencia:
#   MDN HTML (developer.mozilla.org/es/docs/Web/HTML) — tu biblia
#   htmlreference.io (cheatsheet visual)
#   caniuse.com (compatibilidad de features)

Emmet ahorra horas de escritura; MDN es la referencia canónica y caniuse la balanza de compatibilidad. Con esas tres herramientas el HTML se vuelve productivo.

Build y automatización HTML Build

# Para proyectos serios HTML/CSS/JS: Vite (esbuild)
npm create vite@latest mi-sitio -- --template vanilla
cd mi-sitio && npm install
npm run dev      # dev server + HMR
npm run build    # dist/ minificada + hashes

# Plugins útiles:
#   vite plugin html (múltiples pages): vite-plugin-html o multi-page manuales
#   PostCSS + autoprefixer + cssnano en el build
#   imagemin/Squoosh (optimiza imágenes)

# Alternativas: parcel (cero config), astro (multi-page + islas HTML)
# Netlify/Vercel/Pages: solo subes dist/

Vite es hoy el build estándar; Astro resalta si quieres sitios multi-página ultra-rápidos (HTML puro de salida). Despliegas `dist/` en cualquier host estático.

Desplegar sitios HTML Ops

# Hosting estático (cualquiera sirve):
#   GitHub Pages: repos públicos gratis
#   Netlify / Vercel: CI + preview por PR + forms/functions
#   Cloudflare Pages: edge + CDN
#   S3+CloudFront / SCP para escala
# Opciones sin build: subir carpeta + hosting; o con make dist

# .github/workflows/deploy-pages.yml
name: Deploy
on:
  push:
    branches: [main]
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm run build
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist

HTML se publica directo; agrega un workflow de GH Pages o conecta Netlify al repo y tendrás deploy automático en cada push con preview por rama.
