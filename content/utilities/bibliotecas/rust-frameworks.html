¿Para qué sirve y cuándo usarla? Concepto

Rust tiene un ecosistema web sólido y de alto rendimiento: Axum, Actix Web y Rocket para HTTP, y sqlx, diesel o sea-orm para bases de datos con seguridad de tipos. Esta página compara los frameworks y muestra el stack típico de una API en Rust.

¿Para qué se usa?

  • Servidores HTTP y APIs REST de alto rendimiento con Axum o Actix Web.
  • Rutas ergonómicas con macros si prefieres Rocket.
  • Acceso a bases de datos con queries verificadas en compilación (sqlx) u ORMs (diesel, sea-orm).
  • Testing nativo con `#[test]` y pruebas de endpoints con tower::oneshot.

¿En qué casos conviene usarla?

  • APIs de mucho tráfico donde cada milisegundo y cada byte cuentan.
  • Servicios asíncronos sobre tokio que aprovechan varios núcleos.
  • Proyectos que quieren garantías de tipos hasta en la capa de datos.

El ecosistema web de Rust es más joven que el de Node, Python o Rails: hay menos librerías listas para producción. Para CRUD administrativo o un MVP en horas, un framework con generadores sigue siendo más productivo.

Elegir framework web en Rust Guía

# Ecosistema principal de web HTTP
#   Axum:  de tokio, moderno y engranado con el ecosistema async
#   Actix Web: maduro y muy veloz
#   Rocket: ergonómico (macros), buen DX
#   warp / hyper (bajo nivel) / salvo (para APIs) / poem
# Comparativa real (benchmarks contemporáneos):
#   Axum y Actix están en el top; Rocket sencillo; salvo en plan rápido

Axum es la opción recomendada hoy (mantenido por tokio, composición por capas); Actix Web para máximo rendimiento; Rocket si prefieres macros ergonómicas.

---

Axum: servidor con tokio Framework

use axum::{
    routing::get, Json, Router, extract::Path,
};
use serde_json::{json, Value};

async fn saludo(Path(nombre): Path<String>) -> Json<Value> {
    Json(json!({ "saludo": format!("Hola {nombre}") }))
}

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/", get(|| async { "Bienvenido" }))
        .route("/saludo/{nombre}", get(saludo));

    let listener = tokio::net::TcpListener::bind("0.0.0.0:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
// Cargo add axum tokio serde serde_json

Axum usa `Router` + handlers async; con tokio de fondo para concurrencia de alto rendimiento. `axum::serve` gestiona el listener.

Actix Web y Rocket Alternativas

// Actix Web
use actix_web::{get, web, App, HttpResponse, HttpServer, Responder};

#[get("/saludo/{nombre}")]
async fn saludo(nombre: web::Path<String>) -> impl Responder {
    HttpResponse::Ok().body(format!("Hola {nombre}"))
}

#[actix_web::main]
async fn main() -> std::io::Result<()> {
    HttpServer::new(|| App::new().service(saludo))
        .bind(("0.0.0.0", 8080))?
        .run().await
}

// Rocket: macros ergonómicas
use rocket::{get, routes};

#[get("/saludo/<nombre>")]
fn saludo(nombre: &str) -> String {
    format!("Hola {nombre}")
}
// #[launch] fn app() -> _ { rocket::build().mount("/", routes![saludo]) }

Actix Web destaca en rendimiento; Rocket en DX (rutas con macro `#[get]`, extractores inline). Ambos resuelven APIs REST completas.

Datos: diesel, sqlx y sea-orm Datos

// sqlx: consultas SQL verificadas en compilación
use sqlx::Row;

#[tokio::main]
async fn main() -> sqlx::Result<()> {
    let pool = sqlx::postgres::PgPoolOptions::new()
        .connect("postgres://app:pass@localhost/app").await?;

    let fila: (i64,) = sqlx::query_as("SELECT count(*) FROM usuarios")
        .fetch_one(&pool).await?;
    println!("usuarios: {}", fila.0);
    Ok(())
}

// Alternativas:
//   diesel: ORM del tipo "query builder" síncrono
//   sea-orm: async, con semejanza a Spring Data
//   rusqlite: driver SQLite directo

sqlx valida la SQL en tiempo de compilación (con la BD conectada en dev); diesel es el veterano typed; sea-orm async moderno para apps grandes.

Testing en Rust Calidad

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn suma_es_correcta() {
        assert_eq!(suma(2, 3), 5);
    }

    #[test]
    #[should_panic]
    fn divide_por_cero_panica() {
        let _ = divide(1, 0);
    }
}

// Integración: tests/ en otra carpeta
// Pruebas de endpoints: tower::ServiceExt + oneshot
// cargo test ; cargo test -- --nocapture ; cargo tarpaulin (cobertura)

Rust trae testing nativo (`#[test]`), doc-tests y herramientas (`cargo test`). Para HTTP: `tower::ServiceExt::oneshot` sobre el Router de Axum.
