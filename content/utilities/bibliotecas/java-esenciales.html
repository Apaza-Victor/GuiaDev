¿Para qué sirve y cuándo usarla? Concepto

Java incluye en el JDK una biblioteca estándar muy completa. Esta página presenta lo esencial: colecciones, streams, fechas con java.time, concurrencia y entrada y salida, además de la base que evita dependencias externas innecesarias.

¿Para qué se usa?

  • Modelar datos y algoritmos con colecciones y streams.
  • Tratar fechas y horas de forma segura con java.time.
  • Escribir código concurrente con java.util.concurrent.

¿En qué casos conviene usarla?

  • En aplicaciones de negocio y backends que corren sobre la JVM.
  • Para migrar código antiguo basado en java.util.Date a java.time.
  • Cuando se quiere reducir dependencias y mantener compatibilidad.

No añadas librerías externas cuando el JDK ya lo cubre: JSON, logging y utilidades básicas vienen incluidos. Confía también en los records y en las interfaces selladas antes que en librerías de boilerplate.

JDK y las librerías principales Base

El JDK trae librerías suficientes para la mayoría de proyectos: colecciones, streams, I/O, fecha, concurrencia, archivos y red.

import java.util.*;
import java.util.stream.*;

// Colecciones e inmutables
List<String> lista = List.of("a", "b", "c");          // inmutable
List<Integer> nums = new ArrayList<>(List.of(3, 1, 2));
Map<String, Integer> edad = new HashMap<>();
edad.put("Ana", 30);

// Streams: pipelines funcionales
int total = nums.stream()
    .filter(n -> n &gt; 1)
    .mapToInt(Integer::intValue)
    .sum();

// Fecha/hora moderno (java.time)
LocalDate hoy = LocalDate.now();
LocalDate navidad = hoy.withMonth(12).withDayOfMonth(25);
long dias = ChronoUnit.DAYS.between(hoy, navidad);

// Archivos
List<String> lineas = Files.readAllLines(Path.of("datos.txt"));
Files.writeString(Path.of("out.txt"), String.join("\n", lineas));

Desde Java 8+ el JDK cubre el 80% de las necesidades. `java.time`, `Files` y los streams modernizan el código sin dependencias externas.

Gestión de dependencias: Maven y Gradle Build

<!-- pom.xml (Maven): declara dependencias automáticamente -->
<dependency>
  <groupId>com.google.guava</groupId>
  <artifactId>guava</artifactId>
  <version>33.0.0-jre</version>
</dependency>

// build.gradle (Gradle: declarativo y flexible)
dependencies {
  implementation 'com.google.guava:guava:33.0.0-jre'
}

mvn dependency:resolve          # descarga las deps
mvn compile                     # compila
mvn package                     # empaqueta jar/war
./gradlew build                 # versionado de Gradle

Maven (XML) y Gradle (Groovy/Kotlin) resuelven dependencias desde Maven Central. Nunca bajes JARs a mano: usa el ecosistema.

Guava y Apache Commons Utilidad

// Guava (Google): utilidades que faltan en el JDK
import com.google.common.collect.*;

ImmutableList<String> inmut = ImmutableList.of("x", "y");
Multimap<String, Integer> mm = ArrayListMultimap.create();
mm.put("Frutas", 1); mm.put("Frutas", 2);   // clave con varios valores

// Apache Commons Lang3: strings y objetos
import org.apache.commons.lang3.StringUtils;
import org.apache.commons.lang3.RandomStringUtils;

String abrev = StringUtils.abbreviate("Guía de desarrollo muy larga", 12);
boolean vacio = StringUtils.isBlank("   ");
String clave = RandomStringUtils.randomAlphanumeric(16);

// Commons IO
import org.apache.commons.io.FileUtils;
List<String> lineas = FileUtils.readLines(new File("datos.txt"), "UTF-8");

Guava (colecciones inmutables, cache, hashing) y Commons (strings, math, io) son las dos librerías de utilidad más usadas de Java juntas.

Logging (SLF4J + Log4j2) y JSON (Jackson) Utilidad

// SLF4J: fachada de logging estándar
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

Logger log = LoggerFactory.getLogger(MiClase.class);
log.info("Servidor en puerto {}", 8080);
log.warn("Uso de memoria {}%", 91);
log.error("Error de conexión", exception);

// Jackson: JSON la "más usada"
import com.fasterxml.jackson.databind.ObjectMapper;

// Clase: record Usuario(String nombre, int edad) {}
ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(new Usuario("Ana", 30));
Usuario u = mapper.readValue(json, Usuario.class);

Jackson domina el JSON (valida, convierte, ignora desconocidas con config). SLF4J hace tus logs intercambiables entre Log4j2, Logback y java.util.logging.

Instalación del JDK Inicio

# Adoptium Temurin LTS (recomendado) o Microsoft OpenJDK
winget install EclipseAdoptium.Temurin.21.JDK     # Windows
# sdkman para Linux/Mac
curl -s "https://get.sdkman.io" | bash
sdk install java 21-tem

# Verificar
java --version
javac --version

# Primer proyecto
mkdir demo && cd demo
echo 'public class Hola { public static void main(String[] a){System.out.println("Hola");} }' > Hola.java
javac Hola.java && java Hola

Usa una distribución LTS (17 o 21) de Temurin/Adoptium. IntelliJ IDEA Community y Maven/Gradle completan el flujo.
