El ecosistema HTML en 2025 Guía

# HTML puro + librerías de markup (sin framework completo):
#   HTMX: interactividad con atributos en el HTML (AJAX declarativo)
#   Alpine.js: comportamientos ligeros en el markup
#   Web Components: etiquetas personalizadas (custom elements + Shadow DOM)
#   Stimulus (Rails) / Petite-Vue  | Liquid/Jinja (templates del server)
# Complementos para usar HTML en el servidor: templating
#   (Handlebars, EJS, Mustache, Twig en backend)
# Recomendación: HTMX o Alpine antes de meter React/Vue/Svelte

HTMX/Alpine añaden interactividad sin framework de JS; los Web Components multiplican el HTML. Si solo necesitas actualizar fragmentos, van a tu rescate.

---

HTMX: interactividad en el HTML HTMX

<script src="https://unpkg.com/htmx.org@2.0.4"></script>

<!-- Cargar fragmentos vía AJAX -->
<button hx-get="/recientes" hx-target="#lista" hx-swap="innerHTML">
  Cargar recientes
</button>
<ul id="lista"></ul>

<!-- Enviar formularios sin recargar -->
<form hx-post="/guardar" hx-target="#respuesta">
  <input name="nombre" />
  <button type="submit">Guardar</button>
</form>
<div id="respuesta"></div>

<!-- Transiciones y polling -->
<div hx-trigger="every 30s" hx-get="/status">estado...</div>

HTMX hace que el servidor devuelva HTML y el cliente lo intercambie con atributos. Menos JS, mismo resultado dinámico; ideal sobre backends tipo Rails, Laravel o Django.

Alpine.js y Web Components Ligero

<script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3.14.1/dist/cdn.min.js"></script>

<!-- Alpine: estado y eventos en el markup -->
<div x-data="{ abierto: false }">
  <button @click="abierto = !abierto">Toggle</button>
  <p x-show="abierto" x-transition>Contenido que aparece</p>
</div>

<!-- Web Components: etiquetas propias encapsuladas -->
<script>
  class TarjetaUsuario extends HTMLElement {
    connectedCallback() {
      this.innerHTML = `<article class="card">
        <h2>${this.getAttribute('nombre')}</h2>
        <slot></slot></article>`;
    }
  }
  customElements.define('tarjeta-usuario', TarjetaUsuario);
</script>
<tarjeta-usuario nombre="Ana"><p>perfil popular</p></tarjeta-usuario>

Alpine te da reactividad mínima; Web Components encapsulan y reutilizan UI abstracta con Shadow DOM. Ambos sin dependencias fuertes y perfectos con HTML vanilla.

Templating: server-side vs client-side Templates

<!-- Client-side: Handlebars (lógica suave) -->
<script src="https://cdn.jsdelivr.net/npm/handlebars@4.7.8/dist/handlebars.min.js"></script>
<script id="plantilla" type="text/x-handlebars-template">
  <li>{{nombre}} — {{edad}} años</li>
</script>
<script>
  const src = document.getElementById('plantilla').innerHTML;
  const templ = Handlebars.compile(src);
  document.getElementById('lista').innerHTML = datos.map(templ).join('');
</script>

<!-- Server-side: EJS / Twig / Jinja2 (en backend) -->

<!-- ejemplo EJS (Node) -->
<ul>
  <% datos.forEach(u => { %>
    <li><%= u.nombre %></li>
  <% }) %>
</ul>

Templates en client (Handlebars/Mustache) pintan datos obtenidos vía AJAX; en server (EJS/Twig/Jinja) se pintan al renderizar. En HTML puro ambos son fáciles de adicionar por CDN.

Ejercicios prácticos Reto

  1. Añade HTMX con hx-get/hx-target para simular carga de una lista.
  2. Migra un toggle de JS manual a Alpine (x-data/x-show).
  3. Define un web component tarjeta-usuario con slot.
  4. Crea una plantilla Handlebars y renderiza 5 elementos.
  5. Combina hx-polling para un estado auto-refrescado.
