¿Para qué sirve y cuándo usarla? Concepto

El ecosistema de herramientas de Python es muy amplio: va desde IDEs completos como PyCharm hasta editores ligeros con extensiones, pasando por cuadernos Jupyter para análisis y gestores de entornos. Esta página compara las opciones y orienta cuál conviene según el tipo de proyecto.

¿Para qué se usa?

  • Desarrollo de aplicaciones y servicios: PyCharm y VS Code con la extensión Python.
  • Ciencia de datos y exploración: Jupyter Notebook y JupyterLab.
  • Gestión de entornos y dependencias: venv, conda, uv y poetry.
  • Calidad de código: linters (ruff), formateadores y tipado con mypy dentro del editor.

¿En qué casos conviene usarla?

  • Proyectos de ingeniería de software: un IDE completo con refactors y tests integrados.
  • Análisis de datos: Jupyter cuando el objetivo es explorar datos de forma iterativa.
  • Proyectos nuevos: crea el entorno virtual y congela dependencias antes de escribir código.

Elegir herramienta no es elegir lenguaje: todas ejecutan el mismo Python. Prioriza un flujo cómodo de entornos virtuales (venv o uv) y nunca instales paquetes en el Python del sistema; el editor se puede cambiar más adelante sin fricción.

PyCharm para productividad tradicional, VS Code para flujo ligero/generoso, JupyterLab para análisis de datos. Todos con depurador interactivo integrado.

Gestores de paquetes modernos: uv, poetry, conda Deps

# uv: el gestor más rápido (reemplaza pip+venv+pipx)
pip install uv
uv venv                    # crea .venv
uv pip install requests    # instala sin pip
uv add requests            # con pyproject (uv.lock reproducible)

# poetry: pyproject con dependencias aisladas
poetry new proyecto
poetry add requests
poetry run python main.py

# conda / mamba: cuando necesitas binarios nativos (numpy, cuda, GDAL)
conda create -n data python=3.12
conda activate data

Hoy se recomienda `uv` o `poetry` con `pyproject.toml`. `conda` sigue siendo útil para entornos científicos con binarios precompilados.

Tipos, linting y formato Calidad

# Tipado
pip install mypy
mypy mi_codigo/                  # verificación de tipos
# pyright (de Microsoft) integrado con Pylance en VS Code

# Linting y formato
pip install ruff
ruff check .                     # lint a velocidad de explosión
ruff format .                    # formateo (auto black-compatible)

# Alternativas clásicas
# black (formato), flake8 (lint), isort (orden imports),
# pre-commit para ejecutarlos antes de cada commit:
#   pre-commit install ; pre-commit run --all-files

def procesar(nombre: str, edad: int) -> dict[str, str]:
    return {"nombre": nombre.upper(), "categoria": "adulto" if edad >= 18 else "menor"}

`ruff` unifica lint+formato en un solo binario ultrarrápido. Añade mypy para tipado fuerte, especialmente útil en proyectos de largo plazo.

Debug y perfilado Diagnóstico

# pdb: depurador interactivo
python -m pdb script.py
# o en el código: breakpoint()

# Post-mortem al ejecutar bajo pdb
python -m pdb -c continue script.py

# Perfilado
python -m cProfile -o perfil.prof script.py
pip install snakeviz
snakeviz perfil.prof             # visual IC

# Memoria
pip install memory_profiler
python -m memory_profiler script.py

# Visual Studio Code: GUI debugger (solo clic en la línea)
# PyCharm: profiler gráfico integrado

cProfile + snakeviz son el par estándar para encontrar cuellos de botella. En los IDEs el debug visual (breakpoints con mouse) suele ser suficiente en el día a día.

Producción: contenedores y CI Cloud

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app/ app/
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]

# GitHub Actions
- uses: actions/setup-python@v5
  with: { python-version: '3.12' }
- run: pip install -r requirements-dev.txt
- run: ruff check .
- run: mypy app/
- run: pytest -v --cov=app --cov-fail-under=80

Imagen `-slim`, desactivar cache de pip, y un pipeline que corra ruff+mypy+pytest antes del push: mínimo de calidad reproducible.
