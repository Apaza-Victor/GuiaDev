¿Para qué sirve y cuándo usarla? Concepto

SQL es el estándar para consultar y gestionar bases de datos relacionales, el almacenamiento de la mayoría de las aplicaciones. Esta página cubre lo esencial: el propio lenguaje (DDL/DML), cómo elegir motor (PostgreSQL, MySQL, SQLite), joins y agregaciones, índices y optimización, y migraciones con Flyway o Liquibase.

¿Para qué se usa?

  • Definir esquemas con DDL y manipular datos con DML estándar.
  • Relacionar tablas con JOIN y resumir con GROUP BY o funciones de ventana.
  • Acelerar consultas con índices y verificar el plan con EXPLAIN.
  • Versionar el esquema con migraciones versionadas.

¿En qué casos conviene usarla?

  • Datos que exigen integridad transaccional (ACID) y relaciones fuertes.
  • Reportes y agregaciones sobre tablas de negocio.
  • Backend persistente de casi cualquier aplicación web o móvil.

Para datos sin estructura rígida o escalabilidad horizontal extrema evalúa NoSQL o JSONB, pero no por inercia: para la mayoría de negocios el SQL transaccional sigue siendo la opción correcta. Y nunca concatenes valores en las consultas: usa parámetros.

SQL: el lenguaje de datos Base

-- SQL standard: consultas, DDL, DML y DCL
-- DDL: estructuras
CREATE TABLE usuarios (
  id        INT PRIMARY KEY AUTO_INCREMENT,
  nombre    VARCHAR(100) NOT NULL,
  email     VARCHAR(255) UNIQUE,
  creado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- DML: datos
INSERT INTO usuarios (nombre, email) VALUES ('Ana', 'ana@example.com');
SELECT nombre, email FROM usuarios WHERE email LIKE '%example.com' ORDER BY nombre;
UPDATE usuarios SET nombre = 'Ana M.' WHERE id = 1;
DELETE FROM usuarios WHERE id = 2;

-- DCL: permisos
GRANT SELECT ON app.* TO 'lector'@'localhost';

El SQL estándar es compartido por PostgreSQL, MySQL, SQL Server, Oracle y SQLite; cada motor añade dialéctos: funciones (`NOW()`, `getdate()`) y tipos.

Elegir motor de base de datos Inicio

# Contexto habitual
#   PostgreSQL: recomendado de facto (open source, robusto, JSONB, GIS)
sudo apt install postgresql postgresql-contrib
#   MySQL / MariaDB: alternativa muy extendida en web legacy
sudo apt install mysql-server
#   SQLite: embebido sin servidor (apps de escritorio/movil/SPAs)
winget install SQLite.SQLite
#   SQL Server: ecosistema Windows/.NET; Oracle: corporativo/legacy

# Conectarse vía CLI
psql -U ana -d miapp          # PostgreSQL
mysql -u ana -p miapp         # MySQL
sqlite3 mi.db                 # SQLite

Para proyectos nuevos elige PostgreSQL; usa SQLite para algo local sin servidor; heredas MySQL/SQL Server/Oracle cuando ya existen en tu entorno.

Joins, agregaciones y funciones ventana Consulta

SELECT c.nombre, o.total
FROM clientes c
LEFT JOIN ordenes o ON o.cliente_id = c.id
ORDER BY o.total DESC;

-- Agregaciones y filtro de grupos
SELECT estado, COUNT(*) AS total, AVG(total) AS promedio
FROM ordenes
GROUP BY estado
HAVING COUNT(*) > 10;

-- Funciones de ventana: filas sin agrupar
SELECT 	n,
        n - LAG(n) OVER (ORDER BY n) AS diff_anterior,
        SUM(n) OVER (ORDER BY n ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS media_movil
FROM numeros;

Domina `JOIN` (INNER/LEFT/RIGHT/FULL), `GROUP BY` + `HAVING`, y las ventanas (`RANK`, `LAG`, `SUM(...) OVER`) que resuelven rankings y comparaciones sin subconsultas.

Índices y optimización Rendimiento

-- Índices: aceleran búsquedas y joins
CREATE INDEX idx_usuarios_email ON usuarios(email);
CREATE INDEX idx_ordenes_cliente ON ordenes(cliente_id, estado);

-- Plan de ejecución (PostgreSQL)
EXPLAIN ANALYZE
SELECT * FROM ordenes o JOIN clientes c ON c.id = o.cliente_id
WHERE c.ciudad = 'Madrid';

-- buenas prácticas de consulta
--   1. Evitar SELECT * salvo prototipos
--   2. Filtrar en WHERE, no en HAVING cuando se pueda
--   3. Preferir EXISTS sobre IN (...) en subconsultas grandes
--   4. Evitar funciones sobre columnas en el WHERE (WHERE year(f) = 2024)

Unificar una columna en el WHERE con función rompe índices: usa rangos (`WHERE f >= '2024-01-01' AND f < '2025-01-01'`) y `EXPLAIN ANALYZE` para confirmar.

Migraciones (Flyway/Liquibase) y seguridad Datos

-- Flyway: migraciones versionadas en archivos .sql
-- V001__crear_usuarios.sql
CREATE TABLE usuarios (id INT PRIMARY KEY, nombre VARCHAR(100) NOT NULL);
-- V002__agrega_email.sql
ALTER TABLE usuarios ADD COLUMN email VARCHAR(255) UNIQUE;
-- Ejecutar: flyway migrate

-- Seguridad básica: parámetros, nunca concatenación (SQL injection)
SELECT * FROM usuarios WHERE email = '?email?' -- prepared statement

-- Backups
pg_dump miapp > backup.sql        -- PostgreSQL
mysqldump miapp > backup.sql      -- MySQL
.sqlite3 mi.db ".backup backup.db"

Versiona el esquema con migraciones (Flyway/Liquibase) en lugar de editar la BD a mano, usa parámetros en consultas dinámicas y programa backups regulares.
