¿Para qué sirve y cuándo usarla? Concepto

El ecosistema de frameworks de Groovy incluye a Grails para aplicaciones web full-stack, Micronaut para microservicios y Ratpack para servidores funcionales y rápidos. Esta página compara estas opciones y cuándo conviene adoptarlas sobre la JVM.

¿Para qué se usa?

  • Desarrollar aplicaciones web completas con convenciones de Grails.
  • Construir microservicios ligeros y de arranque rápido con Micronaut.
  • Servidores HTTP funcionales y de alto rendimiento con Ratpack.
  • Combinar con el ecosistema Java y Gradle para builds y dependencias.

¿En qué casos conviene usarla?

  • Para apps MVC con mucha convención y CRUD, Grails es productivo.
  • Para microservicios donde importa el tiempo de arranque y la huella.
  • Cuando el equipo ya vive en el ecosistema JVM y quiere continuidad.

No elijas un framework Groovy solo porque esté de moda: evalúa la curva y el mantenimiento. Para proyectos nuevos JVM, lenguajes y ecosistemas de Kotlin o Java pueden convenir más; usa Groovy cuando el equipo aporte experiencia en él.

Frameworks Groovy/Grails Guía

# En el mundo Groovy:
#   Grails (MVC completo, igual Spring bajo el hood) - el "Rails de Groovy"
#   Ratpack (ligero, microservicios, reactor)
#   Micronaut (soporta Groovy, compilación nativa)
#   Spring Boot funciona con Groovy también
# Scripting: Jenkins pipelines también usan Groovy (no framework web)

Grails es el framework web integrador (GORM + plugins); Ratpack ligero para micro; Micronaut+Groovy para cloud nativo.

Grails: MVC completo Framework

# Crear proyecto
grails create-app mi-app
cd mi-app
grails run-app         # dev en :8080

// Dominios (Domain/GORM)
package mi.app
class Usuario {
    String nombre
    Integer edad
    static constraints = { nombre blank:false; edad min: 0 }
}

// Controlador (Controller)
package mi.app
class UsuarioController {
    def index() {
        render view: 'index', model: [usuarios: Usuario.list()]
    }
    def guardar() {
        Usuario u = new Usuario(nombre: params.nombre, edad: params.int('edad'))
        u.save()
        redirect action: 'index'
    }
}

Grails da convención-sobre-configuración: GORM (persistencia sobre Hibernate), plugins, GSP (templates) y scaffolding. Común en empresas que usan Groovy.

Ratpack y Micronaut Micro

// Ratpack
import ratpack.groovy.Groovy
import static ratpack.groovy.Groovy.ratpack

ratpack {
    handlers {
        get('saludo/:nombre') { ctx ->
            ctx.render "Hola ${ctx.pathTokens['nombre']}"
        }
        post('usuarios') { ctx ->
            def body = ctx.request.body.text()
            ctx.render(body)
        }
    }
}
// run: ratpack.main / gradle run

// Micronaut + Groovy
import io.micronaut.http.annotation.*

@Controller('/saludo')
class SaludoController {
    @Get('/{nombre}')
    String saludo(String nombre) { "Hola $nombre" }
}
// gradle run / micronaut-cli

Ratpack: handler-based y non-blocking (Netty). Micronaut: DI + compilación a native con GraalVM; ambos por debajo de 100MB y ideales para cloud.

GORM y persistencia Datos

// GORM (Grails Object Relational Mapping) sobre Hibernate
def lista = Usuario.where { edad > 18 }.list(sort: 'nombre')

// create/read/update/delete de dominio
def nuevo = new Usuario(nombre: 'Ana', edad: 30).save(flush: true)
def existente = Usuario.get(1)
existente.edad = 31
existente.save()
existente.delete()

// Consultas: criteria, HQL (Usuario.executeQuery), 
//   findBy / findAllBy (magia de métodos):
def ana = Usuario.findByNombre('Ana')
// sácale más: en GORM también .withCriteria { like 'nombre', 'A%' }

GORM añade finders mágicos (findByNombre), criteria DSL y validaciones del dominio. Fuera de Grails también hay `GORM standalone` para Spring.

Spock: testing especificación Calidad

import spock.lang.Specification

class CalculadoraSpec extends Specification {
    def "suma correcta"() {
        expect:
        Calculadora.suma(a, b) == resultado

        where:
        a | b | resultado
        2 | 3 | 5
        0 | 0 | 0
        -1| 1 | 0
    }

    def "lanza error"() {
        when: Calculadora.divide(1, 0)
        then: thrown(ArithmeticException)
    }
}
// Correr: gradle test o con grails test-app

Spock es la joya de Groovy: tests tipo BDD con tablas `where`, bloques given/when/then. Corre sobre JUnit en CI (Gradle) y con mocks integrados.
