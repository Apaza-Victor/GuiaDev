¿Para qué sirve y cuándo usarla? Concepto

El desarrollo moderno en PHP se apoya en editores potentes y herramientas de calidad. Esta página reúne PHPStorm como IDE de referencia, VS Code con intelephense, Xdebug para depuración, Composer para dependencias y PHPUnit para testing.

¿Para qué se usa?

  • Desarrollar con depuración paso a paso usando Xdebug en el IDE.
  • Obtener autocompletado y análisis de tipos con intelephense en VS Code.
  • Ejecutar pruebas unitarias y de integración con PHPUnit.

¿En qué casos conviene usarla?

  • En proyectos grandes donde importan depuración y refactorizaciones.
  • Para configurar un entorno local sin romper la versión del servidor.
  • Para aplicar calidad con análisis estático y pruebas en el CI.

Xdebug ralentiza PHP notablemente: actívalo solo cuando vayas a depurar y desactívalo el resto del tiempo. Configúralo bien para que el IDE y el CLI compartan el mismo socket.

Análisis estático: PHPStan y Psalm Calidad

<?php
// PHPStan: análisis profundo por niveles (0..9)
function sumar(array $nums): int {
  return array_sum($nums);
}
// $ composer require --dev phpstan/phpstan
// vendor/bin/phpstan analyse src --level=8

# Configuración (phpstan.neon)
parameters:
  level: 8
  paths: [src]
# Psalm: alternativa, con supresión por anotación
# Rector: refactorización automática (PHP 7 a 8, modernizar código)
vendor/bin/rector process src
# Pint (de Laravel): formateador basado en PHP-CS-Fixer
vendor/bin/pint

PHPStan/Psalm encuentra bugs antes de ejecutar. Rector automatiza migraciones. Todos corren en CI sin fricción.

Xdebug y herramientas de debug Debug

# Xdebug: depurador y profiler de PHP
pecl install xdebug        # o apt php-xdebug
# php.ini
zend_extension=xdebug.so
xdebug.mode=debug,develop

# Cómos increibles de depuración
xdebug_break();            # breakpoint en código
xdebug_error_log();
# Profiler: xdebug.mode=profile + Webgrind/cachegrind
# var_dump() y print_r() siguen siendo tus amigos rápidos

# Herramientas de CLI: Laravel Telescope en dev (inspección de requests)
# php -d error_reporting=E_ALL script.php para ver advertencias

Xdebug en modo `debug` ralentiza; actívalo solo en desarrollo/local. Para CI usa `--no-debug` y errores de PHPUnit.

Entornos de desarrollo con Docker Dev

# Imagen oficial: configurar 3 servicios (php, mysql, nginx)
FROM php:8.3-cli
RUN docker-php-ext-install pdo_mysql \
    && apt-get update \
    && apt-get install -y git unzip \
    && curl -sS https://getcomposer.org/installer | php -- --install-dir=/usr/local/bin --filename=composer
WORKDIR /app
COPY . .
RUN composer install
CMD ["php", "-S", "0.0.0.0:8000", "-t", "public"]

# Laravel Sail (docker-compose ya configurado para Laravel)
curl -s "https://laravel.build/example-app" | bash
./vendor/bin/sail up -d
# Laravel Herd/Laragon (Windows/Mac) para Apache/nginx local con una UI

Docker + Composer hacen al equipo idéntico; Laravel Sail envuelve el Dockerfile de Laravel listo para usar. Xampp/Laragon para prototipos rápidos.

Ejercicios prácticos Reto

  1. Instala Intelephense en VS Code y repasa autocompletado/ir-a-definición.
  2. Analiza tu `src/` con PHPStan nivel 8 y corrige 3 errores de tipo.
  3. Coloca un `xdebug_break()` en un endpoint y depura paso a paso desde el editor.
  4. Configura rector para modernizar una función de PHP 5 a PHP 8.
  5. Levanta tu proyecto con Docker multi-servicio (php+mysql+nginx) y navega.
