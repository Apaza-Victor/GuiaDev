¿Para qué sirve y cuándo usarla? Concepto

Esta página reúne el entorno para programar en Julia: la extensión de VS Code, los cuadernos reactivos de Pluto, el REPL interactivo y el gestor de paquetes Pkg, que controla dependencias y entornos por proyecto.

¿Para qué se usa?

  • Desarrollar con autocompletado y depuración visual con la extensión de Julia en VS Code.
  • Explorar el código de forma reactiva con los cuadernos de Pluto.
  • Instalar y gestionar paquetes con Pkg en entornos reproducibles.

¿En qué casos conviene usarla?

  • Para prototipar un análisis en un cuaderno antes de pasarlo a un paquete.
  • Para mantener proyectos de datos con entornos aislados por proyecto.
  • Para iterar sobre funciones en el REPL sin reiniciar el proceso.

Sin Revise, cada cambio de una función obliga a reiniciar el proceso y se pierde el estado. Configúralo al empezar el proyecto para ahorrar horas de recompilación.

Juno? mejor: JuliaFormatter y tooling CLI CLI

# JuliaFormatter.jl: formatter oficial de estilo
using JuliaFormatter
format("src/")          # o format_file
format("src/", overwrite = true)
# CI: format("src/"; verbose=true) y verifica cambios

# Habilidades extra
#   PackageCompiler.jl: crea binaries nativos (sysimage)
#     using PackageCompiler; create_app("proyecto","mi_app")
#   BenchmarkTools: @benchmark para microbenchmarks
using BenchmarkTools
@benchmark suma(2, 3)

# terminal con julia
julia -e 'println("hola")'
julia -e 'include("script.jl")'
julia --project=. -e 'using Pkg; Pkg.status()'
# REPL: shift+enter multipline

JuliaFormatter estandariza; BenchmarkTools hace microbenchmarks fiables; PackageCompiler crea ejecutables/sysimag (arranque instantáneo). Estos son los aliados del tooling Julia moderno.

Depuración y perfilado Debug

# @show / @info para inspección rápida
@show variable sensata

# Debugger: VS Code (DAP) o
using Debugger
@enter mi_funcion(42)     # step-by-step interactivo en REPL

# Profiling
using Profile
@profile mi_funcion(datos)
Profile.print()
# PProf.jl → pprof UI para flamegraph

# Code tools: @code_lowered, @code_llvm, @code_native
#   para verificar que la compilación bajó sin boxes
mf = @code_warntype mi_funcion(42)   # warnings de tipado perezoso

Julia compila al vuelo; los patrones de "type instability" degradan rendimiento. `@code_warntype` muestra esas fugas y `Profiler+pprof` mide hot spots reales.

Compilar y desplegar Julia Ops

# PackageCompiler: binario standalone (sysimage)
julia --project=. -e 'using PackageCompiler; create_app(".", "mi_app")'
./mi_app/bin/mi_app

# Contenedor

FROM julia:1.10-slim
WORKDIR /app
COPY Project.toml Manifest.toml ./
COPY src src
RUN julia --project=. -e 'using Pkg; Pkg.instantiate()' \
  && julia --project=. -e 'using PackageCompiler; create_app(".", "app_build")'
CMD ["./app_build/bin/app_build"]

Con PackageCompiler produces un binario nativo (sin arrancar LLVM cada vez); la imagen `julia:slim` es grande pero los ejecutables sirven bien en servicios/APIs.

Ejercicios prácticos Reto

  1. Ejecuta una función pesada y observa la compilación (primera vs segunda).
  2. Formatea tu proyecto con JuliaFormatter y pídelo estricto en CI.
  3. Haz un benchmark con @benchmark y recuerda los resultados.
  4. Inspecciona con @code_warntype una función con empuje a Any.
  5. Construye el ejecutable con PackageCompiler y mide el arranque.
