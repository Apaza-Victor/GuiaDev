¿Para qué sirve y cuándo usarla? Concepto

Esta página reúne el equipamiento para desarrollar en Java: IDEs como IntelliJ IDEA, Eclipse y VS Code; gestores de build y dependencias como Maven y Gradle; y las herramientas de pruebas y análisis de la JVM.

¿Para qué se usa?

  • Editar, refactorizar y navegar código con un IDE con soporte maduro de Java.
  • Gestionar dependencias, compilación y empaquetado con Maven o Gradle.
  • Ejecutar pruebas con JUnit y explorar la JVM con JShell y perfiladores.

¿En qué casos conviene usarla?

  • Para empezar un proyecto nuevo con una estructura estándar.
  • Para refactorizar código grande con seguridad frente a cambios.
  • Para experimentar fragmentos de Java en JShell sin compilar clases completas.

No dejes que el IDE elija las versiones por ti: fija una versión Java LTS, usa toolchains y comparte la configuración de formato del equipo para que todo el mundo compile igual.

Build tools: Maven y Gradle Build

# Maven: convención sobre configuración (más popular)
mvn archetype:generate -DgroupId=com.demo -DartifactId=app -Dversion=1.0
cd app && mvn clean package && java -jar target/app.jar
mvn dependency:tree      # ver árbol de dependencias
mvn test                 # correr tests JUnit

# Gradle: flexible y rápido (wrapper para versionar)
./gradlew clean build
./gradlew test --tests "*CalculadoraTest*"
# Kotlin DSL (build.gradle.kts) es la variante moderna

Con Java puedes necesitar `--add-opens` / `--enable-preview` para módulos; Maven/Gradle los manejan via ``/`jvmArgs`.

Herramientas de JVM: jcmd, jmap, javap Diagnóstico

# JVM aún corriendo: jps lista procesos Java
jps -l
# jcmd: inspeccionar "live" un proceso
jcmd 12345 Thread.print          # stack traces de todos los hilos
jcmd 12345 GC.heap_info          # estado del heap
# jmap: dump de heap para análisis Offline (MAT)
jmap -dump:format=b,file=heap.bin 12345
# javap: desensamblar la clase (ver bytecode)
javap -c MiClase
# jhat / Eclipse MAT / VisualVM para lectura de dumps
# JFR (Flight Recorder) ahora openjdk: jcmd 12345 JFR.start

`jcmd Thread.print` ante un "hang" muestra dónde se quedó cada hilo. Un heap dump + Eclipse MAT resuelve fugas de memoria. Todo esto es gratis dentro del JDK.

Contenedores y CI con Java Cloud

# Multi-stage: construir en uno, ejecutar en imagen ligera
FROM maven:3.9 AS build
WORKDIR /app
COPY pom.xml . && RUN mvn -B dependency:go-offline
COPY src src
RUN mvn -B package -DskipTests

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/target/app.jar app.jar
EXPOSE 8080
CMD ["java", "-XX:+UseZGC", "-jar", "app.jar"]

# CI (GitHub Actions): test + build + coordinador imagen
- uses: actions/checkout@v4
- uses: actions/setup-java@v4
  with: { distribution: temurin, java-version: '21' }
- run: mvn -B verify

Imágenes JRE (sin JDK) hacen el despliegue más pequeño. Docker multistage + un pipeline que corre `mvn verify` es la ruta a producción segura en Java.

Lombok y las mejoras modernas Moderno

// Lombok: reducir boilerplate
package com.demo;
import lombok.*;

@Getter @Setter @NoArgsConstructor @AllArgsConstructor
public class UsuarioDTO {
  private Long id;
  private String nombre;
  private int edad;
}

// Con records de Java 16+ (ya sin Lombok para data classes)
public record Usuario(Long id, String nombre, int edad) {
  // auto: constructor, equals, hashCode, toString, accessores
}

// Otras mejoras: var (Java 10+), switch-expression (14), text blocks (15+),
// pattern matching (21), virtual threads/Project Loom (21)

Prefer records para DTO/data classes; Lombok útil para clases que no pueden ser records. Virtual Threads (Java 21) simplifican la concurrencia con alto rendimiento.

Ejercicios prácticos Reto

  1. Crea un proyecto Maven desde cero con un `record` y un test JUnit 5.
  2. Usa `jcmd Thread.print` contra una app que simule un hang y localiza el hilo.
  3. Genera un heap dump con jmap y ábrelo en Eclipse MAT identificando el mayor objeto.
  4. Escribe un Dockerfile multi-stage y contruye/ejecuta tu app dentro.
  5. Implementa el mismo DTO con Lombok y con un record; compara el bytecode.
