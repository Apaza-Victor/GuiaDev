Xcode: el IDE de Apple IDE

# Xcode (App Store, macOS): IDE oficial de Apple
xcode-select --install        # CLI tools con swift y clang
xcodebuild -version
# componentes: editor+debug+Interface Builder+Simulator
# scheme/workspace para maquetar; pruebas ⌘U; perfiles ⌘I

# Desde terminal: trae swiftc, swift, xcrun (wrappers, sign)
xcrun simctl list
# crear un simulador iOS y lanzar la app

Xcode es obligatorio para apps Apple: editor, debugger (LLDB), Interface Builder, perfiles (Instruments) e integración con Xcode Cloud (CI).

`swift-format` es el oficial; SwiftLint es el guardián de estilo de facto; `swift test --enable-code-coverage` + xccov para métricas.

# logs y tiempos
print("debug: \(valor)")
// os_log (sistema) / Logger (framework moderno)
import os
let logger = Logger(subsystem: "app", category: "net")

# Performance profiling en Xcode Instruments:
#   Time Profiler, Allocations, Leaks, Energy

LLDB es potente pero crudo; en Xcode se usa vía GUI. `Logger`/`os_log` estructuran los logs; Instruments detecta leaks y energía en la fase de perfiles.

Despliegue y CI Swift Ops

# Backend Vapor en contenedor

FROM swift:6.0 AS build
WORKDIR /app
COPY . .
RUN swift build -c release --static-swift-stdlib

FROM swift:6.0-jammy AS runtime
WORKDIR /app
COPY --from=build /app/.build/release/Run .
EXPOSE 8080
CMD ["./Run", "serve", "--hostname", "0.0.0.0", "--port", "8080"]

# Apps iOS: App Store Connect + Xcode Cloud / Fastlane
#   fastlane lane deploy (beta/release), firma, TestFlight
# CI en GitHub Actions: usar macos-14 runner con Xcode

Backend Swift corre en servidores Linux sin problema (Docker con swift-slim). Apps Apple necesitan macOS runner + firma; Fastlane automatiza certificados y subida.
