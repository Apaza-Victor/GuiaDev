PowerShell es el lenguaje de automatización de Windows + DevOps. Para APIs HTTP internas: el módulo Pode. Pero su valor real: configurar y desplegar todo.

---

Pode y Invoke-RestMethod: web con PS Web

# Pode: framework web en PS (server con rutas)
Install-Module Pode

# server.ps1
Import-Module Pode
Start-PodeServer {
    Add-PodeEndpoint -Address * -Port 8080 -Protocol Http
    Add-PodeRoute -Method Get -Path '/saludo/:nombre' -ScriptBlock {
        Write-PodeJsonResponse -Value @{ saludo = "Hola $($args[0])" }
    }
    Add-PodeRoute -Method Post -Path '/datos' -ScriptBlock {
        $body = Read-PodeRequestJson
        Write-PodeJsonResponse -Value @{ recibido = $body.nombre }
    }
}
# pwsh ./server.ps1

# Desde otros scripts el cliente: Invoke-RestMethod (ya visto)

Pode sirve APIs HTTP/WebSocket en PowerShell puro; ideal para tools internas o mock servers. `Invoke-RestMethod` es el cliente universal para consumir cualquier API.

Az PowerShell y AWS.Tools Cloud

# Azure: Az module
Install-Module -Name Az -Scope CurrentUser -Force
# Login y tareas
Connect-AzAccount
New-AzResourceGroup -Name mi-grupo -Location 'eastus'
New-AzVM -ResourceGroupName mi-grupo -Name mi-vm -Location 'eastus' `
    -Image 'Win2022Datacenter' -Credential (Get-Credential) -OpenPorts 3389
Get-AzVM | Select-Object Name, Location

# AWS: AWS.Tools (modulares)
Install-Module -Name AWS.Tools.EC2
Set-AWSCredential -ProfileName default
New-EC2Instance -ImageId ami-... -InstanceType t3.micro -KeyName mi-llave
Get-EC2Instance

# ambos interoperan con pipeline y secreto en vault

Az.* e AWS.Tools.* permiten orquestar toda la nube desde PS: crear infra, funciones, secretos. Identidad: Connect-AzAccount / Set-AWSCredential con perfiles.

DSC y automatización de config Config

# DSC (Desired State Configuration): declarativo
Configuration WebServerCFG {
    Node 'localhost' {
        WindowsFeature IIS { Ensure = 'Present'; Name = 'Web-Server' }
        Service Spooler { Ensure = 'Running'; Name = 'Spooler' }
        File AppDir { Ensure = 'Present'; DestinationPath = 'C:\App' }
    }
}
Compress-Archive -Path .\WebServerCFG -DestinationPath cfg.zip
# Aplicar: Start-DSCConfiguration -Path .\WebServerCFG -Wait -Force

Pester: testing de scripts Calidad

# Pester 5
Describe 'Calculadora' {
    It 'suma correcta' {
        Calculadora::Suma 2 3 | Should -Be 5
    }
    It 'lanza con división por cero' {
        { Calculadora::Divide 1 0 } | Should -Throw
    }
}
# Correr: Invoke-Pester ./tests/
# Tests de funciones: puede mockear:
Mock Get-Content { return '{"a": 1}' }
# Cobertura: Invoke-Pester -CodeCoverage ./mi-module.psm1

Pester es el framework de tests de PS (BDD: Describe/It/Should). Mockea cmdlets externos para tests aislados; se integra en GitHub Actions (pwsh) y Azure DevOps.
