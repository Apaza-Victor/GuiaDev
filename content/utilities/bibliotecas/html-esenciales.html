HTML semántico: la base de todo Base

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Página semántica</title>
</head>
<body>
  <header> <!-- logotipo y nav -->
    <nav aria-label="Principal">
      <ul><li><a href="#inicio">Inicio</a></li>
          <li><a href="#contacto">Contacto</a></li></ul>
    </nav>
  </header>
  <main>
    <section id="inicio">...</section>
    <article> <!-- contenido autónomo --> </article>
    <aside> <!-- contenido lateral, no esencial --> </aside>
  </main>
  <footer><p>© 2025 GuiaDev</p></footer>
</body>
</html>
<!-- Semántica = estructura con significado: header/nav/main/section/article/aside/footer -->

Usa HTML semántico antes que divs: mejora SEO, accesibilidad y mantenimiento. `

/
/
/
/
` comunican el significado de cada bloque.

Formularios y multimedia Interacción

<!-- Formularios accesibles: label siempre asociado -->
<form action="/register" method="post">
  <label for="nombre">Nombre</label>
  <input id="nombre" name="nombre" type="text" required autocomplete="name" />

  <label for="correo">Correo</label>
  <input id="correo" name="correo" type="email" required autocomplete="email" />

  <fieldset>
    <legend>Plan</legend>
    <label><input type="radio" name="plan" value="basic" /> Básico</label>
    <label><input type="radio" name="plan" value="pro" /> Pro</label>
  </fieldset>

  <button type="submit">Enviar</button>
</form>

<!-- Multimedia con fallbacks -->
<img src="foto.jpg" alt="Descripción de la foto" loading="lazy" />
<picture>
  <source srcset="foto.webp" type="image/webp" />
  <img src="foto.png" alt="..." />
</picture>
<video controls preload="metadata"><source src="clip.mp4" /></video>

Accesibilidad: WAI-ARIA y buenas prácticas A11y

<!-- ARIA solo cuando el HTML no basta -->
<button aria-label="Cerrar modal">×</button>
<div role="alert" aria-live="assertive">Error guardando</div>
<nav aria-label="Breadcrumb">
  <ol><li><a href="/">Inicio</a></li>
      <li><a href="/guias">Guías</a></li></ol>
</nav>

<!-- Semántica primero: -->
<!--  - un solo h1 por página -->
<!--  - enlaces con texto descriptivo (no "click aquí") -->
<!--  - lang en <html> y metadescription -->
<!--  - atributos: tabindex=0 / :focus-visible -->

Regla de oro: etiqueta nativa > ARIA. Contraste, navegación por teclado y navegación semánticamente clara son las prioridades. Valida con el W3C validator y Lighthouse.

Empezar y verificar HTML Inicio

# HTML no "se instala": editas un archivo y lo abres en el navegador
# Herramientas de desarrollo:
#   - Editor: VS Code + extensiones (HTML CSS Support, Prettier)
#   - Validación: https://validator.w3.org (o "npx html-validate")
npm i -D html-validate
npx html-validate src/
#   - Rendimiento: Chrome DevTools (F12) + Lighthouse
#   - Compatibilidad: caniuse.com para resolver features

# Build para proyecto serio: vite/parcel (ver módulo de herramientas)
npm create vite@latest mi-sitio -- --template vanilla

Empezar es abrir VS Code y crear `index.html`. Para validar estructura: W3C validator o html-validate. Cuando crezca, Vite te da live-reload y build.
