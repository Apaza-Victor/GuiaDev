El stack de Elixir Guía

# Phoenix: el framework web de facto (MVC, LiveView, WebSocket)
#   - full stack (HTML+channels) y también API JSON
# Plug: capa HTTP mínima sobre Cowboy/bandit (como Rack)
# Ecto: base de datos + validador (schema/query) junto con Phoenix
# LiveView: UI en tiempo real sin escribir JS (server-rendered)
# Alternative: Absinthe (GraphQL oficial de Elixir)

Phoenix lo cubre todo (rutas+channels+json); Ecto la persistencia; LiveView te da interactividad en servidor. Absinthe para GraphQL.

---

Phoenix: web completo y LiveView Framework

# Generar un proyecto
mix phx.new mi_app --no-assets --database sqlite3
cd mi_app && mix deps.get
mix phx.server            # localhost:4000

# lib/mi_app_web/router.ex (ejemplo)
defmodule MiAppWeb.Router do
  use MiAppWeb, :router
  pipeline :api do
    plug :accepts, ["json"]
  end
  scope "/api", MiAppWeb do
    pipe_through :api
    get "/saludo/:nombre", SaludoController, :index
  end
end

# Controlador
defmodule MiAppWeb.SaludoController do
  use MiAppWeb, :controller
  def index(conn, %{"nombre" => nombre}) do
    json(conn, %{saludo => "Hola #{nombre}"})
  end
end

# LiveView: render diffs por websocket
#   def render(assigns) ... live components

Phoenix separa router/controller/view; LiveView reutiliza el servidor para diffs en tiempo real. Con `--no-assets` incluso encuentras todo lo mínimo. Es el stack estándar de Elixir.

Ecto: esquemas y queries Datos

defmodule MiApp.Usuario do
  use Ecto.Schema
  import Ecto.Changeset
  schema "usuarios" do
    field :nombre, :string
    field :edad, :integer
    timestamps()
  end
  def cambios(usuario, params) do
    usuario
    |> cast(params, [:nombre, :edad])
    |> validate_required([:nombre])
    |> validate_number(:edad, greater_than: 0)
  end
end

# Y en el contexto/repo:
# Ecto.Query: Usuario |> where([u], u.edad > 18) |> Repo.all()
# Repo.insert! / Repo.get! / update_all...
# Migraciones con mix ecto.migrate

Ecto es ORM+changesets: esquema (schema), changeset para validar/cast, y el DSL Ecto.Query. Con `mix ecto.setup` creas BD y la migración inicial.

OTP: GenServer y supervisores OTP

defmodule Contador do
  use GenServer

  def start_link(init \\ 0), do: GenServer.start_link(__MODULE__, init)

  def incrementar(pid), do: GenServer.call(pid, :incrementar)

  @impl true
  def init(n), do: {:ok, n}

  @impl true
  def handle_call(:incrementar, _from, n), do: {:reply, n + 1, n + 1}

  @impl true
  def handle_info(:reset, _n), do: {:noreply, 0}
end

# Supervisores: OTPSupervisor para auto-restart de procesos
# children = [{Contador, []}]
# OTP da aislamiento de fallos y concurrencia del sistema

GenServer encapsula estado+concurrencia y supervisores reinician procesos; esa robustez OTP es la razón principal de elegir Elixir/Erlang para sistemas de alto tráfico.

Testing: ExUnit y doctest Calidad

defmodule CalculadoraTest do
  # test "suma" do assert ... end
  use ExUnit.Case, async: true

  test "suma correcta" do
    assert Calculadora.suma(2, 3) == 5
  end

  test "división por cero lanza error" do
    assert_raise ArithmeticError, fn -> Calculadora.divide(1, 0) end
  end
end

# doctest: pruebas de documentación dentro de @doc
# @doc """
#   iex> Calculadora.suma(1, 2)
#   3
# """
# Correr: mix test ; mix test --trace ; cover: mix test --cover

ExUnit es simple y potente (async, corre en clúster); `doctest` prueba ejemplos del @doc; `--cover` calcula cobertura. Para fuzz: StreamData. Todo con `mix test`.
