¿Para qué sirve y cuándo usarla? Concepto

Esta página reúne el entorno de trabajo necesario para programar en Haskell: el compilador GHC, los gestores de proyectos Cabal y Stack, el intérprete GHCi y la integración con editores mediante haskell-language-server.

¿Para qué se usa?

  • Compilar y ejecutar programas con GHC y automatizar dependencias con Cabal o Stack.
  • Explorar código e iterar expresiones con el intérprete GHCi.
  • Obtener autocompletado, diagnósticos y refactorizaciones con haskell-language-server.

¿En qué casos conviene usarla?

  • Para montar el primer proyecto Haskell sin perder tiempo en la toolchain.
  • Para probar fragmentos sueltos en GHCi antes de integrarlos en el fichero.
  • Para trabajar en el editor con el compilador y el LSP en la misma versión.

Haskell-language-server suele ir un paso por detrás de las versiones nuevas de GHC. Instala la toolchain que recomienda tu gestor para que el LSP y el compilador hablen la misma versión y evites diagnósticos falsos.

IDEs y GHCi IDE

# VS Code: extensión "Haskell" (haskell-language-server LSP)
code --install-extension haskell.haskell
# haskell-language-server: completado, tipos, refactors, full LSP
# Opción alternativa: Neovim con haskell-language-server
# IntelliJ Haskell plugin (alternativo)

# GHCi: REPL potente
ghci
#   :t expresion   (tipo)
#   :i función     (info)
#   :reload        (cargar de nuevo)
#   :set -Wall     (warnings)
# Config de formato se delega a ormolu

haskell-language-server es el LSP de referencia y otorga HLS, refactors, types via GHC. GHCi con `:t`/`:i` sigue siendo el maestro para explorar.

---

ormolu, fourmolu y herramientas CLI CLI

# Formato: ormolu (moderno) / Fourmolu (fork configurable)
cabal install ormolu
ormolu -i -m inplace src/Main.hs
ormolu --mode check src/**/*.hs   # CI

# hlint: linter de sugerencias (definitiva)
cabal install hlint
hlint src/                       # muestra sugerencias (no reescribe)

# análisis de tipos
cabal build --ghc-options="-Wall -Werror"
# profiling trabaja con la RTS del binario compilado
# haskell-language-server integra ormolu+hlint en el editor

ormolu es el estilo oficial; hlint recomienda refactors; GHC con `-Wall -Werror` convierte advertencias en errores en el build (CI ideal).

Depurar y perfilar Haskell Debug

# GHCi debugger integrado
ghci -d Debug
#   :break function, :trace, :backtrace, :print var
# tracer más simple: DuckDebug / liftIO (print intermedia)
# Debug sencillo intermedio: imprimir en IO (liftIO . print)
# profiling con RTS flags (uso de heap)
cabal build --enable-profiling
./app +RTS -p -RTS           # genera app.prof
ghc-prof-flamegraph app.prof # representa visualmente

# memory: +RTS -hT ; hp2ps profiler

Con `:break`/`:trace` de GHCi puedes depurar; para rendimiento/uso de memoria la combinación profiling (+RTS -p/-hT) y flamegraph del profiler es lo habitual.

Compilar y desplegar Ops

# Binario estático con GHC
cabal build
ghc --make -O2 src/Main.hs -o mi-app
# static linking a glibc en Linux (GHC) para binario portable

FROM haskell:9.6 AS build
WORKDIR /app
COPY . .
RUN cabal update && cabal build --offline

FROM ubuntu:22.04
WORKDIR /app
COPY --from=build /app/dist-newstyle/build/*/*/x/mi-app/build/mi-app/mi-app .
EXPOSE 8080
CMD ["./mi-app"]

GHC con `-O2` y linking estático produce binarios standalone; la imagen final (Ubuntu base + binario) es pequeña. La etapa build lleva stack completo (GHC).

Ejercicios prácticos Reto

  1. Instala haskell-language-server y explora autocompletado en un script.
  2. Corre hlint sobre tu proyecto y aplica 3 sugerencias.
  3. Formatea con ormolu y revisa el diff (-mode check en CI).
  4. Perfilea el uso de memoria de una función recursiva con -hT.
  5. Compila con -O2 y prueba el binario estático en Docker.
