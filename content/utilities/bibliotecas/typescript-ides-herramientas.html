¿Para qué sirve y cuándo usarla? Concepto

El tooling de TypeScript se apoya en editores con soporte nativo de tipos (VS Code), el compilador `tsc` y herramientas de calidad como ESLint, Prettier, Biome y Vitest. Una buena configuración de editor y CI reduce errores de tipos y estilos en cada commit.

¿Para qué se usa?

  • Edición con auto-completado y diagnóstico de tipos en vivo.
  • Lint y format del código con ESLint + Prettier o Biome.
  • Compilación y tests con `tsc` y Vitest/Jest.

¿En qué casos conviene usarla?

  • Equipos que quieren revisiones automáticas de tipos en CI.
  • Refactors grandes donde el editor muestra los errores al instante.
  • Monorepos con múltiples paquetes TS (pnpm + workspaces).

No sobre-cargues: cada herramienta añade latencia y configuración. Empieza con VS Code + `tsc --noEmit` en CI y agrega linters solo cuando el proyecto lo necesite.

Editores y herramientas de CI IDE

# VS Code es el predilecto (typescript + vuelve al LSP tsserver nativo)
code --install-extension dbaeumer.vscode-eslint
code --install-extension esbenp.prettier-vscode
# JetBrains WebStorm / IntelliJ: potentes pero de pago
# Neovim + typescript-language-server

# Pipeline de calidad obligatoría en TS
npm run typecheck     # tsc --noEmit
npm run lint          # eslint
npx prettier --check .   # formato
npm run test
# Fails en CI si cualquiera falla; usa npm scripts centralizados

Integra `tsc --noEmit`, ESLint (para TS) y Prettier como scripts; el editor y el CI comparten la misma configuración y no hay sorpresas.

El LSP (tsserver/typescript-language-server) Editor

# El editor habla con TS mediante el protocolo LSP:
#   - autocompletado, ir a definición, renombrar, refactorización
#   - "quick fix" de errores directamente en el editor
# VS Code trae el TS nativo (no tsserver aparte)
# Tip: usa "typescript.tsdk" para apuntar a un SDK concreto

# Herramientas CLI derivadas del LSP
npx ts-node script.ts          # ejecutar TS al vuelo
npx tsx script.ts              # esd moderna, rápido
node --experimental-strip-types script.ts   # Node 22.6+ con stripping

Node moderno puede ejecutar TS directo con strip-types (sin typecheck). Para apps: los bundlers (Vite/tsup) se encargan de la transformación.

Monorepos y empaquetado Escala

# Monorepos con workspaces (pnpm / npm / yarn)
# pnpm-workspace.yaml
packages:
  - packages/*

# Turborepo pnpm dev/test/build con caché
npx create-turbo@latest
pnpm add turbo --save-dev

# Empaquetar librerías TS
# tsup (esbuild): rápido, genera CJS+ESM+d.ts
npx tsup src/index.ts --dts --format esm,cjs
# alternatives: rollup/tsup, esbuild, tsc --declaration
# Publicar a npm: npm run build && npm publish --access public

Con pnpm workspaces + Turborepo gestionas múltiples paquetes en un repo con caché de builds. tsup empaqueta librerías en segundos con tipos.

Debugging y rendimiento Diagnóstico

# En el navegador: DevTools (sources maps de Vite/Rollup)
# en Node: node --inspect y attach del editor
node --inspect dist/server.js

# Node --prof
node --prof dist/server.js && node --prof-process v8.log > perfil.txt

# source maps: output estándar "inlineSourceMap" en tsconfig para debug
# - Memoria: chrome devtools profile/heap snapshot (SPA)
#   o --inspect + Chrome DevTools en Node
# - Otros: `npx tsx --inspect script.ts`  (script sin compilar)

source maps hacen que el debug de TS sea transparente; en Node usa `node --inspect` con el editor para breakpoints con tipado correcto.

Despliegue: contenedores y edge Cloud

FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY --from=build /app/package*.json ./
RUN npm ci --omit=dev
EXPOSE 3000
CMD ["node", "dist/index.js"]

# Edge y funciones serverless (Hono/Workers)
# Vercel/Netlify: deploy directo de Next.js
# Cloudflare Workers: Hono o Workers frameworks
# Render/Fly/Linode: cualquier proceso Node

Compila con multi-stage, instala `--omit=dev` en la imagen final y expone solo el `dist`. El edge + Hono reduce la latencia en funciones serverless.
