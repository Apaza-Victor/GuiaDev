4.1 Controladores y acciones

Qué es un controlador

Un controlador recibe las peticiones HTTP y coordina la respuesta. Cada método público del controlador es una acción que se corresponde con una ruta.

Estructura de un controlador

# app/controllers/articulos_controller.rb
class ArticulosController < ApplicationController
  def index
    @articulos = Articulo.all
  end

  def show
    @articulo = Articulo.find(params[:id])
  end

  def new
    @articulo = Articulo.new
  end

  def create
    @articulo = Articulo.new(articulo_params)
    if @articulo.save
      redirect_to @articulo, notice: "Artículo creado"
    else
      render :new
    end
  end

  private

  def articulo_params
    params.require(:articulo).permit(:titulo, :contenido)
  end
end

Convenciones

  • Los controladores heredan de ApplicationController
  • El nombre va en plural: ArticulosController
  • Cada acción por defecto renderiza la vista con el mismo nombre
  • Las variables de instancia (@articulo) se comparten con la vista

4.2 Render y redirecciones

Acciones de respuesta

Un controlador termina cada acción de una de estas formas:

MétodoQué haceCuándo usarlo
renderMuestra una vista específicaFormularios con errores
redirect_toEnvía una redirección HTTPDespués de crear o actualizar
headResponde sin cuerpoOperaciones sin contenido

Ejemplos de render

# Renderizar la vista por defecto (mismo nombre de acción)
def index
  @productos = Producto.all
  # Implícitamente render :index
end

# Render de otra vista dentro del mismo controlador
def create
  @producto = Producto.new(producto_params)
  if @producto.save
    redirect_to @producto
  else
    # Muestra de nuevo 'new' para corregir los errores
    render :new, status: :unprocessable_entity
  end
end

# Render de una vista de otro controlador
render "compartido/error"

# Render de JSON (muy útil en APIs)
render json: @producto

# Render de texto plano
render plain: "Hola mundo"
Usa redirect_to tras mutar datos para evitar el doble envío de formularios al recargar la página (patrón PRG: Post-Redirect-Get).

4.3 Vistas ERB

Qué es ERB

ERB (Embedded Ruby) permite mezclar HTML con código Ruby. Las vistas tienen extensión .html.erb y viven en app/views/nombre_controlador/.

Etiquetas ERB

EtiquetaFunciónEjemplo
<%= %>Evalúa y muestra el resultado<%= @producto.nombre %>
<% %>Ejecuta sin mostrar nada<% if @producto %>
<%# %>Comentario ERB<%# solo para ti %>

Ejemplo de vista

<h1>Lista de productos</h1>

<ul>
  <% @productos.each do |producto| %>
    <li>
      <%= link_to producto.nombre, producto %>
      <%= number_to_currency(producto.precio) %>
    </li>
  <% end %>
</ul>

<% if @productos.empty? %>
  <p>No hay productos registrados.</p>
<% end %>
Usa <%= %> con escape automático. Rails escapa el HTML por defecto para prevenir ataques XSS.

4.4 Layouts

Qué es un layout

Un layout es la plantilla común que envuelve todas las vistas. Define el esqueleto HTML: cabecera, menú, pie de página.

Layout por defecto

<!-- app/views/layouts/application.html.erb -->
<!DOCTYPE html>
<html>
<head>
  <title><%= content_for(:title) || "Mi Tienda" %></title>
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <%= csrf_meta_tags %>
  <%= csp_meta_tag %>
  <%= stylesheet_link_tag "application", "data-turbo-track": "reload" %>
  <%= javascript_importmap_tags %>
</head>
<body>
  <header>
    <nav>Menu principal</nav>
  </header>

  <main>
    <%= yield %>
  </main>

  <footer>
    <p>Mi Tienda 2026</p>
  </footer>
</body>
</html>

Uso de content_for y yield

Puedes definir bloques de contenido que el layout coloca en zonas concretas:

<!-- En una vista -->
<% content_for :title do %>
  Productos - Mi Tienda
<% end %>

<!-- En el layout -->
<title><%= content_for(:title) %></title>
<aside><%= content_for(:sidebar) %></aside>

Layouts específicos por controlador

class AdminController < ApplicationController
  layout "admin"
end

4.5 Partials

Qué son los partials

Los partials son fragmentos de vista reutilizables. Su nombre empieza con guión bajo, por ejemplo _producto.html.erb, y se renderizan desde otras vistas.

Crear y renderizar un partial

<!-- app/views/productos/_producto.html.erb -->
<div class="producto-card">
  <h3><%= producto.nombre %></h3>
  <p><%= producto.descripcion %></p>
  <span class="precio"><%= number_to_currency(producto.precio) %></span>
</div>
<!-- app/views/productos/index.html.erb -->
<h1>Todos los productos</h1>

<div class="grid">
  <%= render @productos %>
</div>

<!-- También podemos pasarlo explícitamente -->
<%= render "producto", producto: @producto %>

Partials con variables y colecciones

<!-- Render de una colección con variable local producto -->
<%= render partial: "producto", collection: @productos %>

<!-- Partial con una variable local específica -->
<%= render "producto", producto: @producto %>

Partials compartidos entre vistas

<!-- app/views/compartido/_formulario_busqueda.html.erb -->
<%= form_with url: buscar_path, method: :get do |form| %>
  <%= form.text_field :q, placeholder: "Buscar..." %>
  <%= form.submit "Buscar" %>
<% end %>
<!-- Usarlo en cualquier vista -->
<%= render "compartido/formulario_busqueda" %>

4.6 Strong Parameters y CSRF

Strong Parameters

Rails exige que indiques explícitamente qué parámetros se permiten en las peticiones. Esto evita ataques de asignación masiva:

class ProductosController < ApplicationController
  def create
    @producto = Producto.new(producto_params)
    # ...
  end

  private

  def producto_params
    params.require(:producto).permit(:nombre, :precio, :stock, :categoria_id)
  end
end

Nested parameters

# Permitir parámetros anidados
params.require(:producto).permit(
  :nombre,
  categoria_attributes: [:id, :nombre, :_destroy]
)

Protección CSRF

CSRF (Cross-Site Request Forgery) protege contra peticiones maliciosas. Rails lo habilita por defecto en ApplicationController:

class ApplicationController < ActionController::Base
  # Evita ataques CSRF lanzando una excepción
  protect_from_forgery with: :exception
end

En las vistas se incluye el token automáticamente dentro de los formularios generados con form_with.

Nunca uses skip_forgery_protection salvo que tengas una razon clara, como endpoints API con autenticación por token externo.

Resumen

**Lo que aprendiste en esta sección:** - Los controladores organizan la lógica en acciones públicas - render muestra una vista; redirect_to envía una redirección - ERB mezcla HTML con Ruby usando <%= %> y <% %> - Los layouts definen el esqueleto común de la aplicación - Los partials reutilizan fragmentos de interfaz - Strong Parameters y CSRF protegen las peticiones
