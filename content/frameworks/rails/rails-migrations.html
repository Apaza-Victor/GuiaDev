6.1 Qué son las migraciones

Definición

Las migraciones son archivos Ruby que describen cambios en el esquema de la base de datos de forma versionada y reproducible. Permiten crear, modificar o eliminar tablas y columnas usando código en lugar de SQL manual.

Ventajas de usar migraciones

VentajaDescripción
VersionadoCada cambio queda registrado con fecha y orden
ReproducibleSe aplica el mismo esquema en cualquier entorno
ReversiblePermite deshacer cambios con rollback
IndependenciaFunciona con SQLite, PostgreSQL, MySQL, etc.
ColaborativoTodo el equipo aplica los mismos cambios

Estructura de una migración

# db/migrate/20260101120000_create_productos.rb
class CreateProductos < ActiveRecord::Migration[7.0]
  def change
    create_table :productos do |t|
      t.string :nombre
      t.decimal :precio

      t.timestamps
    end
  end
end

6.2 Generar migraciones

Generador de migraciones

Rails ofrece un generador que crea archivos de migración siguiendo convenciones de nombres:

# Generar una tabla
rails generate migration CreateProductos nombre:string precio:decimal

# Añadir una columna
rails generate migration AddStockToProductos stock:integer

# Eliminar una columna
rails generate migration RemoveStockFromProductos stock:integer

# Crear una tabla vacía con solo timestamps
rails generate migration CreateCategorias

Convenciones de nombres

NombreQué genera
CreateXXXCrea una tabla
AddCampoToTablaAñade una columna
RemoveCampoFromTablaElimina una columna
ChangeCampoInTablaModifica una columna

La migración de un modelo con generate model

# rails generate model Producto nombre:string
# db/migrate/xxxx_create_productos.rb
class CreateProductos < ActiveRecord::Migration[7.0]
  def change
    create_table :productos do |t|
      t.string :nombre

      t.timestamps
    end
  end
end

Opciones de columnas

create_table :productos do |t|
  t.string :nombre, null: false
  t.string :sku, null: false, default: "SIN-SKU", limit: 50
  t.decimal :precio, precision: 10, scale: 2
  t.boolean :publicado, default: false

end

add_index :productos, :sku, unique: true

6.4 Modificar el esquema

Métodos principales de cambio

class ModifyProductos < ActiveRecord::Migration[7.0]
  def change
    # Añadir columna
    add_column :productos, :marca, :string

    # Eliminar columna
    remove_column :productos, :obsoleto

    # Cambiar tipo
    change_column :productos, :descripcion, :text

    # Cambiar el nombre
    rename_column :productos, :nombre, :titulo

    # Añadir una tabla
    create_table :categorias do |t|
      t.string :nombre
      t.timestamps
    end

    # Reasignar la asociación
    add_reference :productos, :categoria, foreign_key: true
  end
end

Cambios no reversibles

Algunas operaciones como remove_column o change_column no se pueden revertir automáticamente. Para ello usa up y down:

class RemoveStockFromProductos < ActiveRecord::Migration[7.0]
  def up
    remove_column :productos, :stock
  end

  def down
    add_column :productos, :stock, :integer
  end
end
Si el cambio no es reversible, define los métodos up y down manualmente. Rails lanzará un error si intentas revertir una migración irreversible.

6.5 Comandos de migración

Comandos principales

ComandoDescripción
rails db:migrateAplica las migraciones pendientes
rails db:rollbackDeshace la última migración
rails db:migrate:statusMuestra el estado de cada migración
rails db:migrate:redoRollback y migrate de nuevo
rails db:schema:loadCarga el esquema desde schema.rb

Ver el estado de las migraciones

rails db:migrate:status

# Salida orientativa:
#   up    20260101120000  Create productos
#   up    20260102090000  Add stock to productos
#   down  20260103080000  Create categorias

Esquema de la base de datos

Tras migrar, Rails mantiene el esquema actualizado en db/schema.rb. Este archivo refleja el estado real de la base de datos y es la fuente para db:schema:load:

# db/schema.rb
create_table "productos", force: :cascade do |t|
  t.string "nombre"
  t.decimal "precio"
  t.datetime "created_at", null: false
  t.datetime "updated_at", null: false
end

6.6 Seeds y configuración

Archivo seeds

El archivo db/seeds.rb crea datos iniciales de la base de datos. Se ejecuta con rails db:seed:

# db/seeds.rb
categoria = Categoria.create!(nombre: "Electrónica")
categoria2 = Categoria.create!(nombre: "Ropa")

Producto.create!(nombre: "Laptop", precio: 999.99, categoria: categoria)
Producto.create!(nombre: "Mouse", precio: 29.99, categoria: categoria)
Producto.create!(nombre: "Camiseta", precio: 19.99, categoria: categoria2)

Ejecutar los seeds

rails db:seed
# Resetear la base de datos (drop + create + migrate + seed)
rails db:reset

Configuración de la base de datos

# config/database.yml
default: &default
  adapter: sqlite3
  pool: <%= ENV.fetch("RAILS_MAX_THREADS") { 5 } %>
  timeout: 5000

development:
  <<: *default
  database: db/development.sqlite3

test:
  <<: *default
  database: db/test.sqlite3
Usa rails db:seed para cargar datos iniciales y rails db:reset para reconstruir la base de datos completa. Nunca pongas datos sensibles en los seeds.

---

Resumen

**Lo que aprendiste en esta sección:** - Las migraciones versionan los cambios del esquema de forma reproducible - El generador crea migraciones con convenciones de nombres claras - Rails soporta tipos de datos como string, text, decimal y boolean - add_column, remove_column y change_column modifican el esquema - rails db:migrate, rollback y status gestionan las migraciones - db/seeds.rb carga datos iniciales y db/schema.rb refleja el esquema
