3.1 Arquitectura MVC

Qué es el patrón MVC

Rails implementa el patrón de diseño Modelo-Vista-Controlador, que separa la aplicación en tres capas con responsabilidades claras:

CapaResponsabilidadUbicación
ModeloDatos, validaciones y lógica de negocioapp/models
VistaPresentación y HTML de la interfazapp/views
ControladorRecibe peticiones, orquesta y respondeapp/controllers

Ciclo de una petición en Rails

1. El navegador envía GET /productos
2. Rails busca la ruta en config/routes.rb
3. El router envía la petición a ProductosController#index
4. El controlador consulta el modelo Producto
5. El controlador renderiza la vista index.html.erb
6. La vista genera HTML y se envía al navegador

Ejemplo: Flujo completo

# config/routes.rb
Rails.application.routes.draw do
  resources :productos
end

# app/controllers/productos_controller.rb
class ProductosController < ApplicationController
  def index
    @productos = Producto.all
  end
end

# app/views/productos/index.html.erb
<ul>
  <% @productos.each do |producto| %>
    <li><%= producto.nombre %></li>
  <% end %>
</ul>

3.2 Configuración de rutas (config/routes.rb)

El archivo de rutas

El archivo config/routes.rb es el mapa de la aplicación. Define qué controlador y acción responde a cada URL:

# config/routes.rb
Rails.application.routes.draw do
  # Ruta raíz
  root "bienvenidos#index"

  # Ruta simple: GET /acerca
  get "acerca", to: "paginas#acerca"

  # Ruta con parámetro
  get "productos/:id", to: "productos#show"

  # Ruta que envía a otra URL
  get "inicio", to: redirect("/")
end

Formato de una ruta

Cada ruta asocia una URL con un controlador#acción:

URLControlador#AcciónResultado
/bienvenidos#indexMuestra la página principal
/blogarticulos#indexLista los artículos
/blog/5articulos#showMuestra el artículo 5
Puedes ver todas las rutas de tu aplicación ejecutando rails routes en la terminal.

3.3 Routing RESTful

Recursos y las 7 acciones REST

Rails combina verbos HTTP y URLs para definir las operaciones CRUD de forma RESTful:

resources :articulos
VerboRutaAcciónDescripción
GET/articulosindexListar todos
GET/articulos/newnewFormulario de nuevo
POST/articuloscreateCrear artículo
GET/articulos/:idshowVer un artículo
GET/articulos/:id/editeditFormulario de edición
PATCH/articulos/:idupdateActualizar artículo
DELETE/articulos/:iddestroyEliminar artículo

Rutas anidadas

Rails.application.routes.draw do
  resources :articulos do
    resources :comentarios
  end
end
# Genera rutas como /articulos/1/comentarios

3.4 Recursos y rutas personalizadas

Modificar los recursos por defecto

Puedes limitar o ampliar las rutas de un recurso según tus necesidades:

Rails.application.routes.draw do
  # Solo algunas acciones
  resources :articulos, only: [:index, :show]

  # Todas excepto destroy
  resources :usuarios, except: [:destroy]

  # Cambiar la ruta de la URL
  resources :articulos, path: "publicaciones"
end

Rutas de colección y de miembro

resources :articulos do
  # Ruta de colección: actúa sobre todos
  collection do
    get :recientes
  end

  # Ruta de miembro: actúa sobre un elemento
  member do
    patch :publicar
    get :estadisticas
  end
end

# Genera:
#   GET    /articulos/recientes
#   PATCH  /articulos/:id/publicar
#   GET    /articulos/:id/estadisticas

Otras formas de rutas

get "dashboard", to: "usuarios#dashboard"
post "login", to: "sesiones#create"
match "buscar", to: "busquedas#index", via: [:get, :post]

3.5 Rutas con parámetros

Parámetros en la URL

Puedes definir segmentos dinámicos en las rutas precedidos por dos puntos:

Rails.application.routes.draw do
  get "categoria/:categoria/:id", to: "productos#show"
end
# app/controllers/productos_controller.rb
class ProductosController < ApplicationController
  def show
    @producto = Producto.where(categoria: params[:categoria])
                        .find(params[:id])
  end
end

Parámetros de query string

/productos?categoria=electronica&orden=precio
# Se acceden con params
params[:categoria]   # "electronica"
params[:orden]       # "precio"

Restricciones de formato

# Limitar el formato de los parámetros con constraints
get "productos/:id", to: "productos#show",
                     constraints: { id: /\d+/ }

# Con formato activo/default
get "articulos/:id(.:formato)", to: "articulos#show"
Rails siempre entrega params como strings. Convierte los valores numéricos usando to_i o las constraints de tipo.

3.6 Helpers de rutas y URLs

Generar URLs sin escribirlas a mano

Rails genera helpers de rutas basados en los nombres del recurso:

resources :articulos
HelperURL generada
articulos_path/articulos
nuevo_articulo_path/articulos/new
articulo_path(3)/articulos/3
editar_articulo_path(3)/articulos/3/edit
articulos_urlhttp://localhost:3000/articulos

Uso en vistas

<%= link_to "Todos los artículos", articulos_path %>
<%= link_to "Leer", articulo_path(@articulo) %>
<%= link_to "Editar", edit_articulo_path(@articulo) %>

Redirecciones en el controlador

class ArticulosController < ApplicationController
  def create
    @articulo = Articulo.new(articulo_params)
    if @articulo.save
      redirect_to @articulo, notice: "Artículo creado"
    else
      render :new
    end
  end
end

Resumen

**Lo que aprendiste en esta sección:** - MVC separa la app en Modelo, Vista y Controlador - config/routes.rb mapea URLs a controlador#acción - resources genera las 7 acciones RESTful automáticamente - Las rutas anidadas y personalizadas organizan recursos relacionados - Los parámetros de ruta se acceden mediante params - Los helpers path generan URLs dinámicamente en vistas y controladores
