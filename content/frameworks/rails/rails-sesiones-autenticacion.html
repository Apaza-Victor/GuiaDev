7.1 Cookies y sesiones

Qué es una cookie

Una cookie es un pequeño dato que el servidor envía al navegador y que se almacena en el cliente. Rails las usa internamente para guardar el identificador de sesión y otros datos.

Sesión en Rails

La sesión es un hash de Ruby disponible en el controlador mediante session. Permite conservar datos entre peticiones del mismo usuario:

class CarritoController < ApplicationController
  def añadir
    # Guardar un valor en la sesión
    session[:carrito] ||= []
    session[:carrito] << params[:producto_id]

    # Leer un valor de la sesión
    carrito = session[:carrito]

    # Eliminar un valor
    session.delete(:descuento)

    # Limpiar toda la sesión
    reset_session
  end
end

Dónde se guardan las sesiones

BackendDescripción
CookieStore(Por defecto) Se guarda en la cookie cifrada del navegador
CacheSe guarda en la caché del servidor (memcached, Redis)
Base de datosSe guarda en una tabla de la base de datos
Las sesiones no deben usarse para datos grandes o sensibles. Guarda solo identificadores o datos pequeños; la información completa ve a la base de datos.

7.2 Autenticación manual

Modelo de usuario

Para autenticar necesitas un modelo Usuario. La contraseña debe guardarse cifrada con un hash, no en texto plano:

rails generate model Usuario email:string password_digest:string
rails db:migrate
# app/models/usuario.rb
class Usuario < ApplicationRecord
  has_secure_password
  validates :email, presence: true, uniqueness: true
end
# Gemfile (añade la gema bcrypt y ejecuta bundle install)
gem "bcrypt", "~> 3.1"

Registro e inicio de sesión

# app/controllers/sesiones_controller.rb
class SesionesController < ApplicationController
  def create
    usuario = Usuario.find_by(email: params[:email])

    if usuario && usuario.authenticate(params[:password])
      session[:usuario_id] = usuario.id
      redirect_to root_path, notice: "Sesión iniciada"
    else
      flash.now[:alert] = "Credenciales incorrectas"
      render :new, status: :unprocessable_entity
    end
  end

  def destroy
    session.delete(:usuario_id)
    redirect_to root_path, notice: "Sesión cerrada"
  end
end

Registro de un usuario

usuario = Usuario.new(email: "ana@correo.com",
                      password: "secreto123",
                      password_confirmation: "secreto123")
if usuario.save
  session[:usuario_id] = usuario.id
else
  # El error de validación aparece en usuario.errors
end

7.4 Autorización

Autenticación vs autorización

La autenticación verifica quién eres. La autorización determina qué puedes hacer. Ambas son necesarias en aplicaciones con roles o permisos.

Roles de usuario

# Añadir una columna rol al modelo
rails generate migration AddRolToUsuarios rol:integer
rails db:migrate
# app/models/usuario.rb
class Usuario < ApplicationRecord
  has_secure_password

  enum rol: { usuario: 0, admin: 1 }
end

# Uso
admin = Usuario.find_by(email: "admin@correo.com")
admin.admin?   # true
admin.usuario? # false

Comprobar el rol en el controlador

# app/controllers/admin/base_controller.rb
class Admin::BaseController < ApplicationController
  before_action :requiere_admin

  private

  def requiere_admin
    unless current_usuario.admin?
      redirect_to root_path, alert: "No tienes permisos"
    end
  end
end

Gemas de autorización

GemaEnfoque
PunditClases de políticas por recurso
CanCanCanHabilidades declarativas de forma centralizada
# Ejemplo con Pundit
class ProductoPolicy
  attr_reader :usuario, :producto

  def initialize(usuario, producto)
    @usuario = usuario
    @producto = producto
  end

  def update?
    usuario.admin? || producto.usuario == usuario
  end
end

7.5 Remember me y tokens

Recordar la sesión

Para mantener la sesión del usuario después de cerrar el navegador, se guarda un token en una cookie persistente:

# app/models/usuario.rb
class Usuario < ApplicationRecord
  has_secure_password

  before_create :generar_token

  private

  def generar_token
    self.remember_token = SecureRandom.urlsafe_base64
  end
end

Guardar la cookie persistente

# En el inicio de sesión
def recordar(usuario)
  token = usuario.remember_token
  cookies.permanent.signed[:usuario_id] = usuario.id
  cookies.permanent.signed[:remember_token] = token
end

Autenticación con tokens de API

En APIs, el cliente envía un token en cada petición mediante la cabecera Authorization:

class Api::V1::BaseController < ApplicationController
  before_action :autenticar_con_token

  private

  def autenticar_con_token
    token = request.headers["Authorization"]&.split(" ")&.last
    @usuario = Usuario.find_by(api_token: token)
    head :unauthorized unless @usuario
  end
end

Ejemplo de respuesta no autorizada

head :unauthorized
# HTTP/1.1 401 Unauthorized
Nunca guardes contraseñas ni tokens en texto plano. Usa has_secure_password (bcrypt) para contraseñas y tokens firmados para los "remember me".

7.6 Flash y seguridad

Mensajes flash

Flash son mensajes temporales que se muestran una sola vez tras una redirección. Se definen en el controlador y se leen en la vista:

# En el controlador
redirect_to root_path, notice: "Bienvenido de nuevo"
redirect_to root_path, alert: "Acción no permitida"

# Con flash directo
flash[:success] = "Datos guardados correctamente"
flash.now[:error] = "Revisa los campos del formulario"
<!-- En el layout -->
<% flash.each do |tipo, mensaje| %>
  <div class="<%= "alert alert-#{tipo}" %>">
    <%= mensaje %>
  </div>
<% end %>

Buenas prácticas de seguridad

MedidaDescripción
Contraseñas cifradasSiempre con bcrypt, nunca en texto plano
Protección CSRFMantener protect_from_forgery activo
Escape de salidaUsar <%= %> para escapar HTML automáticamente
Rutas protegidasUsar before_action para restringir acceso
Tokens segurosGenerar con SecureRandom y expirarlos

Ejemplo de cierre de sesión seguro

def destroy
  # Invalidar la sesión y la cookie
  reset_session
  cookies.delete(:usuario_id)
  cookies.delete(:remember_token)

  redirect_to root_path, notice: "Sesión cerrada correctamente"
end

Resumen

**Lo que aprendiste en esta sección:** - Las cookies y sesiones permiten conservar datos entre peticiones - has_secure_password cifra las contraseñas con bcrypt - Devise ofrece autenticación completa lista para usar - La autorización controla qué puede hacer cada usuario según sus roles - Los tokens y cookies persistentes implementan el "remember me" - El flash muestra mensajes temporales y la seguridad es una prioridad
