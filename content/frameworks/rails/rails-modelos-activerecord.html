5.1 Modelos y Active Record

Qué es Active Record

Active Record es el ORM (Object Relational Mapping) de Rails. Convierte tablas de una base de datos en clases de Ruby y filas en objetos, siguiendo el patrón Active Record.

Convenciones de mapeo

Base de datosRubyEjemplo
TablaClaseproductos → Producto
ColumnaAtributoprecio → producto.precio
FilaObjetoUna fila → una instancia
Llave primariaidColumna id automática
Llaves foráneasmodelo_idcategoria_id

Definir un modelo

# app/models/producto.rb
class Producto < ApplicationRecord
  belongs_to :categoria
end

# Herencia de una clase base que ya trae Active Record configurado
Los nombres de modelos se singularizan en Ruby, mientras que las tablas se pluralizan: Producto ←→ tabla productos.

5.2 Validaciones

Para qué sirven las validaciones

Las validaciones aseguran que solo se guarden datos correctos. Se ejecutan antes de guardar y evitan que lleguen datos inválidos a la base de datos.

Validaciones más comunes

class Producto < ApplicationRecord
  validates :nombre, presence: true
  validates :precio, numericality: { greater_than_or_equal_to: 0 }
  validates :sku, uniqueness: true
  validates :descripcion, length: { maximum: 500 }
  validates :email, format: { with: URI::MailTo::EMAIL_REGEXP }
  validates :cantidad, numericality: { only_integer: true }
end
ValidaciónQué comprueba
presenceEl atributo no está vacío
uniquenessEl valor no se repite
numericalityEs un número y cumple la condición
lengthCumple el rango de longitud
formatCoincide con una expresión regular
inclusionEstá dentro de una lista de valores

Comprobar errores

producto = Producto.new(nombre: "", precio: -5)

producto.valid?                     # false
producto.errors.full_messages
# => ["Nombre no puede estar vacío", "Precio debe ser mayor o igual a 0"]

5.3 Consultas con Active Record

Métodos de búsqueda comunes

# Todos los registros
Producto.all

# Primero y último
Producto.first
Producto.last

# Por llave primaria
Producto.find(3)

# Por atributos
Producto.find_by(nombre: "Laptop")
Producto.find_by!(nombre: "Laptop")  # lanza excepción si no existe

# With chain de condiciones
Producto.where(precio: 100..500)
Producto.where("precio > ?", 100)
Producto.order(:nombre)
Producto.order(precio: :desc)

# Limitar resultados
Producto.limit(10).offset(20)

# Contar
Producto.count

Consultas encadenadas (lazy)

articulos = Articulo.where(publicado: true)
                    .order(:fecha)
                    .limit(5)

# La consulta SQL se ejecuta al usar la relación
articulos.each { |a| puts a.titulo }
# SELECT articulos.* FROM articulos
# WHERE publicado = 1 ORDER BY fecha LIMIT 5

Agregaciones

Producto.sum(:precio)
Producto.average(:precio)
Producto.maximum(:precio)
Producto.minimum(:precio)
Producto.group(:categoria_id).count

5.4 Asociaciones

Tipos de asociaciones

Las asociaciones definen las relaciones entre modelos y generan métodos para acceder a datos relacionados:

TipoRelaciónEjemplo
belongs_to1 → 1 (hijo)Producto pertenece a Categoría
has_many1 → muchosCategoría tiene muchos Productos
has_one1 → 1 (padre)Perfil tiene un Avatar
has_and_belongs_to_manymuchos → muchosEstudiante tiene muchos Cursos

Ejemplo de asociaciones

class Categoria < ApplicationRecord
  has_many :productos, dependent: :destroy
end

class Producto < ApplicationRecord
  belongs_to :categoria
  has_many :imagenes
  has_one :ficha_tecnica
end

class Estudiante < ApplicationRecord
  has_and_belongs_to_many :cursos
end

Métodos generados por has_many

categoria = Categoria.find(1)

categoria.productos            # Colección de productos
categoria.productos.create(...) # Crea un producto asociado
categoria.productos.build(...)  # Construye sin guardar
categoria.productos.empty?     # true/false
categoria.productos.size       # Cantidad
Usa dependent: :destroy (o :nullify) para definir qué pasa con los registros relacionados cuando se elimina el padre.

5.5 CRUD con Active Record

Crear (Create)

# Con new y save
producto = Producto.new(nombre: "Laptop", precio: 999.99)
producto.save

# Con create (new + save en un solo paso)
Producto.create(nombre: "Mouse", precio: 29.99)

# Con create! lanza excepción si falla la validación
Producto.create!(nombre: "", precio: 10)

# Build de una asociación
categoria.productos.create(nombre: "Teclado", precio: 49.99)

Leer (Read)

Producto.all                      # Todos
Producto.find(1)                  # Por id
Producto.find_by(nombre: "Laptop")
Producto.where(precio: 0..50).order(:nombre)

Actualizar (Update)

producto = Producto.find(1)

producto.precio = 899.99
producto.save

# O directamente
producto.update(precio: 849.99)

# Actualizar varios a la vez
Producto.update_all("precio = precio * 0.9")

Eliminar (Delete)

# destroy ejecuta callbacks y dependencias
producto.destroy

# delete omite callbacks y validaciones
producto.delete

# Eliminar varios
Producto.where(precio: 0).destroy_all

5.6 Callbacks y scopes

Callbacks

Los callbacks ejecutan código en momentos clave del ciclo de vida de un registro:

class Pedido < ApplicationRecord
  before_validation :asignar_referencia
  before_save :calcular_total
  after_create :enviar_confirmacion

  private

  def asignar_referencia
    self.referencia = "PED-" + SecureRandom.hex(4).upcase
  end

  def calcular_total
    self.total = items.sum(&:subtotal)
  end

  def enviar_confirmacion
    PedidoMailer.confirmacion(self).deliver_later
  end
end

Scopes

Los scopes son consultas reutilizables definidas en el modelo:

class Producto < ApplicationRecord
  scope :economicos, -> { where("precio < 50") }
  scope :en_stock, -> { where("stock > 0") }
  scope :recientes, -> { order(created_at: :desc) }
  scope :de_categoria, ->(categoria) { where(categoria: categoria) }
end

# Uso
Producto.economicos.en_stock
Producto.recientes.de_categoria(2)
CallbackMomento
before_saveAntes de guardar
after_createDespués de crear
before_destroyAntes de eliminar
after_updateDespués de actualizar

Resumen

**Lo que aprendiste en esta sección:** - Active Record mapea tablas a clases y filas a objetos - Las validaciones aseguran que solo se guarden datos correctos - where, find, find_by y order permiten consultar la base de datos - Las asociaciones relacionan modelos y generan métodos útiles - Active Record implementa CRUD completo con create, update, destroy - Los callbacks y scopes encapsulan lógica reutilizable del modelo
