9.1 Modo API de Rails

Qué es el modo API

Rails puede funcionar solo como API, sirviendo JSON o XML en lugar de vistas HTML. Se genera con la bandera --api y omite las capas relacionadas con la presentación en el navegador.

# Crear un proyecto en modo API
rails new mi_api --api

# O crearlo normal y comentar los módulos de middleware de vista

Diferencias frente a una app normal

CaracterísticaApp normalModo API
VistasERB y layoutsNo genera vistas
CSRFActivo por defectoDesactivado
Cookies/sesiónDispuestasSolo de forma opcional
RespuestasHTMLJSON

Controlador base API

# app/controllers/application_controller.rb
class ApplicationController < ActionController::API
  # Hereda de ActionController::API, no de Base
end

9.2 Rutas de API versionada

Namespacing de la API

Es una buena práctica versionar la API para no romper a los clientes existentes cuando cambias el contrato:

# config/routes.rb
Rails.application.routes.draw do
  namespace :api do
    namespace :v1 do
      resources :productos, only: [:index, :show, :create, :update, :destroy]
      resources :categorias, only: [:index, :show]
    end
  end
end

Esto genera rutas como /api/v1/productos y /api/v1/productos/1.

Ver las rutas generadas

rails routes | grep api

Definir el controlador versionado

# app/controllers/api/v1/productos_controller.rb
module Api
  module V1
    class ProductosController < ApplicationController
      def index
        @productos = Producto.all
        render json: @productos
      end

      def show
        @producto = Producto.find(params[:id])
        render json: @producto
      end

      def create
        @producto = Producto.new(producto_params)
        if @producto.save
          render json: @producto, status: :created
        else
          render json: @producto.errors, status: :unprocessable_entity
        end
      end

      private

      def producto_params
        params.require(:producto).permit(:nombre, :precio)
      end
    end
  end
end

9.3 Respuesta JSON

Usar render json

El método render json: serializa un objeto Ruby a JSON y lo envía en la respuesta:

# Objeto simple
render json: { mensaje: "Hola", ok: true }

# Un registro con todas sus columnas
render json: @producto

# Una colección
render json: Producto.all

# Con estados HTTP
render json: @producto, status: :ok
render json: @producto, status: :created
render json: { error: "No encontrado" }, status: :not_found

Estados HTTP más usados en APIs

CódigoSímboloCuándo usarlo
200:okRespuesta correcta (leer)
201:createdRecurso creado correctamente
204:no_contentEliminación exitosa
400:bad_requestPetición malformada
401:unauthorizedSin autenticación
403:forbiddenSin permisos
404:not_foundRecurso no existe
422:unprocessable_entityErrores de validación
# Respuesta sin cuerpo
head :no_content

9.4 Serialización con serializers

Por qué usar serializers

Por defecto, render json: @producto expone todas las columnas del modelo. Con serializers controlas exactamente qué se devuelve, evitas exponer datos sensibles y das formato a la salida.

Gemas populares

GemaEnfoque
ActiveModel::SerializersClases que definen atributos y asociaciones
jsonapi-serializerImplementa el estándar JSON:API
jbuilderVistas basadas en archivos .jbuilder (incluido en Rails)

Ejemplo con jbuilder

# app/views/api/v1/productos/show.json.jbuilder
json.id @producto.id
json.nombre @producto.nombre
json.precio @producto.precio
json.categoria do
  json.nombre @producto.categoria.nombre
end

Ejemplo con ActiveModel::Serializers

# app/serializers/producto_serializer.rb
class ProductoSerializer < ActiveModel::Serializer
  attributes :id, :nombre, :precio
  belongs_to :categoria
end

# En el controlador
render json: @producto
Nunca serialices el modelo completo si contiene campos sensibles como password_digest o api_token. Define siempre una serialización explícita.

9.5 Autenticación de API

Métodos comunes

MétodoDescripción
API key simpleClave estática en cabecera o query
Token de accesoToken generado al iniciar sesión
JWTToken firmado sin estado en el servidor
OAuth2Delegado a terceros (Google, GitHub)

Token de acceso simple

rails generate migration AddApiTokenToUsuarios api_token:string
rails db:migrate
# app/models/usuario.rb
class Usuario < ApplicationRecord
  has_secure_password
  before_create :generar_api_token

  private

  def generar_api_token
    self.api_token = SecureRandom.hex(20)
  end
end

Controlador base autenticado

# app/controllers/api/v1/base_controller.rb
module Api
  module V1
    class BaseController < ApplicationController
      before_action :autenticar

      private

      def autenticar
        token = request.headers["Authorization"]&.split(" ")&.last
        @usuario = Usuario.find_by(api_token: token)
        render json: { error: "No autorizado" }, status: :unauthorized unless @usuario
      end
    end
  end
end
# Heredar de BaseController en los controladores protegidos
module Api
  module V1
    class ProductosController < BaseController
      def index
        render json: @usuario.productos
      end
    end
  end
end

9.6 Pruebas y documentación de API

Probar la API con curl

# Listar productos
curl http://localhost:3000/api/v1/productos

# Crear un producto
curl -X POST http://localhost:3000/api/v1/productos \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer TU_TOKEN" \
  -d '{"producto":{"nombre":"Laptop","precio":999.99}}'

# Eliminar un producto
curl -X DELETE http://localhost:3000/api/v1/productos/3 \
  -H "Authorization: Bearer TU_TOKEN"

Pruebas de integración en Rails

# test/controllers/api/v1/productos_controller_test.rb
require "test_helper"

module Api
  module V1
    class ProductosControllerTest < ActionDispatch::IntegrationTest
      test "lista productos" do
        get "/api/v1/productos"
        assert_response :success
        cuerpo = JSON.parse(response.body)
        assert_kind_of Array, cuerpo
      end

      test "crea un producto con token" do
        post "/api/v1/productos",
             params: { producto: { nombre: "Mouse", precio: 29.99 } },
             headers: { "Authorization" => "Bearer #{api_token}" }
        assert_response :created
      end

      test "rechaza sin token" do
        get "/api/v1/productos"
        assert_response :unauthorized
      end
    end
  end
end

Herramientas de pruebas y documentación

HerramientaFunción
Postman / InsomniaCliente gráfico para probar APIs
Swagger/OpenAPIDocumentación interactiva y generación de clientes
RswagGenera documentación Swagger desde los tests
rspec-rails + FactoryBotTests robustos con datos de fábrica
Documentar la API con OpenAPI/Swagger facilita que otros equipos la consuman y permite autogenerar clientes en distintos lenguajes.

Resumen

**Lo que aprendiste en esta sección:** - El modo API (--api) sirve JSON en lugar de vistas HTML - Namespace :api :v1 permite versionar la API - render json: serializa objetos y define estados HTTP - Los serializers controlan exactamente qué se expone - La autenticación se hace con tokens o JWT en la cabecera Authorization - Las pruebas de integración y OpenAPI documentan y validan la API
