1.1 Qué es NestJS

Definición

NestJS (Nest) es un framework progresivo para Node.js creado para construir aplicaciones de servidor eficientes, escalables y confiables. Está construido con TypeScript por defecto y combina elementos de la programación orientada a objetos, la programación funcional y la programación reactiva.

Internamente, NestJS usa por defecto a Express como motor HTTP, aunque también permite usar Fastify para obtener un rendimiento aún mayor.

Características del framework

CaracterísticaDescripción
TypeScriptEscrito y pensado para TypeScript, con soporte de JavaScript
Arquitectura modularDivide la aplicación en módulos reutilizables y organizados
Inyección de dependenciasSistema de contenedor de dependencias integrado
DecoradoresMeta-programación declarativa con decoradores de TypeScript
Motor HTTP intercambiableExpress por defecto y Fastify como alternativa
Ecosistema amplioMódulos oficiales: autenticación, bases de datos, websockets, etc.

Ejemplo: primera aplicación NestJS

// app.module.ts
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
  imports: [],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}

1.2 Por qué elegir NestJS

Ventajas principales

VentajaDescripción
Estructura claraPatrón de diseño definido que ordena el proyecto desde el inicio
EscalabilidadArquitectura modular que crece junto con la aplicación
TypeScriptTipado estático que reduce errores y mejora el autocompletado
Documentación y comunidadDocumentación oficial excelente y comunidad activa
Soporte empresarialUsado por grandes empresas y con licencia MIT
Curva de aprendizajeModerada: conocer Angular o Spring facilita la adaptación

Cómo se compara aspirar a algo con estructura

Una de las mayores ventajas de NestJS es que impone una estructura clara. Mientras que con Express cada desarrollador organiza los archivos como quiere, NestJS define dónde van controladores, servicios y módulos, lo que facilita el trabajo en equipo.

Cuándo elegir NestJS

  • APIs corporativas: proyectos medianos y grandes que requieren mantenimiento
  • Microservicios: soporte nativo para transporte de eventos
  • Equipos que ya usan TypeScript: consistencia en el front y el back
  • Proyectos a largo plazo: la arquitectura facilita agregar características

1.3 NestJS vs Express

Comparativa de frameworks

AspectoNestJSExpress
TipoFramework estructuradoMicroframework
LenguajeTypeScript por defectoJavaScript
ArquitecturaModular con capasLibre, sin estructura definida
Inyección de dependencias Integrada No
RendimientoAlto (usa Express o Fastify)Alto
Curva de aprendizajeModeradaBaja
Organización del proyectoBuenas prácticas integradasDepende del desarrollador

Cuándo usar cada uno

  • Express: prototipos rápidos, APIs simples y pequeños proyectos
  • NestJS: aplicaciones de producción, proyectos medianos y grandes, microservicios

Ejemplo: mismo endpoint en ambos

// Express
import express from 'express';
const app = express();

app.get('/usuarios', (req, res) => {
  res.json([{ id: 1, nombre: 'Ana' }]);
});
// NestJS
import { Controller, Get } from '@nestjs/common';

@Controller('usuarios')
export class UsuariosController {
  @Get()
  listar() {
    return [{ id: 1, nombre: 'Ana' }];
  }
}

1.4 Arquitectura de NestJS

Piezas fundamentales

NestJS organiza la aplicación en torno a cuatro piezas principales que trabajan juntas:

PiezaResponsabilidadDecorador
MóduloAgrupa características relacionadas@Module
ControladorRecibe peticiones HTTP y define rutas@Controller
ServicioContiene la lógica de negocio@Injectable
ProviderCualquier clase inyectable (servicios, repositorios, etc.)@Injectable

Cómo fluye una petición

Petición HTTP -> Guard -> Pipe -> Controlador -> Servicio -> Base de datos
                  <------------------------ Respuesta -----------------------

Ejemplo: módulo raíz de la aplicación

import { Module } from '@nestjs/common';
import { UsuariosModule } from './usuarios/usuarios.module';

@Module({
  imports: [UsuariosModule],
})
export class AppModule {}

1.5 Características principales

Características destacadas

  • Decoradores: metadatos declarativos para definir rutas, controladores, inyección, etc.
  • Inyección de dependencias: contenedor IoC integrado para desacoplar componentes
  • Módulos: encapsulación de funcionalidades en bloques reutilizables
  • Pipes: transformación y validación de datos de entrada
  • Guards: autorización y protección de rutas
  • Interceptores: lógica transversal (logging, transformación de respuestas)
  • Middleware: funciones que se ejecutan antes de los controladores
  • Soporte de bases de datos: TypeORM, Prisma, Mongoose, Sequelize y más

1.6 Empresas que usan NestJS

Adopción en el mundo real

  • Adidas: plataformas de comercio electrónico
  • Autodesk: servicios internos de sus aplicaciones
  • Uber: herramientas y servicios de backend
  • Microsoft: algunos servicios de Azure
  • Miro: APIs de su plataforma de colaboración

Por qué las empresas lo eligen

La adopción empresarial se explica por la estructura predecible, el soporte de TypeScript y la escalabilidad. Estos factores reducen el costo de mantener el código y facilitan la incorporación de nuevos desarrolladores al equipo.

Ejemplo: API de una empresa con NestJS

// pedidos.controller.ts
import { Controller, Get, Post, Body } from '@nestjs/common';

interface Pedido {
  id: number;
  total: number;
}

@Controller('pedidos')
export class PedidosController {
  private pedidos: Pedido[] = [];
  private siguienteId = 1;

  @Get()
  todos(): Pedido[] {
    return this.pedidos;
  }

  @Post()
  crear(@Body() pedido: Pedido): Pedido {
    pedido.id = this.siguienteId++;
    this.pedidos.push(pedido);
    return pedido;
  }
}

Resumen

**Lo que aprendiste en esta sección:** - NestJS es un framework progresivo de Node.js construido con TypeScript - Usa Express o Fastify como motor HTTP interno - Organiza el código en módulos, controladores, servicios y providers - Ofrece inyección de dependencias, pipes, guards e interceptores - A diferencia de Express, impone una estructura clara y escalable - Es utilizado por empresas grandes gracias a su arquitectura robusta
