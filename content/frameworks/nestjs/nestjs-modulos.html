3.1 Qué es un módulo

Definición

Un módulo en NestJS es una clase anotada con el decorador @Module que agrupa una funcionalidad relacionada de la aplicación. Es la unidad fundamental de organización y encapsulación en NestJS.

Cada aplicación tiene al menos un módulo: el módulo raíz (AppModule). A medida que la aplicación crece, se crean módulos para cada funcionalidad: usuarios, pedidos, productos, etc.

Beneficios de la modularidad

BeneficioDescripción
OrganizaciónCada funcionalidad vive en su propia carpeta
ReutilizaciónUn módulo se importa en varios lugares
EncapsulaciónOculta los proveedores internos que no deben exponerse
EscalabilidadAgregar características no rompe el resto
PruebasFacilita probar cada módulo de forma aislada

Ejemplo: módulo raíz

import { Module } from '@nestjs/common';
import { UsuariosModule } from './usuarios/usuarios.module';

@Module({
  imports: [UsuariosModule],
})
export class AppModule {}

---

3.2 La estructura de @Module

Propiedades del decorador

El decorador @Module recibe un objeto con cuatro propiedades principales:

PropiedadFunción
importsLista de módulos que este módulo necesita importar
controllersInstancia los controladores definidos en este módulo
providersServicios y proveedores que Nest podrá inyectar
exportsSubconjunto de providers que otros módulos pueden usar

Ejemplo: módulo con todas las propiedades

import { Module } from '@nestjs/common';
import { UsuariosController } from './usuarios.controller';
import { UsuariosService } from './usuarios.service';
import { DatabaseModule } from '../database/database.module';

@Module({
  imports: [DatabaseModule],
  controllers: [UsuariosController],
  providers: [UsuariosService],
  exports: [UsuariosService],
})
export class UsuariosModule {}
Si un provider se exporta, otros módulos pueden inyectarlo. Si no se exporta, solo es visible dentro del propio módulo.

---

3.3 Módulos de características

Qué es un módulo de características

Un módulo de características organiza el código relacionado con una funcionalidad concreta: sus controladores, servicios, pipes, guards y submodulos. Es la forma recomendada de estructurar aplicaciones NestJS de cualquier tamaño.

Generar un módulo de características

# Generar el módulo con su carpeta
nest g mo usuarios

# Crear los archivos del módulo (se integran automáticamente)
nest g co usuarios
nest g s usuarios

Estructura resultante

src/usuarios/
├── usuarios.module.ts
├── usuarios.controller.ts
├── usuarios.service.ts
└── usuarios.service.spec.ts

Ejemplo: módulo de características

import { Module } from '@nestjs/common';
import { UsuariosController } from './usuarios.controller';
import { UsuariosService } from './usuarios.service';

@Module({
  controllers: [UsuariosController],
  providers: [UsuariosService],
})
export class UsuariosModule {}

---

3.4 Módulos compartidos

Qué es un módulo compartido

Un módulo compartido exporta sus providers para que otros módulos puedan usarlos. Es la forma de centralizar servicios comunes como el acceso a bases de datos, la configuración o servicios de terceros.

Mecanismo de exportación

Cuando un módulo A importa un módulo compartido B, los providers que B exporta quedan disponibles dentro de A para su inyección.

Ejemplo: módulo de base de datos compartido

// database.module.ts
import { Module } from '@nestjs/common';
import { DatabaseService } from './database.service';

@Module({
  providers: [DatabaseService],
  exports: [DatabaseService],
})
export class DatabaseModule {}
// usuarios.module.ts
import { Module } from '@nestjs/common';
import { DatabaseModule } from '../database/database.module';
import { UsuariosService } from './usuarios.service';

@Module({
  imports: [DatabaseModule],
  providers: [UsuariosService],
})
export class UsuariosModule {
  // Dentro de UsuariosService se puede inyectar DatabaseService
}

Ventajas

  • Reutilización: el servicio se define una sola vez
  • Consistencia: todos usan la misma instancia y configuración
  • Mantenimiento: los cambios se hacen en un solo lugar

3.5 Módulos globales y reexportación

Módulos globales con @Global

El decorador @Global hace que el módulo sea visible en toda la aplicación sin necesidad de importarlo en cada módulo. Es útil para servicios que se usan en casi todos los lugares, como configuración o logging.

import { Module, Global } from '@nestjs/common';
import { ConfiguracionService } from './configuracion.service';

@Global()
@Module({
  providers: [ConfiguracionService],
  exports: [ConfiguracionService],
})
export class ConfiguracionModule {}
// app.module.ts: solo se importa una vez
import { Module } from '@nestjs/common';
import { ConfiguracionModule } from './configuracion/configuracion.module';
import { UsuariosModule } from './usuarios/usuarios.module';

@Module({
  imports: [ConfiguracionModule, UsuariosModule],
})
export class AppModule {}
Un módulo marcado con `@Global` debe registrarse una sola vez, idealmente en el módulo raíz. Abusar de la globalidad dificulta entender las dependencias.

Reexportación de módulos

Un módulo puede reexportar los módulos que importa, propagando sus providers a otros módulos sin exponer internamente la importación completa.

import { Module } from '@nestjs/common';
import { DatabaseModule } from '../database/database.module';

@Module({
  imports: [DatabaseModule],
  exports: [DatabaseModule],
})
export class CoreModule {}

3.6 Ejemplo completo de módulos

Aplicación con varias características

Una aplicación de tienda con autenticación, productos y pedidos:

src/
├── main.ts
├── app.module.ts
├── auth/
│   ├── auth.module.ts
│   ├── auth.controller.ts
│   └── auth.service.ts
├── productos/
│   ├── productos.module.ts
│   ├── productos.controller.ts
│   └── productos.service.ts
└── pedidos/
    ├── pedidos.module.ts
    ├── pedidos.controller.ts
    └── pedidos.service.ts

Módulo raíz

import { Module } from '@nestjs/common';
import { AuthModule } from './auth/auth.module';
import { ProductosModule } from './productos/productos.module';
import { PedidosModule } from './pedidos/pedidos.module';

@Module({
  imports: [AuthModule, ProductosModule, PedidosModule],
})
export class AppModule {}

Pedidos necesita productos y usuarios

import { Module } from '@nestjs/common';
import { AuthModule } from '../auth/auth.module';
import { ProductosModule } from '../productos/productos.module';
import { PedidosController } from './pedidos.controller';
import { PedidosService } from './pedidos.service';

@Module({
  imports: [AuthModule, ProductosModule],
  controllers: [PedidosController],
  providers: [PedidosService],
  exports: [PedidosService],
})
export class PedidosModule {}
El CLI usa el comando `nest g mo` para generar cada módulo. Todos son independientes por defecto: controladores y servicios también deben generarse dentro de la misma carpeta.

---

Resumen

**Lo que aprendiste en esta sección:** - Un módulo es una clase anotada con `@Module` que agrupa funcionalidad - Las propiedades son `imports`, `controllers`, `providers` y `exports` - Los módulos de características organizan cada funcionalidad en una carpeta - Los módulos compartidos exportan providers reutilizables - `@Global` hace un módulo visible en toda la aplicación - La reexportación propaga providers entre módulos
