8.1 Qué es JWT y la autenticación

Qué es JWT

JWT (JSON Web Token) es un estándar abierto (RFC 7519) que define una forma compacta y segura de transmitir información entre partes como un objeto JSON. En el contexto de una API, se usa para verificar la identidad de un usuario y autorizar el acceso a recursos protegidos.

Estructura de un token JWT

Un token JWT se compone de tres partes separadas por puntos, cada una codificada en Base64Url:

ParteContenido
HeaderTipo de token y algoritmo de firma (p. ej. HS256)
PayloadClaims: datos del usuario, expiración, emisor, etc.
SignatureFirma generada con una clave secreta

Flujo de autenticación

Usuario -> POST /auth/login -> valida credenciales -> devuelve JWT
Cliente -> GET /protegido (Authorization: Bearer <JWT>) -> guard verifica -> responde

8.2 Instalación de paquetes y configuración

Dependencias necesarias

# Módulos oficiales de autenticación para NestJS
npm install @nestjs/jwt @nestjs/passport passport passport-jwt

# Biblioteca para encriptar contraseñas
npm install bcrypt

# Tipos para TypeScript (solo desarrollo)
npm install -D @types/passport-jwt @types/bcrypt

Configurar variables de entorno

# .env
JWT_SECRET=mi_clave_secreta_super_segura
JWT_EXPIRES_IN=1h

Módulo de autenticación

import { Module } from '@nestjs/common';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { AuthService } from './auth.service';
import { AuthController } from './auth.controller';

@Module({
  imports: [
    PassportModule,
    JwtModule.register({
      secret: process.env.JWT_SECRET,
      signOptions: { expiresIn: process.env.JWT_EXPIRES_IN },
    }),
  ],
  controllers: [AuthController],
  providers: [AuthService],
})
export class AuthModule {}
Nunca guardes la clave secreta del JWT en el código fuente. Usa siempre variables de entorno y mantén la clave fuera del repositorio.

8.3 Servicio de autenticación y bcrypt

Encriptar las contraseñas

Las contraseñas nunca deben almacenarse en texto plano. Se encriptan con bcrypt, que aplica un hash con sal automática y es resistente a ataques de fuerza bruta.

import { Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import * as bcrypt from 'bcrypt';
import { Usuario } from './usuario.entity';

@Injectable()
export class AuthService {
  constructor(
    @InjectRepository(Usuario)
    private readonly usuarios: Repository<Usuario>,
    private readonly jwtService: JwtService,
  ) {}

  async validarUsuario(email: string, password: string) {
    const usuario = await this.usuarios.findOne({ where: { email } });
    if (!usuario) {
      throw new UnauthorizedException('Credenciales inválidas');
    }
    const valida = await bcrypt.compare(password, usuario.password);
    if (!valida) {
      throw new UnauthorizedException('Credenciales inválidas');
    }
    return usuario;
  }

  async login(usuario: Usuario) {
    const payload = { sub: usuario.id, email: usuario.email, rol: usuario.rol };
    return { access_token: this.jwtService.sign(payload) };
  }
}

Al registrar un usuario

async registrar(email: string, password: string) {
  const encriptada = await bcrypt.hash(password, 10);
  const usuario = this.usuarios.create({ email, password: encriptada });
  return this.usuarios.save(usuario);
}

8.4 Estrategia JWT con Passport

Qué es una estrategia

Passport usa estrategias para autenticar peticiones. La estrategia passport-jwt extrae el token del encabezado Authorization (tipo Bearer) y verifica su firma y expiración.

Servicio de estrategia

import { Injectable } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: process.env.JWT_SECRET,
    });
  }

  async validate(payload: any) {
    return { userId: payload.sub, email: payload.email, rol: payload.rol };
  }
}
El método `validate` se ejecuta cuando el token es válido. Lo que devuelva se asigna al objeto `request.user` y queda disponible en el controlador.

Registrar la estrategia en el módulo

providers: [AuthService, JwtStrategy],
exports: [JwtStrategy, PassportModule],

8.5 Guard de autenticación y controlador

Guard con AuthGuard de Passport

El AuthGuard de Passport se usa como decorador para proteger rutas. Al aplicar AuthGuard('jwt'), la estrategia JWT protege el endpoint.

Proteger una ruta

import { Controller, Get, UseGuards, Request } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';

@Controller('perfil')
export class PerfilController {
  @Get()
  @UseGuards(AuthGuard('jwt'))
  verPerfil(@Request() req) {
    return { mensaje: 'Acceso concedido', usuario: req.user };
  }
}

Controlador de autenticación

import { Controller, Post, Body, UseGuards } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';
import { AuthService } from './auth.service';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('login')
  async login(@Body() { email, password }: any) {
    const usuario = await this.authService.validarUsuario(email, password);
    return this.authService.login(usuario);
  }

  @Post('registro')
  async registrar(@Body() { email, password }: any) {
    return this.authService.registrar(email, password);
  }

  @Get('protegido')
  @UseGuards(AuthGuard('jwt'))
  protegido() {
    return { mensaje: 'Ruta protegida por JWT' };
  }
}

Prueba con curl o Postman

# Obtener el token
curl -X POST http://localhost:3000/auth/login -H "Content-Type: application/json" -d "{\"email\":\"ana@mail.com\",\"password\":\"123456\"}"

# Usar el token
curl http://localhost:3000/perfil -H "Authorization: Bearer <TOKEN>"

8.6 Roles y control de acceso

Autorización por roles

La autenticación verifica quién es el usuario; la autorización decide qué puede hacer. Se suele implementar con un guard que lee los roles del token.

Decorador personalizado de roles

import { SetMetadata } from '@nestjs/common';

export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

Guard de roles

import { Injectable, CanActivate, ExecutionContext, ForbiddenException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride<string[]>('roles', [
      context.getHandler(),
      context.getClass(),
    ]);

    if (!roles || roles.length === 0) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const rolUsuario = request.user?.rol;

    if (!roles.includes(rolUsuario)) {
      throw new ForbiddenException('No tienes permisos');
    }
    return true;
  }
}

Aplicar roles a un endpoint

@Get('admin')
@UseGuards(AuthGuard('jwt'), RolesGuard)
@Roles('admin')
adminSolo() {
  return { mensaje: 'Solo administradores' };
}

Resumen

**Lo que aprendiste en esta sección:** - JWT es un token compacto y firmado que transmite la identidad del usuario - Se compone de header, payload y firma, separados por puntos - Se instala con `@nestjs/jwt`, `@nestjs/passport` y `passport-jwt` - Las contraseñas se encriptan con bcrypt antes de guardarlas - La estrategia JWT valida el token y expone los datos en `request.user` - Los guards protegen rutas y los roles controlan los permisos
