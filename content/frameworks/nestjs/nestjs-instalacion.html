2.1 Requisitos previos

Requisitos para instalar NestJS

RequisitoVersión recomendada
Node.js20.x o superior (compilación nativa de esbuild y SWC)
npm10.x o superior (incluido con Node.js)
Editor de códigoVS Code con la extensión de ESLint y Prettier
GitOpcional, recomendado para control de versiones

Verificar la instalación de Node.js

# Verificar versión de Node.js
node --version
# v20.11.0

# Verificar versión de npm
npm --version
# 10.2.4
Si no tienes Node.js instalado, descárgalo desde el sitio oficial de Node.js y usa la versión LTS para proyectos de producción.

Node.js vs NestJS

NestJS es un framework de Node.js: necesita Node instalado para crear el proyecto, instalar dependencias y ejecutar la aplicación. NestJS 10 requiere Node 16 o superior, mientras que NestJS 11 requiere Node 20 o superior.

2.2 Instalación de Nest CLI

Qué es Nest CLI

Nest CLI es la herramienta de línea de comandos oficial que permite crear proyectos, generar módulos, controladores y servicios, y ejecutar la aplicación con un solo comando.

Instalar Nest CLI de forma global

# Instalación global con npm
npm install -g @nestjs/cli

# Verificar la instalación
nest --version
# 10.3.0

# Ver la ayuda del CLI
nest --help

Opciones de instalación

OpciónDescripción
npm install -g @nestjs/cliInstala el CLI globalmente (recomendado)
npx @nestjs/cliUsa el CLI sin instalarlo (por proyecto)
Si usas `npx`, puedes ejecutar comandos como `npx @nestjs/cli new mi-proyecto` sin instalar nada de forma global.

2.3 Crear el primer proyecto con nest new

Comando nest new

# Crear un nuevo proyecto
nest new mi-primer-api

# Crear un proyecto sin git
nest new mi-primer-api --no-git

# Crear un proyecto con el gestor de paquetes indicado
nest new mi-primer-api --package-manager npm

El comando genera la estructura base, instala las dependencias y pregunta por el gestor de paquetes preferido.

Entrar y explorar el proyecto

# Entrar a la carpeta del proyecto
cd mi-primer-api

# Ver los scripts disponibles
npm run

Flags principales

FlagDescripción
--skip-git / --no-gitNo inicializar un repositorio git
--package-managerDefine npm, yarn o pnpm
--strictHabilita el modo estricto de TypeScript

2.4 Estructura de carpetas

Estructura generada por nest new

mi-primer-api/
├── src/
│   ├── app.controller.ts     # Controlador raíz
│   ├── app.controller.spec.ts# Pruebas del controlador
│   ├── app.module.ts         # Módulo raíz
│   ├── app.service.ts        # Servicio raíz
│   └── main.ts               # Punto de entrada
├── test/
│   ├── app.e2e-spec.ts       # Pruebas de integración
│   └── jest-e2e.json         # Configuración de pruebas e2e
├── node_modules/             # Dependencias
├── package.json
├── nest-cli.json             # Configuración del CLI
├── tsconfig.json             # Configuración de TypeScript
├── tsconfig.build.json
├── eslint.config.mjs         # Configuración de ESLint
├── prettierrc               # Configuración de Prettier
└── .gitignore

Archivos esenciales

ArchivoRol
main.tsArranca la aplicación y configura el puerto
app.module.tsMódulo raíz que agrupa toda la aplicación
app.controller.tsControlador del endpoint raíz /
app.service.tsServicio con la lógica de negocio principal

Contenido de main.ts

import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(3000);
}

bootstrap();

2.5 Ejecutar la aplicación

Modos de ejecución

ComandoDescripción
npm run startCompila y ejecuta la aplicación
npm run start:devEjecuta con recarga automática (watch mode)
npm run start:debugEjecuta con recarga y el inspector de Node.js
npm run start:prodEjecuta la compilación de producción desde dist

Ejecutar en modo desarrollo

npm run start:dev

# Salida esperada:
# [Nest] 12345  - Logging  => Starting Nest application...
# [Nest] 12345  - RoutesResolver => Mapped {/ , GET} route
# [Nest] 12345  - Nest application successfully started

El modo de desarrollo usa nest start --watch, que reinicia la aplicación automáticamente cuando detecta cambios en el código.

Probar la aplicación

# Abrir en el navegador
http://localhost:3000

# Respuesta esperada (Hola Mundo)
Hello World!
Nunca uses `start:dev` en producción: el modo watch y los logs extras reducen el rendimiento y pueden reiniciar el servicio inesperadamente.

2.6 Comandos útiles del CLI

Comandos de generación

# Generar un módulo
nest generate module usuarios

# Generar un controlador dentro de un módulo
nest generate controller productos

# Generar un servicio
nest generate service pedidos

# Generar un recurso completo (CRUD con migas de pan)
nest generate resource catalogo

# Generar un guard
nest generate guard auth

# Generar un pipe
nest generate pipe validar-dni

Formas abreviadas

Comando largoAbreviatura
nest generate module Xnest g mo X
nest generate controller Xnest g co X
nest generate service Xnest g s X
nest generate resource Xnest g res X

Otros comandos

# Ver la información del proyecto y sus dependencias
nest info

# Compilar la aplicación
npm run build

# Ejecutar las pruebas unitarias
npm run test

---

Resumen

**Lo que aprendiste en esta sección:** - NestJS requiere Node.js 20.x o superior - Se instala el CLI global con `npm install -g @nestjs/cli` - `nest new nombre-proyecto` crea la estructura base con dependencias - La carpeta `src` contiene módulos, controladores, servicios y `main.ts` - `npm run start:dev` ejecuta la aplicación con recarga automática - El CLI genera código con comandos como `nest g co`, `nest g s` y `nest g res`
