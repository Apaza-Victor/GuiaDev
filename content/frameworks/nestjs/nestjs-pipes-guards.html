6.1 Qué son los Pipes

Definición

Un pipe en NestJS es una clase con el decorador @Injectable() que implementa la interfaz PipeTransform. Cada pipe procesa los argumentos de una petición antes de que lleguen al controlador y cumple dos funciones: transformación y validación.

Funciones de un pipe

FunciónDescripción
TransformaciónConvierte los datos: string a number, minúsculas, etc.
ValidaciónRechaza datos inválidos lanzando una excepción

Ciclo de una petición con pipe

Petición -> Pipes de validación -> Controlador -> Servicio
import { PipeTransform, Injectable, BadRequestException } from '@nestjs/common';

@Injectable()
export class TransformarTextoPipe implements PipeTransform {
  transform(value: any) {
    if (typeof value !== 'string') {
      throw new BadRequestException('El valor debe ser texto');
    }
    return value.toLowerCase();
  }
}

6.2 Pipes integrados en NestJS

Pipes disponibles

PipeQué hace
ValidationPipeValida y transforma según DTOs y class-validator
ParseIntPipeConvierte a número entero
ParseFloatPipeConvierte a número con decimales
ParseBoolPipeConvierte a booleano
ParseUUIDPipeValida que sea un UUID y lo devuelve
ParseArrayPipeValida y convierte arreglos
DefaultValuePipeAsigna un valor por defecto

Ejemplo con ParseIntPipe

import { Controller, Get, Param, ParseIntPipe } from '@nestjs/common';

@Controller('gatos')
export class GatosController {
  @Get(':id')
  obtenerUno(@Param('id', ParseIntPipe) id: number) {
    // id ya es un number. "abc" lanzaría 400 Bad Request
    return `Gato con id numérico: ${id + 1}`;
  }
}

Ejemplo con DefaultValuePipe

import { Controller, Get, Query, DefaultValuePipe, ParseIntPipe } from '@nestjs/common';

@Controller('gatos')
export class GatosController {
  @Get()
  paginar(
    @Query('pagina', new DefaultValuePipe(1), ParseIntPipe) pagina: number,
  ) {
    return `Página solicitada: ${pagina}`;
  }
}

6.3 Validación con class-validator y ValidationPipe

Instalar las dependencias

npm install class-validator class-transformer

Activar el ValidationPipe global

// main.ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(new ValidationPipe({ whitelist: true }));
  await app.listen(3000);
}

bootstrap();

DTO con decoradores de validación

// crear-gato.dto.ts
import { IsString, IsInt, Min, MaxLength, IsOptional } from 'class-validator';

export class CrearGatoDto {
  @IsString()
  @MaxLength(50)
  nombre: string;

  @IsInt()
  @Min(0)
  edad: number;

  @IsOptional()
  @IsString()
  raza?: string;
}

Controlador que valida el body

import { Controller, Post, Body } from '@nestjs/common';
import { CrearGatoDto } from './crear-gato.dto';

@Controller('gatos')
export class GatosController {
  @Post()
  crear(@Body() datos: CrearGatoDto) {
    return `Gato válido: ${datos.nombre}`;
  }
}
La opción `whitelist: true` elimina automáticamente las propiedades que no están declaradas en el DTO, evitando ataques de sobrerescritura de propiedades.

Errores de validación devueltos

POST /gatos  {"nombre": 123, "edad": -5}

{
  "statusCode": 400,
  "message": [
    "nombre must be a string",
    "edad must not be less than 0"
  ],
  "error": "Bad Request"
}

6.4 Pipes personalizados

Interfaz PipeTransform

Para crear un pipe personalizado se implementa la interfaz PipeTransform, que exige el método transform.

import { PipeTransform, Injectable, ArgumentMetadata, BadRequestException } from '@nestjs/common';

@Injectable()
export class ValidarEmailPipe implements PipeTransform {
  transform(value: any, metadata: ArgumentMetadata) {
    if (typeof value !== 'string' || !value.includes('@')) {
      throw new BadRequestException('El correo no es válido');
    }
    return value.trim().toLowerCase();
  }
}

Usar el pipe en un endpoint

import { Controller, Post, Body, UsePipes } from '@nestjs/common';
import { ValidarEmailPipe } from './validar-email.pipe';

@Controller('usuarios')
export class UsuariosController {
  @Post('registro')
  @UsePipes(new ValidarEmailPipe())
  registrar(@Body('email') email: string) {
    return `Correo registrado: ${email}`;
  }
}

Pipe a nivel de parámetro

@Post('registro')
registrar(@Body('email', ValidarEmailPipe) email: string) {
  return email;
}

Niveles de aplicación de un pipe

NivelAlcance
GlobalToda la aplicación
ControladorTodos los handlers del controlador
MétodoUn único handler
ParámetroUn único argumento

6.5 Qué son los Guards

Definición

Los guards determinan si una petición debe continuar o rechazarse. Se usan sobre todo para autorización: verificar permisos, roles o autenticación antes de ejecutar el handler.

Diferencias con los middlewares

GuardMiddleware
Se ejecuta después del middlewareSe ejecuta antes
Conoce la ruta y el método invocadosNo conoce el destino final
Implementa CanActivateFunción o clase con NestMiddleware

Ejemplo: guard que autentica con token

import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';

@Injectable()
export class ApiKeyGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const apiKey = request.headers['x-api-key'];

    if (apiKey !== 'clave-super-secreta') {
      throw new UnauthorizedException('API key inválida');
    }
    return true;
  }
}

6.6 Proteger rutas con Guards

Aplicar un guard a un endpoint

import { Controller, Get, UseGuards } from '@nestjs/common';
import { ApiKeyGuard } from './api-key.guard';

@Controller('privado')
export class PrivadoController {
  @Get()
  @UseGuards(ApiKeyGuard)
  secreto() {
    return 'Información protegida';
  }
}

Aplicar un guard a todo un controlador

import { Controller, Get, UseGuards } from '@nestjs/common';
import { ApiKeyGuard } from './api-key.guard';

@UseGuards(ApiKeyGuard)
@Controller('privado')
export class PrivadoController {
  @Get()
  secreto() {
    return 'Todo este controlador está protegido';
  }
}

Guard global con roles

import { Injectable, CanActivate, ExecutionContext, ForbiddenException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { ROLES_KEY } from './roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const rolesRequeridos = this.reflector.getAllAndOverride<string[]>(
      ROLES_KEY,
      [context.getHandler(), context.getClass()],
    );

    if (!rolesRequeridos || rolesRequeridos.length === 0) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const rolUsuario = request.user?.rol;

    if (!rolesRequeridos.includes(rolUsuario)) {
      throw new ForbiddenException('No tienes permisos suficientes');
    }
    return true;
  }
}
Genera guards con el CLI: `nest g guard nombre`. Se registran automáticamente como providers en el módulo.

Resumen

**Lo que aprendiste en esta sección:** - Los pipes transforman y validan los datos antes de llegar al controlador - NestJS incluye pipes integrados como `ParseIntPipe` y `ValidationPipe` - `class-validator` y `class-transformer` habilitan la validación con DTOs - Los pipes personalizados implementan la interfaz `PipeTransform` - Los guards autorizan o rechazan peticiones con `CanActivate` - Los guards se aplican con `@UseGuards` a nivel de handler o controlador
