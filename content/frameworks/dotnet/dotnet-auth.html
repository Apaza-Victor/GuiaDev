9.1 Autenticación vs autorización

Diferencias

Dos conceptos similares pero distintos:

ConceptoPreguntaSignificado
AutenticaciónQuién eresVerifica la identidad (login)
AutorizaciónQué puedes hacerControla los permisos de acceso

Flujo típico

// 1. El usuario inicia sesión (autenticación)
// 2. El sistema emite una credencial (cookie o token)
// 3. En cada petición se valida la credencial
// 4. Se decide si el usuario puede acceder (autorización)

9.2 ASP.NET Core Identity

Qué es Identity

ASP.NET Core Identity es el sistema integrado de gestión de usuarios: registro, login, contraseñas, roles y claims. Se integra con EF Core y almacena los usuarios en la base de datos.

Instalar y registrar

dotnet add package Microsoft.AspNetCore.Identity.EntityFrameworkCore
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("Conexion")));

builder.Services.AddDefaultIdentity<IdentityUser>()
    .AddEntityFrameworkStores<AppDbContext>();

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();
app.Run();
Usa el comando `dotnet new mvc` con autenticación individual para obtener las plantillas de login y registro.

9.3 Autenticación con cookies

Qué es el esquema de cookies

En aplicaciones web MVC, la autenticación suele usar cookies: tras el login, el servidor guarda una cookie cifrada en el navegador que identifica al usuario en cada petición.

Iniciar sesión

[HttpPost]
public async Task<IActionResult> Login(LoginViewModel modelo)
{
    var resultado = await _signInManager
        .PasswordSignInAsync(modelo.Email, modelo.Password,
            persistente: true, lockoutOnFailure: false);

    if (resultado.Succeeded)
        return RedirectToAction("Index", "Home");

    ModelState.AddModelError("", "Credenciales inválidas");
    return View(modelo);
}

Cerrar sesión

[HttpPost]
public async Task<IActionResult> Logout()
{
    await _signInManager.SignOutAsync();
    return RedirectToAction("Index", "Home");
}

9.4 JWT Bearer para APIs

Qué es JWT

En las APIs REST se suele usar JWT (JSON Web Tokens): el cliente envía un token firmado en la cabecera Authorization: Bearer <token>.

Configurar la autenticación JWT

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidIssuer = "mi-api",
            ValidAudience = "mis-clientes",
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes("clave-super-secreta-de-prueba-123"))
        };
    });

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();
app.Run();
Nunca guardes claves secretas en el código; configúralas en variables de entorno o secrets de usuario.

9.5 El atributo [Authorize]

Proteger rutas

El atributo [Authorize] exige que el usuario esté autenticado (y opcionalmente autorizado) para acceder a una acción o controlador.

Ejemplos de uso

public class CuentaController : Controller
{
    // Requiere iniciar sesión
    [Authorize]
    public IActionResult Perfil()
    {
        return View();
    }

    // Requiere un rol específico
    [Authorize(Roles = "Admin")]
    public IActionResult GestionUsuarios()
    {
        return View();
    }

    // Requiere una claim concreta
    [Authorize(Policy = "SoloAdultos")]
    public IActionResult ContenidoRestringido()
    {
        return View();
    }
}

Proteger toda la app o un controlador

[Authorize]
public class PedidosController : Controller
{
    // Todas las acciones requieren autenticación
}

9.6 Roles y claims

Diferencias

Ambos otorgan información sobre el usuario:

ElementoDescripción
RolGrupo de permisos (Admin, Editor, Usuario)
ClaimAfirmación concreta (edad, departamento, permiso)

Asignar un rol

var usuario = new IdentityUser { UserName = email, Email = email };
var resultado = await _userManager.CreateAsync(usuario, password);
if (resultado.Succeeded)
{
    await _userManager.AddToRoleAsync(usuario, "Admin");
}

Crear un rol

if (!await _roleManager.RoleExistsAsync("Admin"))
{
    await _roleManager.CreateAsync(new IdentityRole("Admin"));
}
Combina roles y claims según la complejidad: roles para grupos generales y claims para permisos específicos.

Resumen

**Lo que aprendiste en esta sección:** - Autenticación verifica la identidad; autorización controla permisos - ASP.NET Core Identity gestiona usuarios, roles y claims - Las apps MVC suelen usar autenticación con cookies - Las APIs REST usan JWT con la cabecera Bearer - [Authorize] protege rutas con roles y políticas - Roles agrupan permisos; claims expresan afirmaciones concretas
