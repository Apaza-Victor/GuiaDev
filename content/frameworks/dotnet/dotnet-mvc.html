3.1 El patrón MVC

Qué es MVC

MVC (Model-View-Controller) es un patrón de diseño que separa la lógica de la aplicación en tres componentes: Modelo, Vista y Controlador. ASP.NET Core implementa este patrón de forma nativa para construir aplicaciones web.

Los tres roles

ComponenteResponsabilidad
ModeloDatos y reglas de negocio
VistaPresentación o interfaz (HTML)
ControladorManeja la petición y orquesta

Flujo de una petición

// Flujo: Browser -> Controlador -> Modelo -> Vista -> HTML
// 1. El navegador envía una petición a una URL
// 2. El Controlador recibe la solicitud
// 3. Consulta el Modelo (datos)
// 4. Elige una Vista y devuelve la respuesta
// 5. La Vista genera el HTML que ve el usuario

---

3.2 El Modelo

Qué es el Modelo

El Modelo representa los datos de la aplicación y las reglas de negocio. Suele ser clases C# que mapean tablas de base de datos o representan estructuras de dominio.

Ejemplo: Modelo Producto

public class Producto
{
    public int Id { get; set; }
    public string Nombre { get; set; }
    public decimal Precio { get; set; }
    public string Categoria { get; set; }
}

Tipos de modelos

  • Modelos de dominio: Representan entidades de negocio
  • ViewModels: Datos que consumirá una vista específica
  • DTOs: Objetos para transferir datos entre capas

---

3.3 La Vista

Qué es la Vista

La Vista es la capa de presentación. En ASP.NET Core se crean con archivos Razor .cshtml que combinan HTML con código C# usando la sintaxis @.

Ejemplo: Vista que muestra un producto

@model Producto

<h1>Detalle del producto</h1>
<p>Nombre: @Model.Nombre</p>
<p>Precio: @Model.Precio</p>
<p>Categoría: @Model.Categoria</p>

Carpeta de vistas (convención)

Views/
  Home/Index.cshtml
  Producto/Detalle.cshtml
  Cart/Ver.cshtml

---

3.4 El Controlador

Qué es el Controlador

El Controlador recibe la petición HTTP, procesa la lógica necesaria, consulta modelos y devuelve la vista correspondiente. Hereda de Controller.

Ejemplo: Controlador de Productos

public class ProductoController : Controller
{
    public IActionResult Detalle(int id)
    {
        var producto = new Producto
        {
            Id = id,
            Nombre = "Laptop Gamer",
            Precio = 1299.99m,
            Categoria = "Tecnología"
        };
        return View(producto);
    }
}

Acciones

Cada método público del controlador es una acción que responde a una ruta. Devuelve un IActionResult (vistas, JSON, redirecciones).

3.5 Middleware y pipeline

Qué es middleware

El middleware son componentes que forman el pipeline de procesamiento de cada petición. Cada middleware puede validar, modificar o pasar la petición al siguiente.

Orden típico del pipeline

  • UseStaticFiles: Sirve archivos estáticos
  • UseRouting: Resuelve la ruta de la petición
  • UseAuthentication: Autentica al usuario
  • UseAuthorization: Autoriza el acceso
  • MapControllers: Enruta a los controladores

Ejemplo: Configurar el pipeline

var app = builder.Build();

app.UseStaticFiles();
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapDefaultControllerRoute();

app.Run();

3.6 Program y la inyección de dependencias

La clase Program

Con el modelo de hosting minimal, Program.cs construye la aplicación, registra servicios y configura el middleware.

Registro de servicios (DI)

var builder = WebApplication.CreateBuilder(args);

// Registrar MVC
builder.Services.AddControllersWithViews();

// Registrar servicios personalizados
builder.Services.AddScoped<IProductoServicio, ProductoServicio>();

var app = builder.Build();

app.UseStaticFiles();
app.MapDefaultControllerRoute();
app.Run();

Inyección en un controlador

public class ProductoController : Controller
{
    private readonly IProductoServicio _servicio;

    public ProductoController(IProductoServicio servicio)
    {
        _servicio = servicio;
    }

    public IActionResult Index()
    {
        return View(_servicio.ObtenerTodos());
    }
}
La inyección de dependencias reduces el acoplamiento y facilita las pruebas con mocks.

---

Resumen

**Lo que aprendiste en esta sección:** - MVC separa la aplicación en Modelo, Vista y Controlador - El Modelo maneja datos y reglas de negocio - Las Vistas son archivos Razor .cshtml con HTML y C# - El Controlador recibe la petición y coordina la respuesta - El pipeline usa middleware (static, routing, auth, controllers) - Program.cs registra servicios y configura la inyección de dependencias
