10.1 dotnet publish

Qué es publicar

dotnet publish compila la aplicación y genera todos los archivos necesarios para desplegarla (binarios, dependencias, vistas y estáticos) en la carpeta de publicación.

Comando básico

dotnet publish -c Release -o /ruta/publicacion

Opciones importantes

OpciónDescripción
-c ReleasePublica en modo Release
-oCarpeta de salida
-rRuntime específico (win-x64, linux-x64)
--self-containedIncluye el runtime de .NET

---

10.2 Publish profiles

Qué son

Un publish profile guarda la configuración de publicación (destino, modo, runtime) para reutilizarla. Se generan al publicar desde Visual Studio.

Publicar con un profile

dotnet publish -p:PublishProfile=MiServidor -p:Configuration=Release

Ejemplo de profile (Properties/PublishProfiles)

<Project>
  <PropertyGroup>
    <PublishProtocol>FileSystem</PublishProtocol>
    <PublishDir>bin\Release\net8.0\publish\</PublishDir>
    <Configuration>Release</Configuration>
  </PropertyGroup>
</Project>
Los profiles facilitan publicar a varios entornos (dev, staging, producción) con configuraciones distintas.

10.3 Kestrel e IIS

El servidor Kestrel

Kestrel es el servidor web integrado y multiplataforma de ASP.NET Core. Es el que se usa por defecto para servir la aplicación.

Despliegue en Windows con IIS

IIS suele actuar como proxy inverso delante de Kestrel, agregando gestión de procesos y seguridad:

  • Instalar el ASP.NET Core Hosting Bundle
  • Publicar la app en una carpeta (por ejemplo C:\inetpub\apps\miapp)
  • Crear un sitio o aplicación en IIS apuntando a esa carpeta
  • Asignar el grupo de aplicaciones (Sin código administrado)
dotnet publish -c Release -o C:\inetpub\apps\miapp

10.4 Despliegue con Docker

Qué es Docker (concepto)

Docker empaqueta la aplicación y sus dependencias en un contenedor ligero y portátil que se ejecuta igual en cualquier entorno (Windows, Linux, nube).

Ejemplo: Dockerfile

# Imagen base para publicación
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

# Imagen de ejecución
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .
EXPOSE 80
ENTRYPOINT ["dotnet", "MiApp.dll"]

Comandos

docker build -t miapp .
docker run -p 8080:80 miapp
Docker facilita el despliegue consistente en desarrollo, CI/CD y producción.

10.5 Variables de entorno y appsettings

Configuración por entornos

ASP.NET Core lee la configuración de varios orígenes: appsettings.json, appsettings.{Environment}.json y variables de entorno (que tienen prioridad).

Ejemplo: appsettings.json

{
  "ConnectionStrings": {
    "Conexion": "Server=.;Database=MiDB;Trusted_Connection=True;"
  },
  "Logging": {
    "LogLevel": { "Default": "Information" }
  }
}

Variables de entorno

Para producción conviene sobreescribir valores sensibles sin modificar el código:

$env:ConnectionStrings__Conexion = "Server=prod;Database=MiDB;..."; dotnet run

La doble barra baja (__) representa la anidación de secciones.

10.6 Buenas prácticas de despliegue

Recomendaciones

  • Publicar en Release: nunca desplegar una compilación Debug
  • No guardar secretos: usar variables de entorno o secretos administrados
  • Habilitar logging: registrar errores y excepciones correctamente
  • Usar migraciones: aplicar cambios de BD de forma controlada
  • Configurar HTTPS: forzar conexiones seguras
  • CI/CD: automatizar build, pruebas y despliegue

Ejemplo: forzar HTTPS y redirigir

var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.MapDefaultControllerRoute();
app.Run();
Ejecuta las migraciones de la base de datos como paso previo al despliegue de la aplicación.
