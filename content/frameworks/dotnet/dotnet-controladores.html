4.1 Qué es un controlador

Definición

Un controlador es una clase C# que hereda de Controller (o ControllerBase) y agrupa acciones relacionadas que responden a peticiones HTTP.

Ejemplo: Controlador básico

public class HomeController : Controller
{
    public IActionResult Index()
    {
        return View();
    }

    public IActionResult Privacy()
    {
        return View();
    }
}

Características

CaracterísticaDescripción
AccionesMétodos públicos que responden peticiones
RutasCada acción tiene una URL
ResultadosDevuelven vistas, JSON o redirecciones
Verbos HTTPGET, POST, PUT, DELETE

---

4.2 Acciones

Qué es una acción

Una acción es un método público de un controlador que maneja una petición. Su nombre y el controlador determinan la URL por convención.

Ejemplo: Acciones con distintos verbos

public class ProductoController : Controller
{
    // GET /Producto
    public IActionResult Lista()
    {
        return View();
    }

    // GET /Producto/Crear
    public IActionResult Crear()
    {
        return View();
    }

    // POST /Producto/Crear
    [HttpPost]
    public IActionResult Crear(Producto producto)
    {
        return RedirectToAction("Lista");
    }
}

Atributos de verbo

  • [HttpGet]: Solo responde peticiones GET
  • [HttpPost]: Solo responde peticiones POST
  • [HttpPut]: Solo peticiones PUT
  • [HttpDelete]: Solo peticiones DELETE

---

4.3 Routing

Qué es el routing

El routing asocia una URL solicitada con una acción concreta. En ASP.NET Core se define con convenciones (rutas por defecto) o con atributos.

Ruta por convención

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

Con este patrón: /Producto/Detalle/5 llama a ProductoController.Detalle(5).

Ruting con atributos

[Route("[controller]")]
public class ProductoController : Controller
{
    [Route("")]
    [Route("Lista")]
    public IActionResult Lista() => View();

    [Route("Detalle/{id:int}")]
    public IActionResult Detalle(int id) => View();
}

---

4.4 IActionResult y los resultados

Qué devuelven las acciones

Las acciones devuelven un IActionResult, un objeto que describe la respuesta. Existen varios tipos de resultados.

ResultadoMétodoUso
ViewView()Devuelve una vista
JSONJson()Devuelve JSON
RedirectRedirectToAction()Redirige a otra acción
NotFoundNotFound()Error 404
ContentContent()Devuelve texto sencillo

Ejemplo: Distintos resultados

public IActionResult Acciones(int id)
{
    if (id <= 0)
        return NotFound();

    if (id == 1)
        return Content("Texto plano");

    if (id == 2)
        return Json(new { Nombre = "Ana" });

    return RedirectToAction("Index");
}

4.5 Parámetros y enlace de modelos

Tipos de parámetros

Las acciones pueden recibir parámetros desde la ruta, la cadena de consulta (query) o el cuerpo de la petición.

Ejemplo: Parámetros desde la URL

// /Producto/Buscar?nombre=laptop&orden=precio
public IActionResult Buscar(string nombre, string orden = "precio")
{
    return Content($"Buscando: {nombre} ordenado por {orden}");
}

// /Producto/Detalle/7
public IActionResult Detalle(int id)
{
    return Content($"Producto {id}");
}

Enlace de modelos (model binding)

public class ProductoController : Controller
{
    // Los datos del formulario se enlazan al objeto Producto
    [HttpPost]
    public IActionResult Guardar(Producto producto)
    {
        return Content($"{producto.Nombre} - {producto.Precio}");
    }
}
El model binding convierte automáticamente los valores de la petición en tipos C#.

---

Resumen

**Lo que aprendiste en esta sección:** - Los controladores heredan de Controller y agrupan acciones - Cada acción es un método público que responde una petición - El routing asocia URLs con acciones (convención o atributos) - IActionResult permite devolver vistas, JSON, redirecciones y errores - Los parámetros llegan desde la ruta, query o el cuerpo de la petición - El model binding convierte los datos automáticamente
