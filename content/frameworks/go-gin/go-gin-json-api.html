5.1 Respuestas JSON

c.JSON()

Gin serializa automáticamente structs, mapas y slices a JSON con la función c.JSON():

r.GET("/simple", func(c *gin.Context) {
    c.JSON(200, gin.H{
        "nombre": "Juan",
        "edad":   30,
    })
})

r.GET("/struct", func(c *gin.Context) {
    c.JSON(200, Usuario{
        Nombre: "Ana",
        Email:  "ana@mail.com",
    })
})

r.GET("/lista", func(c *gin.Context) {
    c.JSON(200, []string{"rojo", "verde", "azul"})
})

r.GET("/nulo", func(c *gin.Context) {
    c.JSON(200, nil) // devuelve null
})

Métodos de respuesta

MétodoFormato
c.JSON()JSON
c.XML()XML
c.YAML()YAML
c.String()Texto plano
c.HTML()Página HTML
c.Data()Bytes crudos (binarios)

JSON con headers personalizados

c.Header("X-Custom-Header", "valor")
c.JSON(200, gin.H{"ok": true})

5.2 Structs y modelos

Definir modelos

// models/usuario.go
package models

type Usuario struct {
    ID        int       `json:"id"`
    Nombre    string    `json:"nombre"`
    Email     string    `json:"email"`
    Edad      int       `json:"edad,omitempty"`
    Password  string    `json:"-"`
    CreadoEnv time.Time `json:"creado_en"`
}

type Respuesta struct {
    Exito   bool        `json:"exito"`
    Mensaje string      `json:"mensaje"`
    Datos   interface{} `json:"datos,omitempty"`
}

Tags de JSON

TagEfecto
json:"id"Nombre de la clave en JSON
json:"edad,omitempty"Omite el campo si es cero/vacío
json:"-"Excluye el campo del JSON

Uso en handlers

func usuarioHandler(c *gin.Context) {
    usuario := models.Usuario{
        ID:    1,
        Nombre: "Maria",
        Email: "maria@mail.com",
        Edad:  25,
    }
    // Password no aparece en la respuesta
    c.JSON(200, models.Respuesta{
        Exito:   true,
        Mensaje: "Usuario obtenido",
        Datos:   usuario,
    })
}
Nombra tus claves JSON en snake_case (creado_en) para seguir la convención de Go y la mayoría de las APIs REST.

5.3 Binding de request

ShouldBindJSON

El binding convierte automáticamente el cuerpo JSON de un request en un struct:

type UsuarioCrear struct {
    Nombre   string `json:"nombre" binding:"required"`
    Email    string `json:"email" binding:"required,email"`
    Password string `json:"password" binding:"required,min=6"`
}

r.POST("/usuarios", func(c *gin.Context) {
    var u UsuarioCrear
    if err := c.ShouldBindJSON(&u); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }
    c.JSON(201, gin.H{
        "mensaje": "usuario creado",
        "usuario": u,
    })
})

Otras formas de binding

Método de bindingFuente de datos
ShouldBindJSONCuerpo JSON
ShouldBindQueryQuery strings
ShouldBindUriParámetros de la URL
ShouldBindFormFormularios
ShouldBindDetecta automáticamente según Content-Type

Combinación de fuentes

type UsuarioBusqueda struct {
    Termino string `form:"q" json:"q"`
    Pagina  int    `form:"page" json:"page" binding:"gte=1"`
}

r.GET("/buscar", func(c *gin.Context) {
    var filtro UsuarioBusqueda
    if err := c.ShouldBindQuery(&filtro); err != nil {
        c.JSON(400, gin.H{"error": "query inválida"})
        return
    }
    c.JSON(200, filtro)
})

5.4 Validación de datos

Tags de validación

Gin usa el validador go-playground/validator mediante tags binding::

type Producto struct {
    Nombre      string   `json:"nombre" binding:"required"`
    Precio      float64  `json:"precio" binding:"gt=0"`
    Stock       int      `json:"stock" binding:"gte=0"`
    CategoriaID int      `json:"categoria_id" binding:"required"`
    Etiquetas   []string `json:"etiquetas" binding:"max=5"`
    Email       string   `json:"email" binding:"omitempty,email"`
    FechaVe     string   `json:"fecha_vencimiento" binding:"required,datetime=2006-01-02"`
}

Tabla de validadores

Errores legibles

import "github.com/go-playground/validator/v10"

type ErrorValidacion struct {
    Campo   string `json:"campo"`
    Mensaje string `json:"mensaje"`
}

func procesarErrores(verr validator.ValidationErrors) []ErrorValidacion {
    var errores []ErrorValidacion
    for _, e := range verr {
        errores = append(errores, ErrorValidacion{
            Campo:   e.Field(),
            Mensaje: "valor inválido para la regla " + e.Tag(),
        })
    }
    return errores
}

// En el handler:
if err := c.ShouldBindJSON(&u); err != nil {
    c.JSON(400, gin.H{"errores": procesarErrores(err.(validator.ValidationErrors))})
    return
}

5.5 Códigos de estado

Usando net/http

import "net/http"

// 200 - OK
c.JSON(http.StatusOK, gin.H{"ok": true})

// 201 - Creado
c.JSON(http.StatusCreated, gin.H{"id": 1})

// 204 - Sin contenido
c.Status(http.StatusNoContent)

// 400 - Request inválido (validación falló)
c.JSON(http.StatusBadRequest, gin.H{"error": "datos inválidos"})

// 401 - No autenticado
c.JSON(http.StatusUnauthorized, gin.H{"error": "requiere token"})

// 403 - Sin permisos
c.JSON(http.StatusForbidden, gin.H{"error": "acceso denegado"})

// 404 - No encontrado
c.JSON(http.StatusNotFound, gin.H{"error": "recurso no existe"})

// 500 - Error interno
c.JSON(http.StatusInternalServerError, gin.H{"error": "error del servidor"})

5.6 Ejemplo de API JSON

API compacta con validación

package main

import (
    "net/http"
    "github.com/gin-gonic/gin"
)

type Tarea struct {
    ID          int    `json:"id"`
    Titulo      string `json:"titulo" binding:"required"`
    Completada  bool   `json:"completada"`
    Prioridad   int    `json:"prioridad" binding:"gte=1,lte=5"`
}

var tareas = []Tarea{}
var secuencia = 1

func main() {
    r := gin.Default()

    r.GET("/tareas", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{
            "total":  len(tareas),
            "tareas": tareas,
        })
    })

    r.POST("/tareas", func(c *gin.Context) {
        var t Tarea
        if err := c.ShouldBindJSON(&t); err != nil {
            c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
            return
        }
        t.ID = secuencia
        secuencia++
        tareas = append(tareas, t)
        c.JSON(http.StatusCreated, t)
    })

    r.GET("/tareas/:id", func(c *gin.Context) {
        id := c.Param("id")
        for _, t := range tareas {
            if fmt.Sprint(t.ID) == id {
                c.JSON(http.StatusOK, t)
                return
            }
        }
        c.JSON(http.StatusNotFound, gin.H{"error": "tarea no encontrada"})
    })

    r.Run(":8080")
}

Probar con curl

curl -X POST http://localhost:8080/tareas \
  -H "Content-Type: application/json" \
  -d '{"titulo": "Aprender Gin", "prioridad": 5}'

curl http://localhost:8080/tareas
Siempre responde con códigos de estado correctos: 201 al crear, 404 si no existe, 400 si la validación falla.

Resumen

**Lo que aprendiste:** - c.JSON() serializa structs y mapas a JSON automáticamente - Los structs con tags organizan la respuesta y ocultan campos sensibles - ShouldBindJSON convierte el request en struct validado - Los tags de validación evalúan required, email, min, max, gte, etc. - Los códigos de estado correctos hacen la API predecible - Puedes construir APIs completas combinando JSON, binding y validación
