2.1 Instalar Go

Descarga e instalación

Visita https://go.dev/dl/ y descarga el instalador para tu sistema operativo. Go está disponible para Windows, macOS y Linux.

Verificar instalación

go version
# Salida esperada: go version go1.22.0 windows/amd64

go env GOROOT
# Ruta donde está instalado Go

go env GOPATH
# Ruta del directorio de trabajo de Go (por defecto: ~/go)

Variables de entorno importantes

VariableDescripciónValor típico
GOROOTDirectorio raíz de la instalación de GoC:/Go o /usr/local/go
GOPATHDirectorio de trabajo y caché de módulos~/go
GOBINDirectorio donde se instalan binarios$GOPATH/bin
PATHDebe incluir $GOPATH/binAutomático en instaladores
Los instaladores oficiales de Go configuran GOROOT y PATH automáticamente. Solo verifica con go version después de instalar.

2.2 Estructura del proyecto

Organización recomendada

Un proyecto Go con Gin sigue esta estructura:

mi-api/
├── main.go           # Punto de entrada
├── go.mod            # Definición del módulo y dependencias
├── go.sum            # Sumas de verificación de dependencias
├── handlers/         # Handlers de rutas
│   └── usuarios.go
├── models/           # Modelos de datos (structs)
│   └── usuario.go
├── middleware/        # Middleware personalizado
│   └── auth.go
├── config/           # Configuración
│   └── config.go
└── tests/            # Pruebas
    └── main_test.go

Convenciones

  • Los nombres de paquetes usan minúsculas sin guiones (no mi-paquete)
  • Los archivos de Go usan snake_case (usuarios.go)
  • El archivo main.go siempre está en el paquete main
  • Los exportables (funciones, tipos) comienzan con mayúscula

Crear el proyecto

# Crear directorio
mkdir mi-api && cd mi-api

# Inicializar módulo Go
go mod init mi-api

# Crear archivos básicos
touch main.go
mkdir handlers models middleware config tests

2.3 Gestión de módulos

go.mod

El archivo go.mod define el módulo y sus dependencias:

module mi-api

go 1.22

require (
    github.com/gin-gonic/gin v1.9.1
    github.com/google/uuid v1.6.0
)

Comandos de módulos

ComandoFunción
go mod init nombreInicializa un nuevo módulo
go mod tidyAgrega dependencias faltantes y elimina las no usadas
go mod downloadDescarga todas las dependencias
go mod graphMuestra el grafo de dependencias
go mod vendorCopia dependencias al directorio vendor/

Agregar una dependencia

# Agregar Gin al proyecto
go get github.com/gin-gonic/gin

# Agregar una versión específica
go get github.com/gin-gonic/gin@v1.9.1

# Actualizar todas las dependencias
go get -u ./...
Go descarga las dependencias automáticamente al ejecutar go get. El archivo go.sum se genera automáticamente y no debe editarse manualmente.

2.4 Instalar Gin

Paso a paso

# 1. Crear el proyecto
mkdir mi-api-gin && cd mi-api-gin

# 2. Inicializar módulo
go mod init mi-api-gin

# 3. Instalar Gin

# 4. Verificar que se agregó a go.mod

2.5 Servidor básico

Código completo

package main

import (
    "net/http"
    "github.com/gin-gonic/gin"
)

func main() {
    // Crear router con middleware por defecto
    router := gin.Default()

    // Ruta raíz
    router.GET("/", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{
            "status":  "activo",
            "mensaje": "API funcionando con Gin",
        })
    })

    // Ruta con parámetro
    router.GET("/usuarios/:id", func(c *gin.Context) {
        id := c.Param("id")
        c.JSON(http.StatusOK, gin.H{
            "usuario_id": id,
            "nombre":     "Juan Perez",
        })
    })

    // Iniciar servidor
    router.Run(":8080")
}

Componentes clave

  • gin.Default(): Crea router con Logger y Recovery middleware
  • c.JSON(status, objeto): Responde con JSON
  • c.Param("nombre"): Extrae parámetro de la URL
  • router.Run(":8080"): Escucha en el puerto especificado

Probar

go run main.go
# Abre http://localhost:8080
# Abre http://localhost:8080/usuarios/42

2.6 Comandos go run y go build

go run

Compila y ejecuta el programa directamente. Ideal para desarrollo:

go run main.go
go run .                    # Ejecuta todos los .go del directorio
go run ./handlers/          # Ejecuta un paquete específico

go build

Compila el programa y genera un ejecutable binario:

go build                     # Genera binario con nombre del módulo
go build -o mi-api.exe       # Nombre personalizado
go build -ldflags="-s -w"    # Binario más pequeño (sin symbols)

Diferencias

ComandoResultadoUso
go runEjecuta directamenteDesarrollo y pruebas
go buildGenera binario en discoDespliegue en producción
go installInstala en $GOPATH/binHerramientas CLI

Comandos útiles adicionales

go vet ./...          # Analiza errores comunes
go fmt ./...          # Formatea el código
go test ./...          # Ejecuta las pruebas
go clean               # Limpia archivos temporales
En desarrollo usa go run para ejecución rápida. En producción usa go build para generar un binario optimizado que se despliega sin necesidad de instalar Go en el servidor.

Resumen

**Lo que aprendiste:** - Go se instala desde go.dev y se verifica con go version - Los proyectos usan go.mod para gestionar módulos y dependencias - go get descarga e instala paquetes como Gin - Un servidor Gin se crea con gin.Default() y se ejecuta con r.Run() - go run ejecuta directamente; go build genera un binario - La estructura de proyecto separa handlers, models, middleware y config
