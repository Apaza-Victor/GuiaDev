3.1 Definir rutas

gin.Default() vs gin.New()

Existen dos formas de crear un router en Gin:

MétodoMiddleware incluidoUso recomendado
gin.Default()Logger + RecoveryDesarrollo y producción
gin.New()NingunoCuando quieres control total

Sintaxis de rutas

r := gin.Default()

// Rutas simples
r.GET("/inicio", handlerInicio)      // GET /inicio
r.POST("/crear", handlerCrear)       // POST /crear
r.PUT("/actualizar", handlerPut)     // PUT /actualizar
r.DELETE("/borrar", handlerDelete)   // DELETE /borrar
r.PATCH("/parcial", handlerPatch)    // PATCH /parcial

// Cualquier método HTTP
r.Any("/cualquiera", handlerCualquiera)

// Ruta que no existe devuelve 404 automáticamente

Handler signature

Un handler en Gin siempre recibe un puntero a gin.Context:

func miHandler(c *gin.Context) {
    // c contiene toda la información del request
    c.String(200, "Respuesta de texto")
}

3.3 Parámetros en rutas

Tipos de parámetros

TipoSintaxisEjemplo
Path parameter:nombre/usuarios/:id
Wildcard*nombre/archivos/*ruta

Usando c.Param()

// Parámetro simple
r.GET("/usuarios/:id", func(c *gin.Context) {
    id := c.Param("id")
    c.JSON(200, gin.H{"id": id})
})

// Múltiples parámetros
r.GET("/usuarios/:id/posts/:postId", func(c *gin.Context) {
    id := c.Param("id")
    postId := c.Param("postId")
    c.JSON(200, gin.H{
        "usuario_id": id,
        "post_id":    postId,
    })
})

// Wildcard (captura todo lo que sigue)
r.GET("/archivos/*ruta", func(c *gin.Context) {
    ruta := c.Param("ruta")
    c.JSON(200, gin.H{"ruta": ruta})
})

Query strings con c.Query()

// GET /buscar?q=golang&page=2
r.GET("/buscar", func(c *gin.Context) {
    q := c.Query("q")         // "golang"
    page := c.DefaultQuery("page", "1")  // "2" o "1" por defecto
    c.JSON(200, gin.H{
        "busqueda": q,
        "pagina":   page,
    })
})

3.4 Grupos de rutas

Organización con grupos

Los grupos permiten organizar rutas relacionadas y aplicar middleware de forma específica:

r := gin.Default()

// Grupo de usuarios
usuarios := r.Group("/api/usuarios")
{
    usuarios.GET("", listarUsuarios)
    usuarios.POST("", crearUsuario)
    usuarios.GET("/:id", obtenerUsuario)
    usuarios.PUT("/:id", actualizarUsuario)
    usuarios.DELETE("/:id", eliminarUsuario)
}

// Grupo de productos
productos := r.Group("/api/productos")
{
    productos.GET("", listarProductos)
    productos.POST("", crearProducto)
    productos.GET("/:id", obtenerProducto)
}

// Grupo con middleware específico
admin := r.Group("/api/admin", requireAuth())
{
    admin.GET("/dashboard", dashboardHandler)
    admin.GET("/stats", statsHandler)
}

Jerarquía de grupos

api := r.Group("/api")
{
    v1 := api.Group("/v1")
    {
        v1.GET("/usuarios", listarV1)
    }
    v2 := api.Group("/v2")
    {
        v2.GET("/usuarios", listarV2)
    }
}
// Resultado: /api/v1/usuarios y /api/v2/usuarios

Middleware por grupo

// Logger personalizado solo para rutas de admin
admin := r.Group("/admin", miLogger())

3.5 Estructura de router

Patrón recomendado

Separar las rutas en archivos dedicados para mantener el código organizado:

// routes/routes.go
package routes

import (
    "mi-api/handlers"
    "github.com/gin-gonic/gin"
)

func SetupRouter() *gin.Engine {
    r := gin.Default()

    api := r.Group("/api")
    {
        api.GET("/usuarios", handlers.ListarUsuarios)
        api.POST("/usuarios", handlers.CrearUsuario)
        api.GET("/usuarios/:id", handlers.ObtenerUsuario)
        api.PUT("/usuarios/:id", handlers.ActualizarUsuario)
        api.DELETE("/usuarios/:id", handlers.EliminarUsuario)
    }

    return r
}

main.go simplificado

package main

import "mi-api/routes"

func main() {
    r := routes.SetupRouter()
    r.Run(":8080")
}

Conviene usar groups cuando

  • Tienes más de 10 endpoints
  • Algunas rutas requieren autenticación y otras no
  • Quieres versionar tu API (/api/v1, /api/v2)
  • Los endpoints están agrupados por dominio (usuarios, productos, etc.)

3.6 Ejemplo completo de rutas

API de blog

package main

import (
    "net/http"
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    // Grupo público
    publico := r.Group("/api")
    {
        publico.GET("/posts", func(c *gin.Context) {
            c.JSON(http.StatusOK, gin.H{
                "posts": []string{"Post 1", "Post 2"},
            })
        })
        publico.GET("/posts/:id", func(c *gin.Context) {
            c.JSON(http.StatusOK, gin.H{
                "id":    c.Param("id"),
                "titulo": "Mi post",
            })
        })
    }

    // Grupo privado (simulado)
    privado := r.Group("/api/admin")
    {
        privado.POST("/posts", func(c *gin.Context) {
            c.JSON(http.StatusCreated, gin.H{"mensaje": "Post creado"})
        })
        privado.DELETE("/posts/:id", func(c *gin.Context) {
            c.JSON(http.StatusOK, gin.H{
                "mensaje": "Post eliminado",
                "id":     c.Param("id"),
            })
        })
    }

    r.Run(":8080")
}

Resumen

**Lo que aprendiste:** - gin.Default() crea un router con middleware; gin.New() sin middleware - Cada método HTTP (GET, POST, PUT, DELETE) tiene su función de routing - Los parámetros de ruta se obtienen con c.Param() - Las query strings se obtienen con c.Query() o c.DefaultQuery() - Los grupos de rutas organizan endpoints y permiten middleware específico - Separar rutas en archivos dedicados mejora la mantenibilidad
