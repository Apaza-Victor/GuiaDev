10.1 Qué es SvelteKit

El framework de aplicación

SvelteKit es el framework de aplicación construido sobre Svelte. Aporta el conjunto completo de herramientas para crear aplicaciones web: enrutamiento, renderizado en servidor (SSR), optimización de recursos, generación de sitios estáticos y despliegue en distintas plataformas.

Mientras Svelte se encarga de los componentes, SvelteKit orquesta todo el proyecto: rutas, layouts, carga de datos y adaptadores de despliegue.

Características principales

CaracterísticaDescripción
Routing por archivosCada archivo en src/routes define una ruta
SSR y SSGRenderizado en servidor y estático opcional
AdaptadoresDespliegue en Node, Vercel, Netlify, etc.
Carga de datosFunciones +page.js y +layout.js
OptimizaciónCode splitting, preloading y lazy loading

10.2 Routing por archivos

Las rutas son carpetas

SvelteKit usa el routing por archivos: la estructura de carpetas dentro de src/routes define las URL de tu aplicación. Cada carpeta puede contener un archivo +page.svelte que representa la página de esa ruta.

Estructura de ejemplo

src/routes/
  +page.svelte        <!-- / -->
  +layout.svelte      <!-- layout global -->
  about/
    +page.svelte      <!-- /about -->
  blog/
    +page.svelte      <!-- /blog -->
    [slug]/
      +page.svelte    <!-- /blog/:slug (dinámica) -->

Las carpetas entre corchetes [slug] crean rutas dinámicas que capturan un segmento de la URL.

---

10.3 El archivo +page.svelte

Página de una ruta

El archivo +page.svelte contiene el componente que se muestra en su ruta. Puede recibir datos mediante la prop data, que se rellena con las funciones de carga load definidas en +page.js o +page.server.js.

Ejemplo: página simple

<script>
  export let data;
</script>

<h1>{data.titulo}</h1>
<p>{data.contenido}</p>

El archivo +layout.svelte define la estructura común (header, footer) que envuelve a las páginas de su carpeta.

10.4 SSR y carga de datos

Renderizado en el servidor

Por defecto SvelteKit hace SSR (Server-Side Rendering): las páginas se renderizan en el servidor y se envían como HTML al navegador, mejorando el SEO y el tiempo de carga inicial. Después se hidrata en el cliente.

Los datos se cargan con la función load exportada desde +page.js o +page.server.js.

Ejemplo: función load

// src/routes/blog/+page.js
export function load() {
  return {
    posts: [
      { titulo: 'Primer post', resumen: 'Hola' },
      { titulo: 'Segundo post', resumen: 'Adiós' }
    ]
  };
}

Los datos devueltos por load llegan al componente a través de data.

10.5 Adaptadores de despliegue

Publicar la aplicación

Los adaptadores transforman la aplicación para desplegarla en plataformas específicas. Se instalan como dependencias y se configuran en svelte.config.js.

Adaptadores comunes

AdaptadorPlataforma
@sveltejs/adapter-nodeServidor Node.js propio
@sveltejs/adapter-staticSitios estáticos (SSG)
@sveltejs/adapter-vercelVercel
@sveltejs/adapter-netlifyNetlify
@sveltejs/adapter-cloudflareCloudflare Pages

10.6 Proyecto final

Paso a paso

  1. Crear el proyecto con npm create svelte@latest
  2. Instalar las dependencias con npm install
  3. Definir las rutas con archivos +page.svelte en src/routes
  4. Compartir estado con stores y el prefijo $
  5. Cargar datos con funciones load
  6. Estilizar con las directivas de transición y animación
  7. Desplegar usando un adaptador según la plataforma

Ejemplo: arrancar el servidor de desarrollo

npm create svelte@latest mi-app
cd mi-app
npm install
npm run dev

Con esto tienes las bases completas para construir y publicar aplicaciones modernas con Svelte y SvelteKit.

Resumen

**Lo que aprendiste en esta sección:** - SvelteKit es el framework de aplicación construido sobre Svelte - El routing se define por archivos y carpetas en src/routes - +page.svelte representa la página de cada ruta - SSR renderiza en el servidor y mejora el SEO - Los adaptadores preparan el despliegue en distintas plataformas - Completaste el recorrido de Svelte hasta un proyecto final
