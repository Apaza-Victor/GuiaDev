8.1 Repaso de tiendas writable

Estado compartido

La tienda writable es la más común en Svelte. Almacena un valor que cualquier componente puede leer y modificar, lo que libera a los componentes de pasarse datos por cadenas largas de props.

Se crea con writable(valorInicial) y devuelve un objeto con los métodos set, update y subscribe.

Ejemplo: tienda simple

<script>
  import { writable } from 'svelte/store';

  export const usuario = writable(null);
</script>

---

8.2 Métodos set, update y get

Modificar el estado

Para cambiar el valor de una tienda writable se usan los métodos set (sustituir) y update (calcular a partir del valor actual). El método get lee el valor de forma síncrona fuera de un componente o de la suscripción.

Ejemplo: usar los tres métodos

<script>
  import { contador, get } from './stores.js';

  const limpiar = () => contador.set(0);
  const incrementar = () => contador.update(n => n + 1);
  const verValor = () => {
    console.log(get(contador));
  };

  contador.subscribe((valor) => {
    console.log('Cambió a', valor);
  });
</script>

---

8.3 Tiendas derived

Derivar valores calculados

Una tienda derived calcula un nuevo valor a partir de una o varias tiendas fuente. Se recalcula automáticamente cada vez que alguna de sus fuentes cambia, sin necesidad de lógica manual.

Ejemplo: derivar el doble

<script>
  import { writable, derived } from 'svelte/store';

  const contador = writable(5);
  const doble = derived(contador, ($contador) => $contador * 2);
</script>

<p>Contador: {$contador}</p>
<p>Doble: {$doble}</p>

También puedes derivar de varias tiendas pasando un arreglo como primera fuente.

---

8.4 Suscripción manual

Suscribirse sin el prefijo $

Aunque el prefijo $ automatiza la suscripción en los componentes, a veces necesitas hacerlo manualmente, por ejemplo en código outside de un componente o en un función. El método subscribe recibe un callback que se ejecuta con cada cambio y devuelve una función para cancelar la suscripción.

Ejemplo: suscribirse y desuscribirse

<script>
  import { contador } from './stores.js';

  let valor;

  const sinSuscripcion = contador.subscribe((n) => {
    valor = n;
  });

  function detener() {
    sinSuscripcion();
  }
</script>

<p>Valor actual: {valor}</p>
<button on:click={detener}>Detener suscripción</button>

---

8.5 Contexto con setContext y getContext

Compartir datos en el árbol

El contexto de Svelte permite compartir datos entre un componente y sus descendientes sin pasarlos por cada prop intermedia. Se usa setContext(clave, valor) en el ancestro y getContext(clave) en los componentes hijos.

A diferencia de los stores, el contexto no es global: solo es visible en el subárbol del componente que lo definió.

Ejemplo: compartir una función

<script>
  import { setContext, getContext } from 'svelte';

  const CLAVE = 'usuario';

  function proveedor() {
    setContext(CLAVE, { nombre: 'Ana', rol: 'admin' });
  }

  function consumidor() {
    const usuario = getContext(CLAVE);
    return usuario;
  }
</script>

---

8.6 Store vs Contexto

Cuándo usar cada uno

AspectoStoreContexto
AlcanceGlobal a toda la appSolo al subárbol del componente
Por defectoTiene valor inicialSolo existe si el ancestro lo define
Motivo comúnEstado compartido entre rutasPasar dependencias jerárquicas
SuscripciónReactiva con $Re-renderiza el componente

Regla práctica: usa stores para estado global de aplicación y contexto para dependencias de componentes dentro de un contenedor.

Resumen

**Lo que aprendiste en esta sección:** - writable crea tiendas de estado legibles y modificables - set reemplaza el valor y update lo calcula desde el actual - get lee el valor de forma síncrona - derived calcula valores a partir de otras tiendas - subscribe permite la suscripción manual y su cancelación - setContext y getContext comparten datos en un subárbol
