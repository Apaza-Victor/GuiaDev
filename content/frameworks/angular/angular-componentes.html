3.1 Qué es un componente

Definición

Un componente es la unidad básica de construcción de una aplicación Angular. Controla una parte de la pantalla: su presentación (template), su lógica (clase TypeScript) y su estilo.

CaracterísticaDescripción
ResponsabilidadUna parte concreta de la interfaz de usuario
ReutilizableSe puede usar varias veces en la aplicación
EncapsulaTemplate, estilos y lógica en una sola entidad
ComunicaciónRecibe datos (inputs) y emite eventos (outputs)

Anatomía de un componente

Un componente Angular se compone de tres partes:
1. Decorador @Component → metadatos (selector, template o templateUrl, estilos)
2. Clase TypeScript → lógica, propiedades y métodos
3. Template → la parte visual (HTML)

Ejemplo visual

// Componente sin template separado (template inline)
import { Component } from '@angular/core';

@Component({
  selector: 'app-boton',
  template: '<button>Pulsa aquí</button>',
  styles: ['button { color: white; background: blue; }']
})
export class BotonComponent {}

// Componente con template en archivos separados (recomendado)
import { Component } from '@angular/core';

@Component({
  selector: 'app-tarjeta',
  templateUrl: './tarjeta.component.html',
  styleUrls: ['./tarjeta.component.css']
})
export class TarjetaComponent {}

3.2 El decorador @Component

¿Qué es un decorador?

Un decorador es una función especial de TypeScript que añade metadatos a una clase. El decorador @Component le indica a Angular que la clase es un componente.

Sintaxis del decorador

import { Component } from '@angular/core';

@Component({
  selector: 'app-ejemplo',
  templateUrl: './ejemplo.component.html',
  styleUrls: ['./ejemplo.component.css']
})
export class EjemploComponent {
  titulo: string = 'Mi componente';
}

Propiedades principales del decorador

PropiedadDescripción
selectorNombre de la etiqueta HTML con la que se usa el componente
template / templateUrlHTML del componente (inline o archivo externo)
styles / styleUrlsEstilos CSS/SCSS del componente
providersServicios disponibles en este componente y sus hijos
El prefijo app- en el selector es la convención por defecto de Angular CLI. Así se evitan colisiones con elementos HTML nativos.

3.3 Selector, template y estilos

El selector

El selector define cómo se usará el componente dentro de otros templates. Puede ser por etiqueta, atributo o clase.

Tipo de selectorEjemploUso en el template
Elementoapp-navbar<app-navbar></app-navbar>
Atributo[appNavbar]<div appNavbar></div>
Clase.app-navbar<div class="app-navbar"></div>

Template inline vs. templateUrl

// Inline: el HTML va dentro del decorador
@Component({
  selector: 'app-hola',
  template: '<h2>Hola mundo</h2>'
})
export class HolaComponent {}

// Externo: el HTML vive en un archivo .html
@Component({
  selector: 'app-hola',
  templateUrl: './hola.component.html'
})
export class HolaComponent {}

Estilos del componente

// En línea
@Component({
  selector: 'app-caja',
  template: '<p>Caja</p>',
  styles: ['p { border: 1px solid #ccc; padding: 10px; }']
})
export class CajaComponent {}

// Desde un archivo
@Component({
  selector: 'app-caja',
  templateUrl: './caja.component.html',
  styleUrls: ['./caja.component.css']
})
export class CajaComponent {}
Los estilos de un componente son encapsulados: solo afectan a su propio template y no a otros componentes. Esto es una enorme ventaja de Angular.

3.4 La clase del componente

¿Qué contiene la clase?

La clase TypeScript del componente alberga la lógica de negocio: propiedades (datos), métodos (comportamiento) y hooks del ciclo de vida (ngOnInit, etc.).

Propiedades y métodos

import { Component, OnInit } from '@angular/core';

export interface Tarea {
  id: number;
  nombre: string;
  completada: boolean;
}

@Component({
  selector: 'app-tareas',
  templateUrl: './tareas.component.html'
})
export class TareasComponent implements OnInit {
  // Propiedades del componente
  titulo: string = 'Mis tareas';
  contador: number = 0;
  tareas: Tarea[] = [];

  // Método del ciclo de vida: se ejecuta al inicializar
  ngOnInit(): void {
    this.tareas = [
      { id: 1, nombre: 'Aprender Angular', completada: false },
      { id: 2, nombre: 'Crear un proyecto', completada: true }
    ];
  }

  // Método propio
  completarTarea(tarea: Tarea): void {
    tarea.completada = !tarea.completada;
    this.contador++;
  }
}

Uso en el template

<h2>{{ titulo }}</h2>
<p>Tareas completadas: {{ contador }}</p>
<ul>
  <li *ngFor="let tarea of tareas" (click)="completarTarea(tarea)">
    {{ tarea.nombre }} - {{ tarea.completada ? 'Hecha' : 'Pendiente' }}
  </li>
</ul>
La clase se escribe en TypeScript, por lo que tienes tipado, interfaces y autocompletado en tu editor en todo momento.

3.5 Metadatos del componente

Otras propiedaddes del decorador

Más allá de selector, template y estilos, @Component acepta más metadatos para controlar el comportamiento del componente:

PropiedadDescripción
providersRegistra servicios disponibles para este componente
encapsulationControla la encapsulación de estilos (Emulated, None, ShadowDom)
changeDetectionEstrategia de detección de cambios (Default, OnPush)
standaloneMarca el componente como independiente (sin necesidad de NgModule)
hostPermite añadir atributos, clases o listeners al elemento host
animationsDefine animaciones asociadas al componente

Ejemplos de uso

import { Component, ChangeDetectionStrategy, ViewEncapsulation } from '@angular/core';

@Component({
  selector: 'app-listado',
  templateUrl: './listado.component.html',
  encapsulation: ViewEncapsulation.Emulated,   // estilos aislados por defecto
  changeDetection: ChangeDetectionStrategy.OnPush, // render más eficiente
  providers: []  // aquí se podrían registrar servicios
})
export class ListadoComponent {}
La mayoría de los proyectos usan los valores por defecto. Los metadatos avanzados se ajustan cuando se necesita mejorar el rendimiento o cambiar la encapsulación.

3.6 Crear y usar componentes

Crear un componente con la CLI

# Genera: navbar.component.ts, .html, .css y .spec.ts
ng generate component componentes/navbar

# Abreviatura
ng g c componentes/navbar

Registro en el módulo

En las aplicaciones clásicas (con NgModule), el componente debe declararse en su módulo para poder usarse:

import { NgModule } from '@angular/core';
import { AppComponent } from './app.component';
import { NavbarComponent } from './components/navbar/navbar.component';

@NgModule({
  declarations: [AppComponent, NavbarComponent],
  bootstrap: [AppComponent]
})
export class AppModule {}

Usar el componente en un template

<!-- Una vez declarado, se usa con su selector -->
<app-navbar></app-navbar>

<!-- Reutilizable cuantas veces quieras -->
<app-navbar></app-navbar>

Estructura de archivos generada

app/
└── componentes/
    └── navbar/
        ├── navbar.component.ts     # Clase con el decorador @Component
        ├── navbar.component.html   # Template
        ├── navbar.component.css    # Estilos
        └── navbar.component.spec.ts # Pruebas unitarias
Crea siempre los componentes con ng generate: se generan los 4 archivos y visualiza la estructura correcta automáticamente.

---

Resumen

**Lo que aprendiste en esta sección:** - Un **componente** es la unidad básica: template + clase TypeScript + estilos - El decorador @Component añade los **metadatos** que Angular necesita - El **selector** define la etiqueta con la que se usa el componente - El **template** puede ser inline o externo (templateUrl), igual que los estilos - La **clase** contiene propiedades, métodos y hooks del ciclo de vida - Los componentes se generan con ng generate component y se declaran en su módulo
