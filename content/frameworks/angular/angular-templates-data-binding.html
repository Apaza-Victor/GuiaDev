5.1 Interpolación {{ }}

Definición

La interpolación (doble llave) permite mostrar los valores de propiedades de la clase TypeScript directamente en el template. Es el binding más sencillo: va de un solo sentido, de la clase hacia la vista.

Sintaxis

<!-- app.component.html -->
<h1>Hola, {{ nombre }}</h1>
<p>Tu edad es {{ edad }} años</p>
// app.component.ts
export class AppComponent {
  nombre: string = 'Carlos';
  edad: number = 30;
}

Expresiones permitidas

  • Variables: {{ usuario }}
  • Métodos: {{ obtenerTotal() }}
  • Operaciones: {{ precio * cantidad }}
  • Operador ternario: {{ activo ? 'Sí' : 'No' }}

Ejemplo completo

export class ProductoComponent {
  nombre: string = 'Laptop Gamer';
  precio: number = 1200;
  stock: number = 3;

  tieneStock(): string {
    return this.stock > 0 ? 'Disponible' : 'Agotado';
  }
}
<h2>{{ nombre }}</h2>
<p>Precio: ${{ precio }}</p>
<p>Estado: {{ tieneStock() }}</p>
La interpolación solo admite expresiones simples sin efectos secundarios: no uses asignaciones, `++`, ni operaciones con múltiples sentencias dentro de `{{ }}`.

5.2 Property binding [ ]

Definición

El property binding vincula el valor de una propiedad de un elemento, componente o directiva con una expresión de la clase. Se escribe con corchetes: [propiedad].

Sintaxis

<!-- Vinculación de propiedades HTML -->
<img [src]="imagenUrl" [alt]="textoAlternativo">
<input [disabled]="estaDeshabilitado" [placeholder]="textoPlaceholder">

Vincular propiedades de componentes hijos

<!-- app.component.html -->
<app-persona [nombre]="persona.nombre" [edad]="persona.edad"></app-persona>
// persona.component.ts
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-persona',
  template: '<p>{{ nombre }} - {{ edad }} años</p>'
})
export class PersonaComponent {
  @Input() nombre!: string;
  @Input() edad!: number;
}

Diferencias con la interpolación

Interpolación {{ }}Property binding [ ]
Muestra texto en el contenido del elementoAsigna valores a propiedades o atributos
<p>{{ texto }}</p><input [value]="texto">
Solo salida (one-way)Solo salida (one-way)

5.3 Event binding ( )

Definición

El event binding responde a eventos del usuario (clics, teclado, envío de formularios...) ejecutando métodos de la clase. Se escribe con paréntesis: (evento).

Sintaxis

<button (click)="guardar()">Guardar</button>
<input (input)="actualizarTexto($event)">
<form (ngSubmit)="enviarFormulario()">

Ejemplo con variables de plantilla

// contador.component.ts
export class ContadorComponent {
  contador: number = 0;

  incrementar(): void {
    this.contador++;
  }

  decrementar(): void {
    this.contador--;
  }

  reiniciar(): void {
    this.contador = 0;
  }
}
<p>Valor: {{ contador }}</p>
<button (click)="incrementar()">+1</button>
<button (click)="decrementar()">-1</button>
<button (click)="reiniciar()">Reiniciar</button>

Eventos de entrada de texto

<input (keyup.enter)="buscar()" placeholder="Escribe y pulsa Enter">
<input (blur)="validar()" placeholder="Déjalo al salir">
<input (input)="mostrarEnVivo($event)" placeholder="Escribe... ">

5.4 Two-way binding [(ngModel)]

Definición

El two-way binding sincroniza en ambos sentidos: la vista actualiza la propiedad y la propiedad actualiza la vista. En Angular se logra con la directiva ngModel usando la sintaxis [(ngModel)] (corchetes + paréntesis = "banana in a box").

Sintaxis

<input [(ngModel)]="nombre" placeholder="Escribe tu nombre">
<p>Hola, {{ nombre }}</p>

Requisito: importar FormsModule

import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { FormsModule } from '@angular/forms';

import { AppComponent } from './app.component';

@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule, FormsModule],
  bootstrap: [AppComponent]
})
export class AppModule {}

Ejemplo de uso con un objeto

export class FormularioComponent {
  usuario = {
    nombre: '',
    email: '',
    activo: false
  };
}
<input [(ngModel)]="usuario.nombre" placeholder="Nombre">
<input [(ngModel)]="usuario.email" placeholder="Email">
<input type="checkbox" [(ngModel)]="usuario.activo"> Activo
<p>Resumen: {{ usuario | json }}</p>
`[(ngModel)]` no es magic: es la unión de property binding (entrada `[ngModel]`) + event binding (salida `(ngModelChange)`). Puedes escribir cualquiera de las dos formas por separado.

5.5 Comparativa de bindings

Tabla resumen de los tipos de binding

BindingSintaxisDirecciónUso
Interpolación{{ expresion }}Clase → VistaMostrar texto
Property binding[propiedad]Clase → VistaAsignar atributos/propiedades
Event binding(evento)Vista → ClaseReaccionar a eventos
Two-way binding[(ngModel)]Clase ↔ VistaSincronizar formularios e inputs

Resumen visual

<img [src]="imagen" alt="Interpolación: {{ titulo }}">   <!-- [ ] entrada, {{ }} texto -->
<button (click)="accion()" [disabled]="cargando">Enviar</button> <!-- ( ) salida, [ ] entrada -->
<input [(ngModel)]="campo">                              <!-- banana in a box -->
Recuerda la regla mnemotécnica: `[property]` de la clase a la vista, `(event)` de la vista a la clase, y `[(...)]` para ambos sentidos.

5.6 ngModel y FormsModule

Qué es FormsModule

FormsModule es el módulo de Angular que proporciona la directiva ngModel y las funcionalidades de los formularios template-driven (basados en el template). Sin importarlo, usar [(ngModel)] produce un error.

ngModel en solitario: de una sola vía

<!-- Actúa como una "clase CSS de forma": valida y añade clases -->
<input name="email" ngModel>

ngModel con tracking del estado del formulario

<form #miFormulario="ngForm" (ngSubmit)="enviar(miFormulario)">
  <input name="nombre" [(ngModel)]="datos.nombre" required ngModel #nombre="ngModel">
  <p *ngIf="nombre.invalid && nombre.touched">El nombre es obligatorio</p>
  <button type="submit" [disabled]="miFormulario.invalid">Enviar</button>
</form>

Pasos para usar ngModel

  • 1: Importar FormsModule en el módulo que usa el formulario
  • 2: Escribir <input [(ngModel)]="propiedad" name="campo">
  • 3: Declarar la propiedad en la clase del componente
La directiva `ngModel` requiere que el elemento tenga un atributo `name` para registrarse en el formulario y permitir su validación y envío.

Resumen

**Lo que aprendiste en esta sección:** - La interpolación {{ }} visualiza valores y expresiones de la clase en la vista - El property binding [propiedad] envía valores de la clase a atributos o componentes hijos - El event binding (evento) ejecuta métodos cuando el usuario interactúa - El two-way binding [(ngModel)] sincroniza la vista y la clase en ambos sentidos - [(ngModel)] requiere importar FormsModule y el atributo name en el input - Cada binding tiene una dirección: clase → vista, vista → clase, o ambas
