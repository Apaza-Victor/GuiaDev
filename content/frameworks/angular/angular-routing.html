8.1 RouterModule y configuración de rutas

Definición

El RouterModule es el módulo de Angular que gestiona la navegación interna de la aplicación (client-side routing). Permite mapear URLs a componentes sin recargar la página, convirtiendo la SPA en una experiencia fluida.

Configuración básica

import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { InicioComponent } from './inicio/inicio.component';
import { ContactoComponent } from './contacto/contacto.component';

const routes: Routes = [
  { path: '', component: InicioComponent },
  { path: 'contacto', component: ContactoComponent }
];

@NgModule({
  imports: [RouterModule.forRoot(routes)],
  exports: [RouterModule]
})
export class AppRoutingModule {}

Propiedades de una ruta

PropiedadDescripción
pathLa URL que se mapea (sin barra inicial)
componentEl componente que se muestra al acceder a esa ruta
childrenRutas anidadas bajo esta ruta
redirectToRedirige a otra ruta
pathMatchEstrategia de coincidencia ('full' o 'prefix')
loadChildrenCarga lazy de un módulo o componente

Ejemplo con redirección

const routes: Routes = [
  { path: '', redirectTo: '/inicio', pathMatch: 'full' },
  { path: 'inicio', component: InicioComponent },
  { path: '**', redirectTo: '/inicio' }
];
Siempre coloca la ruta comodín `**` al final de la configuración. Angular evalúa las rutas en orden y la primera coincidencia gana.

8.2 RouterLink y navegación

¿Qué es RouterLink?

RouterLink es la directiva que reemplaza al enlace <a> tradicional para navegar dentro de una SPA Angular. Evita recargas completas de página y mantiene el estado de la aplicación.

Sintaxis básica

<!-- Navegación estática -->
<a routerLink="/inicio">Inicio</a>
<a routerLink="/contacto">Contacto</a>

<!-- Navegación con array de rutas -->
<a [routerLink]="['/productos']">Productos</a>

<!-- Navegación relativa -->
<a [routerLink]="['../']">Volver al padre</a>

Resaltado de ruta activa

<a routerLink="/inicio" routerLinkActive="activo">Inicio</a>
<a routerLink="/contacto" routerLinkActive="activo">Contacto</a>

<!-- Excluir una ruta padre del resaltado -->
<a routerLink="/inicio" routerLinkActive="activo" [routerLinkActiveOptions]="{ exact: true }">
  Inicio
</a>

Navegación programática

import { Router } from '@angular/router';

@Component({ ... })
export class LoginComponent {
  constructor(private router: Router) {}

  login(): void {
    // lógica de autenticación...
    this.router.navigate(['/inicio']);
  }

  irAProducto(id: number): void {
    this.router.navigate(['/productos', id]);
  }
}
Usa `routerLink` para la navegación en templates y `router.navigate()` cuando necesitas navegar como respuesta a una lógica programática (después de un login, envío de formulario, etc.).

8.3 RouterOutlet y rutas anidadas

¿Qué es RouterOutlet?

RouterOutlet es una directiva que actúa como un placeholder en el template del componente padre: es donde Angular renderiza el componente de la ruta activa.

Sintaxis básica

<!-- app.component.html -->
<nav>
  <a routerLink="/inicio">Inicio</a>
  <a routerLink="/admin">Admin</a>
</nav>
<router-outlet></router-outlet>

Rutas anidadas con children

const routes: Routes = [
  {
    path: 'admin',
    component: AdminComponent,
    children: [
      { path: '', component: DashboardComponent },
      { path: 'usuarios', component: UsuariosComponent },
      { path: 'configuracion', component: ConfigComponent }
    ]
  }
];
<!-- admin.component.html -->
<aside>
  <a routerLink="/admin/usuarios">Usuarios</a>
  <a routerLink="/admin/configuracion">Config</a>
</aside>
<router-outlet></router-outlet>

RouterOutlet auxiliar (named outlets)

<router-outlet></router-outlet>
<router-outlet name="panel"></router-outlet>
{ path: 'noticias', component: NoticiasComponent, outlet: 'panel' }
Los named outlets permiten mostrar contenido en dos zonas de la pantalla simultáneamente. Son útiles para paneles laterales, modales o áreas de notificaciones persistentes.

8.4 Parámetros de ruta y query strings

Parámetros en la URL

Angular permite recibir parámetros dinámicos en la ruta para identificar recursos: usuarios, productos, artículos, etc.

Definición de ruta con parámetro

const routes: Routes = [
  { path: 'productos/:id', component: ProductoDetalleComponent }
];

Lectura del parámetro con ActivatedRoute

import { Component, OnInit } from '@angular/core';
import { ActivatedRoute } from '@angular/router';

@Component({
  selector: 'app-producto-detalle',
  template: '<p>Producto ID: {{ productoId }}</p>'
})
export class ProductoDetalleComponent implements OnInit {
  productoId: string = '';

  constructor(private route: ActivatedRoute) {}

  ngOnInit(): void {
    this.productoId = this.route.snapshot.paramMap.get('id') ?? '';
  }
}

Parámetros vs. Query Parameters vs. Data

TipoSintaxis URLCómo se lee
Param/productos/42route.snapshot.paramMap.get('id')
Query/productos?page=2route.snapshot.queryParamMap.get('page')
DataDefinida en la rutaroute.snapshot.data['titulo']

Navegación con query parameters

// Navegar con query params
this.router.navigate(['/productos'], {
  queryParams: { page: 2, ordenar: 'precio' }
});

// Leer en el componente
ngOnInit(): void {
  this.route.queryParamMap.subscribe(params => {
    const page = params.get('page') ?? '1';
  });
}
Usa `snapshot` cuando el componente no se reutiliza (la ruta cambia y se crea uno nuevo). Usa `subscribe` en `paramMap` o `queryParamMap` cuando el componente se reutiliza y el parámetro puede cambiar sin destruir el componente.

8.5 Rutas protegidas y guards

¿Qué es un guard?

Un guard (guardia de ruta) es un servicio que Angular ejecuta antes de permitir la activación de una ruta. Se usa para proteger rutas que requieren autenticación o autorización.

Tipos de guards

Guard¿Cuándo se ejecuta?Uso típico
canActivateAntes de activar la rutaProteger rutas privadas
canActivateChildAntes de activar una ruta hijaProteger sub-rutas
canDeactivateAntes de salir de la rutaConfirmar si hay cambios sin guardar
canMatchAntes de intentar hacer match con la rutaValidaciones previas

Ejemplo: guard funcional (Angular moderno)

// auth.guard.ts
import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';
import { AuthService } from './auth.service';

export const authGuard: CanActivateFn = (route, state) => {
  const authService = inject(AuthService);
  const router = inject(Router);

  if (authService.estaAutenticado()) {
    return true;
  }

  return router.createUrlTree(['/login'], {
    queryParams: { returnUrl: state.url }
  });
};

Uso en la configuración de rutas

const routes: Routes = [
  { path: 'login', component: LoginComponent },
  {
    path: 'admin',
    canActivate: [authGuard],
    component: AdminComponent
  }
];
Los guards funcionales (forma moderna) reemplazan a las clases con `CanActivate`. Para proyectos nuevos, usa siempre la forma funcional; para proyectos existentes, verifica qué estilo usa el proyecto.

8.6 Lazy loading de módulos

¿Qué es el lazy loading?

El lazy loading (carga perezosa) retrasa la carga de módulos o componentes hasta que el usuario navega a ellos por primera vez. Esto reduce el tamaño del bundle inicial y mejora el tiempo de carga de la aplicación.

Lazy loading con módulos (tradicional)

const routes: Routes = [
  {
    path: 'productos',
    loadChildren: () =>
      import('./productos/productos.module').then(m => m.ProductosModule)
  }
];
// productos-routing.module.ts
import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { ListaProductosComponent } from './lista/lista.component';

const routes: Routes = [
  { path: '', component: ListaProductosComponent }
];

@NgModule({
  imports: [RouterModule.forChild(routes)],
  exports: [RouterModule]
})
export class ProductosRoutingModule {}

Lazy loading de componentes standalone

const routes: Routes = [
  {
    path: 'dashboard',
    loadComponent: () =>
      import('./dashboard/dashboard.component').then(c => c.DashboardComponent)
  }
];

Impacto en el rendimiento

AspectoSin lazy loadingCon lazy loading
Bundle inicialTodo el código se carga de golpeSolo el código necesario para la ruta inicial
Tiempo de cargaMás lento en apps grandesSignificativamente más rápido
ExperienciaEspera larga al abrir la appCarga rápida, contenido bajo demanda
Aplica lazy loading a todos los módulos de funcionalidades secundarias (admin, reportes, configuración). Solo los módulos necesarios para la ruta inicial se cargan de forma eagerly.

---

Resumen

**Lo que aprendiste en esta sección:** - **RouterModule** configura las rutas de la aplicación con el array de objetos `Routes` - **RouterLink** navega sin recargar la página y **routerLinkActive** resalta la ruta activa - **RouterOutlet** es el placeholder donde Angular renderiza el componente de la ruta activa - Los **parámetros de ruta** (`:id`) y **query parameters** pasan datos a través de la URL - Los **guards** protegen rutas antes de permitir la navegación (autenticación, autorización) - El **lazy loading** retrasa la carga de módulos/componentes y mejora el rendimiento inicial
