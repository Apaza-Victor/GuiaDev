4.1 Qué es un NgModule

Definición

Un NgModule es una clase decorada con @NgModule que agrupa componentes, directivas, pipes y servicios relacionados, y define cómo se combinan para formar una funcionalidad o la aplicación completa.

ConceptoDescripción
ContenedorOrganiza el código en unidades lógicas y reutilizables
AlcancePuede agrupar una característica completa (ej. módulo de autenticación)
CompilaciónDefine qué componentes se reconocen dentro de sus templates
EstándarFue la forma clásica de Angular desde la versión 2

Por qué se usa un módulo

  • Organizar: Agrupar componentes, directivas y pipes relacionados
  • Encapsular: Controlar qué partes se exportan al resto de la app
  • Reutilizar: Importar la misma funcionalidad en varias aplicaciones
  • Lazy loading: Cargar módulos completos solo cuando se necesitan
En la práctica, un NgModule es una pieza de la aplicación: una feature (productos, carrito, login) o el propio AppModule raíz.

---

4.2 El decorador @NgModule

Sintaxis básica

import { NgModule } from '@angular/core';
import { CommonModule } from '@angular/common';
import { LoginComponent } from './login/login.component';

@NgModule({
  declarations: [LoginComponent],
  imports: [CommonModule],
  exports: [LoginComponent],
  providers: []
})
export class LoginModule {}

Propiedades del decorador

PropiedadDescripción
declarationsComponentes, directivas y pipes que pertenecen al módulo
importsOtros módulos cuyas declaraciones y exports se necesitan
exportsQué declaraciones se hacen visibles para otros módulos
providersServicios disponibles para toda la aplicación o el módulo
bootstrapEl componente raíz que se inicia (solo en AppModule)
Un componente, directiva o pipe solo puede pertenecer a un NgModule. Declararlo en dos módulos produce un error de compilación.

---

4.3 Declarations, imports y exports

Declarations

En declarations se listan todos los componentes, directivas y pipes que pertenecen a este módulo. Angular los compila dentro del contexto del módulo.

@NgModule({
  declarations: [
    ProductosComponent,   // componente declarado
    CardDirective,        // directiva declarada
    PrecioPipe            // pipe declarado
  ]
})
export class ProductosModule {}

Imports

En imports se incluyen otros módulos que exportan funcionalidades que este módulo necesita. Al importar CommonModule obtienes ngIf, ngFor, etc.

@NgModule({
  declarations: [ProductosComponent],
  imports: [
    CommonModule,          // directivas de Angular
    FormsModule,           // formularios template-driven
    RouterModule           // directivas de routing
  ]
})
export class ProductosModule {}

Exports

Con exports decides qué piezas declaradas en este módulo serán visibles para otros módulos que lo importen.

@NgModule({
  declarations: [MiBotonComponent],
  exports: [MiBotonComponent]  // ahora es usable fuera de este módulo
})
export class UiModule {}
BloqueQué contiene¿Visible fuera?
declarationsComponentes, directivas y pipes propiosNo
importsMódulos externos necesariosNo
exportsDeclaraciones que se compartenSí

4.4 Providers y bootstrap

Providers

La propiedad providers registra servicios en el inyector. Según el módulo donde se registren, estarán disponibles a nivel de aplicación o de módulo con lazy loading.

import { NgModule } from '@angular/core';
import { ApiService } from './api.service';

@NgModule({
  providers: [ApiService]  // se inyectará donde se solicite
})
export class CoreModule {}

Bootstrap

La propiedad bootstrap solo está presente en el módulo raíz y define el componente que se instancia al arrancar la aplicación. Por convención es AppComponent.

import { NgModule } from '@angular/core';
import { AppComponent } from './app.component';

@NgModule({
  declarations: [AppComponent],
  imports: [],
  providers: [],
  bootstrap: [AppComponent]  // componente de arranque
})
export class AppModule {}

Cómo arranca una app Angular

// main.ts - Punto de entrada
import { platformBrowserDynamic } from '@angular/platform-browser-dynamic';
import { AppModule } from './app/app.module';

platformBrowserDynamic()
  .bootstrapModule(AppModule)
  .catch((err) => console.error(err));
La CLI genera main.ts, AppModule y AppComponent automáticamente cuando ejecutas ng new.

4.5 AppModule: el módulo raíz

¿Qué es AppModule?

AppModule es el módulo raíz de toda aplicación Angular creada con la CLI. Es el encargado de declarar los componentes iniciales, importar los módulos globales y arrancar la app.

Estructura típica generada por la CLI

import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { FormsModule } from '@angular/forms';
import { HttpClientModule } from '@angular/common/http';

import { AppComponent } from './app.component';
import { AppRoutingModule } from './app-routing.module';

@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule, AppRoutingModule, FormsModule, HttpClientModule],
  providers: [],
  bootstrap: [AppComponent]
})
export class AppModule {}

Módulos que suele importar

MóduloProporciona
BrowserModuleFuncionalidades para aplicaciones en el navegador
AppRoutingModuleLa configuración del router
FormsModulengModel y formularios template-driven
HttpClientModulePeticiones HTTP
ReactiveFormsModuleFormularios reactivos
En las aplicaciones standalone (más modernas) el AppModule desaparece y el bootstrap se hace directamente con bootstrapApplication(AppComponent).

4.6 Módulos vs. standalone components

¿Qué son los standalone components?

Desde Angular 14+ existen los standalone components: componentes que no necesitan pertenecer a ningún NgModule. Se marcan con la propiedad standalone: true e importan directamente sus dependencias.

Comparativa

AspectoCon NgModuleStandalone
DependenciasSe declaran imports del móduloSe importan en el propio decorador
ConfiguraciónMás archivos y boilerplateMenos código repetitivo
Lazy loadingSe cargan módulos completosSe cargan rutas/componentes sueltos
Curva de aprendizajeMás conceptosMás simple
TendenciaLegado/establecidoRecomendado en Angular moderno

Componente standalone

import { Component } from '@angular/core';
import { CommonModule } from '@angular/common';
import { NavbarComponent } from '../navbar/navbar.component';

@Component({
  selector: 'app-pagina',
  standalone: true,                 // no requiere NgModule
  imports: [CommonModule, NavbarComponent],  // deps directas
  templateUrl: './pagina.component.html'
})
export class PaginaComponent {}
Entender los NgModules es clave porque encontrarás miles de proyectos y documentación que los usan. Para proyectos nuevos, la comunidad recomienda empezar con standalone.

---

Resumen

**Lo que aprendiste en esta sección:** - Un **NgModule** agrupa componentes, directivas, pipes y servicios en unidades lógicas - declarations lista las piezas propias; imports trae módulos externos; exports comparte piezas - providers registra servicios y bootstrap define el componente raíz - **AppModule** es el módulo raíz que arranca la aplicación desde main.ts - Angular moderno ofrece **standalone components** que no requieren módulos - Un elemento solo puede declararse en un módulo
