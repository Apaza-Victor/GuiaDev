9.1 HttpClient: configuración

¿Qué es HttpClient?

HttpClient es el servicio oficial de Angular para realizar peticiones HTTP (GET, POST, PUT, DELETE, etc.) a APIs REST o cualquier servidor. Está basado en RxJS y devuelve observables.

Importación y configuración

import { NgModule } from '@angular/core';
import { HttpClientModule } from '@angular/common/http';

@NgModule({
  imports: [
    HttpClientModule  // habilita HttpClient en toda la aplicación
  ]
})
export class AppModule {}

Uso con standalone components

import { bootstrapApplication } from '@angular/platform-browser';
import { provideHttpClient } from '@angular/common/http';
import { AppComponent } from './app/app.component';

bootstrapApplication(AppComponent, {
  providers: [
    provideHttpClient()
  ]
});

Inyección en un servicio

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class ProductoService {
  private apiUrl = 'https://api.ejemplo.com/productos';

  constructor(private http: HttpClient) {}

  obtenerTodos(): Observable<any[]> {
    return this.http.get<any[]>(this.apiUrl);
  }
}
Configura HttpClient una sola vez en el módulo raíz o en los providers de bootstrap. Una vez habilitado, está disponible para inyectar en cualquier servicio o componente.

9.2 Peticiones GET, POST, PUT, DELETE

Operaciones CRUD con HttpClient

Método HTTPHttpClientUso típico
GEThttp.get<T>(url)Obtener datos
POSThttp.post<T>(url, body)Crear un recurso
PUThttp.put<T>(url, body)Actualizar un recurso completo
PATCHhttp.patch<T>(url, body)Actualizar parcialmente
DELETEhttp.delete<T>(url)Eliminar un recurso

Ejemplo completo: servicio de productos

import { Injectable } from '@angular/core';
import { HttpClient, HttpHeaders } from '@angular/common/http';
import { Observable } from 'rxjs';

export interface Producto {
  id: number;
  nombre: string;
  precio: number;
}

@Injectable({ providedIn: 'root' })
export class ProductoService {
  private apiUrl = 'https://api.ejemplo.com/productos';

  constructor(private http: HttpClient) {}

  // GET: obtener todos
  listar(): Observable<Producto[]> {
    return this.http.get<Producto[]>(this.apiUrl);
  }

  // GET: obtener uno por ID
  obtenerPorId(id: number): Observable<Producto> {
    return this.http.get<Producto>(`${this.apiUrl}/${id}`);
  }

  // POST: crear
  crear(producto: Producto): Observable<Producto> {
    return this.http.post<Producto>(this.apiUrl, producto);
  }

  // PUT: actualizar
  actualizar(id: number, producto: Producto): Observable<Producto> {
    return this.http.put<Producto>(`${this.apiUrl}/${id}`, producto);
  }

  // DELETE: eliminar
  eliminar(id: number): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/${id}`);
  }
}

Uso en un componente

export class ProductosComponent implements OnInit {
  productos: Producto[] = [];

  constructor(private productoService: ProductoService) {}

  ngOnInit(): void {
    this.productoService.listar().subscribe({
      next: (data) => this.productos = data,
      error: (err) => console.error('Error al cargar productos', err)
    });
  }
}
Siempre suscríbete a los observables que devuelve HttpClient. Si no te suscribes, la petición HTTP no se ejecutá nunca (los observables son "cold" por defecto).

9.3 Manejo de errores e interceptores

Manejo de errores con catchError

Las peticiones HTTP pueden fallar por muchos motivos: red, servidor, datos inválidos. Angular proporciona el operador catchError de RxJS para manejar errores de forma elegante.

import { catchError, throwError } from 'rxjs';

obtenerPorId(id: number): Observable<Producto> {
  return this.http.get<Producto>(`${this.apiUrl}/${id}`).pipe(
    catchError(error => {
      console.error('Error obteniendo producto:', error);
      return throwError(() => new Error('No se pudo cargar el producto'));
    })
  );
}

¿Qué son los interceptores?

Un interceptor es un servicio que puede capturar, modificar o reenviar todas las peticiones HTTP salientes y las respuestas entrantes, antes de que lleguen al componente o servicio.

Ejemplo: interceptor de autenticación

import { Injectable } from '@angular/core';
import {
  HttpInterceptor, HttpRequest, HttpHandler, HttpEvent
} from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable()
export class AuthInterceptor implements HttpInterceptor {
  intercept(
    req: HttpRequest<any>,
    next: HttpHandler
  ): Observable<HttpEvent<any>> {
    const token = localStorage.getItem('token');

    if (token) {
      const authReq = req.clone({
        setHeaders: { Authorization: `Bearer ${token}` }
      });
      return next.handle(authReq);
    }

    return next.handle(req);
  }
}

Registro del interceptor

import { HTTP_INTERCEPTORS } from '@angular/common/http';
import { AuthInterceptor } from './auth.interceptor';

@NgModule({
  providers: [
    { provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }
  ]
})
export class AppModule {}
Los interceptores son ideales para añadir tokens de autenticación, registrar logs, mostrar spinners globales de carga o manejar errores 401/403 de forma centralizada.

9.4 Formularios template-driven

¿Qué son los formularios template-driven?

En los formularios template-driven, la lógica del formulario se define mayoritariamente en el template HTML usando directivas como ngModel y ngForm. Son ideales para formularios simples.

Configuración: importar FormsModule

import { FormsModule } from '@angular/forms';

@NgModule({
  imports: [FormsModule]
})
export class AppModule {}

Ejemplo completo

import { Component } from '@angular/core';

@Component({
  selector: 'app-contacto',
  templateUrl: './contacto.component.html'
})
export class ContactoComponent {
  contacto = {
    nombre: '',
    email: '',
    mensaje: ''
  };

  enviar(): void {
    console.log('Datos enviados:', this.contacto);
  }
}
<form #contactoForm="ngForm" (ngSubmit)="enviar(contactoForm)">
  <label>Nombre:
    <input name="nombre" [(ngModel)]="contacto.nombre" required minlength="3" #nombre="ngModel">
  </label>
  <div *ngIf="nombre.invalid && nombre.touched">
    <p>El nombre es obligatorio (mínimo 3 caracteres)</p>
  </div>

  <label>Email:
    <input name="email" [(ngModel)]="contacto.email" required email #email="ngModel">
  </label>
  <div *ngIf="email.invalid && email.touched">
    <p>Introduce un email válido</p>
  </div>

  <label>Mensaje:
    <textarea name="mensaje" [(ngModel)]="contacto.mensaje" required></textarea>
  </label>

  <button type="submit" [disabled]="contactoForm.invalid">Enviar</button>
</form>

Clases CSS de estado del formulario

ClaseQué indica
ng-pristineEl usuario no ha modificado el campo
ng-dirtyEl usuario ha modificado el campo
ng-validEl campo cumple todas las validaciones
ng-invalidEl campo no cumple alguna validación

Los formularios template-driven son perfectos para formularios simples (login, contacto). Para formularios complejos con validaciones dinámicas, considera los formularios reactivos.

9.5 Formularios reactivos

¿Qué son los formularios reactivos?

Los formularios reactivos (basados en código) definen la estructura y validación del formulario en la clase TypeScript usando FormControl, FormGroup y FormBuilder. Son más potentes, testeables y escalables.

Configuración: importar ReactiveFormsModule

import { ReactiveFormsModule } from '@angular/forms';

@NgModule({
  imports: [ReactiveFormsModule]
})
export class AppModule {}

Ejemplo: formulario de registro

import { Component, OnInit } from '@angular/core';
import { FormBuilder, FormGroup, Validators } from '@angular/forms';

@Component({
  selector: 'app-registro',
  templateUrl: './registro.component.html'
})
export class RegistroComponent implements OnInit {
  registroForm!: FormGroup;

  constructor(private fb: FormBuilder) {}

  ngOnInit(): void {
    this.registroForm = this.fb.group({
      nombre: ['', [Validators.required, Validators.minLength(3)]],
      email: ['', [Validators.required, Validators.email]],
      password: ['', [Validators.required, Validators.minLength(6)]],
      confirmarPassword: ['', Validators.required]
    });
  }

  get f() { return this.registroForm.controls; }

  enviar(): void {
    if (this.registroForm.valid) {
      console.log(this.registroForm.value);
    }
  }
}

Template del formulario reactivo

<form [formGroup]="registroForm" (ngSubmit)="enviar()">
  <input formControlName="nombre" placeholder="Nombre">
  <div *ngIf="f['nombre'].invalid && f['nombre'].touched">
    <p>El nombre es obligatorio (mín. 3 caracteres)</p>
  </div>

  <input formControlName="email" placeholder="Email">
  <div *ngIf="f['email'].invalid && f['email'].touched">
    <p>Introduce un email válido</p>
  </div>

  <input formControlName="password" type="password" placeholder="Contraseña">
  <input formControlName="confirmarPassword" type="password" placeholder="Confirmar">

  <button type="submit" [disabled]="registroForm.invalid">Registrarse</button>
</form>
Los formularios reactivos son la opción recomendada para formularios complejos. Permiten validaciones asíncronas, validadores personalizados y un control total sobre el estado del formulario desde la clase.

Validador personalizado (reactivos)

import { AbstractControl, ValidationErrors, ValidatorFn } from '@angular/forms';

export function passwordsIguales(
  password: string, confirmar: string
): ValidatorFn {
  return (group: AbstractControl): ValidationErrors | null => {
    const pass = group.get(password);
    const conf = group.get(confirmar);

    if (pass && conf && pass.value !== conf.value) {
      conf.setErrors({ passwordsNoCoinciden: true });
      return { passwordsNoCoinciden: true };
    }
    return null;
  };
}

Envío de datos a la API

export class RegistroComponent implements OnInit {
  registroForm!: FormGroup;

  constructor(
    private fb: FormBuilder,
    private http: HttpClient
  ) {}

  ngOnInit(): void {
    this.registroForm = this.fb.group({
      nombre: ['', Validators.required],
      email: ['', [Validators.required, Validators.email]],
      password: ['', [Validators.required, Validators.minLength(6)]]
    });
  }

  enviar(): void {
    if (this.registroForm.valid) {
      this.http.post('/api/usuarios', this.registroForm.value).subscribe({
        next: () => console.log('Registro exitoso'),
        error: (err) => console.error('Error:', err)
      });
    }
  }
}

Diferencias clave: template-driven vs. reactivo

AspectoTemplate-drivenReactivo
DefiniciónEn el template HTMLEn la clase TypeScript
Complejidad idealFormularios simplesFormularios complejos
TesteabilidadDifícil (depende del DOM)Fácil (se puede probar sin renderizar)
Validaciones dinámicasLímiteTotal control
Para formularios nuevos, usa formularios reactivos: son más explícitos, testeables y escalables. Los template-driven solo son prácticos para casos muy sencillos.

Resumen

**Lo que aprendiste en esta sección:** - **HttpClient** se configura una vez y permite realizar peticiones GET, POST, PUT y DELETE a APIs REST - Las peticiones HTTP devuelven **observables** y se consumen con `subscribe()` - Los **interceptores** modifican o registran todas las peticiones de forma centralizada - Los formularios **template-driven** usan `ngModel` y `ngForm` en el template; son ideales para casos simples - Los formularios **reactivos** usan `FormGroup`, `FormControl` y `FormBuilder` en la clase; son más potentes - Ambos tipos de formulario integran **validaciones** de Angular y permiten validadores personalizados
