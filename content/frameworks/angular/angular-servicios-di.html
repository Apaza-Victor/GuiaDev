7.1 Qué es un servicio

Definición

Un servicio es una clase TypeScript reutilizable que encapsula lógica de negocio o funcionalidad compartida: consumo de APIs, cálculo, almacenamiento, autenticación, logs, etc. Los componentes se encargan de la vista; los servicios, de los datos y las operaciones.

Ventajas de usar servicios

  • Reutilización: la misma lógica se comparte entre varios componentes
  • Separación de responsabilidades: componentes más ligeros y legibles
  • Testeabilidad: la lógica se prueba de forma aislada
  • Estado centralizado: se pueden compartir datos entre componentes sin prop-drilling

Creación con el CLI

ng generate service productoServicio
# abreviado
ng g s productoServicio

Ejemplo básico de servicio

// productov.servicio.ts (simplificado)
import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'
})
export class CalculadoraService {
  sumar(a: number, b: number): number {
    return a + b;
  }
}

7.2 El decorador @Injectable

Definición

El decorador @Injectable marca una clase como inyectable: el sistema de inyección de dependencias de Angular puede crearla y administrarla. Es el decorador que acompaña a todos los servicios.

Sintaxis

import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'
})
export class UsuarioService {
  private usuarios: string[] = [];

  listar(): string[] {
    return [...this.usuarios];
  }

  agregar(usuario: string): void {
    this.usuarios.push(usuario);
  }
}

Opciones del decorador

OpciónDescripción
providedIn: 'root'El servicio es singleton global; se crea una sola vez en la app
providedIn: UsuarioModuleSolo disponible dentro de ese NgModule
providedIn: 'platform' / 'any'Ámbitos alternativos de singleton (plataforma) o nueva instancia por inyector
`providedIn: 'root'` permite que el servicio esté disponible sin tener que registrarlo manualmente en ningún módulo: se importa y se inyecta directamente.

7.3 Inyección de dependencias

Definición

La inyección de dependencias (DI) es un patrón en el que Angular proporciona automáticamente las instancias que una clase necesita, en lugar de que la clase las cree o las busque por sí misma.

Formas de inyección

// 1) Inyección por constructor (la más común)
export class ListaComponente {
  constructor(private usuarioService: UsuarioService) {}
}

// 2) Inyección con inject() en campos (Angular moderno)
import { inject } from '@angular/core';

export class ListaComponente {
  private usuarioService = inject(UsuarioService);
}

Beneficios del patrón DI

  • Desacoplamiento: los componentes no crean sus dependencias
  • Testeabilidad: es fácil pasar mocks o falsos en las pruebas
  • Singleton automático: Angular reutiliza la misma instancia cuando procede

Inyección con tokens alternativos

import { Injectable, InjectionToken, inject } from '@angular/core';

export const API_URL = new InjectionToken<string>('api.url');

@Injectable({ providedIn: 'root' })
export class DatosService {
  private apiUrl = inject(API_URL);
}

7.4 Providers: dónde se registran

Definición

Un provider es el registro que le dice a Angular cómo crear una dependencia y en qué ámbito estará disponible. Existen varios niveles de registro.

Niveles de registro

NivelCómo se registraAlcance
Raíz (root)providedIn: 'root' en @InjectableToda la aplicación (singleton)
MóduloArreglo providers en @NgModuleTodos los componentes del módulo
ComponenteArreglo providers en @ComponentEl componente y sus hijos (nueva instancia)

Ejemplo de provider a nivel de componente

import { Component } from '@angular/core';
import { UsuarioService } from './usuario.service';

@Component({
  selector: 'app-lista',
  templateUrl: './lista.component.html',
  providers: [UsuarioService] // instancia dedicada a este componente
})
export class ListaComponent {
  constructor(private usuarioService: UsuarioService) {}
}

Puntos a recordar

  • providedIn: 'root' es la opción por defecto y recomendada para la mayoría de servicios
  • Registrar a nivel de componente crea una nueva instancia por cada ocurrencia del componente
  • El nivel de módulo es útil para servicios de funcionalidades con lazy loading
Si dos componentes se registran su propio `providers` del mismo servicio, cada uno tendrá una instancia distinta y no compartirán estado.

7.5 Uso de servicios en componentes

Inyección y consumo

Una vez registrado, el servicio se inyecta en el constructor (o con inject()) y sus métodos se llaman desde el componente.

Ejemplo completo

// tarea.service.ts
import { Injectable } from '@angular/core';

export interface Tarea { id: number; titulo: string; }

@Injectable({ providedIn: 'root' })
export class TareaService {
  private tareas: Tarea[] = [];
  private siguienteId = 1;

  listar(): Tarea[] {
    return [...this.tareas];
  }

  agregar(titulo: string): void {
    this.tareas.push({ id: this.siguienteId++, titulo });
  }

  eliminar(id: number): void {
    this.tareas = this.tareas.filter(t => t.id !== id);
  }
}
// app.component.ts
import { Component, OnInit } from '@angular/core';
import { TareaService, Tarea } from './tarea.service';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent implements OnInit {
  tareas: Tarea[] = [];
  nuevaTarea = '';

  constructor(private tareaService: TareaService) {}

  ngOnInit(): void {
    this.tareas = this.tareaService.listar();
  }

  crear(): void {
    if (!this.nuevaTarea.trim()) return;
    this.tareaService.agregar(this.nuevaTarea);
    this.tareas = this.tareaService.listar();
    this.nuevaTarea = '';
  }
}
<input [(ngModel)]="nuevaTarea" placeholder="Nueva tarea">
<button (click)="crear()">Añadir</button>
<ul>
  <li *ngFor="let tarea of tareas">{{ tarea.titulo }}</li>
</ul>

7.6 Compartir datos entre componentes

Por qué los servicios para compartir estado

Para comunicar datos entre componentes que no tienen relación directa (padre-hijo), los servicios con estado singleton son la solución natural: varios componentes leen y escriben en la misma instancia del servicio.

Con BehaviorSubject para notificar cambios

import { Injectable } from '@angular/core';
import { BehaviorSubject } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class CarritoService {
  private totalSubject = new BehaviorSubject<number>(0);
  total$ = this.totalSubject.asObservable();

  actualizarTotal(nuevaCantidad: number): void {
    this.totalSubject.next(nuevaCantidad);
  }
}

Componentes que lo consumen

// header.component.ts
import { Component, OnInit } from '@angular/core';
import { CarritoService } from './carrito.service';

@Component({
  selector: 'app-header',
  template: '<p>Total carrito: {{ total }}</p>'
})
export class HeaderComponent implements OnInit {
  total = 0;

  constructor(private carritoService: CarritoService) {}

  ngOnInit(): void {
    this.carritoService.total$.subscribe(t => this.total = t);
  }
}
// producto.component.ts
import { Component } from '@angular/core';
import { CarritoService } from './carrito.service';

@Component({
  selector: 'app-producto',
  template: '<button (click)="comprar()">Comprar</button>'
})
export class ProductoComponent {
  constructor(private carritoService: CarritoService) {}

  comprar(): void {
    this.carritoService.actualizarTotal(this.carritoService.total$ ? 1 : 1);
  }
}
`BehaviorSubject` siempre entrega el último valor a los nuevos suscriptores, por lo que los componentes que se montan tarde reciben el estado actual sin problemas.

Resumen

**Lo que aprendiste en esta sección:** - Un servicio encapsula lógica de negocio y datos compartidos fuera de los componentes - @Injectable marca la clase como inyectable; providedIn: 'root' crea un singleton global - La inyección de dependencias entrega automáticamente las instancias necesarias - Los providers definen el ámbito: raíz, módulo o componente - Los componentes inyectan servicios en el constructor o con inject() y llaman a sus métodos - Los servicios singleton permiten compartir datos entre componentes, por ejemplo con BehaviorSubject
