6.1 Estado global con useState

Qué es useState

useState es un composable de Nuxt para crear estado global con capacidad de simulación de servidor. Esto significa que el mismo estado se comparte entre servidor y cliente sin perder sincronización, algo clave con SSR.

Ejemplo: Contador global

<!-- composables/useContadorGlobal.ts -->
export function useContadorGlobal() {
  const contador = useState('contador-global', () => 0)
  const incrementar = () => contador.value++
  return { contador, incrementar }
}

<!-- Cualquier componente -->
<script setup>
const { contador, incrementar } = useContadorGlobal()
</script>

Cómo funciona

  • useState necesita una clave única para identificar el estado
  • El valor inicial solo se establece la primera vez
  • Con SSR, el estado se serializa y se reenvía al cliente

Diferencias con ref

CaracterísticauseStateref
CompartidoSí, de forma globalNo, solo local
SSR friendlySí, se sincronizaNo, se pierde en el servidor
Requiere claveSíNo

6.2 Introducción a Pinia en Nuxt

Qué es Pinia

Pinia es la librería de gestión de estado recomendada para Vue 3 y Nuxt. Ofrece una API basada en la Composition API con stores tipadas y reactivas. En Nuxt se instala como un módulo con soporte SSR integrado.

Cómo funciona un store

Un store es un contenedor de estado y acciones relacionadas. Se define con la función defineStore y se usa en cualquier componente.

// stores/contador.ts
export const useContadorStore = defineStore('contador', {
  state: () => ({ valor: 0 }),
  getters: {
    doble: (state) => state.valor * 2
  },
  actions: {
    incrementar() {
      this.valor++
    }
  }
})

Ventajas de Pinia frente a useState

  • Organización más clara con stores dedicados
  • Soporte para DevTools y time-travel debugging
  • Getters y actions bien definidos
  • Módulo oficial de Nuxt con SSR automático

6.3 Plugins en Nuxt

Qué son los plugins

Los plugins son pequeños módulos que se ejecutan cuando la aplicación se inicia. Sirven para registrar librerías externas, inyectar funcionalidades o ejecutar código de inicialización. Se guardan en app/plugins/.

Crear un plugin sencillo

<!-- app/plugins/cambios.js -->
export default defineNuxtPlugin(() => {
  console.log('La aplicación Nuxt ha iniciado')
})

Inyectar una variable global

// app/plugins/helpers.ts
export default defineNuxtPlugin((nuxtApp) => {
  return {
    provide: {
      formatoMoneda: (valor) => `$${valor.toFixed(2)}`
    }
  }
})

// Uso en cualquier parte:
// const { $formatoMoneda } = useNuxtApp()

Tipos de plugins

TipoEjecución
ClienteNombre con sufijo .client.ts
ServidorNombre con sufijo .server.ts
AmbosSin sufijo, se ejecuta en los dos

6.4 Middleware de navegación

Qué es el middleware de navegación

Los middlewares de Nuxt son funciones que se ejecutan antes de renderizar una página. Son ideales para proteger rutas, redirigir usuarios o validar condiciones. Se guardan en app/middleware/.

Ejemplo: Proteger rutas privadas

// app/middleware/auth.ts
export default defineNuxtRouteMiddleware((to, from) => {
  const sesion = useState('sesion', () => null)

  if (!sesion.value) {
    // Redirigir al login si no hay sesión
    return navigateTo('/login')
  }
})

Aplicar el middleware a una página

<!-- pages/perfil.vue -->
<script setup>
definePageMeta({
  middleware: 'auth'
})
</script>

Middleware inline

También puedes definir un middleware directamente en la definición de la página:

<script setup>
definePageMeta({
  middleware: [function (to, from) {
    // lógica de validación
  }]
})
</script>
Usa navigateTo para redirigir y abortNavigation para cancelar la navegación a una ruta.

6.5 Composables personalizados

Qué son los composables

Los composables son funciones que encapsulan lógica reutilizable usando la Composition API. En Nuxt, los que se colocan en app/composables/ se auto-importan automáticamente.

Ejemplo: Composable de formato de fecha

// app/composables/useFormatoFecha.ts
export function useFormatoFecha() {
  const formatear = (fecha) => {
    return new Intl.DateTimeFormat('es', {
      day: '2-digit', month: 'long', year: 'numeric'
    }).format(new Date(fecha))
  }

  return { formatear }
}

Usar el composable sin importar

<script setup>
const { formatear } = useFormatoFecha()
const hoy = formatear(new Date()) // "30 de agosto de 2026"
</script>

Buenas prácticas

  • Nómbralos con el prefijo use
  • Mantén una única responsabilidad por composable
  • Devuelve un objeto explícito con los valores y funciones
  • Combínalos con useState para lógica global compartida

6.6 Resumen de estado y ciclo de vida

Qué herramienta usar

NecesidadHerramienta
Estado local de un componenteref o reactive
Estado global simple con SSRuseState
Estado global complejo con getters y actionsPinia
Lógica reutilizableComposables en app/composables/
Inicialización o librerías externasPlugins en app/plugins/
Protección de rutasMiddleware en app/middleware/

Flujo típico de una petición

Petición
  -> Middleware (validación de ruta)
  -> Plugins (inicialización)
  -> Carga de datos con useAsyncData/useFetch
  -> Renderizado del layout y la página
  -> Estado compartido con useState/Pinia
  -> Hidratación en el cliente

Resumen

**Lo que aprendiste en esta sección:** - useState crea estado global con soporte SSR y una clave única - Pinia es el store recomendado para estado global complejo - Los plugins inicializan la app y registran librerías - El middleware protege y valida el acceso a las rutas - Los composables en app/composables/ se auto-importan - Cada herramienta (estado, plugins, middleware) tiene su propósito
