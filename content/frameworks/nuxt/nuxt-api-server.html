8.1 El servidor Nitro

Qué es Nitro

Nitro es el motor de servidor de Nuxt. Ofrece un backend completo integrado: puedes crear tus propios endpoints de API y middleware directamente en tu proyecto Nuxt, sin levantar un servidor aparte.

Ventajas de Nitro

  • Crea una API REST junto a tu frontend
  • Despliegue universal: Node, serverless y edge
  • Variables de entorno y configuración de runtime
  • Caché y almacenamiento integrados
  • Compatibilidad con rutas de archivo y middleware

Estructura del servidor

server/
├── api/          # Endpoints REST (routes /api/*)
├── routes/       # Rutas personalizadas del servidor
└── middleware/   # Middleware de servidor

Ejemplo: Endpoint raíz de la API

<!-- server/api/index.ts -->
export default defineEventHandler((event) => {
  return { mensaje: 'API de Nuxt funcionando' }
})

8.2 Server API endpoints HTTP

Crear endpoints REST

Los archivos dentro de server/api/ se convierten en rutas accesibles bajo /api/. El nombre del archivo determina la ruta y el método HTTP la operación.

Ejemplo: CRUD de usuarios

<!-- server/api/usuarios.get.ts -> GET /api/usuarios -->
export default defineEventHandler(() => {
  return [
    { id: 1, nombre: 'Ana' },
    { id: 2, nombre: 'Carlos' }
  ]
})

<!-- server/api/usuarios.post.ts -> POST /api/usuarios -->
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  return { id: 3, ...body }
})

Sufijos de método

ArchivoMétodo HTTP
usuarios.get.tsGET
usuarios.post.tsPOST
usuarios.put.tsPUT
usuarios.delete.tsDELETE
usuarios.patch.tsPATCH
Si el archivo no tiene sufijo de método, responde a todos los métodos HTTP.

8.3 Rutas y parámetros dinámicos en server

Parámetros en las rutas del servidor

Al igual que en pages/, puedes usar corchetes para crear rutas dinámicas en server/api/. Se accede a los parámetros con getRouterParam.

Ejemplo: Obtener un usuario por id

<!-- server/api/usuarios/[id].get.ts -> GET /api/usuarios/5 -->
export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')
  return { id, nombre: `Usuario ${id}` }
})

Server routes fuera de /api

Los archivos en server/routes/ se sirven fuera del prefijo /api, para páginas o endpoints accesibles en rutas directas.

<!-- server/routes/test.ts -> /test -->
export default defineEventHandler(() => {
  return { ruta: 'personalizada' }
})

Helpers útiles de event

FunciónPropósito
getQuery(event)Obtener los parámetros de consulta
readBody(event)Leer el cuerpo de la petición
getRouterParam(event, 'x')Leer un parámetro de ruta
getCookie(event, 'x')Leer una cookie

8.4 Consumir la API con $fetch

El helper global $fetch

$fetch es un cliente HTTP disponible globalmente en Nuxt. Es ideal para consumir tus propios endpoints del servidor y APIs externas, con soporte para SSR.

Ejemplo: Obtener usuarios en una página

<!-- pages/usuarios.vue -->
<script setup>
// Llamada a tu propia API (se ejecuta en el servidor con SSR)
const { data: usuarios } = await useFetch('/api/usuarios')
</script>

Otras operaciones con $fetch

<!-- Crear usuario -->
const nuevo = await $fetch('/api/usuarios', {
  method: 'POST',
  body: { nombre: 'Nuevo usuario' }
})

<!-- Actualizar usuario -->
await $fetch('/api/usuarios/5', {
  method: 'PUT',
  body: { nombre: 'Actualizado' }
})

<!-- Eliminar usuario -->
await $fetch('/api/usuarios/5', { method: 'DELETE' })

Ventajas de $fetch

  • Funciona igual en servidor y cliente
  • Se integra bien con useFetch y useAsyncData
  • Devuelve el JSON parseado automáticamente
  • Soporta interceptores y configuración global

8.5 Manejar errores en la API

Errores del servidor

Para devolver errores desde un endpoint se usa createError. Esto permite enviar códigos de estado y mensajes claros al cliente.

Ejemplo: Validación en el servidor

<!-- server/api/usuarios/[id].get.ts -->
export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')

  if (id === 'no-existe') {
    throw createError({
      statusCode: 404,
      statusMessage: 'Usuario no encontrado'
    })
  }

  return { id, nombre: `Usuario ${id}` }
})

Capturar errores en el cliente

<script setup>
const { data, error } = await useFetch('/api/usuarios/no-existe')

if (error.value) {
  console.log(error.value.statusCode) // 404
  console.log(error.value.message)
}
</script>

Zod para validar los datos recibidos

Un patrón habitual es validar el body con una librería como Zod antes de procesarlo:

<!-- server/api/usuarios.post.ts -->
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  if (!body?.nombre || body.nombre.length < 2) {
    throw createError({
      statusCode: 400,
      statusMessage: 'El nombre es obligatorio'
    })
  }

  return { id: Date.now(), ...body }
})

8.6 Middleware de servidor y buenas prácticas

Middleware de servidor

Los archivos en server/middleware/ se ejecutan en cada petición antes de llegar a los endpoints. Son útiles para añadir cabeceras, validar autenticación o registrar peticiones.

<!-- server/middleware/log.ts -->
export default defineEventHandler((event) => {
  const ruta = getRequestURL(event).pathname
  console.log(`[${new Date().toISOString()}] ${ruta}`)
})

Buenas prácticas

  • Valida siempre los datos de entrada en el servidor
  • Devolver códigos de estado HTTP correctos
  • No exponer datos sensibles en las respuestas
  • Organiza los endpoints por recurso en archivos separados
  • Usa middleware para tareas globales como auth y logging

Ejemplo: Proteger un endpoint con clave API

<!-- server/middleware/auth.ts -->
export default defineEventHandler((event) => {
  const clave = getHeader(event, 'x-api-key')

  if (clave !== process.env.API_KEY) {
    throw createError({
      statusCode: 401,
      statusMessage: 'No autorizado'
    })
  }
})

Resumen

**Lo que aprendiste en esta sección:** - Nitro es el motor de servidor integrado de Nuxt - Tienes endpoint own en server/api/* y rutas personalizadas en server/routes/ - Los sufijos de archivo determinan el método HTTP - Los parámetros dinámicos se leen con getRouterParam - $fetch y useFetch consumen tus endpoints con soporte SSR - createError y el middleware de servidor gestionan errores y seguridad - Valida siempre los datos de entrada en el servidor
