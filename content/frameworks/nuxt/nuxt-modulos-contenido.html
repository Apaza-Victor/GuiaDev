9.1 El ecosistema de módulos

Qué son los módulos

Los módulos son paquetes que extienden Nuxt añadiendo funcionalidades: integraciones de CSS, autenticación, contenido, SEO y mucho más. Se instalan vía npm y se registran en nuxt.config.ts.

Módulos populares

MóduloFinalidad
@pinia/nuxtIntegración de Pinia para estado global
@nuxt/contentManejar contenido basado en archivos
@nuxtjs/tailwindcssSoporte de Tailwind CSS
@nuxtjs/seoHerramientas de SEO (sitemap, robots)
@nuxt/imageOptimización de imágenes

Instalar un módulo

npm install @nuxtjs/tailwindcss
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@pinia/nuxt', '@nuxtjs/tailwindcss', '@nuxt/content']
})
Los módulos suelen venir con su propia configuración y opciones para personalizarlos.

9.2 Content con archivos Markdown

Qué es @nuxt/content

El módulo @nuxt/content permite crear contenido basado en archivos (Markdown, JSON, YAML) y mostrarlo de forma reactiva en tu aplicación. Es ideal para blogs, documentación y páginas de contenido.

Estructura del contenido

content/
├── index.md
└── blog/
    ├── primer-post.md
    └── segundo-post.md

Ejemplo: Un archivo Markdown

---
title: Primer post del blog
description: Mi primera publicación
date: 2026-08-30
---

# Bienvenido a mi blog

Este es el contenido de mi primera **publicación** usando Nuxt Content.

Mostrar el contenido en una página

<script setup>
const { data: posts } = await useAsyncData('posts', () =>
  queryContent('/blog').find()
)
</script>

Rutas dinámicas con content

<!-- pages/blog/[slug].vue -->
<script setup>
const route = useRoute()

const { data: post } = await useAsyncData(`post-${route.params.slug}`, () =>
  queryContent(`/blog/${route.params.slug}`).findOne()
)
</script>

9.3 De archivos a páginas con content

Consultar el contenido

El módulo ofrece una API de consulta (queryContent) para filtrar, ordenar y limitar los archivos de contenido.

Ejemplo: Consultas comunes

<script setup>
// Todos los posts
const posts = await queryContent('/blog').find()

// Solo los publicados, ordenados por fecha
const publicados = await queryContent('/blog')
  .where({ publicado: true })
  .sort({ fecha: -1 })
  .limit(5)
  .find()

// Un solo documento
const unPost = await queryContent('/blog/primer-post').findOne()
</script>

Integración con navegación

<template>
  <ul>
    <li v-for="post in posts" :key="post._path">
      <NuxtLink :to="post._path">{{ post.title }}</NuxtLink>
    </li>
  </ul>
</template>

Ventajas de Nuxt Content

  • Escribe en Markdown y got HTML renderizado
  • Rutas generadas automáticamente desde la estructura de archivos
  • Consulta flexible con filtros y ordenación
  • Ideal para blogs, documentación y sitios de contenido

9.4 Variables de entorno y runtime config

Qué es runtimeConfig

runtimeConfig expone variables de configuración a tu aplicación. Es la forma correcta y segura de usar variables de entorno en Nuxt, tanto en el servidor como en el cliente.

Definir config en nuxt.config

// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    // Solo está disponible en el servidor
    apiSecreta: process.env.API_SECRETA,
    public: {
      // Disponible también en el cliente (prefijo NUXT_PUBLIC_)
      apiUrl: process.env.NUXT_PUBLIC_API_URL || 'https://api.ejemplo.com'
    }
  }
})

Variables de entorno en .env

# .env
API_SECRETA=super-secreto-servidor
NUXT_PUBLIC_API_URL=https://api.ejemplo.com

Usar runtimeConfig en el código

<script setup>
const config = useRuntimeConfig()

// En el servidor: /api/secretos
const { data } = await useFetch(config.apiUrl)

// En el cliente y servidor
console.log(config.public.apiUrl)
</script>
ValorAccesible en
runtimeConfig.apiSecretaSolo servidor (usa useRuntimeConfig())
runtimeConfig.public.*Servidor y cliente
Nunca pongas secretos en la propiedad `public`; solo lo que debe ver el navegador.

9.5 Middleware de seguridad (concepto)

Seguridad en la aplicación y el servidor

La seguridad en Nuxt se aborda en varias capas: validación de entrada, autenticación, cabeceras HTTP y protección de rutas. Los middlewares de servidor y de navegación juegan un papel clave.

Capas de seguridad

CapaFunción
Validación de entradaVerificar los datos antes de procesarlos
AutenticaciónConfirmar la identidad del usuario
Cabeceras HTTPProteger contra XSS y otras amenazas
Middleware de rutasProteger páginas privadas en el cliente
Middleware de servidorProteger endpoints de la API

Ejemplo: Cabeceras de seguridad globales

// nuxt.config.ts
export default defineNuxtConfig({
  routeRules: {
    '/**': {
      headers: {
        'X-Content-Type-Options': 'nosniff',
        'X-Frame-Options': 'DENY'
      }
    }
  }
})

Conceptos clave de seguridad

  • Nunca confíes en los datos del cliente: valida en el servidor
  • Usa diferentes claves secretas para producción
  • Limpia y escapa el contenido generado por el usuario
  • Mantén las dependencias actualizadas

9.6 Gestionar runtime config y seguridad

Variables por entorno

Puedes tener configuraciones distintas para desarrollo y producción usando archivos de entorno por entorno.

.env                # común
.env.development    # solo desarrollo
.env.production     # solo producción

Ejemplo: Configurar secretos de forma segura

// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    jwtSecreto: process.env.JWT_SECRETO,
    public: {
      apiUrl: process.env.NUXT_PUBLIC_API_URL
    }
  },
  // No exponer archivos sensibles
  nitro: {
    publicAssets: [{ baseURL: '/privado/' }]
  }
})

Buenas prácticas de seguridad

  • Mantén las variables de entorno fuera del repositorio (.gitignore)
  • Usa useRuntimeConfig en lugar de process.env directo en el código
  • Protege rutas privadas con middleware de navegación
  • Valida y sanitiza toda la entrada del servidor
Para aplicaciones con usuarios, considera un módulo de autenticación como Nuxt Auth y gestiona las sesiones de forma segura.

Resumen

**Lo que aprendiste en esta sección:** - Los módulos extienden Nuxt con funcionalidades adicionales - @nuxt/content gestiona contenido basado en archivos Markdown - queryContent permite consultar y filtrar el contenido - runtimeConfig expone variables de entorno de forma segura - Las claves públicas y secretas se separan correctamente - La seguridad se aplica en varias capas: validación, auth, cabeceras y middleware - Nunca expongas secretos en la parte pública del config
