7.1 Instalar y configurar Pinia

Módulo oficial de Pinia

Nuxt ofrece el módulo @pinia/nuxt para integrar Pinia con soporte SSR automático. Solo hay que instalarlo y añadirlo a la configuración.

Pasos de instalación

# Instalar el módulo de Pinia para Nuxt
npm install @pinia/nuxt
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@pinia/nuxt']
})

Estructura de stores

stores/
├── carrito.ts
├── usuarios.ts
└── contador.ts

Carpeta de stores

Pinia busca los stores por convención en la carpeta stores/ (ubicada en la raíz o dentro de app/). Cada archivo exporta un store con defineStore.

Recuerda reiniciar el servidor de desarrollo tras instalar un módulo nuevo.

7.2 Definir un store con state, getters y actions

El store de carrito

Un store de Pinia se compone de state, getters y actions. Veamos un ejemplo completo con el patrón de Setup Store.

Ejemplo: Store de carrito con Setup

// stores/carrito.ts
export const useCarritoStore = defineStore('carrito', () => {
  // state
  const items = ref([])

  // getters
  const total = computed(() =>
    items.value.reduce((sum, item) => sum + item.precio, 0)
  )
  const cantidad = computed(() => items.value.length)

  // actions
  function agregar(producto) {
    items.value.push(producto)
  }
  function vaciar() {
    items.value = []
  }

  return { items, total, cantidad, agregar, vaciar }
})

Componentes del store

ParteFunción
stateDatos reactivos del store
gettersValores derivados calculados (computed)
actionsFunciones para modificar el estado o hacer peticiones

7.3 Usar el store en componentes

Acceder al store

Para usar un store en un componente se llama a la función useCarritoStore(). Una vez dentro, tienes acceso a state, getters y actions.

Ejemplo: Widget del carrito

<!-- app/components/CarritoWidget.vue -->
<template>
  <div class="carrito">
    <p>Artículos: {{ cantidad }}</p>
    <p>Total: {{ formato(total) }}</p>
    <button @click="vaciar">Vaciar</button>
  </div>
</template>

<script setup>
const store = useCarritoStore()
const { cantidad, total, vaciar } = storeToRefs(store)
</script>

storeToRefs para reactividad

Para mantener la reactividad de los state/getters al desestructurar, usa storeToRefs(). Las actions se pueden desestructurar directamente porque son funciones.

<script setup>
const store = useCarritoStore()

// state y getters con storeToRefs (reactivos)
const { cantidad, total } = storeToRefs(store)

// actions son funciones, se pueden desestructurar
const { agregar, vaciar } = store
</script>
No desestructures state sin storeToRefs, porque perderías la reactividad.

7.4 Actions asíncronas con Pinia

Actions que obtienen datos

Las actions pueden ser asíncronas, por ejemplo para obtener datos de la API y guardarlos en el store. Esto centraliza la lógica de datos en el store.

Ejemplo: Store con llamada a API

// stores/productos.ts
export const useProductosStore = defineStore('productos', () => {
  const lista = ref([])
  const cargando = ref(false)

  async function cargarProductos() {
    cargando.value = true
    try {
      const { data } = await $fetch('/api/productos')
      lista.value = data
    } finally {
      cargando.value = false
    }
  }

  return { lista, cargando, cargarProductos }
})

Usar la action en un componente

<script setup>
const store = useProductosStore()

onMounted(() => {
  store.cargarProductos()
})
</script>

Alternativa con useAsyncData

Para SSR, a menudo es mejor combinar useAsyncData (fuera del store) con una action del store:

const store = useProductosStore()

await useAsyncData('productos', () => store.cargarProductos())

7.5 Composables que usan Pinia

Combinar composables y stores

Una buena práctica es crear composables en app/composables/ que encapsulen la interacción con los stores. Así los componentes quedan más limpios.

Ejemplo: Composable del carrito

// app/composables/useCarrito.ts
export function useCarrito() {
  const store = useCarritoStore()

  const agregarProducto = (producto) => {
    store.agregar(producto)
    console.log('Producto añadido', producto.nombre)
  }

  return {
    items: computed(() => store.items),
    total: computed(() => store.total),
    agregarProducto,
    vaciar: store.vaciar
  }
}

Usarlo en un componente

<!-- pages/productos.vue -->
<template>
  <button @click="agregarProducto({ nombre: 'Laptop', precio: 999 })">
    Añadir
  </button>
</template>

<script setup>
const { total, agregarProducto } = useCarrito()
</script>

Ventajas de este patrón

  • Lógica reutilizable y desacoplada del componente
  • Los componentes solo ven lo que necesitan
  • Fácil de testear de forma aislada

7.6 Pinia hydration y SSR

Cómo funciona Pinia con SSR

El módulo @pinia/nuxt gestiona automáticamente el estado entre servidor y cliente. El estado del servidor se serializa y se reenvía al cliente para la hidratación.

Flujo con SSR

Servidor -> crea un store nuevo por petición
  -> rellena el estado con datos
  -> serializa el estado en el payload

Cliente  -> crea el store usando el estado recibido
  -> la interfaz ya muestra los datos sin otra petición

Precaución con datos sensibles

Toda la información que guardes en el store durante el SSR viaja al cliente en el payload. Evita guardar secretos, tokens de servidor o datos sensibles en el store durante el renderizado inicial.

No almacenes tokens de acceso o datos privados del usuario en el estado global durante el SSR; quedan expuestos en el HTML.

Reiniciar estado por petición

// app/plugins/pinia.server.ts
export default defineNuxtPlugin(() => {
  // Lógica específica de servidor para reiniciar stores
})
