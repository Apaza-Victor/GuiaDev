5.1 useFetch

Qué es useFetch

useFetch es el composable recomendado de Nuxt para obtener datos en una página o componente. Funciona tanto en el servidor como en el cliente y devuelve un objeto con data, error y status.

Ejemplo: Obtener una lista de productos

<!-- pages/productos.vue -->
<template>
  <div>
    <h1>Productos</h1>
    <ul v-if="data">
      <li v-for="p in data" :key="p.id">{{ p.nombre }}</li>
    </ul>
    <p v-if="error">Error al cargar: {{ error.message }}</p>
  </div>
</template>

<script setup>
const { data, error, status } = await useFetch('/api/productos')
</script>

Parámetros útiles

OpciónDescripción
methodMétodo HTTP (GET, POST, ...)
bodyCuerpo de la petición
headersEncabezados de la petición
watchVuelve a ejecutar cuando cambian ciertos valores
keyIdentificador único para el cacheado
useFetch reutiliza los datos entre servidor y cliente, evitando peticiones dobles.

5.2 useAsyncData y watch como reactividad

Qué es useAsyncData

useAsyncData es el composable de más bajo nivel para obtener datos. A diferencia de useFetch, tú controlas la petición (por ejemplo con $fetch u otra librería), lo que da más flexibilidad.

Ejemplo: Datos con lógica propia

<!-- pages/detalle.vue -->
<script setup>
const { data: detalle, refresh } = await useAsyncData(
  'detalle-producto',
  () => $fetch(`/api/productos/${id}`)
)
</script>

Recargar datos con refresh

El objeto devuelto incluye una función refresh() para volver a ejecutar la petición manualmente:

<template>
  <button @click="refresh">Recargar</button>
</template>

<script setup>
const { data, refresh } = await useAsyncData('datos', () => $fetch('/api/datos'))
</script>

Reactividad con watch

Puedes hacer que la petición se repita cuando cambie una dependencia usando la opción watch:

const pagina = ref(1)

const { data } = await useAsyncData(
  'lista',
  () => $fetch(`/api/items?pag=${pagina.value}`),
  { watch: [pagina] }
)

5.3 Servidor vs cliente e hidratación

Cómo se obtienen los datos

Con SSR, las peticiones de datos se ejecutan primero en el servidor. El HTML ya llega renderizado con los datos. Después, Nuxt "hidrata" la página en el cliente, reutilizando los datos payload sin hacer una segunda petición.

El payload

Servidor -> ejecuta useFetch -> HTML + payload
Cliente  -> hidrata usando el payload (sin repetir petición)

Controlar ejecución según entorno

<script setup>
// Solo se ejecuta en el servidor
const { data: serverData } = await useAsyncData('server', () => $fetch('/api/server'))

// Solo en el cliente
if (import.meta.client) {
  // lógica de cliente
}
</script>
ValorEntorno
import.meta.servertrue solo en el servidor
import.meta.clienttrue solo en el navegador

Ventajas del renderizado en servidor

  • El usuario ve contenido real antes de que cargue JavaScript
  • Mejor SEO porque el HTML contiene los datos
  • Menos peticiones redundantes

5.4 ISR con revalidate

Qué es ISR

La Revalidación Estática Incremental (ISR) combina páginas estáticas con la posibilidad de regenerarlas después de un tiempo. Es ideal para contenido que cambia con poca frecuencia pero que debe permanecer nuevo.

Ejemplo: Fuente de datos con revalidación

<!-- pages/dashboard.vue -->
<script setup>
const { data } = await useFetch('/api/estadisticas', {
  // Revalidar la página cada 60 segundos
  revalidate: 60,
  defer: true
})
</script>

Cómo funciona

  • La primera petición se sirve y se guarda como estática
  • Durante 60 segundos se sirve la versión guardada (rápida)
  • Pasado ese tiempo, la siguiente visita regenera la página en segundo plano

Configuración a nivel de ruta

<script setup>
definePageMeta({
  // marcar esta ruta para ISR
  isr: true
})
</script>

ISR vs SSG

ModoComportamiento
SSGContenido fijo, se regenera solo al hacer deploy
ISREstático pero se revalida tras un intervalo
SSRSe renderiza en cada petición (siempre actual)

5.5 useSeoMeta y metadatos

Qué es useSeoMeta

useSeoMeta es un composable de Nuxt que simplifica la gestión de metadatos para SEO: título, descripción, Open Graph, etc., de forma reactiva.

Ejemplo: SEO de una página

<script setup>
useSeoMeta({
  title: 'Mi tienda de productos',
  description: 'Compra los mejores productos con descuento',
  ogTitle: 'Mi tienda online',
  ogDescription: 'Productos de calidad al mejor precio',
  ogImage: '/imagen-portada.jpg',
  ogType: 'website'
})
</script>

Metadatos estáticos en nuxt.config

// nuxt.config.ts
export default defineNuxtConfig({
  app: {
    head: {
      htmlAttrs: { lang: 'es' },
      titleTemplate: '%s | Mi Sitio',
      meta: [
        { name: 'charset', content: 'utf-8' },
        { name: 'viewport', content: 'width=device-width, initial-scale=1' }
      ]
    }
  }
})

Metadatos dinámicos según datos

<script setup>
const { data: producto } = await useFetch(`/api/productos/${id}`)

useSeoMeta({
  title: () => producto.value?.nombre || 'Producto',
  description: () => producto.value?.descripcion || ''
})
</script>

5.6 Suspense y carga asíncrona de páginas

Qué es Suspense

Suspense es el mecanismo de Vue/Nuxt para manejar componentes que necesitan datos antes de renderizar. Con await dentro de script setup, Nuxt espera la resolución de los datos antes de completar la navegación.

Cómo funciona con Nuxt

Cuando usas await useFetch o await useAsyncData en el top-level de una página, Nuxt hace lo siguiente:

  1. Carga los datos mientras se prepara la página
  2. Mientras espera, usa la página en estado de carga
  3. Cuando los datos están listos, renderiza la página final

Ejemplo: Controlar la carga

<template>
  <div>
    <p v-if="status === 'pending'">Cargando...</p>
    <ul v-else-if="data">
      <li v-for="item in data" :key="item.id">{{ item.nombre }}</li>
    </ul>
  </div>
</template>

<script setup>
const { data, status } = await useFetch('/api/items')
</script>

Estado de la petición

EstadoSignificado
pendingLa petición está en curso
errorLa petición falló
successLa petición se completó correctamente
Usa el atributo defer cuando no quieras bloquear la renderización esperando los datos.

Resumen

**Lo que aprendiste en esta sección:** - useFetch es el composable recomendado para obtener datos - useAsyncData ofrece más control sobre la petición - Los datos se obtienen en el servidor y se hidratan en el cliente - ISR con revalidate permite contenido estático actualizable - useSeoMeta gestiona metadatos reactivos para SEO - Suspense y los states (pending, error, success) controlan la carga
