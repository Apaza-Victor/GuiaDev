8.1 Qué es una REST API

Definición

Una API REST (Representational State Transfer) es un conjunto de reglas para construir servicios web que se comunican mediante HTTP y JSON. Cada recurso tiene una URL y se manipula con métodos HTTP.

Principios REST

  • Recursos: Entidades como usuarios, productos o tareas
  • URLs descriptivas: `/usuarios`, `/productos/5`
  • Métodos HTTP: GET, POST, PUT, DELETE
  • Sin estado: Cada petición es independiente
  • JSON como formato: Formato estándar de intercambio

Mapeo de operaciones REST

MétodoURLAcción
GET/usuariosListar usuarios
GET/usuarios/1Obtener un usuario
POST/usuariosCrear un usuario
PUT/usuarios/1Actualizar un usuario
DELETE/usuarios/1Eliminar un usuario
REST se basa en recursos y métodos HTTP. El estado del cliente no se guarda en el servidor (sin estado).

8.2 Devolver JSON con jsonify

Qué es jsonify

jsonify() convierte objetos de Python (diccionarios y listas) a formato JSON y crea una respuesta HTTP con el tipo de contenido correcto.

Devolver un diccionario

from flask import Flask, jsonify

app = Flask(__name__)


@app.route("/usuario")
def usuario():
    return jsonify({"id": 1, "nombre": "Ana", "email": "ana@correo.com"})

Devolver una lista

@app.route("/usuarios")
def usuarios():
    lista = [
        {"id": 1, "nombre": "Ana"},
        {"id": 2, "nombre": "Carlos"},
    ]
    return jsonify(lista)

Respuesta con código de estado

@app.route("/crear", methods=["POST"])
def crear():
    return jsonify({"mensaje": "Creado"}), 201

Alternativa: devolver dict directamente

# Flask convierte automáticamente los dicts a JSON
@app.route("/info")
def info():
    return {"aplicacion": "Mi API", "version": "1.0"}
`jsonify` te permite fijar el código de estado de la respuesta, útil para indicar si fue una creación (201) o un error (404).

8.3 Métodos en las rutas

Crear una API CRUD completa

Definimos distintos endpoints para gestionar recursos con cada método HTTP:

from flask import Flask, request, jsonify

app = Flask(__name__)

tareas = []
contador = 1


# GET - Listar todas las tareas
@app.route("/tareas", methods=["GET"])
def listar():
    return jsonify(tareas)


# GET - Obtener una tarea
@app.route("/tareas/<int:tarea_id>", methods=["GET"])
def obtener(tarea_id):
    for t in tareas:
        if t["id"] == tarea_id:
            return jsonify(t)
    return jsonify({"error": "Tarea no encontrada"}), 404


# POST - Crear una tarea
@app.route("/tareas", methods=["POST"])
def crear():
    global contador
    datos = request.json
    nueva = {"id": contador, "titulo": datos.get("titulo"), "hecha": False}
    contador += 1
    tareas.append(nueva)
    return jsonify(nueva), 201

Actualizar y eliminar

# PUT - Actualizar una tarea
@app.route("/tareas/<int:tarea_id>", methods=["PUT"])
def actualizar(tarea_id):
    datos = request.json
    for t in tareas:
        if t["id"] == tarea_id:
            t["titulo"] = datos.get("titulo", t["titulo"])
            t["hecha"] = datos.get("hecha", t["hecha"])
            return jsonify(t)
    return jsonify({"error": "Tarea no encontrada"}), 404


# DELETE - Eliminar una tarea
@app.route("/tareas/<int:tarea_id>", methods=["DELETE"])
def eliminar(tarea_id):
    global tareas
    tareas = [t for t in tareas if t["id"] != tarea_id]
    return jsonify({"mensaje": "Tarea eliminada"})
Cada endpoint define su método explícitamente: GET para leer, POST para crear, PUT para actualizar y DELETE para eliminar.

8.4 Manejo de errores en la API

Devolver errores en JSON

Las APIs deben responder con códigos de estado y mensajes útiles en JSON:

from flask import Flask, jsonify

app = Flask(__name__)


# Manejo global de errores 404 en JSON
@app.errorhandler(404)
def no_encontrado(error):
    return jsonify({"error": "Recurso no encontrado", "codigo": 404}), 404


@app.errorhandler(500)
def error_interno(error):
    return jsonify({"error": "Error interno del servidor", "codigo": 500}), 500

Validación de entrada

@app.route("/usuario", methods=["POST"])
def crear_usuario():
    datos = request.json or {}
    if not datos.get("nombre"):
        return jsonify({"error": "El campo nombre es obligatorio"}), 400
    return jsonify({"mensaje": "Usuario creado", "nombre": datos["nombre"]}), 201

Códigos de error REST habituales

CódigoSignificadoUso típico
400Solicitud incorrectaDatos de entrada inválidos
401No autenticadoFalta token o credenciales
403ProhibidoSin permisos
404No encontradoRecurso inexistente
500Error internoFallo del servidor
Siempre usa el código de estado correcto: ayuda a los clientes a entender el resultado sin leer el mensaje.

8.5 Consumir la API

Probar la API con herramientas

  • Navegador: Ideal para peticiones GET sencillas
  • curl: Consumir desde la terminal
  • Postman / Insomnia: Herramientas gráficas para probar APIs

Consumir con curl

# GET - listar
curl http://127.0.0.1:5000/tareas

# POST - crear
curl -X POST -H "Content-Type: application/json" \
     -d '{"titulo": "Comprar pan"}' http://127.0.0.1:5000/tareas

# DELETE - eliminar
curl -X DELETE http://127.0.0.1:5000/tareas/1

Consumir desde Python con requests

import requests

# GET
respuesta = requests.get("http://127.0.0.1:5000/tareas")
print(respuesta.json())

# POST
respuesta = requests.post(
    "http://127.0.0.1:5000/tareas",
    json={"titulo": "Hacer ejercicio"}
)
print(respuesta.json())

Consumir desde JavaScript (fetch)

// POST desde el navegador
fetch("/tareas", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify({titulo: "Estudiar"})
}).then(r => r.json()).then(datos => console.log(datos));
Una API REST puede ser consumida desde cualquier cliente: navegador, terminal, Python, JavaScript u otras aplicaciones.

8.6 Estructura de una REST API

Buenas prácticas de estructura

  • URLs en plural y en minúsculas: `/usuarios`, no `/Usuario`
  • Recursos anidados: `/usuarios/1/posts` para posts de un usuario
  • Verbos fuera de las URLs: Usa métodos HTTP, no `/crear-usuario`
  • Listas paginadas: Devuelve fragmentos con metadatos de paginación
  • Respuestas JSON consistentes: Mismo formato en toda la API

Ejemplo de respuesta paginada

@app.route("/usuarios")
def listar_usuarios():
    pagina = request.args.get("pagina", 1, type=int)
    por_pagina = request.args.get("limite", 10, type=int)
    inicio = (pagina - 1) * por_pagina
    fin = inicio + por_pagina
    datos = usuarios[inicio:fin]
    return jsonify({
        "pagina": pagina,
        "total": len(usuarios),
        "resultados": datos
    })

Métodos de cada recurso

RecursoGETPOSTPUTDELETE
/usuariosListarCrear--
/usuarios/{id}Obtener-ActualizarEliminar
Evita poner verbos en las URLs (ej. `/usuarios/crear`). REST se apoya en los métodos HTTP para representar las acciones.

Resumen

**Lo que aprendiste en esta sección:** - Una REST API usa recursos, URLs descriptivas y métodos HTTP - `jsonify` convierte datos Python a respuestas JSON - Cada método HTTP define una operación sobre el recurso - Los errores se devuelven con códigos de estado y mensajes JSON - La API puede consumirse con curl, requests, fetch o Postman - Una buena estructura usa URLs plurales y consistencia en las respuestas
