6.1 Manejar formularios

Flujo de un formulario en Flask

  1. El usuario ve un formulario HTML (ruta GET)
  2. El usuario lo envía con POST
  3. Flask recibe los datos con request.form
  4. La aplicación valida y procesa los datos
  5. Redirige a otra página o muestra un mensaje

Formulario HTML

<form method="POST" action="/contacto">
    <input type="text" name="nombre" placeholder="Tu nombre">
    <input type="email" name="email" placeholder="Tu correo">
    <textarea name="mensaje"></textarea>
    <button type="submit">Enviar</button>
</form>

Recibir y procesar en Flask

from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/contacto", methods=["GET", "POST"])
def contacto():
    if request.method == "POST":
        nombre = request.form.get("nombre")
        email = request.form.get("email")
        mensaje = request.form.get("mensaje")
        return f"Gracias {nombre}, recibimos tu mensaje."
    return render_template("contacto.html")
Separa la ruta GET (que muestra el formulario) de la POST (que procesa los datos) para mantener el flujo claro.

6.2 Flask-WTF (concepto)

Qué es Flask-WTF

Flask-WTF es una extensión que integra WTForms en Flask. Permite definir formularios como clases de Python, con validación integrada y protección CSRF automática.

Instalación

pip install flask-wtf

Concepto: definir un formulario como clase

from flask_wtf import FlaskForm
from wtforms import StringField, PasswordField, SubmitField
from wtforms.validators import DataRequired, Email

class RegistroForm(FlaskForm):
    nombre = StringField("Nombre", validators=[DataRequired()])
    email = StringField("Correo", validators=[DataRequired(), Email()])
    password = PasswordField("Contraseña", validators=[DataRequired()])
    enviar = SubmitField("Registrar")

Ventajas de Flask-WTF

  • Validación declarativa y reutilizable
  • Protección CSRF automática
  • Renderizado de formularios en plantillas
  • Manejo de errores de validación integrado
Flask-WTF simplifica el trabajo con formularios: defines todo en la clase y la extensión se encarga del resto.

6.3 Validación manual

Validar sin librerías externas

Puedes validar los datos manualmente comprobando los valores de request.form:

from flask import Flask, request, redirect, url_for, flash

app = Flask(__name__)
app.secret_key = "clave_secreta"


@app.route("/registro", methods=["GET", "POST"])
def registro():
    if request.method == "POST":
        nombre = request.form.get("nombre", "").strip()
        email = request.form.get("email", "").strip()
        password = request.form.get("password", "")

        errores = []
        if not nombre:
            errores.append("El nombre es obligatorio")
        if "@" not in email or "." not in email:
            errores.append("El correo no es válido")
        if len(password) < 6:
            errores.append("La contraseña debe tener al menos 6 caracteres")

        if errores:
            for error in errores:
                flash(error, "error")
            return render_template("registro.html")

        flash("Registro exitoso", "exito")
        return redirect(url_for("inicio"))
    return render_template("registro.html")
La validación manual es útil para casos simples, pero para formularios complejos es preferible usar Flask-WTF que ya incluye validación y CSRF.

6.4 Mensajes flash

Crear y mostrar mensajes flash

Los mensajes flash son la forma estándar de mostrar avisos tras un envío de formulario.

from flask import Flask, flash, redirect, render_template, url_for

app = Flask(__name__)
app.secret_key = "clave_secreta"


@app.route("/guardar", methods=["POST"])
def guardar():
    # Procesar datos...
    flash("Tus cambios se guardaron correctamente", "exito")
    flash("Revisa tu correo para confirmar", "aviso")
    return redirect(url_for("perfil"))

Mostrar con categorías

{% with mensajes = get_flashed_messages(with_categories=true) %}
  {% if mensajes %}
    {% for categoria, mensaje in mensajes %}
      <div class="alerta alerta-{{ categoria }}">
        {{ mensaje }}
      </div>
    {% endfor %}
  {% endif %}
{% endwith %}

Categorías habituales

  • exito: Operación completada correctamente
  • error: Algo salió mal
  • aviso: Información adicional
Usa categorías en los mensajes flash para aplicar estilos distintos y mejorar la experiencia de usuario.

6.5 url_for y redirección

Qué es url_for

url_for() genera una URL a partir del nombre de la función de vista, evitando escribir rutas a mano.

Usos comunes de url_for

from flask import Flask, redirect, url_for, render_template

app = Flask(__name__)


@app.route("/")
def inicio():
    return "Inicio"


@app.route("/perfil/<nombre>")
def perfil(nombre):
    return f"Perfil de {nombre}"


@app.route("/redirigir")
def redirigir():
    # Redirigir por nombre de función
    return redirect(url_for("inicio"))


@app.route("/ir-perfil")
def ir_perfil():
    # Redirigir pasando parámetros
    return redirect(url_for("perfil", nombre="Ana"))

Uso en plantillas

<form method="POST" action="{{ url_for('guardar') }}">
<a href="{{ url_for('perfil', nombre='Ana') }}">Ver perfil</a>
Si renombras una función de vista, solo debes actualizar `url_for` y `redirect`; las URLs generadas se ajustan automáticamente.

6.6 Patrón POST/Redirect/GET

Qué es el patrón PRG

El patrón POST/Redirect/GET (PRG) consiste en que, tras procesar un formulario enviado por POST, la aplicación responda con una redirección (GET) en lugar de devolver la página directamente.

Por qué usarlo

  • Evita reenvíos: Al recargar, no se reenvía el formulario
  • Mejora la experiencia: Evita avisos de "repetir el envío" en el navegador
  • Mantiene la URL limpia: Tras el POST, la URL apunta al GET
  • Correcto con flash: Los mensajes se muestran en la página de destino

Flujo PRG completo

from flask import Flask, request, redirect, url_for, flash, render_template

app = Flask(__name__)
app.secret_key = "clave_secreta"


@app.route("/tarea", methods=["GET", "POST"])
def tarea():
    if request.method == "POST":
        texto = request.form.get("texto")
        if not texto:
            flash("El texto es obligatorio", "error")
            return redirect(url_for("tarea"))
        # Guardar la tarea...
        flash("Tarea creada correctamente", "exito")
        return redirect(url_for("tarea"))
    return render_template("tarea.html")
Siempre que proceses un formulario POST, responde con `redirect()` en lugar de renderizar directamente. Así aplicas el patrón PRG correctamente.

Resumen

**Lo que aprendiste en esta sección:** - Los formularios se manejan combinando rutas GET (mostrar) y POST (procesar) - Flask-WTF permite definir formularios como clases con validación y CSRF - La validación manual comprueba los valores de `request.form` - Los mensajes flash muestran avisos temporales tras el envío - `url_for` genera URLs a partir de nombres de funciones - El patrón POST/Redirect/GET evita reenvíos y mejora la experiencia
