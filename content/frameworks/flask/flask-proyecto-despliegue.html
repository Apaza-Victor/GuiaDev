10.1 Estructura profesional de un proyecto

Estructura recomendada

miapp/
├── app/
│   ├── __init__.py          # Crea la aplicación Flask
│   ├── rutas.py             # Vistas y rutas
│   ├── modelos.py           # Modelos de base de datos
│   ├── templates/           # Plantillas Jinja2
│   └── static/              # CSS, JS, imágenes
├── migrations/              # Migraciones del esquema
├── tests/                   # Pruebas automatizadas
├── venv/                    # Entorno virtual
├── requirements.txt         # Dependencias
├── config.py                # Configuración
├── run.py                   # Punto de entrada
└── .env                     # Variables de entorno (no se sube)

Fábrica de aplicaciones (app factory)

# app/__init__.py
from flask import Flask


def crear_app():
    app = Flask(__name__)
    app.config.from_object("config.Config")

    from .rutas import main
    app.register_blueprint(main)

    return app

Punto de entrada

# run.py
from app import crear_app

app = crear_app()

if __name__ == "__main__":
    app.run(debug=True)
La fábrica de aplicaciones permite crear varias instancias (una para desarrollo, otra para pruebas, otra para producción) de forma limpia.

10.2 requirements.txt

Qué es requirements.txt

Es un archivo que lista las dependencias de tu proyecto con sus versiones, permitiendo reproducir el entorno en cualquier máquina.

Generarlo automáticamente

# Genera la lista de todas las dependencias instaladas
pip freeze > requirements.txt

Ejemplo de contenido

flask==3.0.0
flask-sqlalchemy==3.1.1
flask-migrate==4.0.5
flask-wtf==1.2.1
gunicorn==21.2.0
python-dotenv==1.0.0

Instalar desde requirements.txt

pip install -r requirements.txt

Buenas prácticas

  • Bloquea las versiones con == para reproducibilidad
  • Separa `requirements-dev.txt` para herramientas de desarrollo
  • Actualiza el archivo cada vez que agregues una dependencia
`pip freeze` incluye todas las dependencias transitivas; filtrar las principales en un archivo manual es más legible.

10.3 Variables de entorno

Qué son las variables de entorno

Las variables de entorno guardan datos de configuración (claves secretas, URIs de base de datos, puertos) fuera del código, para no exponerlos en el repositorio.

Archivo .env

# .env (no se sube a git)
SECRET_KEY=clave_muy_secreta
DATABASE_URL=sqlite:///datos.db
FLASK_DEBUG=1

Cargar variables con python-dotenv

pip install python-dotenv
# run.py
import os
from dotenv import load_dotenv

load_dotenv()  # Carga el archivo .env

app.config["SECRET_KEY"] = os.getenv("SECRET_KEY")
app.config["SQLALCHEMY_DATABASE_URI"] = os.getenv("DATABASE_URL")

Archivo .gitignore

venv/
.env
__pycache__/
*.pyc
instance/
Nunca subas el archivo `.env` al repositorio: contiene secretos. Añádelo siempre a `.gitignore`.

10.4 Despliegue con Gunicorn

Por qué Gunicorn

El servidor de desarrollo de Flask no es apto para producción. Gunicorn es un servidor WSGI robusto y orientado a producción.

Instalar Gunicorn

pip install gunicorn

Ejecutar la aplicación con Gunicorn

# gunicorn app.fabrica:objeto
gunicorn -w 4 -b 0.0.0.0:8000 "app:crear_app()"

Opciones principales

OpciónDescripción
-w 4Número de workers (procesos)
-b 0.0.0.0:8000Dirección y puerto
--timeout 120Tiempo máximo por petición
--access-logfileArchivo de logs de acceso

Despliegue flujo completo

  1. Instala dependencias con pip
  2. Carga variables de entorno
  3. Ejecuta migraciones de base de datos
  4. Arranca Gunicorn
  5. Configura un proxy inverso (Nginx) delante de Gunicorn
En entornos Linux suele usarse Nginx como proxy inverso delante de Gunicorn para servir estáticos y manejar conexiones.

10.5 Buenas prácticas de seguridad

Secret key

La secret key firma cookies y sesiones. Debe ser larga, aleatoria y guardada en una variable de entorno:

import secrets
# Genera una clave aleatoria segura
clave = secrets.token_hex(32)
print(clave)
# app.py
import os
app.secret_key = os.getenv("SECRET_KEY")

Protección CSRF

CSRF (Cross-Site Request Forgery) es un ataque que envía peticiones no autorizadas en nombre del usuario. Flask-WTF la protege automáticamente:

pip install flask-wtf

from flask_wtf.csrf import CSRFProtect

csrf = CSRFProtect(app)
# En cada formulario: <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">

Otras buenas prácticas

  • Desactiva debug en producción: Nunca uses debug=True
  • Cifra contraseñas: Usa hashing, nunca texto plano
  • Valida entradas: Evita inyección y datos maliciosos
  • Usa HTTPS: Asegura la comunicación con el cliente
  • Actualiza dependencias: Mantén Flask y sus extensiones al día
En producción: debug desactivado, secret key desde variable de entorno, HTTPS activo y CSRF habilitado en los formularios.

10.6 Ejemplo completo organizado

Estructura final

miapp/
├── app/
│   ├── __init__.py
│   ├── rutas.py
│   ├── modelos.py
│   ├── templates/
│   └── static/
├── config.py
├── run.py
├── requirements.txt
└── .env

config.py

import os

class Config:
    SECRET_KEY = os.getenv("SECRET_KEY")
    SQLALCHEMY_DATABASE_URI = os.getenv("DATABASE_URL")

app/__init__.py

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from dotenv import load_dotenv

load_dotenv()

db = SQLAlchemy()


def crear_app():
    app = Flask(__name__)
    app.config.from_object("config.Config")

    db.init_app(app)

    from .rutas import main
    app.register_blueprint(main)

    return app

app/rutas.py

from flask import Blueprint, jsonify
from .modelos import Usuario

main = Blueprint("main", __name__)


@main.route("/")
def inicio():
    return jsonify({"mensaje": "API funcionando"})


@main.route("/usuarios")
def listar_usuarios():
    usuarios = Usuario.query.all()
    return jsonify([{"id": u.id, "nombre": u.nombre} for u in usuarios])
Este ejemplo separa configuración, creación de la app, modelos y rutas en archivos distintos para mantener el proyecto limpio y profesional.

Resumen

**Lo que aprendiste en esta sección:** - Una estructura profesional separa la app en módulos (config, rutas, modelos) - `requirements.txt` permite reproducir el entorno con `pip install -r` - Las variables de entorno ocultan secretos y configuración sensible - Gunicorn es el servidor WSGI recomendado para producción - La secret key, CSRF y desactivar debug son esenciales para la seguridad - Una app fábrica organiza mejor proyectos grandes
