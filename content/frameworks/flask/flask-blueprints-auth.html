9.1 Qué son los Blueprints

Definición

Un Blueprint es una forma de organizar una aplicación Flask en módulos separados, cada uno con sus propias rutas, plantillas y estáticos. Permite dividir un proyecto grande en secciones claras y reutilizables.

Beneficios de usar Blueprints

  • Modularidad: Divide la app en partes independientes
  • Reutilización: Un blueprint puede usarse en varios proyectos
  • Mantenibilidad: Cada módulo se desarrolla por separado
  • Escalabilidad: Proyectos grandes más fáciles de gestionar
  • Organización: Separas rutas relacionadas en un mismo lugar

Estructura típica con blueprints

miapp/
├── app.py
├── auth/
│   ├── __init__.py
│   └── rutas.py
├── main/
│   ├── __init__.py
│   └── rutas.py
└── templates/
    └── base.html
Los Blueprints son ideales cuando tu aplicación empieza a crecer y quieres mantener las rutas organizadas por funcionalidad.

9.2 Crear un Blueprint

Definir un blueprint

Creamos un archivo `main.py` con las rutas principales:

# main.py
from flask import Blueprint, render_template

# Se crea el blueprint con nombre y prefijo de URL
main = Blueprint("main", __name__)


@main.route("/")
def inicio():
    return render_template("inicio.html")


@main.route("/acerca")
def acerca():
    return "Acerca de nosotros"

Registrar el blueprint en la app

# app.py
from flask import Flask
from main import main

app = Flask(__name__)

# Registrar el blueprint
app.register_blueprint(main)


if __name__ == "__main__":
    app.run(debug=True)

Prefijos de URL

# main.py
admin = Blueprint("admin", __name__, url_prefix="/admin")


@admin.route("/")
@admin.route("/panel")
def panel():
    return "Panel de administración"

# Accesible en /admin/ y /admin/panel
El parámetro `url_prefix` añade un prefijo a todas las rutas del blueprint, ideal para agrupar secciones como `/admin` o `/api`.

9.3 Register_blueprint

Cómo funciona register_blueprint

Para que la aplicación conozca un blueprint, hay que registrarlo con app.register_blueprint(). Puedes registrar varios blueprints en la misma app.

Registrar varios blueprints

from flask import Flask
from main.rutas import main
from auth.rutas import auth
from admin.rutas import admin

app = Flask(__name__)

app.register_blueprint(main)
app.register_blueprint(auth, url_prefix="/auth")
app.register_blueprint(admin, url_prefix="/admin")


if __name__ == "__main__":
    app.run(debug=True)

Opciones de register_blueprint

OpciónDescripciónEjemplo
url_prefixPrefijo para todas las rutas/api
nameRenombrar el blueprintEvitar conflictos
template_folderCarpeta de plantillas propiatemplates

url_for con blueprints

# En HTML: url_for('nombre_blueprint.nombre_vista')
# Ejemplo: url_for('main.inicio')
#          url_for('auth.login')
Cuando uses `url_for` con blueprints, recuerda el formato `nombre_blueprint.nombre_vista`, por ejemplo `main.inicio`.

9.4 Autenticación básica

Qué es la autenticación

La autenticación verifica la identidad de un usuario. La forma más común en Flask es usar sesiones basadas en cookies firmadas.

Cómo funciona la sesión

  1. El usuario se identifica (usuario y contraseña)
  2. Flask guarda sus datos en la sesión (cookie firmada)
  3. En cada petición, la sesión está disponible
  4. Al cerrar sesión se limpian los datos

Implementar login básico con sesiones

from flask import Flask, session, request, redirect, url_for

app = Flask(__name__)
app.secret_key = "clave_secreta_para_firmar_sesiones"

usuarios = {"admin": "clave123"}


@app.route("/login", methods=["GET", "POST"])
def login():
    if request.method == "POST":
        usuario = request.form.get("usuario")
        clave = request.form.get("clave")
        if usuarios.get(usuario) == clave:
            session["usuario"] = usuario
            return redirect(url_for("panel"))
        return "Credenciales incorrectas"
    return "Formulario de login"


@app.route("/panel")
def panel():
    if "usuario" not in session:
        return redirect(url_for("login"))
    return f"Bienvenido, {session['usuario']}"


@app.route("/logout")
def logout():
    session.pop("usuario", None)
    return redirect(url_for("login"))
Definir `app.secret_key` es obligatorio para usar sesiones. Nunca pongas una clave real en el código; usa variables de entorno.

9.5 Proteger rutas

Qué es proteger una ruta

Proteger una ruta significa impedir el acceso a usuarios que no han iniciado sesión, redirigiéndolos al login o devolviendo un error 401/403.

Verificar sesión manualmente

from flask import session, redirect, url_for

@app.route("/perfil")
def perfil():
    if "usuario" not in session:
        return redirect(url_for("login"))
    return "Contenido del perfil"


@app.route("/admin")
def admin():
    if session.get("usuario") != "admin":
        return "Acceso denegado", 403
    return "Panel de administración"

Decorador de protección reutilizable

from functools import wraps
from flask import session, redirect, url_for


def login_requerido(func):
    @wraps(func)
    def envoltura(*args, **kwargs):
        if "usuario" not in session:
            return redirect(url_for("login"))
        return func(*args, **kwargs)
    return envoltura


@app.route("/privado")
@login_requerido
def privado():
    return "Esta página solo para usuarios autenticados"
Con un decorador como `login_requerido` protegemos varias rutas sin repetir la comprobación en cada una.

9.6 Manejo de usuarios (concepto)

Conceptos clave

  • Registro: Crear una cuenta nueva
  • Login: Iniciar sesión con credenciales
  • Logout: Cerrar la sesión
  • Hashing de contraseñas: Guardar la contraseña cifrada, nunca en texto plano
  • Roles y permisos: Distintos niveles de acceso

Hashing de contraseñas

# Instala: pip install werkzeug
from werkzeug.security import generate_password_hash, check_password_hash

# Al registrar: guardar el hash
hash_clave = generate_password_hash("clave123")

# Al hacer login: comparar
if check_password_hash(hash_clave, "clave123"):
    print("Contraseña correcta")

Flask-Login como alternativa

Para proyectos más avanzados, Flask-Login gestiona sesiones, "recuérdame" y protección de rutas de forma integrada:

pip install flask-login

# flask_login.login_user(usuario)   # Iniciar sesión
# flask_login.logout_user()          # Cerrar sesión
# @login_required                    # Proteger rutas
# current_user.is_authenticated      # Comprobar estado
Nunca guardes contraseñas en texto plano. Usa siempre hashing (como `generate_password_hash`) o una librería de autenticación probada.

Resumen

**Lo que aprendiste en esta sección:** - Los Blueprints modularizan la aplicación en secciones independientes - Un Blueprint se define con `Blueprint()` y se registra con `register_blueprint` - `url_prefix` agrupa rutas bajo un prefijo común - La autenticación básica usa sesiones basadas en cookies firmadas - Las rutas se protegen comprobando la sesión o con decoradores - Las contraseñas deben guardarse con hashing, nunca en texto plano
