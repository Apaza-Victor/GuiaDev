Compilación para producción

El build de producción comprime, optimiza y genera HTML final. Es más estricto que el desarrollo: cualquier error de contenido o tipos rompe la compilación — exactamente lo que quieres antes de publicar:

# Build completo (salida en dist/)
npx astro build

# Previsualizar el build tal como servira produccion
npx astro preview

# Verificar errores de Content Collections y enlaces
npx astro check

Qué hace el build por ti:

  • Minifica HTML, CSS y JS; elimina código muerto (tree-shaking).
  • Cero JavaScript por defecto: las páginas sin islas JS no envían ni un byte de runtime.
  • Optimiza imágenes con astro:assets (formatos WebP/AVIF según soporte).
  • Hashing de archivos: nombres tipo app.8f2c1a.js para caché infinita segura.

Netlify y Vercel

Ambas plataformas detectan Astro automáticamente: conecta el repo, y cada push a main despliega con preview por PR. Configuración típica si necesitas personalizar:

PlataformaComando buildDirectorio salida
Netlify / Vercel / Cloudflarenpm run builddist/
 
// Para SSR en estas plataformas agrega el adaptador
import netlify from '@astrojs/netlify';   // npm i @astrojs/netlify
export default defineConfig({
  output: 'server',
  adapter: netlify()
});
  • Sitio 100% estático: no necesitas adaptador; sube dist/ y listo.
  • Rutas SSR híbridas: adaptador + prerender = false solo donde haga falta.
  • Variables de entorno se configuran en el dashboard de la plataforma, no en el repo.

Cloudflare Pages

Cloudflare Pages ofrece edge rendering global con su adaptador propio:

npm i @astrojs/cloudflare
# astro.config.mjs
# output: 'server', adapter: cloudflare()
  • Preset de framework "Astro" en el panel de Pages; detección automática del build.
  • Ideal cuando tu audiencia es global y quieres latencia mínima sin gestionar servidores.
  • Límite a considerar: runtime Workers no es Node completo (algunos paquetes nativos no funcionan).

Hosting propio y servidores estáticos

Un sitio Astro estático es una carpeta de archivos: cualquier servidor HTTP sirve dist/:

# Nginx: apunta root al dist
root /var/www/midominio/dist;
index index.html;

# O Docker minimalista
FROM nginx:alpine
COPY dist/ /usr/share/nginx/html

Checklist pre-lanzamiento:

  • site configurado en astro.config.mjs (sitemap y canonical correctos).
  • Redirecciones y cabeceras de caché: assets con hash → Cache-Control: immutable.
  • 404 personalizada (404.astro se genera automáticamente).
  • Prueba real con astro preview o el servidor de staging antes del dominio final.

Estrategia de despliegue recomendada: preview automático en cada pull request + producción solo desde main. Así nadie revisa "en producción" jamás.

Ejercicio propuesto: despliega un proyecto Astro estático tuyo en dos plataformas distintas (por ejemplo Netlify y Cloudflare Pages) y compara tiempos de respuesta globales con herramientas como webpagetest.org.
