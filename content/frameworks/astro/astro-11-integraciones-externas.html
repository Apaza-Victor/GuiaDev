Plugins Remark y Rehype

Astro procesa Markdown con el ecosistema unified: los plugins Remark transforman el Markdown crudo y los Rehype actúan sobre el HTML resultante. Se registran en la sección markdown:

import remarkGfm from 'remark-gfm';
import remarkSmartypants from 'remark-smartypants';
import rehypeSlug from 'rehype-slug';
import rehypeExternalLinks from 'rehype-external-links';

export default defineConfig({
  markdown: {
    remarkPlugins: [remarkGfm, remarkSmartypants],
    rehypePlugins: [
      rehypeSlug,                       // ids en headings para anclas
      [rehypeExternalLinks, { target: '_blank', rel: 'noopener' }]
    ]
  }
});

Los más útiles para blogs y documentación:

  • remark-gfm: tablas, tachado y checkboxes estilo GitHub.
  • rehype-slug + rehype-autolink-headings: anclas navegables en cada título.
  • rehype-accessible-images: avisa de imágenes sin alt.
  • remark-code-titles: títulos personalizados en bloques de código.

Analíticas y scripts externos

Los scripts de terceros (analytics, chat, ads) son el enemigo clásico del rendimiento. Astro ofrece dos caminos:

  • <Script /> con estrategia: componente nativo que controla cuándo carga el script.
  • Partytown: mueve scripts a un web worker para que jamás bloqueen el renderizado.
---
import Script from 'astro/components/Script.astro';
---
  • strategy="idle": cuando el navegador esté libre (ideal analytics).
  • strategy="interaction": al primer clic/touch (ideal chat widgets).
  • strategy="load": inmediato tras window load.

CMS headless y fuentes de contenido

Astro no impone CMS: consume contenido local (Content Collections) o remoto en build time:

  • Content Collections (local): tipa tu Markdown con esquemas Zod en src/content/config.ts; errores de contenido rompen el build, nunca producción.
  • CMS headless (remoto): Contentful, Sanity, Strapi, WordPress headless — consultas en frontmatter durante el build con fetch().
  • Patrón híbrido habitual: blog estático local + páginas institucionales editables desde CMS.
// src/content/config.ts - esquema tipado
import { defineCollection, z } from 'astro:content';

const blog = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    pubDate: z.coerce.date(),
    tags: z.array(z.string()).default([]),
    draft: z.boolean().default(false)
  })
});

export const collections = { blog };

Fuentes y terceros optimizados

  • Fuentes locales: usa @fontsource/* como dependencia npm — se versionan y auto-serviven desde tu dominio (sin conexión externa en runtime).
  • Google Fonts igualmente posibles, pero suman una petición cross-origin; mide antes de decidir.
  • Videos embebidos: carga YouTube/Vimeo con fachada (miniatura + iframe solo al clic) — librerías tipo lite-youtube ahorran cientos de KB iniciales.
  • Mapas: mismo principio: imagen estática primero, mapa interactivo bajo demanda.

Cada script externo debe justificar su peso en Lighthouse. Si un tercero no aporta valor medible al usuario o al negocio, su lugar es fuera del proyecto.

Ejercicio propuesto: audita con PageSpeed un sitio tuyo con scripts de terceros activos vs. desactivados. Documenta la diferencia de LCP/TBT y decide qué terceros migrar a Partytown o eliminar.
