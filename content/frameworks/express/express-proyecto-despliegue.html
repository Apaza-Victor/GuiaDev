10.1 Estructura de un proyecto Express real

Organización profesional

Un proyecto Express real se organiza en módulos y capas para facilitar el mantenimiento y la escalabilidad.

mi-api/
|-- src/
|   |-- config/
|   |   `-- db.js
|   |-- models/
|   |   `-- Usuario.js
|   |-- controllers/
|   |   `-- usuarioController.js
|   |-- routes/
|   |   `-- usuarioRoutes.js
|   |-- middleware/
|   |   `-- auth.js
|   `-- app.js
|-- .env
|-- .gitignore
|-- package.json
`-- index.js

Propósito de cada capa

CapaResponsabilidad
configConexiones y configuración (base de datos)
modelsDefinición de los datos/esquemas
controllersLógica de negocio de cada recurso
routesDefinición de las rutas HTTP
middlewareFunciones reutilizables (auth, errores)
Separar rutas, controladores y modelos hace el proyecto mucho más fácil de entender y mantener a medida que crece.

10.2 Uso de Routers para separar módulos

Qué es un Router

express.Router() permite agrupar rutas relacionadas y montarlas en la aplicación principal. Es la forma estándar de modularizar Express.

routes/usuarioRoutes.js

const express = require('express');
const router = express.Router();

// GET /api/usuarios
router.get('/', (req, res) => {
  res.json({ mensaje: 'Lista de usuarios' });
});

// GET /api/usuarios/:id
router.get('/:id', (req, res) => {
  res.json({ id: req.params.id });
});

module.exports = router;

Montar el router en la app

const express = require('express');
const app = express();

const usuarioRoutes = require('./routes/usuarioRoutes');

// Todas las rutas del router quedan bajo /api/usuarios
app.use('/api/usuarios', usuarioRoutes);

app.listen(3000);
Cada módulo gestiona sus propias rutas y se monta con un prefijo, manteniendo la aplicación principal limpia.

10.3 CORS y seguridad básica

Qué es CORS

CORS (Cross-Origin Resource Sharing) controla qué dominios pueden acceder a tu API. Por defecto, un navegador bloquea las peticiones a otros orígenes.

npm install cors
const express = require('express');
const cors = require('cors');
const app = express();

// Permitir todos los orígenes (solo para desarrollo)
app.use(cors());

// Permitir solo orígenes específicos
app.use(cors({
  origin: ['http://localhost:3001', 'https://miapp.com']
}));

app.listen(3000);

Otras medidas de seguridad

  • helmet: Añade cabeceras de seguridad HTTP
  • rate limiting: Limita peticiones por usuario/IP
  • Validación: Valida siempre los datos de entrada
  • Variables de entorno: Nunca expongas secretos
npm install helmet
const helmet = require('helmet');
app.use(helmet());

10.4 Manejo de errores global

Centralizar los errores

Un middleware de error global captura las excepciones y devuelve respuestas estructuradas sin exponer detalles internos.

const express = require('express');
const app = express();

// Ruta que lanza un error asíncrono
app.get('/dividir', (req, res) => {
  const { a, b } = req.query;
  const numero = Number(a) / Number(b);
  if (!isFinite(numero)) {
    const err = new Error('División no válida');
    err.status = 400;
    throw err;
  }
  res.json({ resultado: numero });
});

// Rutas no encontradas -> 404
app.use((req, res) => {
  res.status(404).json({ error: 'Ruta no encontrada' });
});

// Middleware de error global
app.use((err, req, res, next) => {
  console.error('Error:', err.message);
  res.status(err.status || 500).json({
    error: err.status ? err.message : 'Error interno del servidor'
  });
});

app.listen(3000);
En producción, evita devolver mensajes internos del error; registra los detalles en el servidor y responde con un mensaje genérico al cliente.

10.6 Buenas prácticas

Recomendaciones para producción

  • Usa dotenv para configuración y mantén los secretos fuera del código
  • Añade CORS y helmet para una capa base de seguridad
  • Centraliza el manejo de errores en un middleware global
  • Valida todas las entradas antes de procesarlas
  • Organiza el código en routers, controllers y models
  • Escribe logs útiles (morgan) y un manejo ante fallos
  • Define scripts limpios en package.json (start, dev)

Comando para producción

npm install --production

Este comando instala solo las dependencias de producción, sin las de desarrollo, reduciendo el tamaño de la imagen desplegada.

Combinar buena estructura, seguridad y logs hace que la aplicación sea robusta, mantenible y lista para escalar.
