8.1 Principios de una API REST

Qué es REST

REST (Representational State Transfer) es un estilo arquitectónico para construir APIs. Se basa en recursos identificados por URLs y el uso de los métodos HTTP estándar para operar sobre ellos.

Principios fundamentales

PrincipioDescripción
RecursosTodo es un recurso (usuarios, productos)
URLs limpiasNombres en plural y sin verbos
Métodos HTTPGET, POST, PUT, DELETE para cada operación
Sin estadoCada petición es independiente
JSONFormato estándar para intercambio de datos

Ejemplo de endpoints REST

GET    /usuarios        -> listar
GET    /usuarios/1      -> obtener uno
POST   /usuarios        -> crear
PUT    /usuarios/1      -> actualizar
DELETE /usuarios/1      -> eliminar

8.2 Diseño de endpoints REST

Buenas prácticas en el diseño

  • Usa sustantivos en plural para los recursos (/productos, no /obtenerProductos)
  • Anida recursos con profundidad razonable (/usuarios/1/pedidos)
  • Usa query string para filtros y paginación
  • Devuelve códigos de estado coherentes
  • Responde siempre en JSON

Ejemplo de API bien diseñada

const express = require('express');
const router = express.Router();

// GET /api/productos?categoria=x&pagina=1
router.get('/productos', (req, res) => {
  const { categoria, pagina = 1 } = req.query;
  res.json({ categoria, pagina, resultados: [] });
});

// GET /api/productos/:id
router.get('/productos/:id', (req, res) => {
  res.json({ id: req.params.id });
});

module.exports = router;
Mantén las URLs simples y consistentes. La legibilidad para otros desarrolladores es tan importante como la funcionalidad.

8.3 Responder en JSON

Formato de respuestas JSON

Las APIs REST normalmente responden en JSON. res.json() establece automáticamente la cabecera Content-Type: application/json.

app.get('/usuarios/:id', (req, res) => {
  // Respuesta exitosa con datos
  res.status(200).json({
    id: 1,
    nombre: 'Ana',
    email: 'ana@example.com'
  });
});

app.get('/error', (req, res) => {
  // Respuesta de error estructurada
  res.status(500).json({
    error: 'Error interno',
    detalle: 'No se pudo procesar la solicitud'
  });
});

Estructura JSON de respuesta recomendada

{
  "success": true,
  "data": { "id": 1, "nombre": "Ana" },
  "mensaje": "Usuario obtenido"
}
Ser consistente con la estructura de las respuestas facilita el consumo de la API desde el frontend.

8.4 Manejo de errores en la API

Middleware de error centralizado

Un buen manejo de errores devuelve respuestas útiles y estructuradas. Puedes crear un middleware de error global.

const express = require('express');
const app = express();

// Rutas normales
app.get('/usuario/:id', (req, res) => {
  const id = req.params.id;
  if (id !== '1') {
    const err = new Error('Usuario no encontrado');
    err.status = 404;
    throw err;
  }
  res.json({ id: 1, nombre: 'Ana' });
});

// Middleware de error global (4 parámetros)
app.use((err, req, res, next) => {
  const status = err.status || 500;
  res.status(status).json({
    error: err.message || 'Error interno del servidor',
    estado: status
  });
});

app.listen(3000);
El middleware de error global debe ser el último y tener exactamente cuatro parámetros (err, req, res, next).

8.5 Validación de datos

Por qué validar

La validación garantiza que los datos que llegan a tu API sean correctos, evitando errores y datos corruptos en la base de datos.

Validación manual

app.use(express.json());

app.post('/usuarios', (req, res) => {
  const { nombre, email } = req.body;

  const errores = [];
  if (!nombre || nombre.trim() === '') {
    errores.push('El nombre es obligatorio');
  }
  if (!email || !email.includes('@')) {
    errores.push('Email inválido');
  }

  if (errores.length > 0) {
    return res.status(400).json({ errores });
  }

  res.status(201).json({ mensaje: 'Usuario válido', nombre, email });
});

Validación con librerías

npm install express-validator
const { body, validationResult } = require('express-validator');

app.post(
  '/registro',
  [
    body('email').isEmail().withMessage('Email inválido'),
    body('password').isLength({ min: 6 }).withMessage('Mínimo 6 caracteres')
  ],
  (req, res) => {
    const errores = validationResult(req);
    if (!errores.isEmpty()) {
      return res.status(400).json({ errores: errores.array() });
    }
    res.json({ mensaje: 'Registro válido' });
  }
);

8.6 Consumir la API con fetch y axios

Usar fetch (nativo del navegador)

// GET con fetch
fetch('http://localhost:3000/usuarios')
  .then(res => res.json())
  .then(data => console.log(data));

// POST con fetch
fetch('http://localhost:3000/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Carlos', email: 'carlos@example.com' })
}).then(res => res.json())
  .then(data => console.log(data));

Usar axios (librería)

npm install axios
const axios = require('axios');

async function obtenerUsuarios() {
  try {
    const { data } = await axios.get('http://localhost:3000/usuarios');
    console.log(data);
  } catch (error) {
    console.error('Error al consumir la API:', error.response?.status);
  }
}

obtenerUsuarios();
fetch está integrado en el navegador y en Node 18+, mientras que axios ofrece una API más concisa y manejo de errores integrado.

Resumen

**Lo que aprendiste en esta sección:** - REST se basa en recursos, URLs limpias y métodos HTTP - Los endpoints se diseñan con sustantivos en plural y filtros por query - res.json() responde en formato JSON con el estado adecuado - Se usa un middleware de error global para respuestas consistentes - La validación (manual o con express-validator) evita datos inválidos - La API se consume con fetch o axios desde el frontend
