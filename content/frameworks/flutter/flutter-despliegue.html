1.1 Build de release

¿Qué es un build de release?

La versión release es la compilación optimizada y lista para producción. Es más pequeña, rápida y sin las herramientas de desarrollo.

Diferencias entre debug y release

AspectoDebugRelease
TamañoGrandePequeño
RendimientoLentoÓptimo
Hot ReloadSíNo
DepuraciónCompletaLimitada
OptimizaciónNingunaMáxima (AOT)

Comando de build

# Android
flutter build apk --release

# Android - versión de aplicación
flutter build appbundle --release

# iOS
flutter build ios --release

# Web
flutter build web --release

# Windows desktop
flutter build windows --release

1.2 flutter build apk

Tipos de APK

ApkDescripción
app-release.apkContiene código para todas las arquitecturas
app-release.apk (split)Un APK por arquitectura (más pequeño)

Construir el APK

# Generar APK estándar
flutter build apk --release

# Resultado:
# build/app/outputs/flutter-apk/app-release.apk

# Generar APK dividido por arquitectura
flutter build apk --split-per-abi

# Resultado:
# build/app/outputs/flutter-apk/app-armeabi-v7a-release.apk
# build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
# build/app/outputs/flutter-apk/app-x86_64-release.apk

Variables de compilación

# Compilaciónes para diferentes arquitecturas
flutter build apk --target-platform android-arm64
flutter build apk --target-platform android-arm
flutter build apk --target-platform android-x64

1.3 pubspec.yaml y dependencias

Estructura de pubspec.yaml

El archivo pubspec.yaml define la configuración del paquete, incluyendo metadatos y dependencias.

name: mi_aplicacion
description: Descripción de mi aplicación
publish_to: 'none'
version: 1.0.0+5

environment:
  sdk: '>=3.0.0 <4.0.0'

dependencies:
  flutter:
    sdk: flutter
  http: ^1.1.0
  provider: ^6.1.0
  # Recursos locales
  cupertino_icons: ^1.0.2

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^3.0.0

flutter:
  uses-material-design: true

Diccionario de versiones

SintaxisSignificado
^1.2.01.x.x compatible hacia arriba
1.2.0Versión exacta
>=1.0.0 <2.0.0Rango de versiones
anyCualquier versión

Comandos útiles de pub

# Instalar dependencias
flutter pub get

# Actualizar dependencias
flutter pub upgrade

# Obtener un paquete nuevo
flutter pub add nombre_paquete

# Eliminar un paquete
flutter pub remove nombre_paquete

1.4 flutter_dotenv

¿Qué es flutter_dotenv?

flutter_dotenv permite cargar variables de entorno desde un archivo .env. Así almacenas claves de API, URLs de servidores y credenciales fuera de tu código.

Instalación

flutter pub add flutter_dotenv

Archivo .env

API_URL=https://api.example.com
API_KEY=mi_clave_secreta_123
DEBUG=true

Configuración en pubspec.yaml

flutter:
  uses-material-design: true
  assets:
    - .env

Uso en la aplicación

import 'package:flutter/material.dart';
import 'package:flutter_dotenv/flutter_dotenv.dart';

Future<void> main() async {
  // Cargar variables de entorno
  await dotenv.load(fileName: ".env");
  runApp(MiApp());
}

class MiApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    // Acceder a las variables
    final apiUrl = dotenv.env['API_URL'];
    final apiKey = dotenv.env['API_KEY'];

    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: Text('URL: $apiUrl'),
        ),
      ),
    );
  }
}
Nunca subas el archivo .env a un repositorio público. Añádelo a .gitignore para proteger tus credenciales.

1.5 Publicar en tiendas

Google Play Store

Pasos para publicar una app Flutter en Google Play:

  1. Crear una cuenta de desarrollador de Google (pago único)
  2. Generar una Keystore y firmar tu APK/AAB
  3. Dar de alta la app en la Play Console
  4. Completar ficha, fotos y política de privacidad
  5. Subir el App Bundle (AAB) y publicar

Generar Keystore y firmar

# Generar Keystore (Linux/macOS)
keytool -genkey -v -keystore ~/upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload

App Store (iOS)

Pasos para publicar en la App Store:

  1. Crear cuenta de desarrollador de Apple (tarifa anual)
  2. Configurar firma de código y certificados en Xcode
  3. Subir la app con Xcode o Transporter
  4. Completar ficha en App Store Connect
  5. Esperar revisión de Apple

Consideraciones

AspectoGoogle PlayApp Store
Costo inicialPago único $25Anual $99
RevisiónRápida (horas)Lenta (días)
FormatoAABIPA
HardwareCualquier SOSolo Mac

1.6 Buenas prácticas de despliegue

Recomendaciones antes de publicar

PrácticaDescripción
VersionadoUsa versionName y versionCode correctamente
OptimizaciónEjecuta flutter build --release con árbol de reducción
IconosGenera iconos para todas las resoluciones
SeguridadUsa flutter_dotenv para claves y secretos
LimpiezaElimina logs de debug en producción
TesteoPrueba en dispositivos reales antes de publicar

Reducción de tamaño

# Habilitar reducción de código en build.gradle
buildTypes {
    release {
        minifyEnabled true
        shrinkResources true
        proguardFiles getDefaultProguardFile('proguard-android.txt')
    }
}

# Comando de build optimizado
flutter build apk --release --obfuscate \
  --split-debug-info=build/symbols

Ejemplo: Configuración de versionado

# pubspec.yaml
name: mi_aplicacion
version: 1.2.3+45
# versionName: 1.2.3
# versionCode: 45

Checklist final

  • Probar la versión release en múltiples dispositivos
  • Verificar que las APIs y servidores usan HTTPS
  • Revisionar la política de privacidad
  • Configurar nombres de aplicación amigables
  • Subir capturas de pantalla y descripciones
  • Preparar notas de la versión

Resumen

**Lo que aprendiste en esta sección:** - El build de release está optimizado para producción - flutter build apk genera el APK de Android listo para publicar - pubspec.yaml define dependencias y configuración del proyecto - flutter_dotenv protege claves y secretos con variables de entorno - La publicación en tiendas requiere firmar y completar fichas - Las buenas prácticas incluyen versionado, seguridad y testeo
