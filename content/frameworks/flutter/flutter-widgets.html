1.1 Qué es un widget

Definición

Un widget es la unidad básica de construcción de interfaces en Flutter. Todo en Flutter es un widget: desde una etiqueta de texto hasta el diseño completo de una pantalla. Los widgets se componen en una jerarquía (árbol) para construir la UI.

Características principales

CaracterísticaDescripción
InmutablesSu configuración no cambia una vez creados
ComponiblesSe combinan para crear interfaces complejas
JerárquicosForman un árbol de widgets
DeclarativosDescribes cómo se ve la UI
ReutilizablesPuedes usarlos muchas veces

Ejemplo: Widgets básicos

import 'package:flutter/material.dart';

class Ejemplo extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Center(
      child: Text(
        'Hola mundo',
        style: TextStyle(fontSize: 24),
      ),
    );
  }
}

1.2 StatelessWidget vs StatefulWidget

Diferencias principales

AspectoStatelessWidgetStatefulWidget
EstadoNo tiene estado mutableTiene estado mutable
RebuildSolo cuando llegan datos nuevosCuando se llama a setState()
UsoUI estáticaUI dinámica e interactiva
MétodosSolo build()build() y setState()
EjemploText, Icon, IconButtonContador, Formularios, Listas

StatelessWidget

Un widget estático que no cambia su contenido internamente. Solo dibuja lo que se le pasa por parámetros.

class Titulo extends StatelessWidget {
  final String texto;

  Titulo({required this.texto});

  @override
  Widget build(BuildContext context) {
    return Text(
      texto,
      style: TextStyle(fontSize: 30, fontWeight: FontWeight.bold),
    );
  }
}

StatefulWidget

Un widget con estado mutable que puede cambiar con el tiempo.

class Contador extends StatefulWidget {
  @override
  _ContadorState createState() => _ContadorState();
}

class _ContadorState extends State<Contador> {
  int contador = 0;

  @override
  Widget build(BuildContext context) {
    return Text('Contador: $contador');
  }
}

1.3 Árbol de widgets

Jerarquía de widgets

La interfaz se construye anidando widgets. El widget principal contiene a otros, que a su vez contienen más widgets, formando un árbol de widgets.

Ejemplo: Árbol jerárquico

MaterialApp
└── Scaffold
    ├── AppBar
    │   └── Text (título)
    └── Body
        └── Column
            ├── Text (bienvenida)
            ├── Image
            ├── Row
            │   ├── Icon
            │   └── Text
            └── Button

Widgets organizadores

  • Scaffold: Estructura básica de una página
  • Column: Dispone hijos verticalmente
  • Row: Dispone hijos horizontalmente
  • Stack: Superpone hijos
  • Center: Centra a su hijo

Ejemplo: Árbol real en código

class MiPantalla extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: Text('Mi App'),
      ),
      body: Column(
        children: [
          Text('Bienvenido'),
          Row(
            children: [
              Icon(Icons.star),
              Text('Calificación: 4.5'),
            ],
          ),
        ],
      ),
    );
  }
}

1.4 Widgets básicos

Widgets fundamentales

WidgetDescripción
TextMuestra un texto con estilo
ContainerCaja con fondo, borde y padding
RowDispone hijos horizontalmente
ColumnDispone hijos verticalmente
ImageMuestra una imagen
IconMuestra un icono
ButtonBotón interactivo

Ejemplo: Uso de widgets básicos

import 'package:flutter/material.dart';

class WidgetsBasicos extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text('Texto simple'),
        
        Container(
          padding: EdgeInsets.all(16),
          color: Colors.blue,
          child: Text('Contenedor azul'),
        ),
        
        Row(
          children: [
            Icon(Icons.favorite, color: Colors.red),
            Text('Me gusta'),
          ],
        ),
        
        ElevatedButton(
          onPressed: () {},
          child: Text('Presionar'),
        ),
      ],
    );
  }
}

1.5 Método build

¿Qué es build()?

El método build() es el corazón de cada widget. Define qué se dibuja en pantalla. Se ejecuta cada vez que el widget necesita ser reconstruido.

Características de build()

  • Debe ser puro: No debe tener efectos secundarios
  • Devuelve un Widget: Siempre retorna el árbol de widgets
  • Recibe BuildContext: Contexto para acceder al árbol
  • Se ejecuta frecuentemente: No hagas operaciones costosas aquí

Ejemplo: Uso de build()

class MiWidget extends StatelessWidget {
  final String nombre;
  final int edad;

  MiWidget({required this.nombre, required this.edad});

  @override
  Widget build(BuildContext context) {
    // Aquí se construye la UI
    return Card(
      child: Padding(
        padding: EdgeInsets.all(16),
        child: Column(
          children: [
            Text(nombre, style: TextStyle(fontWeight: FontWeight.bold)),
            SizedBox(height: 8),
            Text('Edad: $edad'),
          ],
        ),
      ),
    );
  }
}

Buenas prácticas

  • Mantén build() simple y legible
  • Extrae widgets complejos a métodos o clases
  • Evita cálculos pesados dentro de build()

1.6 Componer widgets

Composición de widgets

La composición es la práctica de unir widgets pequeños para crear widgets más complejos. Así construimos toda la interfaz de manera modular.

Ejemplo: Composición práctica

// Widget base: Avatar
class Avatar extends StatelessWidget {
  final String nombre;

  Avatar({required this.nombre});

  @override
  Widget build(BuildContext context) {
    return CircleAvatar(
      radius: 20,
      child: Text(nombre[0]),
    );
  }
}

// Componiendo Avatar en una tarjeta de usuario
class TarjetaUsuario extends StatelessWidget {
  final String nombre;

  TarjetaUsuario({required this.nombre});

  @override
  Widget build(BuildContext context) {
    return Row(
      children: [
        Avatar(nombre: nombre),
        SizedBox(width: 12),
        Text(nombre),
      ],
    );
  }
}

// Usar en la pantalla principal
class Pantalla extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TarjetaUsuario(nombre: 'Ana'),
        TarjetaUsuario(nombre: 'Carlos'),
        TarjetaUsuario(nombre: 'Luis'),
      ],
    );
  }
}

Ventajas de la composición

  • Reutilización: El mismo widget usado varias veces
  • Mantenimiento: Cambiar un componente actualiza todos sus usos
  • Legibilidad: Código organizado y claro
  • Testing: Puedes probar cada pieza por separado

Resumen

**Lo que aprendiste en esta sección:** - Un widget es la unidad básica de UI en Flutter - StatelessWidget es estático y StatefulWidget tiene estado mutable - Los widgets forman un árbol jerárquico - Text, Container, Row y Column son widgets fundamentales - build() define cómo se dibuja cada widget - La composición permite construir UI complejas a partir de piezas simples
