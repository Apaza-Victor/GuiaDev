1.1 Navigator y rutas

¿Qué es Navigator?

Navigator es un widget de Flutter que gestiona un conjunto de pantallas apiladas (una pila de rutas). Permite navegar entre pantallas con push (agregar) y pop (quitar).

Concepto de pila

La navegación funciona como una pila (stack): La pantalla actual está arriba. Con push agregas una pantalla al tope y con pop la quitas para volver a la anterior.

Rutas

ConceptoDescripción
Ruta (Route)Representa una pantalla
MaterialPageRouteRuta con animación de Material Design
pushAbre una nueva pantalla
popCierra la pantalla actual
pushNamedAbre una ruta definida por nombre

Ejemplo: Navegación básica

// Pantalla principal
class PantallaInicio extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Inicio')),
      body: Center(
        child: ElevatedButton(
          onPressed: () {
            // Abrir nueva pantalla
            Navigator.push(
              context,
              MaterialPageRoute(builder: (context) => PantallaDetalle()),
            );
          },
          child: Text('Ir al detalle'),
        ),
      ),
    );
  }
}

// Pantalla de detalle
class PantallaDetalle extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Detalle')),
      body: Center(
        child: ElevatedButton(
          onPressed: () {
            // Volver a la pantalla anterior
            Navigator.pop(context);
          },
          child: Text('Volver'),
        ),
      ),
    );
  }
}

1.2 push y pop

Métodos principales

MétodoFunción
Navigator.push()Agrega una pantalla a la pila
Navigator.pop()Quita la pantalla superior de la pila
Navigator.pop(context, resultado)Vuelve devolviendo un resultado
Navigator.pushReplacement()Reemplaza la pantalla actual

Devolver resultados con pop

puedes devolver un valor desde la pantalla que se cierra con pop():

// Pantalla que devuelve un resultado
class PantallaOpciones extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Elige opción')),
      body: Column(
        children: [
          ListTile(
            title: Text('Opción A'),
            onTap: () => Navigator.pop(context, 'A'),
          ),
          ListTile(
            title: Text('Opción B'),
            onTap: () => Navigator.pop(context, 'B'),
          ),
        ],
      ),
    );
  }
}

// Llamada desde la pantalla anterior (async)
Future<void> abrirOpciones(BuildContext context) async {
  final resultado = await Navigator.push(
    context,
    MaterialPageRoute(builder: (_) => PantallaOpciones()),
  );

  print('Elegiste: $resultado'); // 'A' o 'B'
}

1.3 Rutas nombradas

¿Qué son las rutas nombradas?

Las rutas nombradas permiten definir todas las pantallas de la app en un solo lugar y navegar a ellas por nombre, evitando importarlas en cada archivo.

Definir rutas en MaterialApp

void main() {
  runApp(MiApp());
}

class MiApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      initialRoute: '/',
      routes: {
        '/': (context) => PantallaInicio(),
        '/login': (context) => PantallaLogin(),
        '/perfil': (context) => PantallaPerfil(),
      },
    );
  }
}

// Navegar por nombre
Navigator.pushNamed(context, '/login');
Navigator.pushNamed(context, '/perfil');

Rutas iniciales y fallback

MaterialApp(
  initialRoute: '/',
  routes: {
    '/': (context) => PantallaInicio(),
    '/login': (context) => PantallaLogin(),
  },
  onGenerateRoute: (settings) {
    // Manejar rutas dinámicas
    return MaterialPageRoute(
      builder: (context) => PantallaError(), // Ruta no encontrada
    );
  },
)

1.4 Pasar argumentos

Pasar datos entre pantallas

Es muy común necesitar pasar datos de una pantalla a otra, como IDs de artículos, objetos de usuario, etc.

// Modelo de datos
class Usuario {
  final String nombre;
  final int edad;

  Usuario({required this.nombre, required this.edad});
}

// Pantalla que recibe el dato
class PantallaDetalle extends StatelessWidget {
  final Usuario usuario;

  PantallaDetalle({required this.usuario});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(usuario.nombre)),
      body: Center(
        child: Text('Edad: ${usuario.edad}'),
      ),
    );
  }
}

// Navegar pasando el argumento
void abrirDetalle(BuildContext context) {
  final usuario = Usuario(nombre: 'Ana', edad: 25);

  Navigator.push(
    context,
    MaterialPageRoute(
      builder: (context) => PantallaDetalle(usuario: usuario),
    ),
  );
}

1.5 Navigator 2.0

¿Qué es Navigator 2.0?

Navigator 2.0 es el nuevo sistema de navegación declarativo de Flutter. A diferencia del Navigator clásico (imperativo), el estado de navegación se controla desde el código, facilitando la persistencia del estado y la navegación basada en URLs (para web).

Diferencias entre versiones

AspectoNavigator 1.0Navigator 2.0
EnfoqueImperativoDeclarativo
Controlpush/pop directoEstado controlado en código
URLs webNo soportadoSoportado
PersistenciaLimitadaFácil de persistir
ComplejidadSimpleMás complejo

Consejo práctico

Para la mayoría de las apps, el Navigator clásico con push/pop es suficiente. Navigator 2.0 es útil cuando necesitas soporte web con URLs o sincronizar navegación con el estado del sistema.

// Concepto de Navigator 2.0 (declarativo)
// La lista de rutas se deriva del estado actual
final List<Page> _pages = [
  MaterialPage(child: PantallaInicio()),
  if (_estadoLogueado) MaterialPage(child: PantallaPerfil()),
  if (_verDetalle) MaterialPage(child: PantallaDetalle(id: _id)),
];

Navigator(
  pages: _pages, // Lista de páginas actuales
  onPopPage: (route, result) => route.didPop(result),
)

1.6 Ejemplo práctico de navegación

Flujo completo: lista a detalle

Ejemplo típico: una lista de productos donde cada elemento navega a su página de detalle pasando el producto seleccionado.

// Modelo
class Producto {
  final String nombre;
  final double precio;

  Producto({required this.nombre, required this.precio});
}

// Pantalla lista
class ListaProductos extends StatelessWidget {
  final List<Producto> productos = [
    Producto(nombre: 'Laptop', precio: 999.99),
    Producto(nombre: 'Mouse', precio: 29.99),
    Producto(nombre: 'Teclado', precio: 89.99),
  ];

  @override
  Widget build(BuildContext context) {
    return ListView.builder(
      itemCount: productos.length,
      itemBuilder: (context, indice) {
        final producto = productos[indice];
        return ListTile(
          leading: Icon(Icons.shopping_bag),
          title: Text(producto.nombre),
          subtitle: Text('\$${producto.precio}'),
          onTap: () {
            Navigator.push(
              context,
              MaterialPageRoute(
                builder: (_) => DetalleProducto(producto: producto),
              ),
            );
          },
        );
      },
    );
  }
}

// Pantalla detalle
class DetalleProducto extends StatelessWidget {
  final Producto producto;

  DetalleProducto({required this.producto});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(producto.nombre)),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Icon(Icons.shopping_bag, size: 100),
            SizedBox(height: 16),
            Text(producto.nombre, style: TextStyle(fontSize: 24)),
            SizedBox(height: 8),
            Text('\$${producto.precio}', style: TextStyle(fontSize: 20)),
          ],
        ),
      ),
    );
  }
}
Siempre devuelve los datos mediante pop(resultado) si la pantalla que se cierra produce información útil para la anterior.

Resumen

**Lo que aprendiste en esta sección:** - Navigator gestiona una pila de pantallas - push agrega una pantalla y pop la quita - Puedes devolver resultados con pop(context, valor) - Las rutas nombradas centralizan la navegación por nombre - Puedes pasar argumentos a las pantallas con constructores - Navigator 2.0 es declarativo y útil para web y estado complejo
