1.1 Qué es el estado

Definición

Estado es la información que puede cambiar durante la vida de la aplicación y que afecta lo que se muestra en pantalla. Por ejemplo: un contador, la posición de scroll, los datos cargados de una API o la selección del usuario.

Tipos de estado

TipoDescripciónEjemplo
Estado localPertenece a un solo widgetContador, checkbox
Estado compartidoUsado por varios widgetsDatos de sesión de usuario
Estado persistenteSe guarda en disco o base de datosPreferencias, historial

Ejemplo: Estado local en un widget

class EstadoEjemplo extends StatefulWidget {
  @override
  _EstadoEjemploState createState() => _EstadoEjemploState();
}

class _EstadoEjemploState extends State<EstadoEjemplo> {
  bool meGusta = false; // Estado local

  @override
  Widget build(BuildContext context) {
    return IconButton(
      icon: Icon(meGusta ? Icons.favorite : Icons.favorite_border),
      onPressed: () {
        setState(() {
          meGusta = !meGusta;
        });
      },
    );
  }
}

1.2 setState()

¿Qué es setState()?

setState() es un método de StatefulWidget que le dice a Flutter que el estado del widget cambió y que debe reconstruir la UI.

Cómo funciona

import 'package:flutter/material.dart';

class ContadorApp extends StatefulWidget {
  @override
  _ContadorAppState createState() => _ContadorAppState();
}

class _ContadorAppState extends State<ContadorApp> {
  int contador = 0;

  void incrementar() {
    setState(() {
      contador++; // Cambiamos el estado
    });
    // La UI se reconstruye automáticamente
  }

  void decrementar() {
    setState(() {
      contador--;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text('Contador: $contador', style: TextStyle(fontSize: 32)),
        Row(
          children: [
            ElevatedButton(
              onPressed: incrementar,
              child: Text('+1'),
            ),
            SizedBox(width: 16),
            ElevatedButton(
              onPressed: decrementar,
              child: Text('-1'),
            ),
          ],
        ),
      ],
    );
  }
}

Reglas de setState()

  • Solo se usa en un StatefulWidget (en la clase State)
  • Cambia el valor del estado antes de cerrar el bloque
  • Se puede llamar dentro de callbacks y eventos
  • Llamarlo sin cambios de estado es innecesario

1.3 Interacción con el usuario

Widgets interactivos

WidgetUsoCallback
ButtonAccionesonPressed
SwitchEncender/apagaronChanged
CheckboxSelección múltipleonChanged
SliderValores numéricosonChanged
TextFieldEntrada de textoonChanged
RadioSelección únicaonChanged

Ejemplo: Interacción con varios widgets

class Configuracion extends StatefulWidget {
  @override
  _ConfiguracionState createState() => _ConfiguracionState();
}

class _ConfiguracionState extends State<Configuracion> {
  bool notificaciones = true;
  double volumen = 0.5;
  String tema = 'Claro';

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        SwitchListTile(
          title: Text('Notificaciones'),
          value: notificaciones,
          onChanged: (valor) {
            setState(() {
              notificaciones = valor;
            });
          },
        ),
        ListTile(
          title: Text('Volumen'),
          trailing: Slider(
            value: volumen,
            onChanged: (valor) {
              setState(() {
                volumen = valor;
              });
            },
          ),
        ),
        RadioListTile(
          title: Text('Tema claro'),
          value: 'Claro',
          groupValue: tema,
          onChanged: (valor) {
            setState(() {
              tema = valor.toString();
            });
          },
        ),
      ],
    );
  }
}

1.4 Estado en aplicaciones pequeñas

Gestión de estado para apps simples

Para aplicaciones pequeñas, el estado local con setState() es suficiente. No necesitas bibliotecas externas para manejar el estado básico.

Cuándo usar setState()

  • El estado pertenece a un solo widget
  • La app es pequeña y simple
  • No compartes mucho estado entre pantallas
  • Quieres una solución rápida y directa

Ejemplo: App de lista de tareas con setState

class ListaTareas extends StatefulWidget {
  @override
  _ListaTareasState createState() => _ListaTareasState();
}

class _ListaTareasState extends State<ListaTareas> {
  final List<String> tareas = [];
  final TextEditingController controlador = TextEditingController();

  void agregarTarea() {
    if (controlador.text.isNotEmpty) {
      setState(() {
        tareas.add(controlador.text);
        controlador.clear();
      });
    }
  }

  void eliminarTarea(int indice) {
    setState(() {
      tareas.removeAt(indice);
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Mis tareas')),
      body: Column(
        children: [
          Padding(
            padding: EdgeInsets.all(16),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: controlador,
                    decoration: InputDecoration(hintText: 'Nueva tarea'),
                  ),
                ),
                IconButton(
                  icon: Icon(Icons.add),
                  onPressed: agregarTarea,
                ),
              ],
            ),
          ),
          Expanded(
            child: ListView.builder(
              itemCount: tareas.length,
              itemBuilder: (context, indice) {
                return ListTile(
                  title: Text(tareas[indice]),
                  trailing: IconButton(
                    icon: Icon(Icons.delete),
                    onPressed: () => eliminarTarea(indice),
                  ),
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}

1.5 Estado en aplicaciones grandes

Limitaciones de setState()

En apps grandes, el estado compartido entre muchas pantallas se vuelve difícil de manejar solo con setState(). Se propagan demasiados callbacks y el código se complica.

Soluciones para estado complejo

PaqueteDescripción
ProviderSimple y recomendado por Flutter para comenzar
RiverpodMejora de Provider, más seguro y testable
BlocSeparación estricta en capas de lógica y UI
GetXTodo en uno: estado, navegación y DI

Ejemplo: Concepto con Provider (pubspec.yaml)

dependencies:
  flutter:
    sdk: flutter
  provider: ^6.1.0

Cuándo migrar a una solución global

  • Múltiples pantallas comparten los mismos datos
  • El estado se actualiza desde varios lugares
  • Necesitas persistir o sincronizar datos en tiempo real
  • El código con callbacks se vuelve inmanejable

1.6 Buenas prácticas

Recomendaciones para manejar el estado

PrácticaDescripción
Minimiza setState()Actualiza solo lo necesario
InmutabilidadCrea nuevas instancias, no modifiques listas en lugar
Widgets pequeñosDivide la UI para limitar las reconstrucciones
Evita lógica en build()Mueve el cálculo a métodos
Usa constWidgets constantes se construyen una sola vez

Ejemplo: Actualización segura de listas

// Correcto: crear una nueva lista al modificar
void agregarItem(String item) {
  setState(() {
    items = [...items, item]; // Nueva lista
  });
}

// Correcto: eliminar creando nueva lista
void eliminarItem(int indice) {
  setState(() {
    items = items.where((_) => true).skip(indice).toList();
  });
}

// Usar const para widgets que no cambian
const Text('Este texto nunca cambia')

Consejo final

Comienza siempre con setState() porque es simple y directo. Solo migra a Provider, Bloc u otra solución cuando el proyecto realmente lo necesite.

---

Resumen

**Lo que aprendiste en esta sección:** - El estado es la información que cambia y afecta la UI - setState() notifica a Flutter que el estado cambió y reconstruye - Solo se usa setState() dentro de un StatefulWidget - Los widgets interactivos usan callbacks como onPressed y onChanged - Para apps pequeñas, setState() es suficiente - Para apps grandes, existen soluciones como Provider, Bloc y Riverpod
