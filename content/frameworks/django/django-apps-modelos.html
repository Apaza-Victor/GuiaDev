3.1 Crear una aplicación con startapp

Qué es una aplicación

Una aplicación (app) es un módulo reutilizable dentro del proyecto que agrupa modelos, vistas y templates de una funcionalidad concreta. Por ejemplo: blog, tienda o usuarios.

Crear la aplicación

# Desde la carpeta del proyecto (la de manage.py)
python manage.py startapp blog

Estructura generada

blog/
├── migrations/
│   └── __init__.py        # Control de migraciones
├── __init__.py
├── admin.py               # Configuración del admin
├── apps.py                # Configuración de la app
├── models.py              # Modelos (tablas)
├── tests.py               # Tests
└── views.py               # Vistas

Registrar la aplicación en el proyecto

# settings.py
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "blog",  # Se agrega la nueva app
]
Si no registras la app en `INSTALLED_APPS`, Django no ejecutará sus migraciones ni reconocerá sus modelos.

3.2 Qué es un modelo

Definición

Un modelo es una clase de Python que representa una tabla de la base de datos. Cada atributo de la clase es una columna y cada instancia una fila. Django traduce las clases a SQL automáticamente gracias a su ORM.

Modelo de ejemplo

# blog/models.py
from django.db import models

class Articulo(models.Model):
    titulo = models.CharField(max_length=200)
    contenido = models.TextField()
    publicado = models.BooleanField(default=False)
    fecha_creacion = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.titulo

Convenciones

  • Los nombres de las clases se escriben en PascalCase (singular)
  • Cada modelo hereda de models.Model
  • Django agrega automáticamente un campo id si no defines una clave primaria
  • __str__ devuelve una representación legible para el admin y la consola

3.3 Campos de modelos

Campos más comunes

CampoTipo de datoUso típico
CharFieldTexto cortoTítulos, nombres, slugs
TextFieldTexto largoContenidos de artículos
IntegerFieldEnteroConteos, cantidades
DecimalFieldDecimal exactoPrecios y montos
FloatFieldFlotanteMediciones aproximadas
BooleanFieldVerdadero/FalsoFlags, estados activos
DateTimeFieldFecha y horaFechas de creación
DateFieldFechaFechas de nacimiento

ManyToManyFieldRelación muchos a muchosEtiquetas de un artículo

Parámetros comunes

titulo = models.CharField(
    max_length=200,          # Longitud máxima (obligatorio en CharField)
    null=False,              # No permite valor NULL en BD
    blank=False,             # El formulario lo exige
    default="Sin título",    # Valor por defecto
    unique=True,             # No permite duplicados
)
Diferencia importante: `null` se refiere a la base de datos (valor NULL) y `blank` se refiere a los formularios (campo obligatorio o no).

3.4 Migraciones: makemigrations y migrate

Qué son las migraciones

Las migraciones son archivos que describen los cambios de los modelos (crear tablas, agregar columnas, etc.). Permiten versionar el esquema de la base de datos.

Paso a paso

# 1. Generar la migración según los modelos
python manage.py makemigrations
# Salida:
# Migrations for 'blog':
#   blog/migrations/0001_initial.py

# 2. Ver el SQL que se ejecutará
python manage.py sqlmigrate blog 0001

# 3. Aplicar la migración a la base de datos
python manage.py migrate
# Operations to perform:
#   Apply all migrations: admin, auth, blog, contenttypes, sessions
# Running migrations:
#   Applying blog.0001_initial... OK
ComandoQué hace
makemigrationsDetecta cambios en los modelos y crea el archivo de migración
sqlmigrateMuestra el SQL que se va a ejecutar sin aplicarlo
migrateAplica las migraciones pendientes a la base de datos
showmigrationsLista el estado de las migraciones
Cada vez que modifiques un campo o agregues un modelo nuevo, ejecuta `makemigrations` y luego `migrate`.

3.5 El admin de Django

Qué es

El admin de Django es un panel de administración automático que se genera a partir de tus modelos. Te permite crear, editar y eliminar registros sin escribir código.

Crear un superusuario

# Crear usuario con permisos de administración
python manage.py createsuperuser
# Username: admin
# Email address: admin@ejemplo.com
# Password: ********

Registrar un modelo

# blog/admin.py
from django.contrib import admin
from .models import Articulo

admin.site.register(Articulo)

Acceder al panel

# Con el servidor corriendo:
python manage.py runserver

Visita http://127.0.0.1:8000/admin/ e inicia sesión con el superusuario. Ahí verás tus registros listos para gestionar.

3.6 Ejemplo: modelo completo de un blog

Modelos de un blog con categorías y comentarios

# blog/models.py
from django.db import models
from django.utils import timezone

class Categoria(models.Model):
    nombre = models.CharField(max_length=100, unique=True)

    def __str__(self):
        return self.nombre

class Articulo(models.Model):
    titulo = models.CharField(max_length=200)
    slug = models.SlugField(unique=True)
    contenido = models.TextField()
    publicado = models.BooleanField(default=False)
    fecha_publicacion = models.DateTimeField(default=timezone.now)
    categoria = models.ForeignKey(
        Categoria,
        on_delete=models.CASCADE,
        related_name="articulos",
    )
    etiquetas = models.ManyToManyField("Etiqueta", blank=True)

    def __str__(self):
        return self.titulo

class Etiqueta(models.Model):
    nombre = models.CharField(max_length=50)

    def __str__(self):
        return self.nombre

Ciclo completo

# Comandos en orden:
python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
Con solo estos comandos ya tendrás tres tablas gestionables desde el admin: Categoria, Articulo y Etiqueta.
