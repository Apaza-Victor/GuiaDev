7.1 Qué son los formularios en Django

Definición

Los formularios de Django permiten definir campos, validar datos y renderizar HTML de forma declarativa. Combinan la entrada del usuario con la lógica de validación y, si lo deseas, la persistencia en la base de datos.

Qué aportan

VentajaDescripción
Validación automáticaComprueba tipos, longitudes y formatos
Renderizado de HTMLGenera los inputs con el formato adecuado
Errores integradosMuestra mensajes de error por campo
Seguridad CSRFTrabaja con la protección integrada
ReutilizaciónEl mismo formulario sirve para crear y editar

Tipos de formularios

  • forms.Form: Formulario libre, no ligado a un modelo
  • forms.ModelForm: Genera formularios a partir de un modelo

7.2 Formularios con forms.Form

Definición

# blog/forms.py
from django import forms

class FormularioContacto(forms.Form):
    nombre = forms.CharField(max_length=100)
    email = forms.EmailField()
    mensaje = forms.CharField(widget=forms.Textarea)
    suscripcion = forms.BooleanField(required=False)
    edad = forms.IntegerField(min_value=18, max_value=120)

Tipos de campo más usados

CampoValidación
CharFieldTexto con longitud máxima
EmailFieldDebe ser un email válido
IntegerFieldNúmero entero con rango
DecimalFieldDecimal con precisión
BooleanFieldCasilla de verificación
DateField / DateTimeFieldFecha en formato correcto
ChoiceFieldSelección entre opciones
FileFieldSubida de archivos

Widgets para personalizar el HTML

mensaje = forms.CharField(
    widget=forms.Textarea(attrs={
        "rows": 5,
        "class": "campo-formulario",
        "placeholder": "Escribe tu mensaje",
    })
)

7.3 Formularios con forms.ModelForm

Definición

Un ModelForm genera automáticamente los campos a partir de un modelo, incluyendo validaciones y tipos.

# blog/forms.py
from django import forms
from .models import Articulo

class FormularioArticulo(forms.ModelForm):
    class Meta:
        model = Articulo
        fields = ["titulo", "contenido", "publicado", "categoria"]
        # fields = "__all__"  # para incluir todos los campos

        widgets = {
            "contenido": forms.Textarea(attrs={"rows": 8}),
        }

Usarlo para crear o editar

# Crear un registro nuevo
form = FormularioArticulo(request.POST)
articulo = form.save()

# Editar un registro existente
form = FormularioArticulo(request.POST, instance=articulo_existente)
articulo = form.save()

# Excluir campos
class Meta:
    model = Articulo
    fields = ["titulo", "contenido"]
    # Para excluir un campo que no quieres mostrar:
    # exclude = ["slug"]
El atributo `instance` convierte el mismo formulario en una edición; sin él, crea registros nuevos.

7.4 Renderizar formularios en plantillas

Pasar el formulario a la plantilla

# blog/views.py
from django.shortcuts import render, redirect
from .forms import FormularioContacto

def contacto(request):
    if request.method == "POST":
        form = FormularioContacto(request.POST)
        if form.is_valid():
            # Procesar los datos
            print(form.cleaned_data)
            return redirect("inicio")
    else:
        form = FormularioContacto()

    return render(request, "blog/contacto.html", {"form": form})

Plantilla con el formulario

<!-- templates/blog/contacto.html -->
<form method="POST">
  {% csrf_token %}

  <!-- Renderizado simple -->
  {{ form.as_p }}

  <!-- Renderizado por campos (más control) -->
  <div>
    {{ form.nombre.label_tag }}
    {{ form.nombre }}
    {{ form.nombre.errors }}
  </div>

  <button type="submit">Enviar</button>
</form>

Métodos de renderizado

MétodoFormato
{{ form.as_p }}Cada campo en un párrafo <p>
{{ form.as_table }}Dentro de una tabla
{{ form.as_ul }}Dentro de una lista <li>

7.5 Protección CSRF

Qué es CSRF

CSRF (Cross-Site Request Forgery) es un ataque donde un tercero envía peticiones falsas en nombre de un usuario autenticado. Django genera un token único por sesión para impedirlo.

Cómo activarlo

<!-- Obligatorio dentro de formularios con metodo POST -->
<form method="POST">
  {% csrf_token %}
  <!-- ... campos ... -->
</form>

Qué genera la etiqueta

<!-- La etiqueta genera un input oculto similar a este: -->
<input type="hidden" name="csrfmiddlewaretoken" value="eRfWd8y4J5..."/>

Excepciones y buenas prácticas

  • Para APIs se usan decoradores como @csrf_exempt, pero mejor se maneja con tokens en el frontend
  • Si el token falta o no coincide, Django devuelve un error 403
  • Siempre usa {% csrf_token %} en formularios internos del sitio
Nunca desactives la protección CSRF en formularios de producción sin una estrategia de token equivalente.

7.6 Validación de datos y procesado POST

El método is_valid

form.is_valid() ejecuta todas las validaciones. Si todo es correcto, los datos limpios quedan disponibles en form.cleaned_data.

Validaciones personalizadas

# blog/forms.py
from django import forms
import re

class FormularioRegistro(forms.Form):
    usuario = forms.CharField(max_length=30)
    email = forms.EmailField()
    password = forms.CharField(widget=forms.PasswordInput)
    confirmar = forms.CharField(widget=forms.PasswordInput)

    def clean_usuario(self):
        # Validación solo para el campo "usuario"
        usuario = self.cleaned_data["usuario"]
        if not re.match(r"^[a-zA-Z0-9_]+$", usuario):
            raise forms.ValidationError(
                "El usuario solo puede tener letras, números y guión bajo"
            )
        return usuario

    def clean(self):
        # Validación global: comparar campos entre sí
        datos = self.cleaned_data
        if datos.get("password") != datos.get("confirmar"):
            raise forms.ValidationError("Las contraseñas no coinciden")
        return datos

Procesar el POST completo

# blog/views.py
from django.shortcuts import render, redirect
from .forms import FormularioRegistro

def registrar(request):
    if request.method == "POST":
        form = FormularioRegistro(request.POST)
        if form.is_valid():
            datos = form.cleaned_data
            # Aquí crearías el usuario u otros registros
            return redirect("login")
    else:
        form = FormularioRegistro()

    return render(request, "blog/registro.html", {"form": form})
Patrón clásico: si es POST y el formulario es válido se procesa y redirige (patrón PRG); si no, se vuelve a mostrar el formulario con errores.

Resumen

**Lo que aprendiste en esta sección:** - Los formularios de Django validan datos y generan HTML de forma automática - `forms.Form` para formularios libres y `forms.ModelForm` para los ligados a modelos - Renderizar con `{{ form.as_p }}` o campos individuales - Usar `{% csrf_token %}` en todo formulario POST - Validar campos con `clean_` y globalmente con `clean` - Procesar el POST con el patrón: POST + is_valid + redirigir
