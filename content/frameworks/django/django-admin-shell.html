9.1 Qué es el panel de administración

Definición

El admin de Django es una interfaz web generada automáticamente a partir de los modelos. Permite gestionar registros, usuarios y permisos sin escribir una sola línea de HTML para el panel.

Características

CaracterísticaDescripción
CRUD automáticoCrear, leer, actualizar y eliminar registros
Búsqueda y filtrosFiltra por campo y búsqueda integrada
Acceso por rolesSeparado por permisos y grupos
HistorialRegistro de cambios sobre cada objeto
PersonalizableSe puede adaptar totalmente al negocio

Acceso

# Crear el superusuario (si aún no lo tienes)
python manage.py createsuperuser

# Con el servidor activo, visita:
# http://127.0.0.1:8000/admin/

9.2 Registrar modelos en el admin

Registro básico

# blog/admin.py
from django.contrib import admin
from .models import Articulo, Categoria, Etiqueta

admin.site.register(Articulo)
admin.site.register(Categoria)
admin.site.register(Etiqueta)

Registro con decorador

# blog/admin.py
from django.contrib import admin
from .models import Articulo

@admin.register(Articulo)
class ArticuloAdmin(admin.ModelAdmin):
    pass

Orden de aparición

Los modelos registrados aparecen agrupados por la aplicación (BLOG) con el nombre legible definido en verbose_name del modelo.

El listado se mejora añadiendo en el ModelAdmin opciones como `list_display` para que el panel sea más útil.

9.3 Personalizar el admin

Opciones de ModelAdmin más usadas

# blog/admin.py
from django.contrib import admin
from .models import Articulo

@admin.register(Articulo)
class ArticuloAdmin(admin.ModelAdmin):
    # Columnas que se muestran en el listado
    list_display = ("titulo", "categoria", "publicado", "fecha_publicacion")

    # Campos por los que se puede editar directamente
    list_editable = ("publicado",)

    # Filtros laterales
    list_filter = ("publicado", "categoria", "fecha_publicacion")

    # Búsqueda
    search_fields = ("titulo", "slug", "contenido")

    # Cantidad de registros por página
    list_per_page = 20

    # Ordenar por defecto
    ordering = ("-fecha_publicacion",)

    # Campos de solo lectura
    readonly_fields = ("fecha_publicacion",)

Secciones de campos

class ArticuloAdmin(admin.ModelAdmin):
    fieldsets = (
        ("Contenido", {
            "fields": ("titulo", "slug", "contenido"),
        }),
        ("Publicación", {
            "fields": ("publicado", "fecha_publicacion", "categoria"),
        }),
    )

Ejemplo de sobrescritura de métodos

class ArticuloAdmin(admin.ModelAdmin):
    def save_model(self, request, obj, form, change):
        # Si no tiene autor y el usuario agrega el registro...
        if not obj.autor:
            obj.autor = request.user
        super().save_model(request, obj, form, change)

9.4 Shell interactivo

Qué es

El shell es una consola de Python con Django ya configurado. Sirve para probar consultas, crear datos de prueba y depurar sin levantar el servidor.

Abrir la consola

# Desde la carpeta de manage.py
python manage.py shell
# Python 3.12.0 (default, ...)
# (InteractiveConsole)
# >>>

Comandos útiles

# Crear datos de prueba
from blog.models import Articulo, Categoria

cat, _ = Categoria.objects.get_or_create(nombre="Backend")

a = Articulo.objects.create(
    titulo="Primer artículo",
    contenido="Contenido de prueba",
    publicado=True,
    categoria=cat,
)

# Consultar con Python normal
print(a.titulo)
print(a.categoria.nombre)

# Salir de la consola con exit() o Ctrl+D (Linux/Mac)
exit()
Con la sintaxis shell_plus de la librería `django-extensions` salen los modelos importados automáticamente.

9.5 Consultas y comandos en la consola

Pruebas de QuerySet en shell

python manage.py shell
from blog.models import Articulo

# Todas las consultas se pueden probar como en el ORM
Articulo.objects.count()
# 3

Articulo.objects.filter(publicado=True)
# <QuerySet [<Articulo: Primer artículo>, ...]>

Articulo.objects.get(pk=1).titulo
# 'Primer artículo'

# Shell de tipo "mejorado": ejecutar scripts enteros
from blog.models import Articulo, Categoria
for c in Categoria.objects.all():
    print(c.nombre, c.articulos.count())

Cargar dumps de datos

# Volcar los datos a un archivo JSON
python manage.py dumpdata blog --indent 2 > blog_data.json

# Cargar datos desde un archivo
python manage.py loaddata blog_data.json

Comandos de depuración

# Ver SQL generado por las consultas
python manage.py shell -e "print(str(Articulo.objects.filter(publicado=True).query))"
`dumpdata` y `loaddata` son útiles para migrar datos entre entornos o crear fixtures de prueba.

9.6 Ejemplo práctico con shell

Script completo de pruebas

python manage.py shell
from django.contrib.auth.models import User
from blog.models import Articulo, Categoria, Etiqueta

# 1. Crear usuarios de prueba
usuario, _ = User.objects.get_or_create(
    username="editor",
    defaults={"email": "editor@ejemplo.com"},
)

# 2. Crear categorías y etiquetas
backend = Categoria.objects.create(nombre="Backend")
etiqueta = Etiqueta.objects.create(nombre="Python")

# 3. Crear artículos con autor
for i in range(5):
    art = Articulo.objects.create(
        titulo=f"Artículo {i + 1}",
        contenido="Contenido de ejemplo",
        publicado=(i % 2 == 0),
        autor=usuario,
        categoria=backend,
    )
    art.etiquetas.add(etiqueta)

# 4. Verificar cuántos registros hay
print("Artículos:", Articulo.objects.count())
print("Publicados:", Articulo.objects.filter(publicado=True).count())

# 5. Salir
exit()
Este patrón es ideal para generar "datos semilla" antes de desarrollar la interfaz.

Resumen

**Lo que aprendiste en esta sección:** - El admin de Django genera un CRUD automático desde tus modelos - Registrar modelos con `admin.site.register()` o el decorador `@admin.register` - Personalizar con `list_display`, `list_filter`, `search_fields` y `fieldsets` - Usar el shell con `python manage.py shell` para probar consultas - Ejecutar consultas, crear datos de prueba y volcar datos con dumpdata/loaddata - Crear datos semilla directo desde la consola
