4.1 Qué es una vista en Django

Definición

Una vista es una función o clase que recibe una petición HTTP y devuelve una respuesta HTTP (normalmente HTML). Es el "cerebro" que conecta la URL con la lógica del negocio.

Estructura de una petición

ElementoDescripción
HttpRequestObjeto con la petición (método, datos, usuario, etc.)
HttpResponseObjeto con la respuesta (HTML, JSON, redirección)
ConvenciónUna vista siempre recibe request como primer parámetro

Tipos de vistas

  • FBV (Function Based Views): Funciones simples, ideales para lógica puntual
  • CBV (Class Based Views): Clases reutilizables, ideales para operaciones repetitivas (listar, crear, detalle)

Vista mínima

# blog/views.py
from django.http import HttpResponse

def saludo(request):
    return HttpResponse("Hola desde una vista")

---

4.2 Vistas por función (FBV)

Qué son

Las Function Based Views (FBV) son funciones de Python que reciben request y devuelven una respuesta. Son las más fáciles de leer y depurar.

Ejemplo: vista de listado

# blog/views.py
from django.shortcuts import render, get_object_or_404
from django.http import Http404
from .models import Articulo

def lista_articulos(request):
    # Solo artículos publicados
    articulos = Articulo.objects.filter(publicado=True)
    return render(request, "blog/lista.html", {
        "articulos": articulos,
    })

def detalle_articulo(request, slug):
    # Devuelve 404 si no existe
    articulo = get_object_or_404(Articulo, slug=slug)
    return render(request, "blog/detalle.html", {
        "articulo": articulo,
    })

def manejar_404(request):
    raise Http404("Página no encontrada")

Devolver distintos tipos de respuesta

# Tipos de respuesta más usados
from django.http import HttpResponse, JsonResponse
from django.shortcuts import redirect

def responder(request):
    return HttpResponse("HTML simple")              # Texto/HTML
    return JsonResponse({"ok": True})               # JSON
    return redirect("home")                          # Redirección

4.3 Vistas por clase (CBV)

Qué son

Las Class Based Views (CBV) son clases que organizan el comportamiento por métodos HTTP: get(), post(), etc. Django incluye vistas genéricas listas para usar.

Vistas genéricas más comunes

VistaFunción
ListViewListar todos los objetos de un modelo
DetailViewMostrar un objeto individual
CreateViewCrear un registro con formulario
UpdateViewEditar un registro existente
DeleteViewEliminar un registro
TemplateViewRenderizar una plantilla estática

Ejemplo: ListView

# blog/views.py
from django.views.generic import ListView, DetailView
from .models import Articulo

class ListaArticulos(ListView):
    model = Articulo
    template_name = "blog/lista.html"
    context_object_name = "articulos"

class DetalleArticulo(DetailView):
    model = Articulo
    template_name = "blog/detalle.html"
Las CBV reducen mucho código repetitivo, pero exigen conocer convenciones de nombres (por defecto buscan plantillas como `articulo_list.html`).

4.4 Patrones de URL con path

Qué es una URL conf

El archivo urls.py mapea URLs con vistas mediante la función path(). Cada entrada incluya una ruta, una vista y un nombre opcional.

Sintaxis de path

# blog/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("", views.inicio, name="inicio"),
    path("articulos/", views.lista_articulos, name="lista"),
    path("articulos/<int:pk>/", views.detalle_articulo, name="detalle"),
]

Convertidores de ruta

ConvertidorCoincide conEjemplo
strCualquier texto sin barra<str:slug>
intNúmeros enteros<int:pk>
slugSlugs (letras, números, guiones)<slug:slug>
uuidIdentificadores UUID<uuid:token>
pathCualquier ruta, incluso con barras<path:ruta>

4.5 Mapeo URL a vistas

Incluir las URLs de una app en el proyecto

# urls.py del proyecto (miapp/urls.py)
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("blog/", include("blog.urls")),
]

Resultado de las rutas

URL finalVista ejecutada
http://127.0.0.1:8000/views.inicio (si se incluye en la raíz)
http://127.0.0.1:8000/blog/views.lista_articulos
http://127.0.0.1:8000/blog/articulos/5/views.detalle_articulo con pk=5

Generar URLs en plantillas y código

# En Python: urlresolvers
from django.urls import reverse
url = reverse("detalle", args=[5])
# Resultado: "/blog/articulos/5/"
<!-- En una plantilla HTML -->
<a href="{% url 'detalle' articulo.pk %}">Ver artículo</a>
Usar el nombre de la ruta (parámetro `name`) evita romper enlaces al cambiar la URL.

4.6 Renderizado de templates

Función render

render() combina una plantilla con un contexto (diccionario de datos) y devuelve un HttpResponse con el HTML final.

Ejemplo completo

# blog/views.py
from django.shortcuts import render
from .models import Articulo

def inicio(request):
    ultimos = Articulo.objects.filter(publicado=True).order_by("-fecha_publicacion")[:5]
    return render(
        request,
        "blog/inicio.html",
        {
            "titulo_pagina": "Mi Blog",
            "articulos": ultimos,
        },
    )

Template asociado

<!-- templates/blog/inicio.html -->
<!DOCTYPE html>
<html>
  <head><title>{{ titulo_pagina }}</title></head>
  <body>
    <h1>{{ titulo_pagina }}</h1>
    <ul>
      {% for articulo in articulos %}
        <li>{{ articulo.titulo }}</li>
      {% endfor %}
    </ul>
  </body>
</html>
El contexto puede contener modelos, listas, cadenas y cualquier objeto serializable por la plantilla.

---

Resumen

**Lo que aprendiste en esta sección:** - Las vistas reciben un request y devuelven una respuesta HTTP - Vistas por función (FBV) para lógica simple y directa - Vistas por clase (CBV) y vistas genéricas para operaciones repetitivas - Definir rutas con `path()` y convertidores como `int`, `str` y `slug` - Incluir las URLs de una app con `include()` - Renderizar templates con `render(request, "plantilla.html", contexto)`
