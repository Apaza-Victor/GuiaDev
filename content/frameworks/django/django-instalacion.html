2.1 Entorno virtual de Python

Qué es un entorno virtual

Un entorno virtual es una carpeta aislada donde se instalan las dependencias de un proyecto sin afectar al resto del sistema. Cada proyecto puede tener sus propias versiones de Django y de otras librerías.

Crear el entorno virtual

# Crear la carpeta del proyecto
mkdir mi_proyecto
cd mi_proyecto

# Crear el entorno virtual llamado venv
python -m venv venv

Activar el entorno virtual

# En Windows (PowerShell):
venv\Scripts\activate

# En Windows (CMD):
venv\Scripts\activate.bat

# En Linux/Mac:
source venv/bin/activate
Cuando el entorno está activo verás el prefijo `(venv)` al inicio de la línea de comandos. Escribe `deactivate` para salir del entorno.

2.2 Instalar Django con pip

Verificar Python

# Comprobar versión de Python
python --version
# Python 3.12.0

# Comprobar pip
pip --version

Instalar Django

# Instalar la última versión estable
pip install django

# Instalar una versión específica
pip install django==5.0.6

Verificar la instalación

# Ver la versión instalada
python -m django --version
# 5.0.6

# Ver el paquete
pip show django
El comando `django-admin` quedará disponible después de la instalación. Si no lo reconoces, verifica que el entorno virtual esté activo.

2.3 Crear el proyecto con django-admin

Comando startproject

# Crear un nuevo proyecto llamado "miapp"
django-admin startproject miapp

# También funciona con python -m django
python -m django startproject miapp

Estructura generada

miapp/
├── manage.py              # Utilidad de línea de comandos
└── miapp/                 # Paquete del proyecto
    ├── __init__.py        # Marca el directorio como paquete
    ├── asgi.py            # Servidor ASGI
    ├── settings.py        # Configuración del proyecto
    ├── urls.py            # Rutas del proyecto
    └── wsgi.py            # Servidor WSGI
ArchivoFunción
manage.pyPermite ejecutar comandos como runserver o startapp
settings.pyConfiguración global: apps, base de datos, idioma, etc.
urls.pyDefine los patrones de URL del proyecto
asgi.pyPunto de entrada para servidores ASGI (Django Channels)
wsgi.pyPunto de entrada para servidores WSGI (Gunicorn, Nginx)

2.4 Estructura de carpetas del proyecto

Proyecto vs aplicación

En Django hay dos conceptos clave:

ConceptoDescripción
ProyectoEl sitio completo: configuración y rutas globales
AplicaciónUn módulo funcional dentro del proyecto (blog, tienda, usuarios)

Estructura de un proyecto tipo

miapp/
├── manage.py
├── miapp/                      # Configuración del proyecto
│   ├── settings.py
│   ├── urls.py
│   └── wsgi.py
├── blog/                       # Aplicación "blog"
│   ├── migrations/
│   ├── admin.py
│   ├── apps.py
│   ├── models.py
│   ├── tests.py
│   └── views.py
├── templates/                  # Plantillas HTML
└── static/                     # CSS, JS e imágenes
La carpeta del proyecto (la interna con `settings.py`) guarda la configuración global; cada aplicación aporta su propia lógica.

2.5 Archivos clave: manage.py, settings.py y urls.py

manage.py

Es la interfaz de comandos del proyecto. Los comandos más usados:

# Comandos de manage.py
python manage.py runserver     # Servidor de desarrollo
python manage.py startapp blog # Crear una aplicación
python manage.py makemigrations# Generar migraciones
python manage.py migrate       # Aplicar migraciones
python manage.py createsuperuser # Crear admin

settings.py

Configuración principal. Algunas claves importantes:

# settings.py
SECRET_KEY = "clave-secreta-de-seguridad"
DEBUG = True  # Cambiar a False en producción

INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
]

LANGUAGE_CODE = "es"        # Idioma en español
TIME_ZONE = "America/Mexico_City"
USE_TZ = True

urls.py

Define las rutas del proyecto. Ejemplo mínimo:

# urls.py
from django.contrib import admin
from django.urls import path

urlpatterns = [
    path("admin/", admin.site.urls),
]

2.6 Servidor de desarrollo (runserver)

Iniciar el servidor

# Desde la carpeta que contiene manage.py
python manage.py runserver

# Salida esperada:
# Performing system checks...
# System check identified no issues (0 silenced).
# You have 18 unapplied migration(s).
# Your project may not work properly...
# Starting development server at http://127.0.0.1:8000/

Opciones del comando

OpciónDescripción
--portCambiar el puerto (por defecto 8000)
--hostEscuchar en otra dirección IP
Sin cambiosSe recarga solo al editar el código
# Servidor en un puerto específico
python manage.py runserver 3000

# Accesible desde la red local
python manage.py runserver 0.0.0.0:8000
El servidor de desarrollo no es seguro para producción. Úsalo solo para programar y probar localmente.

Probar el proyecto desde el navegador

Visita http://127.0.0.1:8000 y verás la página de bienvenida de Django. Si todo salió bien, ya tienes tu primer proyecto funcionando.

Resumen

**Lo que aprendiste en esta sección:** - Crear y activar un entorno virtual con `python -m venv venv` - Instalar Django con `pip install django` - Crear un proyecto con `django-admin startproject miapp` - Identificar la estructura de carpetas: manage.py, settings.py, urls.py - Diferenciar proyecto (configuración) y aplicación (funcionalidad) - Levantar el servidor con `python manage.py runserver`
