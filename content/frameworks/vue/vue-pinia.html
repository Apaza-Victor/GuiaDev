¿Por qué Pinia?

Pinia es la librería oficial de manejo de estado para Vue 3 y reemplaza a Vuex. Nació como prototipo de Vuex 5 y terminó siendo mejor: misma API en todos los stores, tipado completo sin esfuerzo, devtools integrado y cero mutaciones.

VuexPinia
mutations + actions + gettersSolo state, getters y actions (las actions mutan directo)
Un solo store global con módulosMúltiples stores planos por dominio
Tipado manual y verbosoInferencia automática de TypeScript
Anidado por namespacesStores se importan y componen libremente

Regla mental: el estado vive en Pinia cuando múltiples componentes no relacionados necesitan compartirlo. El estado local de un formulario o un modal sigue siendo ref() local — no todo debe ir al store.

Instalación y configuración

npm install pinia
// src/main.js
import { createApp } from 'vue';
import { createPinia } from 'pinia';
import App from './App.vue';

createApp(App).use(createPinia()).mount('#app');

Convención de estructura: un archivo por dominio en src/stores/ (counter.js, auth.js, carrito.js). Stores pequeños y cohesivos vencen a un mega-store.

defineStore() y estado

// src/stores/carrito.js - sintaxis Options
import { defineStore } from 'pinia';

export const useCarrito = defineStore('carrito', {
  state: () => ({
    items: [],
    abierto: false
  }),
});
// Sintaxis Setup (recomendada en Composition API)
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useCarrito = defineStore('carrito', () => {
  // state = refs
  const items = ref([]);
  const abierto = ref(false);

  // getter = computed
  const total = computed(() =>
    items.value.reduce((acc, i) => acc + i.precio * i.cantidad, 0)
  );

  // action = funciones normales
  function agregar(producto) {
    const existente = items.value.find(i => i.id === producto.id);
    existente ? existente.cantidad++ : items.value.push({ ...producto, cantidad: 1 });
  }
  function vaciar() { items.value = []; }

  return { items, abierto, total, agregar, vaciar };
});
  • El primer argumento es el id único del store; úsalo en devtools.
  • En sintaxis setup: ref → state, computed → getter, función → action. Sin ceremonia.

storeToRefs() y uso en componentes

Dentro de componentes, desestructura con cuidado: las acciones pueden extraerse directo, pero el estado y getters necesitan storeToRefs() para mantener reactividad:

<script setup>
import { useCarrito } from '@/stores/carrito';
import { storeToRefs } from 'pinia';

const carrito = useCarrito();

// INCORRECTO: pierde reactividad al desestructurar
// const { items, total } = carrito;

// CORRECTO: refs reactivas
const { items, total } = storeToRefs(carrito);

// Las acciones SI se extraen directo
const { agregar, vaciar } = carrito;
</script>

<template>
  <p>{{ items.length }} productos — Total: ${{ total }}</p>
  <button @click="vaciar()">Vaciar</button>
</template>

Compartir estado entre stores

Los stores se combinan simplemente llamándose entre sí:

// src/stores/pedidos.js
import { defineStore } from 'pinia';
import { useCarrito } from './carrito';
import api from '@/services/api';

export const usePedidos = defineStore('pedidos', () => {
  async function confirmar() {
    const carrito = useCarrito();          // dentro de la accion
    const pedido = await api.post('/pedidos', {
      items: carrito.items,
      total: carrito.total
    });
    carrito.vaciar();
    return pedido;
  }

  return { confirmar };
});

Llama a otro store dentro de sus acciones, nunca en el nivel superior del setup del store: así evitas dependencias circulares al inicializar.
