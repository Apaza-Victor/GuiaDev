Instalación y configuración del router

Vue Router es el enrutador oficial de Vue 3 para construir SPAs. Instalación y registro básico:

npm install vue-router@4
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router';
import HomeView from '@/views/HomeView.vue';

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/', name: 'home', component: HomeView },
    {
      path: '/about',
      name: 'about',
      // Lazy loading: solo se descarga al visitar la ruta
      component: () => import('@/views/AboutView.vue')
    }
  ]
});

export default router;
// src/main.js
import { createApp } from 'vue';
import App from './App.vue';
import router from './router';

createApp(App).use(router).mount('#app');

Usa siempre rutas nombradas (name:): referenciar por nombre sobrevive a cambios de path y hace el código autodocumentado.

Navegación declarativa y programática

<!-- Declarativa: componente RouterLink -->
<RouterLink to="/">Inicio</RouterLink>
<!-- Con nombre y params -->
<RouterLink :to="{ name: 'user', params: { id: 42 } }">
  Ver usuario
</RouterLink>

<!-- Donde se renderiza la ruta activa -->
<RouterView />
// Programática: tras un submit, por ejemplo
import { useRouter } from 'vue-router';

const router = useRouter();

async function guardar() {
  await api.crear(datos);
  router.push({ name: 'detail', params: { id: nuevo.id } });
}
  • push(): navega y añade al historial.
  • replace(): navega sin añadir al historial (login → dashboard).
  • back() / forward() / go(-2): control del historial.

useRouter() y useRoute()

En Composition API, dos composables sustituyen a this.$router y this.$route:

<script setup>
import { useRoute, useRouter } from 'vue-router';
import { computed, watch } from 'vue';

const route = useRoute();   // leer informacion de la ruta ACTUAL
const router = useRouter(); // ACCIONES de navegacion

// /usuarios/42?tab=posts
const userId = route.params.id;   // "42"
const tab = route.query.tab;      // "posts"

// Reaccionar a cambios de la MISMA ruta (param distinto reutiliza componente)
watch(() => route.params.id, (nuevoId) => {
  cargarUsuario(nuevoId);
});
</script>

Clave conceptual: route es un objeto reactivo de solo lectura; router es el motor que navega. Cambiar de parámetro en la misma ruta NO recrea el componente — observa los params si necesitas recargar datos.

Rutas dinámicas e hijas

const routes = [
  // Dinamica: segmento variable
  { path: '/productos/:id', component: ProductoView },

  // Anidadas: RouterView dentro del padre renderiza las hijas
  {
    path: '/panel',
    component: PanelLayout,
    children: [
      { path: '', component: PanelHome },        // /panel
      { path: 'perfil', component: PerfilView }, // /panel/perfil
      { path: 'ajustes', component: AjustesView }// /panel/ajustes
    ]
  },

  // Catch-all 404 (siempre al final)
  { path: '/:pathMatch(.*)*', name: 'not-found', component: NotFoundView }
];

El layout padre contiene un <RouterView /> interno donde se pintan las hijas — perfecto para sidebars persistentes con contenido cambiante.

Guardias de navegación

Los guards interceptan la navegación: protegen rutas, cargan datos previos o bloquean salidas sin guardar:

// Global: se ejecuta en TODA navegacion
router.beforeEach((to) => {
  const auth = useAuthStore();
  if (to.meta.requiereAuth && !auth.estaLogueado) {
    return { name: 'login', query: { redirect: to.fullPath } };
  }
});

// Por ruta via meta + guard global (patron recomendado)
{ path: '/admin', component: AdminView, meta: { requiereAuth: true } }
  • beforeEach: antes de entrar — el más usado (autenticación).
  • beforeResolve: justo antes de confirmar, ideal para precargar datos.
  • onBeforeRouteLeave (en componente): confirmar salida con formulario sucio.

Ejercicio propuesto: implementa rutas anidadas para un panel con sidebar, protege /panel con meta + beforeEach y agrega lazy loading en todas las vistas hijas.
