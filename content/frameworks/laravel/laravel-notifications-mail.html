Sistema de notificaciones

Las notificaciones de Laravel envían un mismo mensaje por múltiples canales (email, base de datos, Slack, SMS) con una sola clase. La diferencia conceptual clave: una notificación dice "algo le pasó a ESTE usuario"; un mailable es solo "manda este correo".

php artisan make:notification FacturaPagada
class FacturaPagada extends Notification
{
    public function __construct(public Factura $factura) {}

    // Canales por los que viaja
    public function via(object $notifiable): array
    {
        return ['mail', 'database'];
    }

    public function toMail(object $notifiable): MailMessage
    {
        return (new MailMessage)
            ->subject('Tu factura fue pagada')
            ->greeting("Hola {$notifiable->name}")
            ->line("La factura #{$this->factura->numero} fue pagada con exito.")
            ->action('Ver factura', url("/facturas/{$this->factura->id}"));
    }

    public function toArray(object $notifiable): array
    {
        return [
            'factura_id' => $this->factura->id,
            'mensaje' => 'Factura pagada',
        ];
    }
}

// Envio desde cualquier parte
$usuario->notify(new FacturaPagada($factura));

// A muchos a la vez
Usuario::where('plan', 'premium')->each(
    fn ($u) => $u->notify(new FacturaPagada($factura))
);

Notificaciones en base de datos

El canal database guarda cada notificación en la tabla notifications — la base del clásico sistema de campanita:

# Tabla + columna en usuarios
php artisan make:notifications-table
php artisan migrate
// Leer y marcar
$noLeidas = $usuario->unreadNotifications;
$usuario->notifications->markAsRead();

// Broadcast en tiempo real (opcional)
public function via($notifiable) { return ['database', 'broadcast']; }

Con Laravel Echo + Pusher/Reverb, el canal broadcast actualiza la campanita sin recargar página.

Mailables y vistas de correo

Cuando necesitas control total del correo (diseño HTML propio, adjuntos complejos), los mailables son la herramienta:

php artisan make:mail BienvenidaMail
// app/Mail/BienvenidaMail.php
class BienvenidaMail extends Mailable
{
    use Queueable;

    public function __construct(public Usuario $usuario) {}

    public function envelope(): Envelope
    {
        return new Envelope(
            subject: 'Bienvenido a nuestra plataforma',
            tags: ['onboarding'],          // util para tracking
            replyTo: ['soporte@midominio.com'],
        );
    }

    public function content(): Content
    {
        return new Content(
            markdown: 'emails.bienvenida',   // vista markdown con componentes
            with: ['nombre' => $this->usuario->name],
        );
    }

    public function attachments(): array
    {
        return [Attachment::fromPath(storage_path('app/manual.pdf'))];
    }
}

// Envio
Mail::to($usuario->email)->send(new BienvenidaMail($usuario));
<!-- resources/views/emails/bienvenida.blade.php -->

Las plantillas markdown de Laravel generan HTML responsive con botones y paneles listos. Empieza siempre ahí; solo construye CSS propio si la marca lo exige realmente.

Configuración SMTP y pruebas

# .env - desarrollo local
MAIL_MAILER=log              # escribe correos a storage/logs/laravel.log

MAIL_MAILER=smtp             # produccion o Mailtrap para staging
MAIL_HOST=smtp.mailtrap.io
MAIL_PORT=2525
MAIL_USERNAME=xxx
MAIL_PASSWORD=xxx
MAIL_FROM_ADDRESS=hola@midominio.com
  • MAIL_MAILER=log: cero configuración para desarrollar; revisa el log.
  • Mailtrap / Mailpit: bandeja falsa para staging — ves el diseño real sin enviar nada a clientes.
  • Pruebas automatizadas: Mail::fake() + Mail::assertSent(BienvenidaMail::class).
  • Envía mailables pesados SIEMPRE encolados: send(new ...) → queue(new ...).
