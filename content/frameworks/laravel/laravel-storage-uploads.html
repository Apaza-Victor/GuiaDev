Discos de almacenamiento (Storage)

La facade Storage de Laravel abstrae el sistema de archivos gracias a Flysystem: el mismo código funciona sobre disco local, S3, FTP o Dropbox. Los discos se definen en config/filesystems.php:

'disks' => [
    'local' => [
        'driver' => 'local',
        'root' => storage_path('app/private'),   // NO accesible por web
    ],
    'public' => [
        'driver' => 'local',
        'root' => storage_path('app/public'),
        'url' => env('APP_URL').'/storage',
        'visibility' => 'public',
    ],
    's3' => [
        'driver' => 's3',
        'key' => env('AWS_ACCESS_KEY_ID'),
        'secret' => env('AWS_SECRET_ACCESS_KEY'),
        'region' => env('AWS_DEFAULT_REGION'),
        'bucket' => env('AWS_BUCKET'),
    ],
],

No olvides el enlace simbólico que expone el disco public en la carpeta web: php artisan storage:link.

Operaciones básicas

use Illuminate\Support\Facades\Storage;

// Guardar
Storage::disk('local')->put('facturas/2026/f001.pdf', $contenido);

// Leer y verificar
$contenido = Storage::get('facturas/2026/f001.pdf');
Storage::exists('facturas/2026/f001.pdf');

// Copiar, mover y eliminar
Storage::copy('viejo.pdf', 'nuevo.pdf');
Storage::move('temporal.pdf', 'definitivo.pdf');
Storage::delete(['a.pdf', 'b.jpg']);

// Listar y tamanos
Storage::files('facturas/2026');
Storage::size('facturas/2026/f001.pdf');   // bytes
Storage::lastModified('facturas/2026/f001.pdf');

Especifica siempre el disco explícitamente (Storage::disk('s3')) en código de negocio. Depender del default hace que cambiar configuración mueva datos sin querer.

Subir archivos validados

El request maneja uploads nativamente. Valida tipo y tamaño ANTES de mover nada:

// Formulario: <form method="POST" enctype="multipart/form-data">

public function store(Request $request)
{
    $validated = $request->validate([
        'avatar' => ['required', 'image', 'mimes:jpg,png,webp', 'max:2048'],   // KB
        'documento' => ['required', 'file', 'mimetypes:application/pdf', 'max:10240'],
    ]);

    $ruta = $request->file('avatar')->store('avatars', 'public');

    // Con nombre propio en lugar del hash aleatorio
    $rutaDoc = $request->file('documento')->storeAs(
        'documentos',
        now()->format('Ymd') . '-usuario-' . auth()->id() . '.pdf',
        'local'
    );

    Perfil::create(['avatar_path' => $ruta]);
}
  • store() genera nombre seguro automático (hash) — preferible para contenido de usuario.
  • mimes: valida extensión; mimetypes: valida el tipo real del archivo. Usa ambos cuando el riesgo lo amerite.
  • max: se expresa en kilobytes; recuerda también los límites de php.ini (upload_max_filesize) si despliegas sin Laravel Sail.

Público vs privado, URLs y descargas

// URL publica (requiere storage:link o disco cloud)
$url = Storage::url('avatars/hash.jpg');          // /storage/avatars/hash.jpg

// Archivo PRIVADO: nunca URL directa; sirve via controlador
Route::get('/facturas/{factura}/descargar', function (Factura $factura) {
    $this->authorize('view', $factura);           // solo su dueno

    return Storage::download(
        "facturas/{$factura->archivo}",
        "factura-{$factura->numero}.pdf"          // nombre al usuario
    );
});

// Visibilidad temporal (S3): URLs firmadas con expiracion
$urlTemporal = Storage::temporaryUrl(
    'privado/video.mp4', now()->addMinutes(30)
);
  • Público: imágenes de perfil, logos — accesibles por URL directa.
  • Privado + controlador con authorize: facturas, documentos sensibles — la autorización vive en tu código, no en el filesystem.
  • En S3, temporaryUrl descarga directo desde AWS sin pasar por tu servidor: ahorra ancho de banda.
