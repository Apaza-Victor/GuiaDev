Spring AOP: programación orientada a aspectos

AOP permite extraer lógica transversal (logging, seguridad, métricas) de la lógica de negocio. Un aspecto envuelve métodos que cumplen cierta condición sin modificarlos:

@Aspect
@Component
public class AuditoriaAspect {

    @Pointcut("within(@org.springframework.web.bind.annotation.RestController *)")
    public void controladores() {}

    @Around("controladores()")
    public Object auditar(ProceedingJoinPoint joinPoint) throws Throwable {
        long inicio = System.currentTimeMillis();
        try {
            return joinPoint.proceed();
        } finally {
            long duracion = System.currentTimeMillis() - inicio;
            log.info("{} ejecuto en {} ms",
                joinPoint.getSignature().toShortString(), duracion);
        }
    }
}

Tipos de advice: @Before (antes), @AfterReturning (tras éxito), @AfterThrowing (excepción), @Around (envuelve todo — el más potente).

Perfilamiento y configuración por entorno

Los perfiles separan configuración por entorno sin tocar código:

# application-dev.properties
spring.datasource.url=jdbc:h2:mem:testdb
spring.jpa.show-sql=true

# application-prod.properties
spring.datasource.url=jdbc:postgresql://db:5432/app
spring.jpa.show-sql=false
java -jar app.jar --spring.profiles.active=prod

# O via variable de entorno
SPRING_PROFILES_ACTIVE=prod
  • @Profile("dev") activa beans solo en ese perfil (mocks, datos semilla).
  • Spring Boot Actuator expone /health, /metrics, /info para monitoreo en producción.
  • Credenciales SIEMPRE fuera del repo: variables de entorno o Spring Cloud Config/Vault.

Seguridad con Spring Security

La configuración moderna usa un SecurityFilterChain declarativo:

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .formLogin(Customizer.withDefaults());
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
  • Sesiones + form login: apps web tradicionales.
  • JWT stateless: APIs REST — desactiva sesiones y valida el token en cada request.
  • Nunca guardes contraseñas sin BCrypt; nunca escribas tu propio hash.

Caching y testing integrado

// Cache: una anotacion evita repetir consultas costosas
@Cacheable(value = "productos", key = "#id")
public Producto buscar(Long id) { ... }

@CacheEvict(value = "productos", key = "#producto.id")
public Producto actualizar(Producto producto) { ... }
// Testing con contexto real
@SpringBootTest
@AutoConfigureMockMvc
class ProductoControllerTest {

    @Autowired MockMvc mockMvc;

    @Test
    void listarProductos() throws Exception {
        mockMvc.perform(get("/api/productos"))
               .andExpect(status().isOk())
               .andExpect(jsonPath("$[0].nombre").exists());
    }
}

@SpringBootTest levanta el contexto completo: potente pero lento. Para tests unitarios de servicios, inyecta mocks con Mockito y reserva el contexto completo para pruebas de integración puntuales.

Ejercicio propuesto: agrega a un proyecto tuyo un aspecto de auditoría (@Around), dos perfiles con bases distintas, cache sobre el servicio más consultado y un test @SpringBootTest del endpoint principal.
