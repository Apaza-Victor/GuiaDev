Autenticación con Breeze: el punto de partida

Para proyectos nuevos, Laravel Breeze instala el stack completo de auth con Inertia ya funcionando: login, registro, reset de contraseña, verificación de email:

composer require laravel/breeze --dev
php artisan breeze:install vue   # o react
npm install && npm run dev
php artisan migrate

Breeze usa la autenticación nativa de Laravel (sesiones + cookies). No hay tokens JWT ni API keys: el navegador mantiene la sesión como siempre lo hizo un sitio clásico, pero la interfaz es SPA. Menos piezas = menos superficie de ataque.

Proteger rutas en el backend

La protección es Laravel puro — middleware estándar sobre rutas que renderizan páginas Inertia:

// routes/web.php
Route::middleware(['auth', 'verified'])->group(function () {
    Route::get('/panel', PanelController::class)->name('panel');
});

// Con roles/permisos (gate o middleware propio)
Route::middleware('can:administrar')->group(function () {
    Route::resource('/admin/usuarios', AdminUsuarioController::class);
});

Regla de oro: la seguridad vive en el servidor. El frontend oculta botones por conveniencia visual; el middleware decide quién entra de verdad.

Redirigir a login desde Inertia

Cuando una visita XHR llega sin sesión válida, el middleware Authenticate debe responder con una redirección que Inertia entienda (401 → redirect al login):

// app/Http/Middleware/Authenticate.php
protected function redirectTo(Request $request): ?string
{
    return $request->expectsJson() ? null : route('login');
}

Inertia detecta el redirect y navega suavemente a /login sin error visible. El usuario inicia sesión y regresa exactamente donde estaba gracias a la URL previa guardada.

Estado de auth en el frontend

El usuario autenticado viaja como prop compartida (patrón visto en Shared Props) y alimenta toda la UI condicional:

// HandleInertiaRequests
'auth' => [
    'user' => fn () => $request->user()
        ? $request->user()->only('id', 'name', 'email')
        : null,
],
<script setup>
import { usePage } from '@inertiajs/vue3';
import { computed } from 'vue';

const user = computed(() => usePage().props.auth.user);
</script>

<template>
  <Link v-if="!user" href="/login">Iniciar sesion</Link>
  <Link v-else :href="route('logout')" method="post" as="button">
    Cerrar sesion
  </Link>
</template>
  • Logout: Link con method="post" hacia la ruta logout (POST, nunca GET — evita cierre por prefetch/crawlers).
  • Roles: agrega 'roles' => $user->roles->pluck('name') a la prop compartida para menús condicionales.
  • Email verification: el middleware verified redirige a la página verify-email de Breeze automáticamente.

Ejercicio propuesto: protege tres rutas con auth+verified, cierra sesión manualmente borrando la cookie de sesión y verifica que la siguiente navegación XHR te lleva a /login conservando la intención original.
