Code splitting de páginas

Sin configuración extra, Inertia + Vite divide tu app en chunks por página: cada visitante descarga solo el JS de la página que ve, no toda la aplicación:

// resources/js/app.js
import { createInertiaApp } from '@inertiajs/vue3';

createInertiaApp({
  resolve: (name) => {
    const pages = import.meta.glob('./Pages/**/*.vue');
    return pages[`./Pages/${name}.vue`]();   // lazy automatico
  },
});

El patrón import.meta.glob crea un chunk dinámico por cada archivo en Pages/. Resultado: una app de 40 páginas carga ~15KB iniciales en vez de megabytes.

Partial reloads con only

Cuando solo necesitas refrescar UNA prop sin re-renderizar todo, pide únicamente esa:

<script setup>
import { router } from '@inertiajs/vue3';
import { watch } from 'vue';

// Al cambiar la busqueda, solo llega "usuarios"
watch(busqueda, (nueva) => {
  router.visit('/usuarios', {
    only: ['usuarios'],
    preserveState: true,
    preserveScroll: true,
    data: { busqueda: nueva },
  });
});
</script>
  • only: lista blanca — SOLO esas props viajan y se actualizan.
  • except: inversa — todas menos esas.
  • Las props compartidas lazy también se resuelven aquí si las incluyes en only.
  • Ideal para: búsqueda en vivo, notificaciones, dashboards que se auto-refrescan.

Lazy loading en el backend

La otra cara del partial reload: el backend puede saber qué props pidieron y evitar computar lo demás:

public function index(Request $request)
{
    return Inertia::render('Users/Index', [
        // Solo consulta pesada si alguien pidio esta prop
        'estadisticas' => fn () => Estadistica::complejas(),

        'usuarios' => User::paginate(10),   // siempre
    ]);
}

Laravel detecta automáticamente si la prop fue solicitada en un partial reload. Si nadie pidió estadisticas, ni siquiera se ejecuta el closure.

Componentes y assets diferidos

  • defineAsyncComponent: componentes Vue pesados (gráficos, editores) cargan al usarse:
const EditorChart = defineAsyncComponent(() =>
  import('@/Components/EditorChart.vue')
);
  • Dynamic import() para librerías grandes dentro de acciones (al abrir modal de exportación → cargar jsPDF).
  • <Deferred> de Inertia: muestra placeholder mientras llegan props lentas:
<script setup>
import { Deferred } from '@inertiajs/vue3';
</script>

<template>
  <Deferred data="estadisticas">
    <template #fallback>Cargando estadisticas...</template>
    <PanelEstadisticas />
  </Deferred>
</template>

Métrica objetivo: primera visita bajo 200KB de JS. Si superas eso, revisa imports estáticos de librerías pesadas — casi siempre hay alguna candidata a diferirse.

Ejercicio propuesto: mide el bundle inicial de tu app Inertia (vite build --report). Identifica la librería más pesada, muévela a dynamic import y documenta cuántos KB bajó la carga inicial.
