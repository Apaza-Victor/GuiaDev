Respuestas de Inertia: la convención

En Inertia no hay endpoints JSON: cada ruta devuelve o una página completa (primer render) o una respuesta Inertia (XHR con props). El mismo método sirve ambas:

// Laravel: Inertia::render() en lugar de view()
use Inertia\Inertia;

public function index()
{
    return Inertia::render('Users/Index', [
        'users' => User::paginate(10),
        'filtros' => request()->only(['busqueda', 'rol']),
    ]);
}

Cuando el request llega por XHR (header X-Inertia), Laravel devuelve JSON parcial automáticamente; cuando es navegación normal, HTML completo. Tu código no distingue.

Redirects después de acciones

public function store(Request $request)
{
    $pedido = Pedido::create($request->validated());

    // Redirect estandar de Laravel - Inertia lo interpreta
    return redirect()->route('pedidos.show', $pedido);

    // Otras variantes utiles
    return back();                          // volver a donde estaba
    return redirect('/pedidos')->with('success', 'Pedido creado!');
}
  • back() + formularios: patrón crear-y-volver.
  • El with() viaja en flash session — se consume en el siguiente render.
  • Tras DELETE suele redirigirse al index, nunca a un recurso inexistente.

Flash messages

El mensaje "Pedido creado" debe mostrarse una sola vez, en la página siguiente. Eso es exactamente la flash session:

// Laravel: enviar
return redirect('/pedidos')->with('success', 'Pedido creado correctamente');
// Laravel (HandleInertiaRequests): compartir SIEMPRE
public function share(Request $request): array
{
    return [
        ...parent::share($request),
        'flash' => [
            'success' => fn () => $request->session()->get('success'),
            'error' => fn () => $request->session()->get('error'),
        ],
    ];
}
<!-- Vue: componente Toast global que lee $page.props.flash -->
<script setup>
import { usePage } from '@inertiajs/vue3';
import { computed } from 'vue';

const page = usePage();
const mensaje = computed(() => page.props.flash.success);
</script>

Como las props compartidas se resuelven en cada visita (por eso el fn (), lazy evaluation), el toast aparece tras cualquier acción que redirija con with().

Manejo de errores de validación

Los errores de validación de Laravel vuelven como redirect + errors en sesión. El helper useForm los recibe listos para usar:

<script setup>
import { useForm } from '@inertiajs/vue3';

const form = useForm({ nombre: '', email: '' });

function submit() {
  form.post('/usuarios');
}
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="form.nombre" />
    <div v-if="form.errors.nombre" class="error">{{ form.errors.nombre }}</div>
    <button :disabled="form.processing">
      {{ form.processing ? 'Guardando...' : 'Guardar' }}
    </button>
  </form>
</template>
  • form.errors: objeto con errores por campo (422 automático).
  • form.processing: true mientras dura la petición — deshabilita botones con él.
  • form.reset(): limpia campos tras éxito (en onSuccess).
