8.1 Qué es el middleware en Next.js

Concepto

El middleware es una función que se ejecuta antes de que se procese una petición. Es perfecto para redirigir, proteger rutas o modificar headers. Se define en un archivo middleware.ts en la raíz del proyecto:

// middleware.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const token = request.cookies.get("token");

  if (!token) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*"],
};

Cuándo se ejecuta

  • Antes del renderizado de la página
  • En cada petición que coincida con el matcher
  • Tanto para navegación como para API routes
El middleware no debe realizar operaciones pesadas; es de ejecución rápida y no tiene acceso a Node.js completo.

8.2 Proteger rutas con middleware

Proteger varias rutas con matcher

// middleware.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

const rutasProtegidas = ["/dashboard", "/perfil", "/admin"];

export function middleware(request: NextRequest) {
  const token = request.cookies.get("sesion");

  const url = request.nextUrl.clone();
  const esRutaProtegida = rutasProtegidas.some(
    (ruta) => url.pathname.startsWith(ruta)
  );

  if (esRutaProtegida && !token) {
    url.pathname = "/login";
    return NextResponse.redirect(url);
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*", "/perfil/:path*", "/admin/:path*"],
};
Usa `matcher` para definir qué rutas ejecutan el middleware y reducir el trabajo innecesario.

8.3 Redirecciones y reescrituras

Redireccionar (redirect)

// middleware.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;

  // Redirigir si el usuario está autenticado y entra al login
  if (pathname === "/login" && request.cookies.get("token")) {
    return NextResponse.redirect(
      new URL("/dashboard", request.url)
    );
  }

  return NextResponse.next();
}

Reescribir (rewrite)

// Reescribir muestra otra ruta sin cambiar la URL
return NextResponse.rewrite(
  new URL("/alternativa", request.url)
);
FunciónQué hace
redirect()Cambia la URL del navegador
rewrite()Muestra otra ruta sin cambiar la URL
next()Continúa con la petición normal

8.4 Manejo de sesiones y credenciales

Concepto de sesión

Una sesión identifica al usuario entre peticiones. Las credenciales (email y contraseña) se verifican en el servidor y se genera un token que se guarda en una cookie:

// app/api/login/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function POST(request: NextRequest) {
  const { email, password } = await request.json();

  // Verificar credenciales contra la base de datos
  if (email === "admin@test.com" && password === "123456") {
    const token = generarToken(email); // firma el usuario

    const response = NextResponse.json({ ok: true });
    response.cookies.set("token", token, {
      httpOnly: true,
      secure: process.env.NODE_ENV === "production",
      sameSite: "lax",
      maxAge: 60 * 60 * 24, // 1 día
    });
    return response;
  }

  return NextResponse.json(
    { error: "Credenciales inválidas" },
    { status: 401 }
  );
}

Buenas prácticas de sesiones

  • Guarda el token en cookies httpOnly
  • Deja que librerías como Auth.js gestionen la sesión
  • Expira las sesiones con maxAge
  • Usa HTTPS en producción para proteger las cookies
Para proyectos reales usa Auth.js (NextAuth) o Clerk; el ejemplo es solo ilustrativo del flujo de sesión.

8.5 Variables de entorno (ENV)

Qué son y cómo se declaran

Las variables de entorno guardan secretos y configuración fuera del código. Se definen en archivos .env:

# .env.local (secreto, no se sube a git)
DATABASE_URL=postgres://usuario:pass@localhost:5432/mibd
API_SECRET=clave-super-secreta

# Prefijo NEXT_PUBLIC_ para exponer al cliente
NEXT_PUBLIC_API_URL=https://api.example.com

Acceder a las variables

// En el servidor (seguro)
const db = process.env.DATABASE_URL;

// En el cliente (solo NEXT_PUBLIC_)
const apiUrl = process.env.NEXT_PUBLIC_API_URL;

Archivos .env disponibles

ArchivoUso
.env.localVariables del entorno local
.env.productionVariables de producción
.env.developmentVariables de desarrollo
Añade `.env*` a tu `.gitignore`. Jamás subas claves secretas al repositorio.

8.6 Uso de Auth.js para autenticación

Por qué usar una librería

Gestionar sesiones, proveedores OAuth y seguridad de forma manual es complejo. Auth.js (antes NextAuth) simplifica todo el flujo:

// app/api/auth/[...nextauth]/route.ts
import NextAuth from "next-auth";
import GitHub from "next-auth/providers/github";
import Credentials from "next-auth/providers/credentials";

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [
    GitHub,
    Credentials({
      credentials: {
        email: {},
        password: {},
      },
      async authorize(creds) {
        const user = await verificarCredenciales(
          creds.email,
          creds.password
        );
        return user || null;
      },
    }),
  ],
});

Proteger una página con auth

// app/dashboard/page.tsx
import { auth } from "../api/auth/[...nextauth]/route";

export default async function Dashboard() {
  const session = await auth();

  if (!session) {
    return <p>No has iniciado sesión</p>;
  }

  return <p>Bienvenido, {session.user.name}</p>;
}
Auth.js ofrece proveedores de Google, GitHub, email y credenciales, además de adaptadores para bases de datos.

Resumen

**Lo que aprendiste en esta sección:** - El middleware se ejecuta antes de procesar cada petición - Protege rutas usando matcher y redirecciones - Las sesiones identifican al usuario entre peticiones - Los tokens se guardan en cookies httpOnly - Las variables de entorno se declaran en archivos .env - Auth.js simplifica la autenticación con proveedores OAuth
