4.1 Componentes React en Next.js

Qué es un componente

Un componente es una función que devuelve JSX y se reutiliza en varias partes de la aplicación. Next.js usa exactamente los mismos componentes de React:

// app/components/Boton.tsx
interface BotonProps {
  texto: string;
  onClick?: () => void;
}

export default function Boton({ texto, onClick }: BotonProps) {
  return (
    <button onClick={onClick} className="btn">
      {texto}
    </button>
  );
}

Usar el componente

// app/page.tsx
import Boton from "./components/Boton";

export default function Home() {
  return (
    <div>
      <h1>Inicio</h1>
      <Boton texto="Guardar" />
      <Boton texto="Cancelar" />
    </div>
  );
}
Los componentes que no usan eventos ni hooks se pueden usar sin la directiva `"use client"`.

4.2 El archivo layout.tsx

Qué es un Layout

Un layout es la estructura compartida entre varias páginas. Contiene elementos como el header, footer o la navegación que se mantienen al cambiar de ruta:

// app/layout.tsx
import type { Metadata } from "next";
import "./globals.css";

export const metadata: Metadata = {
  title: "Mi Tienda",
  description: "Tienda en línea creada con Next.js",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="es">
      <body>
        <header>Logotipo y menú</header>
        {children}
        <footer>Pie de página</footer>
      </body>
    </html>
  );
}

Layouts anidados

Cada carpeta puede tener su propio layout que envuelve a sus páginas hijas:

app/
├── layout.tsx          # Layout raíz
├── dashboard/
│   ├── layout.tsx      # Layout del dashboard
│   ├── page.tsx        # /dashboard
│   └── settings/
│       └── page.tsx    # /dashboard/settings
Los layouts no se re-renderizan al navegar, por lo que el estado dentro de ellos se conserva.

4.3 Head y metadatos con Metadata API

Exportar metadatos estáticos

// app/contacto/page.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Contacto | Mi Tienda",
  description: "Ponte en contacto con nosotros",
  keywords: ["contacto", "soporte", "tienda"],
};

export default function Contacto() {
  return <h1>Contacto</h1>;
}

Metadatos más usados

CampoDescripción
titleTítulo de la pestaña del navegador
descriptionDescripción mostrada en buscadores
keywordsPalabras clave para SEO
openGraphMetadatos para redes sociales
applicationNameNombre de la aplicación

Generar metadatos dinámicamente

// app/posts/[id]/page.tsx
import type { Metadata } from "next";

export async function generateMetadata({
  params,
}: {
  params: { id: string };
}): Promise<Metadata> {
  const res = await fetch(
    `https://api.example.com/posts/${params.id}`
  );
  const post = await res.json();

  return { title: post.title, description: post.body };
}

4.4 Metadatos dinámicos y Open Graph

Open Graph para redes sociales

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Producto destacado",
  openGraph: {
    title: "Producto destacado | Mi Tienda",
    description: "Un producto increíble con descuento",
    url: "https://mitienda.com/producto",
    images: [
      {
        url: "https://mitienda.com/imagen.jpg",
        width: 1200,
        height: 630,
      },
    ],
  },
};

Metadatos desde una API (dinámicos)

// app/perfil/[usuario]/page.tsx
import type { Metadata } from "next";

export async function generateMetadata({
  params,
}: {
  params: { usuario: string };
}): Promise<Metadata> {
  const res = await fetch(
    `https://api.example.com/usuarios/${params.usuario}`
  );
  const usuario = await res.json();

  return {
    title: `Perfil de ${usuario.nombre}`,
    description: `Perfil del usuario ${usuario.nombre}`,
  };
}

export default function Perfil() {
  return <h1>Perfil</h1>;
}
La función `generateMetadata` recibe los mismos `params` que la página y debe devolver un objeto `Metadata`.

4.5 Diferencias entre Server y Client Components

Dos tipos de componentes

AspectoServer ComponentClient Component
EjecuciónEn el servidorEn el navegador
HooksNo usa useState/useEffectSí usa hooks de estado
Acceso a BDDirecto y seguroNo directo
DirectivaPor defecto"use client" al inicio
Size del JSXSin agregar JS al clienteAñade su código al bundle

Marca un componente como cliente

// app/components/Contador.tsx
"use client";

import { useState } from "react";

export default function Contador() {
  const [n, setN] = useState(0);
  return (
    <button onClick={() => setN(n + 1)}>
      Clicks: {n}
    </button>
  );
}
Los Server Components son la estrategia por defecto en el App Router y mejoran el rendimiento al no enviar tanto JavaScript al cliente.

4.6 Composición de componentes y props

Pasar datos con props

// app/components/Tarjeta.tsx
interface TarjetaProps {
  titulo: string;
  precio: number;
  children: React.ReactNode;
}

export default function Tarjeta({
  titulo,
  precio,
  children,
}: TarjetaProps) {
  return (
    <div className="tarjeta">
      <h3>{titulo}</h3>
      <p>Precio: ${precio}</p>
      {children}
    </div>
  );
}

Composición con children

// app/page.tsx
import Tarjeta from "./components/Tarjeta";

export default function Home() {
  return (
    <div>
      <Tarjeta titulo="Laptop" precio={999}>
        <button>Comprar</button>
      </Tarjeta>
      <Tarjeta titulo="Mouse" precio={29}>
        <button>Ver más</button>
      </Tarjeta>
    </div>
  );
}
Los props se pasan de componentes padres a hijos y no deben modificarse dentro del hijo.

Resumen

**Lo que aprendiste en esta sección:** - Los componentes de React funcionan igual dentro de Next.js - layout.tsx define la estructura compartida de las páginas - Los layouts se pueden anidar por carpeta - La Metadata API controla títulos, descripciones y Open Graph - Los Server Components se ejecutan en el servidor por defecto - Los Client Components usan la directiva "use client"
