10.1 Preparar el proyecto para producción

Compilar para producción

El primer paso es compilar la aplicación para generar la versión optimizada:

npm run build

La compilación genera una carpeta .next con las páginas estáticas (SSG), las funciones servidor (SSR/ISR) y el caché.

Ejecutar en modo producción

npm start

Errores a revisar antes del build

ProblemaCómo evitarlo
Errores de TypeScriptEjecuta npm run build y corrige los tipos
Fallos de ESLintCorrige las reglas marcadas por npm run lint
Imágenes sin optimizarUsa next/image en todas las imágenes
Ejecuta siempre `npm run build` en local antes de desplegar para detectar errores temprano.

10.2 Configuración de next.config

El archivo next.config.mjs

// next.config.mjs
/** @type {import("next").NextConfig} */
const nextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "api.example.com",
      },
    ],
  },
  poweredByHeader: false,
};

export default nextConfig;

Opciones de configuración comunes

OpciónDescripción
images.remotePatternsPermite optimizar imágenes de dominios externos
poweredByHeaderElimina el header X-Powered-By (seguridad)
reactStrictModeActiva el modo estricto de React
output: "standalone"Genera un servidor autónomo para Docker
Para servir imágenes desde dominios externos debes agregarlos en `images.remotePatterns`.

10.3 Desplegar en Vercel

Vercel: la plataforma oficial

Vercel es la empresa creadora de Next.js y su despliegue es el más sencillo. Conecta tu repositorio de GitHub y cada push genera una preview o producción:

# Instalar el CLI de Vercel
npm i -g vercel

# Desplegar en local
vercel

# Desplegar a producción
vercel --prod

Pasos en la web de Vercel

  • Crea una cuenta en vercel.com
  • Conecta tu repositorio de GitHub
  • Importa el proyecto (detecta Next.js automáticamente)
  • Configura las variables de entorno
  • Pulsa Deploy y obtén tu URL
Cada push a la rama principal genera un nuevo despliegue de forma automática.

10.4 Variables de entorno en producción

Cómo definirlas en producción

Las variables de entorno no se copian del proyecto; deben configurarse en la plataforma de despliegue. En Vercel se definen en el apartado Settings > Environment Variables:

# Variables a configurar en producción
DATABASE_URL=postgres://usuario:pass@produccion/db
API_SECRET=otra-clave-distinta
NEXT_PUBLIC_SITE_URL=https://miproyecto.vercel.app

Variables por entorno

VariableDesarrolloProducción
DATABASE_URL.env.localPanel de Vercel
API_SECRET.env.localPanel de Vercel
NEXT_PUBLIC_API_URLlocalhostURL pública
No valores distintas entre entornos. Nunca subas `.env.local` al repositorio.

10.5 Desplegar en otros servicios con Node.js

Requirement para servidores Node.js

Puedes alojar tu app en cualquier servidor que ejecute Node.js. Necesitas compilar y arrancar el servidor de producción:

# Instalar dependencias
npm install --production

# Compilar
npm run build

# Arrancar en producción
npm start

Con Docker (standalone)

// next.config.mjs
const nextConfig = {
  output: "standalone",
};
# Dockerfile (simplificado)
FROM node:20-alpine AS base

WORKDIR /app
COPY package.json ./
RUN npm install

COPY . .
RUN npm run build

EXPOSE 3000
CMD ["npm", "start"]
La opción `output: "standalone"` genera un servidor mínimo con todo lo necesario para ejecutarse solo.

10.6 Buenas prácticas en producción

Recomendaciones finales

PrácticaPor qué importa
Usar HTTPS siempreSeguridad y confianza del usuario
Configurar analyticsMide el rendimiento y el uso
Revisar errores con loggingDetecta fallos rápidamente
Optimizar imágenesReduce el tiempo de carga
Añadir error.tsxMuestra errores elegantes

Manejar errores en el cliente

// app/error.tsx
"use client";

export default function ErrorPage({ reset }: { reset: () => void }) {
  return (
    <div>
      <h1>Algo salió mal</h1>
      <button onClick={reset}>Reintentar</button>
    </div>
  );
}

Verificar el despliegue

  • Ejecuta Lighthouse en producción
  • Comprueba que las variables de entorno son correctas
  • Verifica que sitemap.xml y robots.txt responden
  • Prueba todas las rutas dinámicas y subidas de archivos
Un despliegue correcto combina build sin errores, variables de entorno bien configuradas y monitoreo continuo.

Resumen

**Lo que aprendiste en esta sección:** - `npm run build` genera la versión optimizada de producción - next.config.mjs controla imágenes y opciones avanzadas - Vercel es la plataforma más sencilla para desplegar Next.js - Las variables de entorno de producción se configuran en el panel - Se puede desplegar en cualquier servidor Node.js o con Docker - Las buenas prácticas incluyen HTTPS, analytics y manejo de errores
