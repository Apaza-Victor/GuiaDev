1.1 Qué es Next.js

Definición

Next.js es un framework de React para construir aplicaciones web del lado del servidor (SSR) y estáticas (SSG). Se basa en React y añade enrutamiento, renderizado híbrido, optimización de imágenes y más funcionalidades listas para producción.

Fue creado por la empresa Vercel y es uno de los frameworks de React más populares del ecosistema, usado por empresas como Netflix, TikTok y Twitch.

Características principales

CaracterísticaDescripción
SSR y SSGRenderizado en servidor y generación estática
App RouterSistema de rutas basado en el sistema de ficheros
Optimización de imágenesComponente next/image con carga diferida
API RoutesCrear endpoints backend dentro del proyecto
TypeScriptSoporte nativo de primera clase

  return (

      <h1>Hola, Next.js</h1>
      <p>Esta página se renderiza en el servidor.</p>
    </main>
  );

1.2 Por qué usar Next.js en vez de React puro

Ventajas sobre React puro

React es una librería para construir interfaces, pero deja muchas decisiones a tu cargo. Next.js es un framework que incorpora soluciones probadas:

  • Enrutamiento: React necesita react-router; Next.js usa el sistema de ficheros
  • SEO: React renderiza en cliente (malo para SEO); Next.js renderiza en servidor
  • Rendimiento: Code splitting y optimización automática
  • Backend integrado: API routes sin montar un servidor aparte
  • Configuración: Cero configuración con create-next-app

Cuándo elegir cada uno

NecesidadReact puroNext.js
SEO e indexaciónComplicado Óptimo
SPA simple IdealPosible
Aplicación completaMucho trabajo manual Ideal
Rutas dinámicasConfiguración manualAutomático
Si necesitas una SPA puramente interactiva usa React con Vite. Si quieres una app completa, con SEO y backend, elige Next.js.

1.3 SSR, SSG, ISR y CSR: estrategias de renderizado

Las cuatro estrategias de renderizado

EstrategiaSiglasQué haceCuándo usar
Client Side RenderingCSRRenderiza en el navegador con JavaScriptPanel de usuario, apps interactivas
Server Side RenderingSSRRenderiza en el servidor en cada peticiónDatos dinámicos en tiempo real
Static Site GenerationSSGGenera HTML estático en build timeBlogs, docs, páginas públicas
Incremental Static RegenerationISRSSG con regeneración en segundo planoCatálogos, noticias, datos semi-dinámicos

SSR: renderizado en servidor

// app/products/page.tsx (SSR - se renderiza en cada petición)
export default async function Products() {
  const res = await fetch(
    "https://api.example.com/products",
    { cache: "no-store" }
  );
  const products = await res.json();

  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>{p.name}</li>
      ))}
    </ul>
  );
}
La estrategia por defecto en Next.js depende de cada ruta. Las rutas estáticas se generan en build time y las dinámicas se renderizan en servidor.

1.4 SSG e ISR con revalidate

SSG y cache por defecto

Cuando una ruta app/ no usa datos dinámicos, Next.js la genera como estática (SSG) en tiempo de compilación.

ISR con revalidate

Para datos que cambian de vez en cuando puedes usar regeneración estática incremental:

// app/posts/page.tsx (ISR - se regenera cada 60 segundos)
export default async function Posts() {
  const res = await fetch("https://api.example.com/posts", {
    next: { revalidate: 60 },
  });
  const posts = await res.json();

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

Diferencias de un vistazo

EstrategiaComportamiento
SSGSe genera una vez al compilar, no cambia
ISRSe regenera cada revalidate segundos
SSRSe renderiza en cada petición
CSRSe renderiza en el navegador

Evolución de las versiones

VersiónAñoAportación clave

Next.js 132022App Router y Server Components (beta)
Next.js 142023App Router estable, Turbopack
Next.js 152024Async request APIs, mejoras de rendimiento

Ecosistema que lo rodea

  • React: La librería base de todo
  • Tailwind CSS: Estilos preferidos por defecto
  • Vercel: Plataforma de despliegue oficial
  • Auth.js: Autenticación para aplicaciones
  • Prisma: ORM para bases de datos
A partir de Next.js 13 el App Router es la forma recomendada de trabajar. El Pages Router sigue disponible pero está en modo de compatibilidad.

1.6 Casos de uso en el mundo real

Empresas que usan Next.js

  • Vercel: Plataforma oficial de despliegue
  • Netflix: Algunas de sus experiencias de usuario
  • TikTok: Páginas de marketing
  • Twitch: Interfaces de su plataforma
  • Notion: Documentación y marketing

Tipos de proyectos ideales

  • E-commerce: Catálogos con ISR y carritos
  • Blogs: SSG con gran rendimiento y SEO
  • Dashboards: SSR y CSR combinados
  • Dashboards comerciales: SaaS completos con API propia

Ejemplo: Capa de datos combinada

// app/blog/[slug]/page.tsx
export default async function Post({
  params,
}: {
  params: { slug: string };
}) {
  const res = await fetch(
    `https://api.example.com/posts/${params.slug}`,
    { next: { revalidate: 3600 } }
  );
  const post = await res.json();

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
    </article>
  );
}

Resumen

**Lo que aprendiste en esta sección:** - Next.js es un framework de React que funciona como herramienta completa para producción - Ofrece SSR, SSG, ISR y CSR según la ruta y las necesidades - Mejora el SEO y el rendimiento respecto a React puro - Usa el App Router basado en el sistema de ficheros - Vercel es la plataforma de despliegue oficial - A partir de la versión 13 el App Router es la vía recomendada
