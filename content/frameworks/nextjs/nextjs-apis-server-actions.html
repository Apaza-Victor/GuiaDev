6.1 Route Handlers en app/api

Qué es un Route Handler

Un Route Handler es una función que responde a peticiones HTTP. Se define exportando funciones con nombres de métodos HTTP dentro de app/api/:

app/
└── api/
    └── usuarios/
        └── route.ts   # /api/usuarios

Crear un endpoint GET

// app/api/usuarios/route.ts
import { NextResponse } from "next/server";

export async function GET() {
  const usuarios = [
    { id: 1, nombre: "Ana" },
    { id: 2, nombre: "Carlos" },
  ];

  return NextResponse.json(usuarios);
}

Estructura de una ruta API

FunciónMétodo HTTP
GETLeer datos
POSTCrear datos
PUTActualizar completos
PATCHActualización parcial
DELETEEliminar
Usa `NextResponse.json()` para devolver respuestas JSON correctamente formateadas.

6.2 Crear endpoints con POST y PUT

Endpoint POST para crear

// app/api/usuarios/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function POST(request: NextRequest) {
  const body = await request.json();

  // Validación básica
  if (!body.nombre) {
    return NextResponse.json(
      { error: "El nombre es obligatorio" },
      { status: 400 }
    );
  }

  // Aquí guardarías en la base de datos
  const nuevoUsuario = { id: Date.now(), nombre: body.nombre };

  return NextResponse.json(nuevoUsuario, { status: 201 });
}

Endpoint PUT para actualizar

// app/api/usuarios/[id]/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function PUT(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const body = await request.json();
  // Actualizar el usuario con id = params.id
  return NextResponse.json({
    id: params.id,
    nombre: body.nombre,
  });
}
El `request` de tipo `NextRequest` permite leer el cuerpo con `request.json()` y los headers.

6.3 Qué son las Server Actions

Concepto

Las Server Actions son funciones asíncronas que se ejecutan en el servidor y se pueden invocar desde componentes cliente. Evitan escribir endpoints manuales para operaciones simples:

// app/actions.ts
"use server";

export async function guardarPost(formData: FormData) {
  const titulo = formData.get("titulo");
  const contenido = formData.get("contenido");

  // Aquí se podría guardar en una base de datos
  console.log("Guardando:", titulo, contenido);

  return { ok: true };
}

Diferencias con Route Handlers

Route HandlerServer Action
Endpoint HTTP explícitoFunción transparente
Se llama con fetchSe invoca directamente
Más control sobre la URLMás simple para formularios
Ideal para APIs públicasIdeal para acciones internas
Cualquier archivo que exporte acciones debe comenzar con la directiva `"use server"`.

6.4 Uso de Server Actions con formularios

Acción en un componente servidor

// app/contacto/page.tsx
import { guardarContacto } from "./actions";

export default function Contacto() {
  return (
    <form action={guardarContacto}>
      <input name="email" type="email" placeholder="Email" />
      <input name="mensaje" placeholder="Mensaje" />
      <button type="submit">Enviar</button>
    </form>
  );
}

Definir la action en actions.ts

// app/contacto/actions.ts
"use server";

export async function guardarContacto(formData: FormData) {
  const email = formData.get("email");
  const mensaje = formData.get("mensaje");

  if (!email || !mensaje) {
    return { error: "Faltan datos" };
  }

  // Guardar o enviar el contacto
  return { ok: true };
}

Ventajas de las Server Actions

  • No necesitas escribir fetch manual
  • Progresive enhancement: funciona sin JavaScript
  • Gestionan la revalidación de rutas automáticamente
  • Simplifican el código de formularios

6.5 Interacción con estado y pendiente

Usar useActionState para gestionar formularios

// app/formulario-con-estado.tsx (Client Component)
"use client";

import { useActionState } from "react";
import { crearUsuario } from "./actions";

export default function FormularioConEstado() {
  const [estado, formAction] = useActionState(crearUsuario, {
    mensaje: null,
  });

  return (
    <form action={formAction}>
      <input name="nombre" placeholder="Nombre" />
      <button type="submit">Crear usuario</button>
      {estado.mensaje ? <p>{estado.mensaje}</p> : null}
    </form>
  );
}

Revalidar rutas tras una acción

// app/actions.ts
"use server";

import { revalidatePath } from "next/cache";

export async function crearPost() {
  // Crear el post en la base de datos
  revalidatePath("/blog");
  return { ok: true };
}
'useActionState' reemplaza a 'useFormState' en React 19 y permite gestionar el estado y los errores de formularios.

6.6 Buenas prácticas de APIs y acciones

Recomendaciones

  • Valida siempre los datos recibidos antes de procesarlos
  • Responde códigos HTTP correctos (200, 201, 400, 404...)
  • Protege las Server Actions con comprobaciones de permisos
  • No expongas datos sensibles en las respuestas
  • Usa revalidatePath para refrescar rutas tras mutar datos

Manejo de errores típico

// app/api/productos/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(request: NextRequest, { params }: any) {
  try {
    const datos = await obtenerProductos();
    return NextResponse.json(datos);
  } catch (error) {
    return NextResponse.json(
      { error: "Error interno del servidor" },
      { status: 500 }
    );
  }
}
CódigoSignificado
200Operación correcta
201Recurso creado
400Petición inválida
401No autenticado
404No encontrado
500Error de servidor

Resumen

**Lo que aprendiste en esta sección:** - Los Route Handlers son funciones dentro de app/api/ - Cada método HTTP se exporta como una función con su nombre - Las Server Actions se ejecutan en el servidor con "use server" - Se enlazan a formularios mediante la prop action - revalidatePath refresca rutas tras mutar datos - Valida siempre los datos y responde códigos HTTP correctos
