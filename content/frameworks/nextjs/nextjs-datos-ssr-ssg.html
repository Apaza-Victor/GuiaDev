5.1 Server Components y fetching de datos

Cómo obtener datos en el servidor

En los Server Components puedes hacer fetch directamente dentro del componente. Next.js detecta si la ruta es estática o dinámica automáticamente:

// app/posts/page.tsx
export default async function Posts() {
  const res = await fetch("https://api.example.com/posts");
  const posts = await res.json();

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

Comportamientos del fetch

OpciónComportamiento
Sin opcionesSe cachea como SSG
{ cache: "no-store" }SSR, se renderiza en cada petición
{ next: { revalidate } }ISR, se regenera cada N segundos
Hacer `fetch` directamente en la función del componente es posible gracias a que este se ejecuta en el servidor.

5.2 Componentes cliente con la directiva "use client"

Cuándo usar un componente cliente

Usa la directiva "use client" cuando necesites estado, eventos o efectos. Estos componentes se ejecutan en el navegador:

// app/components/FormularioLogin.tsx
"use client";

import { useState } from "react";

export default function FormularioLogin() {
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log("Iniciar sesión con", email);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        placeholder="Email"
      />
      <input
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
        placeholder="Contraseña"
      />
      <button type="submit">Entrar</button>
    </form>
  );
}
La directiva `"use client"` debe ir en la primera línea del archivo, antes de cualquier import.

5.3 Fetch de datos en componentes cliente (CSR)

Obtener datos con useEffect

// app/components/ListaProductos.tsx
"use client";

import { useEffect, useState } from "react";

interface Producto {
  id: number;
  nombre: string;
}

export default function ListaProductos() {
  const [productos, setProductos] = useState<Producto[]>([]);
  const [cargando, setCargando] = useState(true);

  useEffect(() => {
    fetch("https://api.example.com/productos")
      .then((res) => res.json())
      .then((data) => {
        setProductos(data);
        setCargando(false);
      });
  }, []);

  if (cargando) {
    return <p>Cargando productos...</p>;
  }

  return (
    <ul>
      {productos.map((p) => (
        <li key={p.id}>{p.nombre}</li>
      ))}
    </ul>
  );
}
Para datos que cambian constantemente (notificaciones, precios en vivo) puede ser útil un renderizado en cliente (CSR).

5.4 Revalidación incremental (ISR)

Qué es ISR

ISR combina lo mejor de SSG y SSR: sirve HTML estático rápido, pero se regenera en segundo plano cada cierto tiempo definido por revalidate:

// app/noticias/page.tsx
export default async function Noticias() {
  const res = await fetch("https://api.example.com/noticias", {
    next: { revalidate: 300 }, // regenerar cada 5 minutos
  });
  const noticias = await res.json();

  return (
    <ul>
      {noticias.map((n) => (
        <li key={n.id}>{n.titulo}</li>
      ))}
    </ul>
  );
}

Usos típicos de ISR

  • Catálogos de productos: precios y stock actualizados
  • Blogs: nuevas entradas sin recompilar
  • Noticias: contenidos con frecuencia moderada

Ventajas respecto a SSG puro

SSGISR
Contenido congelado al compilarSe actualiza cada revalidate
No refleja datos nuevosMuestra datos frescos
Debes recompilar para cambiosRegenera en segundo plano

5.5 generateStaticParams para rutas dinámicas

Generar rutas estáticas con datos

Para pre-generar páginas dinámicas conocidas de antemano, usa generateStaticParams:

// app/posts/[id]/page.tsx
export async function generateStaticParams() {
  const res = await fetch("https://api.example.com/posts");
  const posts = await res.json();

  return posts.map((post) => ({ id: String(post.id) }));
}

export default async function Post({
  params,
}: {
  params: { id: string };
}) {
  const res = await fetch(
    `https://api.example.com/posts/${params.id}`
  );
  const post = await res.json();

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
    </article>
  );
}
Las rutas no enumeradas en `generateStaticParams` se renderizan bajo demanda si se visitan.

5.6 Consejos para elegir la estrategia correcta

Guía rápida de decisión

¿Tipo de contenido?Estrategia
Público y casi no cambiaSSG
Público pero cambia a vecesISR
Personalizado por usuarioSSR o CSR
Interactivo en tiempo realCSR

Buenas prácticas

  • Prefiere Server Components cuando no necesites estado
  • Usa ISR en lugar de SSR para contenidos con tráfico alto
  • Separa los componentes que sí usan hooks en archivos cliente
  • Combina SSR para el esqueleto y CSR para la interacción

Ejemplo combinado

// app/usuario/page.tsx (Server Component)
import PerfilCliente from "./PerfilCliente";

export default async function Usuario() {
  const res = await fetch("https://api.example.com/perfil");
  const perfil = await res.json();

  return (
    <div>
      <h1>Hola, {perfil.nombre}</h1>
      <PerfilCliente datos={perfil} />
    </div>
  );
}

Resumen

**Lo que aprendiste en esta sección:** - Los Server Components permiten hacer fetch directamente en el componente - La directiva "use client" convierte un componente en cliente - En client components se obtienen datos con useEffect (CSR) - ISR con revalidate regenera las páginas estáticas en segundo plano - generateStaticParams pre-genera rutas dinámicas - Elige la estrategia según cuánto cambie tu contenido
