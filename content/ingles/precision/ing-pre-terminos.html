Argument vs Parameter

Objetivo

Resolver las parejas de términos que hasta los seniors confunden, con su diferencia clara y ejemplos reales de código y docs.

Argument vs Parameter

InglésEspañolDiferencia Escuchar
argumentargumento (valor real)el valor que pasas en la llamada
parameterparámetro (declaración)la variable declarada en la firma
function greet(name) { ... }        // "name" es el PARAMETER
greet("Ana");                       // "Ana" es el ARGUMENT

"The function takes two parameters; I passed three arguments — that's a bug."
Los parámetros se declaran; los argumentos se pasan. En JS/TS además existe rest parameters (...args) y default parameters; en inglés de docs: "accepts an optional parameter", "pass an argument".

Method vs Function

InglésEspañolDiferencia Escuchar
functionfunción (libre)bloque reutilizable independiente
methodmétodofunción que vive dentro de un objeto/clase
Toda method es una función; no toda función es un method. La doc de JS te lo marca: Array.prototype.push() es method; JSON.parse() es function estática. Decir "the parse method" es normal; decir "the method of the array" cuando el array no es objeto, no.

Run vs Execute vs Invoke

VerboRegistroEjemplo natural Escuchar
runinformal, el del día a díarun the tests · run the app locally
executeformal / SQL / binariosexecute the query · execute a script
invokellamada a función/APIinvoke the callback · the function is invoked
En una conversación diaria nadie dice "let's execute the project". El que más se usa es run: "Let's run the build and see." "Invoke" suena a lenguaje de libs y frameworks: "the hook is invoked on every render." Y por cierto: "call" es el pan nuestro: call a function.

Práctica

Completa con la palabra correcta (argument / parameter / method / function / run / execute / invoke):

  1. "I passed three ______ to `parseUser`, but the signature only declares two ______."
  2. "`getUserById` is a ______ of the UserService class."
  3. "Can you ______ the test suite before pushing?"
  4. "The event handler is ______ on every click."

Modelo: "I passed three arguments to `parseUser`, but the signature only declares two parameters." / "getUserById is a method of the UserService class." / "Can you run the test suite before pushing?" / "The event handler is invoked on every click."

Endpoint vs Route vs API

InglésEspañolAlcance Escuchar
APIinterfaz / APIel contrato completo de comunicación
endpointel punto URL precisoPOST /api/users
routeruta (enrutado del servidor)el cómo el server mapea cada URL
// Express: defines a route. From outside, it's an endpoint.
app.get("/api/users", handler)      // "route" aquí

// In docs you read: "This endpoint returns the list of users."
// In code/discussion: "Let's add a route for the health check."
"La API del frontend" (interfaz pública de tu módulo) también se llama API surface: "we keep the API surface small." Y no confundas endpoint con URL base: el endpoint incluye método + path + parámetros: GET /v2/users/:id.

Compile vs Build vs Transpile

VerboEspañolEjemplo Escuchar
compilecompilarC# → IL · Go → binario
buildcompilar y empaquetarbundling, minificar, assets finales
transpiletraducir a otro lenguajeTS → JS · JSX → JS
En JS y frontend casi nunca escucharás "compile": se usa build. "This transpiles TypeScript to JS" es la frase correcta; "this compiles TS to JS" es aceptable pero menos preciso. En .NET y Java sí: "the code compiled without errors".

Práctica

Traduce estas frases reales de standup/docs:

  1. "Esa biblioteca la llamamos cuando queremos; es una dependencia nuestra."
  2. "El endpoint DELETE /api/sessions ya está expuesto, solo falta configurar la ruta."
  3. "Bun transpila TypeScript muy rápido y el build en producción tarda 40 segundos."

Modelo: "That library is something we call when we need it; it's a dependency of ours." / "The DELETE /api/sessions endpoint is already exposed; we just need to wire up the route." / "Bun transpiles TypeScript really fast, and the production build takes about 40 seconds."

Otras Parejas Clave

El mapa de acciones sobre datos

ParejaDefiniciónEjemplo Escuchar
parseleer texto estructuradoparse the JSON response

refactormejorar por dentro SIN cambiar el comportamientorefactor this component
rewritereescribir desde cerorewrite the legacy module
migratetrasladar sistema/datosmigrate to PostgreSQL

Matices que te salvan en code review

  • parse vs serialize: operaciones inversas. JSON.stringify() serializes; JSON.parse() parses. "We send the serialized payload and the client parses it."
  • refactor vs rewrite: refactor = mismo comportamiento, mejor estructura; rewrite = empiezas de cero. "Rewrite" asusta y cuesta caro; "refactor" es incremental. En PR: "small refactor, zero behavior change."
  • migrate vs port: migras usuarios/datos a un nuevo sistema; portas software a otra plataforma/OS. "We migrated the data (no data loss) and then deprecated the old API."
  • deprecate vs remove: primero se deprecates (mantienes con avisos), luego se removes. "It's deprecated, we plan to remove it in v3."
  • null vs undefined: en JS, null suele ser "vacío intencional" y undefined "sin asignar". Di el tipo en inglés: "it's null, not undefined".
Regla conversacional: primero deprecate, después remove. Si alguien dice "let's remove it" y todavía hay usuarios, responde "let's deprecate it first". Precisión = menos bugs y menos drama.

Práctica

Elige la palabra correcta en cada frase:

  1. "We plan to ______ the query builder in v2 but won't ______ it until v3." (deprecate / remove)
  2. "This repo is a mess, we should ______ it from scratch." (refactor / rewrite)
  3. "Don't ______ the request body; just ______ the JSON from the response." (parse / serialize)
  4. "The mobile app was ______ to Android and the DB was ______ to the new schema." (migrated / ported)

Modelo: "We plan to deprecate the query builder in v2 but won't remove it until v3." / "This repo is a mess, we should rewrite it from scratch." / "Don't serialize the request body; just parse the JSON from the response." / "The mobile app was ported to Android and the DB was migrated to the new schema."
