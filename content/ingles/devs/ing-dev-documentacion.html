Commits y PRs Convencionales

Conventional Commits: los tipos y cuándo usarlos

feat: add OAuth login flow            (nueva función)
fix: prevent duplicate submissions    (bug corregido)
docs: update installation steps       (solo documentación)
refactor: extract validation helper   (sin cambiar comportamiento)
test: cover empty-cart checkout       (tests)
chore: bump dependencies              (mantenimiento)
perf: cache user lookups              (rendimiento)
style: format with prettier           (formato)

El verbo en presente, modo indicativo

El mensaje completa la frase mágica: "If applied, this commit will ___" :

  • ✅ add dark mode toggle → "...will add dark mode toggle"
  • ❌ ~~added~~, ~~fixes~~, ~~changes~~ (el pasado no aplica a la fórmula)
  • Cuerpo opcional: qué y por qué (el diff ya dice el cómo).

Descripción de PR que los reviewers aman

## What does this PR do?
Adds rate limiting to the public API endpoints.

## Why is it needed?
We're seeing bursts from scrapers (see #231).

## How was it tested?
- Unit tests for the limiter config
- Load-tested locally at 500 req/s

## Screenshots / Notes
Breaking change: none. Config via RATE_LIMIT env var.

Práctica final

Escribe el Quick Start (máx 10 líneas) de una herramienta tuya: requisitos, instalación, un comando de uso, una nota de advertencia. Luego revisa: ¿todo en imperativo? ¿presente simple? ¿una idea por oración?
