Comentar un Pull Request

Objetivo

Comentar PRs con el tono exacto que usan los equipos anglo: directo en lo técnico, suave en lo humano.

Vocabulario de estados de revisión

EstadoFrase estándar
Aprobado"LGTM 🚀" (looks good to me) / "Approving — nice work!"
Casi listo"Almost there! Just a couple of nits." (nit = detalle menor)
Cambios necesarios"Requesting changes: see comment on the auth logic."
Pregunta antes de aprobar"One question before I approve: why the extra query here?"
No es tuyo el tema"Adding @sara who owns this module."

Plantillas de comentarios frecuentes

SituaciónComentario modelo
Naming confuso"Nit: could we rename `data` to `userPayload`? Makes it easier to scan."
Código duplicado"This looks similar to `utils/date.ts`. Could we reuse that helper instead?"
Falta test"Could we add a test for the empty-cart case? That's where I'd expect this to break."
Preocupación de rendimiento"This will fire N+1 queries on large carts. What about batching with Promise.all?"
Elogio específico"Love how you handled retries here 👏"
Estilo/opinión no bloqueante"Totally optional, but a switch might read cleaner than nested ifs."
Convención útil: marca tus comentarios con prefijos — nit: (opcional), question: (necesito entender), suggestion: (mejora propuesta), sin prefijo = importante.

Dar Feedback con Tacto

La fórmula del feedback anglosajón

Crítica directa al código, indirección hacia la persona. Estructura: observación → impacto → pregunta/sugerencia:

✗ "This function is too long and badly written."

✓ "This function does a lot at once. It's hard to
   follow the happy path — could we extract the
   validation into its own helper? Would make it
   much easier to test."

Suavizadores gramaticales

Duro ❌Suavizado ✅
This is wrong.I might be missing something, but shouldn't this check come first?
You forgot the tests.Would it make sense to add coverage for X?
This breaks everything.This seems to break the checkout flow on Safari — repro steps attached.
Don't do it like that.Have we considered using the existing pattern here?
That's overengineering.Could we start simpler and iterate if we need more?

Recibir feedback como nativo

Aceptar:      "Good catch, fixing now." · "Fair point!"
              "TIL, thanks!" (today I learned)
Discutir:     "I hadn't considered that. My thinking was
               X because Y — what do you think?"
              "Makes sense. Pushing an update shortly."
Rechazar bien:"I see where you're coming from; in this case
               I'd keep it as is since... — thoughts?"
"Good catch!" es LA frase mágica del inglés dev: reconoce el aporte del otro sin admitir incompetencia. Úsala siempre que alguien encuentre un error tuyo.

Discutir Trade-offs

El lenguaje de las decisiones técnicas

Toda discusión de arquitectura es un trade-off. Estas frases te dejan participar aunque tu inglés no sea perfecto:

FunciónFrase
Plantear opciones"We have two options here: A gives us speed, B gives us safety."
Pesar pros/contras"The upside is performance; the downside is complexity."
Dar tu recomendación"If I had to choose, I'd go with A for now."
Condicional pragmático"Let's go simple now and revisit if traffic grows."
Marcar deuda consciente"We're taking on some tech debt here — let's track it as a follow-up issue."
Cerrar la discusión"Sounds like we have consensus on A. Any strong objections? No? Let's move forward."

Frases para reuniones técnicas difíciles

  • Pedir datos antes de decidir: "Can we benchmark both approaches first?"
  • Proteger el alcance: "Is this in scope for the current sprint?"
  • Discrepar con respeto: "I see it differently — hear me out."
  • Admitir límites: "That's outside my wheelhouse; @expert, thoughts?"
  • Registrar decisión: "Let's document this decision in the ADR."
Silencio = consentimiento en culturas anglo. Si no estás de acuerdo, DEBES decirlo en la reunión ("I'd push back a little on that"); callarte y quejarse después se lee mal.

Práctica final

Situación: proponen reescribir todo el frontend en otro framework. Escribe 4 frases: una preguntando por datos, una señalando el trade-off principal, una alternativa más pequeña y una para cerrar.
