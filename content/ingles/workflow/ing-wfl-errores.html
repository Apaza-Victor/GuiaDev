Mensajes de Error Frecuentes

Objetivo

Entender el error de la terminal a la primera y poder describir lo que ves sin leer mal la palaba clave del mensaje.

Los errores que verás mil veces

MensajeQué pasa en realidad

Cómo armar la frase del error

"I'm getting a 'cannot find module' error when I
 run the tests."
"Which directory is it looking in? The module is
 in node_modules, right?"
"It's throwing 'permission denied' on the logs
 folder. Probably a Docker volume issue."
Kit de primeros auxilios del error: 1) copia el stack trace, 2) di la primera línea del error (no leas 40 líneas en voz alta), 3) añade qué comando ejecutabas. Eso es el 90% del bug report oral.

Niveles de Log

La escala debug → fatal

NivelPara qué se usa
debugdetalles finos para depurar, no va a producción normalmente
infoeventos normales: "server started", "user logged in"
warnalgo raro pero recuperable: deprecado, retry
errorfalla concreta que conviene atender
fatalcatastrófico: el proceso muere o ya no sirve

Cuando veas WARN no paniques; cuando veas FATAL sí. Los equipos anglo describen el nivel antes que el contenido: "It's a fatal — the pod keeps restarting".

Describir un Error a un Colega

La fórmula para pedir ayuda técnica

Los devs anglohablantes piden ayuda con una estructura fija: qué comando/cuándo + qué error exacto + qué intentaste. Nada de "it doesn't work".

PasoFrases modelo
1. Cuándo/cómoI'm getting 'Cannot find module X' when I run the tests.
2. Lo que vesThe stack trace points to jwt.ts, line 42.
3. Lo que intentasteI already tried clearing node_modules and reinstalling.
4. Lo que esperasShould I just pin the package version, or is there a better fix?

Errores que verás en logs ajenos

  • Time out / timed out: "The request timed out after 10 seconds." (no "se hizo late")
  • It hangs / it's hanging: el proceso se queda colgado sin responder
  • It keeps crashing: se cae una y otra vez (loop)
  • It's intermittent: falla de forma intermitente, no reproducible a la primera

Práctica final

Describe en inglés este error (escribe los 4 pasos de la fórmula): levantas la app con npm run dev, sale error EADDRINUSE: address already in use :3000, e intentaste cambiar el puerto.

Di en voz alta el paso 1 y el paso 3:

  • I'm getting "EADDRINUSE: address already in use" on port 3000 when I run npm run dev.
  • I already tried killing the process and switching the port, still the same.
