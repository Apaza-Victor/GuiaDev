Estados y Tipos de Ticket

Objetivo

Leer un tablero en Jira, Trello o Azure DevOps en inglés y mover tarjetas sin tener que adivinar qué significa cada estado.

Tipos de ticket: no es solo "issue"

TipoQué es Escuchar
Bugcomportamiento incorrecto, esto hay que arreglarlo
Epiciniciativa grande que agrupa historias
Storyfuncionalidad con valor para el usuario
Tasktrabajo técnico sin valor directo de usuario

Diferencia clave: blocked es que algo externo te impide seguir; on hold es que el equipo decidió pausarlo. Decir "this ticket is blocked" cuando solo es pausa confunde a los anglohablantes.

Regla práctica anglosajona: priority = cuándo lo hacemos, severity = cuánto duele. En Jira vienen juntos, pero un bug cosmetic con high priority puede existir: lo arreglas pronto porque molesta a un cliente importante.

User Stories y Acceptance Criteria

La fórmula "As a... I want... So that..."

La user story clásica describe quién, qué y para qué. Escribirla bien en inglés es mitad skill de producto, mitad skill de idioma:

ParteEjemplo Escuchar
As a... (quién)As a returning customer,
I want... (qué)I want to save my payment method,
So that... (para qué)so that I can check out faster on my next order.

Acceptance criteria y Definition of Done

STORY: As a returning customer, I want to save my
       payment method so that I can check out faster.

ACCEPTANCE CRITERIA:
- [ ] User can save a card from the checkout page
- [ ] Saved cards show masked (e.g. **** 4242)
- [ ] Card can be removed from Settings
- [ ] Saving a card requires 2FA

DEFINITION OF DONE:
- Code merged into main
- Covered by automated tests
- QA signed off
ExpresiónUso Escuchar
definition of donela lista de requisitos para considerar "terminado"
moving to donepasar el ticket al estado Done
flagging it as blockedmarcar el ticket como bloqueado
reopened because it regressedse reabrió porque volvió a fallar
splitting the storypartir la historia en piezas más chicas
"Done" no significa "yo ya codeo": significa definition of done cumplida. Los equipos anglo se quejan en la retro: "We marked it done but QA never signed off." Done sin DoD es medio trabajo.

Práctica

Escribe en inglés:

  1. Una user story para "recordar el carrito cuando el usuario cierra sesión" con las tres partes (As a / I want / So that).
  2. Los criterios de aceptación de esa historia (2 a 3, en frases "the user can..." / "the cart is...").

Frases para decirlas en voz alta (di la tuya y compara):

  • As a logged-in user, I want my cart to be saved so that I can finish my purchase later.
  • We're moving this to done, QA signed off.
  • I'm flagging this ticket as blocked — we're waiting on the API credentials.
  • This ticket was reopened because the payment flow regressed in QA.
