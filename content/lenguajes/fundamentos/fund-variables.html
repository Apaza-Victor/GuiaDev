¿Qué son las variables?

Un programa manipula datos: números, textos, respuestas Sí/No. Para guardarlos usa variables, que son cajas con etiqueta en la memoria del computador donde se almacena un valor que puede cambiar durante la ejecución.

Imagina un casillero escolar: cada casilla tiene un nombre que la identifica (la etiqueta) y dentro hay un solo contenido (el valor). Puedes abrir la casilla, mirar lo que hay, sacarlo o modificarlo; lo que no puedes es guardar dos cosas a la vez en la misma casilla.

Una variable se describe con tres atributos:

  • Nombre: identificador único con el que nos referimos a la casilla (edad).
  • Tipo: qué clase de datos puede guardar (Entero, Real, Carácter, Lógico).
  • Valor actual: el dato guardado en este instante, que muta (cambia) durante la ejecución.

En matemáticas, x es la incógnita, un valor que se descubre y no varía. En programación, x es una caja: primero guardas el 10, luego le sumas 5 y el contenido pasa a ser 15. La variable "vive" de verdad y cambia de valor paso a paso mientras el programa corre.

Una pista para leer el pseudocódigo: cuando veas x <- 15, lee "guarda el valor 15 DENTRO de la caja x", no "x es igual a 15".

---

Tipos de datos básicos

No todos los datos son iguales: el tipo determina qué valores puede tomar una variable y qué operaciones se pueden hacer con ella. Estos son los cuatro tipos básicos de PSeInt:

TipoGuardaEjemplosUso típico
EnteroNúmeros sin decimales-3, 0, 18, 540Edades, cantidades, contadores
RealNúmeros con decimales-2.5, 0.0, 3.1416Precios, temperaturas, medias
CarácterUn único símbolo'A', '5', '@'Una letra, una opción de menú
LógicoVerdadero o falsoV, FCondiciones y banderas Sí/No

¿Por qué importa el tipo?

Porque define qué puedes hacer con el valor: con un entero puedes restar, con un carácter no. Además, el tipo previene errores: no tiene sentido "sumar" dos nombres ni dividir un verdadero entre dos.

Dos matices importantes:

  • Carácter vs. cadena: un Carácter es una sola letra o símbolo; una cadena (como "Hola") es una secuencia de varios caracteres. PSeInt maneja textos y conviene tener clara la diferencia.
  • Booleano: en PSeInt se llama Lógico y solo admite V (verdadero) o F (falso). Será la base de todas las decisiones que verás en la lección de Operadores.

Declaración y asignación

Declarar una variable es decirle al programa que existe y qué tipo tendrá. Asignar es darle un valor (o cambiárselo) en un momento concreto. Son dos acciones distintas y complementarias:

Algoritmo declaracionVsAsignacion
    // Declaración: crear la caja con su tipo
    Definir edad Como Entero
    Definir precio Como Real
    Definir inicial Como Caracter
    Definir aprobado Como Logico

    // Asignación: meter un valor dentro de la caja
    edad <- 18
    precio <- 12.50
    inicial <- 'M'
    aprobado <- V
FinAlgoritmo

La instrucción contador <- contador + 1 significa: lee el valor actual de la caja contador (por ejemplo 0), súmale 1 y guarda el resultado de nuevo en la caja (1). Aunque parezca una contradicción matemática, en programación es el pan de cada día. Así funciona un contador; un acumulador es igual, pero sumando cada vez un valor distinto (notas, ventas, kilómetros…).

OperaciónSintaxis PSeIntQué hace
DeclararDefinir x Como EnteroCrea la variable con su tipo
Asignar una constantex <- 5Guarda el valor 5 dentro de x
Asignar un resultadototal <- precio * cantidadEvalúa la expresión y guarda el valor

Ejemplo completo que combina un contador y un acumulador:

Algoritmo contadorYAcumulador
    Definir nota, suma, contador Como Entero
    suma <- 0
    contador <- 0

    Escribir "Nota 1:"
    Leer nota
    suma <- suma + nota      // acumulador: acumula la nota
    contador <- contador + 1 // contador: una nota más leída

    Escribir "Nota 2:"
    Leer nota
    suma <- suma + nota
    contador <- contador + 1

    Escribir "Notas leídas: ", contador
    Escribir "Suma total: ", suma
FinAlgoritmo

En PSeInt, <- es asignación y = es comparación. Usar uno donde debería ir el otro es uno de los errores más típicos de quien empieza; lo repasaremos a fondo en la próxima lección sobre operadores.

Constantes

Algunos valores jamás cambian durante un programa: el número π, el IVA de tu país, el máximo de intentos de una contraseña. Son constantes: variables "a prueba de cambios".

En PSeInt no existe una palabra reservada dedicada, pero la convención es declararla con Definir, escribir su nombre en MAYÚSCULAS y jamás reasignarla:

Algoritmo areaCirculo
    Definir PI Como Real
    Definir radio, area Como Real

    PI <- 3.1416

    Escribir "Ingrese el radio:"
    Leer radio
    area <- PI * radio * radio
    Escribir "Área: ", area
FinAlgoritmo

Los lenguajes reales garantizan esta inmutabilidad por ley: en C o Java se usa const, en Swift let. Intentar reasignar una constante produce un error de compilación, no una sorpresa en mitad de la ejecución.

¿Por qué conviene usar constantes?

  • Evitan errores: nadie puede cambiar PI por accidente a mitad del programa.
  • Auto-documentan: ver IVA comunica más que ver el número 0.16 suelto por el código.
  • Centralizan cambios: si el IVA cambia, solo se modifica una línea, no cuarenta repartidas por el programa.

Regla práctica: elige el valor concreto (por ejemplo 3.1416) una sola vez, en la constante; a partir de ahí, refiérete siempre a la constante, nunca al número.

Buenas prácticas de nombrado

Un buen nombre convierte el código en una historia que se lee sola; un mal nombre lo vuelve un jeroglífico. Estas son las reglas básicas:

El mismo algoritmo, antes y después de aplicar las reglas:

// ❌ Nombres incomprensibles
Definir a, b, c Como Real
a <- 100
b <- 12
c <- a / b
Escribir c

// ✅ Mismo algoritmo, nombres que se explican solos
Definir kilometros, litros, consumo Como Real
kilometros <- 100
litros <- 12
consumo <- kilometros / litros
Escribir "Consumo: ", consumo, " km/l"

El nombre es la primera forma de documentación del código. Si tardas más de dos segundos en entender qué guarda una variable, el nombre no cumple su función.

Errores comunes

1. Usar una variable sin declararla

// ❌ "edad" todavía no existe
Escribir edad

// ✅ Primero declara, después asigna, después usa
Definir edad Como Entero
edad <- 18
Escribir edad

2. Usarla sin inicializarla

Una variable declarada pero nunca asignada no tiene un valor conocido. Inicializa siempre los acumuladores y contadores (suma <- 0, contador <- 0) antes de usarlos; si no, la suma parte de un valor "basura".

3. Desbordamiento del tipo

Un Entero tiene un rango limitado: intentar guardar un número enorme (como 1234567890123) desborda la caja y produce resultados absurdos. Elige el tipo adecuado al tamaño real del dato.

4. Confundir asignación y comparación

// ❌ Esto compara, no guarda
// nota = 7

// ✅ Asignación correcta
nota <- 7

El símbolo <- guarda; el símbolo = pregunta. Mezclarlos genera errores muy difíciles de detectar.

5. Nombrar variables a, b, x1

A los cinco minutos ya nadie sabe si b era la base, el bono o la altura. Invierte tres segundos más en nombres reales y ahorrarás horas de confusión.

6. Mezclar tipos en las operaciones

Sumar un entero a un texto, dividir un carácter… Cada lenguaje (y PSeInt) tiene reglas de compatibilidad de tipos. Antes de operar, pregúntate: ¿estos dos valores son del mismo tipo?

Recuerda siempre el trío: declarar → inicializar → usar. Es el mismo orden mental con el que preparas y llenas una hoja de cálculo.

Ejercicios

Resuelve estos ejercicios en PSeInt (o a mano) para dominar variables y tipos. Están ordenados de menor a mayor dificultad:

  1. Ficha de persona: declara variables para nombre, edad (Entero), altura (Real) y soltero (Lógico); asígnales valores y muestra todas ellas con un Escribir.
  2. Promedio de dos notas: declara nota1 y nota2 como Real, asígnalas, calcula el promedio con suma y división, y muestra el resultado.
  3. Contador en tres pasos: partiendo de contador <- 0, ejecuta contador <- contador + 1 tres veces y muestra el valor final. Razona en voz alta qué contendrá la caja tras cada operación.
  4. Constante IVA: declara una constante IVA (Real, valor 0.16) y calcula el total de una compra de 950 sumando el impuesto. Muestra subtotal, impuesto y total.
  5. Caza de errores: corrige el siguiente pseudocódigo, que intenta calcular la edad que tendrá una persona dentro de 5 años. Encuentra al menos dos problemas:
    Algoritmo edadFutura
    Escribir anioActual + 5
    Definir anioActual Como Entero
    anioActual = 2005
FinAlgoritmo
