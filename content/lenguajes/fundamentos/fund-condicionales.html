La toma de decisiones

Hasta ahora los programas que hemos visto ejecutan sus instrucciones una tras otra, en orden. A eso se le llama ejecución secuencial. Pero un programa útil rara vez es solo una lista plana de pasos: necesita decidir. ¿Qué hago si el usuario es menor de edad? ¿Y si la nota no llega al mínimo? Esas preguntas solo se pueden responder si el programa es capaz de tomar decisiones en mitad de su ejecución.

La buena noticia es que la toma de decisión, por sofisticada que parezca, se reduce siempre a una única elección binaria: evaluar una condición que es verdadera (V) o falsa (F). No existe "más o menos": o la condición se cumple, o no se cumple. Sobre esa base de V/F construimos toda la lógica de decisión de un programa.

La decisión como un cruce de caminos

Visualmente, una decisión se dibuja en los diagramas de flujo como un rombo: dentro va la condición, y de él salen dos caminos (Sí/No) que se vuelven a reunir cuando termina. Así se dibujan los condicionales. Las computadoras eligen de esta forma binaria:

   ┌───────────┐
   │  inicio   │
   └─────┬─────┘
         │
         v
   ┌─────┴──────┐
   │ ¿nota >= 60?│  << decisión (V/F)
   └──┬──────┬──┘
     Sí│      │No
      v       v
  ┌───────┐ ┌──────────┐
  │ Aprobó │ │ Reprobó  │
  └───┬───┘ └────┬─────┘
      │          │
      └────┬─────┘
         │
         v
   ┌─────────────┐
   │   final     │
   └─────────────┘

El programa como combinación de piezas

Todo programa se construye combinando tres tipos de elementos básicos: secuencias (pasos en orden), decisiones (condicionales) y repeticiones (bucles, que veremos en la próxima lección). Si un programador no domina las decisiones, no puede escribir prácticamente ninguna lógica real. Sin condiciones no hay "lógica": no puedes reaccionar a datos de entrada, validar errores ni adaptar el comportamiento del programa a lo que ocurre en tiempo de ejecución.

Las computadoras no "piensan" ni "deciden" con intuición: solo comparan valores y comprueban si una condición da V o F. Toda la inteligencia que percibes en un programa es, al final, una gran cantidad de estas elecciones binarias bien combinadas.

---

if / else

El condicional más básico recibe el nombre de if (palabra que en muchos lenguajes significa "si"). En español, dentro de PSeInt, se escribe con Si. Su estructura permite ejecutar un bloque de instrucciones solo si se cumple una condición, y opcionalmente otro bloque cuando no se cumple.

Sintaxis en PSeInt

La forma más simple ejecuta algo solo cuando la condición es verdadera:

Algoritmo if_simple
    Definir nota Como Entero
    Escribir "Ingrese la nota:"
    Leer nota

    Si nota >= 60 Entonces
        Escribir "Aprobaste"
    FinSi

FinAlgoritmo

Cuando además queremos qué hacer si la condición es falsa, usamos la rama SiNo (que en otros lenguajes es else):

Algoritmo if_else
    Definir nota Como Entero
    Escribir "Ingrese la nota:"
    Leer nota

    Si nota >= 60 Entonces
        Escribir "Aprobaste"
    SiNo
        Escribir "Reprobaste"
    FinSi

FinAlgoritmo

Tabla de verdad mental

Condición (nota >= 60)Rama que se ejecutaResultado
VerdaderaSi ... Entonces"Aprobaste"
FalsaSiNo (else)"Reprobaste"

Siempre indenta (sangra) el interior del condicional con espacios: aunque PSeInt no lo exija estrictamente, ayuda a leer qué instrucciones pertenecen a cada rama. La buena indentación evita errores de comprensión.

if / else if / else

No siempre hay solo dos caminos. Muchas veces necesitamos evaluar varias condiciones alternativas y ejecutar una sola de ellas. Para eso encadenamos ramas con SiNo Si (que en otros lenguajes es else if), y cerramos con un SiNo final que actúa como caso por defecto.

Clasificación de edades con varias ramas

Algoritmo clasificar_edad
    Definir edad Como Entero
    Escribir "Ingrese su edad:"
    Leer edad

    Si edad < 18 Entonces
        Escribir "Eres menor de edad"
    SiNo Si edad < 65 Entonces
        Escribir "Eres adulto"
    SiNo
        Escribir "Eres un adulto mayor"
    FinSi

FinAlgoritmo

Fíjate en el orden: si la edad es 10, la primera condición (edad < 18) es verdadera y no evaluamos las demás. Si la edad es 30, la primera es falsa, la segunda (edad < 65) es verdadera, y el SiNo final no se toca.

El orden importa

La primera rama que resulte verdadera se ejecuta y las restantes se ignoran. Por eso conviene colocar primero los casos más específicos o más comunes. Si intercambias el orden, una rama puede "tragarse" las demás. Por ejemplo, si pusieras Si edad < 65 primero, nunca llegarías a distinguir al menor de edad.

Diagrama de ramas múltiples

   ┌──────────────┐
   │  leer edad   │
   └──────┬───────┘
          v
   ┌───────────────┐   Sí ┌──────────────┐
   │ ¿edad < 18?   │────▶│ menor de edad │
   └──────┬────────┘     └──────────────┘
         No│
          v
   ┌───────────────┐   Sí ┌──────────────┐
   │ ¿edad < 65?   │────▶│   adulto     │
   └──────┬────────┘     └──────────────┘
         No│
          v
   ┌───────────────┐
   │ adulto mayor  │
   └───────────────┘

Cada rama recibe exactamente una condición, y la secuencia de SiNo Si se evalúa en orden. Si ninguna condición coincide, se ejecuta el SiNo final; si no lo hay, no se ejecuta ninguna rama.

switch

Cuando una decisión depende exclusivamente de que una variable sea igual a uno de varios valores exactos, encadenar muchos SiNo Si resulta verboso y difícil de leer. Para esos casos existe la estructura switch, que en PSeInt se llama Segun.

Sintaxis en PSeInt

Segun variable Hacer
    caso1:
        // acciones si variable = caso1
    caso2:
        // acciones si variable = caso2
    De Otro Modo:
        // acciones si variable no coincide con ningún caso
FinSegun

Ejemplo: un menú de opciones

Algoritmo menu
    Definir opcion Como Entero
    Escribir "1. Sumar"
    Escribir "2. Restar"
    Escribir "3. Multiplicar"
    Escribir "4. Salir"
    Escribir "Elija una opción:"
    Leer opcion

    Segun opcion Hacer
        1:
            Escribir "Elegiste sumar"
        2:
            Escribir "Elegiste restar"
        3:
            Escribir "Elegiste multiplicar"
        4:
            Escribir "Saliste del programa"
        De Otro Modo:
            Escribir "Opción no válida"
    FinSegun

FinAlgoritmo

¿Cuándo conviene y cuándo no?

El Segun brilla cuando comparamos por valor exacto (opciones de un menú, códigos, estados). No sirve para comparaciones de rango: "si la edad está entre 18 y 65" no se puede expresar con un solo caso; para eso usamos if / else if con las condiciones que ya conoces.

Criterioif / else ifSegun (switch)
Igualdad con varios valores exactosFunciona, pero verbosoIdeal y legible
Comparaciones de rango (<, >, entre)IdealNo apto
Condiciones compuestas (Y / O)IdealNo apto
Menús con opciones numeradasFuncionaRecomendado

Regla rápida: si te encuentras escribiendo Si var = 1, Si var = 2, Si var = 3..., es señal de que deberías usar Segun.

Condiciones compuestas

Una sola condición a veces no basta. Queremos preguntar "¿es adulto en edad laboral?" que junta dos condiciones: edad >= 18 Y edad <= 65. Para combinar condiciones usamos los operadores lógicos: Y (AND), O (OR) y NO (NOT).

Operadores lógicos

OperadorResultado verdadero cuando…Ejemplo
YTodas las condiciones son verdaderasA Y B
OAl menos una condición es verdaderaA O B
NOLa condición es falsa (invierte)NO A

Ejemplo correcto e incorrecto

Algoritmo condiciones_compuestas
    Definir edad, credito Como Entero

    // ✅ Correcto: ambas deben cumplirse
    Si edad >= 18 Y edad <= 65 Entonces
        Escribir "Edad laboral"
    FinSi

    // ✅ Correcto: basta cumplir una
    Si edad < 18 O edad > 65 Entonces
        Escribir "Fuera del rango laboral"
    FinSi

    // ❌ Incorrecto: no se puede expresar un rango con O
    Si edad >= 18 O edad <= 65 Entonces
        Escribir "Esto se cumple SIEMPRE (error de lógica)"
    FinSi

FinAlgoritmo

El ejemplo incorrecto es un clásico: edad >= 18 O edad <= 65 es verdadero para cualquier edad (todo número es mayor o igual a 18, o menor o igual a 65). Para definir un rango hay que usar Y, no O.

Agrupación con paréntesis

Puedes combinar ambas con paréntesis para clarificar el orden, igual que en matemáticas. La expresión (A O B) Y C significa "A o B, pero además C".

// Tarjeta válida solo si (es estudiante O es empleado) Y además es mayor de 16
Si (estudiante O empleado) Y edad > 16 Entonces
    Escribir "Tarjeta habilitada"
FinSi

Algunos lenguajes aplican la evaluación en cortocircuito: si la primera parte de un Y es falsa, no evalúan la segunda (y viceversa con O). Depende del lenguaje, pero como buena práctica ordena las condiciones de forma que evites errores y costes innecesarios.

---

Errores comunes

1. Olvidar el FinSi

Cada Si debe cerrarse con su FinSi. Si falta, PSeInt mostrará un error y el resto del algoritmo quedará mal interpretado.

2. Usar = en lugar de comparación

// ❌ En muchos lenguajes = asigna, no compara
// Si x = 5 Entonces  →  podría asignar, no comparar

// ✅ Comparar usa operadores como == o la sintaxis de PSeInt
Si x = 5 Entonces
    Escribir "x es 5"
FinSi

En PSeInt el signo = ya se interpreta como igualdad dentro de una condición, pero en lenguajes como C, Java o JavaScript el operador de comparación es == y usar = es uno de los errores más típicos.

3. Ramas vacías que caen en orden en Segun

En algunos lenguajes, si olvidas el break de un switch, la ejecución "cae" al siguiente caso. Asegúrate de cerrar bien cada caso según la sintaxis que uses.

4. Usar Segun para rangos

Intentar expresar edad entre 18 y 65 con Segun no funciona: para rangos usa Si ... SiNo ....

5. Comparar reales con igualdad exacta

Definir a, b Como Real
a <- 0.1
b <- 0.3
// ❌ a + a = b podría ser FALSO por errores de precisión
// ✅ comparar reales alejando: abs(a - b) < 0.0001

6. Condición con fluctuaciones

Una condición que cambia de valor entre evaluaciones (por ejemplo, depende de algo aleatorio o de otra línea que la modifica) produce comportamientos impredecibles. Evalúa una vez y guarda el resultado si lo necesitas estable.

Ejercicios

Resuelve estos ejercicios en PSeInt o en tu lenguaje favorito. Están ordenados de menor a mayor dificultad:

  1. Mayor de tres números: lee tres números y con varios if / else if determina cuál es el mayor (o si hay empate).
  2. Par o impar: lee un número y con la operación módulo (%) y un condicional imprime si es par o impar.
  3. Menú con Segun: muestra un menú de 4 opciones, lee la opción elegida y con Segun reacciona a cada una; usa De Otro Modo para entradas no válidas.
  4. Clasificar por edad: lee una edad y con ramas múltiples clasifícala en niño, adolescente, adulto o adulto mayor (define tú los rangos y cuida el orden).
  5. Validar rango compuesto: lee un número y con una condición compuesta (Y) valida que esté dentro de un rango, p. ej. entre 1 y 100 incluidos.
