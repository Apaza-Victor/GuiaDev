Repetir sin copiar código

Pronto te toparás con una necesidad inevitable: hacer lo mismo muchas veces. ¿Imprimir los números del 1 al 100? ¿Sumar las notas de toda una clase? ¿Mostrar un menú una y otra vez hasta que el usuario decida salir? La solución ingenua sería copiar y pegar el mismo bloque un centenar de veces… pero eso es un desastre: el código se hace gigante, es casi imposible de mantener y cualquier cambio obliga a editar cada copia.

Para eso existen los bucles (también llamados ciclos o repeticiones): estructuras que permiten ejecutar un bloque de instrucciones varias veces, de forma controlada. Son uno de los tres pilares de la programación junto con la secuencia y las decisiones.

Repetición determinada e indeterminada

  • Determinada: sabemos de antemano cuántas veces se repite (p. ej. 100 veces). La resuelve el bucle Para.
  • Indeterminada: no sabemos cuántas veces, depende de una condición. La resuelven Mientras y Repetir.

Diagrama de un bucle

        ┌───────────┐
        │   inicio  │
        └─────┬─────┘
              v
   ┌──────────┴──────────┐
   │  ¿condición cierta? │──No──▶ salir del bucle
   └──────────┬──────────┘
             Sí│
              v
        ┌───────────┐
        │  cuerpo   │  << se repite
        └─────┬─────┘
              │
              └──▶ vuelve a evaluar la condición

La clave es el cuerpo (lo que se repite) y la condición de salida. Cada vuelta debe acercar al programa a terminar el bucle; si no, caemos en un bucle infinito.

Copiar/pegar suele funcionar… hasta que cambia un requisito. Con un bucle, ese cambio se hace en un solo lugar; con copias, en cien. Por eso la regla de oro es: nunca copies código que puedas repetir.

---

El bucle for

El bucle Para (en otros lenguajes for) se usa cuando sabemos exactamente cuántas veces queremos repetir. Tiene un contador que recorre un rango. Su estructura consta de tres partes: inicialización, condición y incremento.

Sintaxis en PSeInt

Para i <- 1 Hasta 10 Hacer
    // cuerpo: se ejecuta con i = 1, 2, ..., 10
FinPara

// Con paso (incremento) de 2 en 2
Para i <- 1 Hasta 10 con paso 2 Hacer
    // i = 1, 3, 5, 7, 9
FinPara

Las tres partes del bucle

ParteEn PSeIntQué hace
Inicializacióni <- 1Define el valor inicial del contador
CondiciónHasta 10Determina el valor límite
Incrementocon paso 2 (o Decremento)Cuánto avanza el contador cada vuelta

Ejemplo: sumar del 1 al 100 (acumulador)

Algoritmo sumar_1_100
    Definir suma, i Como Entero
    suma <- 0

    Para i <- 1 Hasta 100 Hacer
        suma <- suma + i
    FinPara

    Escribir "La suma del 1 al 100 es: ", suma

FinAlgoritmo

Fíjate en la variable suma: se llama acumulador y debe inicializarse a 0 antes del bucle. Dentro, en cada vuelta, le sumamos el valor actual de i. Al final tiene la suma total (5050).

Ejemplo: la tabla del 7

Algoritmo tabla_del_7
    Definir i, resultado Como Entero

    Para i <- 1 Hasta 10 Hacer
        resultado <- 7 * i
        Escribir "7 x ", i, " = ", resultado
    FinPara

FinAlgoritmo

El nombre del contador (i) es convención para "índice", pero puedes usar cualquiera. Lo importante es que no lo modifiques dentro del cuerpo: el bucle ya avanza solo con su incremento.

El bucle while

Cuando no sabemos cuántas veces se repetirá el bloque, usamos el bucle Mientras (en otros lenguajes while). Repite mientras una condición sea verdadera, y deja de hacerlo cuando se vuelve falsa. Es un bucle de tipo pre-test: comprueba la condición antes de entrar, por lo que puede no ejecutarse nunca.

Sintaxis en PSeInt

Mientras condicion Hacer
    // cuerpo: se repite mientras condicion sea verdadera
FinMientras

Ejemplo: leer notas hasta que el usuario meta 0

Algoritmo leer_notas
    Definir nota, total, contador, promedio Como Real
    total <- 0
    contador <- 0

    Escribir "Ingrese una nota (0 para terminar):"
    Leer nota

    Mientras nota <> 0 Hacer
        total <- total + nota
        contador <- contador + 1
        Escribir "Ingrese otra nota (0 para terminar):"
        Leer nota
    FinMientras

    Si contador > 0 Entonces
        promedio <- total / contador
        Escribir "El promedio es: ", promedio
    FinSi

FinAlgoritmo

No sabemos cuántas notas escribirá el usuario; solo termina cuando escriba 0. Por eso Mientras es la elección natural.

Pre-test vs post-test

BucleTipo¿Se ejecuta al menos una vez?
MientrasPre-testNo: si la condición es falsa desde el inicio, no entra nunca
RepetirPost-testSí: garantiza al menos una ejecución

Dentro de un Mientras debe existir algo que pueda cambiar la condición (leer un dato, incrementar una variable). Si la condición nunca cambia, el bucle no termina jamás: es un bucle infinito.

---

El bucle do-while

El bucle Repetir (en muchos lenguajes do-while) es un bucle de tipo post-test: se ejecuta el cuerpo una vez y luego comprueba la condición. Garantiza que el bloque se ejecute al menos una vez, lo cual es perfecto para menús que siempre se muestran al menos una vez.

Sintaxis en PSeInt

Repetir
    // cuerpo: se ejecuta al menos una vez
Hasta Que condicion

Importante: en PSeInt el bucle termina cuando la condición es verdadera (por eso se llama "Hasta Que"). Es lo contrario del Mientras, que repite mientras sea verdadera.

Ejemplo: menú repetido hasta elegir salir

Algoritmo menu_repetido
    Definir opcion Como Entero

    Repetir
        Escribir "1. Ver saldo"
        Escribir "2. Depositar"
        Escribir "3. Retirar"
        Escribir "4. Salir"
        Escribir "Elija:"
        Leer opcion

        Segun opcion Hacer
            1: Escribir "Tu saldo es 500"
            2: Escribir "Depósito realizado"
            3: Escribir "Retiro realizado"
            4: Escribir "Adiós"
            De Otro Modo: Escribir "Opción inválida"
        FinSegun
    Hasta Que opcion = 4

FinAlgoritmo

El menú siempre se muestra al menos una vez (algo que el Mientras no garantizaría si la condición inicial fuera falsa).

¿Cuál usar?

NecesidadBucle recomendado
Sé cuántas veces repetirPara (for)
No sé cuántas veces y quizá no entrarMientras (while)
Debe ejecutarse al menos una vezRepetir (do-while)

La regla para elegir bucle es sencilla: cuenta lo que sabes. Sabes el número → Para. Sabes cuándo parar pero no cuántas veces → Mientras o Repetir según necesites garantizar (o no) la primera ejecución.

break y continue

A veces queremos salir de un bucle antes de que termine su recorrido natural, o saltar una vuelta en concreto. En muchos lenguajes existen las sentencias break (salir del bucle) y continue (saltar a la siguiente vuelta). PSeInt clásico no las tiene como tal, pero podemos conseguir el mismo efecto con condiciones de salida, a menudo con una variable bandera (flag) que controla el fin.

Salir temprano con una bandera

Algoritmo primer_multiplo
    Definir encontrado Como Logico
    Definir i Como Entero
    encontrado <- Falso

    Para i <- 1 Hasta 100 Y NO encontrado Hacer
        Si i MOD 7 = 0 Entonces
            Escribir "Primer múltiplo de 7: ", i
            encontrado <- Verdadero
        FinSi
    FinPara

FinAlgoritmo

La bandera encontrado empieza en falso; en cuanto encontramos el valor buscado la ponemos a verdadero y el bucle (que exige NO encontrado) se detiene. Es el equivalente práctico de un break.

¿Qué hacen break y continue?

ConceptoEfectoEquivalente en PSeInt
breakSalir del bucle por completoBandera + condición de salida
continueSaltar al inicio de la siguiente vueltaUn Si que envuelve lo que queremos omitir

No abuses de break ni de banderas para salir: suelen indicar que la condición del bucle no está bien planteada. Lo legible es plantear una condición que termine de forma natural. Usa la salida temprana solo cuando simplifique mucho el código.

Bucles anidados

Un bucle puede vivir dentro de otro bucle. Se llaman bucles anidados y resultan imprescindibles para trabajar con estructuras de dos dimensiones: tablas, matrices, figuras dibujadas con asteriscos. Por cada vuelta del bucle externo, el bucle interno recorre todas las suyas.

Ejemplo: tabla de multiplicar 10x10

Algoritmo tabla_10x10
    Definir i, j Como Entero

    Para i <- 1 Hasta 10 Hacer
        Para j <- 1 Hasta 10 Hacer
            Escribir i * j, " "
        FinPara
        Escribir ""   // salto de línea al terminar cada fila
    FinPara

FinAlgoritmo

El bucle interno (j) se ejecuta completo por cada valor del externo (i). En total son 10 × 10 = 100 ejecuciones del cuerpo más interno.

Imprimir una figura de asteriscos

Algoritmo triangulo_asteriscos
    Definir i, j, n Como Entero
    n <- 5

    Para i <- 1 Hasta n Hacer
        Para j <- 1 Hasta i Hacer
            Escribir Sin Saltar "*"
        FinPara
        Escribir ""   // salto de línea
    FinPara

FinAlgoritmo

El resultado es un triángulo: en la fila i se imprimen i asteriscos.

Cuidado con el tiempo

El número total de iteraciones es el producto de las de cada bucle. Un bucle de 1000 dentro de otro de 1000 ejecuta un millón de veces el cuerpo interno. Combínalo con un tercero y el tiempo puede dispararse. Antes de anidar demasiado, piensa si realmente es necesario.

En bucles anidados es convención usar índices distintos (normalmente i, luego j, luego k). Usar el mismo índice en ambos niveles es una fuente clásica de errores difíciles de rastrear.

---

Errores comunes

1. Bucle infinito (olvidar el incremento)

// ❌ Contador que nunca cambia: nunca llegará a 5
Mientras i <> 5 Hacer
    Escribir i   // i nunca se modifica → bucle infinito
FinMientras

// ✅ Aumenta el contador dentro del cuerpo
Mientras i <> 5 Hacer
    Escribir i
    i <- i + 1
FinMientras

2. Bucle que no entra (condición falsa desde el inicio)

Si la condición de un Mientras es falsa antes de la primera vuelta, el cuerpo no se ejecuta jamás. Comprueba que inicializaste las variables que intervienen en la condición.

3. Usar el contador mal (i en lugar de i+1)

Confundir el valor actual de i con el siguiente produce resultados desfasados, sobre todo al acceder a posiciones de datos. Revisa si necesitas i o i + 1.

4. Índices intercambiados en bucles anidados

En un doble bucle, usar j donde toca i (por ejemplo al acceder a una matriz) genera errores lógicos difíciles de detectar. Nombra y respeta el rol de cada índice.

5. Acumulador no inicializado

// ❌ suma empieza con valor basura
// suma <- suma + i   → resultado incorrecto

// ✅ inicializar a 0 antes del bucle
suma <- 0
Para i <- 1 Hasta 100 Hacer
    suma <- suma + i
FinPara

Ejercicios

Resuelve estos ejercicios en PSeInt o en tu lenguaje de preferencia. De menor a mayor dificultad:

  1. Sumar pares del 1 al 100: con un Para, recorre los números y suma solo los pares; muestra el total.
  2. Tabla de un número leído: lee un número y muestra su tabla de multiplicar del 1 al 10 con un bucle.
  3. Contar cifras de un número: con un Repetir, divide un número entre 10 hasta que sea 0 y cuenta cuántas cifras tiene.
  4. Triángulo de asteriscos: con bucles anidados, imprime una figura: línea 1 con un asterisco, línea 2 con dos, y así hasta N.
  5. Promedio de N notas: pide cuántas notas leer, luego usa un bucle para leerlas y calcula su promedio con un acumulador.
