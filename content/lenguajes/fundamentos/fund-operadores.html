¿Qué es una expresión?

Una expresión es una combinación de operandos (valores o variables) y operadores que, al evaluarse, produce un único resultado. Por ejemplo, precio * cantidad toma los operandos precio y cantidad, los combina con el operador * y devuelve un número.

Conviene distinguir dos conceptos: una expresión produce un valor; una instrucción (Leer, Escribir, Si…Entonces) produce una acción. La asignación conecta ambos mundos: total <- precio * cantidad evalúa la expresión de la derecha y guarda su valor en la variable de la izquierda.

¿Cómo se evalúa una expresión?

La evaluación sigue unas reglas fijas de precedencia y asociatividad (las verás en la sección de Precedencia). Sustituye mentalmente cada variable por su valor actual y aplica las operaciones en el orden correcto:

Algoritmo evaluacion
    Definir a, b, resultado Como Entero
    a <- 10
    b <- 3
    resultado <- a + b * 2
    // se evalúa primero b * 2 = 6, después a + 6 = 16
    Escribir resultado   // 16
FinAlgoritmo

Operadores aritméticos

Son los que conoces de las matemáticas y se aplican siempre a números. En PSeInt se escriben así:

OperadorNombreEjemploResultado
+Suma7 + 310
-Resta7 - 34
*Multiplicación7 * 321
/División7 / 23.5
%Módulo (resto de la división)7 % 31
^Potencia2 ^ 38

División entera vs. división real

En PSeInt, / con datos Real da división real: 7 / 2 = 3.5. Si los operandos son Enteros, el resultado se ajusta al tipo y se trunca: 7 / 2 entre enteros da 3 (se desprecia el decimal). El módulo (%) devuelve el resto de esa división entera: 7 % 2 = 1. Ambas caminan juntas: "el 7 entre 2 cabe 3 veces y sobran 1".

Usos clásicos del módulo

  • Par o impar: n % 2 devuelve 0 si n es par y 1 si es impar.
  • Comportamiento circular: % 24, % 12 o % 60 mantienen un valor dentro de un rango y "dan la vuelta", como la aguja de un reloj.
  • Repartos: saber cuánto sobra al repartir objetos entre personas.

Ejemplo completo que usa paréntesis bien puestos y la potencia:

Algoritmo operacionesAritmeticas
    Definir nota1, nota2, nota3, promedio Como Real
    Definir radio, pi, area Como Real
    pi <- 3.1416

    Escribir "Ingrese tres notas:"
    Leer nota1, nota2, nota3
    promedio <- (nota1 + nota2 + nota3) / 3   // paréntesis imprescindibles
    Escribir "Promedio: ", promedio

    Escribir "Ingrese el radio:"
    Leer radio
    area <- pi * radio ^ 2                    // radio al cuadrado
    Escribir "Área: ", area
FinAlgoritmo

Operadores de comparación

Sirven para comparar dos valores y responden con un valor lógico: V (verdadero) o F (falso). En PSeInt se escriben así:

OperadorSignificadoEjemploResultado
=Igual a5 = 5V
<>Distinto de5 <> 3V
<Menor que2 < 5V
>Mayor que9 > 5V
<=Menor o igual5 <= 5V
>=Mayor o igual4 >= 5F

Como siempre responden V o F, su lugar natural está dentro de las estructuras de decisión (Si, Mientras…): el programa "pregunta" y, según la respuesta, toma un camino u otro.

Ojo al par más peligroso del curso: <- es asignación ("guarda este valor en la caja") y = es comparación ("¿el contenido de la caja es este?"). Confundirlos es el error número uno de quien empieza.

Operadores lógicos

Los operadores lógicos combinan condiciones y devuelven también V o F. En PSeInt son tres: Y, O y NO.

  • Y (conjunción): verdadero solo si ambas condiciones lo son.
  • O (disyunción): verdadero si al menos una condición lo es.
  • NO (negación): invierte el valor (NO V = F, NO F = V).

Las tablas de verdad resumen su comportamiento completo:

VVV
VFF
FVF
FFF
Condición 1Condición 21 O 2
VVV
VFV
FVV
FFF

Ejemplo con condiciones compuestas: comprobar que una edad está entre 18 y 65, y aceptar una matrícula escrita en mayúscula o minúscula:

Algoritmo condicionesCompuestas
    Definir edad Como Entero
    Definir matricula Como Caracter

    Escribir "Ingrese su edad:"
    Leer edad
    Si edad >= 18 Y edad <= 65 Entonces
        Escribir "Edad dentro del rango laboral"
    SiNo
        Escribir "Edad fuera del rango"
    FinSi

    Escribir "¿Cursó la asignatura? (S/N):"
    Leer matricula
    Si matricula = 'S' O matricula = 's' Entonces
        Escribir "Está matriculado"
    SiNo
        Escribir "No está matriculado"
    FinSi
FinAlgoritmo

La negación es fácil de malinterpretar: NO (edad < 18) equivale a edad >= 18. Cuando tengas dudas, simplifica con una tabla de verdad de dos filas.

Precedencia de operadores

Cuando una expresión mezcla varios operadores, la computadora no los resuelve de izquierda a derecha: aplica un orden de precedencia. En PSeInt, de mayor a menor prioridad:

PrioridadOperadoresCategoría
1 (máxima)^Potencia
2* / %Multiplicación, división, módulo
3+ -Suma y resta
4= <> < > <= >=Comparaciones
5NONegación
6YConjunción
7 (mínima)ODisyunción

Los paréntesis tienen la máxima prioridad y sobreescriben cualquier regla. Por eso son la herramienta para no depender de memorizar la tabla:

// Sin paréntesis: 3 + 4 * 2 = 3 + 8 = 11  (la multiplicación manda)
// Con paréntesis: (3 + 4) * 2 = 7 * 2 = 14

// En las comparaciones, la aritmética se resuelve antes:
// a + b >= c + d   equivale a   (a + b) >= (c + d)

// Orden real de evaluación de esta expresión:
// 2 + 3 * 4 ^ 2 = 2 + 3 * 16 = 2 + 48 = 50

Dos expresiones equivalentes en intención pero distintas en escritura: la diferencia no está en que una tenga paréntesis, sino en que la segunda deja visible para el lector humano qué se agrupa y qué se agrupa sin ambigüedad:

  • (nota1 + nota2 + nota3) / 3 deja claro que primero se suman las tres notas.
  • edad >= 18 Y edad <= 65 evita la duda de dónde acaba la primera comparación.

Cuando un profesor o un colega lea tu código, agradecerá los paréntesis "de más". La regla recomendada: escribe siempre los paréntesis cuando la expresión tenga más de un operador distinto.

Errores comunes

1. Confundir = con <-

Asignar con = o comparar con <- son dos caras del mismo error. La asignación guarda; la comparación pregunta. Revisa cada línea con esta pregunta: "¿quiero guardar o quiero preguntar?"

// ❌ edad = 18 intenta comparar
// ✅ edad <- 18 asigna
// ✅ Si edad = 18 Entonces... compara

2. Usar % con reales sin comprender el resultado

El módulo está pensado para números enteros. Aplicarlo a reales produce resultados confusos (decimales con signo según el lenguaje). Cuando quieras saber si un número es par o impar, trabaja con enteros.

3. Olvidar los paréntesis en (a + b) / 2

// ❌ promedio <- nota1 + nota2 + nota3 / 3
//    divide solo nota3 y luego suma (¡resultado erróneo!)
// ✅ promedio <- (nota1 + nota2 + nota3) / 3

Sin paréntesis, / tiene más prioridad que + y se aplica antes: el cálculo se rompe por completo.

4. Comparar cadenas con = cuando no procede

Comparar texto con = depende del lenguaje y de distinciones mayúscula/minúscula. Si dudas, convierte todo el texto a un mismo formato (PSeInt permite comparar cadenas, pero acostúmbrate a pensar en esos detalles).

5. Negar dos veces

NO (NO x) vale x, pero leerlo cuesta el doble. Prefiere la forma positiva: edad >= 18 en lugar de NO (edad < 18).

6. Asumir asociatividad de izquierda a derecha en todo

La potencia y la negación tienen reglas propias (por ejemplo, -2 ^ 2 puede leerse como -(2 ^ 2) = -4). No lo adivines: usa paréntesis y que el orden sea visible.

La mayoría de los fallos de operadores no se ven a simple vista porque el programa "funciona con algunos valores". Prueba siempre casos límite: ceros, números negativos, igualdad, división entre cero.

Ejercicios

Resuelve estos ejercicios en PSeInt. Recuerda comprobar tus resultados a mano antes de ejecutar:

  1. Evaluar a mano: calcula el valor final de (5 + 3) * 2 - 8 / 4 + 2 ^ 3 siguiendo la tabla de precedencia y compáralo con lo que devuelve PSeInt.
  2. Par o impar: escribe un pseudocódigo que lea un número entero y muestre si es par o impar usando el operador %.
  3. Rango de edad: escribe un pseudocódigo que lea una edad y muestre "adulto" solo si está entre 18 y 65, usando una sola condición con Y.
  4. ¿Es vocal? escribe un pseudocódigo que lea un carácter y diga si es vocal usando O en una sola condición.
  5. Precedencia en la mira: reescribe la expresión a + b * c ^ 2 / d con paréntesis explícitos para que quede claro el orden de evaluación, y luego cambia la agrupación para obtener un resultado distinto (por ejemplo, que se sume antes de multiplicar).
