¿Por qué comunicarse con el usuario?

Hasta ahora los algoritmos funcionaban con datos fijos. Pero un programa real es útil porque es interactivo: recibe datos del usuario (entrada), los procesa y devuelve resultados (salida). Esa conversación constantemente entre programa y persona es lo que hace útil una calculadora, un formulario o una caja registradora.

DirecciónNombreEjemplo
Usuario → ProgramaEntrada (input)Teclear la edad, elegir una opción, escribir el radio
Programa → UsuarioSalida (output)Mostrar el resultado, avisar de un error, imprimir la factura

¿Por qué leemos datos en lugar de hardcodearlos (escribirlos fijos en el programa)? Porque un programa que solo sabe restar 10 menos 3 no sirve para nada; uno que pregunta "¿qué números quieres restar?" sirve para siempre. Los datos variables se deciden en tiempo de ejecución, no al escribir el código.

El ciclo completo de un programa interactivo se puede representar así:

    ENTRADA            PROCESO              SALIDA
+--------------+    +-----------+    +-----------------+
| Leer nombre  | →  | saludo <- | →  | Escribir "Hola, |
| Leer edad    |    | nombre    |    | [nombre]"       |
+--------------+    +-----------+    +-----------------+

La entrada y la salida son el "rostro" del programa. Un programa puede tener una lógica impecable y aun así ser inútil si el usuario no entiende qué se le pide o qué se le muestra.

---

Leer datos de entrada

En PSeInt la entrada se hace con la instrucción Leer. Cuando el programa llega a un Leer, se pausa y espera a que el usuario teclee un valor y pulse Enter; ese valor se guarda en la variable indicada.

Leer edad          // guarda lo tecleado en la variable edad
Leer a, b, c       // lee tres valores seguidos, separados por comas o espacios

Visualmente, la ejecución se detiene justo en la instrucción Leer y no continúa hasta que el usuario responde:

+----------------------------+
|  Escribir "¿Qué edad tienes?"  |
+----------------------------+
              |
              v
+----------------------------+
|  Leer edad                |   <-- aquí se pausa el programa
+----------------------------+
              |
              v
+----------------------------+
|  Escribir "Edad: ", edad  |
+----------------------------+

Regla de oro: antes de cada Leer debe ir un Escribir que diga qué hay que introducir. Si no, el programa se queda esperando y el usuario no sabe qué tiene que escribir.

Algoritmo saludoPersonalizado
    Definir nombre Como Caracter
    Definir edad Como Entero

    Escribir "¿Cómo te llamas?"
    Leer nombre
    Escribir "¿Qué edad tienes?"
    Leer edad

    Escribir "Hola, ", nombre, ". El año que viene tendrás ", edad + 1
FinAlgoritmo

Mensaje claro como "Ingrese su edad:" vale mucho más que un "Dato:" seco. El usuario debe saber qué escribir, en qué formato (¿entero?, ¿real?) y, si aplica, el rango permitido.

---

Mostrar resultados

La salida en PSeInt se hace con Escribir. Puedes imprimir texto, variables o la combinación de ambos separándolos con comas. El programa junta todo en una misma línea de salida:

Escribir "La edad es ", edad          // texto + variable
Escribir "Suma: ", a + b               // texto + expresión calculada en el momento
Escribir "Hola, ", nombre, "!"         // varios trozos pegados en una línea
Tipo de salidaVista al ejecutar
Bien formadaEl promedio de las notas es: 7.5
Mal formada (cruda)7.5

Compara ambas: la primera responde a la pregunta "¿qué me estás mostrando?"; la segunda obliga al usuario a adivinar. Formatea siempre la salida con una frase que le dé contexto al número.

Salida en varias líneas

Cada instrucción Escribir produce una línea de salida independiente. Si quieres dos líneas consecutivas, escribes dos instrucciones:

Escribir "--- Factura ---"
Escribir "Subtotal: ", subtotal
Escribir "Total con IVA: ", total

La salida se muestra siempre con un salto de línea implícito al final. Si las líneas aparecen pegadas o sin orden, revisa que no estés "horneando" varios datos en un único Escribir sin comas ni texto que los separe.

Una calculadora sencilla que lee dos números y muestras sus operaciones básicas:

Algoritmo miniCalculadora
    Definir n1, n2 Como Real

    Escribir "Ingrese el primer número:"
    Leer n1
    Escribir "Ingrese el segundo número:"
    Leer n2

    Escribir n1, " + ", n2, " = ", n1 + n2
    Escribir n1, " - ", n2, " = ", n1 - n2
    Escribir n1, " * ", n2, " = ", n1 * n2
    Escribir n1, " / ", n2, " = ", n1 / n2
FinAlgoritmo

Fíjate en el formato Escribir n1, " + ", n2, " = ", n1 + n2: cada coma añade un trozo a la línea. El texto entre comillas aporta los símbolos y espacios; las expresiones numéricas aportan los valores.

---

Conversión de tipos

Los datos entran y salen del programa como texto: el teclado siempre envía caracteres. El programa debe decidir con qué tipo los interpreta: Leer edad espera un entero, Leer sueldo espera un real. Si el usuario teclea algo incompatible, el programa falla.

En PSeInt el tipo de la variable guía la interpretación del Leer. En muchos lenguajes hay conversiones explícitas (parseInt(), str(), Float()…) que transforman un tipo en otro:

ConversiónEjemploResultadoRiesgo
Real → Entero (truncar)Entero(3.9)3Pierde el decimal (no redondea)
Real → Entero (redondear)Redondear(3.6)4Comportamiento según la función usada
Entero → Real3 como 3.03.0Sin pérdida de precisión
Número → Texto"La nota es 7.5"CadenaYa no se puede operar con él
Texto → Número"10" como entero10Falla si el texto no es numérico

¿Por qué importa?

Porque en algunos lenguajes "10" + "5" no es 15, sino "105": al ser dos textos, el operador + los concatena en vez de sumarlos. La confusión entre "número que se suma" y "texto que se pega" es fuente infinita de errores.

Veamos cómo se comporta la conversión de un real a entero en PSeInt, con sus dos variantes (truncar vs. redondear):

Algoritmo conversionTipos
    Definir precio Como Real
    Definir truncado, redondeado Como Entero

    precio <- 39.75
    truncado <- Truncar(precio)       // 39: elimina los decimales
    redondeado <- Redondear(precio)   // 40: redondea al entero más cercano

    Escribir "Truncado: ", truncado
    Escribir "Redondeado: ", redondeado
FinAlgoritmo

Truncar(2.99) da 2 y Redondear(2.5) da 3: elige la función según la intención real del problema. Truncar pierde información; redondear puede sumar o restar medio punto.

Antes de operar, pregúntate: ¿qué tengo aquí, un número o una cadena que parece número? Convertir primero y operar después evita sorpresas como "105" o divisiones imposibles.

Errores comunes

1. Leer sobre una variable no definida

// ❌ Falta Definir antes del Leer
Leer precio

// ✅ Declarar primero
Definir precio Como Real
Leer precio

2. Escribir sin mensaje previo

Un Leer sin su Escribir deja al programa parado en pantalla con el cursor parpadeando: el usuario no sabe qué se espera. Todo Leer merece su pregunta.

3. No convertir entre tipos

Mezclar un número con una cadena que "parece número" ("10" + 5) produce comportamientos según el lenguaje: concatenación, error o suma inesperada. Convierte de forma explícita y consciente.

4. Asumir que el usuario siempre teclea bien

Un real donde se pedía un entero, una letra donde se pedía un número, un Enter que falta… El usuario comete errores; un programa robusto los anticipa y muestra mensajes de aviso (lo veremos con las estructuras de repetición y de validación).

5. Olvidar el salto de línea en la salida

Salidas que se encadenan sin orden ("Hola.Ana.3" todo pegado) son ilegibles. Organiza los Escribir y los formatos para que cada dato viva en su lugar y haya separación visual entre mensajes.

6. Leer varios datos sin avisar del orden

// ❌ El usuario no sabe cuántos ni en qué orden teclear
Leer a, b, c

// ✅ Se indica qué se espera
Escribir "Ingrese base, altura y número de lados:"
Leer base, altura, lados

Cuando leas varios valores a la vez, el mensaje previo debe describir todos, en el mismo orden en que serán leídos.

Prueba siempre tu programa con una entrada anómala además de la correcta: tecleará letras, un número negativo o un espacio de más. Ahí es donde se descubre si tu entrada/salida es robusta o frágil.

Ejercicios

Resuelve estos ejercicios en PSeInt. Cuida siempre la forma de los mensajes de entrada y salida:

  1. Saludo con nombre: lee el nombre del usuario y muestra Hola, [nombre], bienvenido a GuiaDev.
  2. Suma por teclado: lee dos números, los suma y muestra el resultado con el formato [a] + [b] = [suma].
  3. Área de un rectángulo: lee base y altura (Reales), calcula el área y muéstrala con un mensaje claro: El área del rectángulo es 24 unidades cuadradas.
  4. Convertidor Celsius → Fahrenheit: lee una temperatura en grados Celsius y muestra su equivalente en Fahrenheit usando la fórmula F = C * 9 / 5 + 32.
  5. Formato de mensajes: escribe un pseudocódigo que pregunte "Ingrese su edad:" y luego muestre exactamente dos líneas: Tu edad es [edad] años y Dentro de 10 años tendrás [edad+10]. Comprueba el salto de línea entre ambas salidas.
