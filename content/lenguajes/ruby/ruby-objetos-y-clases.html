Definir clases e instanciarlas

Ruby es un lenguaje orientado a objetos puro: todo valor es un objeto y los objetos pertenecen a una clase. Una clase define los atributos (datos) y los métodos (comportamiento) que tendrán sus instancias.

Se define una clase con class + nombre en mayúscula, y se crean instancias con new. El método initialize es el constructor, que se ejecuta al instanciar.

class Perro
  def initialize(nombre, raza = "mestiza")
    @nombre = nombre
    @raza = raza
  end

  def ladrar
    "#{@nombre} dice ¡Guau!"
  end

  def presentarse
    "Soy #{@nombre}, un #{@raza}"
  end
end

perro = Perro.new("Toby", "Labrador")
puts perro.ladrar       # => Toby dice ¡Guau!
puts perro.presentarse  # => Soy Toby, un Labrador

Las variables de instancia llevan @ al inicio (@nombre) y son privadas por defecto. Solo se acceden mediante métodos de la propia instancia.

---

attr_accessor, attr_reader y attr_writer

Acceder a las variables de instancia desde afuera requiere definir métodos getter (leer) y setter (escribir). Como eso es muy común, Ruby ofrece macros que los generan automáticamente.

attr_reader crea solo getters (solo lectura), attr_writer solo setters (solo escritura) y attr_accessor ambos.

class Producto
  attr_accessor :nombre, :precio
  attr_reader :codigo
  attr_writer :stock

  def initialize(nombre, precio, codigo)
    @nombre = nombre
    @precio = precio
    @codigo = codigo
    @stock = 0
  end
end

p = Producto.new("Teclado", 1500, "TCK-101")
p.nombre = "Teclado RGB"     # setter (escritura)
puts p.nombre                # getter => Teclado RGB
puts p.precio                # => 1500
puts p.codigo                # => TCK-101 (solo lectura)
p.stock = 25                 # attr_writer permite escribir

Elegí attr_reader (no attr_accessor) para datos que no deben modificarse tras la creación, como códigos o ids. Menos escritura pública significa menos bugs.

---

Métodos de instancia y de clase

Los métodos de instancia se llaman sobre una instancia concreta y tienen acceso a sus atributos. Los métodos de clase se llaman sobre la clase misma (con NombreClase.metodo) y no dependen de ninguna instancia en particular.

Los métodos de clase son útiles para operaciones globales o constructores alternativos. Se definen con self.metodo dentro de la clase.

class Circulo
  attr_accessor :radio

  def initialize(radio)
    @radio = radio
  end

  def area
    Math::PI * @radio ** 2
  end

  def self.desde_diametro(diametro)
    new(diametro / 2.0)
  end

  def self.descripcion
    "Clase para representar círculos"
  end
end

c = Circulo.new(5)
puts c.area.round(2)              # => 78.54

c2 = Circulo.desde_diametro(10)
puts c2.radio                     # => 5.0
puts Circulo.descripcion          # => Clase para representar círculos

El self dentro de la clase (pero fuera de un método) se refiere a la clase misma. Así, def self.metodo define un método de clase y new llama al constructor.

Herencia

La herencia permite que una clase herede atributos y métodos de otra con el operador <. La clase hija puede reutilizar el comportamiento del padre, agregar nuevos métodos y sobrescribir los existentes.

En Ruby cada clase hereda de a lo sumo una clase padre (herencia simple), y todas heredan en última instancia de Object.

class Animal
  def initialize(nombre)
    @nombre = nombre
  end

  def hablar
    "hace un sonido"
  end

  def presentarse
    "#{@nombre} #{hablar}"
  end
end

class Gato < Animal
  def hablar
    "dice ¡Miau!"
  end
end

class Perro < Animal
  def hablar
    "dice ¡Guau!"
  end
end

g = Gato.new("Milo")
p = Perro.new("Toby")
puts g.presentarse   # => Milo dice ¡Miau!
puts p.presentarse   # => Toby dice ¡Guau!
ConceptoDetalle
superLlama al método del padre con el mismo nombre
overrideReescribir un método heredado en la clase hija
ObjectClase raíz de todo objeto en Ruby

Priorizá la composición (incluir módulos) sobre la herencia profunda. Cadenas largas de herencia hacen el código difícil de entender; en Ruby los módulos te dan flexibilidad sin acoplar clases.

---

Módulos y mixins (include, extend)

Un módulo es un contenedor de métodos y constantes que no puede instanciarse. Sirve para dos propósitos: agrupar métodos relacionados (como un namespace) y mezclar comportamiento en clases mediante include o extend.

include agrega los métodos del módulo como métodos de instancia, mientras que extend los agrega como métodos de clase. A esta técnica de mezcla se la conoce como mixin.

module Volador
  def volar
    "#{@nombre} vuela alto"
  end
end

module Nadador
  def nadar
    "#{@nombre} nada en el agua"
  end
end

class Pajaro
  include Volador
  def initialize(nombre)
    @nombre = nombre
  end
end

pajaro = Pajaro.new("Piolín")
puts pajaro.volar   # => Piolín vuela alto

module Utilidades
  def formatear(num)
    "$%.2f" % num
  end
end

class Cuenta
  extend Utilidades
end

puts Cuenta.formatear(25.5)   # => $25.50

Con include el módulo agrega métodos que las instancias pueden usar; con extend los agrega a la clase. Recordá: include → instancias, extend → clase.

Ejercicios prácticos

Poné a prueba la programación orientada a objetos en Ruby con estos ejercicios.

  1. Creá una clase CuentaBancaria con attr_accessor para saldo y métodos depositar y retirar.
  2. Añadí a la clase anterior un attr_reader para el número de cuenta y comprobá que no se pueda modificar desde fuera.
  3. Definí un método de clase que cuente cuántas cuentas se han creado (usando una variable de clase @@total).
  4. Creá las clases Vehiculo (padre) y Auto/Moto (hijas) sobrescribiendo un método descripcion.
  5. Creá un módulo Conducible con include y otro de utilidades con extend para comprobar la diferencia.
