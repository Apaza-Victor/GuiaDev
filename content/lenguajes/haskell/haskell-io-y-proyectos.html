IO: acciones puras para efectos

Haskell separa el mundo puro del mundo IO: las funciones son puras y el efecto vive en el tipo IO a. Una "acción IO" es un valor que, al ejecutarse, produce efectos y devuelve un a.

-- Firmas IO
getLine :: IO String
putStrLn :: String -> IO ()
readFile :: FilePath -> IO String

-- main es una acción IO
main :: IO ()
main = do
  putStrLn "¿Cómo te llamas?"
  nombre <- getLine              -- <- extrae el valor del contexto IO
  putStrLn ("Hola, " ++ nombre)

-- Comparación:
valorPuro   :: Int
valorPuro   = 42

-- una acción que devuelve Int:
dameCinco   :: IO Int
dameCinco   = return 5    -- "return" mete valor en IO (no "return" de funciones)

-- En GHCi:
ghci> valorPuro
42
ghci> dameCinco
5   (- aunque el tipo es IO Int)

return solo "mete" un valor dentro de IO: no termina la función. Las funciones puras NO pueden leerse/escribirse: esa separación es lo que hace a Haskell tan fiable.

Notación do

do es azúcar sintáctico para encadenar acciones IO con >>= (bind). Dentro, cada expresión ejecuta una acción y cada x <- acción extrae su valor.

main :: IO ()
main = do
  putStrLn "Dame un número:"
  linea <- getLine
  let n = read linea :: Int
  putStrLn $ "El doble es: " ++ show (n * 2)

-- Lo mismo con bind (>>=) explícito:
-- main = getLine >>= \l -> putStrLn ("Hola " ++ l)

-- En un do:
-- líneas sin <- son acciones ignoradas:
main2 :: IO ()
main2 = do
  putStrLn "acción 1"
  putStrLn "acción 2"

-- <- con pares y let combinados
main3 :: IO ()
main3 = do
  let (a, b) = (3, 4)
  print (a + b)

-- Sharing: valores puros dentro de do (let)
  let cuadrado x = x * x
  print (cuadrado 9)

lnea <- getLine es la línea que más verás en tutoriales. Cuando domines el do, entenderás que las mónadas "devuelven" efecto; casi todo I/O del mundo real (archivos, red, parseos) se escribe así.

cabal: paquetes y proyectos

cabal es el gestor de paquetes (Hackage) y entornos de Haskell: crea proyectos, resuelve dependencias y aísla versiones. Su forma moderna usa "cabal.project" con un paquete por directorio.

# Actualizar índice
cabal update

# Instalar paquetes globalmente NO es lo normal
# Preferimos declarar en el proyecto:

# 1. Usar cabal init
mkdir mi_app && cd mi_app
cabal init --interactive --non-interactive     # genera .cabal

# 2. Estructura clásica
# mi_app/
#   mi_app.cabal      # metadata, deps, libraries
#   cabal.project     # configuración del build (opcional)
#   app/Main.hs        # o src/Main.hs, test/...
#   src/lib.hs

# 3. Añadir dependencia (edita el .cabal: build-depends)
#   build-depends: base ^>=4.14, text, containers, bytestring

# 4. Compilar y ejecutar
cabal build
cabal run
cabal repl     # GHCi con las deps del proyecto
-- mi_app.cabal (extracto)
cabal-version:      3.0
name:               mi_app
version:            0.1.0.0
library
  exposed-modules:     MiLib
  build-depends:       base, text
executable mi-app
  main-is:            Main.hs
  build-depends:      base, mi_app
  hs-source-dirs:     app, src

Puedes crear Main.hs en app/ y bibliotecas en src/. Con stack (alternativa popular) el flujo es similar: tutorial de stack new. Elige el que tu equipo use.

Pruebas con QuickCheck y HUnit

Dos frameworks clásicos: HUnit (asserts) y QuickCheck (property-based: genera datos aleatorios y verifica propiedades). La pureza de Haskell hace el testing realmente robusto.

-- Cabal: test-suite tests
--   type: exitcode-stdio-1.0
--   main-is: Spec.hs
--   build-depends: base, QuickCheck, HUnit, mi_app

import Test.QuickCheck
import Test.HUnit

-- Propiedades
prop_identidad :: [Int] -> Bool
prop_identidad xs = reverse (reverse xs) == xs

prop_suma :: Int -> Int -> Bool
prop_suma a b = a + b == b + a

prop_dobles :: [Int] -> Bool
prop_dobles xs = map (*2) xs == [2*x | x <- xs]

-- HUnit assears
test_suma :: Test
test_suma = TestCase (assertEqual "2+3" 5 (2 + 3))

-- main: correr el suite
main :: IO ()
main = do
  quickCheck prop_identidad
  quickCheck prop_suma
  countTests runTestTT test_suma
  putStrLn "Hecho"

QuickCheck prueba con MILES de entradas generadas aleatoriamente. Ese nivel de "proof via sampling" es más potente que 5 asserts. Es de los mayores beneficios de la pureza.

Mini-proyecto práctico

Juntemos todo: un programa pequeño que lee una lista de la terminal, la procesa con funciones puras y muestra resultados.

module Main where

-- Biblioteca pura (sin IO): estadísticos
promedio :: [Double] -> Maybe Double
promedio [] = Nothing
promedio xs = Just (sum xs / fromIntegral (length xs))

mayoresQue :: Double -> [Double] -> [Double]
mayoresQue umbral = filter (> umbral)

-- IO: pedir números, procesar, mostrar
main :: IO ()
main = do
  putStrLn "Escribe números separados por espacio:"
  linea <- getLine
  let nums = map read (words linea) :: [Double]
  putStrLn $ "Números: " ++ show nums
  case promedio nums of
    Nothing -> putStrLn "Lista vacía"
    Just p  -> do
      putStrLn $ "Promedio: " ++ show p
      putStrLn $ "Mayores que el promedio: "
                  ++ show (mayoresQue p nums)

-- Ejecución:
-- cabal run
--   > Escribe números separados por espacio:
--   > 4 8 15 16 23 42
--   > Números: [4.0,8.0,15.0,16.0,23.0,42.0]
--   > Promedio: 18.0
--   > Mayores que el promedio: [23.0,42.0]

Observa la separación: las funciones puras están "abajo" y el IO solo "arriba". Ese es el modelo: sistema puro con una cáscara IO. Te queda un módulo de lógica 100% testeable con QuickCheck.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. IO básico: escribe main que pida tu nombre con getLine y lo imprima con putStrLn.
  2. do: lee dos números, súmalos (función pura) y muestra el doble con un do.
  3. cabal: crea un proyecto cabal, añade text como dep y ejecuta cabal repl.
  4. QuickCheck: escribe una propiedad prop_intercambio (a+b == b+a) y hazla pasar.
  5. Mini-app: termina el proyecto del promedio añadiendo la desviación estándar, y genera un test que verifique maxima >= minima.

Felicidades: has completado Haskell en GuiaDev. La comunidad recomienda seguir con el libro "Learn You a Haskell" y con QuickCheck para afianzar.
