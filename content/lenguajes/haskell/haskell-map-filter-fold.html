map y filter

Las dos funciones de orden superior más usadas: map aplica una función a cada elemento; filter conserva los que cumplen un predicado. Se definen recursivamente en el Prelude.

-- map: aplicar una función a cada elemento
ghci> map (+1) [1..5]
[2,3,4,5,6]
ghci> map (*2) [1..5]
[2,4,6,8,10]
ghci> map toUpper "hola"    -- "HOLA"

-- filter: conservar los que cumplen
ghci> filter even [1..10]
[2,4,6,8,10]
ghci> filter (> 5) [1..10]
[6,7,8,9,10]

-- Combinarlas
ghci> map (^2) (filter odd [1..10])
[1,9,25,49,81]

-- Sus definiciones (así trabajan)
miMap :: (a -> b) -> [a] -> [b]
miMap _ []     = []
miMap f (x:xs) = f x : miMap f xs

miFilter :: (a -> Bool) -> [a] -> [a]
miFilter _ []     = []
miFilter p (x:xs)
  | p x       = x : miFilter p xs
  | otherwise = miFilter p xs

Las firmas lo dicen todo:
map :: (a -> b) -> [a] -> [b]
filter :: (a -> Bool) -> [a] -> [a]
Suele ser más eficiente y legible que un bucle manual.

Funciones anónimas (lambda)

Con \x -> ... defines funciones sin nombre (ϵ-cálculo). Se usan "inline" donde necesitas una función corta que no merece definición propia.

-- Lambda básica
ghci> (\x -> x * x) 5
25

-- Usadas con map/filter
ghci> map (\x -> x * x) [1..4]
[1,4,9,16]
ghci> filter (\x -> x `mod` 3 == 0) [1..20]
[3,6,9,12,15,18]

-- Dos argumentos
ghci> (\a b -> a + b) 2 3
5

-- Son la forma de "expr" de construir funciones al vuelo
mayores10 = map (\x -> if x > 10 then x else 0) [5, 15, 3]

Si una lambda crece más de una línea, mejor definirla en un where. Pero para casos cortos, son perfectas: no gastan un nombre y despliegan la firma en uso.

fold: términos de reducción

foldr y foldl reducen una lista a un valor con un acumulador. foldr procesa de derecha a izquierda (perezoso, ideal para listas infinitas); foldl' (estricto) para sumas de muchos datos.

-- foldr f z [a,b,c] = f a (f b (f c z))
ghci> foldr (+) 0 [1,2,3,4]
10

ghci> foldr (*) 1 [1,2,3,4]
24

-- Los dos argumentos de f: elemento y acumulador
sumaUsandoFold' = foldr (+)
ghci> sumaUsandoFold' 0 [1..100]
5050

-- foldl': variante estricta para acumular números
import Data.List (foldl')
ghci> foldl' (+) 0 [1..1000]
500500

-- ¡construir!! Cons dor fold entregan reverse con foldl
ghci> foldl' (flip (:)) [] [1,2,3]
[3,2,1]

-- Reduce (sin valor inicial; errores en lista vacía)
ghci> foldr1 max [3,1,4,1,5]
5

En GHC moderno, foldr es "composable" y funde con map/filter gracias a las reglas de fusión (map f . map g == map (f . g)). No te preocupes por el rendimiento en la mayoría de casos: el compilador optimiza.

zip y combinaciones

zip agrupa dos listas en pares (trunca a la menor), y se combina con map/comprensiones para operaciones pareadas.

ghci> zip [1,2,3] ['a','b','c']
[(1,'a'),(2,'b'),(3,'c')]

ghci> zip [1,2,3] [10,20]
[(1,10),(2,20)]     -- 3 excedente: se trunca

-- zipWith aplica la función a cada par
ghci> zipWith (+) [1,2,3] [10,20,30]
[11,22,33]

-- Suma de vectores
sumaVectores v w = zipWith (+) v w

-- Índices
ghci> zip [0..] "abc"
[(0,'a'),(1,'b'),(2,'c')]

-- Pdto punto (azúcar con zipWith)
punto a b = sum (zipWith (*) a b)
ghci> punto [1,2,3] [4,5,6]
32

zipWith es zip + map desempacar: en la práctica prefieres zipWith directo. Para "enumerar" listas usa zip [0..], un truco clásico.

Aplicativos en listas

La lista es un Applicative (pure x = [x], <*> = producto de funciones). Esto generaliza map: aplicar funciones a múltiples listas a la vez.

-- <$> es fmap de aplicativos: f <$> xs  ==  map f xs
ghci> (*2) <$> [1,2,3]
[2,4,6]

-- <*>: combinar lista de funciones y de valores
ghci> [(+1), (*2)] <*> [1,2,3]
[2,3,4, 2,4,6]

-- En la práctica: todas las combinaciones
ghci> (\x y -> x + y) <$> [1,2] <*> [10,20]
[11,21, 12,22]

-- Comprensiones vs aplicativos
-- [x + y | x <- [1,2], y <- [10,20]]  el mismo resultado

-- Aplicativos sobre Maybe: propagan Nothing
ghci> (+) <$> Just 2 <*> Just 3
Just 5
ghci> (+) <$> Nothing <*> Just 3
Nothing

-- Y sobre funciones (Reader): toda función es aplicativa
-- (e -> a) es aplicativo; <*> compone por argumento común

Los Aplicativos son la generalización de "aplicar una función a un valor dentro de un contexto". Listas (no determinismo), Maybe (posible ausencia) y IO los usan. Es el escalón previo a las mónadas.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. map/filter: con una lista de edades, conserva mayores de 18 y muéstralos duplicados.
  2. Lambda: pasa a mayúsculas las vocales de un string usando map (\c -> ...).
  3. foldr: implementa sumaCuadrados = foldr que sume los cuadrados; verifies con una lista.
  4. zipWith: calcula el promedio de cada par (a,b) con zipWith.
  5. Aplicativos: genera todas las sumas de [1,2] y [10,20] usando (+) <$> ... <*> ....
