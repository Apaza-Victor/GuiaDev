Records

Un Record es un tipo de dato con nombre para sus campos, creado con type Nombre = { ... }. Viene con igualdad estructural, representación %A, y copy-and-update (una forma de "modificar" preservando la inmutabilidad).

type Persona = {
    Nombre : string
    Edad   : int
    Ciudad : string
}

let ana = { Nombre = "Ana"; Edad = 30; Ciudad = "Lima" }
printfn "%A" ana                         // { Nombre = "Ana"; ... }

// Acceso por punto
printfn "%s (%d) - %s" ana.Nombre ana.Edad ana.Ciudad

// Igualdad estructural (dos records con mismos valores = iguales)
let otra = { Nombre = "Ana"; Edad = 30; Ciudad = "Lima" }
printfn "%b" (ana = otra)                // true

// Copy-and-update: nuevo record modificando campos
let ana_31 = { ana with Edad = 31 }
printfn "%d" ana.Edad                    // 30 (inmutable, no cambió)
printfn "%d" ana_31.Edad                 // 31

// Patrón de campos en match
let describir (p: Persona) =
    match p with
    | { Nombre = n; Edad = e } -> $"{n} tiene {e} años"
printfn "%s" (describir ana)

Los Records no necesitan funciones constructoras ni setters: sobre todo with es la forma "inmutable" de actualizar un dato persistente. Los Records son ideales para datos de dominio (entidades, VMs).

Uniones Discriminadas

Una unión discriminada define un conjunto cerrado de casos. El compilador obliga a tratarlos todos, lo que elimina estados inválidos (el famoso "make illegal states unrepresentable").

type Estado =
    | Activo
    | Inactivo
    | Suspendido

let estado = Activo

let texto =
    match estado with
    | Activo -> "funcionando"
    | Inactivo -> "detenido"
    | Suspendido -> "en pausa"
printfn "%s" texto

// Con datos
type Figura =
    | Rectangulo of float * float
    | Circulo    of float

let area (fig: Figura) =
    match fig with
    | Rectangulo (a, b) -> a * b
    | Circulo r -> System.Math.PI * r * r

let f1 = Rectangulo (3.0, 4.0)
let f2 = Circulo 2.0
printfn "Áreas: %f, %f" (area f1) (area f2)

Las uniones discriminadas + match te dan "enum con datos" y modelado de estados de forma total. Es la herramienta con la que F# construye software a prueba de balas.

Option: ausencia segura

Option<'T> es la "nullable" segura: Some valor o None. Obliga a manejar la ausencia; no hay null silencioso ni NullReferenceException.

let buscarEn (pares: (string * int) list) clave =
    List.tryFind (fun (k, _) -> k = clave) pares

// List.tryFind devuelve option
let baseDatos = [ ("ana", 30); ("pedro", 25) ]
let r = buscarEn baseDatos "ana"      // Some ("ana", 30)
let r2 = buscarEn baseDatos "maria"   // None

match r with
| Some (nombre, edad) -> printfn "%s: %d" nombre edad
| None -> printfn "No encontrado"

// Comodines útiles
printfn "%A" (Option.defaultValue (-1) (buscarEn baseDatos "ana"   |> Option.map snd))
printfn "%A" (Option.defaultValue (-1) (buscarEn baseDatos "maria" |> Option.map snd))

// Encadenar with Option.map / Option.bind
let doble = Option.map (fun (_, e) -> e * 2)
printfn "%A" (doble (buscarEn baseDatos "ana"))    // Some 60

Reglas de oro: nunca uses null, nunca fundas Option.get sin chequear, y encadena con Option.map/Option.bind. El alias Option en F# corresponde a la maybe monada de Haskell.

Result: errores como datos

Result<'Ok, 'Error> es Ok valor o Error err: representas fallos como datos, sin excepciones. Ideal para validación donde quieres errores acumulables y control total.

type ErrorValidacion = string

let validarEdad (n: int) : Result<int, ErrorValidacion> =
    if n < 0 then Error "Edad negativa"
    elif n > 120 then Error "Edad imposible"
    else Ok n

let resultado = validarEdad 25

let mensaje =
    match resultado with
    | Ok n -> $"edad válida: {n}"
    | Error e -> $"inválido: {e}"
printfn "%s" mensaje

// Combinar Result con Result.bind (encadenar)
let validarNombre (s: string) : Result<string, ErrorValidacion> =
    if s.Length > 3 then Ok s else Error "nombre corto"

let completa =
    validarNombre "Ana"
    |> Result.bind (fun _ -> validarEdad 121)

match completa with
| Ok (nom) -> printfn "Todo OK: %s" nom
| Error e -> printfn "Fallo: %s" e

Result inspirado en TypeScript/Either. Lo usas cuando quieres propagar errores esperados (validación, IO) como datos; las excepciones quedan para bugs imprevistos.

Parsing y la regla "parse, don't validate"

Un patrón F# favorito: parsear los datos brutos a tipos fuertes (con Option/Result) y nunca más validar después. Los tipos garantizan que el dato ya es válido.

type Email = Email of string
type Usuario = {
    Nombre : string
    Email  : Email
}

let crearEmail (s: string) : Result<Email, string> =
    if s.Contains("@") && s.Contains(".") then Ok (Email s)
    else Error $"Email inválido: {s}"

let crearUsuario nombre email =
    match crearEmail email with
    | Ok em -> Ok { Nombre = nombre; Email = em }
    | Error e -> Error e

let resultado = crearUsuario "Ana" "ana@guia.dev"
match resultado with
| Ok u -> printfn "Usuario: %s (%A)" u.Nombre u.Email
| Error e -> printfn "No: %s" e

// Ahora "Email" conlleva la garantía de validez: nadie puede crear un
// Email inválido sin pasar por crearEmail

Evita los "stringly typed" (modelar todo como string). Crea tipos para Email, ID, Código... y benefíciate de la comprobación del compilador y de la documentación implícita.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Record Producto: define Producto = { Nombre; Precio }, crea dos y usa with para subir precio un 10%.
  2. Máquina de estados: modela Vehiculo = Parado | Andando of float | Averiado y una función que match y describa cada estado.
  3. Busqueda con Option: sobre una lista de pares, implementa buscar con List.tryFind y maneja None.
  4. Validación con Result: crea validarEdad y validarNombre, compónlas con Result.bind.
  5. Email tipado: implementa crearEmail y un Usuario cuyo Email sea infaliblemente válido.

En la próxima lección dominaremos colecciones: listas, secuencias, y las funciones de orden superior de F#.
