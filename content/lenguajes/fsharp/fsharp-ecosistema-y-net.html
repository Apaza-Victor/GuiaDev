Interoperabilidad con .NET

F# se ejecuta en .NET y puede usar toda la plataforma: librerías de C#, NuGet, `System.*`, entity framework, y al revés, C# puede consumir F# sin problemas. Los tipos F# se convierten a tipos CLR estándar.

open System
open System.Text

// Clases y métodos del BCL
let fecha = DateTime.Now
printfn "Hoy: %s" (fecha.ToString("yyyy-MM-dd"))

let enorme = StringBuilder()
[ "Hola"; " "; "F#" ] |> List.iter (fun s -> enorme.Append(s) |> ignore)
printfn "%s" (enorme.ToString())

// Colecciones .NET desde F#
let col = System.Collections.Generic.List<int>()
col.Add(1); col.Add(2)
for x in col do printfn "%d" x

// Consumir una clase C# (ejemplo estilizado)
// let app = new MiClaseCSharp()
// app.HacerAlgo()

// F# dentro de C#: los modules se exponen como funciones estáticas

Compartes el runtime y las librerías: si existe en NuGet, F# lo usa (aunque los lea en su estilo idiomático).

F# se usa dentro de empresas donde C# es el lenguaje principal: proyectos F# ocultos o módulos de dominio F# funcionando junto a C#, entre ellos Giraffe/Saturn para web.

Async y computación

F# ofrece flujos de computación asíncrona con async-expressions. El operador let! y do! hacen que el código se lea como secuencial pese a ser asíncrono; Async.RunSynchronously ejecuta.

open System.Net.Http

let fetchLongitud (url: string) = async {
    use cliente = new HttpClient()
    let! contenido = cliente.GetStringAsync(url) |> Async.AwaitTask
    return contenido.Length
}

let urls = [ "https://example.com"; "https://dotnet.microsoft.com" ]

// Ejecutar en paralelo
let totales =
    urls
    |> List.map fetchLongitud
    |> Async.Parallel
    |> Async.RunSynchronously

printfn "Longitudes: %A" totales

// Pipeline asíncrono con let!
let proceso = async {
    let! a = fetchLongitud "https://example.com"
    let! b = fetchLongitud "https://dotnet.microsoft.com"
    return a + b
}
printfn "Suma: %d" (Async.RunSynchronously proceso)

// 3 líneas o menos para lanzar un async sencillo
# of
let micro = async { return 41 + 1 }
printfn "%d" (Async.RunSynchronously micro)

let! (y do!, return!) "extrae el valor" dentro del contexto async. No abuses tareas no await: gestiona cancelaciones con Async.Catch si la tarea puede fallar.

Testing con Expecto / xUnit

La gran ventaja: funciones puras, verificables por tipos; testear se simplifica. Los frameworks clásicos son xUnit (estándar .NET) y Expecto (100% F#, funciones como casos de prueba).

// Ejemplo con Expecto (NuGet: Expecto)
open Expecto

let agregar a b = a + b
let divide a b = if b = 0 then failwith "división por cero" else a / b

let tests =
    testList "aritmética" [
        testCase "suma básica" (fun () ->
            Expect.equal (agregar 2 3) 5 "2+3 debe ser 5")
        testCase "suma negativos" (fun () ->
            Expect.equal (agregar -1 1) 0 "-1+1 = 0")
        testCase "división por cero lanza" (fun () ->
            Expect.throws (fun () -> divide 1 0 |> ignore) "must throw")
    ]

// Ejecutar: dotnet run (en el proyecto de tests)
// [<EntryPoint>]
// let main argv = runTestsWithCLIArgs [] argv tests
# Con xUnit en un proyecto F#
dotnet new xunit -lang F# -o Tests
dotnet add Tests reference ../MiAula/MiAula.fsproj
cd Tests
dotnet test

Expecto permite escribir tests como funciones y ejecutarlos en paralelo con la opción --parallel (pruebas en F# son cheap). xUnit queda para equipos que ya trabajan con C#.

Aplicaciones web

F# puede servir APIs y front con ASP.NET Core, y tiene librerías propias: Giraffe (HTTP funcional) y Saturn/Fable (frontend JS/FS). Ejemplo con Giraffe en unas líneas:

open Giraffe
open Microsoft.AspNetCore.Builder
open Microsoft.Extensions.Hosting

// Handler: una función que devuelve HTTP
let holaHandler : HttpHandler =
    fun next ctx ->
        ctx.WriteJsonAsync({| saludo = "Hola F#"; estado = "ok" |})

let webApp : HttpHandler =
    choose [
        GET >>= route "/" >>= holaHandler
        GET >>= routef "/hola/%s" (fun nombre ->
            text $"Hola, {nombre}")
        setStatusCode 404 >>= text "No existe"
    ]

// Host de ASP.NET
[<EntryPoint>]
let main _ =
    let builder = Host.CreateDefaultBuilder()
    builder.ConfigureWebHostDefaults(fun w ->
        w.Configure(fun app -> app.UseGiraffe webApp) |> ignore)
    builder.Build().Run()
    0
# Plantillas de Saturn / Farmer para backends
dotnet new saturn -o MiApi
cd MiApi
dotnet run

Giraffe/Saturn exponen el patrón "web como función de request a response". Para frontend, Fable compila F# a JavaScript y te permite un stack 100% F#.

Buenas prácticas en proyectos F#

Lo que los profesionales y el libro "Domain Modeling Made Functional" (Scott Wlaschin) recomiendan en 2026:

// 1. "Primitive obsession": nada de string sobre string
type ProductoId = ProductoId of System.Guid

// 2. Domino con Records + Uniones Discriminadas; valides con tipos
type EstadoOrden =
    | Nueva
    | Pagada
    | Cancelada

// 3. Totalidad: match siempre con todas las ramas (sin comodines fáciles)
let procesar (e: EstadoOrden) =
    match e with
    | Nueva -> "crear"
    | Pagada -> "enviar"
    | Cancelada -> "reembolsar"

// 4. Inmutabilidad: funciones puras, data-in//data-out
// 5. Módulos por feature, no por tipo:
//    Archivo "Orden.fs": type Orden + module Orden (crear, pagar, cancelar)
// 6. IoT de Función = la vista; el dominio en el centro, sin IO
PrácticaPor qué importa
Compilador totalErrores tempranos, refactor seguro
Uniones discriminadasEstados válidos modelados, no "strings"
Funciones purasTesteables y paralelizables
Pipelines > buclesCódigo declarativo, corto
Option/ResultNada de null ni excepciones por flujo normal

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Interop: usa System.Net.Http para traer el contenido de una URL y mostrar su longitud.
  2. Async paralelo: lanza 3 peticiones HTTP con Async.Parallel y muestra la suma de longitudes.
  3. Tests: crea un proyecto xunit F# que pruebe agregar y divide; ejecuta dotnet test.
  4. API Giraffe: monta un endpoint /hola/%s y pruebalo con curl en localhost.
  5. Domain modeling: modela un pedido con ProductoId, EstadoOrden y una función procesar total.
