Gradle: scripts de build con Groovy

Gradle es el sistema de build más usado en la JVM, y sus scripts tradicionales están escritos en Groovy (aunque soporta Kotlin DSL). Entender Gradle es entender Groovy DSL en acción: bloques, closures, delegate.

// build.gradle (DSL Groovy)
plugins {
    id 'groovy'
    id 'application'
}

group = 'com.guiadev'
version = '1.0.0'

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.codehaus.groovy:groovy:4.0.26'
    testImplementation platform('org.spockframework:spock-bom:2.4-M3-groovy-4.0')
    testImplementation 'org.spockframework:spock-core'
}

application {
    mainClass = 'com.guiadev.Main'
}

// Tu propia tarea con closures
tasks.register('hola') {
    doLast {
        println 'Tarea hola desde Groovy DSL'
    }
}
# Comandos típicos
gradle build          # compilar + test
gradle run            # ejecutar la app (plugin application)
gradle test           # solo tests
gradle hola           # tu tarea
gradle dependencies   # árbol de dependencias
gradle wrapper        # genera gradlew (recomendado)

# Lanzar sin gradle instalado globalmente
./gradlew run

Todo en build.gradle es Groovy: dependencies { ... } es una closure evaluada sobre el proyecto. Aprender Groovy te da el control total de tu build (y leyendo builds Kotlin entenderás el diseño).

Testing con Spock

Spock es el framework de testing BDD de la JVM escrito en Groovy: testes legibles con bloques given/when/then y where para datos.

// src/test/groovy/com/guiadev/CalculadoraSpec.groovy
import spock.lang.Specification

class CalculadoraSpec extends Specification {
    def "suma básica"() {
        given: "una calculadora"
        def calc = new Calculadora()

        when: "sumo 2 y 3"
        def r = calc.suma(2, 3)

        then: "obtengo 5"
        r == 5
    }

    def "suma con tabla"() {
        expect: "a + b == resultado"
        calc.suma(a, b) == resultado

        where:
        a | b | resultado
        1 | 2 | 3
        10 | 5 | 15
        0 | 0 | 0
    }

    def "division valida"() {
        when: "intento dividir por cero"
        calc.divide(1, 0)

        then:
        thrown(ArithmeticException)
    }
}

class Calculadora {
    int suma(int a, int b) { a + b }
    int divide(int a, int b) { a / b }
}

Los strings de los test en """...""" se convierten en nombres de test legibles. where: ejecuta N casos de la misma expect, perfecto para matrices. Spock integra mocks (interaction { }) sin librerías extra.

Jenkins: pipelines con Groovy

Los Jenkinsfile de Jenkins (Declarative/Shared Library) están escritos en Groovy. Veamos el patrón de un pipeline declarativo simple.

// Jenkinsfile
pipeline {
    agent any

    environment {
        APP_VERSION = '1.2.3'
    }

    stages {
        stage('Checkout') {
            steps { checkout scm }
        }
        stage('Build') {
            steps {
                sh 'gradle clean build'
            }
        }
        stage('Test') {
            steps {
                sh 'gradle test'
            }
        }
        stage('Despliegue') {
            steps {
                echo "Desplegando ${APP_VERSION}"
            }
        }
    }

    post {
        always { echo 'Fin del pipeline' }
        failure { echo 'Pipeline falló' }
    }
}

Jenkins usa Groovy por su DSL y su capacidad de scripting. Los "Shared Libraries" son librerías Groovy reutilizables entre pipelines. Conocer Groovy te permite escribir Jenkinsfile complejos con condiciones, closures y variables sin fricción.

Servicios REST y consola

Groovy brilla para hacer clientes REST (HttpBuilder-NG), parsear respuestas, y también para crear servicios con frameworks como Grails o Micronaut. En scripting, groovy con un script pequeño es tu curl con esteroides.

// Cliente HTTP simple sin librerías extra
// (Groovy 3+ incluye HttpBuilder; más simple: java.net.http)

import java.net.URI
import java.net.http.*

def client = HttpClient.newHttpClient()
def req = HttpRequest.newBuilder()
        .uri(URI.create('https://httpbin.org/json'))
        .GET()
        .build()

def resp = client.send(req, HttpResponse.BodyHandlers.ofString())
println "Estado: ${resp.statusCode()}"
println resp.body()

// Parsear JSON con Groovy
import groovy.json.JsonSlurper
def json = new JsonSlurper().parseText(resp.body())
println json.slideshow.title

// API con Grails 5+ [resumen] o con Micronaut:
// Aplicación completa se genera con:
//   curl -s https://start.micronaut.io | groovy ...
// Código:
// import io.micronaut.http.annotation.*
// @Controller('/saludo')
// class SaludoController {
//     @Get('/{nombre}')
//     String saluda(String nombre) { "Hola $nombre" }
// }

Para microservicios rápidos en JVM con Groovy: Micronaut y Grails (con su "reload" en desarrollo) son dos opciones reales. Los scripts con JsonSlurper cubren consumo de APIs de forma inmediata.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Gradle: crea un proyecto gradle init con plugin groovy, añade la tarea hola y ejecútala.
  2. Spock: escribe un Spec para Calculadora con una tabla where de 3 casos.
  3. Jenkinsfile: escribe un pipeline con stages build/test/deploy y un post que siempre imprima "fin".
  4. REST: con java.net.http haz GET a una API pública y extrae un campo con JsonSlurper.
  5. Buenas prácticas: añade @CompileStatic a un método crítico y explica qué garantiza.

Eso cierra el módulo de Groovy: del primer println a un pipeline de CI con el mismo lenguaje.
