Informes reproducibles con RMarkdown

RMarkdown combina prosa y código en un único documento que se compila a HTML, PDF o Word gracias a knitr. El resultado es un informe reproducible: cada vez que lo renderizas se vuelve a ejecutar el código y se regeneran números, tablas y gráficas. Es la manera estándar de comunicar análisis en la ciencia de datos.

# Instalar los motores una sola vez
install.packages("rmarkdown")
install.packages("knitr")

# Renderizar un documento informe.Rmd a HTML
rmarkdown::render("informe.Rmd", output_format = "html_document")
---
title: "Analisis de ventas 2026"
author: "Maria Garcia"
date: "agosto 2026"
output: html_document
---

El botón Knit de RStudio equivale a rmarkdown::render(). Cada compilación corre en un entorno casi limpio; si tu script dependía de variables de sesión que nunca guardaste, fallará justo ahí: eso es reproducibilidad en acción.

Chunks de código y texto inline

El documento mezcla markdown y chunks: bloques delimitados por triples comillas inversas con opciones que controlan si se muestra el código, los resultados o solo las gráficas. El texto inline permite insertar valores de R dentro de la prosa.

# Un chunk sin opciones: muestra código y resultados
```{r}
notas <- c(7, 8, 9)
mean(notas)
```

# Chunk con opción echo = FALSE: esconde el código
```{r, echo = FALSE}
summary(mpg$hwy)
```

# Chunk con etiqueta y caché (reutiliza el cálculo)
```{r carga, cache = TRUE}
grande <- read.csv("datos/censo.csv")
```
# Texto inline: pega el resultado dentro de la prosa
#  -> "La media de millas por galon es `r mean(mtcars$mpg)`"
#  -> Se renderiza como: "La media de millas por galon es 20.090625"

Proyectos RStudio y rutas relativas

Un Proyecto RStudio (archivo .Rproj) fija la raíz de trabajo e independiza tus rutas del sistema operativo. Al abrir el proyecto, la sesión arranca en esa carpeta; tú escribes rutas relativas como datos/ventas.csv y el código funciona igual en tu máquina y en la del equipo.

# La pesadilla de setwd: rutas absolutas que solo sirven en tu equipo
setwd("C:/Users/algo/Descargas/proyecto")      # evita esto

# Con un proyecto, ya estás en la raíz correcta
getwd()                 # .../MiProyecto
list.files()            # ves los archivos del proyecto
# Rutas relativas explícitas y el paquete here
install.packages("here")
library(here)
here()                  # raíz del proyecto, sin importar la carpeta

ventas <- read.csv(here("datos", "ventas.csv"))
productos <- read.csv(here("datos", "productos.csv"))

# Escribir siempre con la misma raíz
write.csv(ventas, here("salidas", "ventas_limpias.csv"), row.names = FALSE)

Nunca uses setwd() en un script compartido: rompe el código en cualquier otra máquina. Emplea proyectos y here. Evita también los espacios en los nombres de carpetas cuando colaboras en equipo.

Estilo y buenas prácticas

El código se lee más veces de las que se escribe. Seguir convenciones (snake_case para nombres, pipes encadenados legibles, comentarios que expliquen el porqué y no el qué) vuelve tus análisis mantenibles y revisables. Los equipos de datos viven de esto.

# Nombres claros y consistentes
ingresos_2026 <- 250000                       # snake_case para datos
calcular_margen <- function(x) x * 0.35       # verbos al nombrar funciones

# Mala elección: no dicen nada
x <- 250000
func1 <- function(a) a * 0.35
# Estructura tipo de un script analitico
# 0) Cargar librerías
library(tidyverse)

# 1) Importar datos (rutas relativas)
datos <- read_csv("datos/ventas.csv")

# 2) Limpiar y transformar con dplyr en cadena
limpio <- datos %>%
  filter(!is.na(region)) %>%
  mutate(total_bruto = cantidad * precio)

# 3) Analizar
por_region <- limpio %>%
  group_by(region) %>%
  summarize(total = sum(total_bruto))

# 4) Visualizar y exportar
por_region %>%
  ggplot(aes(x = region, y = total)) +
  geom_col()
ggsave("salidas/total_por_region.png")

Crear y usar funciones propias

Cuando repites un bloque tres veces, conviértelo en función: encapsulas lógica, ganas consistencia y pruebas el código una sola vez. Una función recibe argumentos, hace algo y devuelve el último objeto evaluado (o el marcado con return()).

# Sintaxis: nombre <- function(argumentos) { cuerpo }
imc <- function(peso, altura) {
  valor <- peso / altura^2
  return(valor)             # explícito, aunque opcional
}

imc(70, 1.75)               # 22.85714
imc(peso = 55, altura = 1.6)  # 21.48

# Argumentos con valores por defecto
redondear2 <- function(x, digitos = 2) round(x, digits = digitos)
redondear2(pi)
redondear2(pi, 4)
# Funciones que reciben y devuelven data frames
resumen_grupo <- function(datos, grupos) {
  datos %>%
    group_by({{ grupos }}) %>%
    summarize(media = mean(ventas, na.rm = TRUE),
              n = n())
}
resumen_grupo(mpg, manufacturer)

# Documentar para equipos (sintaxis roxygen2)
#' @title Calcula el margen bruto
#' @param precio Precio unitario
#' @return Margen en unidades monetarias
margen <- function(precio) precio * 0.35

Escribe funciones pequeñas con una sola responsabilidad y nómbralas con un verbo (calcular_x, leer_datos). Cuando una función supera 20 líneas, probablemente conviene dividirla.

Ejercicios prácticos

Construye tu primer informe reproducible de principio a fin.

  1. Informe mínimo: crea un .Rmd con título y un texto que cite inline el valor r mean(mtcars$mpg); compílalo a HTML.
  2. Tres chunks: agrega uno de carga de paquetes con message = FALSE, otro con echo = FALSE y un tercero que dibuje con ggplot2 la gráfica de ventas por región.
  3. Purgando setwd: convierte un script que empiece por setwd() a rutas relativas usando here() o un proyecto .Rproj.
  4. Limpieza de nombres: renombra tres variables que se llamen x, y, z en tu script de ejercicios a nombres descriptivos en snake_case.
  5. Función reutilizable: escribe graficar_hist(datos, variable) que devuelva un histograma de ggplot2 y pruébala con hwy del dataset mpg.

Felicidades: ya tienes el ciclo completo de ciencia de datos en R — describir, visualizar, modelar y comunicar. Sigue explorando el ecosistema.
