Declarar variables: var, := y const

A diferencia de Python, donde una variable es una etiqueta que puede apuntar a cualquier cosa, en Go toda variable tiene un tipo fijo decidido en tiempo de compilación. Esto permite al compilador detectar errores antes de ejecutar el programa y generar binarios muy eficientes. Go ofrece tres formas de declarar, y elegir bien entre ellas comunica intención al resto del equipo:

// Forma completa: var nombre tipo = valor
var pais string = "España"

// Con inferencia: el compilador deduce que es string
var poblacion = 48000000

// Sin valor inicial: toma su zero value (seccion siguiente)
var visitas int

// Declaracion corta := : SOLO dentro de funciones
ciudad := "Madrid"

// Agrupadas en bloque (estilo habitual a nivel de paquete)
var (
	ancho  = 800
	alto   = 600
	titulo = "Panel de control"
)

// Constantes: valor fijo conocido en tiempo de compilacion
const MaxIntentos = 3

¿Cuándo usar cada forma?

FormaDónde funcionaCuándo conviene
var nombre TEn cualquier parteCuando quieres dejar claro que empieza con su zero value, o al declarar a nivel de paquete
nombre := valorSolo dentro de funcionesEl 90 % del día a día: declara e infiere el tipo en una sola escritura
const nombre = valorEn cualquier parteValores fijos: límites, tasas, mensajes de configuración

Convención extendida en la comunidad: := dentro de funciones, var cuando quieras subrayar que la variable arranca vacía (var buffer bytes.Buffer) y const para todo lo que no deba cambiar jamás.

Dos reglas que sorprenden al llegar de otros lenguajes

  • Una variable local declarada y no usada es un error de compilación, no una advertencia: el compilador elimina el código muerto antes de que llegue a producción.
  • No puedes redeclarar con := en el mismo ámbito, pero sí en una asignación múltiple si al menos una variable es nueva: nombre, err := pedirDatos().

Los tipos primitivos y sus tamaños

Los literales tienen un tipo por defecto: un número entero es int, un decimal es float64 y una cadena es string. El especificador %T de Printf revela el tipo real de cualquier valor, ideal para aprender:

entero := 42             // int
decimal := 3.14          // float64
texto := "hola"          // string
bandera := true          // bool

fmt.Printf("%T %T %T %T\n", entero, decimal, texto, bandera)
// int float64 string bool

byte y rune no son tipos nuevos sino alias: type byte = uint8. Existen para que el código exprese intención: lees bytes de un fichero, pero recorres un texto runa a runa.

var pequenio int8 = 127 // el maximo de int8
pequenio++              // ¡sin error en compilacion!
fmt.Println(pequenio)   // -128 : el desborde "da la vuelta"

Go no detecta desbordes de enteros en ejecución: sumar 1 a un int8 en su máximo produce −128 en silencio. Elige tipos grandes salvo que estés manipulando formatos binarios exactos.

Nunca representes dinero con float32 ni operes precios acumulados en coma flotante sin cuidado: los errores de redondeo se acumulan. La práctica profesional es usar centavos enteros (int64) o tipos decimales exactos de librerías especializadas.

Zero values: aquí no existe undefined

En JavaScript una variable puede estar undefined; en Java un campo puede quedar a null por descuido. Go elimina esa categoría de bugs con una regla de oro: toda variable declarada recibe automáticamente un valor inicial válido llamado zero value. Nunca hay memoria basura ni estados indefinidos.

TipoZero value
Numéricos (int, float64, ...)0
string"" (cadena vacía, no nil)
boolfalse
Punteros, slices, maps, canales, funciones, interfacesnil
StructsEstructura con cada campo en su zero value
type Tarea struct {
	Nombre    string
	Prioridad int
	Hecha     bool
}

var t Tarea // sin constructor, sin inicializar
fmt.Println(t) // { 0 false}: perfectamente imprimible y utilizable

Este comportamiento habilita un patrón muy gozoso de Go: estructuras utilizables en su valor cero. Un strings.Builder recién declarado ya acepta escrituras, y un mapa declarado con make ya acepta inserciones, sin constructores de por medio.

Fíjate en lo que desaparece: los errores de «variable sin inicializar» que en C leen basura de memoria, y los NullPointerException accidentales de campos olvidados. El zero value convierte el «no inicializado» en un estado diseñado.

nil en Go no es el null universal de otros lenguajes: solo pueden ser nil los tipos con referencia interna (punteros, slices, maps, canales, funciones, interfaces). Desreferenciar un puntero nil provoca un panic inmediato.

Conversión explícita: nada se convierte solo

Go no realiza ninguna coerción implícita entre tipos, ni siquiera entre int y float64, los tipos numéricos más comunes. La conversión siempre se escribe T(valor). Parece burocracia, pero evita bugs históricos: pérdidas silenciosas de precisión y divisiones enteras por accidente.

litros := 130
viajes := 3

mediaEntera := litros / viajes                    // 43: division ENTERA, trunca
mediaReal := float64(litros) / float64(viajes)    // 43.333...

// mala := litros + mediaReal // ERROR de compilacion: int + float64
buena := litros + int(mediaReal) // conversion explicita obligatoria

Tipos definidos frente a alias

Con type puedes crear dos cosas distintas: un tipo definido (nuevo, incompatible con el original aunque compartan representación) o un alias (otro nombre para el mismo tipo).

type Metros float64       // tipo DEFINIDO: nuevo e independiente
type Kilogramos = float64 // ALIAS: es exactamente float64

var distancia Metros = 42.195
peso := Kilogramos(72.5)  // sigue siendo un float64 corriente

// velocidad := distancia / peso // ERROR: Metros y float64 no se mezclan
fmt.Printf("%T %.3f\n", distancia, distancia) // main.Metros 42.195

Crear tipos definidos para unidades (Metros, Segundos) o identificadores (IDUsuario int) aporta seguridad semántica gratuita: el compilador impedirá dividir metros entre kilogramos, el fallo que costó la misión Mars Climate Orbiter en 1999.

Constantes tipadas, no tipadas e iota

Las constantes se evalúan en tiempo de compilación con aritmética de precisión arbitraria. Las constantes no tipadas son especialmente flexibles: no tienen tipo propio hasta que se usan y se adaptan al contexto:

const MaxConexiones = 500        // NO tipada: se adapta al destino
const Pi float64 = 3.14159265    // TIPADA: solo opera con float64

var puerto int16 = MaxConexiones // OK: la constante cabe en int16
// var mal := int(Pi)            // Pi es float64; conversion necesaria

// Precision arbitraria: esto no desborda en compilacion
const NanosegundosPorHora = 60 * 60 * 1000000000

iota: enumeraciones elegantes

El identificador iota vale 0 en la primera línea de un bloque const y avanza en uno por cada línea. Es la forma estándar de construir enumeraciones:

type DiaSemana int

const (
	Lunes DiaSemana = iota // 0
	Martes                 // 1: iota se propaga con la expresion repetida
	Miercoles              // 2
	Jueves
	Viernes
	Sabado
	Domingo                // 6
)

type NivelLog int

const (
	Debug NivelLog = iota
	Info
	Warn
	Error
	_               // guion bajo: salta una posicion
	Fatal           // vale 5
)

iota admite expresiones: Kilobyte = 1 << (10 * iota) genera 1, 1024, 1048576... en líneas sucesivas. Cada bloque const reinicia iota a cero.

Strings UTF-8: bytes frente a runas

Un string en Go es una secuencia inmutable de bytes codificados en UTF-8. Esta decisión explica comportamientos que desconciertan a principiantes: len() cuenta bytes, no letras, y un carácter como é u un emoji ocupan varios bytes.

saludo := "¡Olé!"
// ¡ y O,l,e ocupan 1 byte; ó ocupa 2 bytes en UTF-8

fmt.Println(len(saludo))                    // 6 BYTES (no 5 letras)
fmt.Println(utf8.RuneCountInString(saludo)) // 5 caracteres

// range decodifica runa a runa; el indice apunta al BYTE inicial
for i, r := range saludo {
	fmt.Printf("byte %d -> %c\n", i, r)
}

runas := []rune(saludo)      // convertir a slice de runas
fmt.Println(string(runas[3])) // é: ahora si es un solo elemento
Necesito...Sobre bytesSobre runas (caracteres)

Cortar una cadena con s[:4] puede partir una runa por la mitad y producir caracteres corruptos (mojibake). Si vas a trocear texto con acentos o emojis, convierte primero a []rune o usa paquetes como strings que respetan UTF-8.

Errores comunes

Estos tropiezos aparecen en casi todo desarrollador que llega a Go desde lenguajes dinámicos. Reconocerlos ahorra horas de depuración:

Error típicoSíntomaSolución
Declarar y no usar una variable localdeclared and not used: no compilaÚsala o elimínala; usa _ para descartar conscientemente
Importar un paquete sin usarloimported and not usedBorra el import; tu editor lo gestiona al guardar
Mezclar int y float64 en una operacióninvalid operation: mismatched typesConvierte explícitamente con T(valor)
Creer que len(s) cuenta letrasTextos con acentos miden «demasiado»utf8.RuneCountInString(s) o []rune(s)
Desborde silencioso en enteros pequeñosValores absurdos tras sumar/restarUsa int por defecto; reserva los pequeños para binario
Shadowing: err re-declarado dentro de un ifEl error exterior parece «desaparecer»Reutiliza con = o renombra; vigila cada := nuevo bloque
err := primerPaso()
if err == nil {
	datos, err := segundoPaso() // := crea OTRO err, solo visible aqui
	_ = datos
	_ = err
}
// fuera del if, err sigue siendo el de primerPaso: bug clasico

Activa el análisis en tiempo real de VSCode (extensión oficial de Go) y ejecuta go vet ./... antes de cada commit: entre ambos cazan el shadowing sospechoso, los formatos incorrectos en Printf y conversiones dudosas.

Ejercicios prácticos

Resuélvelos en orden dentro de un módulo nuevo (go mod init guidev/tipos): cada ejercicio reutiliza el anterior.

  1. Tres formas de decir lo mismo: declara la variable version (valor 3) con var completa, var con inferencia y :=. Imprime su tipo con fmt.Printf("%T\n", version) y explica en un comentario por qué las tres compilan igual.
  2. Conversor de temperaturas: crea los tipos definidos Celsius y Fahrenheit sobre float64 y funciones que conviertan entre ellos con conversiones explícitas. Intenta a propósito sumar un Celsius con un float64 sin convertir y lee el error del compilador.
  3. Enumeración con iota: modela EstadoPedido con los estados Pendiente, Pagado, Enviado, Entregado y Cancelado. Imprime cada constante con su valor numérico usando fmt.Println y %d.
  4. Analizador de cadenas: toma la frase "¡Mañana será ñoño 🚀!" y muestra lado a lado len(), utf8.RuneCountInString() y el recorrido con range. Escribe en comentarios cuántos bytes ocupa cada carácter especial.
  5. Calculadora de factura: con constantes (IVA = 0.21, DescuentoVolumen = 0.05) y variables float64, calcula subtotal, descuento, impuestos y total de tres productos. Después intenta hacer el mismo cálculo con int y documenta en un comentario exactamente dónde aparecería el truncado y cuánto dinero «desaparecería».
