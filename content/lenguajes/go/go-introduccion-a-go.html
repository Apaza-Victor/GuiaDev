¿Por qué Go?

Go (también llamado Golang) es un lenguaje de programación creado en Google en 2009 por Rob Pike, Ken Thompson y Robert Griesemer: tres veteranos con décadas de experiencia en sistemas (entre ellos están Unix, el editor Plan 9 y el estándar UTF-8). Su motivación era muy concreta: en Google, los proyectos gigantes escritos en C++ tardaban minutos u horas en compilar, Java se sentía pesado y verboso, y Python era demasiado lento para la infraestructura crítica. Go nació como respuesta directa a ese problema.

Filosofía: la simplicidad como ventaja competitiva

La gran apuesta de Go es tener menos características, no más. No hay herencia clásica, no hay sobrecarga de operadores, no hay excepciones tradicionales, no existe el bucle while. Todo eso se resuelve con mecanismos más simples: composición, valores de error y un único bucle for. La consecuencia práctica es notable: dos equipos distintos escriben código Go sorprendentemente parecido, lo que reduce el coste de leer y mantener código ajeno.

Pilar de diseñoQué significa en la práctica
Simplicidad radicalCerca de 25 palabras clave (Java tiene ~50); una sola forma correcta de hacer cada cosa
Compilación ultrarrápidaProyectos enormes compilan en segundos gracias a un modelo de dependencias estricto
Binario estáticoEl ejecutable incluye todo el runtime: se copia a cualquier servidor o contenedor sin instalar nada
Concurrencia nativaGoroutines y channels forman parte del lenguaje, no de librerías externas
Recolector de basuraMemoria gestionada automáticamente, pero con pausas de microsegundos pensadas para servidores

Casos de uso reales: quién usa Go y para qué

Go no es un lenguaje académico: fue diseñado para resolver problemas reales de escala, y hoy sostiene buena parte de la infraestructura de internet. Si alguna vez has usado Docker, Kubernetes o Terraform, ya has ejecutado software escrito íntegramente en Go.

Perfiles profesionales donde Go brilla hoy

  • Backends y APIs: servidores HTTP de altísimo rendimiento con la librería estándar, sin frameworks obligatorios.
  • Microservicios: despliegues pequeños, arranque instantáneo y consumo mínimo de RAM.
  • Herramientas CLI: Terraform, gh (GitHub CLI) o kubectl son el estándar de oro de las interfaces de consola.
  • DevOps y cloud-native: casi todo el ecosistema CNCF (Cloud Native Computing Foundation) está escrito en Go.
  • Redes y proxies: manejo eficiente de miles de conexiones simultáneas.

Aprender Go abre puertas laborales muy concretas: DevOps, SRE, plataformas cloud y backends de alto rendimiento. Es, literalmente, el idioma nativo de la computación cloud-native moderna.

Go no es la mejor opción para todo: las GUIs de escritorio, la ciencia de datos intensiva o los videojuegos AAA tienen mejores herramientas en otros ecosistemas. Go domina donde importan red, concurrencia y despliegue sencillo.

Instalación oficial y workspace moderno con módulos

Instalar el compilador

La forma recomendada es descargar el instalador oficial desde go.dev/dl. Existen instaladores gráficos para Windows y macOS, y un tarball para Linux. Elige siempre la versión estable más reciente: Go garantiza compatibilidad hacia atrás, de modo que código escrito en 2012 sigue compilando hoy sin cambios.

  1. Descarga el instalador para tu sistema operativo desde go.dev/dl
  2. Ejecuta el instalador con los valores por defecto (configura el PATH automáticamente)
  3. Abre una terminal nueva y verifica la instalación:
go version
# go version go1.22.5 windows/amd64

Si tras instalar recibes go: command not found (o "no se reconoce como comando") en Windows, cierra y vuelve a abrir la terminal: el PATH solo se recarga al iniciar una sesión nueva.

El workspace moderno: módulos, no GOPATH

Antes de 2018, Go obligaba a guardar todos los proyectos en una carpeta global llamada GOPATH, algo incómodo. Hoy el estándar son los módulos: cada proyecto es una carpeta independiente con su propio archivo go.mod, ubicada donde tú quieras. Crear un proyecto nuevo son dos comandos:

mkdir hola
cd hola
go mod init guidev/hola
# go: creating new go.mod: module guidev/hola

El comando go mod init genera el archivo go.mod, la "credencial de identidad" del proyecto:

module guidev/hola

go 1.22

La primera línea declara el nombre del módulo (su identificador único, importante cuando otros proyectos lo importen) y la segunda indica la versión mínima de Go necesaria para compilarlo.

No necesitas un IDE pesado: VSCode + la extensión oficial de Go ofrece autocompletado, depurador, detección de errores en tiempo real y formateo automático al guardar. Es la combinación usada por la mayoría de la comunidad.

Tu primer programa, explicado línea a línea

Crea dentro de la carpeta del proyecto un archivo llamado main.go con este contenido clásico:

package main

import "fmt"

func main() {
	fmt.Println("Hola, GuiaDev!")
}

Aunque parece trivial, cada línea encierra una decisión de diseño importante:

LíneaExplicación
package mainTodo archivo Go declara a qué paquete pertenece. El paquete main es especial: define un programa ejecutable (los demás paquetes son librerías reutilizables)
import "fmt"Importa fmt, el paquete estándar de entrada/salida formateada. Go prohíbe importar sin usar: si no lo empleas, el compilador rechaza el programa
func main()Punto de entrada del ejecutable: aquí comienza y termina el programa. No recibe argumentos ni devuelve valores
fmt.Println(...)Imprime los argumentos en consola seguidos de un salto de línea. Fíjate: la letra mayúscula (Println) indica que es público, exportado por el paquete

Ejecutarlo de dos maneras

# Modo desarrollo: compila en memoria y ejecuta al instante
go run .
# Hola, GuiaDev!

# Modo distribucion: genera el binario real en la carpeta actual
go build
# Windows crea hola.exe ; Linux/macOS crean ./hola

go run compila a un archivo temporal, lo ejecuta y lo borra: perfecto para iterar rápido. go build produce el artefacto definitivo, el que copiarías a producción.

Solo puede existir una función main por programa y debe vivir en el paquete main. Si tu archivo dice package utils, obtendrás librerías, nunca un ejecutable: el error "runtime: no main function" te lo recordará.

Los comandos esenciales de la herramienta go

Go destaca porque no necesitas un ecosistema de herramientas externas para ser productivo: un único comando, go, cubre compilar, formatear, analizar, testear y documentar. Estas son las subórdenes que usarás a diario:

ComandoPara qué sirveEjemplo típico
go runCompila en memoria y ejecuta en un paso (ideal para desarrollo)go run .
go buildGenera el binario ejecutable finalgo build ./cmd/app
go fmtReformatea el código al estilo oficial (gofmt)go fmt ./...
go vetAnálisis estático: detecta errores sospechosos que compilan pero son bugsgo vet ./...
go installCompila e instala el binario en $HOME/go/bin (accesible desde el PATH)go install
go getAñade o actualiza dependencias externas al go.modgo get github.com/google/uuid
go testEjecuta las pruebas unitarias del proyectogo test ./...
go docMuestra documentación desde la terminal, sin internetgo doc fmt.Println

El patrón ./... significa "este paquete y todos sus subpaquetes recursivamente", así que esas variantes son las que normalmente pondrás en tus scripts de CI.

Nunca despliegues producción con go run: compila cada vez que arranca y depende de fuentes presentes en el servidor. El flujo profesional es go build una vez, distribuir el binario resultante.

Prueba go doc net/http.ServeMux o go doc strings.Builder: toda la documentación de la librería estándar vive instalada en tu máquina, disponible sin conexión y con ejemplos.

Situar Go respecto a lenguajes que ya conoces aclara rápidamente su nicho: quiere la velocidad y seguridad de un lenguaje compilado con la agilidad de un lenguaje moderno y minimalista.

Un mismo programa en Go

// Go: tipado estatico con inferencia, compilable a binario
package main

import "fmt"

func main() {
	lenguaje := "Go"                 // := declara e infiere el tipo (string)
	anio := 2009                     // int
	fmt.Printf("%s nacio en %d\n", lenguaje, anio)
}

Go eligió deliberadamente no tener herencia ni excepciones: en su lugar usa composición (structs embebidos) y errores como valores ordinarios. Parecen ausencias, pero son decisiones que eliminan categorías enteras de bugs. Las verás en profundidad en las lecciones 4, 5 y 6.

Buenas prácticas desde el primer día

La comunidad Go tiene una cultura de uniformidad poco común, y conviene adoptarla desde el primer programa para no arrastrar malos hábitos de otros lenguajes.

Reglas de oro del principiante Go

PrácticaRazón
Ejecuta go fmt siempreEl formato no se debate: tabuladores, llaves en la misma línea, imports agrupados. Configura tu editor para formatear al guardar
Nombres cortos cerca, largos lejosi vale para un índice de 3 líneas; maxConexionesServidor para un campo exportado. El contexto acorta los nombres
Errores explícitosNo ocultes fallos: devuélvelos como valor error y decide arriba qué hacer con ellos
Menos abstracciónNo crees interfaces "por si acaso" ni capas de indirección: Go premia el código directo y legible
Comenta el porqué, no el quéEl código ya dice qué hace; el comentario valioso explica la intención o la decisión
// Mal: nombre largo y redundante en un contexto pequeno
var nombreDelUsuarioActual string = "Ana"

// Bien: contexto local, nombre corto, tipo inferido
name := "Ana"

go fmt embellece, pero no detecta errores lógicos. Combínalo siempre con go vet, que encuentra descuidos clásicos como formatos incorrectos en Printf o variables capturadas por referencia en bucles.

Hábito ganador: antes de cada commit ejecuta go vet ./... && go test ./.... Dos comandos que evitan el 90% de las sorpresas en revisión de código.

Ejercicios prácticos

Instala el entorno y consolida el flujo de trabajo básico de todo desarrollador Go. Resuélvelos en orden: cada uno apoya al siguiente.

  1. Verificación del entorno: instala Go 1.22 o superior, ejecuta go version y anota tu combinación de sistema operativo y arquitectura (por ejemplo windows/amd64). Comprueba también dónde quedó instalado el binario con where go o which go.
  2. Primer módulo: crea una carpeta saludo, inicialízala con go mod init guidev/saludo y escribe un programa que imprima tres líneas: tu nombre, la versión de Go en ejecución (pista: fmt.Println(runtime.Version()) importando runtime) y tu sistema operativo.
  3. Domar al compilador: provoca a propósito los dos errores más famosos de Go: usa una variable sin utilizar y declara un import sin usar. Lee con calma los mensajes del compilador (indican archivo y línea exacta) y corrige ambos.
  4. Higiene de código: desordena a mano la indentación y las llaves de tu main.go, ejecuta go fmt . y comprueba cómo queda restaurado. Después corre go vet . y verifica que tu código pasa limpio.
  5. Multiplataforma: compila tu programa con go build y anota el tamaño del binario. Luego cross-compila para otra plataforma ($env:GOOS="darwin"; $env:GOARCH="arm64"; go build en PowerShell) y confirma que se genera un ejecutable nuevo para macOS sin cambiar una sola línea de código. Restaura las variables con Remove-Item Env:GOOS, Env:GOARCH.
