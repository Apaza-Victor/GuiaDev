Implementación implícita: sin implements

Una interfaz en Go declara un conjunto de métodos. Cualquier tipo que tenga esos métodos satisface la interfaz — automáticamente, sin declararlo. No existe la palabra implements. Esta decisión, llamada tipado estructural, tiene una consecuencia revolucionaria: puedes hacer que un tipo definido por OTRO (incluso de la stdlib) satisfaga TU interfaz, algo imposible con herencia clásica.

Declaración y satisfacción

// La interfaz: SOLO comportamientos
type Figura interface {
    Area() float64
    Perimetro() float64
}

// Dos tipos independientes...
type Circulo struct{ Radio float64 }
func (c Circulo) Area() float64     { return math.Pi * c.Radio * c.Radio }
func (c Circulo) Perimetro() float64 { return 2 * math.Pi * c.Radio }

type Rectangulo struct{ Base, Altura float64 }
func (r Rectangulo) Area() float64     { return r.Base * r.Altura }
func (r Rectangulo) Perimetro() float64 { return 2 * (r.Base + r.Altura) }

// ...y UNA función que acepta a ambos sin saberlo
func describir(f Figura) {
    fmt.Printf("Área: %.2f | Perímetro: %.2f\n", f.Area(), f.Perimetro())
}

describir(Circulo{Radio: 5})
describir(Rectangulo{Base: 4, Altura: 6})

Ni Circulo ni Rectangulo mencionan a Figura en ninguna parte. La relación nace del comportamiento. Puedes definir mañana una interfaz Dibujable sobre ellos sin tocar sus archivos: eso es imposible en Java o C#.

El lema de Go: acepta interfaces, devuelve structs

ReglaRazón
Acepta interfaces en parámetrosTu función funciona con cualquier implementación presente y FUTURA; quien llama decide el detalle
Devuelve tipos concretosQuien recibe ve TODO lo que puede hacer con el valor, no solo tu subconjunto; las interfaces se definen donde se CONSUMEN

En Go las interfaces suelen ser PEQUEÑAS: uno o dos métodos. Si diseñas una interfaz de diez métodos "por si acaso", estás pensando en Java. Define la interfaz en el paquete consumidor, con exactamente los métodos que ese consumidor necesita.

Interfaces de la stdlib que usarás siempre

fmt.Stringer: tu toString personalizado

type Color struct{ R, G, B uint8 }

// Al implementar String(), fmt.Println/Printf(%v/%s) lo usan solos
func (c Color) String() string {
    return fmt.Sprintf("#%02X%02X%02X", c.R, c.G, c.B)
}

rojo := Color{255, 0, 0}
fmt.Println(rojo) // #FF0000 — sin llamar a nada especial

error: la interfaz más famosa del lenguaje

type error interface {
    Error() string
}

Ese es su código fuente completo. Cualquier tipo con método Error() string es un error válido — por eso crear errores personalizados son tres líneas.

io.Reader e io.Writer: el sistema circulatorio de Go

InterfazMétodoImplementada por
io.ReaderRead(p []byte) (n int, err error)archivos, respuestas HTTP, buffers, strings (strings.Reader), compresión gzip…
io.WriterWrite(p []byte) (n int, err error)stdout, archivos, buffers, respuestas HTTP, hashes…

La magia: funciones como io.Copy(dst Writer, src Reader) funcionan entre CUALQUIER par de implementaciones. Copiar un archivo comprimido descargado por HTTP a un hash SHA-256 son cuatro piezas intercambiables:

respuesta, _ := http.Get(url)
defer respuesta.Body.Close() // Body implementa io.Reader

hash := sha256.New()          // hash.Writer implementa io.Writer
io.Copy(hash, respuesta.Body) // pega cualquier Reader a cualquier Writer
fmt.Printf("%x\n", hash.Sum(nil))

Composición de interfaces

Las interfaces se componen entre sí formando contratos mayores:

type ReadWriter interface {
    Reader
    Writer
}

type ReadWriteCloser interface {
    Reader
    Writer
    Closer
}

// Un *os.File ya satisface ReadWriteCloser: tiene los 3 métodos

Este estilo composicional explica por qué el ecosistema Go encaja tan bien entre sí: todos hablan de Readers, Writers y Closers estándar, no de clases base compartidas.

Interfaz vacía, assertions y type switches

interface{} / any: el comodín

La interfaz vacía no exige ningún método, así que TODOS los tipos la satisfacen. Desde Go 1.18 tiene alias: any. Es el tipo de fmt.Println, de JSON dinámico y de contenedores heterogéneos — pero también pierde toda comprobación de tipos:

var caja any = 42
caja = "ahora texto"
caja = []float64{1.5, 2.5} // todo cabe

Cada uso de any traslada el descubrimiento de errores del tiempo de compilación al runtime. En Go moderno, usa genéricos cuando puedas y reserva any para fronteras genuinamente dinámicas (JSON, plugins, logging).

Type assertion: extraer el concreto

var v any = "hola mundo"

// Forma arriesgada: PANIC si v no es string
s := v.(string)

// Forma idiomática con ok: nunca panic
s, ok := v.(string)
if ok {
    fmt.Println("Longitud:", len(s))
} else {
    fmt.Println("No era un string")
}

Type switch: múltiples tipos, máxima claridad

func imprimir(v any) {
    switch x := v.(type) {
    case nil:
        fmt.Println("nulo")
    case int, int64:
        fmt.Printf("entero: %d\n", x)
    case string:
        fmt.Printf("texto (%d caracteres)\n", len(x))
    case []any:
        fmt.Printf("lista de %d elementos\n", len(x))
    default:
        fmt.Printf("tipo %T\n", x)
    }
}

Detalles finos: nil, valores vs punteros

¿Qué entra exactamente en una interfaz?

Internamente, un valor de interfaz guarda dos cosas: (tipo concreto, valor). Esta pareja explica los casos más confusos del lenguaje:

var w io.Writer

w = os.Stdout      // ( *os.File , descriptor ) → w != nil
w = nil            // (nil, nil)              → w == nil

// LA TRAMPA CLÁSICA:
var f *os.File = nil
w = f              // (*os.File, nil): TIPO presente, VALOR nil
fmt.Println(w != nil) // ¡true! aunque el puntero interno sea nil
SituaciónTipo dinámicoValor dinámicow == nil?
Interfaz cero (var w io.Writer)nilniltrue
Puntero nil asignado (w = (*os.File)(nil))*os.Filenilfalse

Esta trampa causa bugs reales: funciones que devuelven (*MiError)(nil) tipadas como interfaz hacen que err != nil sea true con un error "fantasma". Regla práctica: devuelve nil literal para indicar ausencia de error, nunca un puntero nil tipado.

Ejercicios prácticos

  1. Figuras geométricas: define interfaz Figura (Area, Perimetro); implementa Círculo, Rectángulo y Triángulo; escribe función que reciba un slice de Figuras y devuelva la de mayor área.
  2. Stringer real: crea tipo Duracion (segundos int64) cuyo String() muestre "2h 05m 30s" y úsalo desde fmt.Println sin castings.
  3. Pipeline de Writers: implementa un Mayusculizador que satisfaga io.Writer transformando a mayúsculas lo recibido, y encadénalo: datos → Mayusculizador → bytes.Buffer.
  4. Errores con superpoderes: crea ErrorValidacion con campo Campos []string; haz que una función de registro devuelva este tipo envuelto y demuestra errors.As extrayendo la lista de campos fallidos.
  5. Cazador de la trampa nil: reproduce el bug de la sección "Detalles finos" (interfaz conteniendo puntero nil), verifica que != nil da true, y corrígelo devolviendo nil literal.
