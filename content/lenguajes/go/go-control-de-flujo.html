if y el único bucle: for

Go toma una decisión de diseño radical respecto a otros lenguajes: solo existe una palabra clave para los bucles, for. No hay while, ni do-while, ni until. A cambio, esa única estructura cubre todos los casos, reduce la superficie que debes memorizar y elimina de raíz la pregunta "¿cuál de los cuatro bucles uso aquí?". El if también se simplifica: sin paréntesis obligatorios y con llaves siempre exigidas.

La sentencia if: sin paréntesis, con llaves obligatorias

A diferencia de C, Java o JavaScript, en Go no escribes paréntesis alrededor de la condición y las llaves son obligatorias incluso con una sola instrucción. Esto evita bugs históricos como el famoso caso de Apple #gotofail, donde una instrucción quedó fuera de su if por la falta de llaves.

temperatura := 31

// Sin paréntesis, llaves SIEMPRE
if temperatura > 30 {
    fmt.Println("Hace calor")
} else if temperatura < 10 {
    fmt.Println("Hace frío")
} else {
    fmt.Println("Temperatura agradable")
}

El compilador te obligará a abrir la llave en la misma línea () {). Si la pones abajo, obtendrás un error de sintaxis: así impone Go el estilo uniforme en todo el ecosistema.

Init statement: variables que viven solo dentro del if

El if admite una sentencia de inicialización antes de la condición, separada por punto y coma. La variable creada ahí solo existe dentro del bloque if/else: es la forma idiomática de limitar el alcance y evitar contaminar la función con variables temporales.

archivo, err := os.Open("datos.txt")

// err vive SOLO dentro de este if/else
if err != nil {
    fmt.Println("Error:", err)
} else {
    defer archivo.Close()
    fmt.Println("Archivo abierto:", archivo.Name())
}
// Aquí 'err' ya no está disponible si usó esta variante

Este patrón aparece constantemente en código Go profesional: inicializar, comprobar el error y salir temprano. Acostúmbrate a leerlo como "consigue X; si falla, actúa; si no, continúa".

Las cuatro caras del mismo for

Toda iteración posible en Go se expresa con for. Solo cambia qué partes incluyes entre paréntesis:

FormaSintaxisEquivale aUso típico
Clásicofor i := 0; i < n; i++ { }for de C/JavaÍndices numéricos, conteos
Whilefor condicion { }whileRepetir hasta cumplir condición
Infinitofor { }while(true)Servidores, loops de eventos, workers
Rangefor i, v := range coleccion { }foreachRecorrer slices, maps, strings, channels
 
// 1. Clásico: conoces cuántas vueltas
suma := 0
for i := 1; i <= 100; i++ {
    suma += i
}

// 2. Estilo while: no sabes cuántas vueltas
potencia := 1
for potencia < 1000 {
    potencia *= 2
}

// 3. Infinito: servidores y workers (con salida controlada)
contador := 0
for {
    contador++
    if contador == 3 {
        break // la única forma de salir
    }
}

// 4. Range: la forma idiomática de recorrer colecciones
lenguajes := []string{"Go", "Rust", "Kotlin"}
for indice, valor := range lenguajes {
    fmt.Printf("%d: %s\n", indice, valor)
}

Con range, si solo necesitas el índice omite el segundo valor (for i := range s); si solo necesitas el valor, usa el guion bajo (for _, v := range s). Go rechaza compilar variables declaradas y no usadas, así que _ es obligatorio, no estético.

Qué devuelve range según el tipo

Ojo con range en strings: el primer valor es la posición en bytes, no la posición del carácter. En textos con acentos o emojis, un carácter puede ocupar varios bytes y los índices saltarán de 2 en 2 o más.

switch: el rey de la legibilidad en Go

El switch de Go corrige las dos quejas históricas del switch de C: no hay caída accidental entre casos (no necesitas break; cada caso termina solo) y puede funcionar sin expresión, sustituyendo cadenas largas de else if con mucha más claridad.

Switch básico con agrupación de valores

dia := "sábado"

switch dia {
case "sábado", "domingo": // varios valores separados por coma
    fmt.Println("¡Fin de semana!")
case "lunes":
    fmt.Println("Inicio de semana")
default:
    fmt.Println("Día laborable")
}
// No hace falta break: cada case termina automáticamente

Switch con init statement

Igual que if, el switch acepta una inicialización previa. La variable queda limitada al ámbito del switch:

switch hora := time.Now().Hour(); {
case hora < 12:
    fmt.Println("Buenos días")
case hora < 19:
    fmt.Println("Buenas tardes")
default:
    fmt.Println("Buenas noches")
}

Switch sin expresión: el reemplazo del else-if

Cuando omites la expresión, cada case es simplemente una condición booleana evaluada en orden. Es la forma preferida en Go para decisiones multi-rama complejas:

edad, tieneLicencia := 17, true

switch {
case edad < 16:
    fmt.Println("No puede conducir")
case edad < 18 && !tieneLicencia:
    fmt.Println("Necesita permiso de aprendiz")
case edad < 18:
    fmt.Println("Puede conducir acompañado")
default:
    fmt.Println("Puede conducir solo")
}

Un switch { } con condiciones ordenadas de lo más específico a lo más general es mucho más fácil de leer y modificar que una torre de else if. Úsalo siempre que tengas 3+ ramas.

Type switch: descubrir el tipo dinámico

Cuando trabajas con interfaces (por ejemplo, interface{}/any), el type switch permite ejecutar una rama por cada tipo concreto. Es una pieza central del código Go genérico:

func describir(v any) string {
    switch t := v.(type) { // type switch
    case int:
        return fmt.Sprintf("Entero: %d", t*2)
    case string:
        return fmt.Sprintf("Texto de %d caracteres", len(t))
    case bool:
        if t {
            return "Verdadero"
        }
        return "Falso"
    case nil:
        return "Valor nulo"
    default:
        return fmt.Sprintf("Tipo desconocido: %T", t)
    }
}

fallthrough: el caso excepcional

Si de verdad quieres reproducir el comportamiento de C (entrar al siguiente case sin evaluar su condición), existe fallthrough. Su uso es tan raro que cuando alguien lo lee en revisión de código, sospecha un bug:

nivel := 1
switch nivel {
case 1:
    fmt.Println("Cargando nivel base")
    fallthrough // entra SIEMPRE al siguiente case
case 2:
    fmt.Println("Aplicando texturas")
case 3:
    fmt.Println("Cargando enemigos")
}
// Imprime ambas líneas: "nivel base" Y "texturas"

Etiquetas: break y continue dirigidos

En bucles anidados, break y continue solo afectan al bucle interior. Para salir (o continuar) desde un bucle exterior, Go usa etiquetas: nombres seguidos de dos puntos colocados justo antes del bucle objetivo. Es la alternativa estructurada y legible al goto.

matriz := [][]int{
    {4, 8, 15},
    {16, 23, 42},
}

buscado := 23
encontrado := false

// La etiqueta apunta AL BUCLE EXTERIOR
externo:
for i, fila := range matriz {
    for j, valor := range fila {
        if valor == buscado {
            fmt.Printf("Hallado en [%d][%d]\n", i, j)
            encontrado = true
            break externo // sale de AMBOS bucles
        }
    }
}

if !encontrado {
    fmt.Println("No está en la matriz")
}

Con continue externo, en cambio, no sales: saltas directamente a la siguiente vuelta del bucle exterior. Resulta útil para filtrar combinaciones completas:

// Pares (a, b) donde a*b sea múltiplo de 10,
// descartando toda la fila cuando a sea múltiplo de 5
externo:
for a := 1; a <= 6; a++ {
    for b := 1; b <= 6; b++ {
        if a%5 == 0 {
            continue externo // siguiente valor de 'a'
        }
        if (a * b)%10 == 0 {
            fmt.Printf("%d x %d = %d\n", a, b, a*b)
        }
    }
}

Go conserva goto pero casi nadie lo usa: las etiquetas cubren el caso legítimo (romper bucles anidados) sin los males del salto libre. Si te ves escribiendo goto, casi seguro refactorizarías mejor extrayendo una función.

Patrones idiomáticos de control

Más allá de la sintaxis, el código Go profesional reconoce ciertos patrones recurrentes de control de flujo. Adoptarlos temprano hará que tu código parezca escrito por alguien de la comunidad, no por un traductor de otro lenguaje.

Cláusulas guard: retorna temprano

En lugar de anidar validaciones, valida primero y retorna en cuanto algo falle. El "camino feliz" queda al nivel principal, sin indentación profunda:

func procesarPedido(usuario string, total float64, cupon bool) error {
    // Guards: casos inválidos fuera cuanto antes
    if usuario == "" {
        return errors.New("usuario requerido")
    }
    if total <= 0 {
        return errors.New("total debe ser positivo")
    }

    // Camino feliz, plano y legible
    if cupon {
        total *= 0.9
    }
    fmt.Printf("Pedido OK para %s: %.2f\n", usuario, total)
    return nil
}

El patrón "consigue, comprueba, continúa"

La secuencia x, err := f() seguida de if err != nil representa cerca del 40% del flujo de control en programas Go reales. Verás variantes en todas las APIs de la stdlib:

respuesta, err := http.Get("https://api.ejemplo.com/datos")
if err != nil {
    log.Fatal(err) // corta el programa registrando el error
}
defer respuesta.Body.Close()

cuerpo, err := io.ReadAll(respuesta.Body)
if err != nil {
    return fmt.Errorf("leyendo respuesta: %w", err)
}

Aunque parezca verboso frente a excepciones, este estilo hace visible TODO el flujo de errores: nada falla "mágicamente" entre dos líneas. Los equipos grandes valoran enormemente esa previsibilidad.

Bucle infinito bien construido

Los servidores Go viven en for { }. La clave es que la salida esté explícita y controlada, nunca perdida:

cola := make(chan string, 10)

for trabajo := range cola { // termina cuando cierren el canal
    resultado := procesar(trabajo)
    fmt.Println("Procesado:", resultado)
}
fmt.Println("Cola cerrada: worker terminando limpio")

Errores comunes

Estas trampas aparecen una y otra vez en quienes llegan a Go desde otros lenguajes. Repásalas antes de escribir tu próximo bucle:

Error típicoSíntomaSolución idiomática
Poner paréntesis en if (...) Error de compilaciónEscribe la condición directa: if x > 0 {
Llave de apertura en línea aparteError de sintaxisLa llave va siempre en la misma línea del if/for/switch
Añadir break tras cada caseInnecesario (compila)Elimínalo: Go rompe solo; deja fallthrough solo si lo necesitas de verdad
Usar la variable del range creyendo que muta la colecciónDatos sin cambiar: v es una COPIAEscribe por índice: s[i] = nuevoValor
Declarar variable en init statement y usarla después"undefined: variable"Su ámbito muere con el if/switch; declara fuera si sobrevive
Bucle infinito sin salida definidaPrograma colgadoToda salida debe ser explícita: break, return o cierre de canal
range sobre map esperando orden estableOrden aleatorio en cada ejecuciónExtrae y ordena las claves con sort.Strings antes de iterar

El caso de la copia del range merece énfasis: for _, u := range usuarios { u.Activo = true } NO activa a nadie. Modifica siempre a través del índice: for i := range usuarios { usuarios[i].Activo = true }.

Ejercicios prácticos

  1. FizzBuzz Go: imprime del 1 al 50 usando UN solo for y un switch sin expresión. Múltiplos de 3 → "Fizz", de 5 → "Buzz", de ambos → "FizzBuzz".
  2. Tabla de multiplicar con range: dado un número, imprime su tabla del 1 al 12 iterando con range sobre un slice de enteros precreado.
  3. Clasificador de temperatura: escribe una función que reciba grados Celsius y devuelva una categoría ("congelación", "frío", "templado", "calor", "extremo") usando switch sin expresión, con init statement incluido.
  4. Búsqueda con etiqueta: crea una matriz 4×4 de números aleatorios y busca el mayor valor usando una etiqueta para cortar ambos bucles en cuanto encuentres uno superior a 90.
  5. Contador Unicode: dada una cadena con emojis y acentos (por ejemplo, "ñandú 🦤 café"), cuenta cuántos bytes ocupa y cuántos runess tiene, demostrando la diferencia entre len(s) y el range sobre strings. Explica los resultados en un comentario.
