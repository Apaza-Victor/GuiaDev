Condicionales: if, else if, else

El control de flujo decide qué instrucciones se ejecutan y cuáles no: es el paso de "receta lineal" a "programa que reacciona". Swift mantiene la forma clásica del if, pero con dos reglas estrictas que eliminan bugs históricos: las condiciones van sin paréntesis y las llaves son obligatorias siempre.

let temperatura = 31

if temperatura >= 30 {
    print("Día caluroso")
} else if temperatura >= 20 {
    print("Día templado")
} else {
    print("Día frío")
}

¿Por qué tantas llaves obligatorias?

En lenguajes donde las llaves son opcionales, añadir una línea "dentro" de un if sin llaves produce desastres famosos: el fallo goto fail de Apple (2014) fue exactamente eso, dos líneas ejecutándose cuando solo una debía. El compilador de Swift hace ese error imposible.

// ❌ Ni siquiera compila: faltan llaves
// if activo print("encendido")

// ✅ Siempre con bloque
if activo {
    print("encendido")
}

Solo Bool vale como condición

A diferencia de JavaScript o Python, un número o string no cuenta como condición: debe ser un Bool real. Esto mata la familia de errores de "¿0 es falso aquí?" y obliga a escribir intenciones explícitas:

let visitas = 0
// if visitas { }            ❌ error: 'Int' is not convertible to 'Bool'
if visitas == 0 { }          // ✅ la intención queda escrita

// Operadores lógicos: ! , && , ||
if temperatura >= 20 && temperatura <= 30 {
    print("Zona de confort")
}

Para elegir entre dos valores (no entre dos acciones) existe el operador ternario: let estado = visitas > 0 ? "con tráfico" : "vacío". Úsalo solo en asignaciones cortas; para lógica compleja, mejor un if completo.

Switch exhaustivo

El switch de Swift no se parece al de C: compara cualquier tipo (números, strings, tuplas, enums…), no necesita break porque cada caso termina solo y, sobre todo, debe ser exhaustivo: entre todos los casos debe cubrirse cada valor posible. Si no lo está, el programa ni compila.

let codigo = "ES"

switch codigo {
case "ES", "MX", "AR":       // varios valores por caso, separados por comas
    print("País hispanohablante")
case "DE":
    print("Alemania")
default:                     // obligatorio: cubre todo lo demás
    print("Otro país")
}

Sin caídas accidentales

En C, olvidar un break hacía que la ejecución "cayera" al siguiente caso. Swift elimina esa trampa: cada caso es independiente. Si de verdad quieres heredar el siguiente caso, debes pedirlo explícitamente con la palabra fallthrough, dejando rastro en el código:

let nivel = 1
var puntos = 0

switch nivel {
case 1:
    puntos += 100
    fallthrough          // continúa deliberadamente en el caso 2
case 2:
    puntos += 50
default:
    break                // 'default' vacío necesita break o algo ejecutable
}
print(puntos)   // 150

Cuando compares contra los casos de un enum, el compilador conoce todos los valores posibles: te avisará si falta alguno y hasta ofrecerá insertarlos. Por eso el switch brilla especialmente con enums.

Switch avanzado: rangos, tuplas y where

Aquí empieza la magia. Un caso de switch puede ser un patrón completo: rangos numéricos, tuplas con comodines, variables capturadas (value binding) y condiciones extra con where. Muchas cadenas larguísimas de if/else se convierten en una tabla de decisión legible:

let nota = 84

switch nota {
case 90...100:
    print("Excelente")
case 70..<90:
    print("Aprobado")
case let x where x < 70:
    print("Reprobado: \(x)")   // captura el valor y lo filtra
default:
    print("Fuera de rango")
}

Tuplas, value binding y where en un solo caso

Con tuplas comparas varias cosas a la vez usando _ para ignorar partes; case let x captura valores mientras decides (value binding) y where añade la condición final:

let punto = (x: 1, y: 1)

switch punto {
case (0, 0):
    print("Origen")
case (_, 0):
    print("Sobre el eje X")
case (let x, let y) where x == y:
    print("Diagonal positiva en (\(x), \(y))")
case let (x, y):
    print("Punto general (\(x), \(y))")   // captura sin condición
}

Bucles for-in y rangos

El for-in es el bucle por excelencia de Swift: recorre cualquier secuencia (rangos, arrays, strings, diccionarios) sin manejar contadores a mano, lo que elimina de raíz los clásicos errores de "me pasé uno" (off-by-one). Los rangos definen los límites:

for i in 1...5 {        // cerrado: 1, 2, 3, 4, 5 (incluye el 5)
    print(i)
}

for i in 0..<5 {        // medio abierto: 0, 1, 2, 3, 4 (ideal con count)
    print("vuelta \(i)")
}

for _ in 0..<3 {        // _ ignora el valor: solo repito 3 veces
    print("clap!")
}

for i in (1...5).reversed() {   // cuenta atrás: 5, 4, 3, 2, 1
    print(i)
}

stride: pasos personalizados

Cuando necesitas saltos distintos de 1 (pares, cuenta atrás de 10 en 10, decimales), stride genera la secuencia. La diferencia clave está en si el final queda incluido o no:

LlamadaGenera¿Incluye el final?
stride(from: 0, to: 10, by: 2)0, 2, 4, 6, 8No (to es exclusivo)
stride(from: 0, through: 10, by: 2)0, 2, 4, 6, 8, 10Sí (through incluye)
stride(from: 3, to: 0, by: -1)3, 2, 1No; con paso negativo cuenta hacia atrás
for minuto in stride(from: 10, to: 0, by: -2) {
    print("Despegue en \(minuto)…")
}   // decimales también: stride(from: 0.0, through: 1.0, by: 0.25)

while, repeat-while y saltos etiquetados

Cuando no sabes cuántas iteraciones necesitas (esperar un evento, validar entrada, simular), los bucles condicionales toman el relevo. while evalúa la condición antes de cada vuelta; repeat-while ejecuta primero y pregunta después, garantizando al menos una vuelta:

Bucle¿Cuándo evalúa?Ejecuciones mínimasCaso típico
while cond { }Antes de cada vueltaCeroPuede que no toque iterar ni una vez
repeat { } while condDespués de cada vueltaUnaMenús, pedir dato y validarlo
// while: puede no ejecutarse nunca
var dado = 0
while dado != 6 {
    dado = Int.random(in: 1...6)
}
print("¡Seis tras tirar!")

// repeat-while: mínimo una vuelta (menús interactivos)
var opcion: String
repeat {
    opcion = ["jugar", "salir"].randomElement()!
    print("Menú: \(opcion)")
} while opcion != "salir"

break y continue con etiquetas

continue salta a la siguiente vuelta y break abandona el bucle. En bucles anidados, ambos actúan sobre el bucle más interno; las etiquetas permiten nombrar un bucle exterior y saltarlo directamente:

tablas: for i in 1...10 {
    for j in 1...10 {
        if i * j > 40 {
            break tablas        // abandona AMBOS bucles a la vez
        }
        if j % 2 == 0 {
            continue tablas     // pasa a la siguiente vuelta del EXTERIOR
        }
        print("\(i) × \(j) = \(i * j)")
    }
}

Vigila las condiciones de salida: si nada dentro del bucle puede volver la condición falsa, tienes un bucle infinito y el programa se cuelga. Antes de escribir while true, asegúrate de que existe un break alcanzable.

Guard y salidas tempranas

Ya viste guard let desenvolviendo optionals; aquí interesa su papel como herramienta general de control de flujo. Un guard exige que su condición sea cierta para continuar, y su bloque else debe abandonar el ámbito (return, break, continue…). El resultado: las validaciones se concentran arriba y el código importante queda plano.

Criterioifguard
Camino principalDentro del bloque (más indentación)Fuera, tras el guard (sin anidar)
Obliga a salir si fallaNoSí, compilador lo verifica
Ideal paraRamas alternativas equivalentesValidaciones previas imprescindibles
let pedidos = [
    (cliente: "Ana", unidades: 3),
    (cliente: "", unidades: 0),      // fila inválida
    (cliente: "Luis", unidades: 12)
]

for pedido in pedidos {
    guard !pedido.cliente.isEmpty, (1...10).contains(pedido.unidades) else {
        print("Descartado: \(pedido)")
        continue                     // guard también funciona en bucles
    }
    print("Procesando \(pedido.unidades) uds. para \(pedido.cliente)")
}

Lee guard como una afirmación: "garantizo que el cliente no esté vacío y las unidades sean válidas; de lo contrario, fuera". Ese estilo declarativo hace que las precondiciones de cada función se lean como una lista de requisitos.

Buenas prácticas de control de flujo

1. Prefiere switch sobre cadenas largas de else-if

// ❌ Difícil de leer y mantener
if codigo == 200 { ok() }
else if codigo == 301 || codigo == 308 { redirige() }
else if codigo >= 400 && codigo < 500 { errorCliente() }
else if codigo >= 500 { errorServidor() }

// ✅ Tabla de decisión clara
switch codigo {
case 200:              ok()
case 301, 308:         redirige()
case 400..<500:        errorCliente()
case 500...:           errorServidor()
default:               print("Código inusual: \(codigo)")
}

2. Sal pronto, anida poco

Si una función acumula tres niveles de indentación "porque sí", extrae validaciones con guard o divide en funciones pequeñas. Cada nivel de anidación multiplica los estados mentales que el lector debe sostener.

3. Comprueba la disponibilidad de APIs del sistema

Al tocar frameworks de Apple, tu código puede ejecutarse en versiones antiguas del sistema operativo. Los checks de disponibilidad evitan crashes y comunican el requisito mínimo:

if #available(iOS 17, *) {
    usarAPIsNuevas()          // camino moderno
} else {
    alternativaCompatible()   // soporte para versiones previas
}

4. Nombra las condiciones complejas

// ❌ ¿Qué significa esto dentro de seis meses?
if edad >= 13 && edad <= 17 && tutor || edad >= 18 { ... }

// ✅ Extrae la intención a constantes booleanas
let esAdolescenteConTutor = (13...17).contains(edad) && tieneTutor
let esAdulto = edad >= 18
if esAdolescenteConTutor || esAdulto { ... }

Un buen test mental: lee tus condiciones en voz alta. Si necesitas respirar a mitad de frase, divídelas. El control de flujo bien escrito se lee casi como español: "si hay stock y es cliente frecuente, aplica descuento".

Ejercicios prácticos

Del más sencillo al más retador:

  1. Clasificador de nota: pide un valor nota: Int y clasifícalo con un único switch usando rangos: sobresaliente (90+), notable (70–89), aprobado (50–69) y suspenso (<50); imprime también la nota capturada con value binding.
  2. FizzBuzz swiftiano: recorre 1...30 imprimiendo "Fizz" para múltiplos de 3, "Buzz" para múltiplos de 5, "FizzBuzz" para ambos (pista: un switch sobre la tupla (n % 3, n % 5) queda elegante).
  3. Cazador de productos: con bucles anidados sobre 1...9, encuentra el primer producto i * j mayor que 60 usando una etiqueta y break; imprime los factores hallados y cuántas vueltas diste (contador).
  4. Menú de cajero: simula un menú con repeat-while eligiendo opciones aleatorias de un array ["consultar", "retirar", "salir"]; valida con guard que el saldo simulado no baje de cero al retirar montos aleatorios, y termina solo con "salir".
  5. Depuradora de registros: dada una lista de tuplas (nombre: String, edad: Int?, email: String?), procesa cada registro con guard encadenado: descarta con mensaje específico los que fallen cada validación (nombre vacío, edad nil o menor de 14, email nil o sin "@") y devuelve el array de usuarios válidos formateados.
