UI declarativa frente a imperativa

Durante una década las apps de Apple se construían con UIKit: creabas cada botón, configurabas sus propiedades y lo añadías manualmente a la jerarquía. Ese estilo es imperativo: tú ordenas paso a paso cómo mutar la interfaz, y si el estado cambia, eres responsable de actualizarla otra vez. Con interfaces complejas, esa sincronización manual se convierte en la fuente nº 1 de bugs.

SwiftUI (2019) invierte el modelo con un enfoque declarativo: describes QUÉ debe verse para un estado dado, y el framework calcula y redibuja lo necesario cuando ese estado cambia.

El protocolo View

Toda pieza de interfaz es un tipo que conforma el protocolo View, cuyo único requisito es la propiedad computada body. La anotación some View usa tipos opacos: "devuelvo alguna vista, ya sabré yo cuál exacta" — así el compilador optimiza y tú te ahorras tipos kilométricos:

import SwiftUI

struct Saludo: View {
    var body: some View {
        Text("Hola, GuiaDev!")
            .font(.largeTitle)
            .bold()
    }
}

body es una propiedad computada: cada renderizado la reevalúa. Por eso SwiftUI prohíbe trabajo pesado dentro de ella; construye datos antes, dibuja después.

Composición: stacks y spacers

SwiftUI no tiene layouts absolutos que mantener: apilas contenedores y el sistema resuelve posiciones y tamaños. Los tres contenedores básicos cubren prácticamente cualquier disposición:

ContenedorApila hacia…Ejemplo de uso
VStackVerticalmenteListas verticales, formularios, columnas
HStackHorizontalmenteFilas: icono + texto, barras de botones
ZStackEn profundidad (superpuesto)Fondos con contenido encima, insignias
struct Tarjeta: View {
    let titulo: String

    var body: some View {
        HStack(spacing: 12) {
            Image(systemName: "star.fill")   // iconos SF Symbols integrados
                .foregroundStyle(.yellow)
            Text(titulo)
            Spacer()                          // empuja lo demás al borde final
            Text("4.8").font(.caption)
        }
        .padding()
        .background(Color.yellow.opacity(0.2))
        .cornerRadius(12)
    }
}

La composición escala indefinidamente: los stacks se anidan entre sí (un ZStack { Color…; VStack { … } } crea fondo + contenido) y cada bloque con nombre se convierte en una vista reutilizable.

Spacer() es tu mejor amigo: absorbe el espacio sobrante y empuja los elementos vecinos a los extremos. Sin él, los stacks centran todo por defecto.

Modificadores encadenados

Los modificadores (.padding(), .font(…), .foregroundStyle(…)) transforman una vista y devuelven otra vista nueva envuelta con esa característica. Por eso se encadenan en cascada… y por eso el orden importa: cada eslabón envuelve al anterior:

Text("Orden A")
    .padding()                    // primero margen interior…
    .background(Color.orange)     // …y el color cubre TAMBIÉN el padding

Text("Orden B")
    .background(Color.orange)     // el color abraza solo el texto…
    .padding()                    // …y el margen queda FUERA del naranja

Ambos textos comparten propiedades idénticas salvo el orden, y sin embargo se ven distintos: en A el naranja incluye la zona de aire; en B solo rodea las letras. Regla práctica: lee los modificadores de arriba abajo pensando en capas que se van aplicando de dentro hacia fuera.

Los más usados a diario

.background / .foregroundStyleColor de fondo / de contenido
.clipShape(Circle())Recorta la forma (avatares)

Encadenar veinte modificadores seguidos vuelve el cuerpo ilegible. Si una cadena crece, extrae la vista a un tipo propio o usa variables intermedias con nombre descriptivo.

Vistas básicas: texto, imágenes y formularios

El kit inicial de piezas cubre la mayoría de pantallas cotidianas. Text muestra texto estilizable, Image(systemName:) accede a miles de símbolos vectoriales (SF Symbols), y los controles de entrada trabajan en pareja con bindings que verás enseguida:

struct FichaProducto: View {
    let nombre = "Café de altura"

    var body: some View {
        VStack(alignment: .leading, spacing: 10) {
            Text(nombre).font(.headline)
            Image(systemName: "cup.and.saucer.fill")   // SF Symbols
                .foregroundStyle(.brown)
            Label("Stock disponible", systemImage: "checkmark.circle")
                .foregroundStyle(.green)
        }
        .padding()
    }
}

Formularios con Form

Form agrupa controles con el aspecto nativo de ajustes del sistema: filas separadas, scroll automático y estética coherente gratis:

struct RegistroRapido: View {
    @State private var usuario = ""
    @State private var notificaciones = true

    var body: some View {
        Form {
            Section("Datos") {
                TextField("Tu usuario", text: $usuario)   // $: binding bidireccional
            }
            Section("Preferencias") {
                Toggle("Recibir avisos", isOn: $notificaciones)
                Button("Crear cuenta") { print("Creando \(usuario)…") }
            }
        }
    }
}

Descarga la app gratuita SF Symbols desde developer.apple.com: busca iconos por nombre ("bell", "cart", "heart") y usa exactamente ese identificador en Image(systemName:).

Estado: @State y el flujo de datos

Aquí late el corazón declarativo. Una vista decorada con @State declara: "este dato me pertenece y cuando cambie, redibújame". Tú nunca tocas etiquetas ni recargadas manuales: mutas el estado y SwiftUI recalcula el body:

struct ContadorVista: View {
    @State private var contador = 0          // fuente de verdad LOCAL

    var body: some View {
        VStack(spacing: 16) {
            Text("Pulsaciones: \(contador)")
                .font(.largeTitle.monospacedDigit())

            HStack {
                Button("−") { contador -= 1 }
                    .buttonStyle(.bordered)
                Button("+") { contador += 1 }
                    .buttonStyle(.borderedProminent)
            }
        }
        .padding()
    }
}

El ciclo completo es un círculo virtuoso: el usuario pulsa, el botón muta @State, SwiftUI detecta el cambio, reevalúa body y la pantalla se actualiza. Unidireccional y predecible:

   ┌──────────────┐   interacción    ┌──────────────┐
   │   PANTALLA   │ ───────────────► │  @State      │
   │              │                  │ (contador=3) │
   │              │ ◄─────────────── │              │
   └──────────────┘  reevalúa body  └──────────────┘

Bindings con $

Los controles de entrada necesitan escribir Y leer el valor: eso es un binding bidireccional. El prefijo $ entrega una referencia editable del estado, como viste en TextField("...", text: $usuario): tecleas y la variable se actualiza sola.

La convención oficial es declarar el estado @State private: pertenece a esta vista y nadie externo debería manipularlo. Cuando varios tipos necesiten compartirlo existen @ObservedObject y @Observable, materia avanzada para más adelante.

Previews y estructura de una app

El superpoder diario de SwiftUI son las previews: el lienzo de Xcode renderiza tu vista real sin compilar toda la app, y refleja cada guardado al instante. Con la macro #Preview basta una línea; puedes declarar varias para comparar estados:

#Preview("Normal") {
    ContadorVista()
}

#Preview("Oscuro y grande") {
    ContadorVista()
        .preferredColorScheme(.dark)
        .environment(\.dynamicTypeSize, .accessibility2)
}

El punto de entrada: App y WindowGroup

Toda app arranca en un tipo marcado con @main que conforma App. Su body devuelve una escena; WindowGroup crea la ventana principal y coloca dentro tu vista raíz. Ese es el flujo mínimo completo de una aplicación moderna:

@main
struct GuiaDevApp: App {
    var body: some Scene {
        WindowGroup {
            ContadorVista()      // primera pantalla de la app
        }
    }
}
// Al lanzar: App → WindowGroup → ContadorVista → body → pantalla viva

Fíjate en la simetría: la lección de structs te enseñó que las vistas deben ser value types baratos de copiar; SwiftUI explota esa idea al máximo —cada renderizado reconstruye tu jerarquía de structs y compara qué cambió—. Todo lo aprendido hasta aquí encaja en un solo sistema.

Buenas prácticas en SwiftUI

1. Divide y vencerás: subvistas pequeñas

// ❌ Un body gigante con 15 niveles de indentación
// ✅ Extrae bloques coherentes a tipos propios
struct ListaTareas: View {
    var body: some View {
        List(tareas) { tarea in
            FilaDeTarea(tarea: tarea)     // subvista con nombre
        }
    }
}

2. Deja que el layout fluya

Evita .frame(width: 373) mágicos: usa Spacer, maxWidth: .infinity, padding y stacks. Las medidas fijas rompen en otros tamaños de pantalla o con letras grandes de accesibilidad.

3. El estado vive donde se necesita

Declara @State en la vista más pequeña posible que lo use; pasa datos hacia abajo como constantes (let titulo). Si dos pantallas distantes necesitan el mismo dato, la solución es subir el estado o usar observables, no duplicarlo.

4. Reutiliza componentes del sistema

List, Form, NavigationStack y TabView traen comportamiento nativo (scroll, selección, navegación) gratis. Construirlo a mano suele ser más código y peor resultado.

Hábito de aprendizaje acelerado: mantén siempre un preview abierto mientras estudias. Cambiar un modificador y ver el efecto al instante fija conceptos mucho mejor que leerlos.

Ejercicios prácticos

Constrúyelos en Xcode con previews activos, en orden creciente:

  1. Tarjeta de perfil: crea una vista con imagen de sistema circular, nombre en .title2, ciudad en gris y un botón "Seguir"; compón todo con un VStack y un Spacer que centre verticalmente el conjunto.
  2. Laboratorio de modificadores: replica los ejemplos "Orden A" y "Orden B" de esta lección, añade un tercer caso con .padding().background().cornerRadius(12).shadow(radius: 4) y comenta en el código qué capa produce cada modificador.
  3. Formulario de registro: con Form, monta campos de nombre y correo (TextField), un Toggle de términos aceptados y un Button que imprima los valores; valida con un if en body que el botón se deshabilite si falta el "@".
  4. Contador con límites: extiende el contador de la lección: botones +/− que se deshabiliten al llegar a 0 o 20 (modificador .disabled(contador >= 20)), un indicador de barra hecha con ZStack y colores que cambien según el nivel.
  5. Mini lista de tareas: declara @State private var tareas: [String] y un campo de texto; al pulsar "Añadir", inserta la tarea y limpia el campo; muestra las tareas con List + ForEach y permite borrar tocando cada fila. Añade un contador de pendientes en la cabecera usando Label.
