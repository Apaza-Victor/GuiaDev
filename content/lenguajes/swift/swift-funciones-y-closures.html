Funciones y etiquetas de argumento

Una función empaqueta un bloque de lógica bajo un nombre para reutilizarlo sin duplicar. Pero en Swift van más lejos: están diseñadas para que la llamada se lea como una frase. El secreto son las etiquetas de argumento: cada parámetro puede tener un nombre externo (en la llamada) distinto del interno (dentro del cuerpo).

func saludar(a nombre: String, veces: Int = 1) -> String {
    String(repeating: "Hola \(nombre)! ", count: veces)
}

// La llamada se lee: "saludar A Ana, VECES 2"
let saludo = saludar(a: "Ana", veces: 2)
print(saludo)   // Hola Ana! Hola Ana!

El objetivo es que quien lee el código de uso entienda el papel de cada valor sin abrir la definición. Compara move(3.0, 4.0) con move(fromX: 3.0, toY: 4.0): solo una de las dos se explica sola.

Omitir etiquetas con _

Cuando la etiqueta no aporta nada (el nombre del método ya lo dice todo), se suprime con guion bajo. Es habitual en operadores matemáticos o APIs que imitan funciones globales:

func dividir(_ a: Double, _ b: Double) -> Double {
    a / b
}

// "dividir 10 entre 4": la frase ya fluye sin etiquetas
print(dividir(10, 4))   // 2.5
DeclaraciónLlamada resultanteCuándo usarlo
func mover(de: String, hacia: String)mover(de: "A", hacia: "B")La relación entre argumentos importa
func sumar(_ x: Int, _ y: Int)sumar(2, 3)Etiquetas sobran; lectura matemática
func buscar(texto t: String)buscar(texto: "swift")Nombre externo e interno distintos

Los nombres de función también admiten caracteres Unicode y hasta emojis, pero la convención profesional es camelCase descriptivo en inglés o español consistente… con moderación creativa.

Parámetros avanzados y retornos múltiples

Valores por defecto

Un parámetro con valor por defecto vuelve opcional en la llamada: la API se simplifica sin perder flexibilidad. Por convención se colocan al final:

func conectar(host: String, puerto: Int = 443, seguro: Bool = true) {
    print("\(host):\(puerto) (\(seguro ? "TLS" : "plain"))")
}

conectar(host: "api.guia.dev")                 // usa los dos defectos
conectar(host: "localhost", puerto: 8080)      // solo uno personalizado

Parámetros variádicos

Con tres puntos, un parámetro acepta cualquier número de valores y dentro de la función llega como array:

func promedio(_ notas: Double...) -> Double {
    guard !notas.isEmpty else { return 0 }
    return notas.reduce(0, +) / Double(notas.count)
}

promedio(8, 9, 10)          // 9.0
promedio(7.5)               // 7.5

inout: modificar el original

Los parámetros son constantes por defecto y los valores se copian. Si una función necesita cambiar el valor recibido (patrón clásico: intercambiar dos variables), declara el parámetro inout y pasa la variable con &, dejando visible en la llamada que algo puede mutar:

func intercambiar(_ a: inout Int, _ b: inout Int) {
    let temporal = a
    a = b
    b = temporal
}

var x = 1, y = 2
intercambiar(&x, &y)
print(x, y)   // 2 1

Varios valores de retorno con tuplas

Sin crear tipos nuevos, una tupla nombrada devuelve resultados compuestos. Si puede fallar, convierte toda la tupla en opcional:

func dividir(_ a: Double, _ b: Double) -> (cociente: Double, resto: Double)? {
    guard b != 0 else { return nil }
    return (a / b, a.truncatingRemainder(dividingBy: b))
}

if let r = dividir(17, 5) {
    print(r.cociente, r.resto)   // 3.4 2.0
}

Funciones como ciudadanos de primera clase

En Swift una función es un valor más: tiene un tipo ((Int, Int) -> Int), se guarda en constantes, se pasa como argumento y se devuelve desde otras funciones. Esto habilita la programación funcional y es la base conceptual de los closures.

func sumar(_ a: Int, _ b: Int) -> Int { a + b }
func multiplicar(_ a: Int, _ b: Int) -> Int { a * b }

// El tipo de ambas es (Int, Int) -> Int: cabe en una constante
let operacion: (Int, Int) -> Int = sumar
print(operacion(3, 4))    // 7

// Pasar funciones como argumentos
func aplicar(_ op: (Int, Int) -> Int, _ a: Int, _ b: Int) -> Int {
    op(a, b)
}
aplicar(multiplicar, 3, 4)   // 12

// Devolver funciones: fábrica de operaciones
func elegirOperador(_ simbolo: String) -> (Int, Int) -> Int {
    simbolo == "+" ? sumar : multiplicar
}
elegirOperador("+")(10, 5)   // 15

Piensa en las funciones como datos cuando necesites decidir comportamiento en tiempo de ejecución: estrategias de ordenación, validadores configurables o handlers de eventos son candidatos perfectos.

Closures: funciones sin nombre

Un closure es un bloque de código ejecutable que puede capturar valores de su entorno. Su sintaxis usa llaves y la palabra in para separar parámetros y tipo del cuerpo. Lo mejor: el compilador va eliminando ceremonia cuando la infiere, así que una misma operación admite cuatro niveles de verbosidad:

let nombres = ["Carlos", "ana", "Bea"]

// 1. Completo: tipos explícitos, return obligatorio
let v1 = nombres.sorted(by: { (a: String, b: String) -> Bool in
    return a.lowercased() < b.lowercased()
})

// 2. Tipos inferidos por el contexto (sorted sabe que compara Strings)
let v2 = nombres.sorted(by: { a, b in a.lowercased() < b.lowercased() })

// 3. Return implícito si el cuerpo es una única expresión
let v3 = nombres.sorted { a, b in a.lowercased() < b.lowercased() }

// 4. Argumentos abreviados $0, $1…
let v4 = nombres.sorted { $0.lowercased() < $1.lowercased() }
// Todas producen: ["ana", "Bea", "Carlos"]

Los argumentos abreviados $0, $1, $2 referencian los parámetros por posición. Convierten en instantáneas las transformaciones típicas de colecciones:

let nums = [3, 1, 4, 1, 5]

nums.sorted { $0 > $1 }        // descendente: [5, 4, 3, 1, 1]
nums.filter { $0 % 2 == 0 }    // pares: [4]
nums.map { $0 * 2 }            // dobles: [6, 2, 8, 2, 10]

Closures como valores independientes

// Almacenado con su tipo declarado
let alCuadrado: (Int) -> Int = { $0 * $0 }
alCuadrado(4)                  // 16

// () -> Void: sin parámetros ni retorno, típico de botones y callbacks
let celebrar: () -> Void = { print("¡Golazo!") }

Regla de legibilidad: usa $0/$1 cuando el closure sea corto y obvio. Si necesita más de dos o tres líneas, nombra los parámetros ({ pedido in … }) o extrae una función con nombre.

Trailing closures

Cuando el último argumento de una llamada es un closure, Swift permite sacarlo fuera de los paréntesis. El resultado parece una construcción del propio lenguaje, y es la razón estética detrás de APIs como SwiftUI o las animaciones de UIKit:

// Forma estándar
let animar = UIView.animate(withDuration: 0.3, animations: {
    vista.alpha = 0
})

// Trailing closure: mismo resultado, más limpio
UIView.animate(withDuration: 0.3) {
    vista.alpha = 0
}

// El patrón que verás por todas partes en SwiftUI
Button("Guardar") {
    guardarDocumento()
}

Múltiples trailing closures (Swift 5.3+)

Si la función recibe varios closures, el primero queda sin etiqueta y los siguientes conservan la suya. Así nacen llamadas que casi se leen como frases:

func descargar(imagen url: String,
               alProgresar: (Double) -> Void,
               alTerminar: (Data?) -> Void) {
    alProgresar(0.5)
    alTerminar(Data())
}

descargar(imagen: "logo.png") { progreso in
    print("Barra: \(Int(progreso * 100))%")
} alTerminar: { datos in
    print("Listo: \(datos?.count ?? 0) bytes")
}

Si diseñas tus propias APIs, pon siempre los closures al final de la lista de parámetros: habilitas trailing closures y tu API se sentirá nativa del lenguaje en lugar de importada.

Escaping, captura de valores y listas de captura

@escaping: ¿el closure vive más allá de la llamada?

Por defecto, un closure pasado a una función es non-escaping: se ejecuta antes de que la función termine y luego desaparece. Si lo almacenas o lo lanzas en una cola asíncrona (seguirá vivo después del retorno), debes marcarlo @escaping:

CaracterísticaNon-escaping (por defecto)@escaping
Duración de vidaMuere al terminar la funciónPuede sobrevivir a la llamada
Usos típicosmap, filter, sortedCallbacks asíncronos, handlers guardados
Riesgo de ciclos de memoriaNoSí, si captura objetos fuertemente
Optimización del compiladorMáxima (conoce su destino)Limitada
var manejadores: [() -> Void] = []

func registrar(alPulsar accion: @escaping () -> Void) {
    manejadores.append(accion)   // se guarda: necesita @escaping
}

registrar { print("Botón pulsado") }
manejadores.forEach { $0() }     // se dispara después, ya fuera de registrar

Captura: los closures recuerdan su entorno

A diferencia de muchas funciones anónimas de otros lenguajes, los closures de Swift capturan las variables por referencia: pueden leerlas y modificarlas entre llamadas. Eso permite patrones como contadores persistentes:

func crearContador() -> () -> Int {
    var total = 0                    // capturado por referencia
    return {
        total += 1                   // sigue vivo tras retornar crearContador
        return total
    }
}

let contadorA = crearContador()
contadorA(); contadorA()
print(contadorA())                   // 3: 'total' sobrevivió a la función

let contadorB = crearContador()
print(contadorB())                   // 1: cada closure captura SU propia copia

Listas de captura: congelar valores

Cuando quieres una fotografía del valor en el momento de crear el closure (no un enlace vivo), lo declaras en la lista de captura inicial:

var mensaje = "antes"
let imprimir = { [mensaje] in print(mensaje) }

mensaje = "después"
imprimir()        // "antes" ← capturó la copia del momento
// [weak self] hará el mismo papel con clases para evitar fugas de memoria

Buenas prácticas con funciones y closures

1. Diseña llamadas legibles

// ❌ ¿Qué es true? ¿Qué es 30?
enviar(true, false, 30)

// ✅ Etiquetas y tipos con sentido
enviar(notificaciones: true, sonido: false, volumen: 30)

2. Closures cortos, lógica compleja con nombre

// ❌ Difícil de depurar y probar
let validos = usuarios.filter { $0.edad >= 18 && $0.email.contains("@") && !$0.baneado }

// ✅ Extrae predicados con nombre: autodocumentados y reutilizables
func esClienteActivo(_ u: Usuario) -> Bool {
    u.edad >= 18 && u.email.contains("@") && !u.baneado
}
let activos = usuarios.filter(esClienteActivo)

3. Deja que el compilador trabaje

No declares tipos en closures salvo ambigüedad real; usa $0 en transformaciones de una línea y parámetros nombrados en las largas. Y recuerda: @escaping solo cuando el closure sobreviva a la función, porque cada escape innecesario abre la puerta a retenciones accidentales de memoria.

Señal de que dominas esta lección: cuando lees peliculas.filter { $0.año >= 2000 }.map(\.titulo).sorted(), la interpretas como una frase —"títulos de películas del siglo XXI, ordenados"— y no como símbolos raros. Esa fluidez se construye practicando los ejercicios de abajo.

Ejercicios prácticos

De menor a mayor dificultad:

  1. Saludador configurable: crea saludo(nombre:veces:mayusculas:) con valores por defecto (veces = 1, mayusculas = false) que devuelva el saludo repetido; llama a la función usando etiquetas de forma que la línea se lea como una frase.
  2. Estadísticas variádicas: escribe resumir(_ numeros: Double...) -> (media: Double, maximo: Double, minimo: Double)? que devuelva nil si no hay datos, y pruébala desempaquetando con if let.
  3. Pipeline de calificaciones: dada una lista de notas, obtén en una sola expresión encadenada las aprobadas (>= 5), elevadas a cuadrado y ordenadas descendentemente, usando closures abreviados $0.
  4. Acumuladores independientes: implementa crearSumador(base: Int) -> (Int) -> Int cuyo closure capture el total; demuestra con dos instancias que sus estados no se mezclan y añade una lista de captura para verificar la diferencia entre captura por referencia y copia congelada.
  5. Mini event bus: diseña struct Bus con suscribir(evento: String, handler: @escaping (String) -> Void) y publicar(evento: String); registra varios manejadores con múltiples trailing closures o closures cortos, publica dos eventos y comprueba que solo llegan a sus suscriptores correctos.
