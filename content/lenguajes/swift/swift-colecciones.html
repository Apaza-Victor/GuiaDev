Las tres colecciones

Casi todo programa vive de agrupar datos: una lista de tareas, un inventario sin repetidos, un catálogo que mapea códigos a productos. Swift ofrece tres herramientas nativas para cada necesidad: Array (lista ordenada), Set (elementos únicos sin orden garantizado) y Dictionary (pares clave-valor). Elegir la correcta no es estética: define qué operaciones serán naturales y cuáles costosas.

var lista = ["café", "té"]              // Array<String>
var conjunto: Set<String> = ["café", "té"]   // Set<String>
var inventario = ["café": 12, "té": 30] // Dictionary<String, Int>

// La mutabilidad NO depende del tipo, sino de let/var
let fija = [1, 2, 3]
// fija.append(4)   ❌ error: 'fija' es inmutable
var mutable = [1, 2, 3]
mutable.append(4)      // ✅ [1, 2, 3, 4]

Operaciones básicas de cada colección

// ARRAY: el índice empieza en 0 y el orden se conserva
var lista = [10, 20, 30]
lista.append(40)            // añade al final
lista.insert(5, at: 0)      // inserta en posición concreta
lista[1] = 15               // el subscript también escribe
lista.remove(at: 0)         // elimina por índice y lo devuelve
lista.removeLast()          // elimina y devuelve el último

// SET: los duplicados desaparecen solos
var etiquetas: Set = ["swift", "ios"]
etiquetas.insert("swift")   // ya estaba: la colección sigue igual
print(etiquetas.count)      // 2

// DICTIONARY: escribir crea o actualiza; leer SIEMPRE da opcional
var edades = ["ana": 30]
edades["luis"] = 25         // agrega nueva clave
edades["ana"] = 31          // actualiza la existente
let edadAna = edades["ana"]     // Int? — podría no existir
let segura = edades["ana"] ?? 0 // Int garantizado con respaldo

A diferencia de otros lenguajes, no hay clases separadas tipo NSMutableArray: la mutabilidad la decide let/var. Menos tipos que memorizar y más seguridad en tiempo de compilación.

---

Semántica de valor

Arrays, Sets y Dictionarys son tipos por valor: al asignarlos o pasarlos a una función se copian. Dos variables nunca comparten silenciosamente la misma colección, así que modificar una no sorprende a nadie más:

var originales = [1, 2, 3]
var copia = originales       // copia independiente

copia.append(99)
print(originales.count)      // 3  ← intacta
print(copia.count)           // 4

// Igual ocurre dentro de funciones: recibes tu propia copia
func vaciar(_ numeros: [Int]) {
    var numeros = numeros
    numeros.removeAll()
}
vaciar(originales)
print(originales)            // [1, 2, 3] — la función no pudo tocarla

Esta decisión de diseño tiene dos consecuencias enormes. Primera: razonas sobre el código localmente, sin temer efectos secundarios desde otras partes del programa. Segunda: el código es naturalmente seguro en contextos concurrentes, porque nadie puede mutar "el mismo" array desde dos hilos.

"¿Copiar no es caro?" En la práctica no: la librería estándar usa copy-on-write; la copia real solo ocurre si alguien modifica. Obtienes la seguridad de los valores con el costo de las referencias.

Índices y rangos seguros

El subscript lista[i] es cómodo pero implacable: un índice fuera de rango detiene el programa al instante. Swift prefiere ese fallo honesto antes que devolver basura en silencio, aunque casi nunca necesitas arriesgarte: existen alternativas seguras para cada caso.

let dias = ["lun", "mar", "mié", "jue", "vie"]

dias[2]                 // "mié" ✅
// dias[10]             // 💥 Fatal error: Index out of range

// Acceso seguro: first y last son optionals
if let primero = dias.first { print(primero) }
let ultimo = dias.last ?? "(sin días)"

// Recorrer SIN manejar índices manualmente (la vía idiomática)
for dia in dias { print(dia) }

// ¿Necesitas el índice? enumerated() entrega pares
for (posicion, dia) in dias.enumerated() {
    print("\(posicion + 1). \(dia)")
}

Rangos para recortar colecciones

OperadorNombreIncluye el final
a...bRango cerradoSí (a, a+1, …, b)
a..<bRango medio abiertoNo (útil con índices y count)
...b / ..<bRango parcialDesde el inicio hasta b
a...Rango parcialDesde a hasta el final
let semana = ["lun", "mar", "mié", "jue", "vie", "sáb", "dom"]
let laborales = semana[0..<5]        // ArraySlice: vista, no copia
let finDeSemana = Array(semana[5...]) // convierte a Array normal

semana.prefix(3)      // primeros tres
semana.suffix(2)      // últimos dos
semana.dropFirst()    // todos menos el primero

dropFirst, prefix y el subscript con rangos devuelven un ArraySlice, una vista eficiente que conserva los índices originales: tras dropFirst(), su primer elemento está en el índice 1, ¡no en el 0! Si vas a indexarlo después, envuélvelo en Array(...).

Ordenamiento y búsqueda

Buscar y ordenar son operaciones diarias, y la librería estándar trae versiones listas para usar. El matiz importante: existe una versión que devuelve una colección nueva (sorted()) y otra que muta en el sitio (sort()). Con tus reglas de let/var ya sabes cuándo compila cada una:

let puntajes = [72, 95, 88, 60]

puntajes.sorted()                  // [60, 72, 88, 95] ascendente
puntajes.sorted(by: >)             // [95, 88, 72, 60] descendente
puntajes.reversed()                // invierte el orden (vista perezosa)

// sort() muta en sitio: exige var
var pendientes = ["b", "a", "c"]
pendientes.sort()

// min/max también devuelven optionals: ¿y si está vacía?
let mejor = puntajes.max() ?? 0

Búsqueda: contains y firstIndex

firstIndex(of:) devuelve un Int? porque el elemento puede no estar; conecta directamente con lo aprendido sobre optionals:

let nombres = ["Ana", "Luis", "Marta"]

nombres.contains("Luis")               // true
nombres.contains { $0.hasPrefix("M") } // true, con condición personalizada

if let i = nombres.firstIndex(of: "Luis") {
    print("Luis está en la posición \(i)")   // 1
}
let indice = nombres.firstIndex(of: "Zoe") ?? -1  // -1 como "no encontrado"

Transformaciones: map, filter, reduce…

Aquí brilla el lado funcional de Swift. Las funciones de orden superior describen qué transformación quieres, no cómo construirla bucle a bucle: menos variables auxiliares, menos índices que equivocar, intenciones explícitas.

let nums = [1, 2, 3, 4, 5]

nums.map { $0 * $0 }          // [1, 4, 9, 16, 25]  transforma cada uno
nums.filter { $0 % 2 == 0 }   // [2, 4]             conserva los que cumplen
nums.reduce(0, +)             // 15                 acumula en un único valor

// compactMap: transforma Y descarta los nil resultantes
let textos = ["1", "hola", "3"]
let numeros = textos.compactMap { Int($0) }   // [1, 3]

// flatMap: aplana colecciones anidadas
let grupos = [[1, 2], [3], [4, 5]]
grupos.flatMap { $0 }         // [1, 2, 3, 4, 5]

Encadenar transformaciones: el pipeline

Cada función recibe y devuelve colecciones, así que se encadenan como una línea de producción legible de izquierda a derecha:

struct Producto {
    let nombre: String
    let precio: Double
}

let catalogo = [
    Producto(nombre: "Teclado", precio: 45),
    Producto(nombre: "Cable", precio: 8),
    Producto(nombre: "Monitor", precio: 180)
]

let baratosOrdenados = catalogo
    .filter { $0.precio < 50 }            // descarta los caros
    .sorted { $0.precio < $1.precio }     // ordena por precio
    .map { "\($0.nombre): \($0.precio)€" } // convierte a texto
// ["Cable: 8.0€", "Teclado: 45.0€"]

zip: recorrer dos colecciones en paralelo

let nombres = ["Ana", "Luis"]
let notas = [9.5, 7.0]

for (nombre, nota) in zip(nombres, notas) {
    print("\(nombre): \(nota)")
}
// zip corta con la más corta: sobrantes se ignoran

Para acumular en una colección dentro de reduce, usa la variante reduce(into:): evita copiar el acumulador en cada paso y es la forma recomendada de construir diccionarios (por ejemplo, contadores de frecuencias).

Rendimiento y complejidad

No todas las operaciones cuestan lo mismo en cada colección. La notación O grande resume cómo crece el costo cuando crecen los datos, y explica por qué elegir bien la estructura importa más que cualquier microoptimización posterior:

OperaciónArraySetDictionary
Acceso por índice/claveO(1)—O(1) promedio
Añadir al final / insertarO(1)* amortizado / O(n) al inicioO(1) promedioO(1) promedio
Búsqueda (contains)O(n)O(1) promedioO(1) promedio por clave
Eliminar por índice/claveO(n)O(1) promedioO(1) promedio

La lección práctica

Con mil elementos casi todo vuela; con millones, la diferencia entre array.contains(x) en un bucle (O(n·m)) y una consulta a un Set previamente creado con Set(bloqueados) (O(1) por consulta) son segundos frente a milisegundos. Regla rápida: muchas preguntas "¿está aquí X?" → Set; localizar por identificador → Dictionary; orden y posiciones → Array.

Errores comunes con colecciones

1. Índices fuera de rango

let fila: [String] = []
// print(fila[0])                    // 💥 crash: colección vacía
if let primera = fila.first { print(primera) }   // ✅ seguro

2. Mutar mientras se itera

var nums = [1, 2, 3, 4]
// for n in nums where n % 2 == 0 {
//     nums.removeAll { $0 == n }    // 💥 crash: mutación durante iteración
// }
nums.removeAll { $0 % 2 == 0 }       // ✅ método pensado para esto → [1, 3]

3. Olvidar que leer un Dictionary devuelve opcional

let stock = ["café": 12]
// let unidades = stock["té"] + 5    ❌ error: Int? + Int no compila
let unidades = (stock["té"] ?? 0) + 5   // ✅ decide qué pasa si falta

4. Suponer orden en Set y Dictionary

let letras: Set = ["c", "a", "b"]
// print(letras.first!)   ⚠️ "primero" según SU orden interno, no el de inserción
print(letras.sorted())   // ✅ ["a", "b", "c"]: tú decides el criterio

5. Indexar una rebanada como si fuera un Array nuevo

let todo = [10, 20, 30, 40]
let cola = todo.dropFirst()
// cola[0]        💥 crash: sus índices conservan los originales (empieza en 1)
print(cola[1])    // ✅ 20
print(Array(cola)[0])  // ✅ 10, tras convertir a Array propio

Antídoto universal: piensa en optionals cuando leas, en let/var cuando declares y en el tipo de colección cuando diseñes. Con esos tres reflejos, la mayoría de crashes con colecciones desaparecen antes de nacer.

Ejercicios prácticos

Progresa en orden; cada ejercicio reutiliza el anterior:

  1. Lista de compras: crea un array con cinco productos, imprime el segundo con acceso seguro (first/subscript comprobado), añade uno al principio con insert(_:at:) y muestra el total de caracteres de la lista con map + reduce.
  2. Amigos en común: dados dos arrays de nombres con repetidos, obtén con Set los amigos presentes en ambas listas y cuántos son, imprimiendo el resultado ordenado alfabéticamente.
  3. Notas aprobadas: con el diccionario ["ana": 9.5, "luis": 4.0, "marta": 6.75], genera un nuevo diccionario solo con aprobados usando filter + reduce(into:), y calcula su media.
  4. Analizador de texto: dada una frase, cuenta con un Dictionary cuántas veces aparece cada palabra (pista: split(separator: " ") y reduce(into:)) e imprime las tres palabras más frecuentes.
  5. Inventario inteligente: representa el almacén como [String: Int]; procesa una lista de pedidos retirando stock de forma segura (ignora productos inexistentes o sin unidades), reporta los pedidos rechazados y devuelve el inventario final ordenado por nombre.
