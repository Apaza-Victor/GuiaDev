¿Qué es un optional?

En 1965 Tony Hoare inventó la referencia nula y décadas después la llamó "mi error de mil millones de dólares": en la mayoría de lenguajes, cualquier variable puede ser null sin avisar, y el programa explota en tiempo de ejecución cuando alguien olvida comprobarlo. La respuesta de Swift es radical: la ausencia de valor deja de estar escondida y pasa a formar parte del sistema de tipos.

Un optional es un tipo que dice honestamente: "aquí puede haber un valor de tipo T… o puede que no haya nada". Y aquí está el detalle elegante: internamente no es magia, es un simple enum de la librería estándar:

// Esto es (aproximadamente) lo que escribe el compilador cuando ves T?
enum Optional<Wrapped> {
    case none            // no hay valor
    case some(Wrapped)   // hay un valor envuelto
}

let corto: String? = nil          // Optional.none
let largo: String? = "Toro"       // Optional.some("Toro")

print(largo)                      // Optional("Toro") ← sigue envuelto

La sintaxis String? es azúcar para Optional<String>. Por eso print muestra el valor envuelto: obtener el valor de verdad se llama desenvolver (unwrapping) y es justo el tema de esta lección.

Cómo leer los tipos opcionales

El sufijo ? se pega al tipo completo: Int? se lee "un Int o nada", [Double]? es "una lista de Double o nada", (Int, Int)? es "una tupla de dos Int o nada". En todos los casos equivale a Optional<…> del tipo interior.

nil en Swift no es un puntero nulo ni memoria basura: es simplemente el caso .none de un enum. Solo los optionals pueden valer nil; asignarlo a un Int normal ni siquiera compila.

---

Desenvoltura segura con if let

La forma básica y segura de desenvolver es if let: "si hay valor, créame una constante con él y entra al bloque". Dentro del if trabajas con un valor real, no opcional; fuera, el compilador te recuerda que sigues sin saberlo:

let edades = ["ana": 30, "luis": 25]
let edadAna: Int? = edades["ana"]     // las búsquedas devuelven optionals

if let edad = edadAna {
    print("Ana tiene \(edad) años")   // edad es Int, sin envolver
}
// print(edad)  ❌ error: 'edad' solo existe dentro del if

La forma corta (Swift 5.7+)

Cuando quieres mantener el mismo nombre, puedes omitir el = expresión: el compilador crea una constante sombra (shadowing) no opcional con ese nombre:

if let edadAna {                          // sombra NO opcional, mismo nombre
    print("Ana tiene \(edadAna) años")    // aquí edadAna es Int puro
}

Varias desenvolturas y condiciones combinadas

Puedes desenvolver varios valores en una sola línea separándolos con comas, e incluso añadir condiciones extra tras el where implícito:

if let edad = padron["ana"], edad >= 18 {   // desenvolver + condición extra
    print("Puede votar (\(edad) años)")
}

Nombra la constante desenvuelta según su contenido (edad, textoLimpio), no x ni valor. El código se lee mucho mejor cuando el nombre explica qué se desenvolvió.

---

guard let y salida temprana

guard let invierte la lógica: "si NO hay valor, sal de aquí; si lo hay, continúa". Su superpoder es que la constante desenvuelta queda disponible después del guard, hasta el final del ámbito, porque el flujo garantiza que solo se llega ahí si había valor:

func procesar(edad: Int?) {
    guard let edad, edad >= 18 else {
        print("Edad ausente o menor de edad")
        return               // guard EXIGE salir del scope aquí
    }
    // A partir de este punto 'edad' es Int normal
    print("Adulto de \(edad) años")
}

procesar(edad: 25)   // Adulto de 25 años
procesar(edad: nil)  // Edad ausente o menor de edad

¿Por qué guard prefiere la salida temprana?

Con if let anidados, el código importante se hunde cada vez más a la derecha (la temida pirámide de la perdición). Con guard, los casos inválidos se descartan arriba y el caso feliz queda plano:

// ✅ Guard plano: valida y abandona cuanto antes
func enviar(mensaje: String?) {
    guard let mensaje, !mensaje.isEmpty, mensaje.count <= 140 else {
        return   // aquí iría avisar al usuario; sin valor no hay nada que hacer
    }
    print("Enviando: \(mensaje)")   // código principal sin anidar
}

El bloque else del guard debe terminar forzosamente transfiriendo el control: return, break, continue, throw o una función que nunca retorna. Si no, el compilador lo rechaza. Esa exigencia es lo que hace fiable el patrón.

Regla práctica: usa if let cuando la ausencia del valor sea un camino alternativo legítimo, y guard let cuando sin el valor no tiene sentido continuar (validaciones al inicio de una función).

---

Nil coalescing: el operador ??

Muchas veces no necesitas dos caminos: necesitas "el valor, o este otro por defecto". Para eso existe el operador a ?? b: devuelve a si tiene valor, y b si a es nil. Es un if let comprimido en dos caracteres:

let nombreUsuario: String? = nil
let mostrado = nombreUsuario ?? "anónimo"   // "anónimo"

let configuracion = ["tema": "oscuro"]
let tema = configuracion["tema"] ?? "claro"      // "oscuro"
let idioma = configuracion["idioma"] ?? "es"     // "es" (clave ausente)

// Se pueden encadenar alternativas
let elegido = nombreUsuario ?? configuracion["usuario"] ?? "invitado"

Un detalle fino: la parte derecha se evalúa solo si hace falta (el operador recibe un autoclosure perezoso). Puedes poner ahí cálculos costosos o incluso efectos, sabiendo que solo ocurren ante un nil:

let cache: String? = nil
let dato = cache ?? cargarDeDisco()   // cargarDeDisco() solo si cache == nil

func cargarDeDisco() -> String { "leído del disco" }

Optional chaining: encadenar con ?.

Cuando accedes a propiedades o métodos de un valor que podría ser nil, el encadenamiento opcional con ? evita comprobar cada nivel: si cualquier eslabón es nil, toda la cadena devuelve nil sin ejecutarse (cortocircuito); si todos existen, obtienes el resultado… pero envuelto otra vez en un optional:

struct Direccion { var ciudad: String }
struct Persona {
    var nombre: String
    var direccion: Direccion?
}

let ana = Persona(nombre: "Ana", direccion: Direccion(ciudad: "Lima"))
let fantasma = Persona(nombre: "?", direccion: nil)

ana.direccion?.ciudad        // Optional("Lima")
fantasma.direccion?.ciudad   // nil (ni intenta acceder)

// Combinado con ?? recuperas un valor garantizado
let destino = ana.direccion?.ciudad ?? "Desconocida"   // "Lima"

También sirve para llamar métodos o asignar a través de la cadena: carrito?.agregar("té") solo ejecuta si el objeto existe; si es nil, toda la línea se salta sin error.

El resultado de una cadena ?. siempre es opcional, aunque la última propiedad no lo sea. Olvidarlo lleva a errores de tipos; acostúmbrate a cerrar la cadena con ?? valor o a desenvolverla con if let.

Fuerza bruta (!), IUO y pattern matching

Force unwrap: el operador !

Escribir opcional! dice "confía en mí, sé que hay valor". Si te equivocas, el programa muere al instante con un error en tiempo de ejecución. No hay segunda oportunidad ni recuperación:

let entrada: String? = nil
// print(entrada!)
// 💥 Fatal error: Unexpectedly found nil while unwrapping an Optional value

IUO: Implicitly Unwrapped Optionals (Tipo!)

Un optional implícitamente desenvuelto se declara con ! y funciona como optional, pero el compilador lo desenvuelve automáticamente en cada uso. Existe por dos razones históricas: la interoperabilidad con Objective-C y la inicialización en dos fases, donde una propiedad aún no tiene valor al terminar el init pero lo tendrá antes de usarse (el caso típico son los @IBOutlet conectados desde Interface Builder).

Pattern matching con case let

Como un optional es un enum, también puedes desenvolverlo con switch o if case, dejando visible su naturaleza de dos casos:

let apodo: String? = "Toro"

switch apodo {
case .some(let valor): print("Apodo: \(valor)")   // caso some(Wrapped)
case .none:            print("Sin apodo")         // caso nil
}

if case let valor? = apodo {          // azúcar idiomático para .some(let valor)
    print("Hay valor: \(valor)")
}

Todas las formas de desenvolver, de un vistazo

FormaEjemploCuándo usarla

guard letguard let x = op else { return }Cuando sin valor no se puede continuar; evita anidar

Un ! en producción es una bomba de tiempo: hoy la invarianta se cumple, mañana alguien cambia el orden de carga y la app crashea para usuarios reales. Cada vez que sientas la tentación de escribir !, pregúntate qué haría el programa si el valor faltara… y escríbelo tú mismo.

Errores comunes con optionals

1. Comprobar nil pero usar el optional directamente

let edad: Int? = 30
if edad != nil {
    // print(edad + 1)   ❌ error: 'edad' sigue siendo Int?
    print(edad! + 1)     // ⚠️ compila pero abusa del !
}
if let edad {           // ✅ dentro, 'edad' es Int
    print(edad + 1)
}

2. Silenciar con ?? "" o ?? 0 sin pensar

// ❌ Oculta el problema: ¿era legítimo que faltara el precio?
let precio = producto.precio ?? 0.0

// ✅ Decide conscientemente: valor por defecto razonable O manejo del fallo
guard let precio = producto.precio else {
    print("Producto sin precio: no facturable")
    return
}

3. Forzar optionales de búsquedas que legítimamente fallan

let usuarios = ["ana": 1]
// let ana = usuarios["ana"]!    // ok hoy…
// let pepe = usuarios["pepe"]!  // 💥 crash: la clave no existe
let pepe = usuarios["pepe"] ?? 0 // ✅ o if let para tratar la ausencia

Buen hábito definitivo: trata todo ! como deuda técnica y todo ?? defecto como una decisión de negocio que merece un segundo de reflexión. Los optionals no son un estorbo del compilador: son documentación ejecutable sobre dónde puede fallar tu lógica.

Ejercicios prácticos

Resuélvelos en orden en un Playground; cada uno apoya al siguiente:

  1. Detección de envoltorio: declara var ciudad: String? = "Lima", imprímela tal cual (observa Optional("Lima")), asígnale nil y vuelve a imprimirla. Explica en un comentario qué caso del enum representa cada impresión.
  2. Saludo tolerante: escribe una función saludar(_ nombre: String?) -> String que devuelva "Hola, \(nombre)" o "Hola, invitado" usando únicamente el operador ??.
  3. Validador con guard: crea func inscribir(edad: Int?, nombre: String?) que use un único guard let para validar ambos datos y rechace menores de 18 años; imprime la confirmación con los valores ya desenvueltos.
  4. Cadena de direcciones: define struct Empresa { var web: String? } y struct Cliente { var empresa: Empresa? }; dado un cliente cuya empresa es nil, obtén su web con optional chaining y un valor por defecto "sin sitio web", sin un solo if.
  5. Caza del crash: recibe el diccionario precios = ["café": 1.5, "té": 1.2] y una lista de pedidos ["café", "jugo", "té"]; calcula el total del pedido desenvolviendo cada búsqueda de forma segura (nada de !) e informa qué productos no estaban en catálogo. Reescríbelo después con case let en un switch.
