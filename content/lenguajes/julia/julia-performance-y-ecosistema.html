Compilación JIT y múltiple dispatch

Julia usa compilación just-in-time (JIT): cada función se compila a código máquina especializado para los tipos de los argumentos con los que la llamas por primera vez. Por eso Julia se siente como intérprete pero rinde como compilado.

# La primera llamada compila; verás el tiempo en la primera ejecución
function fib(n)
    n <= 2 ? 1 : fib(n-1) + fib(n-2)
end

for _ in 1:3
    t = @elapsed fib(30)
    println("fib(30) en ", round(t * 1000, digits=1), " ms")
end
# NOTA: tras la primera, el tiempo cae drásticamente

# Agregar método a una función (no "sobrecarga": es dispatch)
f(x::Float64) = "flotante: $x"
f(x::Int)     = "entero: $x"
f(x::String)  = "texto: $x"

println(f(1))      # entero
println(f(2.5))    # flotante
println(f("hola")) # texto

# El dispatch elige por TODOS los argumentos (multiple dispatch)
g(a::Int, b::Int)      = "int+int"
g(a::Int, b::Float64)  = "int+float"
g(a::Float64, b::Int)  = "float+int"
println(g(1, 2))       # int+int
println(g(1, 2.0))     # int+float

El "secreto" del rendimiento de Julia: denotar los tipos de los argumentos para que el compilador genere código especializado. Las funciones sin anotar caen al tipo base y pueden ir lentas en bucles calientes.

Múltiple dispatch en profundidad

El múltiple dispatch es el paradigma central de Julia: el método a ejecutar se decide en tiempo de ejecución según los tipos de todos los argumentos. Reemplaza por completo los patrones de "herencia" y "casting" típicos de otros lenguajes.

abstract type Figura end

struct Circulo <: Figura
    radio :: Float64
end

struct Rectangulo <: Figura
    ancho :: Float64
    alto  :: Float64
end

# Misma función "area", métodos por tipo
area(f::Circulo)     = π * f.radio^2
area(r::Rectangulo)  = r.ancho * r.alto

c = Circulo(2.0)
r = Rectangulo(3.0, 4.0)
println(area(c))   # 12.566...
println(area(r))   # 12.0

# Dispatch sobre tipos abstractos también funciona
function describe(f::Figura)
    "Figura con área $(area(f))"
end
println(describe(c))

# Subtipado de números y búsqueda
println(1.0 isa Real)   # true
println(1 isa Real)     # true
println("x" isa Real)   # false

Con el múltiple dispatch no necesitas interfaces explícitas: basta definir métodos con el mismo nombre para tipos distintos. Es la base de todo el ecosistema matriz/estadístico de Julia.

El registro de paquetes y Pkg

Pkg es el gestor de paquetes integrado de Julia. Instala, actualiza y "precompila" librerías con total reproducibilidad (los entornos pueden fijarse con manifiestos Project.toml/Manifest.toml).

using Pkg

# Comandos básicos
Pkg.add("DataFrames")          # instala una librería
Pkg.add(["Plots", "CSV"])      # varias a la vez
Pkg.rm("Plots")                # desinstala
Pkg.update()                   # actualiza todo del entorno activo
Pkg.status()                   # lista con versiones
Pkg.precompile()               # precompila (acelera el primer uso)
# Desde la terminal
julia -e 'using Pkg; Pkg.add("DataFrames")'
julia --project=. -e 'using Pkg; Pkg.instantiate()'   # instala Manifest

# Estado de salida de un proyecto reproducible
# cat Project.toml
# [deps]
# DataFrames = "a93c6f00-e57d-5684-b7b6-d8193f3e46c0"
ComandoEfecto
Pkg.addInstalar dependencia
Pkg.updateActualizar dependencias
Pkg.statusVer versión instalada
Pkg.precompilePrecompilar paquetes
Pkg.instantiateReconstituir entorno desde Manifest

Paralelismo y computación en clúster

Julia trae paralelismo por procesos (@everywhere, @spawnat, @distributed) y por hilos (Threads.@threads), además de Task para concurrencia ligera. En datos grandes el soporte a JuliaGPU es excelente.

# PARALELISMO POR HILOS (dentro de un proceso)
function sumar_hilos(n)
    sum = zeros(Int, 8)
    Threads.@threads for i in 1:8
        s = 0
        for j in 1:n
            s += j
        end
        sum[i] = s
    end
    sum
end

# ACTIVAR HILOS: lanzar julia con -t 4, o desde REPL:
# julia -t 4

# PARALELISMO POR PROCESOS (Distributed)
using Distributed
addprocs(4)                      # agrega 4 procesos workers
@everywhere using Statistics     # necesita cargar en cada worker

resultado = @distributed (+) for i in 1:100
    i^2
end
println(resultado)   # suma de cuadrados

# TAREAS ASÍNCRONAS (concurrencia ligera)
t = @async begin
    sleep(0.5)
    println("tarea terminada")
end
println("principal inmediato")
wait(t)

# CHANNELS: comunicación entre tareas
ch = Channel{Int}(10)
@async for i in 1:5
    put!(ch, i)
end
for _ in 1:5
    print(take!(ch), " ")
end
println()

Con @distributed la reducción usa el operador que pongas (aquí +); con hilos, ojo con la seguridad de hilos en mutaciones compartidas usa Threads.@threads solo para loops "pure".

Proyectos y entornos

La mejor práctica para aplicaciones Julia es crear un proyecto por aplicación: un directorio con Project.toml que declara dependencias y Manifest.toml que fija versiones. --project activa el entorno.

# Estructura recomendada
# miapp/
#   Project.toml
#   Manifest.toml
#   src/miapp.jl
#   test/runtests.jl

# Crear el entorno desde la terminal
julia --project=. -e 'using Pkg; Pkg.add(["DataFrames", "CSV"])'
julia --project=. -e 'using Pkg; Pkg.status()'

# Ejecutar el código del proyecto
julia --project=. src/miapp.jl

# Entornos aislados con juliaup / JULIA_PROJECT
export JULIA_PROJECT="$(pwd)"   # activa el proyecto actual
export JULIA_DEPOT_PATH=$HOME/.julia
# Declaración dentro de Julia
module Miapp
export duplicar
duplicar(x) = 2x
end

using .Miapp
println(duplicar(21))   # 42

juliaup es el instalador/versionador oficial de Julia (gestiona múltiples versiones como rustup). Separa "entorno de usuario" de "entornos de proyecto" automáticamente; Project.toml + Manifest.toml garantiza reproducibilidad total.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Múltiple dispatch: define una abstract type Animal con subtipos Perro y Gato, y un método sonido(a) distinto para cada uno.
  2. JIT: ejecuta fib(30) tres veces y documenta la mejora de la primera a la tercera ejecución.
  3. Pkg: crea un entorno de proyecto, agrega CSV, muestra Pkg.status() y exporta el Project.toml.
  4. Paralelo: con Threads.@threads calcula la suma de cuadrados de 1:10^6 y compara en tiempo frente a la versión secuencial.
  5. Proyecto reproducible: estructura un miapp con module, Project.toml y un test/runtests.jl mínimo; ejecuta con --project.
