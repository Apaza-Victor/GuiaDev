Módulos y funciones con nombre

El código se organiza en módulos (defmodule) que contienen funciones con nombre (def), funciones privadas (defp) y, si quieres, atributos de módulo.

defmodule Matematica do
  # Atributo de módulo (constante compilada)
  @pi 3.14159

  def area_circulo(radio), do: @pi * radio * radio

  # Función privada no accesible fuera del módulo
  defp doble(x), do: 2 * x

  def publico(x) do
    doble(x)   # llamo a la privada
  end

  # Funciones con aridad distinta son funciones distintas
  def area_base(:circulo, r), do: @pi * r * r
  def area_base(:cuadrado, lado), do: lado * lado
end

IO.inspect(Matematica.area_circulo(2.0))    # 12.56636
IO.inspect(Matematica.publico(5))           # 10
IO.inspect(Matematica.area_base(:cuadrado, 4))  # 16

# Los módulos se pueden anidar con atributos
defmodule App do
  defmodule Repositorio do
    def get(id), do: {:ok, %{id: id}}
  end
end
IO.inspect(App.Repositorio.get(1))

En Elixir la función se identifica por nombre y aridad: area_base/2 es distinta de area_base/3. Por eso la herramienta h de IEx muestra nombre/aridad.

El operador pipe

El operador |> pasa el resultado de la izquierda como primer argumento de la función de la derecha. Es el estilo de encadenado que hace Elixir legible y "fluyente".

# Sin pipe: anidado, se lee de dentro hacia fuera
sl=String.upcase(String.trim(" hola  "))
IO.puts(sl)

# Con pipe: lineal, izquierda → derecha
resultado =
  "  hola  "
  |> String.trim()
  |> String.upcase()
  |> String.split()

IO.inspect(resultado)    # ["HOLA"]

# Pipes con funciones de módulos (String, Enum, Map)
datos =
  [1, 2, 3, 4]
  |> Enum.filter(fn x -> rem(x, 2) == 0 end)
  |> Enum.map(&(&1 * 10))
  |> Enum.sort(:desc)
IO.inspect(datos)        # [40, 20]

# Capturas: &(&1)
dobles = Enum.map([1, 2, 3], &(&1 * 2))
IO.inspect(dobles)       # [2, 4, 6]

# Pipe con capturas
texto = "ana,pedro,pau"
nombres =
  texto
  |> String.split(",")
  |> Enum.map(&String.capitalize/1)
IO.inspect(nombres)      # ["Ana", "Pedro", "Pau"]

Los pipes reemplazan al anidamiento de paréntesis: cada función recibe como primer argumento el valor anterior. String.capitalize/1 es una "referencia a función" usable con &.

Aridad y referencias a funciones

La aridad (número de argumentos) forma parte del nombre de la función. Capturas &modulo.fun/aridad permiten pasar funciones como argumentos.

defmodule Util do
  def suma(a, b), do: a + b    # Util.suma/2
  def suma(a, b, c), do: a + b + c   # Util.suma/3 <- distinta
end

IO.inspect(Util.suma(1, 2))          # 3
IO.inspect(Util.suma(1, 2, 3))       # 6

# Referencia a función: &Modulo.funcion/aridad
mi_funcion = &String.upcase/1
IO.inspect(mi_funcion.("hola"))      # "HOLA"

# Funciones de orden superior reciben funciones
nums = [1, 2, 3, 4]

# Captura con &1 (&2...) de forma abreviada
agregar1 = &(&1 + 1)
IO.inspect(Enum.map(nums, agregar1))          # [2,3,4,5]
IO.inspect(Enum.map(nums, &(&1 * 2)))         # [2,4,6,8]

# Pasar una función definida en módulo con aridad
IO.inspect(Enum.map(nums, &Integer.to_string/1))  # ["1","2","3","4"]

# Compose de funciones: no es pipe, es composición
doble_y_texto = nums |> Enum.map(&(&1 * 2)) |> Enum.map(&Integer.to_string/1)
IO.inspect(doble_y_texto)

Cuando pases &f/1, la aridad debe coincidir con lo que espera la función de orden superior. &(&1 + 1) crea una función anónima de un argumento automáticamente.

Funciones con nombre, defaults y capturas

Elixir permite argumentos con valores por defecto \\, argumentos con nombre (keywords) y la sintaxis de "do block". Veamos el abanico de firma.

defmodule Saludos do
  # Defaults
  def saludar(nombre, saludo \\ "Hola") do
    "#{saludo}, #{nombre}"
  end

  # Cuando hay defaults, la aridad "extra" aparece automáticamente:
  # saludar/1 y saludar/2

  # Con keywords (opciones) al final
  def configurar(datos, opciones \\ []) do
    ancho = Keyword.get(opciones, :ancho, 100)
    color = Keyword.get(opciones, :color, "negro")
    "#{datos} en #{ancho}px y #{color}"
  end

  # El do-block es azúcar: def f() do ... end  es  def f(), do: ...
  def adios(nombre) do
    "chao #{nombre}"
  end
end

IO.inspect(Saludos.saludar("Ana"))                 # "Hola, Ana"
IO.inspect(Saludos.saludar("Ana", "Buen día"))     # "Buen día, Ana"
IO.inspect(Saludos.configurar("panel", ancho: 400))
IO.inspect(Saludos.configurar("panel"))

Los defaults (\\) generan múltiples cláusulas automáticamente; evita conflictos con cláusulas manuales de la misma aridad. Los Keyword son listas de tuplas con átomos primero.

Docs y metaprogramación

Elixir integra la documentación en el código con @doc, @moduledoc y atributos. Esas cadenas son consultables desde IEx con h.

defmodule DocEjemplo do
  @moduledoc """
  Módulo de ejemplo para documentación integrada.

  Se usa para demostrar cómo consultar `h DocEjemplo` e IEx.
  """

  @doc """
  Suma dos números enteros.

  ## Ejemplos

      iex> DocEjemplo.sumar(2, 3)
      5
  """
  def sumar(a, b), do: a + b

  @doc "Invierte una cadena."
  def invertir(cadena), do: cadena |> String.reverse()
end

IO.inspect(DocEjemplo.sumar(2, 3))
IO.inspect(DocEjemplo.invertir("ola"))    # "alo"

# Desde IEx:
# iex> h DocEjemplo
# iex> h DocEjemplo.sumar/2

# Los atributos @doc/@spec/@type son la base de 'mix docs' (ExDoc)
# y del dialyzer para tipos

Metaprogramación (macros) es un tema avanzado, pero saber que def, case, if son macros (no keywords) te da el poder de crear DSLs (quizá no ahora, pero anótalo). ExDoc genera la web de documentación de tu librería.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Módulo: crea Formatos con una función privada y una pública que la use.
  2. Pipeline: toma " elixir | es | genial ", haz String.split, Enum.filter (no vacías) y Enum.map con captura.
  3. Aridad: define concatenar/2 y concatenar/3, y pruébalas en IEx con referencia &concatenar/2.
  4. Defaults: implementa rombo_form(jerarquia, tam \\ 4) con tamaño por defecto.
  5. Documentación: añade @moduledoc y @doc a un módulo y consulta h desde IEx.
