Tipos básicos

Elixir tiene un pequeño conjunto de tipos: números, átomos, strings, listas, tuplas, maps, booleanos y nil. Todos los datos son inmutables y todo es una expresión que devuelve un valor.

# Enteros y flotantes
entero = 42
flotante = 3.14

# Átomos: constantes con nombre, del estilo "self describing"
estado = :ok
error = :error

# Booleanos (son átomos :true / :false) y nil (que es :nil)
activo = true
nada = nil

# Strings (UTF-8)
texto = "Hola, Elixir"
caracteres = String.length(texto)

# Listas (enlazadas) y tuplas (acceso rápido por índice)
lista = [1, 2, 3]
tupla = {:ok, "resultado"}

# Maps (diccionarios)
mapa = %{"clave" => 1, nombre: "Ana"}   # mezcla claves string y atom

# Inspeccionar tipo
IO.inspect(is_integer(42))        # true
IO.inspect(is_map(mapa))          # true

Pattern Matching: el operador =

En Elixir, = NO es asignación: es pattern matching. x = 10 liga x si no estaba ligada; si ya está ligada, compara. Si no coincide, lanza MatchError.

# Ligar
x = 10            # liga (nueva variable)
IO.inspect(x)

# Comparar (ya ligada): 10 = 10 funciona
10 = 10
IO.puts("ok")

# NO funciona: 11 = x  -> MatchError (boom) si x = 10

# Extraer de estructuras
{a, b, c} = {1, 2, 3}
IO.inspect({a, b})                 # {1, 2}

[primero | resto] = [10, 20, 30]
IO.inspect(primero)                # 10
IO.inspect(resto)                  # [20, 30]

%{nombre: n} = %{nombre: "Ana", edad: 30}
IO.inspect(n)                      # "Ana"

# Patrón con desempate
case {1, 2} do
  {1, x} -> "el segundo es #{x}"
  {0, _} -> "empieza por 0"
  _ -> "otra cosa"
end

# El patrón es la herramienta central de Elixir: se usa en case, fn, def

Memoriza: = es "encaja el lado derecho con el izquierdo". Esta misma idea aparece en case, def (cabeceras) y fn (closures). Todo en Elixir "baila" sobre pattern matching.

Inmutabilidad

Todos los datos de Elixir son inmutables: una vez creados, jamás cambian. Las "actualizaciones" crean nuevos valores; las estructuras antiguas permanecen intactas.

lista = [1, 2, 3]

# "Agregar" al final NO modifica la lista original
nueva = lista ++ [4]
IO.inspect(lista)     # [1, 2, 3]  (¡original intacta!)
IO.inspect(nueva)     # [1, 2, 3, 4]

# Dar la vuelta tampoco la modifica
reves = Enum.reverse(lista)
IO.inspect(lista)     # [1, 2, 3]

# Los maps tampoco son mutados
mapa = %{a: 1}
mapa2 = Map.put(mapa, :b, 2)
IO.inspect(mapa)      # %{a: 1}
IO.inspect(mapa2)     # %{a: 1, b: 2}

# Ventaja: compartir y pasar datos sin miedo a efectos colaterales
# La VM comparte el espacio si es posible (estructuras persistentes)

La inmutabilidad elimina toda una clase de bugs (carreras en concurrencia, efectos invisibles) y hace el código enorme de predecible. Phoenix utiliza esto para mantener estados sin bloqueos.

Átomos y maps

Los átomos (:nombre) son constantes que se igualan a sí mismas; aparecen en todas partes (resultados :ok/:error, claves de config, estados). Los maps con claves de átomo admiten la sintaxis abreviada %{clave: valor} y acceso con mapa.clave.

# Átomo como etiqueta de estado
def es_par(n) do
  if rem(n, 2) == 0, do: :par, else: :impar
end
IO.inspect(es_par(4))       # :par

# Maps con claves átomo (sintaxis azúcar)
persona = %{nombre: "Ana", edad: 30}
IO.inspect(persona.nombre)          # "Ana"
IO.inspect(persona[:edad])          # 30

# Actualizar con pattern matching + |
%{persona | edad: 31}
IO.inspect(persona.edad)            # 30 (inmutable, no cambió)

# Map con claves string / variable
otro = %{"nombre" => "Pedro"}
clave = "nombre"
IO.inspect(otro[clave])             # "Pedro" (acceso dinámico)

# Crear y actualizar
nuevo = Map.put(persona, :ciudad, "Lima")
IO.inspect(nuevo.ciudad)            # "Lima"

# Listar claves
IO.inspect(Map.keys(persona))       # [:nombre, :edad]

Regla mental: claves de átomo para maps estáticos de tu propio código; claves string para datos externos (JSON). El operador | solo actualiza claves ya existentes.

Strings e interpolación

Los strings en Elixir son binarios UTF-8. La interpolación con #{"..."} es ubicua; se concatenan con <>.

nombre = "Ana"
edad = 30

# Interpolación
mensaje = "Hola, #{nombre}, tienes #{edad} años"
IO.puts(mensaje)

# Concatenación
saludo = "Bienvenid" <> "a a " <> nombre
IO.puts(saludo)

# Módulo String
IO.puts(String.upcase("elixir"))        # ELIXIR
IO.puts(String.length("café"))          # 4 caracteres
IO.puts(String.split("a,b,c", ","))     # ["a", "b", "c"]
IO.puts(String.contains?("mundo", "do"))

# CharLists (listas de códigos) aparecen en interop con Erlang
chars = ~w(h o l a)                     # list of palabras
IO.inspect(chars)

# Heredoc / sigilos
texto_largo = """
Línea uno
Línea dos
"""
IO.puts(texto_largo)

No confundas <> (concat de strings) con ++ (concat de listas). Y not big deal: [97, 98] en TypeScript NO es "ab"; en Elixir una lista de enteros ≤255 se imprime como charlist ('abc') solo al inspeccionar — para interop Erlang.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Tipos: en IEx crea un valor de cada tipo y muestralo con IO.inspect (incluye tupla y map).
  2. Pattern matching: extrae {:ok, dato} en una variable dato, y separa [cabeza | cola] de una lista.
  3. Inmutabilidad: crea una lista, agrega con ++, e imprime ambas para comprobar que la original no cambió.
  4. Mapa de perfil: construye tu %{nombre:, edad:, ciudad:}, actualiza con | y agrega una clave con Map.put.
  5. Strings: escribe una función que devuelva la inicial en mayúscula de un nombre y la longitud de una frase.

En la próxima lección veremos control de flujo: case, cond, funciones múltiples y guards.
