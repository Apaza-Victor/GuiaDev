Estructura de un script

Un script es un archivo .ps1 con la política de ejecución permitiendo correrlo, el comentario de ayuda .SYNOPSIS y la lógica organizada en funciones.

# mi-script.ps1
<#
.SYNOPSIS
    Reporte de servicios de una máquina.
.DESCRIPTION
    Genera un CSV con el estado de los servicios.
.PARAMETER Computador
    Nombre de la máquina remota.
.EXAMPLE
    .\mi-script.ps1 -Computador server01
#>

[CmdletBinding()]
param(
    [Parameter(Mandatory)]
    [string]$Computador
)

function Get-Reporte {
    param($Equipo)
    Get-Service -ComputerName $Equipo |
        Select-Object Name, Status, DisplayName
}

# --- cuerpo principal ---
$reporte = Get-Reporte -Equipo $Computador
$reporte | Export-Csv "reporte-$Computador.csv" -NoTypeInformation
Write-Host "Reporte generado para $Computador"

El bloque de comentarios <# ... #> con .SYNOPSIS y .PARAMETER alimenta la ayuda automática: Get-Help .\mi-script.ps1. Un script debe tener el objetivo de pasos: README + funciones + main.

Parámetros avanzados

Los atributos de parámetro permiten validación (rangos, conjuntos, existencia de rutas), descripción y conjuntos de parámetros disjuntos.

# Validación de valores
param(
    [ValidateRange(1, 10)] [int]$Nivel,
    [ValidateSet('P', 'D', 'N')] [string]$Modo,
    [ValidateScript({ Test-Path $_ })] [string]$Ruta
)

# Conjuntos de parámetros (solo uno a la vez)
param(
    [Parameter(ParameterSetName = 'Local')]
    [switch]$Local,
    [Parameter(ParameterSetName = 'Remote')]
    [string]$Servidor
)
if ($PSCmdlet.ParameterSetName -eq 'Remote') {
    "Vía remota: $Servidor"
} else {
    'Vía local'
}

# Parametrizar valores con mensajes de ayuda
function Instalar {
    param(
        [Parameter(Mandatory, HelpMessage = '¿Qué paquete?')]
        [string]$Paquete
    )
    "Instalando $Paquete"
}

# Valores contados y matrices
param(
    [int[]]$Puertos,
    [ValidateCount(1, 3)] [string[]]$Nombres
)

# Atributos dinámicos con aliases
param(
    [Alias('hv')]
    [string]$HostVirtual
)

ValidateSet evita errores de tipeo, ValidateScript agrega lógica personalizada (como verificar que una ruta exista) y los ParameterSetName crean firmas de comando distintas según el escenario.

Módulos

Un módulo (.psm1) agrupa funciones reutilizables; un manifest (.psd1) lo describe. Import-Module lo carga y Export-ModuleMember controla qué se expone.

# utilidades.psm1
function Convertir-Celsius {
    param([double]$fahrenheit)
    ($fahrenheit - 32) * 5 / 9
}
function Convertir-MB {
    param([long]$bytes)
    [math]::Round($bytes / 1MB, 2)
}
# Solo exponemos las públicas
Export-ModuleMember -Function Convertir-*

# Cargar el módulo
Import-Module .\utilidades.psm1 -Force
Convertir-Celsius -fahrenheit 212
Convertir-MB -bytes 536870912

# Listar módulos instalados
Get-Module -ListAvailable | Select-Object Name, Version, Author

# Módulo de la galería
Install-Module -Name PSScriptAnalyzer -Scope CurrentUser
Import-Module PSScriptAnalyzer
Invoke-ScriptAnalyzer -Path .\mi-script.ps1

PSGallery es el repositorio oficial de módulos PowerShell. Instálalos con Install-Module y expón solo lo necesario con Export-ModuleMember para mantener APIs limpias.

Programar tareas

Combinar Register-ScheduledJob, el Programador de Tareas (ScheduledTasks) o simplemente Register-ObjectEvent permite ejecutar scripts de forma automática.

# Trabajo programado vía módulo PSScheduledJob
Register-ScheduledJob -Name 'RespaldoDiario' `
    -ScriptBlock {
        & "C:\scripts\respaldar.ps1"
    } `
    -Trigger (New-JobTrigger -Daily -At '02:00')

Get-ScheduledJob
Start-Job -DefinitionName 'RespaldoDiario'
Get-Job -Name 'Respaldo*' | Receive-Job

# Con el Programador de Tareas nativo (más control)
Register-ScheduledTask -TaskName 'LimpiezaTemp' `
    -Action (New-ScheduledTaskAction -Execute 'powershell.exe' `
        -Argument '-File C:\scripts\limpiar.ps1') `
    -Trigger (New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday -At '07:00')

# Habilitar / deshabilitar
Disable-ScheduledTask -TaskName 'LimpiezaTemp'
Enable-ScheduledTask -TaskName 'LimpiezaTemp'

# Eventos del sistema como disparador
Register-ObjectEvent -InputObject $env:COMPUTERNAME `
    -EventName 'TransactionStarted' -Action { 'detectado' }

Distingue: PSScheduledJob son trabajos de PowerShell dentro de la sesión; ScheduledTasks son tareas de Windows más potentes (corren fuera de la sesión). Para tareas de infraestructura, el segundo suele ser el adecuado.

Mejores prácticas

Escribir PowerShell robusto y mantenible sigue una lista corta de reglas: nombrado Verbo-Sustantivo, parámetros nombrados, control explícito de errores, y análisis estático con PSScriptAnalyzer.

# Nombrado: Verbo-Sustantivo (Get-, Set-, New-, Test-, Export-)
function Get-ResumenServicios { ... }
function Test-PuertoAbierto { ... }

# Parámetros nombrados siempre
Get-Service -ComputerName server01 -Name spooler

# No silenciar errores sin más; informarlos
try {
    Remove-Item $path -Force -ErrorAction Stop
} catch {
    Write-Warning "No pude eliminar $path: $($_.Exception.Message)"
}

# No escribir de más: usa Write-Verbose / Write-Debug
function Ping-Sevidor {
    [CmdletBinding()]
    param([string]$Host)
    Write-Verbose "Ping a $Host..."
    Test-Connection -ComputerName $Host -Count 1 -Quiet
}
Ping-Sevidor -Host ejemplo.com -Verbose

# Variables nombradas y sin ambigüedad
$rutaOrigen     = 'C:\in'
$rutaDestino    = 'C:\out'

# Siembra el principio: retorna objetos, no texto
Get-Process | Format-Table  # para ver
Get-Process | Export-Csv    # para procesar

Regla de oro: los cmdlets devuelven objetos; el formateo es solo la vista. Así los scripts se componen y reutilizan. Valida tus scripts con Invoke-ScriptAnalyzer antes de desplegarlos.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Script: crea saludar.ps1 con param([string]$Nombre) y ayuda .SYNOPSIS; invócalo con Get-Help.
  2. Parámetros: amplía el script con ValidateSet('Informal','Formal') que cambie el saludo según el modo.
  3. Módulo: crea un módulo con dos funciones matemáticas y expórtalas con Export-ModuleMember.
  4. Tareas: registra un trabajo programado que ejecute un script ficticio a las 03:00 diarias y verifícalo con Get-ScheduledJob.
  5. Prácticas: ejecuta PSScriptAnalyzer sobre uno de tus scripts y corrige al menos 2 advertencias.
