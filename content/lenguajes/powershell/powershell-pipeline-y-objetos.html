El pipeline

El pipeline (|) es el corazón de PowerShell: cada comando pasa su salida como objetos al siguiente comando, no texto plano. Por eso puedes encadenar operaciones sin parsear nada.

# Uso básico: filtrar procesos por memoria
Get-Process | Where-Object { $_.WorkingSet -gt 100MB }

# $_ representa cada objeto del pipeline
Get-Service | Where-Object { $_.Status -eq 'Running' }

# Seleccionar propiedades
Get-Process | Select-Object -First 5 Name, Id, CPU

# Ordenar
Get-Process | Sort-Object CPU -Descending | Select-Object -First 3

# Transformar archivos
Get-ChildItem *.txt | ForEach-Object { $_.Name }

# Encadenar acumulaciones
1..10 | Where-Object { $_ % 2 -eq 0 } | Measure-Object -Sum

Mentalidad clave: Get-Proceso devuelve objetos; Where-Object filtra, Select-Object proyecta y Sort-Object ordena. Casi todo se resuelve encadenando estos cuatro.

---

Filtrar resultados

Where-Object aplica condiciones sobre cada objeto. Las propiedades se evalúan con $_.propiedad, y comparan con operadores de PowerShell (-eq, -like, -gt...).

# Filtros por propiedad
Get-Process | Where-Object { $_.CPU -gt 10 -and $_.ProcessName -like "*pw*" }
Get-Service | Where-Object { $_.Status -eq 'Stopped' }

# Sintaxis abreviada (llaves opcionales en expresiones simples)
Get-Service | Where-Object Status -eq 'Running'
Get-Process | Where-Object Name -match '^(p|w)'

# Filtros con regex y like
Get-ChildItem | Where-Object { $_.Name -like "*.log" }
Get-ChildItem | Where-Object { $_.Name -match "\d{4}" }

# Combinar condiciones
Get-Process | Where-Object {
    $_.CPU -gt 5 -or $_.WorkingSet -gt 200MB
}

# Nota: algunos cmdlets tienen filtro nativo (-Name term)
Get-Service -Name "*sql*"

-and/-or requieren los paréntesis de { ... }. Cuando el filtro es simple, prefiere el parámetro nativo del cmdlet (-Name, -Status): es mucho más rápido que pasar por todos los objetos.

Trabajar con objetos

PowerShell trata todo como objetos .NET: escribe, lee y manipula gracias a propiedades y métodos, no a cadenas.

# Inspeccionar un objeto
$p = Get-Process pwsh | Select-Object -First 1
$p | Get-Member                    # lista propiedades y métodos

# Propiedades típicas
$p.Name
$p.Id
$p.Path

# Crear tu propio objeto (para salidas limpias)
[PSCustomObject]@{
    Nombre = 'Ana'
    Edad   = 30
    Ciudad = 'Lima'
}

# Objetos propios dentro de un pipeline
Get-Process -First 3 |
    ForEach-Object {
        [PSCustomObject]@{
            Nombre = $_.Name
            ConsumoMB = [math]::Round($_.WorkingSet / 1MB, 2)
        }
    }

# Hashtables (estructuras clave-valor)
$config = @{ Host = 'localhost'; Puerto = 8080 }
$config.Host
$config['Puerto']

# Colecciones de objetos
$procesos = Get-Process
$procesos.Count
$procesos[0]

[PSCustomObject]@{} crea objetos con propiedades nombradas: perfecto para generar reportes, CSV o JSON listos para exportar.

Formatear y mostrar

El formato de salida se controla con cmdlets Format-Table, Format-List y Format-Wide, además de Out-* para archivos y ConvertTo-* para serialización.

# Tabla (por defecto)
Get-Process | Select-Object -First 5 |
    Format-Table Name, Id, CPU -AutoSize

# Lista (todas las propiedades)
Get-Service | Select-Object -First 2 | Format-List *

# Ancho (columnas de nombres)
Get-ChildItem | Format-Wide Name -Column 4

# A archivo
Get-Process | Out-File procesos.txt
Get-Service | Export-Csv servicios.csv -NoTypeInformation

# A JSON (para APIs y configs)
Get-Process -First 2 | Select-Object Name, Id | ConvertTo-Json

# A HTML
Get-ChildItem | ConvertTo-Html -Property Name, Length | Out-File lista.html

# Texto con formato de anchos
'{0,-10} {1,6}' -f 'Nombre', 'Edad'
'{0,10:N2}' -f 1234.5678

Export-Csv, ConvertTo-Json y ConvertTo-Html son la salida "estructurada" de PowerShell: intercambian datos entre scripts, reportes y sistemas, manteniendo los objetos lo más fieles posible.

Comparar y medir

Para comparar colecciones de objetos y obtener estadísticas rápidas, PowerShell trae Compare-Object y Measure-Object.

# Comparar dos listas
$a = 1..10
$b = 5..15
Compare-Object $a $b
# <=> izquierda, => derecha, <= solo en a

# Comparar procesos en dos máquinas (útil en auditorías)
Get-Process | Select-Object Name -Unique | Sort Name > local.txt
Compare-Object (Get-Content remoto.txt) (Get-Content local.txt)

# Medir estadísticas
1..100 | Measure-Object -Sum -Average -Minimum -Maximum

# Contar
Get-Service | Where-Object Status -eq 'Running' | Measure-Object

# Agrupar
Get-Process | Group-Object ProcessName | Sort-Object Count -Descending |
    Select-Object -First 5

# Propiedades de la agrupación
Get-ChildItem | Group-Object Extension

Compare-Object con archivos de procesos es un truco clásico de auditoría: detecta qué procesos difieren entre servidores o entre antes/después de un cambio.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Filtrar procesos: lista los 5 procesos que más memoria consumen, con nombre y consumo en MB.
  2. Pipeline: cuenta cuántos servicios están en ejecución usando Where-Object + Measure-Object.
  3. Objetos propios: crea un [PSCustomObject] de tu perfil con 4 propiedades y muéstralo en tabla.
  4. Formato: exporta un CSV con los nombres y tamaños de los archivos de una carpeta.
  5. Comparación: compara 1..20 con 15..30 con Compare-Object y explica cada símbolo de resultado.

En la próxima lección dominaremos el control de flujo: condicionales, bucles, funciones y manejo de errores.
