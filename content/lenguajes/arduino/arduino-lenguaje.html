Wiring: C++ para maker

Cuando escribes un sketch en el IDE de Arduino, en realidad estás escribiendo C++ compilado con avr-gcc. La plataforma añade una capa de librerías llamada Wiring (creada por Hernando Barragán) que simplifica enormemente la programación: esconde la configuración de registros del micro y ofrece funciones expresivas como digitalWrite(), analogRead() o delay().

¿Qué hace el preprocesador de Arduino?

Tu archivo .ino no es C++ válido tal cual. Antes de compilar, el IDE ejecuta un preprocesador que transforma el sketch en un .cpp real:

  1. Une todos los .ino de la carpeta en un solo archivo.
  2. Añade automáticamente los #include de las librerías de Arduino (como Arduino.h).
  3. Genera prototipos (declaraciones) de tus funciones para que puedas invocarlas antes de definirlas.

Por eso puedes llamar a una función parpadear() al principio de tu sketch aunque la definas más abajo, algo que no funcionaría en un .cpp puro sin declararla antes.

Flujo de ejecución

Arranca la placa
      |
      v
┌─────────────┐   una sola vez
│  setup()    │───────────────────┐
└─────────────┘                   │
      |                           │
      v                           v
┌─────────────┐   ←───────────┘
│   loop()    │   se repite siempre
└─────────────┘

Esto es un diagrama de flujo simplificado en texto: setup() prepara el terreno y loop() ejecuta tu lógica principal sin fin.

¿Por qué es un buen lenguaje para empezar?

  • Tipado estático que atrapa errores en compilación.
  • Sintaxis familiar (llaves, puntos y coma) que sirve para muchos otros lenguajes.
  • Control total de bajo nivel cuando lo necesitas, sin imponerlo al principio.
  • Al estar sobre C++, el conocimiento se transfiere a sistemas embebidos profesionales.

La diferencia clave entre un .ino y un .cpp puro es esa capa de magia: en el .cpp deberías tú escribir los includes, los prototipos y la función main() que llama a setup/loop. Arduino lo hace por ti.

Tipos de datos

Cada dato en C++ tiene un tipo, que define su tamaño en memoria y cómo se interpreta. En un microcontrolador de 8 bits como el ATmega328P, int ocupa 2 bytes (no 4 como en un PC), algo fundamental para no desbordar variables.

Tabla de tipos en el Uno (AVR 8-bit)

TipoBytesRango aproximado
boolean1true / false
char1-128 a 127
byte10 a 255
int2-32 768 a 32 767
unsigned int20 a 65 535
long4-2 147 483 648 a 2 147 483 647
unsigned long40 a 4 294 967 295
float4aprox. ±3.4e38 (precisión ~7 dígitos)
double4en AVR es igual a float

El peligro del desbordamiento (overflow)

Si una variable int acumula más de 32767, se desborda y "da la vuelta" a valores negativos. Lo mismo ocurre con unsigned long: la función millis(), que cuenta milisegundos, se desborda tras unos 49 días de funcionamiento continuo:

unsigned long t = millis();
// t se desborda a 0 después de 4 294 967 295 ms
// = 49,7 días aproximadamente

Esto explica bugs sutiles en proyectos que llevan encendidos mucho tiempo. La solución es comparar restas (millis() - inicio < intervalo) en vez de sumar.

String frente a char[]

Arduino ofrece la clase String, cómoda pero con costo: usa memoria dinámica (heap) que puede fragmentarse. Las cadenas en C puro, char[], son fijas y predecibles. Decidiremos cuándo usar cada una más adelante.

Consultar tamaños con sizeof

void setup() {
  Serial.begin(9600);
  Serial.println(sizeof(int));        // 2 en el Uno
  Serial.println(sizeof(long));       // 4
}

void loop() {}

En un PC int ocupa 4 bytes; en un Arduino Uno solo 2. Si haces cuentas que dependen del tamaño, usa long o tipos explícitos como uint32_t.

Variables y constantes

Una variable es un espacio de memoria con nombre y tipo que puede cambiar. Las constantes son valores que no cambian. Elegirlas bien marca la diferencia entre un sketch claro y uno caótico.

Ámbitos de las variables

  • Globales: declaradas fuera de cualquier función; visibles en todo el sketch. Útiles para configuración de pines y estado compartido.
  • Locales: declaradas dentro de una función; solo existen mientras esta se ejecuta.
  • static: locales que conservan su valor entre llamadas, sin ser globales.

Nombres en camelCase

La convención de Arduino es usar camelCase para variables y funciones (tiempoEspera, leerSensor()) y MAYÚSCULAS_SNAKE para constantes clásicas (TIEMPO_ESPERA). Nombres descriptivos que documenten el código:

const int PIN_LED = 13;          // favorito del principiante
const int RETARDO = 250;         // milisegundos
const float PI = 3.14159;

En general prefiere const: el compilador conoce el tipo y puede detectar errores. No uses constexpr pensando que ganas optimización en AVR: este microcontrolador estándar no tiene soporte completo para C++ moderno.

Ejemplo de configuración de pines con constantes

const int PIN_SENSOR = A0;
const int PIN_LED_ROJO = 9;
const int PIN_BOTON = 2;

void setup() {
  pinMode(PIN_LED_ROJO, OUTPUT);
  pinMode(PIN_BOTON, INPUT_PULLUP);
}

void loop() {
  digitalWrite(PIN_LED_ROJO, digitalRead(PIN_BOTON));
}

Operadores

Los operadores permiten combinar y transformar valores. Arduino usa los de C++, por lo que dominarlos te servirá en cualquier lenguaje próximo.

Aritméticos

int a = 10, b = 3;
int s = a + b;   // 13   suma
int r = a - b;   // 7    resta
int m = a * b;   // 30   multiplicación
int d = a / b;   // 3    división entera (¡trunca!)
int mo = a % b;  // 1    módulo (resto)

Incremento, compuestos y comparación

int n = 5;
n++;             // 6   (también existe --n, n-- …)
n += 3;          // 9   (equivale a n = n + 3)
n *= 2;          // 18

bool igual = (n == 18);    // true
bool distinto = (n != 18); // false
bool menor = (n < 20);     // true

Lógicos y bit a bit

bool cond = (a > 5) && (b < 5);   // Y lógico
bool cond2 = (a > 5) || (b > 5);  // O lógico
bool neg = !cond;                  // negación

// Bit a bit (trabajan bit a bit del número)
int x = 6;                 // 0110 en binario
int y = 3;                 // 0011
int andB = x & y;          // 0010 = 2
int orB = x | y;           // 0111 = 7
int xorB = x ^ y;          // 0101 = 5
int shiftB = x << 1;       // 1100 = 12 (desplaza a la izquierda)
int comp = ~x;             // complemento a uno

Máscaras con operadores bit a bit

En sistemas embebidos es normal empaquetar varios flags en un solo byte y manipularlos con máscaras:

byte estado = 0;
// Activar el bit 3 (valor 8 = 0b1000)
estado |= (1 << 3);
// Preguntar si el bit 5 está activo
if (estado & (1 << 5)) { /* ... */ }
// Apagar el bit 2
estado &= ~(1 << 2);

Usa &&, ||, ! para lógica booleana y &, |, ^ para números bit a bit. Confundirlos es un clásico que produce resultados extraños.

La precedencia sigue a C: multiplicación/división antes que suma/resta, comparación antes que lógicos. Cuando dudes, usa paréntesis: son gratis y aclaran la intención.

Estructuras de control

Las estructuras de control dirigen el flujo del programa: decisiones y repeticiones. Son las mismas que en C/C++.

Tabla resumen de cuándo usar cada una

EstructuraÚsala cuando…
if / else if / elseTienes condiciones sencillas o intervalos
switch / caseComparas una variable con varios valores fijos
forConoces de antemano las iteraciones
whileRepites mientras se cumpla una condición
do...whileDebes ejecutar al menos una vez

if / else y switch de ejemplo

int nivel = leerSensor();

if (nivel > 900) {
  Serial.println("Crítico");
} else if (nivel > 500) {
  Serial.println("Alto");
} else {
  Serial.println("Normal");
}
// Menú con switch
char opcion = 'b';
switch (opcion) {
  case 'a':
    Serial.println("Opcion A");
    break;
  case 'b':
    Serial.println("Opcion B");
    break;
  default:
    Serial.println("Desconocida");
}

Bucles for, while y do...while

// Encender 5 LEDs en secuencia con for
for (int i = 0; i < 5; i++) {
  digitalWrite(pinBase + i, HIGH);
  delay(200);
}

// Esperar mientras pulsemos el boton
while (digitalRead(PIN_BOTON) == HIGH) {
  delay(10);
}

// Ejecutar al menos una vez
do {
  Serial.println("leyendo sensor...");
  delay(1000);
} while (digitalRead(PIN_BOTON) == LOW);

break, continue y el ternario

for (int i = 0; i < 10; i++) {
  if (i == 3) continue;      // salta la iteración 3
  if (i == 7) break;         // sale del bucle en 7
}

// Operador ternario: ? :
int velocidad = (botonPulsado) ? 255 : 0;

El ternario (condición) ? valorSiSi : valorSiNo es azúcar sintáctico para un if/else de una sola asignación. Úsalo solo cuando sea legible.

Funciones propias

Las funciones organizan el código en bloques reutilizables. En Arduino, gracias al preprocesador, no necesitas declarar sus prototipos manualmente: el IDE los genera por ti.

Sintaxis básica

tipoDeRetorno nombreFuncion(tipoParametro parametro) {
  // cuerpo
  return valor;
}

Parámetros por valor y por referencia

Por defecto los parámetros se pasan por valor (una copia), así que modificarlos dentro no afecta al exterior. Para modificar el original se pasa por referencia con &, útil también para no duplicar arrays grandes:

void subeUnidad(int &valor) {
  valor++;              // modifica la variable original
}

void setup() {
  int contador = 5;
  subeUnidad(contador);
  Serial.println(contador);   // 6
}

Función que parpadea un LED n veces

void parpadear(int pin, int veces, int tiempo) {
  for (int i = 0; i < veces; i++) {
    digitalWrite(pin, HIGH);
    delay(tiempo);
    digitalWrite(pin, LOW);
    delay(tiempo);
  }
}

void setup() {
  pinMode(13, OUTPUT);
  parpadear(13, 3, 500);   // 3 parpadeos de 500 ms
}

void loop() {}

Con valores de retorno

int sumaDos(int a, int b) {
  return a + b;
}

int dobleDe(int x) {
  return 2 * x;
}

void setup() {
  Serial.begin(9600);
  Serial.println(sumaDos(3, 4));   // 7
  Serial.println(dobleDe(7));       // 14
}

void loop() {}

Buenas prácticas

  • Una función, una tarea: si una función hace varias cosas, divídela.
  • Nombres descriptivos: verbos que reflejen la acción (encenderLED, leerTemperatura).
  • Limitar parámetros: si hay demasiados, quizá conviene agruparlos.
  • Funciones void cuando no devuelven nada.

Escribir funciones propias es lo que convierte un sketch en un programa profesional: legible, testable y reutilizable entre proyectos.

Errores comunes

Estos son los fallos típicos al programar en Wiring/C++ para Arduino y cómo evitarlos:

1. Tipos demasiado pequeños

byte contador = 0;            // max 255
// contador++ se desborda en 255
unsigned long contadorLargo = 0;   // solución para contadores grandes

2. Acumular en int y desbordar

Si sumas lecturas de sensores en un int, pronto superarás 32767 y el valor "dará la vuelta". Usa long para acumuladores que puedan crecer.

3. Usar = en vez de ==

if (estado = HIGH) { }   // ❌ asigna (¡siempre true!)
if (estado == HIGH) { }  // ✅ compara

4. Puntos y coma o llaves desequilibrados

Un ; o una llave { de más o de menos produce errores en cadena. Revisa siempre el mensaje del compilador que indica la primera línea del problema y usa indentación consistente.

5. Redeclarar variables dentro de bloques

int x = 10;
for (int i = 0; i < 3; i++) {
  int y = x * i;      // y solo existe aquí
}
// aqu� y ya NO existe; intentar usarla es error

6. Pensar que double da más precisión

En el AVR de 8 bits, double es exactamente igual a float (4 bytes). Si necesitas más precisión decimal, tendrías que cambiar de plataforma o usar librerías de coma fija.

7. Abusar de String en bucles

// ❌ multiplica corazones de memoria en el heap
for (int i = 0; i < 100; i++) {
  String s = "valor " + String(i);
}
// ✅ usa char[] de tamaño fijo cuando sea posible

El heap de un Uno es diminuto (2 KB de SRAM en total). Concatener String en bucles o en loop() fragmenta la memoria y termina por colgar la placa o reiniciarla aleatoriamente. Prefiere buffers char[] fijos.

Ejercicios

Pon en práctica el lenguaje de Arduino con estos ejercicios, ordenados por dificultad creciente:

  1. Calcula el overflow de millis: sabiendo que unsigned long llega hasta 4 294 967 295, calcula cuántos días transcurren hasta que millis() se desborde a cero (divide entre 1000 ms/s, luego entre 3600 s/h y luego entre 24 h/día). ¿Qué precaución tomarías en un proyecto que dura semanas?
  2. Switch para día de la semana: escribe un programa que, dado un int dia (1 a 7), imprima por el puerto serie el nombre del día en español usando switch/case (1=Lunes … 7=Domingo) y un default que diga "Día inválido".
  3. Función máximo: escribe una función int maximo(int a, int b) que devuelva el mayor de dos enteros. Pruébala desde setup() imprimiendo maximo(5, 9) y maximo(10, 3). Compárala con la función max() incluida en Arduino.
  4. Una función con referencia: modifica el ejemplo subeUnidad para escribir tu propia función void incrementar(int &n) que sume 1 al valor original, e imprime el resultado por Serial para comprobar que la variable exterior cambió.
  5. Mide tamaños con sizeof: escribe un sketch que imprima sizeof(byte), sizeof(int), sizeof(long), sizeof(float) y sizeof(double). Anota los valores que obtienes en tu placa y explica la diferencia entre ellos.
  6. Detector de desbordamiento de int: crea un int, súmale repetidamente 10000 en un bucle e imprime el valor en cada paso. Observa cuándo se vuelve negativo y explica por qué ocurre y cómo lo evitarías.
