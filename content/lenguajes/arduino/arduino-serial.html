¿Qué es la comunicación serial?

La comunicación serial (o serie) es la forma más básica y universal de que tu placa Arduino intercambie datos con el mundo exterior, sobre todo con tu computadora. Antes de ver el código, conviene entender qué ocurre a nivel físico, porque muchos comportamientos "raros" del Monitor Serie se explican por ahí.

En la comunicación serial los datos viajan bit a bit, uno detrás de otro, por un único hilo conductor. Es el protocolo UART (Universal Asynchronous Receiver-Transmitter). Si necesitas enviar y recibir a la vez tendrás dos hilos: TX (transmisión) y RX (recepción). Es "asíncrono" porque no hay un cable de reloj que sincronice los dos extremos: ambos acuerdan por adelantado una velocidad.

Velocidad de transmisión: los baudios

La velocidad se mide en baudios (baudios/s), que a efectos prácticos podemos leer como bits por segundo. Ambos extremos deben pactar exactamente la misma velocidad: si el emisor envía a 9600 y el receptor espera a 9600, todo coincidirá; si no, recibirás caracteres basura. Es la causa más típica de que "no se vea nada" o de ver símbolos extraños.

El USB del Arduino esconde un convertidor

El ordenador no entiende de TX/RX a nivel de pines; el Arduino Uno no tiene un puerto serie nativo en el USB. Lo que ocurre es que un pequeño chip (en el Uno clásico es el ATmega16U2, y en muchas placas clon un CH340) actúa como convertidor USB-serial: traduce los bytes del UART a señales USB y viceversa. Por eso tu placa aparece en el sistema como un puerto COM virtual (en Windows) o /dev/ttyUSB0 (en Linux/macOS).

Puedes verlo como una "ventana" entre el microcontrolador y la computadora: el Micro escribe texto por el serial, el convertidor lo convierte a USB, y tu PC lo muestra en una ventana (el Monitor Serie). Y a la inversa: lo que escribas en el Monitor viaja por USB hasta el pin RX.

Full duplex y qué es el Monitor Serie

La UART es full-duplex en la práctica: puede enviar (TX) y recibir (RX) al mismo tiempo, lo que hace posible mandar comandos y leer respuestas en la misma sesión. El Monitor Serie es la herramienta integrada del IDE que usa esta vía para depurar tus programas: imprimir el valor de un sensor, el estado de una variable o mensajes de diagnóstico es la forma más rápida y barata de saber qué está haciendo tu placa en cada momento.

---

Serial.begin y el Monitor Serie

Antes de poder enviar o recibir nada debes abrir el puerto serie con Serial.begin(velocidad). Lo habitual es llamarlo en setup(), porque solo hay que configurarlo una vez. El argumento es la velocidad en baudios:

void setup() {
  // Abre el puerto serie a 9600 baudios
  Serial.begin(9600);
}

void loop() {
  // El puerto ya está abierto; podemos usarlo aquí
}

Velocidades habituales

BaudiosUso típico
300 / 600 / 1200Dispositivos slow, GPS antiguos
9600El clásico por defecto; funciona casi siempre
57600 / 115200Datos más fluidos, Ideal para el Serial Plotter
250000 / 1000000Comunicar con otros micros a alta velocidad

No hay una velocidad "correcta" universal: la única regla es que ambos extremos coincidan. 9600 es segura y legible para el ser humano; 115200 es mucho mejor para series de datos largas (como gráficas) porque transmite más de 10 veces más rápido.

Cómo abrir el Monitor Serie

En el Arduino IDE 2.x: menú Herramientas → Monitor Serie o el atajo Ctrl+Shift+M. En la ventana que se abre verás un selector de baudios en la esquina (asegúrate de que coincida con el de Serial.begin) y una lista desplegable del puerto serie si tienes varias placas conectadas.

No ver nada: casi siempre la velocidad

Si el Monitor no muestra nada o muestra símbolos raros (?Ã, çá…), la causa probada es que la velocidad del Monitor no coincide con la del begin(). Antes de tocar el código, verifica ambos números.

Primera prueba: "Hola, mundo"

void setup() {
  Serial.begin(9600);
  // Se imprime una sola vez, porque setup() corre una vez al inicio
  Serial.println("Hola, GuiaDev!");
}

void loop() {
  // Mientras tanto, el programa no hace nada especial
}

El Monitor Serie puede reiniciar la placa al abrirse (la Uno reinicia al abrir el monitor o pulsar reset). A veces verás el mensaje dos veces: es el puerto abriéndose, la placa reiniciándose y volviendo a imprimir. Es normal.

Enviar datos: print y println

Para enviar datos al computador usas dos funciones casi idénticas: Serial.print(valor) imprime el valor sin salto de línea, y Serial.println(valor) hace lo mismo pero añade un salto de línea al final (el ln viene de "line"). Eso hace que cada mensaje ocupe una fila propia, mucho más legible.

void setup() {
  Serial.begin(9600);
  Serial.print("Hola");        // Hola
  Serial.print(" mundo");      // Hola mundo (sin salto)
  Serial.println();            // ahora sí, nueva línea
  Serial.println("Fin");       // Fin + salto de línea
}

Imprimir números, variables y texto

Puedes imprimir texto literal, el valor de variables de cualquier tipo, y combinarlos en un mismo mensaje "concatenado":

int temperatura = 27;

void setup() {
  Serial.begin(9600);
  Serial.print("Mensaje: ");
  Serial.println(57);
  Serial.println(temperatura);
  Serial.println("Temperatura: " + String(temperatura) + " C");
}

Formateo de números

El segundo argumento opcional de print() controla cómo se muestra un número:

int n = 42;
float pi = 3.14159;

void setup() {
  Serial.begin(9600);
  Serial.print(n, DEC);      // 42  (decimal)
  Serial.print(F(", "));
  Serial.print(n, HEX);      // 2A  (hexadecimal)
  Serial.print(F(", "));
  Serial.print(n, BIN);      // 101010 (binario)
  Serial.println();
  Serial.print(pi, 2);       // 3.14 (2 decimales)
  Serial.println();
}

El formateo con , 2 limita los decimales de un float: ideal para lecturas de sensores como el LM35, que entrega 10 mV por grado y produce un número con muchos decimales ilegibles.

Ejemplo: leer un sensor y enviarlo por serial

int pinSensor = A0;

void setup() {
  Serial.begin(9600);
  pinMode(pinSensor, INPUT);
}

void loop() {
  int valor = analogRead(pinSensor);
  Serial.print("Lectura: ");
  Serial.println(valor);
  delay(500);
}

Este patrón —leer, imprimir, esperar— es la base de cualquier instrumento de medición por serial. El delay(500) evita saturar el puerto con miles de líneas por segundo.

Recibir datos: available y read

Recibir datos es tan importante como enviarlos. El flujo es siempre el mismo: primero compruebas cuántos bytes han llegado con Serial.available() y después los lees con Serial.read().

  • Serial.available() devuelve el número de bytes esperando en el búfer de recepción.
  • Serial.read() devuelve el primer byte de la cola y lo consume; si no hay nada, devuelve -1.

Un patrón típico usa un while para no dejar pasar bytes sin leer:

void setup() {
  Serial.begin(9600);
}

void loop() {
  // Mientras haya datos esperando, los lee y los reenvía (eco)
  while (Serial.available() > 0) {
    char c = Serial.read();       // un byte de la cola
    Serial.print(c);              // lo devuelve
  }
}

Byte vs char: son lo mismo internamente

Serial.read() devuelve un int que representa un byte (0–255) o -1. Puedes tratarlo como char para mostrarlo como letra, o como número para manipularlo. Imprimir un byte con println muestra su valor numérico; imprimirlo como char muestra su carácter:

while (Serial.available() > 0) {
  int b = Serial.read();
  Serial.print(b);         // muestra el número (p. ej. 65)
  Serial.print(" = ");
  Serial.println((char)b); // muestra la letra (p. ej. A)
}

Leer hasta nueva línea

Si envías textos terminados en salto de línea, puedes ir acumulando caracteres hasta encontrarlo:

String mensaje = "";

void loop() {
  while (Serial.available() > 0) {
    char c = Serial.read();
    if (c == '\n') {
      Serial.print("Recibido: ");
      Serial.println(mensaje);
      mensaje = "";
    } else if (c != '\r') {
      mensaje += c;         // acumula el carácter
    }
  }
}

El \r (retorno de carro) lo añade la opción "Nueva línea" del Monitor Serie según su configuración. Filtrarlo evita que se cuele un carácter extra de salto al final del mensaje.

Leer números con parseInt y flush

Para recibir números enteros existe Serial.parseInt(), que lee dígitos del búfer y los convierte en un int, saltando espacios y saltos de línea:

void setup() {
  Serial.begin(9600);
  Serial.println("Envíame un número:");
}

void loop() {
  if (Serial.available() > 0) {
    int numero = Serial.parseInt();
    Serial.print("Recibido: ");
    Serial.println(numero);
  }
}

Serial.parseInt() puede quedarse esperando si no llega el número completo (o bloquea hasta un timeout interno). No lo uses para comandos de texto cortos; reserva parseInt() para cuando realmente esperes un número y usa flush() con cuidado, porque descarta todo lo que queda en el búfer.

Protocolos sencillos de texto

La forma más robusta y legible de controlar tu placa desde un computador es definir un protocolo de texto: comandos simples que tu programa interpreta. Por ejemplo, un carácter: 'A' enciende, 'B' apaga; o una palabra terminada en salto de línea: ON, OFF, SET 50.

Parse simple con switch

int led = 13;

void setup() {
  pinMode(led, OUTPUT);
  Serial.begin(9600);
  Serial.println("Comandos: A=on, B=off");
}

void loop() {
  if (Serial.available() > 0) {
    char cmd = Serial.read();
    switch (cmd) {
      case 'A':
        digitalWrite(led, HIGH);
        Serial.println("LED encendido");
        break;
      case 'B':
        digitalWrite(led, LOW);
        Serial.println("LED apagado");
        break;
      default:
        Serial.println("Comando desconocido");
    }
  }
}

Comandos de texto completo con acumulador

Para palabras como ON / OFF acumulamos caracteres y comparamos al llegar el salto de línea:

String buffer = "";
int led = 13;

void setup() {
  pinMode(led, OUTPUT);
  Serial.begin(9600);
  Serial.println("ON / OFF para controlar el LED");
}

void loop() {
  while (Serial.available() > 0) {
    char c = Serial.read();
    if (c == '\n') {
      buffer.trim();                  // quita espacios/retornos
      if (buffer == "ON") {
        digitalWrite(led, HIGH);
        Serial.println("LED encendido (comando ON)");
      } else if (buffer == "OFF") {
        digitalWrite(led, LOW);
        Serial.println("LED apagado (comando OFF)");
      } else {
        Serial.println("Comando desconocido: " + buffer);
      }
      buffer = "";                    // limpia para el siguiente
    } else if (c != '\r') {
      buffer += c;
    }
  }
}

Protocolo con parámetro numérico

Puedes mezclar texto y números: un comando como SET 128 para fijar el brillo PWM:

String buffer = "";

void setup() {
  Serial.begin(115200);
  Serial.println("'SET n' fija el brillo PWM (0-255)");
}

void loop() {
  while (Serial.available() > 0) {
    char c = Serial.read();
    if (c == '\n') {
      buffer.trim();
      if (buffer.startsWith("SET ")) {
        int brillo = buffer.substring(4).toInt();
        analogWrite(9, constrain(brillo, 0, 255));
        Serial.print("Brillo = ");
        Serial.println(brillo);
      }
      buffer = "";
    } else if (c != '\r') {
      buffer += c;
    }
  }
}

Los mensajes de confirmación ("LED encendido…", "Brillo = 128") son buena práctica: cierran el bucle de comunicación y te dicen si la placa interpretó bien el comando, algo vital para depurar protocolos.

Serial Plotter

El Serial Plotter convierte las líneas de datos del puerto serie en una gráfica en tiempo real. Está en Herramientas → Serial Plotter o con el atajo Ctrl+Shift+L. Es perfecto para visualizar lecturas de sensores sin escribir una sola línea de código de visualización.

Cómo formatear los datos

El Plotter interpreta cada línea enviada con println como un nuevo punto de la gráfica. Si quieres dibujar varias curvas a la vez, separa los valores con tabulador (\t) en la misma línea, y etiqueta cada serie al principio con el mismo formato.

void setup() {
  Serial.begin(115200);   // más fluido para gráficas
  Serial.println("Sensor\tUmbral");  // etiquetas de las series
}

void loop() {
  int valor = analogRead(A0);
  int umbral = 512;
  Serial.print(valor);
  Serial.print('\t');
  Serial.println(umbral);
  delay(50);
}

Con esto verás dos curvas en la misma ventana: la lectura del sensor y una línea constante en el valor umbral, útil para comparar y detectar cuándo se cruzan.

Dos valores: la clave del tabulador

El \t entre valores es lo que le dice al Plotter "nueva serie" en la misma fila. Un println al final cierra la fila. Si solo envías un valor por fila, dibujarás una única curva.

Con 9600 baudios el Plotter se ve entrecortado y lento. Para gráficas fluidas usa 115200 (o más) y un delay() corto. El formato de los datos debe ser homogéneo: números (o valores con decimales), nunca texto mezclado en la fila de datos.

Ideal para detectar ruido o picos: prueba a mover un potenciómetro lentamente y observa si la curva es suave o "peluda". Ese pelusa delata interferencias que en el Monitor Serie pasarían desapercibidas.

Errores comunes

La comunicación serial tiene una lista corta pero muy repetida de errores. Conocerlos te ahorrará horas:

1. Velocidad del Monitor distinta a la de begin()

El clásico absoluto. Abres el serial, se "abre" pero no sale nada o salen caracteres raros. Solución: iguala la velocidad del Monitor a la de Serial.begin().

2. Esperar datos sin abrir el Monitor

Si la placa solo espera a recibir comandos (esperando Serial.available()) y nunca abres el Monitor, parece que el programa está "congelado". Además, al abrir el Monitor la placa se reinicia: el USB resetea el micro al establecer la conexión. No es un bug, es el comportamiento esperado.

3. Usar read() sin comprobar available()

Serial.read() devuelve -1 cuando no hay datos. Leer sin comprobar available() puede producir bucles que se comen la CPU o procesar valores basura:

// ❌ Inseguro: si no hay datos, c devuelve -1 y aun así se procesa
// int c = Serial.read();
// Procesar(c);

// ✅ Seguro: solo lee si hay algo
if (Serial.available() > 0) {
  int c = Serial.read();
  Procesar(c);
}

4. Imprimir sin descanso y ralentizar el bucle

Enviar miles de líneas por segundo a 9600 baudios estrangula el loop(), porque la placa espera a que el búfer de salida se vacíe. Imprime solo lo necesario y usa delay() o un temporizador.

5. while(!Serial) en placas con USB nativo

En placas como Leonardo, Micro o Zero el USB es nativo y la línea while (!Serial) { } se usa para esperar a que el Monitor abra la conexión. En el Uno da igual (el 16U2 conecta sin esperar), pero copiar ese while en un Uno puede hacer que el programa se quede esperando un Monitor que nunca se abre si lo usas fuera de contexto.

6. Confundir print y println, y 9600 en gráficas densas

Usar solo print junta todo en una línea ilegible; elegir 9600 baudios para el Plotter lo deja lento y entrecortado. Prueba println para mensajes y 115200 para gráficas.

Cuando depures serial, cambia una sola cosa a la vez: primero la velocidad, luego el puerto, luego el formato de los datos. Cambiarlo todo de golpe oculta cuál de los factores era el culpable.

Ejercicios

Para dominar la comunicación serial, resuelve estos ejercicios con tu placa conectada. Están ordenados por dificultad:

  1. Hola, mundo serial: escribe un sketch que imprima tu nombre una sola vez en setup() y, en loop(), imprima la palabra "tick" cada segundo. Abre el Monitor a 9600 y comprueba el resultado.
  2. Eco de caracteres: crea un programa que lea lo que escribas en el Monitor y lo devuelva en mayúsculas (pista: toupper()). Lee un byte cada vez con Serial.read().
  3. Termómetro LM35 por serial: conecta un LM35 a A0 y envía la temperatura en grados Celsius con un decimal (, 1) cada medio segundo. Compruébala en el Monitor y luego en el Plotter.
  4. Comandos ON/OFF: usa el sketch de comandos de texto que controla el LED con ON/OFF, añádele el comando BLINK que haga parpadear el LED mientras esté activo, y verifica los mensajes de confirmación.
  5. Dos variables para el Plotter: envía en una misma línea, separados por un tabulador, el valor de analogRead(A0) y un umbral fijo (por ejemplo 512). Abre el Serial Plotter y observa las dos curvas. Prueba a cambiar el umbral a 700 y vuelve a mirar.
