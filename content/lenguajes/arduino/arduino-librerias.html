¿Qué es una librería?

Una librería es una colección de código reutilizable (funciones y clases ya escritas y probadas) que evita que reinventes la rueda en cada proyecto. En lugar de programar tú la comunicación con ese sensor o esa pantalla, alguien ya la escribió, la corrigió y la documentó: tú solo la instalas y la llamas.

En Arduino existen tres niveles de código reutilizable:

  • Núcleo (core): el propio lenguaje: pinMode(), digitalWrite(), Serial… forman parte del núcleo que ya trae el IDE.
  • Oficiales: librerías que Arduino mantiene para sus placas, como Servo, LiquidCrystal, SD o EEPROM.
  • De terceros: escritas por la comunidad o por los propios fabricantes de sensores, pantallas y módulos.

Una librería suele constar de uno o varios archivos de cabecera .h (con las declaraciones) y archivos .cpp (con la implementación). Al compilar tu sketch, el IDE compila también los archivos de las librerías que hayas incluido y los enlaza en el binario final que se sube a la placa.

¿Por qué explotar la comunidad?

  • Sensores, pantallas, motores y módulos de comunicación ya tienen su librería publicada.
  • Velocidad: conectas el módulo, cargas un ejemplo y funciona ese mismo día.
  • Mantenimiento: la comunidad corrige errores y amplía funcionalidades con cada versión.

La mayoría de librerías se distribuyen con licencias abiertas (MIT o BSD son las típicas; algunas usan GPL). Antes de integrarlas en un producto comercial, revisa la licencia indicada en el repositorio.

Regla de oro: si tu sensor tiene librería oficial del fabricante, úsala. Normalmente incluye ejemplos, corrección de bugs y compatibilidad con las placas modernas.

Instalar librerías

Hay dos vías principales para instalar una librería: el Gestor de Librerías (recomendada) o añadir un archivo .ZIP descargado a mano.

Vía 1: Gestor de Librerías del IDE

  1. En el IDE: Sketch → Incluir librería → Gestionar librerías… (o el icono del libro en la barra izquierda).
  2. Busca por nombre, por ejemplo DHT sensor library.
  3. Selecciona la librería, elige la versión más reciente y pulsa Instalar.
  4. Espera a que termine la barra de progreso; no hace falta reiniciar el IDE.

Vía 2: Añadir un .ZIP manual

  1. Descarga el archivo .zip desde GitHub o la web del fabricante.
  2. En el IDE: Sketch → Incluir librería → Añadir librería .ZIP… y selecciona el archivo.
  3. El IDE lo descomprime y copia automáticamente en tu carpeta de librerías.

¿Dónde vive cada cosa?

RecursoUbicación
Librerías de usuarioDocuments\Arduino\libraries (Windows) o ~/Arduino/libraries (macOS/Linux)
Librerías del núcleoDentro de la instalación del IDE (no conviene tocarlas)
Ejemplos de cada libreríaArchivo → Ejemplos, agrupados por nombre y autor

Verificar que todo fue bien

Abre Archivo → Ejemplos: si ves la carpeta de la librería recién instalada, está correctamente colocada. Como prueba, compila y sube uno de sus ejemplos con tu placa conectada.

Un mismo Skectch no debería ver dos versiones de la misma librería: si tras actualizar algo se rompe, abre tu carpeta de librerías y borra la copia antigua (o el .zip bloqueado) antes de reinstalar.

Incluir y usar una librería

Para usar una librería hay que declararla en la parte superior del sketch con #include. Los ángulos <Biblioteca.h> indican que es una librería del sistema; las comillas "mi_archivo.h" se reservan para archivos de tu propio proyecto.

Declarar objeto, inicializar, usar

La mayoría de librerías exponen clases, y el flujo típico es siempre el mismo:

#include 

DHT dht(2, DHT11);          // 1. construir el objeto (a nivel global)

void setup() {
  dht.begin();              // 2. inicializarlo en setup()
}

void loop() {
  float t = dht.readTemperature();   // 3. usar sus métodos en loop()
  if (!isnan(t)) {
    Serial.println(t);
  }
}

Observa los tres momentos: declarar el objeto a nivel global (fuera de cualquier función), inicializarlo en setup() (begin, init o attach, según la librería) y llamar a sus métodos en loop(). El patrón se repite en casi todas.

Ejemplo completo: LCD I2C

#include 
#include 

LiquidCrystal_I2C lcd(0x27, 16, 2);   // dirección I2C 0x27, pantalla 16x2

void setup() {
  lcd.init();               // iniciar el LCD
  lcd.backlight();          // encender la retroiluminación
  lcd.setCursor(0, 0);
  lcd.print("Hola, GuiaDev!");
}

void loop() {
  lcd.setCursor(0, 1);      // segunda fila
  lcd.print(millis() / 1000);  // mostrar los segundos transcurridos
  delay(250);
}

Si la librería ya está incluida, no copies su código dentro de tu sketch: duplicar la implementación provoca conflictos de nombres y te impide actualizarla desde el gestor.

Al compilar verás en la consola mensajes sobre archivos .cpp de la librería: es normal. El IDE está compilando la librería junto con tu sketch, no mostrando errores.

Un servo bajo control

#include 

Servo miServo;

void setup() {
  miServo.attach(9);        // servo conectado al pin 9
  miServo.write(0);         // posición inicial 0°
}

void loop() {
  for (int a = 0; a <= 180; a += 10) {
    miServo.write(a);       // barrido suave
    delay(100);
  }
}

Leer temperatura y humedad

#include 
#define PIN_DHT 2
#define TIPO_DHT DHT11

DHT dht(PIN_DHT, TIPO_DHT);

void setup() {
  Serial.begin(9600);
  dht.begin();
}

void loop() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (!isnan(t) && !isnan(h)) {       // proteger frente a lecturas vacías
    Serial.print("Temp: ");
    Serial.print(t);
    Serial.print(" C | Hum: ");
    Serial.println(h);
  }
  delay(2000);
}

La mejor manera de descubrir librerías es buscar por el componente que tienes en la mano. Si hay sensor, hay librería: usa siempre la del fabricante o la más valorada por la comunidad.

Manejo de errores y documentación

Cuando instales una librería, dedica unos minutos a su documentación. La mayoría trae ejemplos listos para ejecutar: son el mejor manual de usuario que existe.

Validar la instalación con un ejemplo

  1. Abre Archivo → Ejemplos y busca el nombre de la librería.
  2. Selecciona y compila el ejemplo más parecido a tu objetivo.
  3. Sube el sketch a la placa: si funciona, la instalación y el cableado son correctos.

Mensajes de error típicos

Documentación y datasheet

Busca la página del fabricante o el datasheet del componente: el pinout (qué pin se conecta a qué pin de la placa) y el protocolo (I2C, SPI o serie) te indican qué librería usar y cómo inicializarla. Si encuentras un bug, no lo parchees en tu sketch: repórtalo en el repositorio de la librería (pestaña Issues de GitHub) con una copia mínima del código y la placa usada.

Versiones y compatibilidad

Anota la versión de librería que usa tu proyecto: algunas exigen núcleos recientes y fallan con IDEs antiguos o con placas de 8 bits frente a las de 32. Desconfía de copias "reempaquetadas" o con nombres raros: prefiere siempre el repositorio oficial del autor.

Antes de "arreglar" una librería a mano, pregunta a la comunidad. Si el problema es de cableado, lo arreglarás antes por ahí que peleándote con la librería.

Errores comunes

1. Olvidar el #include

// ❌ sin el include, "Servo" no existe para el compilador
Servo miServo;
// ✅ al principio del sketch:
// #include <Servo.h>

2. Incluir pero no declarar el objeto

Instalar la librería no basta: hay que crear el objeto. Sin esa línea, al usar métodos aparece el espantoso class has no default member o no matching function for call. La declaración (Servo miServo;, DHT dht(2, DHT11);…) va siempre a nivel global.

3. Instalar sin desinstalar la versión anterior

Dos versiones de la misma librería provocan multiple libraries found y un bucle de "arreglos" que no funcionan. Borra la copia antigua de Documents\Arduino\libraries.

4. Añadir el .ZIP sin extraer (o añadir el zip equivocado)

El IDE espera un .zip que contenga la carpeta de la librería. Si intentas añadir el archivo ya extraído o un zip que no es, no aparecerá en Ejemplos.

5. Llamar a métodos antes de begin()

dht.readTemperature();   // ❌ antes de dht.begin()
dht.begin();             // ✅ primero se inicializa

6. Esperar Serial sin iniciarlo

Si una librería usa Serial y no llamas a Serial.begin(9600), el Monitor Serie no mostrará nada. Mira siempre el setup() de los ejemplos de la librería.

7. Ignorar la incompatibilidad con la placa

Algunas librerías usan APIs que cambian entre Arduino 1.x y 2.x, o requieren placas de 32 bits. Si compilas y ves un mensaje de argumentos o registros (argument mismatch, undefined reference), mira la versión de la librería y la placa que exige.

El error número uno con librerías no es técnico, es de procedimiento: no leer el ejemplo de la librería. Antes de modificar nada, copia un ejemplo tal cual, súbelo y compruébalo: si funciona, tu cableado es el problema, no la librería.

Ejercicios

Cinco ejercicios que te llevarán de instalar a construir proyectos reales con librerías. Recuerda guardar cada sketch en su propia carpeta.

  1. Instalar y validar: instala una librería desde el Gestor de Librerías (elige una con muchas estrellas, por ejemplo DHT sensor library). Abre uno de sus ejemplos, compílalo y súbelo a tu placa. Anota dónde se guardó en disco la librería.
  2. Servo con potenciómetro: con Servo.h, mueve un servo (pin 9) según la lectura de un potenciómetro en A0 usando analogRead() + map() para convertir 0–1023 a 0–180 grados.
  3. Termómetro: con la librería DHT (o NTC, si no tienes el sensor, simula con analogRead de un potenciómetro), imprime por el Monitor Serie "Temp: X C | Hum: Y %" cada 2 segundos.
  4. Memoria EEPROM: escribe un valor en la dirección 0 con EEPROM.write(0, valor), apaga y enciende la placa y verifica con EEPROM.read(0) que el dato sigue ahí. Documenta qué pasa si escribes valores superiores a 255.
  5. LCD I2C "Hola, GuiaDev!": con LiquidCrystal_I2C, muestra tu nombre en la primera fila y, en la segunda, los segundos transcurridos desde el arranque con millis() / 1000. Si no tienes LCD, simúllalo imprimiendo por Serial.
