¿Qué es PWM?

PWM son las siglas de Pulse Width Modulation (modulación por ancho de pulso): una técnica para simular una salida de voltaje variable sin generar realmente un voltaje analógico. En lugar de poner un valor intermedio continuo en el pin, el microcontrolador conmuta entre 0 V y 5 V extremadamente rápido y varía el tiempo que permanece en cada estado.

El parámetro que define el resultado es el ciclo de trabajo (duty cycle): el porcentaje del tiempo que la señal permanece en ALTO dentro de cada periodo. A mayor duty cycle, más tiempo recibe energía la carga y mayor es el valor percibido.

Cada bloque '█' = tiempo en ALTO; '▁' = tiempo en BAJO.

Duty 25 %   █▁▁▁   █▁▁▁   █▁▁▁   █▁▁▁   → el LED brilla poco
Duty 50 %   ██▁▁   ██▁▁   ██▁▁   ██▁▁   → brillo medio
Duty 75 %   ███▁   ███▁   ███▁   ███▁   → casi al máximo

Un periodo completo dura T = 1 / frecuencia.
En el Uno (AVR) T ≈ 2,04 ms a 490 Hz y T ≈ 1,02 ms a 980 Hz.

El ojo humano no sigue conmutaciones de ~500 Hz: percibe el brillo medio integrado en el tiempo. Si el LED está el 50 % del tiempo encendido, parecerá que brilla a la mitad. Con motores ocurre algo parecido entre el par medio y la corriente media. La tabla traduce el duty cycle al valor que acepta analogWrite():

Ciclo de trabajoValor de analogWrite()Efecto en un LED
0 %0apagado
25 %64brillo bajo
50 %128brillo medio
75 %192brillo alto
100 %255encendido total

El PWM no es un voltaje analógico real. Con un multímetro verás un valor promedio, pero en un osciloscopio la señal es una onda cuadrada. Esa conmutación importa en circuitos de audio o aplicaciones de precisión.

---

Los pines con ~

En la placa Uno los pines digitales 3, 5, 6, 9, 10 y 11 llevan un símbolo ~ (tilde) junto al número. Esa tilde indica que el pin está conectado a un temporizador del ATmega328P capaz de generar PWM por hardware. Solo en esos seis pines funciona analogWrite().

Pin PWMFrecuencia aprox. (AVR a 16 MHz)
5, 6~980 Hz (Timer 0)
3, 9, 10, 11~490 Hz (Timers 1 y 2)

Conviene aclarar un malentendido muy común: en Arduino no existen "salidas analógicas". Los pines A0 a A5 son únicamente entradas del conversor ADC; si intentas escribir en ellos con analogWrite(), la función no hará nada (o actuará como un digitalWrite() con poca corriente), porque no llevan módulo PWM.

El ADC y el PWM son circuitos independientes dentro del chip: uno mide voltajes (entrada analógica) y el otro genera ondas cuadradas (salida "analógica simulada"). Que un pin lleve una A en su nombre no lo convierte en una salida.

En Arduino 1.x y 2.x, analogWrite() solo ofrece salida real en los pines con tilde. En otras placas (Mega, Nano, Due) la lista de pines PWM cambia: consulta siempre la documentación de tu modelo.

analogWrite: brillo de un LED

La función analogWrite(pin, valor) recibe un valor entre 0 y 255 y ajusta el ciclo de trabajo de forma proporcional. Internamente llama al temporizador correspondiente y configura la salida; no hace falta una resistencia distinta a la de un LED digital: la misma resistencia limitadora de 220 Ω sigue valiendo, porque la corriente de pico es la misma.

// Sube y baja el brillo de un LED conectado al pin 9
const int LED = 9;

void setup() {
  pinMode(LED, OUTPUT);
}

void loop() {
  // Fade-in: de apagado a máximo
  for (int brillo = 0; brillo <= 255; brillo++) {
    analogWrite(LED, brillo);
    delay(10);
  }
  // Fade-out: de máximo a apagado
  for (int brillo = 255; brillo >= 0; brillo--) {
    analogWrite(LED, brillo);
    delay(10);
  }
}

Este patrón es la base de muchos proyectos con luz: atenuadores, luces de ambiente y un clásico localizado: los LED RGB, donde cada canal (rojo, verde, azul) lleva su propio pin PWM y el brillo relativo de cada color mezcla miles de colores percibidos.

El valor 255 de analogWrite() no "genera más voltaje": mantiene la señal el 100 % del tiempo. Para un desvanecimiento más natural a ojos humanos, aplica una curva de gamma: valor = (brillo * brillo) / 255.

Fade: luz que respira

Una de las demostraciones favoritas del PWM es la luz que respira: un LED que sube lentamente de brillo y luego baja, imitando la intensidad de una inspiración y una espiración. Se consigue recorriendo los 256 valores posibles con dos bucles for: uno ascendente (fade-in) y otro descendente (fade-out).

// "Breathing": el LED respira. LED en el pin 9 con resistencia de 220 Ω.
const int LED = 9;

void setup() {
  pinMode(LED, OUTPUT);
}

void loop() {
  // Inspiración: sube de 0 a 255 con pasos de 15 ms (~3,8 segundos)
  for (int i = 0; i <= 255; i++) {
    analogWrite(LED, i);
    delay(15);
  }
  // Espiración: baja de 255 a 0
  for (int i = 255; i >= 0; i--) {
    analogWrite(LED, i);
    delay(15);
  }
}

El ciclo completo tarda aproximadamente 7,7 segundos, la suma de las dos pasadas. Basta con tocar el argumento de delay() para hacer la respiración más lenta o más rápida.

delay() es la forma más directa para un único efecto, pero bloquea todo el programa: mientras el LED respira, la placa no puede leer botones ni sensores. Para varios efectos simultáneos se usa la técnica non-blocking con millis(), que verás en las próximas lecciones: cada 20 ms se actualiza el valor de PWM sin detener el resto del sketch.

Prueba a combinar este sketch con un potenciómetro en A0: un map() convierte su lectura en la velocidad de la respiración. Unir entrada analógica y salida PWM es el primer gran hito electrónico.

Velocidad de un motor

Un pin de Arduino no puede alimentar un motor directamente: el GPIO entrega como máximo ~40 mA recomendados (según fabricante, ~200 mA de pico absoluto), y un motor pequeño consume decenas o centenas de mA incluso en vacío. Conectarlo al pin fundiría el microcontrolador. La solución clásica es un transistor conmutador: el PWM gobierna una señal pequeña y el transistor permite que una fuente externa alimente el motor.

Fuente externa (6-9 V):  (+) ──► terminal (+) del motor
                         (−) ──► GND común
Motor:                   terminal (•) ──► Drenor del MOSFET
                         (diodo 1N4007 en paralelo: cátodo → (+),
                          ánodo → terminal (•) del motor)
MOSFET (IRF520N):        Gate  ──► 220 Ω ──► pin 9 (PWM)
                         Drain ──► terminal (•) del motor
                         Source ──► GND común
BJT 2N2222 (motor pequeño): Base ──► 220 Ω ──► pin 9 · Colector ──► motor · Emisor ──► GND

Los tres componentes clave: el MOSFET de lógica (p. ej. IRF520N, o el BJT 2N2222 para motores muy pequeños) conmuta el motor a la fuente según el PWM del pin; el diodo flyback (1N4007) absorbe el pico de tensión inversa que se genera al cortar la corriente y protege al transistor; y el GND común hace que placa y fuente compartan la misma referencia.

// Acelera y decelera un pequeño motor controlado desde el pin 9
const int PIN_MOTOR = 9;
const int VELOCIDAD_MAX = 255;

void setup() {
  pinMode(PIN_MOTOR, OUTPUT);
}

void loop() {
  // Arranque progresivo hasta la velocidad de crucero
  for (int v = 0; v <= VELOCIDAD_MAX; v++) {
    analogWrite(PIN_MOTOR, v);
    delay(6);
  }
  analogWrite(PIN_MOTOR, 180);

  // Ciclo de aceleración y frenado suave
  for (int v = 0; v <= VELOCIDAD_MAX; v++) {
    analogWrite(PIN_MOTOR, v);
    delay(4);
  }
  for (int v = VELOCIDAD_MAX; v >= 0; v--) {
    analogWrite(PIN_MOTOR, v);
    delay(4);
  }
}

No alimentes motores desde el pin de 5 V ni desde el regulador de la placa: el regulador de la Uno entrega ~500 mA limitados por la USB, y un motor en arranque pide picos mucho mayores que pueden reiniciar o quemar la placa. Usa siempre una fuente externa separada con GND común.

El mismo principio se usa para regular tiras de LED de 12 V: el MOSFET conmuta la carga contra una fuente externa. Solo debes elegir un transistor adecuado a la corriente total del proyecto.

Tono y sonido

La función tone(pin, frecuencia) genera una onda cuadrada a la frecuencia indicada usando un temporizador por hardware, ideal para un zumbador pasivo (buzzer sin oscilador interno). Se detiene con noTone(pin).

Un detalle importante: tone() reutiliza el mismo temporizador que los pines PWM 3 y 11. Mientras suena un tono, no uses analogWrite() en esos dos pines, o el tono se distorsionará y el PWM dejará de ser estable.

NotaFrecuencia
DO (C4)262 Hz

MI (E4)330 Hz
FA (F4)349 Hz
SOL (G4)392 Hz

// Melodía de la escala mayor: DO RE MI FA SOL FA MI RE DO
const int BUZZER = 8;

const int DO = 262, RE = 294, MI = 330, FA = 349;
const int SOL = 392, LA = 440, SI = 494, DO5 = 523;

const int MELODIA[] = {DO, RE, MI, FA, SOL, FA, MI, RE, DO};
const int DURACION[] = {300, 300, 300, 300, 600, 300, 300, 300, 600};

void setup() {
  pinMode(BUZZER, OUTPUT);
}

void loop() {
  for (int i = 0; i < 9; i++) {
    tone(BUZZER, MELODIA[i]);
    delay(DURACION[i]);
  }
  noTone(BUZZER);
  delay(1000);   // pausa antes de repetir la melodía
}

Con el temporizador del AVR solo puede sonar un tono a la vez; para notas simultáneas hace falta la librería extra Tone o hardware con más temporizadores. En el montaje usa un buzzer pasivo (no uno activo auto-oscilante) con una pequeña resistencia en serie.

Puedes crear una sirena modulando la frecuencia con un bucle: for (int f = 200; f <= 1500; f++) { tone(BUZZER, f); delay(2); } y después bajándola con otro for.

Errores comunes

1. Usar A0-A5 con analogWrite()

// ❌ A0 no tiene módulo PWM: no sale nada por ahí
analogWrite(A0, 128);

// ✅ Usa un pin con tilde (3, 5, 6, 9, 10 u 11)
analogWrite(9, 128);

2. Esperar un voltaje analógico "de verdad"

Medir el pin con un multímetro da un promedio, no un valor continuo. El PWM es conmutación: si la carga la aprovecha directamente (LED, motor) va perfecto; si necesitas una señal analógica limpia tendrás que filtrarla con un condensador RC.

3. tone() y analogWrite() a la vez en los pines 3 y 11

Comparten temporizador. Mientras suena tone(), el PWM de los pines 3 y 11 queda desactivado. Usa los pines 5, 6, 9 o 10 para el PWM mientras el zumbador toca.

4. Motores conectados al pin sin transistor

El GPIO no entrega corriente suficiente y se funde. Siempre transistor + diodo flyback + fuente externa.

5. Calcular mal el duty

// ❌ "50 %" mal traducido: esto es ~79 % de ciclo de trabajo
analogWrite(9, 200);

// ✅ 50 % de 255 ≈ 128
analogWrite(9, 128);   // 255 × 0,50 = 127,5

6. Delays largos que rompen la fluidez del fade

Con delay(200) dentro del bucle, el LED avanza a saltos bruscos. Para un fundido suave usa retardos de pocos milisegundos (o millis(), como adelantamos en la lección).

El fallo más caro de todos: conectar un motor o un relay de más de ~250 mA directamente al pin. El pin se funde y, en el peor de los casos, el microcontrolador entero queda inservible.

Ejercicios

Para afianzar el PWM, monta y resuelve estos cinco ejercicios en orden de dificultad.

  1. Escala de brillo en 5 pasos: con un LED en el pin 9, sube el brillo en 5 pasos (0 → 64 → 128 → 192 → 255), deja cada uno 500 ms y vuelve a bajar. Guarda los valores en un array y recórrelo con un bucle.
  2. Respiración lenta: modifica el sketch de "luz que respira" para que el ciclo completo dure unos 10 segundos. Calcula el delay() que necesitas en cada paso y verifícalo con un cronómetro.
  3. LED RGB: con un LED RGB de cátodo común en los pines 9, 10 y 11 (resistencia en cada canal), muestra en bucle 5 segundos cada uno: rojo (255,0,0), verde, azul, amarillo (255,255,0), magenta (255,0,255) y blanco (255,255,255).
  4. Velocidad de motor: monta el circuito MOSFET descrito y haz que el motor siga este perfil en bucle: parado 2 s, acelera, velocidad alta durante 3 s, frena suavemente y repite. Mide la corriente consumida con un multímetro en serie.
  5. SOS con zumbador: emite el código Morse internacional SOS con tone() y noTone(): 3 pitidos cortos (200 ms), 3 largos (600 ms) y 3 cortos, separando cada letra con 200 ms de silencio y 800 ms entre rondas.
