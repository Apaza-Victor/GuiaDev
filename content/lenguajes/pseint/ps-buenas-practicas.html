Estructura y estilo del código

Escribir algoritmos claros y ordenados hace que sea más fácil entenderlos, corregirlos y modificarlos. Un buen estilo marca la diferencia.

Buenas prácticas de estilo

PrácticaQué hacerEjemplo
Nombres descriptivosNombra variables según su propósito.precioTotal en vez de pt.
IndentaciónDeja sangría dentro de cada bloque.Contenido de Si/Para hacia dentro.
ComentariosExplica bloques de lógica compleja.// Calcula la nota media.
Una cosa por bloqueSepara acciones con claridad.Leer, procesar y mostrar en pasos.
Constantes para valores fijosNo repitas números mágicos.Definir iva <- 0.21 una sola vez.
Algoritmo CalcularAreaTriangulo
    // Variables bien nombradas
    Definir base, altura, area Como Real

    Escribir "Base del triángulo: "
    Leer base
    Escribir "Altura del triángulo: "
    Leer altura

    // Validación de entrada (no aceptar valores negativos)
    Si base <= 0 O altura <= 0 Entonces
        Escribir "Error: base y altura deben ser positivas"
    SiNo
        area <- (base * altura) / 2
        Escribir "Área = ", area
    FinSi
FinAlgoritmo
Ver código PlantUML 
@startuml
start
:Leer base y altura;
repeat
  if (base > 0) then
    if (altura > 0) then
      :validos = VERDADERO;
    endif
  endif
  if (no validos) then
    :Mostrar "Valores inválidos, repite";
  endif
repeat while (no validos)
:area = (base * altura) / 2;
:Mostrar area;
stop
@enduml

El diagrama anterior muestra una validación con repetición: pide los datos una y otra vez hasta que sean correctos. Este es un patrón muy útil para entrada de datos confiable.

Cómo validar la entrada de datos

Los datos que ingresa el usuario suelen tener errores. Es buena práctica validarlos antes de usarlos: rangos, tipos y valores.

Algoritmo ValidarEdad
    Definir edad Como Entero

    Escribir "Ingresa tu edad (0-120): "
    Leer edad

    Mientras edad < 0 O edad > 120 Hacer
        Escribir "Edad fuera de rango. Reintenta: "
        Leer edad
    FinMientras

    Escribir "Edad válida: ", edad
FinAlgoritmo

Validar la entrada tiene dos ventajas: evitas que el programa se comporte mal y mejoras la experiencia del usuario avisándole del error. Usa Mientras o Repetir para volver a pedir el dato hasta que sea válido.

Depurar un algoritmo en PSeInt

Depurar (debugging) es encontrar y corregir errores. PSeInt tiene herramientas que simplifican esto.

Herramientas de depuración

HerramientaQué hace
Ejecución paso a paso (F8)Ejecuta el código de una línea en una, observando el flujo.
Puntos de interrupciónPausan la ejecución en una línea concreta.
Panel de variablesMuestra los valores actuales de todas las variables.
Vista de seguir algoritmo (F5)Muestra el diagrama de flujo que representa tu algoritmo.
Mensajes de errorIdentifican la línea y el tipo de error (sintaxis o lógica).

Los errores de sintaxis (p. ej. FinSi olvidado) los detecta PSeInt al revisar. Los errores de lógica (p. ej. resultado incorrecto) no dan error, por eso usar Escribir var para ver valores hace faltos o la ejecución paso a paso es clave.

// Truco de depuración rápida: mostrar valores intermedios
Algoritmo DepurarSuma
    Definir n, suma Como Entero
    Escribir "Número: "
    Leer n
    suma <- 0
    Para i <- 1 Hasta n Con Paso 1 Hacer
        suma <- suma + i
        Escribir "En i=", i, " la suma es ", suma   // traza
    FinPara
    Escribir "Total: ", suma
FinAlgoritmo

Errores comunes y cómo evitarlos

Reconocer los fallos típicos te ahorra tiempo. Estos son los más frecuentes en PSeInt:

Errores frecuentes

ErrorCausaSolución
Bucle infinitoFalta actualizar la variable de control.Asegura i <- i + 1 dentro del bucle.
Índice fuera de rangoAccedes a a[n+1].Recorre de 1 a la dimensión.
Variable sin definirUsas edad sin Definir.Declara siempre el tipo antes.
Tipo incorrectoGuardas texto en una variable Entero.Revisa el tipo al definir.
Olvidar FinSi/FinParaNo cierras el bloque.Comprueba que cada bloque tiene su cierre.
Comparar en vez de asignarUsar = donde va <-.Asignación con <-, comparación con =.

Regla de oro: antes de "arreglar" a ciegas, di en voz alta qué esperas que haga cada línea. Muchas veces el error se hace evidente al explicarlo.

Repaso final de PSeInt

Has recorrido las bases de PSeInt. Recuerda el flujo de trabajo completo:

Algoritmo Resumen
    // 1. Definir variables (tipos)
    Definir n, i, suma Como Entero
    // 2. Leer entrada
    Leer n
    // 3. Procesar (asignación, condicionales, bucles)
    suma <- 0
    Para i <- 1 Hasta n Con Paso 1 Hacer
        suma <- suma + i
    FinPara
    // 4. Mostrar salida
    Escribir "Suma: ", suma
FinAlgoritmo

Todos los programas siguen el patrón entrada → proceso → salida. Con PSeInt, además, puedes visualizar tu algoritmo como diagrama de flujo, lo que te prepara para diseñar software en cualquier lenguaje real (Python, Java, C...).
