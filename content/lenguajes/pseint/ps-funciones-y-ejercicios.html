¿Qué es un subproceso?

Un subproceso (o función) es un bloque de código con nombre que puedes usar varias veces. Evita repetir código y hace tus algoritmos mucho más legibles y fáciles de mantener.

En PSeInt las dos palabras clave Funcion y SubProceso son sinónimos. La forma típica para declarar una función que devuelve un valor es:

Funcion resultado <- NombreFuncion (parámetros)
    // cuerpo de la función
    resultado <- valorCalculado
FinFuncion

Las funciones que no devuelven valor (solo realizan una tarea) se declaran como SubProceso:

SubProceso NombreSubproceso (parámetros)
    // acciones
FinSubProceso

Empieza por dividir tu problema en tareas pequeñas y conviértelas en funciones. Es una de las buenas prácticas más importantes de la programación (se llama modularización).

---

Funciones que devuelven valor

Una función recibe parámetros, calcula algo y devuelve un resultado mediante la variable de retorno que declaras junto al nombre.

Algoritmo UsoFuncion
    Definir resultado Como Real

    resultado <- areaCirculo(5)
    Escribir "Área del círculo de radio 5: ", resultado

    Escribir "Área del círculo de radio 7: ", areaCirculo(7)
FinAlgoritmo

Funcion area <- areaCirculo (radio)
    Definir area Como Real
    area <- 3.1416 * radio * radio
FinFuncion

Otro ejemplo que combina varios parámetros:

SubProceso Presentacion (nombre, edad)
    Escribir "Hola, me llamo ", nombre, " y tengo ", edad, " años"
FinSubProceso

Algoritmo Principal
    Definir nom Como Cadena
    Definir ed Como Entero

    nom <- "Ana"
    ed <- 25
    Presentacion(nom, ed)
    Presentacion("Luis", 30)
FinAlgoritmo

Fíjate: defines la función fuera del Algoritmo principal (antes o después de él). Al llamarla escribes su nombre con paréntesis y los argumentos que requiere.

Proyecto integrador: calculadora

Vamos a juntar variables, condicionales, bucles y funciones en un programa que funciona como una calculadora con menú.

Algoritmo Calculadora
    Definir a, b, re Como Real
    Definir opc Como Entero

    Repetir
        Escribir "=== CALCULADORA ==="
        Escribir "1. Sumar    2. Restar"
        Escribir "3. Multiplicar  4. Dividir"
        Escribir "5. Salir"
        Escribir "Elige opción:"
        Leer opc

        Si opc >= 1 y opc <= 4 Entonces
            Escribir "Número 1:"
            Leer a
            Escribir "Número 2:"
            Leer b
        FinSi

        Segun opc Hacer
            1: re <- a + b; Escribir "Resultado: ", re
            2: re <- a - b; Escribir "Resultado: ", re
            3: re <- a * b; Escribir "Resultado: ", re
            4: Si b <> 0 Entonces
                    Escribir "Resultado: ", a / b
               SiNo
                    Escribir "División por cero no permitida"
               FinSi
            5: Escribir "Adiós"
            De Otro Modo: Escribir "Opción no válida"
        FinSegun
        Escribir ""
    Hasta Que opc = 5
FinAlgoritmo

Este programa usa Repetir para el menú, Segun para seleccionar la operación, Si para validar (división por cero) y operadores lógicos (y).

Prueba a extraer la lógica de cada operación a funciones. Por ejemplo, crea Funcion r <- sumar(x, y) y llama sumar(a, b) dentro del Segun.

Análisis de un problema con PSeInt

El flujo típico para resolver un problema con PSeInt es: entender → plantear el algoritmo → codificarlo → probarlo → depurarlo.

// Problema: dado un número N, mostrar si es primo.

Funcion esPrimo <- EsPrimo(n)
    Definir esPrimo Como Logico
    Definir i Como Entero
    Si n < 2 Entonces
        esPrimo <- Falso
    SiNo
        esPrimo <- Verdadero
        i <- 2
        Mientras i <= n - 1 y esPrimo Hacer
            Si n mod i = 0 Entonces
                esPrimo <- Falso
            FinSi
            i <- i + 1
        FinMientras
    FinSi
FinFuncion

Algoritmo Primo
    Definir numero Como Entero
    Escribir "Ingresa un número:"
    Leer numero

    Si EsPrimo(numero) Entonces
        Escribir numero, " es primo"
    SiNo
        Escribir numero, " no es primo"
    FinSi
FinAlgoritmo

Observa el patrón: una función que encapsula el cálculo (EsPrimo) y un algoritmo principal que la usa. Separar la lógica en funciones facilita probar cada parte por separado.
