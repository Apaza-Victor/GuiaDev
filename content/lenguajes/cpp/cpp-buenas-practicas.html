RAII y el C++ moderno

Toda la filosofía del C++ moderno se resume en una idea: la adquisición de un recurso ES la construcción de un objeto, y su liberación ES la destrucción. Si cada memoria, archivo, socket o lock vive dentro de un objeto RAII, los errores de recursos se vuelven imposibles por diseño — no por disciplina.

La regla de cero en acción

// ❌ C++ de los 90: gestión manual frágil
class ReporteViejo {
public:
    ReporteViejo() : datos_{new int[1000]} {}
    ~ReporteViejo() { delete[] datos_; }
    // ¿Copias? ¿Asignaciones? → doble delete esperándote
private:
    int* datos_;
};

// ✅ C++ moderno: regla de CERO — cero código de gestión manual
struct Reporte {
    std::vector<int> datos = std::vector<int>(1000);  // RAII interno
    std::string titulo;
};  // copia, asignación, movimiento y destrucción: TODOS correctos gratis

enum class Color { Rojo, Verde }; no se convierte implícitamente a int (adiós comparar colores con números), std::optional<T> expresa "quizá no hay valor" sin punteros nullptr, y std::variant<A,B> reemplaza uniones inseguras. Tipos ricos = bugs atrapados en compilación.

Compilación y herramientas

Warnings: tu primera línea de defensa

# Configuración base NO negociable:
g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror main.cpp

# -Wall       : advertencias comunes críticas
# -Wextra    : adicionales (signed/unsigned, parámetros sin usar)
# -Wpedantic : rechaza extensiones no estándar
# -Werror    : warnings = errores de compilación (disciplina forzada)

Un warning en C++ casi nunca es estética: suele anunciar comportamiento indefinido, truncamiento silencioso o bug lógico real. Proyectos serios tratan -Werror como obligatorio desde el primer commit.

Sanitizers: detectores de runtime integrados

SanitizerFlagDetecta
ASan-fsanitize=addressFugas, use-after-free, buffer overflow, doble free
UBSan-fsanitize=undefinedOverflow signed, divisiones por cero, casts inválidos
TSan-fsanitize=threadCarreras de datos entre threads
 
# Ejecutar TU SUITE con ASan+UBSan es el hábito #1 de calidad:
g++ -std=c++20 -g -fsanitize=address,undefined tests.cpp && ./a.out
# ERROR: AddressSanitizer: heap-use-after-free ... ← línea exacta, stack completo

Const-correctness: contratos en las firmas

class Inventario {
public:
    // const al FINAL: promete no modificar this — exigible desde contextos const
    [[nodiscard]] size_t totalUnidades() const;

    // const& en parámetros: sin copia, sin mutación
    void agregar(const std::string& producto, int unidades);

    // constexpr donde aplique: cálculo movido a compilación
    [[nodiscard]] static constexpr int limiteMaximo() { return 1'000'000; }
};

// const local: intención documentada + optimizaciones
const auto total = inventario.totalUnidades();  // nadie lo cambia después

Ninguna herramienta sustituye pensar, pero todas multiplican tu capacidad de detectar errores ANTES de producción. Un proyecto C++ profesional moderno combina: estándar reciente + warnings estrictos + sanitizers en CI + formato/linting automáticos. Ese combo convierte al "C++ peligroso" de leyenda en un lenguaje industrial controlable.

Ejercicios prácticos

  1. Auditoría personal: toma un ejercicio anterior tuyo de esta serie y pásale clang-tidy + cppcheck; corrige TODO lo reportado y documenta los 3 hallazgos más interesantes.
  2. Modernizador: reescribe una clase con new/delete crudo usando regla de cero (vector + string); verifica con ASan que ambos versiones pasan tus tests.
  3. Cazador de UB: programa deliberadamente 5 UB distintos (signed overflow, uso tras delete, índice fuera de rango...); ejecuta con UBSan/ASan y captura el reporte de cada uno en comentarios.
  4. Setup profesional: monta CMake mínimo + .clang-format + targets con -Wall -Wextra -fsanitize para un proyecto de dos archivos; compila y ejecuta sus tests.
  5. Revisión cruzada: intercambia código con otro estudiante si es posible; aplica la checklist final de la lección como rúbrica y reporta hallazgos por área.
