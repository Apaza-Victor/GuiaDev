Tipos fundamentales y sizeof

C++ es un lenguaje estáticamente tipado: cada variable tiene un tipo fijo en compilación, y ese tipo determina su tamaño en memoria, sus operaciones válidas y su comportamiento al desbordar. A diferencia de Java o C#, el estándar NO fija los tamaños exactos (solo garantías mínimas y relaciones), lo que hace que el código serio consulte sizeof o use tipos de ancho explícito.

int16_t  chico  = 32000;          // exactamente 16 bits

Los separadores de dígitos ' (C++14) hacen legibles los literales grandes: 1'000'000. Y para código portable usa siempre los alias de <cstdint>: int32_t, uint64_t… El long de Windows es 32 bits mientras en Linux es 64: bug clásico multiplataforma.

Punto flotante y la trampa del 0.1

float (~7 dígitos) y double (~15 dígitos) siguen IEEE 754: binario incapaz de representar exactamente decimales como 0.1:

double a = 0.1 + 0.2;
std::cout << std::setprecision(20) << a << "\n";
// 0.30000000000000004441 — nunca compares floats con ==

if (std::abs(a - 0.3) < 1e-9) {  // comparación con tolerancia
    std::cout << "suficientemente igual\n";
}

NUNCA uses float/double para dinero. Un centavo no existe en binario IEEE 754. Usa enteros contando céntimos, o librerías decimales especializadas.

auto y decltype: deducción de tipos

C++11 introdujo auto: el compilador deduce el tipo del inicializador. No es tipado dinámico — el tipo es único y fijo desde compilación:

auto i = 42;              // int
auto d = 3.14;            // double
auto s = std::string{"hi"}; // std::string
auto it = mapa.begin();   // std::map<K,V>::iterator — ¡imposible escribir a mano!

auto suma(int a, double b) -> double { return a + b; } // trailing return
decltype(i) copia = 10;   // "el mismo tipo que i"

auto x = {1, 2, 3}; deduce std::initializer_list<int>, no un array. Y auto descarta referencias y const por defecto: auto c = v[0] sobre un vector de strings COPIA el string. Para no copiar: auto& o const auto&.

const vs constexpr

Ambas palabras evitan modificaciones, pero significan cosas distintas. Dominar la diferencia es señal de madurez en C++ moderno:

Característicaconstconstexpr
"No puedo modificarlo tras crear"SíSí
Valor calculado en COMPILACIÓNNo necesariamenteRequerido
Válido para funcionesNoSí (funciones evaluables en compile-time)
Tamaño de arrays estáticos / parámetros templateA vecesSiempre
Uso típicoParámetros inmutables, punteros constConstantes matemáticas, tablas precalculadas
 
// const: solo promete no modificar
int pedirEdad();
const int edad = pedirEdad(); // OK: se calcula en RUNTIME

// constexpr: GARANTIZA compilación
constexpr int TAMANO = 64;
constexpr double PI = 3.14159265358979;
constexpr int cuadrado(int x) { return x * x; }  // función constexpr
constexpr int TABLA[TAMANO] = {};                 // array estático legal

static_assert(cuadrado(8) == 64, "matemática rota"); // verificado AL COMPILAR

Regla práctica moderna: constantes globales → constexpr. Parámetros y locales que no mutan → const. Si algo puede ser constexpr, hazlo constexpr: el trabajo desaparece del runtime gratis.

Conversiones: static_cast y compañía

Los casts estilo C ((int)x) funcionan pero ocultan qué tipo de conversión ocurre. C++ tiene cuatro casts explícitos:

CastPropósitoEjemplo
static_castConversiones comprobables en compilaciónstatic_cast<double>(total) / n
dynamic_castBajada segura en jerarquías polimórficas (RTTI)dynamic_cast<Perro*>(animal) → nullptr si no
const_castQuitar/añadir const (raro, peligroso)Interfaz legacy sin const
reinterpret_castReinterpretar bits crudos (systems programming)Bytes ↔ punteros hardware
 
int total = 17;
int cantidad = 4;
double promedio = static_cast<double>(total) / cantidad; // 4.25
// SIN cast: 17/4 == 4 (división entera silenciosa — bug #1 de novatos)

std::string: texto sin dolor

std::string gestiona memoria automáticamente: crece, copia y libera sola. Olvida los char[] y strcpy de C salvo en APIs de sistema:

#include <string>

std::string nombre = "Ada";
nombre += " Lovelace";                    // concatenación in-place
std::string completa = nombre + " (1815)";

// Consulta
bool vacia = nombre.empty();
size_t len = nombre.length();             // == nombre.size()
char primera = nombre[0];                 // 'A' — sin chequeo
char segura  = nombre.at(999);            // lanza std::out_of_range

// Búsqueda
size_t pos = nombre.find("Love");
if (pos != std::string::npos) {
    std::cout << "Encontrada en índice " << pos << "\n";
}

// Extracción y modificación
std::string apellido = nombre.substr(4, 8); // "Lovelace"
nombre.replace(0, 3, "ADA");                // reemplaza rango

Construcción con formato

#include <sstream>

std::ostringstream oss;
oss << "Usuario " << nombre << " tiene " << 42 << " mensajes";
std::string mensaje = oss.str();

// C++20: std::format (tipo Python f-strings)
std::string m2 = std::format("Usuario {} tiene {} mensajes", nombre, 42);

string_view: pasar texto sin copiar

Cada paso de std::string por valor copia. std::string_view (C++17) es una vista ligera (puntero + longitud) sobre texto existente — acepta string, literal y char* sin una sola copia:

#include <string_view>

void imprimir(std::string_view sv) {   // NO copia nada
    std::cout << sv << '\n';
}

std::string largo(1000, 'x');
imprimir(largo);            // sin copia
imprimir("literal directo"); // sin copia
imprimir(largo.substr(0, 5)); // substr de string_view: O(1), sin copia

Un string_view NO posee sus datos. Guardarlo más allá de la vida del original (retornarlo de una función que creó el string local) es use-after-free garantizado. Regla: parámetros de entrada → string_view; almacenamiento propio → std::string.

Compila siempre con advertencias agresivas (-Wall -Wextra): la mayoría de estos errores produce warnings detectables. Ignorar warnings en C++ es programar con los ojos cerrados.

Ejercicios prácticos

  1. Inspector de tipos: imprime sizeof de todos los tipos fundamentales en tu plataforma; verifica las garantías mínimas de la tabla y documenta sorpresas (ej: long en Windows).
  2. Detector de palíndromos: función bool esPalindromo(std::string_view) que ignore mayúsculas y espacios; pruébala con "Anita lava la tina".
  3. Parser robusto de enteros: implementa std::optional<int> parseEntero(std::string_view) usando from_chars; debe rechazar "12abc", vacío y overflow, aceptar "-45".
  4. Constantes compile-time: crea tabla constexpr de factoriales hasta 12! con static_assert de verificación; imprímela en runtime.
  5. Cazador de bugs: escribe un programa con división entera accidental, comparación == de doubles y bucle signed/unsigned; corrige cada uno con la técnica correspondiente comentando el antes/después.
