Punteros: la dirección importa

Un puntero es una variable cuyo valor es una dirección de memoria. Es el concepto que más asusta a los recién llegados de Python o JavaScript, pero su lógica es simple: si una variable normal guarda un dato, el puntero guarda DÓNDE vive ese dato. Con él puedes leer, escribir y compartir objetos sin copiarlos.

Dirección (&) e indirección (*)

int edad = 42;

int* ptr = &edad;   // ptr GUARDA la dirección donde vive 'edad'
                    // & = "dirección de"

std::cout << ptr   << "\n"; // 0x7ffd3b2a — la dirección
std::cout << *ptr  << "\n"; // 42 — "lo APUNTADO" (desreferenciar)
std::cout << &ptr  << "\n"; // otra dirección: la del propio puntero

*ptr = 100;         // escribir A TRAVÉS del puntero
std::cout << edad;  // 100 — ¡es la misma memoria!
SímboloContextoLectura mental
T*Declaración"puntero a T"
&xExpresión"la dirección de x"
*pExpresión"el objeto apuntado por p"

nullptr: la ausencia honesta

int* p = nullptr;      // C++11: cero tipado para punteros

if (p != nullptr) {    // o simplemente if (p)
    std::cout << *p;
} else {
    std::cout << "no apunta a nada\n";
}

// Desreferenciar nullptr = CRASH inmediato (segfault):
// std::cout << *p;    // ¡no lo hagas!

Nunca uses NULL ni 0 en código moderno: nullptr es tipado y evita ambigüedades en sobrecargas (f(NULL) podía llamar a la versión int!). Y verifica SIEMPRE antes de desreferenciar punteros cuya procedencia no controlas.

Aritmética de punteros y arrays

int datos[5] = {10, 20, 30, 40, 50};
int* p = datos;          // arrays decaen a puntero al primer elemento

std::cout << *p       << "\n"; // 10
std::cout << *(p + 2) << "\n"; // 30 — avanza 2 ELEMENTOS (8 bytes de int)
std::cout << p[3]     << "\n"; // 40 — ¡v[i] ES *(v+i)!

// Recorrer con puntero:
for (int* q = datos; q != datos + 5; ++q) {
    std::cout << *q << ' ';
}

La aritmética fuera de rango (p + 99) es comportamiento indefinido: puede "funcionar" hoy y corromper memoria mañana con otro compilador. En aplicación moderna usa std::array/std::vector con ranged-for y deja los punteros crudos para interoperar con APIs C.

Regla de oro del C++ moderno: vive en el stack siempre que puedas. El heap solo para tamaños desconocidos en compilación, objetos enormes, o vida útil que cruza scopes — y entonces, casi siempre detrás de un smart pointer.

Memoria dinámica y smart pointers

El modelo manual: new/delete y sus peligros

int* p = new int(42);      // reservar E inicializar
delete p;                  // liberar EXACTAMENTE UNA vez

auto* arr = new int[100];
delete[] arr;              // arrays usan delete[]

// Los tres caballos de Apocalipsis del heap:
// 1) FUGA: olvidar delete → memoria perdida hasta fin de proceso
// 2) DOBLE DELETE: dos deletes → corrupción del heap
// 3) USE-AFTER-FREE: usar tras delete → UB, exploits reales

void fuga() {
    int* datos = new int[1'000'000];
    if (error_ocurrido) {
        return;            // 💥 4MB fugados: delete nunca alcanzado
    }
    delete[] datos;
}

RAII: la idea que salva al C++

Resource Acquisition Is Initialization: envuelve cada recurso (memoria, archivo, mutex, socket) en un objeto cuyo destructor lo libera. Como C++ destruye locales AUTOMÁTICAMENTE al salir del scope — incluso con exceptions — las fugas se vuelven estructuralmente imposibles:

class ArchivoSeguro {
public:
    explicit ArchivoSeguro(const std::string& ruta) : f_(ruta) {}
    ~ArchivoSeguro() { f_.close(); }          // SE EJECUTA SIEMPRE
    ArchivoSeguro(const ArchivoSeguro&) = delete;             // sin copias
    ArchivoSeguro& operator=(const ArchivoSeguro&) = delete;

    std::fstream& get() { return f_; }
private:
    std::fstream f_;
};

void procesar() {
    ArchivoSeguro log("app.log");   // adquirido
    if (algo_falla()) throw std::runtime_error("boom");
                                    // destructor cierra IGUALMENTE ✅
}

Smart pointers: RAII empaquetado

Los punteros inteligentes aplican RAII a la memoria dinámica. Son punteros que destruyen automáticamente lo que poseen:

Smart pointerPropiedadCosteÚsalo cuando
std::unique_ptr<T>Exclusiva: uno solo dueñoCero overhead vs puntero crudoSIEMPRE que haya UN dueño claro (90% de casos)
std::shared_ptr<T>Compartida: contador de referenciasBloque de control + atómicos (~doble)Varios dueños reales con vidas impredecibles
std::weak_ptr<T>Ninguna: observa sin retenerMínimoRomper ciclos shared_ptr; cachés
 
#include <memory>

// unique_ptr: creación moderna (C++14)
auto perro = std::make_unique<Perro>("Rex");
perro->ladrar();
// auto copia = perro;             ❌ NO compila: propiedad exclusiva
auto robado = std::move(perro);    // ✅ transferencia EXPLÍCITA
// perro ahora es nullptr — quedó documentado en el código

// Al salir del scope, make_unique hace delete AUTOMÁTICAMENTE.
// La función fuga() de arriba, arreglada:
void sinFuga() {
    auto datos = std::make_unique<int[]>(1'000'000);
    if (error_ocurrido) return;     // liberado igualmente ✅
}

// shared_ptr: cuenta referencias
auto compartido = std::make_shared<Perro>("Luna");
std::cout << compartido.use_count(); // 1
auto otro = compartido;              // count = 2
otro.reset();                        // count = 1
// El último shared_ptr en morir borra el Perro.

El ciclo clásico y weak_ptr

struct Nodo {
    std::shared_ptr<Nodo> siguiente;   // ⚠️ A→B y B→A = NUNCA se liberan
    std::weak_ptr<Nodo>   padre;       // ✅ referencia que NO retiene
};

// Usar un weak_ptr exige verificar que siga vivo:
if (auto vivo = nodo->padre.lock(); vivo) {
    vivo->marcar();    // seguro: lock() devuelve shared_ptr temporal
}

Firmas modernas que comunican propiedad: unique_ptr<T> retornado = "tú eres dueño"; unique_ptr<T>& param = "uso tu objeto"; T* param = "solo miro, no gestiono vida"; shared_ptr<T> param = "me quedo una copia". El tipo DOCUMENTA la arquitectura.

Ejecuta tus tests con sanitizers: -fsanitize=address detecta fugas y use-after-free EN EL MOMENTO exacto, señalando línea y archivo. Es como tener valgrind integrado en el compilador.

Ejercicios prácticos

  1. Explorador de direcciones: imprime valores y direcciones de tres variables y sus punteros; modifica a través de punteros y verifica los cambios; comenta qué dirección pertenece a stack.
  2. Cazador de fugas: escribe una función con fuga deliberada (early return tras new), compila con -fsanitize=address, observa el reporte y corrígela con make_unique.
  3. Transferencia de propiedad: modela una "caja fuerte" con unique_ptr que pasa entre tres funciones mediante move; imprime use/validity en cada etapa.
  4. Árbol sin fugas: implementa nodo de árbol binario con unique_ptr hijos y weak_ptr padre; inserta, recorre y verifica con ASan que todo se libera al destruir la raíz.
  5. RAII casero: crea clase TempGuard que imprima "adquirido"/"liberado" en constructor/destructor; lánzala dentro de funciones con throws tempranos y demuestra que libera SIEMPRE.
