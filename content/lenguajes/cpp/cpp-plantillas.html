Plantillas de función

Una plantilla es un molde que el compilador instancia: escribes el algoritmo UNA vez con tipos como parámetros, y el compilador genera la versión concreta para cada tipo usado. No hay coste en runtime — el código generado es idéntico al que habrías escrito a mano, pero sin duplicación en tu fuente.

Tu primera plantilla

template <typename T>          // "para todo tipo T..."
T maximo(const T& a, const T& b) {
    return (a > b) ? a : b;
}

int     i = maximo(3, 9);       // T = int      → genera versión int
double  d = maximo(2.5, 1.8);   // T = double   → otra versión
std::string s = maximo(std::string{"pera"}, std::string{"manzana"});
// tres funciones reales, generadas automáticamente

typename y class en el parámetro son intercambiables (template <class T>). Convención moderna: typename para tipos cualquiera; class cuando exiges un concepto/clase.

Múltiples parámetros y deducción mixta

template <typename T, typename U>
auto sumar(const T& a, const U& b) -> decltype(a + b) {
    return a + b;               // decltype deduce el tipo RESULTANTE de a+b
}

auto x = sumar(3, 4.5);         // double: int + double promociona

// Forzar tipo común explícito:
template <typename T>
T promedio(const std::vector<T>& v) {
    static_assert(!v.empty() || true);   // verificaciones en compilación
    return std::accumulate(v.begin(), v.end(), T{}) / static_cast<T>(v.size());
}

Parámetros NO-tipo

Las plantillas aceptan también valores de compilación — tamaños, flags — convirtiéndose en configuración cero-coste:

template <typename T, size_t N>
constexpr size_t longitud(const T (&)[N]) { return N; }   // N deducido del array

int datos[42];
static_assert(longitud(datos) == 42);

template <bool CON_LOG>
void procesar(int x) {
    if constexpr (CON_LOG) {              // if constexpr: rama MUERTA eliminada
        std::cout << "procesando " << x << '\n';
    }
}
procesar<true>(5);    // con log
procesar<false>(5);   // compilado SIN ninguna instrucción de logging

Las plantillas viven en HEADERS por definición: el compilador necesita su cuerpo completo para instanciarlas en cada unidad de traducción. Separarlas en .cpp rompe el link ("undefined reference") salvo especializaciones explícitas.

Plantillas de clase, CTAD y concepts

Clases genéricas: contenedores propios

template <typename T>
class Pila {
public:
    void push(const T& valor) { datos_.push_back(valor); }
    void pop()                { datos_.pop_back(); }          // ¡vacía = UB! ver abajo
    [[nodiscard]] const T& top() const { return datos_.back(); }
    [[nodiscard]] bool empty() const { return datos_.empty(); }
    [[nodiscard]] size_t size() const { return datos_.size(); }

private:
    std::vector<T> datos_;     // composición: la STL hace el trabajo duro
};

Pila<int>    pi;             // pila de enteros
Pila<std::string> ps;        // ...de strings
pi.push(42);
ps.push("hola");

CTAD: deducción del template de CLASE (C++17)

std::pair p{1, 2.5};            // pair<int,double> — sin <>
std::vector v{1, 2, 3};         // vector<int>
std::lock_guard lg(mtx);        // lock_guard<mutex>

// Con guía propia:
template <typename T>
struct Caja { T valor; explicit Caja(T v) : valor{std::move(v)} {} };
Caja c{42};                     // Caja<int> deducida ✅

Concepts: requisitos EXPLÍCITOS (C++20)

El problema histórico: una plantilla compila… hasta que alguien le pasa un tipo sin las operaciones necesarias, y el error ocupa 200 líneas. Los concepts declaran los REQUISITOS formalmente:

#include <concepts>

// Concept propio: "T sabe sumarse consigo mismo"
template <typename T>
concept Sumable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;
};

// Usar el concept: error claro SI el tipo no cumple
template <Sumable T>                       // restricción directa
T acumular(const std::vector<T>& v) {
    T total{};
    for (const auto& x : v) total += x;
    return total;
}

// O con requires-clause:
template <typename T>
requires std::integral<T> || std::floating_point<T>
T doble(T x) { return x * 2; }

doble(21);        // ✅ integral
doble(3.14);      // ✅ floating_point
// doble(std::string{}); ❌ ERROR LEGIBLE: string no es integral ni FP
// Concepts predefinidos: same_as, derived_from, movable, equality_comparable...

Especialización: casos particulares

// Genérica:
template <typename T>
struct Serializador {
    static std::string serializar(const T& v) { return "<" + std::to_string(v) + ">"; }
};

// ESPECIALIZACIÓN TOTAL para bool:
template <>
struct Serializador<bool> {
    static std::string serializar(bool v) { return v ? "sí" : "no"; }
};

Serializador<int>::serializar(42);    // "<42>"
Serializador<bool>::serializar(true); // "sí" — ruta especial

Variádicas: número libre de argumentos

template <typename... Args>                 // pack de parámetros
auto contarYSumar(Args... args) {
    return ((args + 0) + ...);              // fold expression C++17: suma todos
}

contarYSumar(1, 2, 3);            // 6
contarYSumar(1.5, 2.0, 3.5, 4.0); // 11.0 — cualquier cantidad, cualquier mezcla
// Así funciona internamente make_unique<T>(args...) pasando constructores

Todo el ecosistema STL ES templates: vector<T>, function<R(Args...)>, unique_ptr<T>. Entender plantillas no es tema avanzado opcional — es leer la firma de lo que ya usas todos los días.

Ejercicios prácticos

  1. min/max/abs genéricos: implementa los tres como templates con concept Number (integral | floating_point) y pruébalos con int, double y char.
  2. Pila acotada: extiende Pila<T, size_t Capacidad> con parámetro NO-tipo que lance/rechace push cuando esté llena; static_assert de capacidad positiva.
  3. Serializador con especializaciones: template base + especializaciones para std::string, bool y std::vector<T> recursivo (usa la plantilla dentro de la especialización).
  4. Fold expressions: implementa imprimirTodos(args...) que imprima cada argumento separado por comas, y sumaCuadrados(args...).
  5. Cazador de errores pre-C++20 vs C++20: llama doble(std::string{}) sin concept (guarda el muro de errores) y luego con concept; compara ambos mensajes en comentario.
