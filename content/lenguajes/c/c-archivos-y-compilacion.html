Manejo de archivos: fopen, fread, fwrite

Escribir y leer archivos en disco hace tus programas útiles: guardan datos entre ejecuciones. La biblioteca stdio.h ofrece fopen (abrir), fread y fwrite (bloques binarios), fprintf y fgets (texto) y fclose (cerrar).

#include <stdio.h>

int main(void) {
    FILE *archivo = fopen("datos.txt", "w");

    if (archivo == NULL) {
        printf("No se pudo abrir el archivo\n");
        return 1;
    }

    fprintf(archivo, "Nombre: Ana\n");
    fprintf(archivo, "Edad: %d\n", 21);
    fclose(archivo);               // siempre cerrar

    // Ahora lo leemos y lo mostramos en pantalla
    archivo = fopen("datos.txt", "r");
    char linea[100];
    while (fgets(linea, sizeof(linea), archivo) != NULL) {
        printf("%s", linea);
    }
    fclose(archivo);
    return 0;
}
ModoSignificadoSi no existe
"r"LecturaError (NULL)
"w"Escritura (borra el contenido)Lo crea
"a"Añadir al finalLo crea
"r+", "w+", "a+"Combinaciones de lectura y escrituraVaría según el modo

Comprueba siempre que fopen no devuelva NULL: una ruta equivocada o la falta de permisos hace fallar la apertura sin avisar.

Para datos binarios (imágenes, buffers, structs serializados) se usan fread y fwrite, que trabajan con bloques de sizeof bytes.

Argumentos por línea de comandos: argc y argv

Todo programa puede recibir parámetros al ser lanzado desde la terminal. argc cuenta los argumentos (el nombre del programa siempre es el primero) y argv es un arreglo de cadenas con los valores.

#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[]) {
    int i;

    printf("Número de argumentos: %d\n", argc);
    for (i = 0; i < argc; i++) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }

    if (argc > 1 && strcmp(argv[1], "--ayuda") == 0) {
        printf("Uso: programa [archivo]\n");
    }
    return 0;
}

Compila y ejecuta pasando argumentos; por ejemplo, ./programa datos.txt imprime argv[1] = datos.txt.

VariableQué contiene
argcNúmero total de argumentos (incluido el programa)
argv[0]Nombre del programa ejecutado
argv[1]Primer argumento de la línea de comandos

En main(int argc, char *argv[]), argv es un arreglo de punteros a char: cada cadena termina en '\0', como toda cadena de C. Es una primera muestra real de arreglos de punteros.

Compilar múltiples archivos y Makefile

Los proyectos reales se dividen en varios archivos .c y .h. Cada .c se compila a un objeto .o y, al final, el enlazador une todos los objetos en un único ejecutable. La ventaja: al cambiar un solo archivo, solo se recompila ese.

# Compilar (sin enlazar) cada archivo por separado
gcc -c main.c -o main.o
gcc -c utilidades.c -o utilidades.o

# Enlazar los objetos en un único ejecutable
gcc main.o utilidades.o -o programa

# Ejecutar
./programa

Hacer esto a mano es tedioso. La herramienta make automatiza la tarea leyendo un archivo llamado Makefile. Cada regla dice qué depende de qué, y make reconstruye solo lo necesario:

CC = gcc
CFLAGS = -Wall -Wextra

programa: main.o utilidades.o
	$(CC) main.o utilidades.o -o programa

main.o: main.c utilidades.h
	$(CC) $(CFLAGS) -c main.c

utilidades.o: utilidades.c utilidades.h
	$(CC) $(CFLAGS) -c utilidades.c

clean:
	rm -f *.o programa

En un Makefile, la línea que ejecuta el comando de cada regla debe empezar con un tabulador, no con espacios. Es el error más común al escribir el primer Makefile.

El comando make sin argumentos construye la primera regla del archivo. La regla clean se invoca con make clean para eliminar objetos y ejecutables.

El preprocesador y las cabeceras

Antes de compilar, el preprocesador procesa las directivas que empiezan con #: incluye archivos, define constantes y macros, y decide qué bloques se compilan. Puedes inspeccionar su resultado con gcc -E programa.c.

DirectivaQué haceEjemplo
#includeCopia el contenido de un archivo#include <stdio.h>
#defineDefine una constante o macro#define MAXIMO 100
#ifdef ... #endifCompila el bloque solo si algo está definido#ifdef DEBUG
#ifndef ... #defineGuarda contra la doble inclusión#ifndef UTILIDADES_H

La forma clásica de evitar que una misma cabecera se incluya dos veces son las header guards:

#ifndef UTILIDADES_H
#define UTILIDADES_H

int sumar(int a, int b);
double promedio(double a, double b);

#endif  /* UTILIDADES_H */

Si una cabecera se incluye dos veces, sus funciones se declaran dos veces y las definiciones duplicadas pueden hacer fallar el enlazador. Las guards son la protección estándar contra ese problema.

Depuración con gdb y sanitizers

Un error de lógica no produce aviso del compilador: el programa "compila bien" y falla al ejecutarse. Para esos casos existen dos aliados: el depurador gdb y los sanitizers de GCC/Clang, que instrumentan el programa para detectar errores de memoria en tiempo real.

Herramienta / comandoQué permite ver
gcc -g programa.c -o programaGenera símbolos de depuración
gdb ./programaAbre el depurador interactivo
break mainPone un punto de ruptura en main
runEjecuta hasta el primer punto de ruptura
next / stepAvanza línea a línea
print variableMuestra el valor de una variable
gcc -fsanitize=addressDetecta accesos fuera de límites y fugas

Compila en desarrollo con gcc -Wall -Wextra -g: las advertencias evitan errores y los símbolos -g hacen posible el depurado con gdb.

La combinación valgrind + sanitizers + gdb cubre la práctica totalidad de errores de memoria y lógica que un programador de C puede cometer.

Ejercicios prácticos

  1. Escribe un programa que guarde 10 números en numeros.txt y luego los lea e imprima su suma.
  2. Crea un programa con argc y argv que reciba un nombre de archivo y un modo ("leer" o "escribir"), y acepte o rechace la operación con un mensaje.
  3. Divide tu ejercicio anterior en main.c, utilidades.c y su cabecera utilidades.h, y compílalo con gcc en dos pasos.
  4. Escribe un Makefile para ese programa con reglas para cada objeto, la regla principal y un objetivo clean.
  5. Depura un programa que falle con -fsanitize=address y, si tienes valgrind, confirma que no hay fugas al finalizar.

Con esta lección completas la base del lenguaje C: ya puedes escribir programas que interactúan con el sistema, organizar proyectos y depurarlos con criterio.
