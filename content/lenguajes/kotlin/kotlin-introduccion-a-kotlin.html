¿Qué es Kotlin?

Kotlin es un lenguaje de programación moderno, estáticamente tipado y multiparadigma creado por la empresa JetBrains en 2011 (su primera versión oficial estable llegó en 2016). El nombre proviene de la isla de Kotlin, cerca de San Petersburgo, siguiendo la tradición de JetBrains de nombrar sus tecnologías por islas. El objetivo del equipo era resolver un problema muy concreto: los desarrolladores Java vivían frustrados con la verbosidad y las trampas del propio Java (los famosos NullPointerException entre ellas), pero no podían abandonar el enorme ecosistema que ya tenían construido.

La solución fue un lenguaje que compila al mismo bytecode que Java, se ejecuta sobre la misma máquina virtual (la JVM) y puede mezclarse libremente con código Java existente en el mismo proyecto. Así puedes adoptar Kotlin archivo por archivo, sin reescribir nada. Este pragmatismo explica su éxito: Google lo declaró lenguaje oficial para Android en 2017, y hoy es la opción recomendada para apps móviles, backend con Spring Boot o Ktor, scripts de construcción en Gradle y hasta desarrollo multiplataforma.

Kotlin es gratuito y open source desde su nacimiento (licencia Apache 2.0), administrado por la fundación Kotlin Foundation junto a JetBrains y Google.

Ejemplo: menos código para lo mismo

// Java: una clase POJO típica requiere constructor, getters y setters (~30 líneas)

// Kotlin: lo equivalente cabe en una línea
data class Usuario(val nombre: String, var edad: Int)

fun main() {
    val u = Usuario("Ana", 30)   // no necesita "new"
    println(u.nombre)            // getter generado automáticamente
}

Dónde corre Kotlin: JVM, Android, JS, Native y multiplataforma

Kotlin es un lenguaje multiobjetivo: el mismo código fuente puede compilarse a distintos destinos según dónde vaya a ejecutarse. Esto significa que tu inversión en aprenderlo se traslada casi completa a cualquier dominio de la industria.

DestinoCompila a…Casos de uso típicos
JVMBytecode de JavaBackend (Spring Boot, Ktor), aplicaciones de escritorio, herramientas CLI
AndroidBytecode (ART/Dalvik)Apps móviles nativas: lenguaje recomendado por Google desde 2019
JSJavaScript ES5+Frontend web, compartir lógica con el navegador
NativeBinario nativo (LLVM)iOS, Linux, macOS, Windows sin necesidad de JVM
MultiplatformVarios a la vezCompartir lógica de negocio entre iOS/Android/servidor escribiéndola una vez

Si vienes de Java, tu curva de aprendizaje será corta: la mayoría de conceptos (clases, interfaces, colecciones, excepciones) existen igual, solo cambia la sintaxis y algunas reglas nuevas como la null-safety.

Ejemplo: mismo lenguaje, distintos mundos

// Esta función pura funciona idéntica en JVM, JS y Native
fun calcularDescuento(precio: Double, porcentaje: Int): Double {
    require(porcentaje in 0..100) { "El porcentaje debe estar entre 0 y 100" }
    return precio * (100 - porcentaje) / 100
}

// En Android se usa igual para lógica de ViewModel,
// en backend para servicios REST y en iOS vía Kotlin Multiplatform.

Interoperabilidad total con Java

La interoperabilidad no es una característica secundaria: es el corazón del diseño de Kotlin. Un proyecto Android moderno mezcla archivos .kt y .java sin fricción; una clase escrita en Kotlin extiende clases de Java, implementa interfaces Java y usa colecciones Java como si fueran propias. Y en sentido inverso, el código Java consume clases Kotlin sin enterarse de que no son Java (con matices que verás en la lección de interoperabilidad).

// Usando clases 100% Java desde Kotlin, sin adaptadores raros
import java.time.LocalDate

fun main() {
    val hoy: LocalDate = LocalDate.now()          // clase Java usada con naturalidad
    val lista = java.util.ArrayList<String>()     // colección Java
    lista.add("Kotlin habla con Java")

    println("${hoy.year} -> ${lista[0]}")         // 2026 -> Kotlin habla con Java
}

Ojo con una diferencia clave: Kotlin no tiene primitivos "crudos" ni operadores sobrecargados limitados — puedes definir tus propios operadores — pero sí mantiene el rendimiento porque el compilador genera primitivos JVM automáticamente cuando puede.

Variables: val y var

En Kotlin toda variable se declara con dos palabras posibles: val (solo lectura, como una constante local) y var (reasignable). La recomendación oficial es clara: usa val por defecto y recurre a var solo cuando realmente necesites cambiar el valor. La inmutabilidad reduce los estados posibles de tu programa, facilita razonar sobre el código y evita bugs sutiles donde otra parte del programa modificó la variable sin que lo supieras.

val lenguaje = "Kotlin"        // solo lectura: no se puede reasignar
// lenguaje = "Java"           // ERROR: Val cannot be reassigned

var contador = 0               // reasignable
contador += 1                  // correcto

val piAproximado = 3.1416      // tipo inferido: Double
val saludoExplicito: String = "Hola"   // tipo declarado explícitamente

// Nota: "val" congela la REFERENCIA, no siempre el contenido interno
val listaVal = mutableListOf(1, 2)
listaVal.add(3)                // permitido: mutamos el objeto, no la variable
// listaVal = mutableListOf() // esto sí sería un error

Inferencia de tipos

El compilador deduce el tipo a partir del valor inicial, así que escribir el tipo explícito suele ser innecesario. Declararlo ayuda como documentación cuando el valor viene de una expresión poco obvia.

val anio = 2026                  // Int inferido
val factor = 1.5                 // Double inferido
val iniciales = listOf('G', 'D') // List<Char> inferido

val promedio: Double = listOf(8, 9, 10).average()  // explícito: más legible aquí

Activa en IntelliJ IDEA la inspección "Declare explicitly or use val": el IDE te sugiere convertir var en val cuando detecta que nunca reasignas la variable.

Tu primer programa y cómo ejecutarlo

Todo programa Kotlin comienza en una función main, que puede declararse sin parámetros ni clase envolvente. Compara esto con Java, donde necesitas una clase pública con public static void main(String[] args).

// hola.kt
fun main() {
    println("Hola, GuiaDev!")
}

// Variante con argumentos de línea de comandos
fun main(args: Array<String>) {
    println("Recibidos ${args.size} argumentos")
}

// Desde Kotlin 1.3+ existe también main de una sola expresión
fun main() = println("Programa mínimo")

# Compilar a un JAR autoejecutable (-include-runtime embebe la runtime de Kotlin)
kotlinc hola.kt -include-runtime -d hola.jar

# Ejecutar el JAR con cualquier JVM instalada
java -jar hola.jar

# Alternativa rápida: script directo (compila y corre sin generar JAR)
kotlinc hola.kt -script

Buenas prácticas desde tu primer día

Adoptar convenciones desde el inicio evita reaprender después. Estas son las señales de un programador Kotlin maduro, aplicables incluso a tu primer "Hola mundo".

PrácticaRazón
Prefiere val antes que varMenos estado mutable, menos bugs difíciles de rastrear
Deja que el compilador infiera el tipoCódigo más limpio; declara solo cuando aporta claridad
Nombres en camelCase descriptivosprecioFinal comunica; x obliga a leer contexto
Una responsabilidad por funciónFunciones pequeñas se testean y reutilizan mejor
Comenta el PORQUÉ, no el QUÉEl código dice qué hace; el comentario explica la decisión
Confía en el IDEIntelliJ marca código redundante y sugiere versiones idiomáticas (Alt+Enter)
// ❌ Estilo "Java disfrazado": verboso y con nombres pobres
fun calc(a: Int, b: Int): Int {
    return a + b
}

// ✅ Idiomático Kotlin: conciso, claro y con intención
fun sumar(primero: Int, segundo: Int): Int = primero + segundo

// ✅ Con documentación KDoc para APIs públicas
/**
 * Calcula el área de un rectángulo.
 * @param base medida en metros, debe ser positiva
 */
fun areaRectangulo(base: Double, altura: Double): Double {
    require(base > 0 && altura > 0) { "Las medidas deben ser positivas" }
    return base * altura
}

Meta alcanzable: si programas 30 minutos al día siguiendo estas lecciones, en dos semanas escribirás Kotlin funcional; en tres meses, Kotlin idiomático.

Ejercicios prácticos

Pon a prueba lo aprendido. Resuélvelos en el playground de Kotlin (play.kotlinlang.org) o en IntelliJ IDEA.

  1. Saludo personalizado: escribe un main que declare tu nombre en un val y tu edad en un var, luego imprima "Me llamo X y tengo Y años" usando interpolación de cadenas. Incrementa la edad en uno e imprime el nuevo valor.
  2. Detección de inmutabilidad: declara una variable con val e intenta reasignarla. Lee el mensaje de error del compilador, cámbiala a var y confirma que ahora compila. Anota qué error produce Kotlin.
  3. Ficha de producto: crea variables val para nombre (String), precio (Double) y stock (Int) de un producto, e imprime una ficha formateada en varias líneas con interpolación, incluyendo el valor total del inventario (precio × stock).
  4. Conversor de temperatura: escribe una función celsiusAFahrenheit(celsius: Double): Double (fórmula: C × 9/5 + 32) y un main que la pruebe con al menos 3 valores, imprimiendo resultados redondeados a 1 decimal.
  5. Mini calculadora CLI: usando main(args: Array<String>), recibe dos números y una operación (+, -, *, /) como argumentos, valida que sean exactamente 3 argumentos y muestra el resultado o un mensaje de uso claro si falta información. Prueba también a compilarlo con kotlinc y ejecutarlo con java -jar.
