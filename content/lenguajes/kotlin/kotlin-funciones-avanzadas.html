Funciones de expresión única

Cuando una función devuelve el resultado de una única expresión, Kotlin permite omitir las llaves, la palabra return y hasta el tipo declarado: basta con el signo =. No es azúcar gratuito: obliga a pensar en las funciones como transformaciones de datos (entrada → salida) en lugar de como secuencias de instrucciones, y esa mentalidad funcional paga dividendos cuando lleguen las colecciones y las corrutinas.

// Forma clásica con bloque
fun areaCirculo(radio: Double): Double {
    return Math.PI * radio * radio
}

// Misma función como EXPRESIÓN ÚNICA: más corta e igual de clara
fun areaCirculoBreve(radio: Double): Double = Math.PI * radio * radio

// El tipo de retorno puede INFERIRSE (solo válido en este estilo)
fun suma(a: Int, b: Int) = a + b            // Int deducido

// Se combinan naturalmente con when e if como expresiones
fun imc(categoria: String): String = when (categoria) {
    "bajo" -> "Consultar nutricionista"
    "normal" -> "¡Todo en orden!"
    else -> "Consulta médica preventiva"
}

// Con parámetros por defecto y una línea: máxima densidad de información
fun impuesto(monto: Double, tasa: Double = 0.16) = monto * tasa

En APIs públicas conviene declarar el tipo de retorno explícito aunque se pueda inferir: sirve de documentación y evita que un cambio accidental del cuerpo altere silenciosamente el contrato de la función.

Argumentos por defecto y nombrados: adiós a los overloads

En Java, dar opciones a una función obligaba a escribir múltiples versiones (el llamado telescopaje de constructores) o recurrir al patrón Builder. Kotlin lo resuelve en la propia firma: cada parámetro puede llevar un = valorPorDefecto, y quien llama decide qué pasar. Combinado con los argumentos nombrados —que permiten saltarse parámetros intermedios y autodocumentar la llamada— el boilerplate desaparece.

fun enviarCorreo(
    destino: String,
    asunto: String,
    copia: String? = null,
    urgente: Boolean = false,
    firma: String = "Equipo GuiaDev"
): String {
    val marca = if (urgente) "[URGENTE] " else ""
    return "$marca$asunto -> enviado a $destino"
}

// Llamada mínima: solo lo obligatorio
enviarCorreo("ana@ejemplo.com", "Bienvenida")

// Saltando parámetros intermedios gracias a los NOMBRES
enviarCorreo("luis@ejemplo.com", "Reporte mensual", urgente = true)

// Nombrados también mejoran la legibilidad con valores booleanos sueltos
enviarCorreo("soporte@ejemplo.com", "Cambio de plan", firma = "Soporte N1")

// Regla sintáctica: los posicionales van PRIMERO, los nombrados después
// enviarCorreo(destino = "x@y.com", "Asunto")  // ❌ error de compilación

El problema que resuelve: explosión de sobrecargas

// ❌ Equivalente Java: cada combinación necesita SU versión
// fun enviarCorreo(destino: String, asunto: String) { ... }
// fun enviarCorreo(destino: String, asunto: String, urgente: Boolean) { ... }
// fun enviarCorreo(d: String, a: String, u: Boolean, f: String) { ... }

// ✅ Kotlin: UNA firma cubre todas las variantes
fun crearUsuario(nombre: String, rol: String = "editor", activo: Boolean = true) =
    "$nombre ($rol${if (activo) "" else ", inactivo"})"

println(crearUsuario("Ana"))                          // Ana (editor)
println(crearUsuario("Luis", rol = "admin"))          // Luis (admin)
println(crearUsuario("María", activo = false))        // María (editor, inactivo)

Ojo al interoperar: el bytecode JVM no conoce los valores por defecto, así que desde Java tendrías que pasar todos los argumentos. La anotación @JvmOverloads genera las sobrecargas automáticamente — la verás a fondo en la lección de interoperabilidad con Java.

Hábito profesional: en llamadas con tres o más parámetros del mismo tipo (dos Strings seguidos, por ejemplo), usa argumentos nombrados aunque sean obligatorios. Un transferir(origen = "...", destino = "...") evita intercambiarlos por accidente.

vararg, el operador spread e infix functions

Tres herramientas pequeñas que hacen las firmas mucho más naturales. vararg acepta un número variable de argumentos; el operador spread (*) despliega un array existente dentro de esa lista; y las funciones infix permiten llamarlas sin punto ni paréntesis, creando mini-lenguajes legibles.

// vararg: cero o más valores del tipo indicado, recibidos como Array<Int>
fun promedio(vararg notas: Int): Double {
    require(notas.isNotEmpty()) { "Se requiere al menos una nota" }
    return notas.average()
}

promedio(8, 9, 10)          // 9.0
promedio()                  // lanza IllegalArgumentException con mensaje claro

// Spread * : expande un Array en argumentos individuales
val historico = intArrayOf(6, 7, 9)
println(promedio(*historico, 10))   // mezcla array + valores sueltos: 8.0

// infix: método/función de UN parámetro llamada sin punto ni paréntesis
infix fun Int.potencia(exponente: Int): Int {
    var resultado = 1
    repeat(exponente) { resultado *= this }
    return resultado
}

println(2 potencia 8)        // 256 — se lee casi como matemática
println(5 potencia 3)        // 125

// El "to" que ya usaste en mapas ES una infix function de la librería estándar:
val par: Pair<String, Int> = "edad" to 30   // crea un Pair("edad", 30)

Reglas de las funciones infix

RequisitoDetalle
Un solo parámetroSin valor por defecto ni vararg
Miembro o extensiónDebe pertenecer a una clase o extender un tipo
No debe ser ambiguaEl receptor va a la izquierda, el argumento a la derecha
Uso recomendadoRelaciones que se lean como frases: x to y, elemento in lista

El operador spread solo funciona sobre arrays, no sobre List. Si tienes una List<Int>, conviértela primero con .toIntArray() (o .toTypedArray() para tipos genéricos).

Extension functions y properties

Las funciones de extensión te permiten añadir comportamiento a clases ajenas —incluidas clases de librerías que no puedes modificar— sin herencia ni wrappers. Se declaran anteponiendo el tipo receptor: fun Tipo.nombre(). Dentro, this apunta al objeto receptor. La clave conceptual: se resuelven en tiempo de compilación; no modifican la clase real, sino que compilan como funciones estáticas que reciben el receptor por parámetro.

// Extensión sobre String: validación reutilizable en todo el proyecto
fun String.esEmailValido(): Boolean =
    contains("@") && endsWith(".com") || endsWith(".es")

println("ana@guiadev.com".esEmailValido())   // true

// Extensiones útiles sobre colecciones
fun List<Double>.media(): Double = if (isEmpty()) 0.0 else average()
fun List<String>.aMayusculas(): List<String> = map { it.uppercase() }

println(listOf(7.0, 8.0, 9.0).media())       // 8.0

// EXTENSION PROPERTY: se declara como propiedad pero siempre necesita getter
val String.iniciales: String
    get() = split(" ").mapNotNull { it.firstOrNull()?.uppercase() }.joinToString("")

println("Ada Lovelace".iniciales)             // AL

// Dentro de una extensión puedes usar this para encadenar
fun StringBuilder.envolver(tag: String): StringBuilder {
    insert(0, "<$tag>")                       // this.insert(...)
    append("</$tag>")
    return this                               // habilita encadenamiento
}

Las extensiones NO pueden acceder a miembros private/protected de la clase extendida: son invitadas de fuera, no parte de la familia. Si necesitas tocar estado interno, la solución es refactorizar la clase, no forzar la extensión.

Si una clase ya tiene un miembro con el mismo nombre, el miembro siempre gana sobre la extensión (y el compilador no avisa). Para llamar a tu extensión en ese caso, usa this@Clase.extensión() o renómbrala.

Lambdas e it: funciones como valores

Una lambda es una función literal: se define donde se usa, sin nombre, entre llaves. En Kotlin las funciones son ciudadanos de primera clase: se guardan en variables, se pasan como argumento y se devuelven desde otras funciones. A las funciones que reciben o devuelven funciones se les llama higher-order functions (de orden superior), y son el motor de toda la API funcional de colecciones que usarás en la próxima lección.

// Sintaxis general: { parámetros -> cuerpo }
val suma = { a: Int, b: Int -> a + b }
println(suma(2, 3))                    // 5

// Si la lambda tiene UN parámetro, se llama it automáticamente
val alCuadrado: (Int) -> Int = { it * it }   // el tipo vive fuera: no hace falta declarar it
println(alCuadrado(7))                 // 49

// Higher-order function: recibe otra función como parámetro
fun filtrar(numeros: List<Int>, criterio: (Int) -> Boolean): List<Int> {
    val resultado = mutableListOf<Int>()
    for (n in numeros) if (criterio(n)) resultado.add(n)
    return resultado
}

val pares = filtrar((1..10).toList()) { it % 2 == 0 }   // [2, 4, 6, 8, 10]

// TRAILING LAMBDA: si el último parámetro es una función, sale de los paréntesis
val nombres = listOf("Ana", "Alberto", "Luis")
nombres.filter { it.startsWith("A") }.forEach { println(it) }   // Ana, Alberto

// Referencias :: : si ya existe una función, pásala sin envolverla en lambda
fun esPar(n: Int) = n % 2 == 0
val evens = filtrar((1..10).toList(), ::esPar)

Tipos de función: el lenguaje de las firmas

Tipo de funciónEjemplo de declaraciónSignificado
() -> Unitval saludo: () -> Unit = { println("hola") }No recibe nada, no devuelve nada útil
(Int) -> Booleanval test: (Int) -> Boolean = { it > 0 }Recibe Int, devuelve Boolean
(A, B) -> Cval combinar: (Int, Int) -> IntDos entradas, una salida
Int.(Int) -> IntLambda con receptorEl primer Int es el receptor: dentro se accede con this

Usa it solo cuando su significado sea obvio por contexto (una lista de números, un filtro simple). Con dos lambdas anidadas o elementos complejos, nómbralos explícitamente: { pedido -> pedido.total } comunica mucho más que otro it.

Scope functions: let, run, apply, also y with

La librería estándar incluye cinco funciones de orden superior cuyo único propósito es ejecutar un bloque sobre un objeto. Todas hacen algo muy parecido, así que la pregunta correcta no es "¿cuál existe?" sino "¿qué referencia uso dentro (this vs it) y qué quiero devolver (el objeto o el resultado)?". Esta tabla es la chuleta definitiva:

FunciónReceptor dentro del bloqueDevuelveEscenario ideal
letitResultado del bloqueEjecutar código solo si un valor no es null; transformar un valor
runthisResultado del bloqueCalcular un valor tras configurar el objeto (objeto: bloque)
withthisResultado del bloqueAgrupar llamadas sobre un objeto ya creado (no es extensión)
applythisEl propio objetoInicializar/configurar: builders, intentos, propiedades
alsoitEl propio objetoEfectos secundarios dentro de una cadena: log, validación, métricas
data class Servidor(val host: String) {
    var puerto: Int = 80
    var ssl: Boolean = false
    override fun toString() = "$host:${if (ssl) puerto else puerto} (ssl=$ssl)"
}

// APPLY: configuración fluida; dentro, this implícito; devuelve el objeto listo
val servidor = Servidor("api.guiadev.dev").apply {
    puerto = 8443
    ssl = true
}   // servidor ya configurado, sin variables temporales

// ALSO: inspección sin romper la cadena; el objeto sigue viajando
val nombres = listOf("Ana", "Luis", "María")
    .also { println("Procesando ${it.size} nombres") }   // log intermedio
    .filter { it.length > 3 }

// LET + Elvis: el clásico de null-safety
fun procesarEntrada(texto: String?): String =
    texto?.let { it.trim().uppercase() } ?: "entrada vacía"

// WITH: agrupar operaciones sobre un objeto existente
with(servidor) {
    println("Conectando a $host en el puerto $puerto")
}

// RUN: configurar y calcular en el mismo aliento
val descripcion = servidor.run {
    puerto += 1
    "Servidor activo en $this"
}

Anidar scope functions distintas produce bosques de this e it imposibles de seguir ("¿este it, de qué lambda era?"). Regla práctica: máximo una por expresión; si necesitas más, extrae variables con nombre.

Atajo mental para elegirlas: ¿devuelvo el MISMO objeto? → apply (configuro) o also (observo). ¿Devuelvo OTRA cosa? → let (con nulls) o run/with (calculo usando sus miembros).

Buenas prácticas

Estas reglas destilan la experiencia colectiva de la comunidad Kotlin y las guías oficiales de estilo. Aplicarlas desde el principio hace que tu código parezca escrito por alguien con años de Kotlin.

PrácticaRazón
Nombres verbales y específicoscalcularTotal() comunica; proceso() no dice nada
Una responsabilidad por funciónFáciles de probar, reutilizar y depurar

Expresión única cuando cabe en una pantallaElimina ceremonia; si necesita comentarios, usa bloques

// ❌ Firma confusa: ¿qué es cada String? ¿y ese boolean?
fun registrar(u: String, t: String, m: Boolean): String { /* ... */ }
registrar("ana", "admin", true)

// ✅ Misma idea: defaults, nombres claros y llamada legible
data class Registro(val usuario: String, val rol: String)

fun registrar(datos: Registro, notificar: Boolean = false, origen: String = "web"): String =
    "${datos.usuario} registrado como ${datos.rol} desde $origen" +
    if (notificar) " (notificación enviada)" else ""

registrar(
    datos = Registro(usuario = "ana", rol = "admin"),
    notificar = true
)

Deja que IntelliJ trabaje para ti: Refactor → Extract Function (Ctrl+Alt+M) sobre cualquier bloque largo, y la inspección "Convert to single-expression function" sugiere cuándo simplificar a la forma con =.

Ejercicios prácticos

Pon a prueba la lección completa: cada ejercicio exige combinar varias técnicas vistas aquí. Resuélvelos en el playground de Kotlin.

  1. Facturador compacto: escribe fun total(precio: Double, cantidad: Int = 1, descuento: Double = 0.0, iva: Double = 0.21) como función de expresión única que aplique descuento y sume IVA. Haz tres llamadas distintas usando argumentos nombrados, incluyendo una que salte cantidad.
  2. Estadísticas flexibles: crea fun estadisticas(vararg valores: Double) que valide que no venga vacía (con require) y devuelva un String con media, mínimo y máximo. Pruébala con valores sueltos Y con un array pasado mediante el operador spread.
  3. Biblioteca de extensiones: implementa fun String.aTitulo(): String (primera letra de cada palabra en mayúscula), val Int.esPar: Boolean (extensión property con getter) y úsalas juntas sobre una lista de frases.
  4. Filtro configurable: escribe una higher-order function fun procesar(lista: List<Int>, criterio: (Int) -> Boolean, transformacion: (Int) -> Int): List<Int> que filtre y transforme; llámala dos veces con lambdas distintas (pares al cuadrado; impares negados) y una vez con referencias ::.
  5. Builder con apply: modela data class Receta(val nombre: String) con var ingredientes: MutableList<String>, var minutos: Int = 30 y var vegetariana: Boolean = false. Construye dos recetas encadenando apply para configurarlas, inserta un log con also en la cadena y finaliza imprimiendo ambas con with.
