if como expresión: decisiones que devuelven valores

En la mayoría de lenguajes, un if es una sentencia: ejecuta código pero no produce resultado. Kotlin da un paso más y lo convierte en una expresión, es decir, algo que se evalúa y devuelve un valor. Esta idea —que el control de flujo produce datos en lugar de solo moverlos— cambia la forma de escribir programas: desaparece la necesidad del operador ternario (cond ? a : b) y se eliminan variables temporales inicializadas "por defecto" que luego se sobrescriben.

val nota = 78

// El if completo devuelve un valor asignable
val calificacion = if (nota >= 90) "Sobresaliente" else "Aprobado"

// Con varias ramas, cada rama evalúa su expresión
val etiqueta = if (nota >= 90) {
    "Excelente"
} else if (nota >= 70) {
    "Aprobado"
} else {
    "Reprobado"
}

// Con bloques { }, el valor devuelto es la ÚLTIMA expresión del bloque
val mensaje = if (nota >= 70) {
    println("Registrando aprobado...")   // efecto secundario permitido
    "Nota final: $nota"                  // esta línea es lo que se devuelve
} else {
    "Debes repetir el curso"

Cuando usas if como expresión, la rama else es obligatoria. Sin ella el compilador no puede garantizar que siempre haya un valor, y fallará con "missing return statement". Si solo necesitas efectos secundarios, usa el if tradicional sin asignarlo.

Todas las ramas deben devolver el mismo tipo

El tipo resultante de la expresión es el supertipo común de todas sus ramas. Si mezclas tipos incompatibles, el compilador te avisará antes de ejecutar nada.

// ✅ Ambas ramas devuelven String
val estado = if (stock > 0) "disponible" else "agotado"

// ❌ Error: Int y String no comparten un supertipo útil
// val confuso = if (activo) 1 else "no"

// Si realmente necesitas tipos distintos, declara el tipo común explícito:
val valor: Any = if (activo) 1 else "no"

Hábito idiomático: si un if/else if/else encadenado empieza a crecer (más de 3 ramas), migra a when: es más plano, más legible y permite condiciones por rangos o tipos sin repetir el sujeto.

when con sujeto: ramificación expresiva

when es el reemplazo moderno del switch clásico, pero comparado con él es otro planeta: no necesita break (no existe el temido fall-through), cada rama puede ser un valor, varios valores agrupados, un rango, un tipo o cualquier expresión booleana. El sujeto es el valor entre paréntesis contra el que se compara cada rama.

fun clasificarDia(dia: Int): String = when (dia) {
    6, 7 -> "Fin de semana"              // valores AGRUPADOS con coma
    in 1..5 -> "Entre semana"            // rango con el operador in
    else -> "Día inválido"               // equivalente al default
}

fun describir(valor: Any): String = when (valor) {
    is Int -> "Entero positivo: $valor"        // verifica TIPO...
    is String -> "Texto de ${valor.length} letras"  // ...y hace smart cast
    is Boolean -> if (valor) "Verdadero" else "Falso"
    else -> "Tipo desconocido"
}

// Las ramas pueden combinar condiciones arbitrarias
fun riesgoEdad(edad: Int): String = when (edad) {
    in 0..12 -> "Niñez"
    in 13..17 -> "Adolescencia"
    18, 19, 20 -> "Juventud temprana"
    in 21..65 -> "Adultez"
    else -> "Tercera edad"
}

Formas que puede tomar una rama

Forma de ramaEjemploCuándo usarla
Valor literal"es" ->Casos exactos y discretos (códigos, menús)
Valores agrupados6, 7 ->Varios casos comparten la misma respuesta
Rango (in)in 1..5 ->Intervalos numéricos o alfabéticos

Con is, el compilador aplica smart cast: dentro de la rama puedes usar los miembros del tipo concreto sin castear. En el ejemplo anterior, valor.length funciona porque ya sabes que es String.

when sin sujeto y exhaustividad

Cuando omites el sujeto, cada rama se evalúa como una condición booleana independiente de arriba hacia abajo: es la alternativa elegante a las cadenas largas de if / else if, especialmente cuando hay muchas condiciones cruzadas.

fun recomendarRopa(temperatura: Int, lluvia: Boolean): String = when {
    temperatura <= 0 && lluvia -> "Abrigo impermeable"
    temperatura <= 0               -> "Abrigo grueso"
    temperatura in 1..15           -> "Chaqueta ligera"
    temperatura in 16..25          -> "Camiseta y sudadera por si acaso"
    else                           -> "Camiseta y protector solar"
}

Exhaustividad: el compilador cuenta los casos

Cuando el sujeto es un enum o una clase sealed (que verás en profundidad en la lección de clases), el compilador sabe todos los valores posibles y exige cubrirlos: si usas when como expresión sin else y falta un caso, el programa ni compila. Esto convierte un bug silencioso en un error visible.

enum class EstadoPedido { PENDIENTE, ENVIADO, ENTREGADO }

// ✅ Exhaustivo: cubre TODOS los estados, no necesita else
fun descripcion(estado: EstadoPedido): String = when (estado) {
    EstadoPedido.PENDIENTE -> "Esperando confirmación de pago"
    EstadoPedido.ENVIADO   -> "En camino al destino"
    EstadoPedido.ENTREGADO -> "Completado satisfactoriamente"
}

// ⚠ Si mañana añades CANCELADO al enum, ESTE when deja de compilar:
// el compilador te obliga a decidir qué hacer con el nuevo caso.
// Eso protege producción: ningún caso nuevo queda sin manejar.

Añadir else -> "para callar al compilador" en un when sobre enums o sealed classes anula esa red de seguridad: si agregas un nuevo valor, el else lo absorberá en silencio. Prefiere el when exhaustivo sin else.

Desde Kotlin 1.7 el compilador advierte incluso en when-sentencia no exhaustivos sobre enum/sealed, así que la recomendación oficial es tratarlos siempre como completos.

Bucles for y rangos

El for de Kotlin no existe en su forma "clásica" de C (for(i = 0; i < n; i++)): itera directamente sobre elementos de algo iterable. Para secuencias numéricas, el trabajo lo hacen los rangos, objetos de primera clase que también sirven para validaciones (in 1..100) y comparaciones.

OperadorEjemploValores generados
..1..51, 2, 3, 4, 5 (incluye el extremo final)
until1 until 51, 2, 3, 4 (excluye el extremo final)
downTo5 downTo 15, 4, 3, 2, 1 (descendente inclusivo)
step1..10 step 31, 4, 7, 10 (salta de N en N)
'a'..'e'CharRangea, b, c, d, e (¡también funciona con letras!)
for (i in 1..5) print("$i ")          // 1 2 3 4 5
for (i in 0 until 5) print("$i ")     // 0 1 2 3 4  (típico para índices)
for (i in 10 downTo 1 step 2) print("$i ")  // 10 8 6 4 2
for (letra in 'a'..'e') print("$letra")     // abcde

// Iterar una colección directamente: la forma preferida
val lenguajes = listOf("Kotlin", "Java", "Scala")
for (lenguaje in lenguajes) println(lenguaje)

// ¿Necesitas la POSICIÓN? .indices genera solo índices válidos
for (i in lenguajes.indices) println("[$i] ${lenguajes[i]}")

// ¿Índice Y elemento a la vez? withIndex + destructuración
for ((indice, valor) in lenguajes.withIndex()) {
    println("$indice -> $valor")
}

// Iterar un Mapa desestructura clave y valor automáticamente
val poblaciones = mapOf("Madrid" to 3_300_000, "Lima" to 9_700_000)
for ((ciudad, habitantes) in poblaciones) {
    println("$ciudad tiene $habitantes habitantes")
}

Prefiere iterar elementos (for (x in lista)) antes que índices (lista[i]). Los índices invitan a errores off-by-one; úsalos solo cuando la posición sea parte del problema (por ejemplo, comparar vecinos).

while, do-while y saltos con etiquetas

Cuando el número de repeticiones depende de una condición que cambia durante la ejecución (esperar entrada del usuario, procesar hasta agotar una cola), los bucles while y do-while son la herramienta correcta. La diferencia entre ambos es cuándo se comprueba la condición: while la revisa antes de cada vuelta (puede ejecutarse cero veces); do-while la revisa después (garantiza al menos una ejecución).

// while: condición primero — puede no ejecutarse nunca
var intentos = 0
while (intentos < 3 && !conexionEstablecida()) {
    intentos++
}

// do-while: cuerpo primero — ideal para menús interactivos
do {
    mostrarMenu()
    opcion = leerOpcion()
    procesar(opcion)
} while (opcion != SALIR)

break, continue y etiquetas

break aborta el bucle actual y continue salta a la siguiente iteración. En bucles anidados, a veces necesitas salir de ambos a la vez: para eso existen las etiquetas, que nombran un bucle concreto con el formato nombre@.

// Buscar la primera pareja cuyo producto supere un umbral
exterior@ for (fila in matriz) {
    for (valor in fila) {
        if (valor < 0) continue          // ignora negativos, sigue con el siguiente
        if (valor > 900) break@exterior  // corta AMBOS bucles de golpe
        println("Procesando $valor")
    }
}

// Etiqueta con continue: salta directamente a la siguiente vuelta del bucle EXTERIOR
busqueda@ for (usuario in usuarios) {
    for (permiso in usuario.permisos) {
        if (permiso == "admin") continue@busqueda  // este usuario no nos sirve
        auditar(usuario, permiso)
    }
}

Las etiquetas son potentes pero poco frecuentes en código profesional: cuando aparecen demasiado, suelen indicar que la lógica merece extraerse a una función donde un simple return resuelve lo mismo con más claridad.

try/catch como expresión

Coherente con su filosofía, Kotlin también trata try/catch/finally como una expresión: el bloque devuelve el valor de su última línea. El patrón estrella es convertir operaciones propensas a fallo (parsear texto, dividir) en valores por defecto sin variables auxiliares.

val entrada = "42x"

// try devuelve un valor: parsea si puede, si no, usa el respaldo
val numero = try {
    entrada.toInt()
} catch (e: NumberFormatException) {
    0                                  // valor por defecto ante texto inválido
}
println(numero)                        // 0

// Varias capturas especializadas, ordenadas de más concreta a más general
fun dividir(a: Int, b: Int): Int = try {
    a / b                              // puede lanzar ArithmeticException
} catch (e: ArithmeticException) {
    println("División entre cero detectada")
    0
} catch (e: Exception) {
    println("Error inesperado: ${e.message}")
    -1
} finally {
    println("Operación finalizada")    // SIEMPRE corre: limpieza, cierre de recursos
}

// Patrón realista: lectura de configuración tolerante
val puerto = try {
    System.getenv("PORT")?.toInt() ?: 8080
} catch (e: NumberFormatException) {
    8080
}

Evita catch (e: Exception) genérico como primer recurso: atrapa también bugs de programación (como NullPointerException) que deberían verse durante el desarrollo. Captura las excepciones concretas que sabes manejar.

Kotlin no distingue excepciones chequeadas (checked exceptions) como Java: ninguna firma lleva throws. Esto simplifica enormemente los try/catch; verás la contrapartida al interoperar con Java en la última lección.

Errores comunes

Estos tropiezos aparecen una y otra vez en quienes migran desde otros lenguajes. Reconocerlos te ahorrará sesiones de depuración frustrantes.

ErrorSíntomaSolución
if-expresión sin elsemissing return statementAñade la rama else o usa el if como sentencia
.. vs until confundidosUna iteración de más/menos (off-by-one).. incluye el final; until lo excluye
when con ramas imposibles tras un caso amplioAdvertencia is always successfulOrdena las ramas de la más específica a la más general
Falta else en when sobre tipos abiertosnon-exhaustive whenCubre todos los casos o añade else conscientemente
Bucle infinito por condición mal actualizadaPrograma colgado consumiendo CPUVerifica que la variable de control muta DENTRO del bucle
break que solo sale del bucle internoLógica que sigue iterando sin quererUsa etiquetas (break@etiqueta) o extrae a función con return
Asignación dentro de la condiciónassignments are not expressionsKotlin prohíbe = en condiciones: separa la asignación
// ❌ Rama imposible: "in 1..100" absorbe todo antes de llegar al caso específico
when (puntos) {
    in 1..100 -> nivelBajo()
    95 -> nivelAlto()      // ¡nunca se ejecuta! 95 está dentro de 1..100
    else -> fueraDeRango()
}

// ✅ Orden correcto: específico primero, general después
when (puntos) {
    95 -> nivelAlto()
    in 1..100 -> nivelBajo()
    else -> fueraDeRango()
}

IntelliJ IDEA marca en gris las ramas inalcanzables de un when antes de compilar. Acostúmbrate a mirar esas advertencias: son bugs futuros detectados gratis.

Ejercicios prácticos

Resuélvelos en orden: cada uno incorpora un concepto de la lección sobre el anterior. Verifica tus resultados en el playground de Kotlin.

  1. Calificador con if-expresión: dado un val nota = 0..100 leído como entero fijo, usa una única expresión if/else if/else para producir la cadena "Suspenso" (<60), "Aprobado" (60–79), "Notable" (80–89) u "Óptimo" (90+), e imprímela.
  2. Traductor de estaciones: escribe fun estacion(mes: Int): String con un when CON sujeto usando valores agrupados (12, 1, 2 → "Invierno", etc.) y rangos donde aplique; devuelve "Mes inválido" para números fuera de 1..12.
  3. FizzBuzz con when sin sujeto: para los números del 1 al 100 imprime "FizzBuzz" (múltiplo de 3 y 5), "Fizz" (de 3), "Buzz" (de 5) o el número. Debe resolverse con un único when {} sin sujeto dentro de un for.
  4. Tabla de multiplicar invertida: pide un número N (decláralo como constante) y muestra su tabla del 10 al 1 usando downTo y step; formatea cada línea con withIndex() para numerar las filas ("fila 1: 10 × N = …").
  5. Calculadora resistente: implementa un mini-calculador con try como expresión: dados dos textos fijos (por ejemplo "12" y "abc") y un operador, conviértelos con toInt() dentro del try, aplica un when según el operador (+, -, *, /) y devuelve 0 ante NumberFormatException o división entre cero, informando qué ocurrió.
