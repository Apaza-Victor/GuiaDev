Funciones y parámetros

Las funciones son bloques de código reutilizables que reciben parámetros y devuelven resultados. Dart permite parámetros posicionales obligatorios, parámetros nombrados opcionales (entre llaves) y valores por defecto. Además, una función es un valor más: puedes pasarla como argumento o guardarla en una variable.

// Parámetros posicionales y retorno tipado
int sumar(int a, int b) {
  return a + b;
}

// Parámetros nombrados, opcionales y con valores por defecto
String saludar(String nombre, {String saludo = 'Hola', bool entusiasmo = false}) {
  final exclamacion = entusiasmo ? '!' : '.';
  return '$saludo, $nombre$exclamacion';
}

// Función flecha para cuerpos de una sola expresión
int doble(int x) => x * 2;

void main() {
  print(sumar(3, 4));
  print(saludar('GuiaDev'));
  print(saludar('GuiaDev', saludo: 'Bienvenido', entusiasmo: true));
  print(doble(21));
}

// Salida:
// 7
// Hola, GuiaDev.
// Bienvenido, GuiaDev!
// 42

Los parámetros nombrados hacen que la llamada se lea sola: saludar('Ana', saludo: 'Hey') deja claro qué es cada valor. Usa posicionales para uno o dos argumentos imprescindibles y nombrados para los opcionales o los que describen un papel concreto.

Clases y constructores

Dart es un lenguaje orientado a objetos: casi todo lo que escribes vive dentro de una class. Una clase define propiedades (el estado) y métodos (el comportamiento). El constructor prepara el objeto y, como azúcar sintáctico, Dart permite declarar los campos directamente en los parámetros con this; también existen constructores con nombre, ideales cuando un objeto se puede crear de varias formas.

class Producto {
  final String nombre;
  final double precio;

  // Constructor posicional con this
  Producto(this.nombre, this.precio);

  // Constructor con nombre y lista inicializadora
  Producto.barato(this.nombre) : precio = 1.0;

  double precioConIva([double porcentaje = 0.21]) => precio * (1 + porcentaje);
}

void main() {
  final laptop = Producto('Laptop', 899.0);
  final boligrafo = Producto.barato('Bolígrafo');

  print('${laptop.nombre}: ${laptop.precioConIva().toStringAsFixed(2)}');
  print('${boligrafo.nombre}: ${boligrafo.precio}');
}

// Salida:
// Laptop: 1087.79
// Bolígrafo: 1.0
MecanismoQué haceEjemplo
ConstructorInicializa el objeto al crearloProducto(this.nombre, this.precio)
Constructor con nombreCrea el objeto de otra formaProducto.barato('Bolígrafo')
Lista inicializadoraAjusta campos antes del cuerpoProducto.barato(this.nombre) : precio = 1.0
Parámetro opcionalValor por defecto en el argumento[double p = 0.21]

En Producto('Laptop', 899.0) el 899 es un double literal. Dart trata los números decimales con double siempre que aparezca el punto; recuerda usar .0 si quieres forzar el tipo en un constructor.

Getters, setters y campos privados

La encapsulación protege el estado interno de un objeto y expone solo lo necesario. En Dart los campos privados se marcan con un guion bajo (_saldo) y son privados a nivel de archivo, no de objeto. Los getters y setters controlan cómo se lee y se modifica una propiedad, añadiendo validaciones sin cambiar el punto de acceso desde fuera.

class Cuenta {
  double _saldo;

  Cuenta(this._saldo);

  double get saldo => _saldo;

  set saldo(double cantidad) {
    if (cantidad < 0) {
      throw ArgumentError('El saldo no puede ser negativo');
    }
    _saldo = cantidad;
  }

  void depositar(double monto) {
    _saldo += monto;
  }
}

void main() {
  final cuenta = Cuenta(100);
  cuenta.depositar(50);
  cuenta.saldo = 200;          // llamada transparente al setter
  print('Saldo actual: ${cuenta.saldo}');
}

// Salida:
// Saldo actual: 200

El _ hace privado a nivel de librería: otro .dart del mismo proyecto no puede nombrar a _saldo, pero dos clases dentro del mismo archivo sí. Si necesitas privacidad estricta para una API pública, separa las clases en sus propios archivos.

Herencia e interfaces

La herencia permite que una clase reutilice el comportamiento de otra con extends, y en Dart toda clase desciende de Object (herencia simple: una única clase padre). Además, Dart convierte a cada clase en una interfaz implícita: otra clase puede comprometerse a implementar su misma forma con implements. Las clases que no deben instanciarse se declaran abstract.

Palabra claveQué haceEjemplo
extendsHereda los miembros de la clase padreclass Gato extends Animal
implementsObliga a definir la misma superficie de la clase/interfaceclass Coche implements Vehiculo
abstractClase que solo puede heredarse, nunca instanciarseabstract class Figura
@overrideMarca un método que reemplaza al de la clase padre@override String sonido()

En el constructor se llama al de la clase base con super:

class Gato extends Animal { Gato(String nombre) : super(nombre); }

Y un método se puede rediseñar respetando su contrato:

@override String sonido() { return 'miau'; }

Una jerarquía profunda de herencia se vuelve rígida con el tiempo. Antes de heredar pregúntate si necesitas «es un» (usa extends) o solo «se comporta como» (usa implements o un mixin, que verás a continuación).

Mixins

Un mixin reutiliza código sin necesidad de relación de herencia. Se define con mixin y la clase lo incorpora con with, obteniendo de inmediato sus métodos y propiedades. Como Dart solo permite un único padre, los mixins ofrecen la flexibilidad de la composición: puedes aplicar varios a la misma clase.

mixin Nadable {
  void nadar() => print('Estoy nadando');
}

mixin Volador {
  void volar() => print('Estoy volando');
}

class Pato with Nadable, Volador {
  void cuac() => print('Cuac');
}

void main() {
  final donald = Pato();
  donald.nadar();
  donald.volar();
  donald.cuac();
}

// Salida:
// Estoy nadando
// Estoy volando
// Cuac

Los mixins son especialmente útiles para comportamientos transversales: serializar un objeto, registrarlo en logs, notificarlo a observadores. Se combinan con herencia sin problema: class Perro extends Animal with Nadable.

Ejercicios prácticos

Resuelve los ejercicios en clases.dart y ejecútalo con dart run clases.dart:

  1. Funciones puras: Escribe calcularArea(ancho, alto) con parámetros posicionales y una función presentar(String mensaje, {bool enMayusculas}) con parámetros nombrados y valor por defecto.
  2. Clase propia: Define una clase Libro con título, autor y páginas. Añade un constructor normal y un constructor con nombre Libro.desconocido() que use una lista inicializadora.
  3. Encapsulación: Añade a Libro un campo privado _calificacion con getter y setter, y rechaza en el setter los valores fuera del rango 0 a 5 lanzando ArgumentError.
  4. Herencia: Crea Cuento extends Libro que agregue una propiedad moraleja y un método @override de descripción. Verifica que el constructor llame al padre con super.
  5. Desafío mixin: Define un mixin Resumible con un método resumen() y aplícalo a dos clases completamente distintas para comprobar que el mismo comportamiento se comparte sin herencia.
