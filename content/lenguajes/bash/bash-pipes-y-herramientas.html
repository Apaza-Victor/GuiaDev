Pipes y redirección: la filosofía Unix

Cada programa Unix hace UNA cosa bien. El pipe (|) encadena programas conectando la salida de uno a la entrada del siguiente — componiendo herramientas simples en pipelines poderosos:

Los tres streams y su redirección

StreamNúmeroDestino defaultRedirección
stdin0Teclado< archivo
stdout1Pantalla> trunca, >> añade
stderr2Pantalla2>, 2>>, 2>/dev/null
 
# Combinaciones esenciales:
comando > salida.txt 2> errores.log     # separar streams
comando &> todo.log                      # ambos al mismo archivo
comando >&/dev/null                      # silenciar TODO (cuidado)
grep error app.log 2>/dev/null           # ignora fallos de apertura

# stdin desde archivo:
mysql -u user < dump.sql
sort < nombres.txt

# Heredoc: bloques multi-línea literales:
cat <<EOF > config.ini
[server]
host = localhost
puerto = 8080
EOF

Pipelines que usarás cada día

ps aux | grep nginx                       # procesos filtrados
cat access.log | awk '{print $1}' | sort -u    # IPs únicas
du -sh * | sort -rh | head -5             # top 5 carpetas más pesadas
history | awk '{print $2}' | sort | uniq -c | sort -rn | head   # tus comandos top

# tee: ver Y guardar simultáneamente:
make 2>&1 | tee build.log                 # output en pantalla + log

# xargs: convertir texto en ARGUMENTOS:
cat urls.txt | xargs -n1 curl -sO         # descarga cada URL
find . -name "*.tmp" | xargs rm -f        # borrar lo encontrado

xargs -n1 ejecuta un comando POR línea de entrada; sin -n1 agrupa todos como argumentos únicos. Y para pipes con comandos que fallan: set -o pipefail hace que el pipeline entero falle si CUALQUIER eslabón falla — crítico en CI.

grep: buscar dentro de archivos

grep "ERROR" app.log                  # líneas con ERROR
grep -i "error" app.log               # case-insensitive
grep -v "^#" config.txt               # INVERSO: sin comentarios
grep -rn "función" src/               # recursivo + número de línea
grep -c "GET" access.log              # solo CONTAR matches
grep -A2 -B1 "Exception" log.txt      # 2 después, 1 antes de contexto
grep -E "[0-9]{3}-[0-9]{4}" datos.txt # regex extendida
ps aux | grep -v grep | grep nginx    # el clásico anti-autogrep

sed: editor de flujo

sed 's/perro/gato/' animales.txt          # primera ocurrencia por línea
sed 's/perro/gato/g' animales.txt         # TODAS las ocurrencias
sed -i.bak 's/8080/3000/g' server.conf    # editar EN SITIO + backup
sed '/^#/d' config                        # borrar comentarios
sed -n '10,20p' archivo                   # imprimir solo líneas 10-20
echo "Hola Mundo" | sed 's/\b[A-Z]/\U&/g' # mayúsculas iniciales (GNU)

awk: mini-lenguaje de columnas

awk '{print $1}' access.log               # primera columna (IPs)
awk -F',' '{print $2, $4}' datos.csv      # delimitador coma, cols 2 y 4
awk '$9 == 500 {count++} END {print count}' access.log   # contar errores 500
awk '{total += $5} END {printf "%.2f MB\n", total/1024/1024}' logs/*

# Reporte agregado completo:
df -h | awk 'NR>1 {print $6, $5}' | sort -k2 -rh    # uso% por mount

find: localizar y actuar

find . -name "*.jpg"                      # por nombre (glob)
find . -iname "*.JPG"                     # case-insensitive
find /var -type f -size +100M             # archivos >100MB
find . -type f -mtime -7                  # modificados últimos 7 días
find . -name "*.sh" -exec chmod +x {} \;  # actuar sobre resultados
find . -empty -type d -delete             # limpiar dirs vacíos

El combo final: pipeline de análisis real

#!/bin/bash
# Top 10 IPs atacantes en el access log:
grep " 40[13] " /var/log/nginx/access.log \
  | awk '{print $1}' \
  | sort \
  | uniq -c \
  | sort -rn \
  | head -10 \
  | while read -r cuenta ip; do
        echo "$ip → $cuenta intentos bloqueados"
    done

Siete herramientas pequeñas compusieron un reporte de seguridad en 12 líneas. Ninguna sabe qué es nginx ni seguridad — cada una solo filtra, corta o ordena. Esa composición sin acoplamiento es la lección eterna de Unix.

Buenas prácticas

PrácticaRazón
Filtrar temprano en el pipelinegrep antes de sort: menos datos arrastrados
pipefail en scripts productivosSin él, fallos medios pasan invisibles si el último triunfa
sed -i SIEMPRE con sufijo backup (-i.bak)Edición destructiva irreversible sin copia previa
-exec sobre xargs cuando nombres tienen espacios rarosxargs parte mal por defecto (-0 ayuda)
head/tail limitan exploración interactiva de logs gigantesless +F mejor aún para seguir en vivo
uniq necesita sort previo (solo agrupa adyacentes)El par sort|uniq es inseparable en la práctica

Ejercicios prácticos

  1. Análisis de access log: genera/simula un access.log; construye pipelines separados que respondan: ¿IP más frecuente? ¿hora pico? ¿cuántos 404? ¿tamaño medio de respuesta?
  2. Limpiador de config: con sed elimina comentarios (#...) y líneas vacías de cualquier archivo; compara original vs resultado con diff.
  3. Reporte de disco: du + sort + head + awk produciendo tabla formateada de las 5 mayores carpetas con unidades legibles.
  4. Búsqueda quirúrgica: find que liste archivos JS modificados esta semana con más de 100 líneas (wc integrado), excluyendo node_modules.
  5. Monitor one-liner: watch + pipeline propio que muestre cada 5s los 3 procesos con más CPU filtrando ruido de grep — documenta cada eslabón del pipe en comentario.
