Variables: asignación y expansión

Las variables en bash son cadenas de texto por defecto — sin tipos, sin declaraciones. La regla #1 que separa scripts funcionales de scripts rotos: SIN espacios alrededor del = al asignar, y SIEMPRE entre comillas dobles al usar.

Asignación y expansión

nombre="Ana"            # SIN espacios: nombre = "Ana" NO funciona
edad=30                 # sigue siendo string "30"
RUTA="/var/log"         # convención: MAYÚSCULAS = constantes/env

echo "$nombre tiene $edad años"     # comillas DOBLES expanden
echo '$nombre'                       # comillas SIMPLES: literal, no expande

# Variables de entorno útiles (siempre disponibles):
echo "$HOME"      # /home/ana
echo "$USER"      # ana
echo "$PATH"      # dónde busca ejecutables
echo "$PWD"       # directorio actual
echo "$RANDOM"    # número aleatorio 0-32767

Comandos dentro de variables: $( )

Arrays indexados

servidores=("web01" "db01" "cache01")

echo "${servidores[0]}"        # web01 — índice individual
echo "${servidores[@]}"        # TODOS los elementos
echo "${#servidores[@]}"       # cantidad: 3
echo "${servidores[-1]}"       # cache01 — último (bash 4.3+)

for srv in "${servidores[@]}"; do
    echo "Revisando $srv..."
done

# Añadir:
servidores+=("worker01")

LA regla sagrada: "$var" SIEMPRE entre comillas dobles. Sin ellas, un valor con espacios se ROMPE en palabras: archivo="mi informe.txt"; rm $archivo ejecuta rm mi informe.txt — borra "mi" e "informe.txt". Con comillas, una sola pieza. Este bug ha borrado servidores enteros.

shiftDescarta $1 y recorre el restoparseo manual de flags
 
#!/bin/bash
# deploy.sh — uso: ./deploy.sh <entorno> [version]

ENTORNO="${1:?Error: falta entorno}"      # :? aborta con mensaje si vacío
VERSION="${2:-latest}"

if [ $# -lt 1 ]; then
    echo "Uso: $0 <entorno> [version]" >&2
    exit 1                                 # código ≠ 0 = fracaso para CI/cron
fi

echo "Desplegando $VERSION a $ENTORNO..."
echo "Recibidos $# argumentos: $@"

getopts: flags profesionales (-v --verbose style)

#!/bin/bash
VERBOSE=false
OUTPUT="salida.txt"

while getopts "vo:h" opt; do
    case $opt in
        v) VERBOSE=true ;;
        o) OUTPUT="$OPTARG" ;;          # OPTARG = valor tras -o
        h) echo "Uso: $0 [-v] [-o archivo]"; exit 0 ;;
        *) echo "Flag inválida" >&2; exit 1 ;;
    esac
done
shift $((OPTIND - 1))                    # lo restante son args posicionales

$VERBOSE && echo "Modo verbose activo"   # truco: ejecutar condicionalmente
echo "Escribiendo a $OUTPUT..."

"${1:-valor}", "${1:?mensaje}" y getopts cubren el 95% de las necesidades de parámetros. Para CLIs complejas considera saltar directamente a un lenguaje real (Python/Go) — bash escala hasta cierto punto y luego duele.

set -euo pipefail          # modo estricto: la cabecera profesional estándar

readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

Ejercicios prácticos

  1. Ficha personal: script con variables nombre/edad/ciudad impresas interpoladas; demuestra comillas simples vs dobles vs backslash escape en tres echos.
  2. Renombrador masivo: dado un patrón, usa ${var// /_} para convertir espacios a guiones bajos en nombres de archivos de una carpeta (con echo previo de simulación).
  3. CLI con getopts: herramienta backup.sh con -d destino, -v verbose, -h help; valida destino requerido y documenta uso.
  4. Demostrador word splitting: crea "mi archivo.txt", intenta borrarlo con rm $VAR sin comillas (¡en carpeta de prueba!), observa el doble-borrado fallido; arregla con comillas.
  5. Script estricto: añade set -euo pipefail a tu mejor ejercicio anterior y provoca deliberadamente cada protección (variable indefinida, comando fallando en pipe) documentando los errores.
