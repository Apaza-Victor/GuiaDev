Definición y uso de funciones

Las funciones organizan scripts largos, evitan repetición y permiten librerías reutilizables. Sintaxis simple: nombre + paréntesis + bloque. Los parámetros llegan como $1, $2… igual que los argumentos del script — cada llamada tiene su propio conjunto:

Definir y llamar

#!/bin/bash

# Definición (ambas formas equivalentes):
saludar() {
    echo "Hola, $1"
}

function despedir {          # estilo keyword (menos común)
    echo "Adiós, $1"
}

saludar "Ana"                # Hola, Ana
despedir "Luis"

# Parámetros y metainformación:
resumen() {
    echo "Primer arg: $1"
    echo "Cantidad: $#"
    echo "Todos: $@"
}

resumen a b c
# Primer arg: a
# Cantidad: 3
# Todos: a b c

Las funciones DEBEN definirse antes de usarse en el flujo de ejecución. Convención profesional: helpers arriba, main() al final con la orquestación — el script se lee como un programa real.

Variables locales: local

CONTADOR=0                   # global

sumar_veces() {
    local -i n="$1"          # local: SOLO existe dentro de la función
    for ((i = 1; i <= n; i++)); do
        ((CONTADOR++))       # global sí accesible/modificable
    done
}

sumar_veces 5
echo "$CONTADOR"             # 5
# echo "$n"                  ❌ vacía: nunca salió del scope

# Patrón estándar: función que ESCRIBE resultado, llamador CAPTURA:
obtener_rama_git() {
    git rev-parse --abbrev-ref HEAD 2>/dev/null
}

RAMA=$(obtener_rama_git)
echo "Estás en: ${RAMA:-sin-git}"

# Mezcla peligrosa: logs a stderr, datos a stdout
procesar() {
    echo "Iniciando proceso..." >&2      # >&2 = log, NO contamina captura
    sleep 1
    echo "resultado-limpio"              # esto SÍ es lo capturado
}

DATO=$(procesar)                          # DATO="resultado-limpio" ✅

Todo echo extra dentro de una función capturada CONTAMINA el resultado. Regla de oro: datos por stdout, diagnósticos SIEMPRE por stderr (>&2). Revisa tus funciones dos veces cuando las captures.

Librerías con source

# lib/log.sh
log_info()  { echo "[INFO]  $(date '+%H:%M:%S') $*" >&2; }
log_error() { echo "[ERROR] $(date '+%H:%M:%S') $*" >&2; }
die()       { log_error "$1"; exit "${2:-1}"; }
#!/bin/bash
set -euo pipefail
source "$(dirname "$0")/lib/log.sh"

log_info "Comenzando deploy..."
[ -f app.conf ] || die "app.conf requerido" 2
log_info "Deploy OK"

Exit status y composición

Toda función devuelve un código de salida (el de su último comando, o explícito con return). Este código ES la interfaz booleana de bash:

es_par() {
    [ $(( $1 % 2 )) -eq 0 ]     # último comando decide el status
}

if es_par 4; then
    echo "4 es par"
fi

validar_config() {
    [ -f "$1" ] || { echo "Falta config" >&2; return 1; }
    grep -q "puerto" "$1" || { echo "Falta puerto en config" >&2; return 2; }
    return 0                     # éxito explícito
}

validar_config app.conf
case $? in
    0) echo "Válida" ;;
    1) exit 1 ;;
    2) exit 2 ;;
esac
Convención de códigosSignificado habitual
0Éxito universal
1Error genérico
2Uso incorrecto / misusage (getopts lo usa)
126-127Sin permisos / comando no encontrado
130+Terminado por señal (Ctrl+C = 130)

Funciones + traps: limpieza garantizada

TMPDIR=$(mktemp -d)

cleanup() {
    rm -rf "$TMPDIR"                 # se ejecuta SIEMPRE al salir
    echo "Temp limpiado" >&2
}
trap cleanup EXIT                    # EXIT cubre éxito, error y Ctrl+C

echo "Trabajando en $TMPDIR..."
cp grandes_archivos/* "$TMPDIR"/
# aunque algo falle a mitad: cleanup corre igualmente ✅

El trío funciones + set -euo pipefail + trap cleanup EXIT convierte un script frágil en herramienta confiable para CI/CD. Es EL estándar mínimo de calidad que esperan revisores senior en cualquier repo serio.

#!/usr/bin/env bash
set -euo pipefail

readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/lib/log.sh"

main() {
    log_info "Iniciando..."
    parsear_argumentos "$@"
    validar_precondiciones
    ejecutar_despliegue
    log_info "Completado ✅"
}

main "$@"

Ejercicios prácticos

  1. Calculadora modular: funciones sumar/restar/multiplicar/dividir (validando división por cero con return code); menú while+case que las invoque.
  2. Librería de logging: crea lib/log.sh con niveles INFO/WARN/ERROR coloreados (códigos ANSI), timestamp y función die; úsala desde script principal.
  3. Validador compuesto: validar_archivo, validar_permisos, validar_tamaño cada una con código distinto; orquestador que reporte exactamente qué falló via case $?
  4. Recursión controlada: factorial con recursión usando local; compara con versión iterativa en bucle; límite máximo documentado.
  5. Script a prueba de fallos: toma tu mejor ejercicio previo y aplícale el paquete completo: set -euo pipefail, trap cleanup EXIT con mktemp, librería sourced y main(). Verifica que Ctrl+C a mitad deja cero residuos.
