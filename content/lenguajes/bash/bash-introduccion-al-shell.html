¿Qué es un shell y por qué Bash?

El shell es el intérprete que traduce tus comandos al sistema operativo. Cada vez que escribes algo en una terminal, un shell lo recibe, lo interpreta y ejecuta. Bash (Bourne Again Shell) es el estándar de facto en Linux y macOS — y la habilidad más rentable por hora invertida en toda la informática: automatizar tareas repetitivas con 20 líneas.

Dónde vive Bash en tu día a día

  • Servidores Linux: el 90% de la nuebe mundial; sin scripts no administras nada.
  • CI/CD pipelines: GitHub Actions, GitLab CI ejecutan pasos en bash.
  • macOS: terminal nativa zsh, pero bash disponible y scripts portables.
  • Docker: ENTRYPOINT/CMD suelen invocar scripts bash.
  • Windows: vía WSL2, Git Bash o MSYS2 — cada vez más común.

Comprueba tu shell actual con echo $0 o echo $SHELL. En cualquier Linux moderno: bash --version te confirma la versión instalada.

El shebang: declarar el intérprete

El shebang (#!) en la primera línea le dice al sistema QUÉ programa debe interpretar el archivo. Sin él, dependes del shell del usuario — receta para bugs sutiles:

#!/bin/bash
# Todo script serio empieza así

echo "Ejecutado por: $BASH_VERSION"
ShebangCuándo usarlo
#!/bin/bashEstándar clásico; existe en todos los Linux/macOS
#!/usr/bin/env bashPortable: encuentra bash en el PATH (macOS Homebrew, NixOS)
#!/bin/shPOSIX puro ultra-portable pero SIN features de bash (arrays, [[ ]])

/bin/sh NO ES bash: en Debian/Ubuntu apunta a dash, que falla silenciosamente con sintaxis bash como arrays o dobles corchetes. Si usas features bash (y las usarás), declara #!/bin/bash explícitamente.

Hacer ejecutable y correr

# Crear y dar permisos de ejecución:
chmod +x mi_script.sh

# Las TRES formas de ejecutar:
./mi_script.sh          # como PROGRAMA (requiere chmod + shebang correcto)
bash mi_script.sh       # pasándolo al intérprete (no requiere permisos)
source mi_script.sh     # EJECUTA EN TU SHELL ACTUAL (afecta variables/alias!)

# Diferencia clave demostrada:
#   ./script.sh  → subshell aparte: sus variables MUEREN al terminar
#   source       → mismas variables: seteó PATH? ya está cambiado en tu sesión

Si ./script.sh da "Permission denied" → falta chmod +x. Si da "bad interpreter" → shebang mal escrito o finales de línea Windows (CRLF). Arregla CRLF con dos2unix script.sh.

Tu primer script real

#!/bin/bash
# backup-simple.sh — copia una carpeta con fecha en el nombre

ORIGEN="$HOME/proyectos"
DESTINO="$HOME/backups"

FECHA=$(date +%Y-%m-%d_%H%M)
ARCHIVO="backup_$FECHA.tar.gz"

mkdir -p "$DESTINO"
tar -czf "$DESTINO/$ARCHIVO" "$ORIGEN"

if [ $? -eq 0 ]; then
    echo "✅ Backup creado: $DESTINO/$ARCHIVO"
else
    echo "❌ El backup falló" >&2
    exit 1
fi
$ chmod +x backup-simple.sh
$ ./backup-simple.sh
✅ Backup creado: /home/ana/backups/backup_2026-08-23_1415.tar.gz

$ crontab -e
0 2 * * * /home/ana/backup-simple.sh    # cada noche a las 2 AM

Diecinueve líneas útiles: fecha automática, carpeta creada si falta, verificación de éxito, código de salida correcto para cron/CI. Este patrón — comando + verificar resultado + mensaje claro — es EL ciclo mental del scripting.

Anatomía de un comando

tar    -czf    backup.tar.gz    ~/proyectos
 ↑      ↑           ↑               ↑
cmd  opciones    argumento       argumento

Los comentarios (#) en scripts no son decoración: dentro de 6 meses tú serás un desconocido para ti mismo. Documenta QUÉ hace el script, qué parámetros espera y qué produce. El futuro te lo agradecerá.

Errores comunes

Error típicoSíntomaSolución
Olvidar chmod +x"Permission denied"chmod +x script.sh
Finales de línea CRLF (editado en Windows)"bad interpreter: /bin/bash^M"dos2unix o configurar editor LF
Shebang #!/bin/sh usando features bash"Unexpected operator" o fallos rarosDeclarar #!/bin/bash
Probar script destructivo sin echo previoBorraste lo que no debíasSimular primero: echo rm -rf "$DIR"
Editar crontab esperando variables de sesiónScript funciona manual, falla en cronRutas absolutas SIEMPRE en cron; PATH mínimo heredado
No verificar $? tras comandos críticosBackup "exitoso" vacíoset -e global o checks manuales

Ejercicios prácticos

  1. Hola script: crea saludo.sh con shebang, imprime tu nombre y la versión de bash; dale permisos y ejecútalo las tres formas (./, bash, source).
  2. Demostrador source vs ./: script que define SALUDO="hola"; ejecútalo con ./ e intenta echo $SALUDO (vacío); luego con source (aparece). Comenta por qué.
  3. Snapshot diario: adapta backup-simple.sh para comprimir tu carpeta Documentos con timestamp; verifica el tar creado con tar -tzf.
  4. Cazador CRLF: crea un script con finales Windows deliberadamente (o descarga uno), observa el error "bad interpreter", corrige con dos2unix.
  5. Info del sistema: script que imprima kernel (uname -r), disco libre (df -h /), memoria (free -h) y uptime, cada uno con título descriptivo.
