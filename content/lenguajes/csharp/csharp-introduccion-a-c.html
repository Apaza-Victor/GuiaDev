¿Qué es C# y .NET?

C# (pronunciado "C sharp") es un lenguaje moderno de tipado fuerte creado por Microsoft en 2000, hoy dirigido por la fundación .NET Foundation con desarrollo abierto. Desde 2016 vive una segunda juventud: .NET es multiplataforma (Windows, Linux, macOS), open source, y su rendimiento compite cabeza a cabeza con Java y Go en benchmarks reales.

Compilación: de código a IL a nativo

C# no se interpreta ni se compila directo a máquina: compila a IL (Intermediate Language), que el runtime convierte a instrucciones nativas justo-en-tiempo (JIT) al ejecutar. Además existe AOT (Ahead-Of-Time) para binarios nativos sin runtime instalable — arranque en milisegundos ideal para contenedores.

TuCódigo.cs → compilador Roslyn → Ensamblado (.dll con IL + metadatos)
                                        ↓
                            .NET Runtime (JIT → x64/ARM nativo)

Los ensamblados .dll/.exe de .NET contienen metadatos completos: cualquier IDE muestra autocompletado perfecto de librerías sin código fuente. Es también la base del reflection — inspección dinámica de tipos en runtime que hace posible ORMs como Entity Framework.

Tu primer programa

Top-level statements: C# sin ceremonia (C# 9+)

Console.WriteLine("¡Hola desde C#!");

int suma = 2 + 2;
Console.WriteLine($"2 + 2 = {suma}");

Eso ES un programa completo ejecutable. El compilador genera la clase Main por ti. La forma tradicional explícita — aún común en bases de código grandes — es:

using System;                          // importar espacios de nombres

namespace MiApp                        // agrupador lógico de tipos
{
    public class Program               // clase contenedora
    {
        public static void Main()      // punto de entrada
        {
            Console.WriteLine("Hola tradicional");
        }
    }
}
ElementoRolAnalogía
usingImportar namespaces (como import de Python)Python: from X import *
namespaceAgrupar tipos evitando colisiones de nombresCarpetas lógicas de clases
classTodo código vive dentro de un tipoObligatorio (salvo top-level)

// y ///Comentario línea / doc XML generable/// alimenta IntelliSense

C# distingue MAYÚSCULAS: Console ≠ console. Convención universal del ecosistema: PascalCase para tipos/métodos/propiedades públicas, camelCase para variables locales y parámetros, _camelCase para campos privados.

La CLI de dotnet: tu navaja suiza

Todo el ciclo de desarrollo .NET fluye por un único comando: dotnet. Instalado el SDK (desde dotnet.microsoft.com o winget/apt/brew), ya tienes compilador, gestor de paquetes, test runner y más:

# Crear proyectos desde plantillas oficiales
dotnet new console -o MiApp          # aplicación consola
dotnet new webapi   -o MiApi         # API REST con ASP.NET Core
dotnet new mstest   -o MiApp.Tests   # proyecto de tests

# Ejecutar y construir
dotnet run                           # compila Y ejecuta (con hot reload)
dotnet watch                         # recarga automática al guardar ⚡
dotnet build -c Release              # binario optimizado

# Dependencias (NuGet = npm de .NET)
dotnet add package Newtonsoft.Json
dotnet add package Serilog.AspNetCore
dotnet remove package Newtonsoft.Json

# Tests y calidad
dotnet test                          # ejecuta todos los tests
dotnet format                        # formatea según .editorconfig

# Publicar distribuciones
dotnet publish -c Release -r linux-x64 --self-contained
# → binario standalone: corre SIN .NET instalado en destino
ComandoEquivalente mental en otros ecosistemas
dotnet newnpx create-react-app / cargo init
dotnet add packagenpm install / pip install
dotnet runnpm start / python main.py
dotnet testpytest / cargo test
dotnet publishdocker export + setup.exe en uno

dotnet watch incluye Hot Reload real: modificas código mientras la app corre y ves cambios al instante sin reiniciar proceso ni perder estado. Productividad de scripting con rendimiento de lenguaje compilado.

Ejercicios prácticos

  1. Hola mundo completo: crea proyecto console con la CLI, escribe top-level statements que impriman tu nombre y la fecha actual, ejecuta con dotnet run.
  2. Explorador de plantillas: lista todas las disponibles (dotnet new --list) y crea una webapi mínima; arráncala y visita el endpoint de weatherforecast.
  3. NuGet básico: añade el paquete Humanizer y usa DateTime.UtcNow.AddHours(-3).Humanize() para ver humanización de fechas.
  4. Hot reload demostrado: lanza dotnet watch, modifica el mensaje impreso y verifica el recargue instantáneo sin reiniciar manualmente.
  5. Publicación cruzada: publica tu consola self-contained para win-x64 y linux-x64; compara tamaños de carpeta y documenta por qué difieren.
