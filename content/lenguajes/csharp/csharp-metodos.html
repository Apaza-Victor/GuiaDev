Definición y parámetros

Un método encapsula comportamiento reutilizable. Su firma declara visibilidad, retorno, nombre y parámetros — todo tipado, todo verificable en compilación:

Anatomía completa

public static decimal CalcularIVA(decimal baseImponible, double tasa = 0.21)
//  ↑       ↑      ↑            ↑              ↑
// acceso  tipo   NOMBRE       parámetro      opcional con default
{
    return baseImponible * (decimal)tasa;
}

CalcularIVA(100);          // usa tasa por defecto → 21
CalcularIVA(100, 0.10);    // posicional
CalcularIVA(tasa: 0.10, baseImponible: 100);   // ARGUMENTOS NOMBRADOS: orden libre
ModificadorEfecto
public/private/...Visibilidad desde fuera del tipo
staticPertenece a la CLASE, no a instancias (no requiere objeto)
virtual/override/abstract/sealedControl de herencia y polimorfismo
asyncEjecución asíncrona awaitable (lección avanzada)
extern/unsafe/partialCasos especiales: interop, punteros, clases divididas

Expression-bodied: métodos de una línea

// En vez de:
public double Area() { return Math.PI * Radio * Radio; }

// Cuerpo de expresión: la flecha ES el return
public double Area() => Math.PI * Radio * Radio;
public string NombreCompleto => $"{Nombre} {Apellido}";   // también propiedades
public bool EsMayorDeEdad(int edad) => edad >= 18;

Retorno múltiple elegante

// Tuples nombradas: sin crear clase para devolver dos valores
static (bool Exito, string Mensaje) Validar(string input)
{
    if (string.IsNullOrWhiteSpace(input))
        return (false, "Vacío");
    return (true, "Válido");
}

var (ok, msg) = Validar("hola");     // desestructuración directa
Console.WriteLine(ok ? msg : $"Error: {msg}");

Para resultados de dominio complejos prefiere records sobre tuples: record Resultado(bool Ok, string Msg). Las tuples brillan en usos locales; los records documentan contratos públicos.

ref, out e in: paso por referencia

Por defecto TODO se pasa por valor (los objetos comparten la referencia, pero la variable es local). Los modificadores ref/out/in permiten que el MÉTODO toque la variable original:

ModificadorEntrada requeridaSalida obligatoriaUso típico
(nada)Valor copiadoNo afecta al llamadorCaso normal (95%)
refSí, inicializada antesOpcional modificarlaMutación bidireccional; evitar boxing
outNo (el método DEBE asignarla)ObligatoriaRetornos adicionales: TryParse pattern
inSíPromete NO modificarlaStructs grandes: pasar sin copiar ni mutar
 
// out: el patrón más famoso del ecosistema .NET
bool exito = int.TryParse("42", out int resultado);
Console.WriteLine(exito ? resultado : -1);

// out múltiple: función que devuelve por varios canales
void MinMax(int[] datos, out int minimo, out int maximo)
{
    minimo = maximo = datos[0];
    foreach (var n in datos) {
        if (n < minimo) minimo = n;
        if (n > maximo) maximo = n;
    }
}
MinMax(new[] {3, 9, 1}, out var lo, out var hi);
Console.WriteLine($"[{lo}..{hi}]");

// discard _: solo me interesa el bool
if (int.TryParse(input, out _)) { /* era numérico, no necesito el valor */ }

// ref: intercambio real de variables
static void Swap(ref int a, ref int b) => (a, b) = (b, a);
int x = 1, y = 2;
Swap(ref x, ref y);
Console.WriteLine($"{x}{y}");   // 21

// params: número variable de argumentos (debe ser el último)
static int Sumar(params int[] numeros) => numeros.Sum();
Sumar(1, 2, 3, 4);   // 10

El abuso de out/ref produce APIs difíciles de leer y testear. Regla moderna: si necesitas devolver DOS cosas, devuelve una tuple o record; reserva out para el patrón TryXxx consagrado del framework.

Sobrecarga, lambdas y delegados

Sobrecarga (overloading)

Varios métodos comparten nombre si difieren en firma (número/tipos de parámetros). El retorno NO participa en la resolución:

public static string Formatear(decimal monto) => monto.ToString("C");
public static string Formatear(DateTime fecha) => fecha.ToString("d");
public static string Formatear(object valor) => valor?.ToString() ?? "";

Formatear(99.5m);           // llama la versión decimal
Formatear(DateTime.Today);  // la de DateTime
Formatear("cualquiera");    // la genérica object

Lambdas y Func<T>/Action<T>

Los métodos son ciudadanos pasables: los delegados son tipos-firma para funciones, y las lambdas su sintaxis literal:

TipoFirmaDevuelve
Action0+ argumentosNada (void)
Func<T1,T2,...,TReturn>Argumentos + último tipo = retornoEl tipo final
Predicate<T>Un argumentobool
 
Func<int, int> cuadrado = x => x * x;
Func<int, int, int> sumar = (a, b) => a + b;
Action<string> logear = msg => Console.WriteLine($"[LOG] {msg}");
Predicate<int> esPar = n => n % 2 == 0;

Console.WriteLine(cuadrado(7));         // 49
logear("sistema iniciado");

// Composición real: callbacks y eventos
void ProcesarConReintentos(Action operacion, Action<Exception> onError)
{
    try { operacion(); }
    catch (Exception ex) { onError(ex); }
}

ProcesarConReintentos(
    () => Console.WriteLine("trabajo crítico"),
    ex => logear($"FALLO: {ex.Message}")
);

// Lambdas con statement body cuando hay lógica:
Func<string, bool> passwordSegura = pwd => {
    if (pwd.Length < 8) return false;
    return pwd.Any(char.IsDigit) && pwd.Any(char.IsUpper);
};

Las lambdas capturan variables locales del scope (closures): int factor = 3; Func<int,int> triplicar = n => n * factor; funciona. La variable vive mientras viva el delegado — cuidado con bucles que capturan la variable mutable compartida.

Errores comunes

Error típicoSíntomaCorrecto
out sin asignar en algún caminoCS0177: must assign before leavingAsignar SIEMPRE antes de cada return
Sobrecargas ambiguas entre síCS0121 ambiguous call en llamadas mixtasDiferenciar claramente o renombrar métodos
Defaults que cambian sin recompilar clientesLibrerías viejas siguen usando valor viejo horneadoOverloads encadenados para defaults públicos estables
Capturar variable de bucle en lambda esperando snapshotTodas las lambdas ven el ÚLTIMO valor (closure de variable)Copiar a local dentro del loop antes de capturar
ref a propiedad o literalNo compila: ref exige VARIABLEVariable temporal intermedia
Confundir Func<int,bool> con Predicate<int>No son intercambiables pese a misma firma prácticaPredicados para filtros; Func general

Ejercicios prácticos

  1. Biblioteca matemática: crea clase estática con sobrecargas de Maximo() para int, double y params int[]; prueba las tres rutas.
  2. TryParse propio: implementa TryParseFecha(string, out DateTime) validando formato dd/MM/yyyy; úsala con discard cuando solo importa validez.
  3. Motor de reglas funcional: lista de Func<Pedido, decimal> descuentos aplicables; recórrelos sumando; añade uno nuevo SIN tocar el motor.
  4. MinMax triple canal: método que recibe array y saca min/max/promedio vía tres outs; luego reescríbelo retornando tuple nombrada; compara legibilidad.
  5. Closure cazada: genera 3 lambdas en un for capturando i directo (bug demostrable) y versión corregida con local; imprime resultados y explica.
