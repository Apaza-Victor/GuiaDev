Records y modelado inmutable

Desde C# 9, el lenguaje empuja decididamente hacia la inmutabilidad por defecto: datos que no cambian tras crearse son más fáciles de razonar, thread-safe gratis y eliminan estados intermedios inválidos. Los records son el vehículo principal.

Record toolkit completo

// Record posicional: constructor + props init + Equals por valor
public record Punto(int X, int Y);

var a = new Punto(3, 4);
var b = new Punto(3, 4);
Console.WriteLine(a == b);          // TRUE: contenido, no referencia
Console.WriteLine(a.ToString());    // Punto { X = 3, Y = 4 }

// Deconstrucción:
var (x, y) = a;

// with: copia no destructiva — LA operación estrella
var movido = a with { X = 10 };
Console.WriteLine(movido);          // Punto { X = 10, Y = 4 } — 'a' intacta

// Record con lógica propia:
public record Moneda(decimal Cantidad)
{
    public Moneda Duplicar() => this with { Cantidad = Cantidad * 2 };
}

// Herencia entre records + exhaustividad:
public abstract record Figura;
public record Circulo(double Radio) : Figura;
public record Rectangulo(double Ancho, double Alto) : Figura;

double Area(Figura f) => f switch
{
    Circulo c       => Math.PI * c.Radio * c.Radio,
    Rectangulo r    => r.Ancho * r.Alto,
    _               => throw new UnreachableException("Figura nueva sin manejar")
};

int[] serie = [1, 2, 3];
string descripcion = serie switch
{
    []                    => "vacía",
    [var solo]            => $"un solo elemento: {solo}",

};

// Property patterns combinando todo:
static string Evalua(Empleado e) => e switch
{
    { Edad: < 18 }                          => "Menor: no contratamos",
    { Antiguedad: > 10, Sueldo: > 50000m }  => "Senior premium",
    { Antiguedad: > 5 }                     => "Veterano",
    _                                       => "Junior"
};

Records + switch expressions + patterns forman un trío que convierte lógica de negocio ramificada en tablas declarativas verificables. Si añades un nuevo subtipo de Figura, el compilador TE AVISA del case faltante — bugs de clasificación imposibles.

async/await: asincronía sin dolor

Las operaciones de I/O (red, disco, BD) tardan MILLISECONDS mientras tu CPU podría hacer millones de operaciones. async/await libera el hilo durante esas esperas — la base de servidores .NET que atienden miles de peticiones concurrentes:

using System.Net.Http;

HttpClient http = new();

// El método marca async, devuelve Task<T>, y await "pausa" sin bloquear:
async Task<string> DescargarAsync(string url)
{
    Console.WriteLine($"Descargando {url}...");
    string cuerpo = await http.GetStringAsync(url);   // hilo LIBERADO aquí
    Console.WriteLine($"Recibidos {cuerpo.Length} bytes");
    return cuerpo;
}

string html = await DescargarAsync("https://example.com");

Patrones esenciales

// Paralelizar independientes: Task.WhenAll
Task<string> t1 = http.GetStringAsync(url1);
Task<string> t2 = http.GetStringAsync(url2);
string[] resultados = await Task.WhenAll(t1, t2);   // ambas EN PARALELO
// ⚠️ await secuencial (await a; await b;) las haría SERIALES: 2x tiempo

// Timeout con CancellationToken:
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(3));
try {
    var datos = await http.GetStringAsync(urlLenta, cts.Token);
}
catch (TaskCanceledException) {
    Console.WriteLine("Timeout: cancelada a los 3s");
}

// Fire-and-forget responsable (raro pero útil):
_ = RegistrarMetricasAsync();   // descartada conscientemente

// Async Main ya existe: top-level statements son async-friendly
foreach (var url in urls)
    Console.WriteLine((await http.GetStringAsync(url)).Length);

NUNCA mezcles código síncrono bloqueante con async: result.Result o task.Wait() dentro de apps con contexto (ASP.NET clásico, UI) produce DEADLOCKS reales. Regla absoluta: "async all the way up" — si un método hace await, su firmo es async y sus llamadores también.

Ejercicios prácticos

  1. Figuras exhaustivas: jerarquía abstract record Figura + 3 formas; función Area con switch; añade Triangulo y observa el warning de exhaustividad ANTES de arreglarlo.
  2. Scraper paralelo: descarga 5 URLs con Task.WhenAll midiendo tiempo total vs suma secuencial (Stopwatch); documenta speedup obtenido.
  3. Inventario inmutable: record Producto; carrito como ImmutableList (System.Collections.Immutable) usando Add que retorna nueva lista; demuestra que el original jamás muta.
  4. List patterns: clasificador de series numéricas ([], [solo], ascendente con slice check, termina en X) usando list patterns C# 11.
  5. Cazador de deadlock didáctico: consola simple con .Result sobre async local (funciona por suerte) vs versión async correcta; comenta POR QUÉ el mismo patrón muere en ASP.NET Framework/UI.
