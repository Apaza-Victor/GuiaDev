Variables y tipos

C# divide su sistema de tipos en dos universos con comportamientos radicalmente distintos: los tipos de valor (structs, que se copian completas al asignar) y los tipos de referencia (classes, donde la variable guarda una referencia al objeto en el heap). Dominar esta distinción evita la mitad de los bugs de un principiante.

// Valor: copia independiente
int a = 42;
int b = a;
b++;
Console.WriteLine($"{a} {b}");   // 42 43

// Referencia: mismo objeto compartido
var lista1 = new List<int> {1, 2};
var lista2 = lista1;
lista2.Add(3);
Console.WriteLine(lista1.Count); // 3 — ¡la "otra" también cambió!

var, const y readonly

var nombre = "Ana";              // tipo DEDUCIDO en compilación: string
var edad = 30;                   // int — NO es dinámico, ES tipado fuerte
// nombre = 42;                  ❌ no compila: sigue siendo string

const double Pi = 3.14159;       // constante de COMPILACIÓN, inmutable
const int MaxIntentos = 3;

public class Config {
    public readonly DateTime CreadoEn;    // fijo DESPUÉS del constructor
    public Config() { CreadoEn = DateTime.Now; }
}

Regla práctica de var: úsalo cuando el tipo es OBVIO por el lado derecho (new, literales, casts). Evítalo cuando oculta información valiosa (var r = Procesar(); — ¿qué devuelve?). Y recuerda: dynamic sí es dinámico real, resuelto en runtime — casi nunca lo necesitas.

Nullable reference types: adiós a las NullReferenceException

Desde C# 8 activado por defecto en proyectos nuevos, el compilador DISTINGUE strings que pueden ser null de los que no:

#nullable enable

string obligatorio = "texto";     // NUNCA puede ser null
string? opcional = null;          // el ? declara "puede ser null" HONESTAMENTE

// Console.WriteLine(obligatorio.Length); ✅ garantizado seguro
if (opcional != null) {
    Console.WriteLine(opcional.Length);      // tras el check, flujo nulable satisfecho
}
Console.WriteLine(opcional?.Length ?? 0);    // operador ?. + ?? : 0 si null
Console.WriteLine(opcional!.Length!);        // ! = "confía, no es null" (último recurso)

El operador ! (null-forgiving) silencia al compilador pero NO protege en runtime: si te equivocas, NullReferenceException igual. Úsalo solo cuando puedas PROBAR la invariante, preferiblemente documentando por qué.

Strings e interpolación

string es un tipo de referencia INMUTABLE: cada "modificación" crea un nuevo objeto. Para construcción intensiva existe StringBuilder.

string nombre = "Ada";
int edad = 36;

// Interpolación ($): EL estándar moderno
string mensaje = $"{nombre} tiene {edad} años";
Console.WriteLine($"El IVA de {precio:C} es {precio * 0.21:C}");  // formato moneda
Console.WriteLine($"|{nombre,10}|");     // alineado derecha 10 espacios
Console.WriteLine($"|{nombre,-10}|");    // alineado izquierda
Console.WriteLine($"Ratio: {0.856:P1}"); // 85.6 %

// Verbatim (@): rutas y regex sin escapes dobles
string ruta = @"C:\Users\ana\documentos";
string json = """
    {
        "nombre": "multi-línea",
        "raw": true
    }
    """;                                  // raw string literals (C# 11)

// Métodos esenciales
nombre.ToUpper();                        // "ADA"
nombre.Substring(0, 2);                  // "Ad"
nombre.Contains("ad", StringComparison.OrdinalIgnoreCase);
string.Join(", ", new[] {"a", "b"});     // "a, b"
string vaciaOblanco = "   ".Trim();
bool blanca = string.IsNullOrWhiteSpace(vaciaOblanco);

// Split y manipulación
var partes = "ana@dev.io".Split('@');    // ["ana", "dev.io"]

Concatenar strings con += dentro de bucles genera O(n²): cada iteración copia TODO lo acumulado. Para miles de piezas usa StringBuilder.Append(). En código moderno, incluso mejor: string.Join() sobre colecciones.

Conversiones y casting seguro

Implícita vs explícita

int entero = 42;
long grande = entero;            // implícita: int cabe SIEMPRE en long ✅
double d = entero;               // implícita: sin pérdida

double pi = 3.99;
int truncado = (int)pi;          // explícita (cast): TRUNCA → 3, no redondea
long riesgo = (long)entero;      // cast necesario: posible pérdida silenciosa

checked                          // detectar overflow en runtime:
{
    int max = int.MaxValue;
    // int roto = max + 1;       ❌ lanza OverflowException dentro de checked
}

Console.Write("Edad: ");
if (int.TryParse(Console.ReadLine(), out int edadUsuario)) {
    Console.WriteLine($"Naciste aprox. en {DateTime.Now.Year - edadUsuario}");
} else {
    Console.WriteLine("No es un número válido");
}

// is/as para tipos de referencia:
object caja = "soy texto";
if (caja is string texto) {           // verifica Y CONVIERTE en una línea
    Console.WriteLine(texto.Length);
}
string? talVez = caja as string;      // null si no coincide, sin excepción

TryParse + out var es el patrón dominante para validar entrada. La cultura (CultureInfo) importa al parsear números: "3.14" es decimal en EE.UU. pero ¡314 en España! Para datos de servidor usa siempre CultureInfo.InvariantCulture.

Ejercicios prácticos

  1. Calculadora de IVA segura: pide precio por consola con TryParse (reintenta si inválido), calcula IVA 21% en decimal e imprime con formato :C de tu cultura.
  2. Demostrador valor vs referencia: replica el ejemplo List compartida; luego clona correctamente y verifica independencia; documenta en comentarios qué pasó línea a línea.
  3. Formateador de tabla: imprime 3 productos con interpolación alineada: |{nombre,-15}|{precio,10:C}|{stock,5}|.
  4. Parser robusto de fecha: lee "dd/MM/yyyy" del usuario con DateTime.TryParseExact y muestra día de semana en español (CultureInfo es-ES).
  5. Cazador de overflow: provoca overflow de int sin checked (valor absurdo silencioso) y con checked (excepción); explica la diferencia en comentario.
