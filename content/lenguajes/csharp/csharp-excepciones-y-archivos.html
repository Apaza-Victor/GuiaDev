try/catch/finally y jerarquía de excepciones

C# usa excepciones para condiciones excepcionales reales. Toda excepción hereda de System.Exception, y el runtime lanza tipos específicos cuando algo falla — tu trabajo es atrapar lo que PUEDES manejar y dejar propagar lo que no:

Estructura completa

try
{
    string contenido = File.ReadAllText("config.json");
    var config = JsonSerializer.Deserialize<Config>(contenido)
        ?? throw new InvalidOperationException("JSON nulo tras deserializar");
}
catch (FileNotFoundException ex)          // MÁS específicas primero
{
    Console.WriteLine($"Archivo ausente: {ex.FileName}. Usando defaults.");
    return Config.PorDefecto();
}
catch (JsonException ex) when (ex.Message.Contains("depth"))   // filtro 'when'
{
    Console.WriteLine("JSON demasiado anidado");
    throw;                                 // re-lanzar SIN perder stack trace
}
catch (IOException ex)                     // genérica después
{
    Console.WriteLine($"I/O falló: {ex.Message}");
    throw new ApplicationException("Lectura imposible", ex);  // envolver
}
finally
{
    // SIEMPRE se ejecuta: con o sin excepción, return o throw
    Console.WriteLine("Cerrando recursos...");
}

Excepciones propias: dominio expresivo

public class SaldoInsuficienteException : Exception
{
    public decimal Faltante { get; }
    public SaldoInsuficienteException(decimal faltante)
        : base($"Faltan {faltante:C} para completar la operación")
        => Faltante = faltante;

    // Constructor para serialización (convención):
    protected SaldoInsuficienteException(
        System.Runtime.Serialization.SerializationInfo info,
        System.Runtime.Serialization.StreamingContext context)
        : base(info, context) { }
}

// Lanzar con contexto:
if (monto > saldo)
    throw new SaldoInsuficienteException(monto - saldo);

// Atrapar con acceso a datos del dominio:
catch (SaldoInsuficienteException ex)
{
    MostrarAlerta($"Te faltan {ex.Faltante:C}");
}

NUNCA hagas catch (Exception) { } vacío: traga bugs silenciosamente y convierte diagnósticos en pesadillas. Si realmente debes capturar todo (top-level de app), LOGUEA siempre y decide si relanzar.

using y IDisposable: recursos que se limpian solos

Los archivos, conexiones y streams implementan IDisposable: liberan recursos NO gestionados por el GC. El statement using garantiza Dispose() al salir del bloque — incluso con excepciones:

// using statement: scope explícito
using (var reader = new StreamReader("datos.txt"))
{
    Console.WriteLine(reader.ReadLine());
}   // reader.Dispose() AUTOMÁTICO aquí, pase lo que pase

// using DECLARATION (C# 8): hasta fin del método, menos indentación
string LeerPrimeraLinea(string ruta)
{
    using var file = File.OpenText(ruta);
    return file.ReadLine() ?? "";
}   // disposed al salir de LeerPrimeraLinea

El GC gestiona MEMORIA automáticamente pero NO sabe cerrar archivos ni conexiones de red. Toda clase IDisposable que TÚ creas debe vivir dentro de un using — regla inquebrantable que evita fugas de handles (síntoma clásico: "too many open files" días después).

Operaciones comunes de archivos

using System.IO;

// Lectura rápida todo-de-golpe:
string texto = File.ReadAllText("notas.txt");

// Verificaciones y manipulación del sistema:

// Streams para archivos grandes línea a línea (memoria constante):
foreach (string linea in File.ReadLines("gigante.log"))   // perezoso ✅

    if (linea.Contains("ERROR")) Contar(linea);

// Directory:

System.Text.Json: serialización nativa

using System.Text.Json;
using System.Text.Json.Serialization;

public record Configuracion(
    [property: JsonPropertyName("nombre_app")] string NombreApp,
    [property: JsonPropertyName("puerto")] int Puerto,
    [property: JsonPropertyName("debug")] bool Debug = false);

// Serializar bonito:
var config = new Configuracion("MiApp", 8080, true);
string json = JsonSerializer.Serialize(config, new JsonSerializerOptions
{
    WriteIndented = true
});
File.WriteAllText("appsettings.json", json);

// Deserializar tolerante:
var leida = JsonSerializer.Deserialize<Configuracion>(
    File.ReadAllText("appsettings.json"),
    new JsonSerializerOptions { PropertyNameCaseInsensitive = true });
Console.WriteLine(leida?.NombreApp);   // MiApp

System.Text.Json (built-in desde .NET Core 3) es rápido y sin dependencias. Para JSON dinámico/exótico existe Newtonsoft.Json (el clásico), pero proyectos nuevos arrancan con el nativo.

Ejercicios prácticos

  1. Lector robusto de CSV: lee un CSV con ReadLines; parsea cada fila tolerando filas malformadas (skip + contador de errores); reporta total procesadas/fallidas.
  2. Jerarquía de dominio: crea ExcepcionBanco base + SaldoInsuficiente + LimiteExcedido con datos propios; simula operaciones lanzando y capturando cada una diferenciadamente.
  3. Config persistente: record Configuracion ↔ JSON en disco; si el archivo no existe, crea uno con defaults; valida JSON corrupto con mensaje amigable y backup del corrupto.
  4. Monitor de logs streaming: procesa un .log de ~100MB generado por ti con ReadLines contando niveles ERROR/WARN/INFO sin subir memoria (verifica con Task Manager).
  5. Cazador de throw ex: demuestra la pérdida de stack trace con throw ex; luego corrige a throw; comparando los stack traces impresos.
