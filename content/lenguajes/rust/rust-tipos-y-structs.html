Variables: inmutabilidad, mut y shadowing

En Rust let crea una variable inmutable por defecto. Esta decisión de diseño es deliberada: si un valor no puede cambiar, el compilador y cualquier persona que lea el código pueden razonar sobre él sin rastrear mutaciones. Cuando realmente necesitas modificar un valor, lo pides explícitamente con mut, dejando constancia en la firma misma del código:

fn main() {
    let x = 5;
    // x = 6;            // ❌ error[E0384]: cannot assign twice to immutable variable

    let mut y = 5;       // mut = "esta variable va a cambiar"
    y += 1;              // ✅ permitido
    println!("y vale {}", y);
}

Shadowing: no es lo mismo que mut

El shadowing redeclara la variable con otro let: se crea una variable nueva que oculta a la anterior hasta el fin del scope. La diferencia con mut es fundamental y aparece en entrevistas:

fn main() {
    let saldo = 100;
    let saldo = saldo + 50;      // shadowing: NUEVA variable (150)
    let saldo = saldo.to_string(); // ✅ incluso puede cambiar de TIPO: "150"

    let mut deuda = 30;
    // deuda = "treinta";        // ❌ con mut NO puedes cambiar el tipo

    println!("saldo = {}", saldo);   // imprime el más reciente
}

Diferencia clave para entrevistas: el shadowing crea una variable nueva (puede cambiar de tipo y volver a ser inmutable); mut modifica siempre la misma celda, del mismo tipo, hasta el fin del scope.

Además existen constantes: const MAX_INTENTOS: u32 = 3;. Tipo anotado obligatorio, valor calculado en compilación y nombres en MAYÚSCULAS_CON_GUIONES por convención.

Tipos escalares: enteros, flotantes, bool y char

Rust es estática y fuertemente tipado: cada valor tiene un tipo conocido en compilación y no hay conversiones implícitas entre números. A cambio, el compilador infiere el tipo casi siempre, así que rara vez anotas:

fn main() {
    let entero = -42;            // i32 inferido (el default)
    let grande: u64 = 42_u64 * 1_000_000_000;  // sufijo explícito
    let decimal = 3.14;          // f64 inferido (el default)
    let activo = true;           // bool
    let letra = 'ñ';             // char con comilla SIMPLE
    let emoji = '🚀';            // char soporta TODO Unicode

    println!("{} {} {} {} {} {}", entero, grande, decimal, activo, letra, emoji);
}

A diferencia de C, un char en Rust ocupa 4 bytes porque representa un punto Unicode completo, no un byte ASCII. Y los literales numéricos aceptan guion bajo como separador visual: 1_000_000.

Un desbordamiento de entero hace pánico en modo debug pero wraps silenciosamente en release. Si el límite importa en tu lógica, usa métodos como checked_add() o saturating_add() en lugar de confiar en el perfil de compilación.

Tipos compuestos: tuplas, arrays y rangos

Tuplas: heterogéneas y de tamaño fijo

Una tupla agrupa valores de tipos distintos en un solo valor fijo. Se accede por posición con .0, .1... o se desestructura:

fn main() {
    let persona: (&str, i32, bool) = ("Ana", 30, true);

    // Acceso posicional
    println!("Nombre: {}, edad: {}", persona.0, persona.1);

    // Destructuring: extrae los componentes de golpe
    let (nombre, edad, _activo) = persona;
    println!("{} tiene {} años", nombre, edad);
}

Arrays: tamaño fijo, vivos en el stack

A diferencia de otros lenguajes, el array de Rust tiene longitud parte de su tipo ([i32; 3] ≠ [i32; 4]) y vive en el stack. Para colecciones dinámicas usarás Vec:

fn main() {
    let dias = ["lun", "mar", "mié"];       // [&str; 3]: el 3 está en el tipo
    let ceros = [0_u8; 512];                // 512 ceros inicializados
    let primero = dias[0];                  // indexación con corchetes

    println!("{} días, len={}", dias.len(), ceros.len());
    // let fuera = dias[7];  // ❌ compila, pero PANIC en ejecución: out of bounds
}

Rangos para iterar y acotar

fn main() {
    for i in 0..5 { print!("{} ", i); }      // 0 1 2 3 4   (exclusivo)
    println!();
    for i in 1..=5 { print!("{} ", i); }     // 1 2 3 4 5   (inclusivo con =)

    // También acotan slices: &nums[1..4] toma los elementos 1, 2 y 3
}

Structs: tus propios tipos con nombre

Los structs empaquetan datos relacionados bajo un nombre con significado de dominio. Son el ladrillo básico de modelado en Rust: donde en otros lenguajes crearías una clase solo para guardar datos, aquí basta un struct:

#[derive(Debug)]                 // habilita impresión con {:?}
struct Usuario {
    nombre: String,
    edad: u8,
    activo: bool,
}

fn main() {
    let mut u = Usuario {
        nombre: String::from("Ana"),
        edad: 30,
        activo: true,
    };

    u.edad += 1;
    let admin = Usuario {               // sintaxis de actualización:
        nombre: String::from("Beto"),   // copia los campos restantes
        ..u                             // ⚠️ mueve u.nombre: u queda parcialmente inutilizable
    };
    println!("{:?}\n{:#?}", admin, admin);   // Debug en línea y bonito
}

Tuple structs y unit structs

Existen dos variantes adicionales con casos de uso específicos:

// Tuple struct: campos SIN nombre, útiles para wrappers tipados
struct Coordenada(f64, f64);
struct Milimetros(f64);
struct Pulgadas(f64);

// Unit struct: sin datos, útil como marcador o para implementar traits
struct Auditoria;

fn main() {
    let origen = Coordenada(0.0, 0.0);
    println!("x = {}, y = {}", origen.0, origen.1);

    let largo = Milimetros(250.0);
    let ancho = Pulgadas(9.8);
    // largo == ancho ❌ ni siquiera compilan juntas: son tipos DISTINTOS
    // Eso es justo lo que buscábamos: imposible confundir unidades.
    let _ = Auditoria;   // instancia vacía de un tipo marcador
}

Envolver primitivos en tuple structs (newtype pattern) es idiomático: da semántica al tipo e impide mezclas de unidades como la que costó la sonda Mars Climate Orbiter.

Métodos con impl: comportamiento junto a los datos

Los métodos se definen en un bloque impl, separado de los datos. Dentro, Self es un alias del tipo que se implementa. Hay dos clases de funciones:

ClaseReconócelaCómo se llama
Método de instanciaPrimer parámetro &self o &mut selfobjeto.metodo()
Función asociadaSin self (como constructores)Tipo::funcion()
#[derive(Debug)]
struct Rectangulo {
    ancho: f64,
    alto: f64,
}

impl Rectangulo {
    // Función ASOCIADA: constructor por convención llamado `new`
    fn new(ancho: f64, alto: f64) -> Self {
        // Self es alias de Rectangulo; la abreviatura omite campo: valor
        Self { ancho, alto }
    }

    fn area(&self) -> f64 {              // &self: solo lectura
        self.ancho * self.alto
    }

    fn escalar(&mut self, factor: f64) { // &mut self: modifica
        self.ancho *= factor;
        self.alto *= factor;
    }

    fn es_cuadrado(&self) -> bool {     // los métodos pueden devolver lo que sea
        (self.ancho - self.alto).abs() < f64::EPSILON
    }
}

fn main() {
    let mut r = Rectangulo::new(3.0, 4.0);   // llamada con :: (función asociada)
    println!("Área inicial: {}", r.area());   // llamada con . (método)

    r.escalar(2.0);                           // necesita que r sea mut
    println!("Tras escalar: {:?}", r);
    println!("¿Cuadrado? {}", r.es_cuadrado());
}

Rust no tiene herencia de structs: no hay class B extends A. La reutilización se logra con composición (un struct dentro de otro) y con traits, que verás en su propia lección. Es una decisión consciente contra el infierno de jerarquías profundas.

Hábito pro: deriva Debug en todos tus structs desde el principio. Te permitirá imprimirlos con {:?}/{:#?} durante toda la vida del proyecto sin toques extra.

Errores comunes con tipos y structs

Estos son los tropiezos típicos al empezar con el sistema de tipos de Rust, con su diagnóstico y remedio:

SíntomaCausa probableSolución
doesn't implement Debug al usar {:?}Falta derivar el traitAñade #[derive(Debug)] sobre el struct
Comparar floats con == da resultados rarosPrecisión binaria de IEEE-754(a - b).abs() < f64::EPSILON
mismatched types: expected f64, found i32Rust no convierte números solosConversión explícita: x as f64 o f64::from(x)
cannot borrow as mutable al llamar métodoLa variable no era mutlet mut obj = ...;
Desbordamiento silencioso en releaseWraps sin avisar fuera de debugchecked_add() / saturating_add()
Índice fuera de rango panea el programaIndexación directa de array/VecUsa .get(i) que devuelve Option<&T>

No uses as para conversiones numéricas "porque compila": 300_u64 as u8 trunca a 44 silenciosamente. Para conversiones que pueden perder información prefiere try_from(), que devuelve Result.

Ejercicios prácticos

Resuelve en orden creciente; cada uno refuerza lo anterior.

  1. Inferencia y escalares: declara una variable de cada tipo escalar (i32, u64, f64, bool, char) sin anotar tipos, imprímelas con {:?}, y luego fuerza el error E0308 mezclando i32 con f64 en una suma para leer el mensaje del compilador.
  2. Shadowing vs mut: parte de la cadena "42" y conviértela a número con shadowing (parse().unwrap()), súmale 8 y muestra el resultado; después repítelo usando let mut y observa qué problema de tipos aparece.
  3. Tupla de coordenadas: crea una tupla (f64, f64) como punto, desestrúcturala y calcula la distancia al origen con x * x + y * y y raíz cuadrada (f64::sqrt).
  4. Struct Libro: modela Libro con título, autor, páginas y leído (bool); deriva Debug; crea dos instancias (una con sintaxis de actualización), marca uno como leído mediante un método terminar(&mut self), e imprime ambos con {:#?}.
  5. Cuenta bancaria: implementa CuentaBancaria con constructor asociado nueva(titular, saldo_inicial) que rechace saldos negativos devolviendo Option<CuentaBancaria>, más métodos depositar(&mut self, monto: f64) y retirar(&mut self, monto: f64) -> Result<(), String>; simula varias operaciones e imprime el estado final con Debug.
