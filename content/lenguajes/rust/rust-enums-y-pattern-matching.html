Enums con datos: mucho más que constantes

Si vienes de C o Java, olvida los enums numéricos. Un enum de Rust es un tipo suma: el valor es exactamente UNA de sus variantes, y cada variante puede llevar datos propios distintos. Es la herramienta de modelado más poderosa del lenguaje:

enum Forma {
    Circulo(f64),                    // variante con un dato: radio
    Rectangulo(f64, f64),            // variante con dos: base, altura
    Triangulo { base: f64, altura: f64 }, // variante estilo struct
}

fn area(f: &Forma) -> f64 {
    match f {
        Forma::Circulo(r) => std::f64::consts::PI * r * r,
        Forma::Rectangulo(a, b) => a * b,
        Forma::Triangulo { base, altura } => base * altura / 2.0,
    }
}

fn main() {
    let formas = [Forma::Circulo(1.0), Forma::Rectangulo(2.0, 3.0)];
    for f in &formas {
        println!("Área: {:.2}", area(f));
    }
}

Los tipos que ya conoces están construidos así: Option y Result son enums de la stdlib con genéricos. No hay magia especial:

// Así están definidos en la biblioteca estándar:
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}

Cuando modelas estados ("cargando", "listo", "error con mensaje"), un enum obliga a representar SOLO combinaciones válidas. Los bugs de estado imposible desaparecen por diseño.

---

Option<T>: Rust no tiene null (y por qué)

Tony Hoare inventó null en 1965 y lo llamó después "mi error de los mil millones de dólares": referencias nulas que revientan en ejecución. Rust eliminó el problema de raíz: no existe null. En su lugar, "quizás hay un valor" se representa con Option<T>, y el compilador te OBLIGA a considerar ambos casos:

fn buscar_usuario(id: u32) -> Option<String> {
    if id == 1 {
        Some(String::from("Ana"))     // hay valor
    } else {
        None                          // no hay valor: explícito y tipado
    }
}

fn main() {
    let resultado = buscar_usuario(1);

    // El compilador RECHAZA usar el String sin desenvolverlo antes:
    // println!("{}", resultado.len());  // ❌ error: Option no tiene .len()

    match resultado {
        Some(nombre) => println!("Encontrada: {}", nombre),
        None => println!("Usuario inexistente"),
    }

    // Atajos para casos simples:
    let nombre = buscar_usuario(99).unwrap_or(String::from("anónimo"));
    println!("Hola, {}", nombre);
}
Lenguaje con nullRust con Option<T>
Cualquier variable puede ser null sorpresivamenteEl tipo declara si puede faltar: Option<String> vs String

Option convierte una categoría entera de crashes en errores de compilación. Cuando veas Option<T> en una firma, sabes SIN leer el cuerpo que puede no haber valor.

Match: exhaustivo y como expresión

match compara un valor contra patrones y ejecuta el brazo correspondiente. Dos superpoderes lo distinguen del switch tradicional: es exhaustivo (el compilador rechaza variantes sin cubrir) y es una expresión que devuelve un valor:

enum EstadoEnvio {
    Pedido,
    EnCamino(u32),          // días estimados restantes
    Entregado,
    Perdido(String),        // motivo
}

fn describir(estado: EstadoEnvio) -> String {
    // Cada brazo devuelve un String: el MATCH completo ES ese valor
    match estado {
        EstadoEnvio::Pedido => String::from("Esperando recojo"),
        EstadoEnvio::EnCamino(dias) => format!("Llega en {} días", dias),
        EstadoEnvio::Entregado => String::from("¡Recibido!"),
        EstadoEnvio::Perdido(motivo) => format!("Perdido: {}", motivo),
    }   // ← quita cualquier brazo y verás error[E0004]: non-exhaustive patterns
}

Bindings: extraer datos dentro del patrón

Fíjate cómo EnCamino(dias) no solo compara: captura el dato interno en la variable dias. Eso es un binding, y funciona anidado a cualquier profundidad:

match respuesta_http {
    Some((200, cuerpo)) => procesar(&cuerpo),      // tupla anidada desestructurada
    Some((404, _)) => println!("No encontrado"),
    Some((codigo, _)) if codigo >= 500 => println!("Error del servidor"),
    Some(_) => println!("Respuesta inesperada"),
    None => println!("Sin conexión"),
}

Los guards (if codigo >= 500) añaden condiciones extra al patrón cuando la estructura sola no basta.

---

Patrones avanzados: _, |, rangos y @

El pattern matching de Rust es un mini-lenguaje propio. Estos son los patrones que usarás a diario:

fn clasificar(n: i32) -> &'static str {
    match n {
        0 => "cero",
        1 | 2 | 3 => "pequeño",           // OR-patterns: varias opciones, un brazo
        4..=9 => "mediano",               // rango inclusivo
        negativo if negativo < 0 => "negativo",  // guard condicional
        _ => "grande",                    // comodín: todo lo demás
    }
}

fn main() {
    // Desestructuración profunda de structs y tuplas:
    struct Punto { x: i32, y: i32 }
    let p = Punto { x: 0, y: 7 };
    match p {
        Punto { x: 0, y } => println!("Sobre el eje Y en {}", y),
        Punto { x, y: 0 } => println!("Sobre el eje X en {}", x),
        Punto { x, y } => println!("Punto libre ({}, {})", x, y),
    }
}

if let y while let: azúcar para un solo caso

Cuando un match completo es demasiado para lo que necesitas —solo te importa UNA variante—, if let expresa la intención con menos ruido:

fn main() {
    let config: Option<&str> = Some("produccion.toml");

    // Con match: verboso para un solo caso real
    match config {
        Some(ruta) => println!("Cargando {}", ruta),
        _ => (),                       // brazo obligatorio aunque no haga nada
    }

    // Con if let: directo y legible (y admite else para el caso contrario)
    if let Some(ruta) = config {
        println!("Cargando {}", ruta);
    } else {
        println!("Usando valores por defecto");
    }
}
}

while let: consumir hasta agotar

Su caso estrella es drenar una colección mientras quede algo que extraer:

fn main() {
    let mut pila = vec![3, 2, 1];

    while let Some(tope) = pila.pop() {   // itera MIENTRAS haya elementos
        println!("Procesando {}", tope);
    }
    // pop() devuelve None al vaciar: el bucle termina limpiamente
}

No abuses de if let para silenciar casos: si tu lógica debe reaccionar ante TODAS las variantes, match exhaustivo te protege de olvidos cuando el enum crezca. Regla rápida: un caso relevante → if let; todos relevantes → match.

Métodos esenciales de Option

Escribir match para cada Option sería agotador. La stdlib trae una batería de métodos combinables que cubren casi todos los escenarios:

MétodoComportamientoIdeal para
unwrap()Devuelve el valor o PANICA si es NoneSolo prototipos y tests
expect("msg")Como unwrap pero con tu mensaje en el panicInvariantes "imposibles" documentadas
unwrap_or(def)Valor o un default calculado yaValores por defecto inmediatos
unwrap_or_else(|| ...)Valor o default perezoso (closure)Defaults caros de calcular
map(|x| ...)Transforma el interior: Some→Some, None→NoneConversión sin tocar el caso vacío
and_then(|x| ...)Encadena otra operación que devuelve OptionCadenas de pasos fallibles

fn main() {
    let entrada = "  30 ";                       // edad tecleada por usuario

    let edad: Option<u32> = entrada.trim().parse().ok(); // Err → None
    let mayor = edad.map(|e| e >= 18);           // Some(true) — sin unwrap

    println!("¿Mayor de edad? {:?}", mayor);
}

El estilo idiomático encadena map/and_then/filter y deja un único punto final donde decides qué hacer con el None. Tu código queda plano, sin pirámides de match anidados.

Errores comunes con enums y matching

El compilador te protege mucho aquí, pero estos tropiezos aparecen en cuanto dejas de leer sus mensajes:

Un unwrap() olvidado sobre None derriba todo el proceso. Regla profesional: unwrap()/​expect() solo en tests, ejemplos o cuando la invariante esté demostrada dos líneas arriba.

Ejercicios prácticos

Réslolos en orden; cada uno sube el nivel de modelado exigido.

  1. Semáforo: crea el enum Semaforo { Rojo, Amarillo, Verde } con método segundos(&self) -> u32 vía match, y un bucle for que recorra las tres fases imprimiendo su duración.
  2. Figuras geométricas: define enum Figura con variantes Circulo(f64), Rectangulo(f64, f64) y TrianguloEquilatero(f64); implementa area(&self) -> f64 como match-expresión y pruébala con un array de figuras.
  3. Option seguro: escribe fn dividir(a: f64, b: f64) -> Option<f64> y consúmela tres veces: con match, con if let y con map+unwrap_or. Compara legibilidad en tus comentarios.
  4. Parser de comandos: dada la entrada "add 5 3" / "mul 4 2", usa split_whitespace() + collect::<Vec<_>>() + match con patrones [op, x, y] y guards para implementar una mini-calculadora textual.
  5. Máquina expendedora: modela estados (Esperando, MonedaInsertada(u32), ProductoServido(String)) con un enum, procesa una cola de eventos con while let sobre un Vec y usa bindings @ con rangos para validar montos.
