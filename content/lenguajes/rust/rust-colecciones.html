Vec<T>: la colección por defecto

El Vec<T> es un array dinámico que crece en el heap: el equivalente a listas de Python o arrays de JavaScript, pero con las reglas de ownership aplicadas. Es la colección más usada de todo Rust:

fn main() {
    // Dos formas de crearlo:
    let mut notas: Vec<f64> = Vec::new();     // explícito
    let mut primos = vec![2, 3, 5, 7];        // macro vec!: inferencia incluida

    notas.push(7.5);                          // push añade al final (necesita mut)
    notas.push(9.0);
    notas.insert(0, 5.0);                     // insertar en posición concreta

    let ultima = notas.pop();                 // Option<f64>: Some(9.0) si había

    // ACCESO: dos caminos con filosofías distintas
    let segunda = notas[1];                   // f64 directo — PANIC si no existe
    let segura = notas.get(10);               // Option — None en vez de paniquear

    println!("segunda={} get(10)={:?}", segunda, segura);
    println!("¿Contiene el 3? {}", primos.contains(&3));
}
OperaciónComportamientoCuándo usarla
v[i]Devuelve T directo; PANICA fuera de rangoÍndices garantizados por tu lógica
v.get(i)Devuelve Option<&T>; None si faltaÍndices externos o dudosos
v.push(x) / v.pop()Añade / extrae del final (O(1))Pilas y acumulación secuencial
v.remove(i) / v.insert(i,x)Desplaza elementos (O(n))Mutación puntual en medio
v.len() / v.is_empty()Tamaño actualCondicionales y bucles

El pánico index out of bounds derriba el programa completo. Si el índice viene de entrada del usuario o de datos externos, usa SIEMPRE .get() y decide qué hacer con el None.

String vs &str: la confusión número uno

Rust tiene DOS tipos de texto y entenderlos desbloquea la lectura de cualquier API. String es dueño de sus bytes en el heap (crecible); &str ("string slice") es una vista prestada sobre texto existente:

AspectoString&str
PropiedadDueño de su buffer en heapPréstamo (slice) sobre otro texto
Estructura internaPuntero + longitud + capacidadPuntero + longitud (fat pointer)
Mutar/crecerSí: push_str, + , etc.No: es inmutable y fijo
Uso idealCampos de struct, acumular texto, devolverParámetros de funciones, leer fragmentos

La coerción automática hace que un &String se convierta en &str donde haga falta, pero no al revés:

fn saludar(nombre: &str) {           // acepta &str Y &String gracias al deref
    println!("¡Hola, {}!", nombre);
}

fn main() {
    let owned = String::from("GuiaDev");   // String: dueño en el heap
    let literal = "Rust";                  // &'static str: incrustado en el binario

    saludar(&owned);                       // &String → &str automáticamente
    saludar(literal);

    let vista: &str = &owned[0..4];        // slice "Guid" SIN copiar nada
    let copia: String = literal.to_string(); // ahora sí, dueño nuevo
    println!("{} {} {}", vista, copia.len(), owned);
}

Regla de oro para firmas: parámetros → &str (máxima flexibilidad); campos y retornos → String (propiedad clara). Así diseñan las APIs estándar.

Operar strings: concatenar y construir

Los textos UTF-8 de Rust no se indexan por caracteres (¡'ñ' ocupa 2 bytes, '🚀' cuatro!), pero sí ofrecen un arsenal de operaciones seguras:

fn main() {
    let mut saludo = String::from("Hola");
    saludo.push_str(", mundo");          // añade un &str
    saludo.push('!');                    // añade UN char

    // format! NO consume nada y es el preferido para combinar:
    let mensaje = format!("{} — {}", saludo, "Rust es rápido");
    println!("{}", mensaje);

    // Transformaciones habituales:
    let limpio = "  Hola Mundo  ".trim().to_lowercase();
    let palabras: Vec<&str> = "a,b,c".split(',').collect();
    println!("{} | {:?}", limpio, palabras);
}
FormaConsume operandosRecomendada para
s.push_str(t) / s.push(c)No (muta s)Construir incrementalmente
s1 + &s2Sí: mueve s1Casi nunca (sorprende)
format!("{}{}", a, b)NoCombinar varios valores con formato
.concat() / .join(sep)NoUnir colecciones de &str

HashMap y la entry API

HashMap<K, V> mapea claves a valores con acceso O(1). Viene del módulo collections (no está precargado), y sus métodos de acceso devuelven Option, coherente con lo aprendido:

use std::collections::HashMap;

fn main() {
    let mut edades = HashMap::new();
    edades.insert("Ana", 30);
    edades.insert("Luis", 25);

    match edades.get("Ana") {            // get devuelve Option<&i32>
        Some(e) => println!("Ana tiene {}", e),
        None => println!("Desconocida"),
    }

    edades.remove("Luis");
    println!("¿Está Luis? {}", edades.contains_key("Luis"));

    for (nombre, edad) in &edades {      // iterar pares clave-valor
        println!("{}: {}", nombre, edad);
    }
}

entry(): el patrón clásico de conteo de palabras

El escenario más común —"si la clave existe suma, si no inicializa"— tiene un método dedicado que evita búsquedas duplicadas:

use std::collections::HashMap;

fn main() {
    let texto = "hola mundo hola rust hola mundo";
    let mut conteo = HashMap::new();

    for palabra in texto.split_whitespace() {
        // entry devuelve Vacant (inserta 0) u Occupied (devuelve el valor)
        *conteo.entry(palabra).or_insert(0) += 1;
    }

    println!("{:#?}", conteo);
    // {"hola": 3, "mundo": 2, "rust": 1}
}

*map.entry(k).or_insert(default) += 1 es EL patrón para contadores, cachés y agrupaciones. Apréndelo de memoria: aparece en cada codebase Rust del planeta.

Iteradores: map, filter y collect

Toda colección expone un iterador: un objeto perezoso que produce valores bajo demanda. Los adaptadores (map, filter) transforman el flujo sin consumirlo aún; los consumidores (collect, sum) disparan el trabajo real:

fn main() {
    let nums = [1, 2, 3, 4, 5, 6];

    // Pipeline: pares al cuadrado. NADA se ejecuta hasta collect()
    let cuadrados_pares: Vec<i32> = nums
        .into_iter()               // toma posesión del array
        .filter(|&n| n % 2 == 0)   // deja pasar 2, 4, 6
        .map(|n| n * n)            // transforma: 4, 16, 36
        .collect();                // ← aquí SÍ se itera de verdad

    println!("{:?}", cuadrados_pares);   // [4, 16, 36]

    // Consumidores numéricos directos:
    let total: i32 = nums.iter().sum();
    let maximo = nums.iter().max();
    println!("suma={} max={:?}", total, maximo);
}

Perezosos por diseño

La evaluación es lazy: puedes encadenar diez adaptadores y el coste será un único recorrido cuando llegue el consumidor. No hay arrays intermedios ocultos como en otros lenguajes funcionales.

Si collect() se queja de tipos ambiguos, anota el destino (let v: Vec<i32>) o usa el turbofish: collect::<Vec<i32>>(). Es el error de compilación #1 de esta sección.

iter(), into_iter() e iter_mut()

Tres métodos parecidos con consecuencias de ownership radicalmente distintas. Elegir mal es fuente constante de errores de compilación:

MétodoEntrega¿Consume la colección?Úsalo para
.iter()&T (referencias)NoSolo LEER elementos
.iter_mut()&mut TNoMODIFICAR en sitio
.into_iter()T (valores propios)SÍ: la colección muereTransformar/transferir propiedad
fn main() {
    let mut nombres = vec![String::from("ana"), String::from("luis")];

    // iter(): préstamo de lectura — nombres sigue vivo después
    let longitudes: Vec<usize> = nombres.iter().map(|n| n.len()).collect();

    // iter_mut(): préstamo mutable — transforma sin mover
    for n in nombres.iter_mut() {
        n.make_ascii_uppercase();
    }

    // into_iter(): CONSUME — tras este bucle, nombres ya no existe
    for n in nombres.into_iter() {
        println!("procesando y descartando: {}", n);
    }

    println!("{:?} {:?}", longitudes, "fin");   // nombres aquí daría E0382
}

Un bucle for x in coleccion sin método llama implícitamente a into_iter(): ¡consume la colección! Si necesitas seguir usándola después, escribe for x in &coleccion.

Errores comunes con colecciones

Los mismos cuatro o cinco errores se repiten en todo el mundo Rust al manejar Vec, String y HashMap. Reconocerlos ahorra horas:

Error / síntomaCausaSolución
Panic index out of boundsIndexar con v[i] fuera de rangoUsa v.get(i) y maneja el None
E0382 tras concatenar con +El operador + mueve el primer StringUsa format!
E0502: borrow while iteratingMutar mientras un iterador prestado viveiter_mut(), o construir una nueva colección
E0382 después de un forEl bucle consumió la colección (into_iter implícito)Itera con &coleccion
type annotations needed con collectInferencia no sabe qué colección quieresAnota: Vec<T>, HashMap<K,V>... o turbofish
HashMap "desordena" las clavesEs por diseño (hash aleatorio por ejecución)Usa BTreeMap si necesitas orden estable

No copies colecciones enteras con .clone() para poder mutarlas "tranquilamente": casi siempre hay una versión con referencias o iteradores que resuelve sin coste.

Ejercicios prácticos

Réslolos en orden; los últimos combinan varias colecciones a la vez.

  1. Gestor de notas: crea Vec<String> con 4 notas, imprime la media con iter().sum(), la máxima SIN usar max() (bucle manual) y elimina la última con pop().
  2. Normalizador: dado [" ana ", "LUIS", "Beto "], genera un nuevo Vec<String> con nombres trimados y capitalizados usando solo iteradores (map + to_lowercase + manipulación del primer char).
  3. Vocales por palabra: cuenta cuántas vocales tiene cada palabra de una frase y guarda el resultado en un HashMap usando entry().or_insert(0); imprime el mapa ordenado alfabéticamente (pista: recolecta y ordena las claves).
  4. Inventario: define struct Producto { nombre: String, precio: f64, categoria: String }; con iteradores obtén: productos bajo $50 (Vec), valor total del inventario (sum) y un HashMap<String, f64> con el subtotal por categoría.
  5. Top-3 palabras: analiza un párrafo completo, cuenta frecuencias con HashMap entry API y muestra las 3 palabras más repetidas usando sort_by sobre un Vec de tuplas —sin consumir el mapa original.
