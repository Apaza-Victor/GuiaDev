¿Por qué existe Rust?

Rust nació en 2006 como el proyecto personal de Graydon Hoare, un ingeniero frustrado por un bug de memoria que hacía fallar el software de un ascensor. En 2009 Mozilla patrocinó el desarrollo para reconstruir su motor CSS, y en mayo de 2015 se publicó la versión estable Rust 1.0. La meta era ambiciosa: lograr el rendimiento de C/C++ eliminando, de raíz, toda una familia de errores que llevan décadas causando vulnerabilidades.

El problema que resuelve: la seguridad sin recolector de basura

Java o Python garantizan memoria con un garbage collector que pausa tu programa; C/C++ dan control total pero delegan toda la responsabilidad en ti. Rust propone una tercera vía: el modelo de ownership, reglas que el compilador verifica en tiempo de compilación. El resultado es binario nativo tan rápido como C donde fugas, punteros colgantes y carreras de datos simplemente no compilan:

fn main() {
    let mut nombres = vec![String::from("Ana"), String::from("Luis")];
    let primero = &nombres[0];           // préstamo inmutable
    nombres.push(String::from("Beto")); // ❌ ERROR: mutar durante un préstamo
    println!("El primero es {}", primero);
}

Si tu código compila en Rust, la memoria ya es segura: sin segfaults por punteros nulos, sin doble liberación y sin carreras de datos. Ese es el lema "fearless concurrency".

Ventajas frente a trade-offs

Ningún lenguaje es gratis. Rust cobra su seguridad en forma de curva de aprendizaje y tiempos de compilación, y conviene saberlo antes de empezar:

VentajaTrade-off asociado
Memoria segura garantizada al compilarCurva de aprendizaje pronunciada (ownership, borrowing, lifetimes)
Rendimiento comparable a C/C++Tiempos de compilación más largos que lenguajes interpretados
Herramienta integrada excelente (cargo, clippy, rustfmt)Ecosistema más joven; menos librerías que en Java o Python
Mensajes de error didácticos con sugerenciasLuchar contra el "borrow checker" desanima a principiantes

Dónde se usa Rust en el mundo real

Rust ya no es un experimento académico: está dentro del kernel de Linux, del navegador que quizás usas ahora mismo y de la infraestructura que sirve gran parte del tráfico web. Su nicho natural son los lugares donde antes solo se atrevía C/C++ pero donde un fallo de memoria sale carísimo.

ÁreaProyectos realesPor qué Rust
Herramientas CLIripgrep, fd, batBinario único, arranque instantáneo, multiplataforma
NavegadoresFirefox (componentes de Servo)Paralelismo seguro para renderizado CSS
Kernels y driversKernel Linux (desde 6.1), drivers de WindowsMenos del 70% de las vulnerabilidades de CVEs son de memoria
WebAssemblyJuegos, módulos Figma/1PasswordBinarios pequeños y predecibles para WASM
Servidores y cloudAWS Firecracker, Discord, CloudflareBaja latencia sin GC, consumo mínimo de RAM

Desde la versión 6.1 del kernel Linux (2022) ya se aceptan drivers escritos en Rust: la comunidad espera reducir drásticamente los bugs de memoria en código nuevo.

Instalación con rustup

La forma oficial de instalar Rust es rustup, un gestor de versiones que instala todo el toolchain y te permite cambiar entre canales (stable, beta, nightly). Esta guía usa Edition 2021 con Rust 1.75+, disponible en el canal estable actual.

# Windows: descarga y ejecuta https://rustup.rs (rustup-init.exe)
# macOS / Linux:
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Verificar la instalación
rustc --version   # compilador
cargo --version   # gestor de proyectos y dependencias

# Mantener todo al día
rustup update

# Abrir la documentación local completa
rustup doc
ComponenteRol
rustupGestor del toolchain: instala y actualiza versiones de Rust
rustcEl compilador: transforma .rs en binarios nativos
cargoSistema de builds + gestor de paquetes (crates.io)
clippyLinter con más de 700 reglas de buenas prácticas

En Windows, rustup necesita las C++ Build Tools de Visual Studio (el enlazador MSVC). Si la instalación falla, instala "Desktop development with C++" desde el instalador de Visual Studio y vuelve a intentarlo.

Tu primer proyecto con cargo

Olvida compilar archivos sueltos: en Rust siempre trabajas dentro de un proyecto gestionado por cargo. Un solo comando crea la estructura completa, lista para crecer:

cargo new hola_guia_dev
cd hola_guia_dev
cargo run

Cargo genera Cargo.toml (manifiesto) y src/main.rs (punto de entrada), listos para crecer. Además distingue tres formas de trabajar sobre tu proyecto, cada una pensada para un momento distinto del ciclo de desarrollo:

ComandoQué haceCuándo usarlo
cargo checkValida tipos y ownership SIN generar binarioVerificación rápida mientras escribes código
cargo buildCompila a target/debug/ sin ejecutarPreparar el ejecutable para pruebas locales
cargo runCompila (si hace falta) y ejecutaProbar el programa en desarrollo
cargo build --releaseCompila optimizado a target/release/Entregar o medir rendimiento real

Acostúmbrate al ciclo cargo check → editar → cargo check. Es varias veces más rápido que cargo build porque omite la generación del binario, y detecta el 90% de los errores del borrow checker igualmente.

Anatomía del Hello World y println!

El archivo src/main.rs generado contiene apenas dos líneas, pero encierran dos conceptos clave del lenguaje: la función de entrada main y las macros.

fn main() {                          // fn declara funciones; main es el punto de entrada
    println!("Hola, GuiaDev!");      // macro de impresión con salto de línea
}

¿Por qué println! lleva signo de exclamación?

No es una función: es una macro. El ! indica que se expande en tiempo de compilación, lo que permite aceptar cualquier número de argumentos y validar el formato antes de ejecutar el programa. Si pasas un tipo incorrecto al marcador, el error aparece al compilar, no en producción.

fn main() {
    let nombre = "Rust";
    let anio = 2026;
    let pi = 3.14159;

    println!("Lenguaje: {}", nombre);              // marcador posicional clásico
    println!("Año: {}", anio);
    println!("Pi con 2 decimales: {:.2}", pi);     // formato de precisión
    println!("{nombre} también interpola directo"); // captura variables del scope
    println!("Depuración: {:?}", (nombre, anio));  // {:?} formato Debug para tuplas
    print!("Sin salto");                            // print! NO agrega \n
    println!();                                     // línea en blanco
}

Desde Rust 1.58, println!("{nombre}") interpola variables locales sin pasarlas como argumento: es el estilo recomendado hoy en la mayoría de proyectos.

Primer contacto: variables y mutabilidad

Aquí aparece la primera sorpresa filosófica de Rust: toda variable es inmutable por defecto. No es capricho: si el estado no puede cambiar, razonar sobre el código (y paralelizarlo) se vuelve trivial. Cuando necesites modificar algo, lo declaras explícitamente con mut:

fn main() {
    let x = 5;
    // x = 6;            // ❌ error[E0384]: cannot assign twice to immutable variable

    let mut y = 5;       // mut declara intención de cambiar el valor
    y = 6;               // ✅ permitido
    println!("y vale {}", y);

    // Shadowing: crea una NUEVA variable que oculta a la anterior
    let x = x + 1;       // nueva x = 6
    let x = x * 2;       // nueva x = 12
    let x = x.to_string(); // incluso puede CAMBIAR DE TIPO: i32 → String
    println!("x ahora es texto: {}", x);
}

No confundas shadowing con mutabilidad: el shadowing crea una variable NUEVA (puede cambiar de tipo y volver a ser inmutable), mientras mut modifica siempre la misma celda del mismo tipo hasta el fin del scope. El shadowing brilla en pipelines de transformación; mut, en acumuladores y contadores.

Regla práctica de la comunidad: empieza con let; añade mut solo cuando el compilador te lo pida. El código inmutable es más fácil de testear y de paralelizar.

Errores comunes del principiante

Los primeros días con Rust se pelean más con el compilador que con el problema. Estas son las fricciones habituales y cómo resolverlas sin frustración:

Error o warning típicoCausaSolución
error[E0384] cannot assign twice to immutable variableAsignar sin haber declarado mutAñade mut en la declaración
warning: unused variableVariable declarada y nunca leídaElimínala o renómbrala a _variable si es intencional
error[E0308] mismatched typesRust NUNCA convierte números implícitamente (i32 vs f64)Convierte explícito: x as f64 o x.into()
Compilación lentísima en cada pruebaUsas cargo run para validar sintaxisAlterna con cargo check
Compilar archivo suelto con rustc main.rsHábito heredado de otros lenguajesTrabaja siempre dentro de un proyecto cargo new

Los mensajes de error de Rust incluyen secciones help: con el fix sugerido y, muchas veces, el comando exacto. Leerlos completos (no solo la primera línea) acorta enormemente la curva de aprendizaje.

Ejercicios prácticos

Practica en orden: cada ejercicio asume lo aprendido en el anterior.

  1. Instalación verificada: instala rustup, ejecuta rustc --version y cargo --version, y abre rustup doc para localizar el libro oficial de Rust en tu máquina.
  2. Primer proyecto: crea un proyecto llamado presentacion con cargo new, modifica main.rs para imprimir tu nombre, ciudad y año con println! usando interpolación directa {variable}, y ejecútalo con cargo run.
  3. Formato avanzado: imprime el número pi con 1, 3 y 5 decimales usando especificadores {:.1}, {:.3} y {:.5}; luego imprime una tupla ("GuiaDev", 2026) con {:?} y con {:#?} y observa la diferencia.
  4. Inmutabilidad a propósito: declara una variable puntos = 100, intenta reasignarla sin mut, lee el error E0384 completo y corrígelo de DOS maneras distintas: con mut y con shadowing.
  5. Mini calculadora: en un solo main, declara dos números enteros, calcula suma, resta, multiplicación y división entera, guarda cada resultado con shadowing incremental y muestra una tabla formateada en consola usando println! con marcadores alineados {:>5}.
