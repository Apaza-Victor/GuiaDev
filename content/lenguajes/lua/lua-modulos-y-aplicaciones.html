Módulos con require

Para organizar código en proyectos grandes, Lua usa módulos: un archivo que devuelve una tabla con funciones y datos, y que se carga desde otro archivo con require("nombre"). require ejecuta el archivo una sola vez y guarda el resultado en caché: las llamadas posteriores devuelven lo ya cargado.

-- operaciones.lua  (un módulo)
local M = {}

local function privada(x)
  return x * 2
end

function M.sumar(a, b)
  return a + b
end

function M.mostrar_duplicado(x)
  print(privada(x))   -- usa la función interna, no exportada
end

return M
-- principal.lua  (usa el módulo)
local op = require("operaciones")

print(op.sumar(5, 3))        --> 8
op.mostrar_duplicado(4)      --> 8

-- op.privada  -- error: no está exportada
-- El módulo se carga una sola vez: require es idempotente
local op2 = require("operaciones")
print(op == op2)             --> true  (misma tabla en caché)

Como require memoriza los módulos, los nombres de los módulos propios deben ser únicos en el proyecto. Evita usar require con rutas con .. personalizados a menos que lo necesites: la forma idiomática es require("nombre").

Un módulo puede también devolver una función en lugar de una tabla (útil para fabricas) o simplemente registrar efectos en el entorno (menos idiomático). El estándar es devolver la tabla pública.

Librería estándar útil

La librería estándar de Lua es pequeña pero potente. Las funciones más usadas viven en string, table, math, io y os. Conocerlas ahorra muchísimo tiempo. He aquí un vistazo a las operaciones cotidianas:

-- math: funciones matemáticas
print(math.pi)            --> 3.1415926535898
print(math.floor(3.7))    --> 3
print(math.max(4, 9, 2))  --> 9
print(math.random(1, 6))  --> número entre 1 y 6
print(math.min(4, 9, 2))  --> 2

-- string: manipulación de texto
local s = "guia dev"
print(string.upper(s))    --> GUIA DEV
print(string.gsub("a1b2", "%d", "X"))  --> aXbX
print(string.format("Edad: %d", 25))   --> Edad: 25
-- io: lectura y escritura de archivos
local archivo = io.open("notas.txt", "w")   -- "w" = escribir
archivo:write("Línea de ejemplo\n")
archivo:close()

local lectura = io.open("notas.txt", "r")   -- "r" = leer
local contenido = lectura:read("a")          -- "a" = todo el archivo
lectura:close()
print(contenido)   --> Línea de ejemplo

-- os: sistema operativo
print(os.date("%Y-%m-%d"))   --> 2026-08-28 (fecha actual)
print(os.time())             --> timestamp Unix

os.remove("archivo") borra un archivo y os.rename(a, b) lo renombra. Para operaciones más complejas (directorios, permisos), deberás usar un módulo como lfs (LuaFileSystem) de luarocks.

io.open devuelve nil y un mensaje de error si no puede abrir el archivo. Es recomendable comprobar el resultado con assert o pcall, sobre todo cuando trabajas con rutas que vienen del usuario.

Corrutinas

Una corrutina es una función que puede pausarse en un punto y reanudarse más tarde desde donde quedó. En Lua son cooperativas: solo una corre a la vez y se transfieren el control explícitamente con coroutine.yield() y coroutine.resume(). Sirven para tareas como generadores, máquinas de estado y procesamiento paso a paso.

-- Un generador infinito usando una corrutina
local function generador_contador()
  local n = 0
  while true do
    n = n + 1
    coroutine.yield(n)   -- pausa y devuelve n
  end
end

local co = coroutine.create(generador_contador)

for i = 1, 3 do
  local ok, valor = coroutine.resume(co)
  print(valor)   --> 1, luego 2, luego 3
end

Las corrutinas se usan habitualmente para pausar una tarea larga y permitir que otras cosas avancen, como en un juego que proceso enemigos por turnos:

-- Procesar una lista paso a paso con estado preservado
local function limpiar_datos(datos)
  for i, d in ipairs(datos) do
    coroutine.yield("procesado: " .. d)   -- informa a cada paso
  end
  coroutine.yield("terminado")
end

local tarea = coroutine.create(limpiar_datos)
local datos = { "a", "b", "c" }

while true do
  local ok, paso = coroutine.resume(tarea, datos)
  if not ok then break end
  print(paso)
  if paso == "terminado" then break end
end
-- procesado: a
-- procesado: b
-- procesado: c
-- terminado
FunciónQué hace
coroutine.create(f)Crea una corrutina a partir de la función f
coroutine.resume(co, ...)Ejecuta o reanuda la corrutina
coroutine.yield(...)Pausa la corrutina y transfiere el control
coroutine.status(co)Devuelve "running", "suspended", etc.
coroutine.wrap(f)Devuelve una función que resume internamente

A diferencia de los hilos del sistema, las corrutinas no se ejecutan en paralelo y no hay que sincronizar memoria compartida. Son un mecanismo de cooperación, no de concurrencia real.

coroutine.wrap es mucho más cómodo para generadores simples: devuelve una función que, al llamarla, reanuda la corrutina y devuelve el valor de yield, sin manejar los códigos booleanos a mano.

Lua en juegos: LÖVE y más

Uno de los usos más famosos de Lua son los videojuegos. Motores como Roblox, Defold o Garry's Mod lo usan como lenguaje de scripting, y LÖVE (LÖVE2D) es un framework que permite crear juegos 2D escribiendo toda la lógica en Lua y compilando el empaquetado con C++. Con solo unos métodos (love.load, love.update, love.draw) tienes un ciclo de juego completo.

-- main.lua  (un mini juego con LÖVE)
local x, y = 100, 100

function love.load()
  love.window.setTitle("Mi primer juego en LÖVE")
end

function love.update(dt)
  if love.keyboard.isDown("left")  then x = x - 200 * dt end
  if love.keyboard.isDown("right") then x = x + 200 * dt end
end

function love.draw()
  love.graphics.print("Mueveme con las flechas", 10, 10)
  love.graphics.circle("fill", x, y, 20)
end
# Ejecutar el juego con LÖVE (necesitas instalarlo)
love main.lua

Lua en Redis y sistemas embebidos

Lua brilla en sistemas embebidos y servidores. El caso más popular es Redis: permite escribir scripts en Lua que se ejecutan de forma atómica dentro del servidor, lo que asegura operaciones complejas sin condiciones de carrera. Gracias a la API redis.call, un script puede leer y escribir claves con una sola operación indivisible.

-- un script Lua para Redis (ejemplo conceptual)
-- Devuelve la clave si existe, o un valor por defecto
local clave = KEYS[1]
local valor = redis.call("GET", clave)

if valor then
  return valor
else
  redis.call("SET", clave, "por_defecto")
  return "por_defecto"
end
# Evaluar el script en la línea de comandos de Redis
redis-cli --eval mi_script.lua 1 mi_clave

La embebibilidad es la clave del éxito de Lua: al ser un intérprete de pocos cientos de kilobytes con una API en C limpia, cabe perfectamente en routers, microcontroladores y aplicaciones como Nginx (vía OpenResty) o Wireshark. Puedes ejecutar Lua dentro de tu propio programa C con una docena de líneas:

En Redis, un script tarde demasiado en ejecutarse puede bloquear el servidor para el resto de clientes. Mantén los scripts cortos, evita trabajo pesado y, si es posible, usa estructuras de datos nativas de Redis dentro del Lua en lugar de recorrer listas gigantes.

La API de C de Lua te permite exponer funciones del host a los scripts. Es el mismo patrón que usan los motores de juegos: el mundo real (gráficos, red, física) vive en C/C++, y Lua orquesta esa lógica con un lenguaje seguro y de alto nivel.

Ejercicios prácticos

Aplica módulos, librería estándar, corrutinas y los conceptos de aplicación. Crea los archivos indicados y ejecuta lua para comprobar cada entrega.

  1. Crear un módulo: Escribe un módulo utilidades.lua que exporte maximo(...), minimo(...) y aleatorio(a, b). Crea un main.lua que lo importe con require y pruebe las tres funciones.
  2. Librería estándar: Usa string.format para imprimir un resumen formateado de nombre y edad, os.date para mostrar la fecha de hoy y table.sort para ordenar una lista de números.
  3. Generador con corrutinas: Implementa un generador de Fibonacci con coroutine.yield. Reinicia la corrutina 8 veces e imprime los primeros números de la serie.
  4. Mini movimiento en LÖVE: Amplía el ejemplo de LÖVE añadiendo movimiento vertical con las flechas arriba/abajo y un print de posición al soltar una tecla. Si no tienes LÖVE, escribe el código y describe qué haría.
  5. Desafío: script de Redis: Escribe un script de Redis que tome dos claves de enteros, las sume y guarde el resultado en una tercera clave con redis.call, devolviéndolo. Explica en un comentario por qué ejecutarlo con Lua garantiza la atomicidad.
