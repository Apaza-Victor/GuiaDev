Seguridad fundamental

PHP es el lenguaje más atacado del web simplemente porque es el más usado. Estas cinco reglas eliminan la mayoría de vulnerabilidades:

  • Inyección SQL: nunca concatenes entrada del usuario en consultas; usa sentencias preparadas siempre.
  • XSS: escapa toda salida HTML con htmlspecialchars($valor, ENT_QUOTES, 'UTF-8').
  • Passwords: jamás md5/sha1; usa password_hash() y verifica con password_verify().
  • CSRF: token aleatorio por sesión incluido en todo formulario que muta datos.
  • Uploads: valida MIME real (no solo la extensión), renombra archivos y almacénalos fuera del docroot si sirven solo internamente.
// Consulta segura con PDO
$stmt = $pdo->prepare('SELECT * FROM usuarios WHERE email = :email');
$stmt->execute(['email' => $_POST['email']]);
$usuario = $stmt->fetch();

// Password segura
$hash = password_hash($_POST['password'], PASSWORD_DEFAULT);
if (password_verify($passwordIngresada, $hash)) { /* login ok */ }

Estándares de codificación (PSR)

Los PSR (PHP Standard Recommendations) de FIG son el acuerdo común que hace legible el código de cualquier proyecto PHP moderno:

EstándarTemaRegla clave
PSR-1Código básicoTags <?php, clases en StudlyCaps
PSR-12Estilo de códigoIndentación de 4 espacios, llaves consistentes
PSR-4AutoloadNamespace refleja carpetas: App\Models\User → src/Models/User.php
PSR-3LoggingInterfaz LoggerInterface con niveles debug/info/error

No memorices las reglas: automatízalas con PHP-CS-Fixer o PHP_CodeSniffer y deja que la herramienta corrija el estilo mientras tú piensas en la lógica.

Optimización de código PHP

  • OPcache activo: cachea bytecode compilado; es la optimización gratuita más grande.
  • Evita consultas dentro de bucles: el clásico N+1; agrupa con IN o JOINs.
  • Prefiere funciones nativas: array_map, array_filter, in_array están escritas en C y superan a loops manuales.
  • Libera recursos grandes: unset() en arrays enormes y cierre explícito de cursores/cURL.
  • Actualiza la versión de PHP: cada versión mayor trae ganancias sustanciales; PHP 8+ con JIT es dramáticamente más rápido que 7.x.
; php.ini - OPcache basico para produccion
opcache.enable=1
opcache.validate_timestamps=0
opcache.memory_consumption=192

Con validate_timestamps=0 PHP no comprueba cambios de archivos en cada petición (máximo rendimiento), pero tras cada deploy debes reiniciar PHP-FPM para recargar el código.

Estructura y herramientas del proyecto

  • Composer siempre: gestiona dependencias y autoload; ningún proyecto serio debería existir sin él.
  • Separa lógica: nada de SQL mezclado con HTML; como mínimo separa datos/lógica/vista, idealmente adopta un framework.
  • Configuración por entorno: credenciales en variables de entorno (.env), jamás versionadas en Git.
  • Tipado estricto: declara tipos y activa strict_types=1; convierte errores silenciosos en fallos tempranos y visibles.
  • Herramientas de calidad: PHPUnit/Pest para pruebas, PHPStan o Psalm para análisis estático, ambos en el pipeline de CI.
<?php
declare(strict_types=1);

final class CalculadoraDescuento
{
    public function aplicar(float $total, int $porcentaje): float
    {
        if ($porcentaje < 0 || $porcentaje > 100) {
            throw new InvalidArgumentException('Porcentaje invalido');
        }
        return round($total * (1 - $porcentaje / 100), 2);
    }
}

Ejercicio propuesto: audita un proyecto tuyo contra este checklist (prepared statements, escape de salida, PSR-4, .env fuera de Git, strict_types). Corrige lo que falle antes de escribir funcionalidad nueva.
