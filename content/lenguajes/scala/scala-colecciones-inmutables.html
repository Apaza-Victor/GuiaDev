List y ListBuffer

La List inmutable es la colección más icónica de Scala: una lista enlazada persistente cuya construcción y desestructuración se apoya en Nil y el operador :: (cons). Por el contrario, ListBuffer es mutable y sirve para acumular datos de forma eficiente antes de congelarlos en una lista inmutable.

// Lista inmutable: todos los valores están ya definidos
val numeros = List(1, 2, 3, 4, 5)
val vacia: List[Int] = Nil

// Cons: agrega al inicio, la lista original NO se modifica
val conCero = 0 :: numeros
println(numeros)   // List(1, 2, 3, 4, 5)
println(conCero)   // List(0, 1, 2, 3, 4, 5)

// Unir listas con ++
val muchas = numeros ++ List(6, 7)
println(muchas)    // List(1, 2, 3, 4, 5, 6, 7)

// Para construir listas al vuelo: ListBuffer mutable
import scala.collection.mutable.ListBuffer
val buf = ListBuffer(10, 20)
buf += 30
buf ++= List(40, 50)
val finalBuf = buf.toList // se congela en una List
println(finalBuf)         // List(10, 20, 30, 40, 50)
ColecciónMutabilidadUso típico
ListInmutableEs el tipo por defecto para secuencias
ListBufferMutableAcumular datos y luego convertir con toList
VectorInmutableAcceso aleatorio eficiente por índice

Con List se accede rápido al inicio del listado; para accesos aleatorios frecuentes prefiere Vector, que combina buen acceso a cualquier índice con inmutabilidad.

Vector, Map y Set inmutables

Las colecciones inmutables por defecto de Scala son las elegantes para programación funcional. Vector da acceso casi constante a cualquier índice, Map asocia claves a valores y Set almacena elementos únicos. Ninguna modifica la estructura base: cada operación devuelve una versión actualizada.

import scala.collection.immutable.Vector

// Vector: acceso rápido por índice
val v = Vector("a", "b", "c")
println(v(1))            // b
println(v.updated(1, "B")) // Vector(a, B, c)

// Map: asocia claves a valores
val capitales = Map("Perú" -> "Lima", "Chile" -> "Santiago")
println(capitales("Perú"))        // Lima
println(capitales.getOrElse("Brasil", "desconocida"))

// Set: elementos únicos, sin duplicados y sin orden garantizado
val conjunto = Set(1, 2, 2, 3, 3, 3)
println(conjunto)        // Set(1, 2, 3)
println(Set(1, 2) ++ Set(2, 3))   // Set(1, 2, 3)
println(Set(1, 2, 3) -- Set(2))   // Set(1, 3)

Acceder con paréntesis a un Map (capitales("X")) lanza NoSuchElementException si la clave no existe. Usa get (devuelve Option) o getOrElse para un componente seguro.

Option: Some y None

Option[A] modela la presencia o ausencia de un valor, eliminando el null-checking manual. Es una clase genérica con dos subclases: Some(valor) cuando existe el valor y None cuando no. Así el compilador te fuerza a gestionar el caso vacío.

def buscar(usuarioId: Int, db: Map[Int, String]): Option[String] =
  db.get(usuarioId)

@main def demo(): Unit =
  val db = Map(1 -> "Ana", 2 -> "Luis")

  val r1 = buscar(1, db)
  val r2 = buscar(99, db)

  println(r1)            // Some(Ana)
  println(r2)            // None

  // Patrón combinado: decisión sobre el Option en una expresión
  r1 match
    case Some(nombre) => println(s"Encontrado: $nombre")
    case None          => println("No existe")

  // Seguro y elegante: getOrElse y map sobre el interior
  println(r2.getOrElse("inventario vacío"))
  println(r1.map(_.toUpperCase)) // Some(ANA)

Nunca desreferencies None con .get: lanza una excepción. Prefiere usar siempre getOrElse, map, fold o pattern matching.

Higher-order functions

Las higher-order functions (map, filter, flatMap, etc.) reciben funciones como argumento y las aplican a cada elemento. Convierte todo tu trabajo sobre colecciones en expresiones declarativas: describes el "qué", no el "cómo" con bucles.

val numeros = List(1, 2, 3, 4, 5, 6, 7, 8)

// map: transforma cada elemento
val alCuadrado = numeros.map(n => n * n)
println(alCuadrado) // List(1, 4, 9, 16, 25, 36, 49, 64)

// filter: selecciona elementos que cumplen una condición
val pares = numeros.filter(_ % 2 == 0)
println(pares)      // List(2, 4, 6, 8)

// flatMap: map + aplanar listas anidadas en un solo nivel
val palabras = List("hola", "ada")
val letras = palabras.flatMap(_.toList)
println(letras)     // List(h, o, l, a, a, d, a)

// La barra baja _ es el atajo para el parámetro de la lambda
val dobles = List(1, 2, 3).map(_ * 2) // List(2, 4, 6)
println(dobles)

Cada combinador devuelve una nueva colección; puedes encadenarlos: numeros.filter(_ % 2 == 0).map(_ * 10). El resultado es legible de izquierda a derecha.

La sintaxis _.campo equivale a x => x.campo. Es idónea para one-liners: .map(_.precio) extrae precios de una lista de productos.

foldLeft, reduceLeft y agregación

Para acumular una colección en un único valor, Scala ofrece foldLeft (recibe un valor inicial y una función binaria) y reduceLeft (usa automáticamente el primer elemento como acumulador inicial). Ambos van por la izquierda, procesando la lista de principio a fin.

val precios = List(9.99, 14.50, 3.25, 19.99)

// foldLeft: empieza en 0.0 y acumula sumando con función anónima
val total = precios.foldLeft(0.0)((acumulado, precio) => acumulado + precio)
println(total) // 47.73

// con notación abreviada usando comodines
val total2 = precios.foldLeft(0.0)(_ + _)
println(total2)

// reduceLeft: mismo resultado sin valor inicial (la lista no debe ser vacía)
val max = precios.reduceLeft((a, b) => if a > b then a else b)
println(max) // 19.99

// foldLeft sobre una List de cases para construir un String
val nombres = List("Ada", "Grace", "Barbara")
val cadena = nombres.foldLeft("Intro: ")((acc, n) => acc + n + ", ")
println(cadena)

reduceLeft lanza una excepción si la colección está vacía, porque no hay primer elemento que usar. Prefiere foldLeft cuando el resultado pueda ser vacío.
