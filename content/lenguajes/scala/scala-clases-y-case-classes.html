Clases y constructores

Las clases de Scala se declaran igual que en Java, pero son mucho más compactas: los parámetros del constructor se escriben directamente en la definición de la clase. Si llevan val o var se convierten automáticamente en campos públicos; sin la palabra clave solo son parámetros del constructor.

class Persona(val nombre: String, val edad: Int):
  def presentarse(): String = s"Soy $nombre y tengo $edad años"

  def esMayorDeEdad(): Boolean = edad >= 18

@main def demo(): Unit =
  val ana = Persona("Ana", 30) // No hace falta "new"
  println(ana.nombre)          // Ana
  println(ana.presentarse())   // Soy Ana y tengo 30 años
  println(ana.esMayorDeEdad()) // true

En Scala 3 puedes omitir new al instanciar: Persona("Ana", 30) es válido para clases regulares y case classes.

El constructor de Scala no usa llaves como Java: el cuerpo de la clase es el constructor, y se ejecuta en orden de declaración al instanciar.

Métodos y sobrecarga

Los métodos Scala se declaran con def y pueden tener valores por defecto, parámetros de nombre y sobrecarga (dos métodos con el mismo nombre pero distinta firma). También puedes declarar parámetros por nombre para no recordar el orden.

class Calculadora:
  // Sobrecarga: mismo nombre, diferentes parámetros
  def area(largo: Double, ancho: Double): Double = largo * ancho
  def area(radio: Double): Double = math.Pi * radio * radio

  // Parámetros con valor por defecto
  def conImpuesto(precio: Double, impuesto: Double = 0.19): Double =
    precio + precio * impuesto

@main def demo2(): Unit =
  val c = Calculadora()
  println(c.area(4.0, 2.0))      // 8.0
  println(c.area(1.0))           // 3.141592653589793
  println(c.conImpuesto(100))    // 119.0
  println(c.conImpuesto(100, 0.05)) // 105.0

Al llamar con parámetros de nombre (c.conImpuesto(impuesto = 0.05, precio = 100)) el orden ya no importa, y el código se lee solo.

Case classes

Una case class es la herramienta estrella para modelar datos inmutables. Con una sola línea obtienes: constructor automático, equals por valor, toString legible, hashCode consistente, acceso a sus campos con val y desestructuración en pattern matching.

case class Producto(nombre: String, precio: Double, stock: Int)

@main def demo3(): Unit =
  val p1 = Producto("Laptop", 899.99, 10)
  val p2 = Producto("Laptop", 899.99, 10)

  // equals por valor: dos instancias idénticas son iguales
  println(p1 == p2) // true

  // toString legible sin escribir nada
  println(p1) // Producto(Laptop,899.99,10)

  // copy crea una copia con campos cambiados (inmutabilidad)
  val p3 = p1.copy(stock = 0, precio = 799.99)
  println(p3)

  // Desestructuración directa en match
  p3 match
    case Producto(n, pre, s) if s == 0 => println(s"$n sin stock ($pre)")
    case _ => println("Con stock")

Usa case classes para representar datos (pedidos, usuarios, eventos) y clases regulares para comportamiento con estado.

object y companion objects

Un object es un singleton. Cuando lleva el mismo nombre que una clase y vive en el mismo archivo, se llama companion object y puede alojar métodos de fábrica, constantes y lógica estática: en Java dirías static, aquí simplemente pertenece al object.

class Coordenada(val x: Int, val y: Int)

object Coordenada:
  // Métodos de fábrica disponibles sin instanciar
  def origen(): Coordenada = new Coordenada(0, 0)

  val nombreEje: String = "coordenadas XY"

// Uso típico: constantes y configuración en el object
object Config:
  val version = "1.0.0"
  val puerto = 8080

@main def demo4(): Unit =
  val o = Coordenada.origen()
  println(o.x)                  // 0
  println(Config.version)       // 1.0.0
  println(Config.puerto)        // 8080

Un object no se instancia ni recibe parámetros: Config() no tiene sentido. Cualquier estado que guardes en él es global, así que úsalo para datos de solo lectura.

Traits

Un trait es como una interfaz de Java pero con implementación: puede declarar métodos abstractos y concretos, campos, y mezclarse con with. Un trait no se instancia; describe comportamiento que las clases heredan o mezclan, lo que permite composición múltiple (una clase puede usar varios traits).

trait Hable:
  def hablar(): String

trait Caminable:
  val piernas: Int                                              // campo abstracto
  def pasos(metros: Double): Double = metros * 1.2              // método concreto

class Robot(nombre: String) extends Hable, Caminable:
  val piernas = 2
  def hablar(): String = s"$nombre dice: hola humano"

@main def demo5(): Unit =
  val bot = Robot("R2D2")
  println(bot.hablar())   // R2D2 dice: hola humano
  println(bot.piernas)    // 2
  println(bot.pasos(50))  // 60.0

Usa extends para un solo trait (heredar también puede extenderse para una clase) y with para mezclar varios traits adicionales en Scala 2; en Scala 3 la coma resuelve lo mismo.

Combinar traits es la práctica favorita de Scala: se obtiene comportamiento reutilizable sin la rigidez de la herencia múltiple del estilo C++.

Ejercicios prácticos

  1. Crea una clase Cuenta(val numero: String, var saldo: Double) con un método depositar(monto: Double) que actualice el saldo.
  2. Sobrecarga un método imprimir que reciba un Int, un Double y una String e imprima cada uno con un prefijo.
  3. Define la case class Producto(nombre, precio); crea dos instancias iguales y comprueba que == da true. Luego usa copy.
  4. Crea el companion object de Cuenta con una fábrica cuentaBase() que devuelva una cuenta con saldo 0.
  5. Haz un trait Sonoro con método abstracto sonido(): String y hazlo implementar por dos clases distintas para modelar un perro y un gato.
