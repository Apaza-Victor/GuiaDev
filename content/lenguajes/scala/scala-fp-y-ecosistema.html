Inmutabilidad y efectos

La inmutabilidad es la base de la programación funcional de Scala: los datos nunca cambian, y las funciones puras (sin efectos colaterales) solo calculan un resultado a partir de sus entradas. Esto hace tu código más predecible, testable y seguro para concurrencia. Lo que "hace algo al mundo" (imprimir, leer un archivo) sí se expresa, pero aislado del cálculo.

// Función pura: misma entrada, misma salida, sin efectos
def precioConIva(precio: Double, iva: Double = 0.21): Double =
  precio + precio * iva

// Sin mutación: cada transformación devuelve un nuevo valor
def procesar(compras: List[Double]): Double =
  compras
    .filter(_ > 0)              // ignora precios inválidos
    .map(precioConIva(_))       // aplica IVA
    .sum

@main def demo(): Unit =
  val total = procesar(List(10.0, -5.0, 20.0, 15.0))
  println(f"Total con IVA: $total%.2f")

  // El efecto (println) queda en el punto de entrada, separado del cálculo

Si una función no produce efectos externos y su resultado es derivable solo de sus parámetros, es una función pura: la más fácil de probar y paralelizar.

ConceptoVentaja clave
val inmutableNunca cambia, razonamiento simple
Función puraDeterminista y fácil de probar

Pattern matching avanzado

El pattern matching no se limita a números: permite desestructurar case classes, listas, tuplas y usar guards con condiciones. En Scala 3 además es extensible con extracciones personalizadas. Lo verás en casos reales con datos de negocio y estructuras recursivas.

enum Estado:
  case Activo, Inactivo, Suspendido

case class Usuario(nombre: String, estado: Estado)

def estadoDel(usuario: Usuario): String = usuario match
  case Usuario(_, Estado.Activo)     => "Operativo"
  case Usuario(n, Estado.Suspendido) => s"$n suspendido"
  case _                             => "Inactivo"

@main def demo2(): Unit =
  val lista = List(1, 2, 3)
  // Desestructurar listas: head :: tail como patrón
  val res = lista match
    case Nil         => "vacía"
    case x :: rest   => s"primero $x y el resto tiene ${rest.length}"
  println(res) // primero 1 y el resto tiene 2

  println(estadoDel(Usuario("Luis", Estado.Suspendido))) // Luis suspendido

Recuerda el caso Nil para listas vacías cuando desestructuras con ::: si lo olvidas, una lista vacía lanza MatchError.

for-comprehensions

En Scala 2 las for-comprehensions y las cadenas de map/flatMap/filter son intercambiables: for con yield es simplemente azúcar sintáctico de esos combinadores, y con Option permite encadenar operaciones que pueden fallar sin null-checks. Hemos usado esta equivalencia para calcular datos de negocio.

val usuarioDb = Map(1 -> "Ana", 2 -> "Luis")
val edadesDb = Map("Ana" -> 28, "Luis" -> 34)

// Encadenando Option con for: si cualquier paso da None, todo da None
val resultado = for
  usuarioId <- Some(1)
  nombre     <- usuarioDb.get(usuarioId)
  edad       <- edadesDb.get(nombre)
yield s"$nombre tiene $edad años"

println(resultado) // Some(Ana tiene 28 años)

val fallo = for
  usuarioId <- Some(99)
  nombre     <- usuarioDb.get(usuarioId)
yield nombre
println(fallo) // None: la cadena se corta limpiamente

Una for-comprehension sobre Option reemplaza docenas de if (x != null) .... Es la forma idiomática de encadenar pasos que pueden faltar.

Concurrencia con Akka

Akka es el framework de concurrencia distribuida más conocido de Scala y Java. Se basa en el modelo de actores: unidades que procesan mensajes de forma aislada y sin compartir estado mutable, comunicándose por buzones. Por eso es natural combinarlo con la inmutabilidad de Scala. Se añade como dependencia de sbt.

// En build.sbt, añade las dependencias de Akka
libraryDependencies ++= Seq(
  "com.typesafe.akka" %% "akka-actor-typed" % "2.8.5"
)
import akka.actor.typed.{ActorRef, ActorSystem, Behavior}
import akka.actor.typed.scaladsl.Behaviors

object Saludo:
  // Mensaje que un actor procesa
  final case class Saluda(nombre: String)

  def apply(): Behavior[Saluda] = Behaviors.receive { (contexto, mensaje) =>
    contexto.log.info(s"Hola ${mensaje.nombre} desde Akka")
    Behaviors.same
  }

@main def demo3(): Unit =
  // Crea el actor system y envía un mensaje
  val sistema = ActorSystem(Saludo(), "mi-sistema")
  val ref: ActorRef[Saludo.Saluda] = sistema
  ref ! Saludo.Saluda("GuiaDev")

  Thread.sleep(500)
  sistema.terminate()

Akka llegó a ser el estándar de hecho para sistemas reactivos, aunque proyectos nuevos a menudo prefieren Pekko (su fork mantenido por Apache). El modelo de actores visto aquí es el mismo.

Big data con Apache Spark

Apache Spark es el motor de procesamiento big data más usado, y su API principal se escribe en Scala. Procesa conjuntos masivos de datos en memoria y en paralelo mediante RDDs y DataFrames inmutables. Gracias a las higher-order functions de Scala, escribir una pipeline de datos parece trabajar con una colección normal.

// Analogía funcional de un DataFrame en Spark (el pipeline es funcional)
val ventas = Seq(
  ("Lima", 150.0), ("Lima", 200.0), ("Cusco", 90.0)
)

// Análogo funcional: agrupar por ciudad y sumar con fold
val porCiudad = ventas.foldLeft(Map.empty[String, Double]) { (acc, venta) =>
  val (ciudad, monto) = venta
  acc + (ciudad -> (acc.getOrElse(ciudad, 0.0) + monto))
}
println(porCiudad) // Map(Lima -> 350.0, Cusco -> 90.0)
# Spark se gestiona como librería. En build.sbt:
# libraryDependencies += "org.apache.spark" %% "spark-sql" % "3.5.0"
#
# El binario spark-submit lanza el trabajo en un clúster:
# spark-submit --class com.guiadev.Analisis mi-app.jar

Spark y Akka comparten la filosofía funcional de Scala: datos inmutables que se procesan con transformaciones funcionales, en vez de mutar estado compartido entre hilos.

Has completado el ciclo completo: de la sintaxis e inmutabilidad a las for-comprehensions, los actores de Akka y los DataFrames de Spark. Scala es un lenguaje de la JVM que domina tanto la orientación a objetos como el paradigma funcional.

Ejercicios prácticos

  1. Escribe una función pura que calcule el promedio de una List[Double] y otra impura que además lo imprima. Comprueba que la primera da siempre el mismo resultado.
  2. Desestructura List("Scala", "Java", "Rust") con pattern matching e imprime cuál es el primero y cuántos quedan después.
  3. Con una for-comprehension sobre Option, combina dos Maps (por nombre) y devuelve la edad si ambos tienen datos, o None en otro caso.
  4. Investiga (o simula) un actor de Akka que responda "pong" a un mensaje "ping" aplicando el mismo patrón de Behaviors.receive.
  5. Implementa con foldLeft el total de ventas por ciudad en una estructura que imite un agrupamiento de Spark.
