¿Qué es TypeScript?

TypeScript es un superset de JavaScript creado por Microsoft que añade tipos estáticos al lenguaje. Al ser un superset, todo código JavaScript válido también es TypeScript válido; la diferencia es que en TypeScript puedes declarar qué tipo guarda cada variable, y el compilador lo verifica antes de ejecutarse.

// ? JavaScript: sin tipos, los errores aparecen al ejecutar
let edad = 25;
edad = "joven";     // ✔ en JS permitido (aunque sea un error de lógica)

// ? TypeScript: con tipos, el compilador te avisa al instante
let edad: number = 25;
// edad = "joven";
// ❌ Type 'string' is not assignable to type 'number'

TypeScript no corre en el navegador directamente: se compila (transpila) a JavaScript mediante el compilador oficial tsc, produciendo archivos .js que el navegador sí puede ejecutar.

VentajaQué aporta
Tipos estáticosDeclaras el tipo de cada valor y el compilador lo garantiza
Detección de errores en compilaciónLos errores de tipo se detectan al compilar, no al ejecutar
AutocompletadoEl editor sugiere propiedades y métodos válidos de cada valor
Mejor mantenimientoEl tipo documenta la intención y facilita refactorizar proyectos grandes

TypeScript suele escribirse en archivos .ts y se compila con tsc a JavaScript antes de publicar o ejecutar.

Tipos básicos

Los tipos básicos son los bloques fundamentales con los que describes qué puede guardar cada valor. TypeScript aporta los primitivos de JavaScript, ahora verificables por el compilador, además de arreglos, tuplas y enumeraciones.

TipoQué guardaEjemplo
numberEnteros y decimaleslet num: number = 5
stringCadenas de textolet nombre: string = "Ana"
booleantrue o falselet activo: boolean = true
anyCualquier valor (desactiva la comprobación)let dato: any = 42
voidSin retorno (funciones que no devuelven)function log(): void
nullEl valor nulllet x: null = null
undefinedEl valor undefinedlet y: undefined = undefined
number[]Arreglo de númeroslet lista: number[] = [1,2]
Array<number>Arreglo de números (sintaxis genérica)let lista: Array<number> = [1,2]
tupleArreglo con tipos fijos por posiciónlet p: [string, number]
enumConjunto de constantes con nombreenum Color { Rojo }

Declaración con anotación de tipo

// Anotas el tipo de forma explícita con dos puntos
let num: number = 5;
let nombre: string = "Ana";
let esValido: boolean = true;

Inferencia de tipos

// El compilador deduce el tipo solo a partir del valor inicial
let num = 5;          // tipo inferido: number
let nombre = "Ana";   // tipo inferido: string
let esValido = true;  // tipo inferido: boolean

Cuando la variable local tiene valor inicial, deja que TypeScript infiera el tipo; así el código queda más limpio y sin errores.

Tipos avanzados e interfaces

Además de los tipos primitivos, TypeScript permite describir estructuras de objetos y combinar tipos. Las interfaces definen la forma de un objeto; los type aliases crean nombres para cualquier tipo; los union types permiten que un valor acepte varios tipos.

Interface: la forma de un objeto

interface Usuario {
  id: number;
  nombre: string;
  email?: string;      // opcional
}

const usuario: Usuario = { id: 1, nombre: "Ana" };

Type alias: renombrar un tipo

type Nombre = string;               // alias de un primitivo
type Identificador = number | string; // alias de una unión

Union types y literal types

// Unión: acepta string O number
let valor: string | number = "hola";
valor = 42; // ✔ posible

// Literal: solo admite los valores exactos listados
type Estado = "pendiente" | "activo" | "bloqueado";
let estado: Estado = "activo";
CaracterísticaQué hace
InterfaceDefine la forma (propiedades) de un objeto; es extensible y se puede heredar
Type aliasCrea un nombre para cualquier tipo: primitivo, unión, tupla u objeto
Union typePermite que un valor tenga varios tipos posibles (a | b)
Literal typeRestringe un valor a un conjunto exacto de literales

Diferencia clave: interface sirve para describir objetos y se puede extender/heredar; type es más flexible (sirve para cualquier tipo, incluidas uniones y alias) pero x puede reabrirse ni heredar.

Funciones y parámetros

Las funciones tipadas declaran el tipo de sus parámetros y de su retorno. Así el compilador sabe exactamente qué espera y qué devuelve cada función, detectando llamadas incorrectas desde el inicio.

Función con tipos en parámetros y retorno

function sumar(a: number, b: number): number {
  return a + b;
}
const total = sumar(2, 3); // total: number

Arrow functions tipadas

const multiplicar = (a: number, b: number): number => a * b;
// Función completa también se puede tipar
const dividir: (a: number, b: number) => number = (a, b) => a / b;
ElementoQué haceEjemplo
Parámetros obligatoriosTodo parámetro sin ? es requeridofunction f(a: number)
Opcionales (?)Puede omitirse al llamarfunction f(a?: number)
Con valor por defectoSe usa si no se pasa argumentofunction f(a = 0)
Rest (...args)Agrupa los argumentos restantes en un arreglofunction f(...nums: number[])

Si una función no devuelve nada, declara su retorno como void. Esto comunica la intención de que no produce valor alguno.

Clases y POO

TypeScript potencia la POO de JavaScript añadiendo tipos en propiedades, un constructor tipado, modificadores de acceso y una sintaxis más concisa. Las propiedades deben declararse y tiparse antes de usarse en el constructor con this.

Definir una clase con propiedades y tipos

class Cuenta {
  private saldo: number;         // propiedad privada
  readonly titular: string;      // solo lectura

  constructor(titular: string, saldoInicial: number) {
    this.titular = titular;
    this.saldo = saldoInicial;
  }

  depositar(monto: number): void {
    this.saldo += monto;
  }

  obtenerSaldo(): number {
    return this.saldo;
  }
}
ModificadorQué hace
publicAccesible desde cualquier lugar (por defecto)
privateSolo accesible dentro de la propia clase
protectedAccesible en la clase y sus subclases heredadas
readonlySolo asignable en la declaración o en el constructor; no puede cambiarse luego

Herencia con extends

class CuentaAhorro extends Cuenta {
  private interes: number;
  constructor(titular: string, saldo: number, interes: number) {
    super(titular, saldo);
    this.interes = interes;
  }
}

Implements de una interface

interface Repositorio {
  guardar(dato: string): void;
}

class RepositorioLocal implements Repositorio {
  guardar(dato: string): void {
    console.log(dato);
  }
}

Usa extends para heredar de una clase y implements para cumplir un contrato definido por una interface.

Genéricos y módulos

Los genéricos permiten escribir funciones, clases e interfaces que funcionan con cualquier tipo pero conservando el tipado. Los módulos organizan el código en archivos mediante export e import.

Función genérica

function identidad<T>(x: T): T {
  return x;
}

const a = identidad<string>("hola"); // T = string
const b = identidad(42);             // T se infiere: number

Genéricos en clases e interfaces

interface Caja<T> {
  contenido: T;
}

class Almacen<T> {
  private items: T[] = [];
  agregar(item: T): void {
    this.items.push(item);
  }
}

Módulos: export e import

// archivo: funciones.ts
export function sumar(a: number, b: number): number {
  return a + b;
}
export default function multiplicar(a: number, b: number): number {
  return a * b;
}
// import { x } from "./archivo"
import { sumar } from "./funciones";
import multiplicar from "./funciones"; // export default sin llaves
SintaxisQué hace
export functionExpone una función para que otros archivos la importen
export defaultExpone un único valor por defecto del módulo
import { a } from "./archivo"Importa el valor nombrado a de otro archivo
import d from "./archivo"Importa el valor por defecto (sin llaves)

Usa export default para un valor principal del módulo y export nombrado para exponer varias utilidades.

TypeScript vs JavaScript

TypeScript extiende JavaScript añadiéndole tipos; al final de la cadena siempre se compila a JavaScript para que el navegador pueda ejecutarlo. Son el mismo lenguaje base, pero TypeScript añade una capa de verificación en tiempo de desarrollo.

AspectoJavaScriptTypeScript
TipadoDinámico: los tipos cambian en ejecuciónEstático: tipos declarados y verificados
Detección de erroresEn tiempo de ejecución en el navegadorEn tiempo de compilación, antes de ejecutar
CompilaciónNo se compila; lo ejecuta el navegador/NodeSe compila (transpila) a JavaScript con tsc
Archivos.js, .mjs, .cjs.ts (que al compilar producen .js)
Uso en producciónDirectamente en el navegadorSe compila a JS antes de publicarse

Todo código JS es código TS válido, por lo que migrar es gradual. TypeScript se compila a JavaScript, y ese JS es el que el navegador ejecuta.

Conceptos importantes

Glosario rápido con los términos que más encontrarás al trabajar con TypeScript. Dominar este vocabulario facilita leer la documentación y entender los errores del compilador.

ConceptoQué significa
SupersetLenguaje que extiende a otro; todo JS válido es TS válido
TipoDescripción de qué clase de valor admite una variable
Anotación de tipoSintaxis : tipo que declara el tipo de un valor explícitamente
Inferencia de tiposEl compilador deduce el tipo automáticamente del valor inicial
InterfaceDefinición de la forma de un objeto, extensible
Type aliasNombre alternativo creado con type para cualquier tipo
UnionUn valor que puede ser de varios tipos (a | b)
GenéricoCódigo reutilizable que conserva el tipo recibido (<T>)
EnumConjunto de constantes con nombre
TupleArreglo con tipos fijos por posición
AnyTipo que desactiva la comprobación (evita abusar de él)
VoidAusencia de retorno en una función
NeverTipo que nunca se alcanza (por ejemplo, una función que lanza siempre)
Compilador (tsc)Herramienta oficial que convierte TS a JS
TranspilaciónConvertir código de un lenguaje a otro equivalente (TS → JS)
tsconfig.jsonArchivo de configuración del compilador de TypeScript
MóduloBloque de código separado en su propio archivo
Export/ImportMecanismo para exponer y consumir valores entre módulos
DecoradorFunción que añade comportamiento a clases/métodos (usado en frameworks)
Strict modeConjunto de comprobaciones estrictas activadas por defecto en tsconfig

Evita usar any en exceso: apaga la verificación de tipos y pierdes las ventajas de TypeScript. El strict mode te ayuda a mantener el código seguro.
